## 1. 베이스라인 모델이란?

### 1.1. 베이스라인 모델의 정의
**베이스라인 모델(Baseline Model)**은 머신러닝 프로젝트에서 복잡한 모델링을 시작하기 전에 설정하는 **최소한의 성능 기준점**을 의미합니다. 이는 프로젝트의 초기 단계에서 데이터와 문제에 대한 기본적인 이해를 바탕으로 구축되는 가장 단순한 형태의 모델입니다.

**베이스라인 모델의 주요 특징:**
*   **단순성:** 복잡한 알고리즘이나 정교한 특성 공학 없이, 가장 기본적인 방법으로 구현됩니다. 예를 들어, 분류 문제에서는 다수 클래스 예측, 회귀 문제에서는 평균값 예측 등이 될 수 있습니다.
*   **해석 용이성:** 모델의 작동 방식과 예측 결과를 쉽게 이해하고 설명할 수 있습니다.
*   **빠른 구현 및 학습:** 복잡한 모델에 비해 훨씬 적은 시간과 자원으로 빠르게 구축하고 학습시킬 수 있습니다.
*   **성능 기준점:** 이 모델의 성능이 앞으로 개발될 모든 복잡한 모델이 넘어야 할 최소한의 허들(threshold)이 됩니다. 즉, 아무리 정교한 모델이라도 베이스라인 모델보다 성능이 좋지 않다면 그 모델은 의미가 없다고 판단할 수 있습니다.

베이스라인 모델은 단순히 낮은 성능의 모델이 아니라, 향후 모델 개선의 방향을 제시하고 프로젝트의 성공 여부를 가늠하는 중요한 척도 역할을 합니다.

### 1.2. 왜 베이스라인 모델이 중요한가?
많은 데이터 과학자들이 처음부터 복잡하고 성능이 좋은 최신 알고리즘(예: XGBoost, 딥러닝)을 적용하려는 경향이 있습니다. 하지만 베이스라인 모델 없이 복잡한 모델을 바로 만드는 것은 다음과 같은 여러 가지 문제를 야기할 수 있습니다.

1.  **성능 향상 측정의 객관적인 기준 제공:**
    *   기준점(benchmark)이 없으면, 복잡한 모델의 성능이 실제로 얼마나 향상되었는지, 투입한 시간과 노력이 그만한 가치가 있었는지 객관적으로 판단하기 어렵습니다. 베이스라인 모델은 향후 개발될 모든 모델의 성능을 비교할 수 있는 명확한 기준을 제공합니다.
    *   예를 들어, 복잡한 딥러닝 모델이 90%의 정확도를 달성했다고 해도, 베이스라인 모델이 이미 89%의 정확도를 보였다면, 1%의 향상을 위해 들인 노력의 효율성을 재고해볼 수 있습니다.

2.  **문제의 난이도 및 해결 가능성 파악:**
    *   만약 간단한 베이스라인 모델만으로도 충분히 좋은 성능이 나온다면, 해당 문제는 굳이 복잡한 모델을 사용할 필요가 없는 비교적 쉬운 문제일 수 있습니다. 이는 불필요한 복잡성을 피하고 더 효율적인 솔루션을 찾을 수 있도록 돕습니다.
    *   반대로, 베이스라인 모델의 성능이 매우 낮다면, 이는 문제가 매우 어렵거나 현재 데이터만으로는 해결하기 어렵다는 강력한 신호일 수 있습니다. 이 경우, 추가적인 데이터 수집, 특성 공학, 또는 문제 정의 자체의 재검토가 필요하다는 인사이트를 얻을 수 있습니다.

3.  **모델 개선을 위한 방향성 제시:**
    *   베이스라인 모델의 예측 오류를 분석함으로써, 데이터 전처리, 특성 공학, 또는 모델 선택을 어느 방향으로 진행해야 할지에 대한 초기 인사이트를 얻을 수 있습니다. 예를 들어, 베이스라인 모델이 특정 유형의 데이터에서 지속적으로 오류를 범한다면, 해당 데이터에 대한 추가적인 전처리나 특성 공학이 필요하다는 것을 알 수 있습니다.

4.  **시간 및 자원 절약:**
    *   복잡한 모델은 학습과 튜닝에 많은 시간과 컴퓨팅 자원(CPU, GPU)을 소모합니다. 베이스라인 모델을 먼저 구축함으로써 프로젝트의 실현 가능성을 빠르게 가늠하고, 불필요한 자원 낭비를 막을 수 있습니다.
    *   만약 베이스라인 모델이 기대 이하의 성능을 보인다면, 프로젝트의 초기 단계에서 방향을 수정하거나 중단하는 결정을 내릴 수 있어 시간과 비용을 절약할 수 있습니다.

5.  **커뮤니케이션 및 기대치 관리:**
    *   프로젝트 이해관계자들에게 모델의 초기 성능과 개선 목표를 명확하게 제시할 수 있습니다. 이는 프로젝트에 대한 현실적인 기대치를 설정하고, 진행 상황을 효과적으로 소통하는 데 도움이 됩니다.

결론적으로, 베이스라인 모델은 머신러닝 프로젝트의 나침반과 같습니다. 항상 베이스라인을 먼저 설정하고, 이를 기준으로 모델을 점진적으로 개선해나가는 습관을 들이는 것이 성공적인 프로젝트의 핵심입니다.

## 2. 베이스라인 모델 설정 방법

### 2.1. 간단하고 빠른 모델 선택
베이스라인 모델은 복잡한 모델링에 앞서 빠르게 구현하고 평가할 수 있어야 합니다. 일반적으로 다음과 같은 모델들이 베이스라인으로 자주 사용됩니다. 이들은 비교적 단순하고, 학습 속도가 빠르며, 해석이 용이하다는 공통점을 가집니다.

*   **분류(Classification) 문제에서의 베이스라인 모델:**
    *   **`LogisticRegression` (로지스틱 회귀):**
        *   **특징:** 선형 분류 모델로, 빠르고 해석이 용이하며, 특성 간의 선형적인 관계를 잘 잡아냅니다. 이진 분류에 주로 사용되지만 다중 클래스 분류도 가능합니다.
        *   **장점:** 구현이 간단하고, 학습 속도가 빠르며, 예측에 대한 확률을 제공합니다. 과적합에 대한 위험이 비교적 낮습니다.
        *   **사용 시기:** 분류 문제의 첫 번째 베이스라인으로 가장 흔하게 사용됩니다.
    *   **`DecisionTreeClassifier` (의사결정 트리):**
        *   **특징:** 비선형 관계를 학습할 수 있는 트리 기반 모델입니다. `max_depth`와 같은 파라미터를 작게 설정하여 모델의 복잡도를 제한할 수 있습니다.
        *   **장점:** 모델의 결정 과정을 시각화하여 초기 데이터에 대한 인사이트를 얻기 좋습니다. 특성 중요도를 제공합니다.
        *   **사용 시기:** 데이터의 결정 규칙을 직관적으로 파악하고 싶을 때, 또는 비선형 관계가 예상될 때 간단한 형태로 사용합니다.
    *   **`KNeighborsClassifier` (K-최근접 이웃):**
        *   **특징:** 비모수(non-parametric) 모델로, 새로운 데이터 포인트가 주어졌을 때 가장 가까운 K개의 훈련 데이터 포인트를 찾아 다수결로 클래스를 예측합니다.
        *   **장점:** 구현이 간단하고, 데이터의 복잡한 비선형 패턴을 학습할 수 있습니다.
        *   **사용 시기:** 데이터의 지역적인 패턴이 중요하다고 예상될 때, 또는 다른 모델이 잘 작동하지 않을 때 시도해볼 수 있습니다. (단, 특성 스케일에 민감하므로 스케일링이 필수적입니다.)

*   **회귀(Regression) 문제에서의 베이스라인 모델:**
    *   **`LinearRegression` (선형 회귀):**
        *   **특징:** 가장 기본적인 선형 회귀 모델로, 독립 변수와 종속 변수 간의 선형 관계를 모델링합니다.
        *   **장점:** 구현이 간단하고, 학습 속도가 빠르며, 계수를 통해 특성의 영향력을 해석하기 용이합니다.
        *   **사용 시기:** 회귀 문제의 첫 번째 베이스라인으로 가장 흔하게 사용됩니다.
    *   **`Ridge`, `Lasso` (릿지, 라쏘 회귀):**
        *   **특징:** `LinearRegression`에 L2(릿지) 또는 L1(라쏘) 정규화가 포함된 선형 모델입니다. 과적합을 방지하고 모델의 안정성을 높입니다.
        *   **장점:** 다중공선성(Multicollinearity) 문제가 있는 경우에도 안정적인 성능을 보이며, 라쏘는 특성 선택 효과도 가집니다.
        *   **사용 시기:** 특성 수가 많거나 특성 간 상관관계가 높을 때 `LinearRegression`의 대안으로 사용합니다.
    *   **`DecisionTreeRegressor` (의사결정 트리 회귀):**
        *   **특징:** 의사결정 트리를 회귀 문제에 적용한 모델입니다. `max_depth`를 작게 설정하여 모델의 복잡도를 제한할 수 있습니다.
        *   **장점:** 비선형 관계를 학습할 수 있으며, 결정 과정을 시각화하여 이해하기 쉽습니다.
        *   **사용 시기:** 비선형 관계가 예상될 때 간단한 형태로 사용합니다.

이러한 모델들은 복잡한 모델을 개발하기 전에 데이터의 특성을 파악하고, 모델링 방향을 설정하는 데 중요한 초기 기준점을 제공합니다.

### 2.2. 더미(Dummy) 모델 활용
Scikit-learn의 `DummyClassifier`와 `DummyRegressor`는 매우 유용한 베이스라인 도구입니다. 이들은 실제 데이터의 특성을 전혀 학습하지 않고, 단순히 특정 규칙에 따라 예측을 수행합니다. 즉, 데이터의 패턴을 학습하는 것이 아니라, 가장 단순한 통계적 규칙이나 무작위 추측을 기반으로 예측을 생성합니다.

*   **`DummyClassifier` (분류 문제):**
    *   **`strategy='most_frequent'`:** 훈련 데이터에서 가장 빈도가 높은 클래스로 무조건 예측합니다. 이는 불균형 데이터셋에서 다수 클래스에 편향된 모델의 성능을 평가하는 데 유용합니다.
    *   **`strategy='stratified'`:** 훈련 데이터의 클래스 분포를 반영하여 무작위로 예측합니다. 이는 무작위 추측보다 얼마나 더 나은 성능을 보이는지 확인하는 데 사용됩니다.
    *   **`strategy='uniform'`:** 모든 클래스에 대해 균등한 확률로 무작위 예측합니다.
    *   **`strategy='constant'`:** `constant` 파라미터로 지정된 특정 클래스로만 예측합니다.

*   **`DummyRegressor` (회귀 문제):**
    *   **`strategy='mean'`:** 무조건 훈련 데이터의 타겟 변수 평균값으로 예측합니다.
    *   **`strategy='median'`:** 무조건 훈련 데이터의 타겟 변수 중앙값으로 예측합니다.
    *   **`strategy='quantile'`:** 훈련 데이터 타겟 변수의 지정된 분위수(quantile) 값으로 예측합니다.
    *   **`strategy='constant'`:** `constant` 파라미터로 지정된 특정 상수로 예측합니다.

**더미 모델의 중요성:**
만약 힘들게 만든 모델의 성능이 더미 모델보다도 낮다면, 모델링 과정에 심각한 문제가 있음을 의미합니다. 이는 데이터 전처리, 특성 공학, 모델 선택, 또는 하이퍼파라미터 튜닝 등 전반적인 워크플로우를 재검토해야 한다는 강력한 신호입니다. 따라서 더미 모델은 **"최소한 넘어야 할 성능의 최저선"**을 제공하며, 모든 머신러닝 프로젝트에서 가장 먼저 확인해야 할 베이스라인입니다.

## 3. 베이스라인 모델 수립 실습

### 3.1. 분류 문제에서의 베이스라인
분류 문제에서 베이스라인 모델을 수립하는 것은, 모델이 단순히 무작위로 예측하거나 다수 클래스만 예측하는 것보다 얼마나 더 나은 성능을 보이는지 확인하는 데 중요합니다. 여기서는 간단한 파이프라인과 함께 로지스틱 회귀 모델로 베이스라인을 설정하는 예제를 보여줍니다.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.metrics import accuracy_score, classification_report, confusion_matrix
import numpy as np

# 1. 데이터 로드
# 유방암 데이터셋(이진 분류)을 로드합니다. 특성(X)과 타겟(y)으로 구성됩니다.
cancer = load_breast_cancer()
X, y = cancer.data, cancer.target

# 2. 데이터 분할
# 훈련 세트와 테스트 세트로 데이터를 분할합니다. stratify=y를 사용하여 클래스 비율을 유지합니다.
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

print(f"훈련 데이터 클래스 분포: {np.bincount(y_train)}") # 훈련 데이터의 클래스 0과 1의 개수
print(f"테스트 데이터 클래스 분포: {np.bincount(y_test)}")  # 테스트 데이터의 클래스 0과 1의 개수

# 3. 베이스라인 파이프라인 설정
# StandardScaler: 특성 스케일링 (로지스틱 회귀는 스케일링에 민감)
# LogisticRegression: 분류 모델
baseline_pipe = Pipeline([
    ('scaler', StandardScaler()), # 1단계: 데이터 스케일링
    ('model', LogisticRegression(random_state=42, solver='liblinear')) # 2단계: 모델 학습 (solver 지정)
])

# 4. 베이스라인 모델 학습 및 평가
# 파이프라인의 fit() 메서드를 호출하면 전처리부터 모델 학습까지 자동으로 수행됩니다.
baseline_pipe.fit(X_train, y_train)
# 테스트 세트에 대한 예측을 수행합니다.
y_pred = baseline_pipe.predict(X_test)

# 정확도(Accuracy) 계산
accuracy = accuracy_score(y_test, y_pred)

print(f"\n로지스틱 회귀 베이스라인 모델 정확도: {accuracy:.4f}")
print("\n혼동 행렬:\n", confusion_matrix(y_test, y_pred))
print("\n분류 보고서:\n", classification_report(y_test, y_pred))

# 해석:
# 이 정확도(예: 0.9766)는 앞으로 개발할 모든 모델이 넘어야 할 기준점이 됩니다.
# 혼동 행렬과 분류 보고서를 통해 각 클래스별 정밀도(precision), 재현율(recall), F1-점수(f1-score)를 확인하여
# 모델이 단순히 다수 클래스에 편향되지 않았는지도 함께 평가해야 합니다.
# 예를 들어, 클래스 1(양성)에 대한 재현율이 충분히 높은지 확인하는 것이 중요합니다.
```

**분류 베이스라인 모델 평가 시 고려사항:**
*   **평가 지표:** 불균형 데이터셋에서는 정확도(Accuracy)만으로는 모델의 성능을 제대로 평가하기 어렵습니다. 재현율(Recall), 정밀도(Precision), F1-점수(F1-Score), ROC-AUC(Receiver Operating Characteristic - Area Under Curve)와 같은 지표를 함께 고려해야 합니다.
*   **클래스 분포:** `np.bincount(y_train)`을 통해 훈련 데이터의 클래스 분포를 확인하고, 모델이 소수 클래스를 무시하지 않았는지 확인해야 합니다.
*   **더미 모델과의 비교:** 이 로지스틱 회귀 모델의 성능을 `DummyClassifier`의 성능과 비교하여, 모델이 실제 데이터의 패턴을 학습했는지 확인하는 것이 중요합니다.

### 3.2. 회귀 문제에서의 베이스라인
회귀 문제에서 베이스라인 모델은 일반적으로 타겟 변수의 평균이나 중앙값으로 예측하는 더미(Dummy) 모델을 사용하여 설정합니다. 이는 모델이 데이터의 패턴을 전혀 학습하지 않고도 얻을 수 있는 최소한의 성능 기준선이 됩니다.

```python
from sklearn.datasets import fetch_california_housing
from sklearn.dummy import DummyRegressor
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error, mean_absolute_error, r2_score
import numpy as np

# 1. 데이터 로드
# 캘리포니아 주택 가격 데이터셋(회귀)을 로드합니다. 특성(X)과 타겟(y)으로 구성됩니다.
housing = fetch_california_housing()
X, y = housing.data, housing.target

# 2. 데이터 분할
# 훈련 세트와 테스트 세트로 데이터를 분할합니다.
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

print(f"훈련 데이터 타겟 변수 평균: {np.mean(y_train):.4f}")
print(f"훈련 데이터 타겟 변수 중앙값: {np.median(y_train):.4f}")

# 3. 더미 회귀 모델 (평균값으로 예측)
# strategy='mean': 훈련 데이터의 타겟 변수 평균값으로 모든 예측을 수행합니다.
dummy_regr_mean = DummyRegressor(strategy="mean")
dummy_regr_mean.fit(X_train, y_train)
y_pred_dummy_mean = dummy_regr_mean.predict(X_test)

mse_mean = mean_squared_error(y_test, y_pred_dummy_mean)
mae_mean = mean_absolute_error(y_test, y_pred_dummy_mean)
r2_mean = r2_score(y_test, y_pred_dummy_mean)

print(f"\n더미 회귀 모델(평균 예측)의 MSE: {mse_mean:.4f}")
print(f"더미 회귀 모델(평균 예측)의 MAE: {mae_mean:.4f}")
print(f"더미 회귀 모델(평균 예측)의 R2: {r2_mean:.4f}")

# 4. 더미 회귀 모델 (중앙값으로 예측)
# strategy='median': 훈련 데이터의 타겟 변수 중앙값으로 모든 예측을 수행합니다.
dummy_regr_median = DummyRegressor(strategy="median")
dummy_regr_median.fit(X_train, y_train)
y_pred_dummy_median = dummy_regr_median.predict(X_test)

mse_median = mean_squared_error(y_test, y_pred_dummy_median)
mae_median = mean_absolute_error(y_test, y_pred_dummy_median)
r2_median = r2_score(y_test, y_pred_dummy_median)

print(f"\n더미 회귀 모델(중앙값 예측)의 MSE: {mse_median:.4f}")
print(f"더미 회귀 모델(중앙값 예측)의 MAE: {mae_median:.4f}")
print(f"더미 회귀 모델(중앙값 예측)의 R2: {r2_median:.4f}")

# 해석:
# 앞으로 만들 모델의 MSE나 MAE는 최소한 이 값들보다는 낮아야 의미가 있습니다.
# R2 점수는 0에 가깝거나 음수일 것입니다. 이는 모델이 타겟 변수의 분산을 전혀 설명하지 못하거나,
# 평균 예측보다도 못한 성능을 보인다는 의미입니다.
```

**회귀 베이스라인 모델 평가 시 고려사항:**
*   **평가 지표:** 회귀 문제에서는 MSE(Mean Squared Error), MAE(Mean Absolute Error), R2 점수(R-squared) 등 다양한 평가 지표를 사용합니다. 더미 모델의 성능을 이러한 지표들을 통해 확인하고, 앞으로 개발할 모델의 목표 성능을 설정하는 데 활용합니다.
*   **R2 점수:** 더미 회귀 모델의 R2 점수는 일반적으로 0에 가깝거나 음수입니다. R2 점수가 0이라는 것은 모델이 타겟 변수의 분산을 전혀 설명하지 못한다는 의미이며, 음수라는 것은 평균으로 예측하는 것보다도 못한 성능을 보인다는 의미입니다. 이는 더미 모델이 '최저선'임을 명확히 보여줍니다.
*   **이상치 영향:** 타겟 변수에 이상치가 많다면 평균보다는 중앙값 전략을 사용하는 더미 모델이 더 안정적인 베이스라인을 제공할 수 있습니다.

## 4. 베이스라인을 넘어서

베이스라인 모델을 성공적으로 수립하고 그 성능을 이해했다면, 이제 이 기준점을 넘어서 모델의 성능을 더욱 향상시키기 위한 다음 단계들을 계획할 수 있습니다. 이 과정은 일반적으로 반복적이며, 다양한 기법들을 시도하고 평가하는 과정을 포함합니다.

1.  **더 정교한 특성 공학 (Advanced Feature Engineering):**
    *   원시 데이터에서 모델이 학습하기 어려운 숨겨진 패턴이나 관계를 발굴하여 새로운 특성을 생성합니다. 도메인 지식을 활용하거나, 통계적 분석, 또는 다른 머신러닝 기법(예: 차원 축소, 클러스터링)을 통해 새로운 특성을 만들 수 있습니다.
    *   예시: 날짜/시간 특성에서 요일, 월, 분기, 공휴일 여부 추출; 텍스트 데이터에서 TF-IDF, 워드 임베딩 생성; 이미지 데이터에서 엣지, 코너, 또는 사전 학습된 모델의 특징 추출.

2.  **더 복잡하고 성능이 좋은 모델 시도 (Exploring More Complex Models):**
    *   베이스라인 모델이 선형 모델이나 단순한 트리 모델이었다면, 이제는 비선형 관계나 복잡한 패턴을 더 잘 학습할 수 있는 모델들을 시도해볼 수 있습니다.
    *   예시:
        *   **앙상블 모델 (Ensemble Models):** 여러 개의 약한 학습기(weak learners)를 결합하여 더 강력한 예측 성능을 내는 모델입니다. `RandomForest`, `GradientBoosting`, `XGBoost`, `LightGBM` 등이 있습니다. 이들은 일반적으로 단일 모델보다 높은 성능을 보입니다.
        *   **서포트 벡터 머신 (SVM):** 커널 트릭을 사용하여 비선형 결정 경계를 학습할 수 있습니다.
        *   **신경망 (Neural Networks):** 특히 비정형 데이터(이미지, 텍스트, 음성)나 매우 복잡한 패턴을 가진 데이터에서 뛰어난 성능을 발휘합니다.

3.  **하이퍼파라미터 튜닝 (Hyperparameter Tuning):**
    *   선택한 모델의 성능을 최적화하기 위해 하이퍼파라미터(모델 학습 전에 설정하는 파라미터)의 최적 조합을 찾습니다. `GridSearchCV`, `RandomizedSearchCV`와 같은 도구를 사용하여 체계적으로 탐색할 수 있습니다.
    *   적절한 하이퍼파라미터 튜닝은 모델의 성능을 크게 향상시킬 수 있습니다.

4.  **오류 분석 (Error Analysis):**
    *   모델이 잘못 예측하는 샘플들을 심층적으로 분석하여, 어떤 유형의 데이터에서 모델이 취약한지 파악합니다. 이를 통해 추가적인 특성 공학의 아이디어를 얻거나, 데이터 수집의 필요성을 발견할 수 있습니다.

5.  **데이터 증강 (Data Augmentation):**
    *   특히 이미지나 텍스트와 같이 데이터가 부족한 경우, 기존 데이터를 변형하여 새로운 훈련 데이터를 생성함으로써 모델의 일반화 성능을 높일 수 있습니다.

베이스라인 모델은 머신러닝 프로젝트의 나침반과 같습니다. 항상 베이스라인을 먼저 설정하고, 이를 기준으로 모델을 점진적으로 개선해나가는 습관을 들이는 것이 성공적인 프로젝트의 핵심입니다. 이 반복적인 과정을 통해 모델의 성능을 지속적으로 향상시키고, 실제 문제 해결에 기여할 수 있는 강력한 모델을 구축할 수 있습니다.
