### 1. CSV/Excel의 한계

CSV(Comma Separated Values)와 Microsoft Excel 파일은 데이터 교환 및 보고서 작성에 있어 가장 널리 사용되는 형식입니다. 그 이유는 뛰어난 **범용성**과 **인간 가독성** 때문입니다. CSV는 일반 텍스트 편집기로도 쉽게 열어볼 수 있고, Excel은 스프레드시트 프로그램으로 데이터를 시각적으로 확인하고 수동으로 편집하기 용이합니다. 그러나 이러한 장점에도 불구하고, 데이터의 규모가 커지거나 복잡한 분석 워크플로우에 통합될 때 다음과 같은 심각한 한계에 직면하게 됩니다.

*   **1.1. 텍스트 기반의 비효율성**:
    *   **느린 읽기/쓰기 속도**: CSV와 Excel 파일은 데이터를 순수한 텍스트 문자열 형태로 저장합니다. 파일을 읽을 때마다 이 텍스트를 숫자, 날짜, 불리언 등 실제 데이터 타입으로 변환(파싱)하는 과정이 필요합니다. 이 파싱 과정은 CPU 집약적이며, 대규모 데이터셋에서는 상당한 시간을 소모하여 데이터 로딩 및 저장 속도를 현저히 저하시킵니다.
    *   **비효율적인 저장 공간**: 예를 들어, 숫자 `12345`는 텍스트로 저장될 때 5바이트를 차지하지만, 이진(binary) 형식의 정수형으로 저장되면 2바이트 또는 4바이트만으로 충분할 수 있습니다. 모든 데이터를 텍스트로 저장함으로써 파일 크기가 불필요하게 커지고, 이는 디스크 공간 낭비와 네트워크 전송 시간 증가로 이어집니다.

*   **1.2. 스키마(Schema) 정보 부재**:
    *   CSV 파일은 데이터 타입, 컬럼명, 데이터의 의미 등 데이터에 대한 구조적 정보(스키마)를 자체적으로 포함하지 않습니다. Excel 파일은 시트 내에 컬럼명과 같은 일부 정보를 포함할 수 있지만, 각 컬럼의 정확한 데이터 타입(예: 정수, 실수, 날짜, 문자열)에 대한 명시적인 정보는 없습니다.
    *   이로 인해 파일을 읽을 때마다 Pandas와 같은 라이브러리가 각 컬럼의 데이터 타입을 "추론"해야 합니다. 이 추론 과정은 오류를 유발할 수 있으며, 특히 데이터에 일관되지 않은 값이 섞여 있을 경우(예: 숫자 컬럼에 몇몇 문자열이 포함된 경우) 전체 컬럼이 `object` (문자열) 타입으로 잘못 인식되어 후속 분석에 문제가 발생할 수 있습니다.
    *   데이터 타입 추론은 대규모 파일에서 로딩 시간을 더욱 지연시키는 원인이 됩니다.

*   **1.3. 컬럼 기반 연산의 비효율성 (행 지향 저장)**:
    *   CSV와 Excel 파일은 데이터를 기본적으로 "행(row) 지향" 방식으로 저장합니다. 즉, 한 행의 모든 컬럼 데이터가 순서대로 저장된 후 다음 행이 이어지는 방식입니다.
    *   데이터 분석에서는 종종 특정 컬럼(예: `매출액` 컬럼의 합계, `지역` 컬럼의 고유값)만 선택적으로 읽거나 연산해야 하는 경우가 많습니다. 행 지향 포맷에서는 특정 컬럼의 데이터만 필요하더라도 해당 컬럼이 포함된 모든 행을 읽어와야 하므로, 불필요한 I/O(입출력) 작업이 발생하여 비효율적입니다.
    *   이는 특히 수백 개 이상의 컬럼을 가진 넓은(wide) 데이터셋에서 심각한 성능 저하를 초래합니다.

*   **1.4. 압축 효율성 및 분산 처리의 한계**:
    *   텍스트 기반 포맷은 이진 포맷에 비해 압축 효율이 떨어지는 경향이 있습니다. 데이터 중복이 많더라도 텍스트 인코딩의 특성상 높은 압축률을 달성하기 어렵습니다.
    *   또한, CSV와 Excel 파일은 대규모 분산 처리 시스템(예: Apache Spark, Hadoop)에서 효율적으로 병렬 처리하기 어렵습니다. 파일 전체를 읽어야만 데이터의 시작과 끝을 정확히 파악할 수 있어, 데이터를 여러 노드에 분할하여 처리하는 데 제약이 따릅니다.

이러한 한계점들 때문에, 데이터의 규모가 커지거나 분석 파이프라인의 성능이 중요해질수록 CSV나 Excel 대신 Parquet, Feather와 같은 **고성능 이진 파일 포맷**을 사용하는 것이 필수적입니다.

### 2. Parquet 포맷

Parquet은 Apache Hadoop 생태계에서 대규모 분석 워크로드에 최적화된 **컬럼 기반(columnar)** 이진(Binary) 파일 포맷입니다. 이는 Google의 Dremel 논문을 기반으로 개발되었으며, 빅데이터 환경에서 데이터 저장 및 처리에 있어 사실상의 표준으로 자리 잡았습니다. CSV나 Excel과 같은 행(row) 기반 텍스트 포맷의 한계를 극복하기 위해 설계되었습니다.

#### 2.1. Parquet의 주요 특징 및 장점

*   **2.1.1. 컬럼 기반 저장 (Columnar Storage)**:
    *   Parquet은 데이터를 행 단위가 아닌 **컬럼 단위로 저장**합니다. 즉, 파일 내에서 특정 컬럼의 모든 값이 연속적으로 저장되고, 그 다음 컬럼의 모든 값이 저장되는 방식입니다.
    *   **효율적인 읽기 (Column Pruning)**: 데이터 분석에서는 종종 전체 컬럼 중 일부 컬럼만 필요한 경우가 많습니다. 컬럼 기반 저장 덕분에 Parquet은 필요한 컬럼의 데이터만 읽어올 수 있어(Column Pruning), 불필요한 I/O 작업을 최소화하고 읽기 속도를 크게 향상시킵니다.
    *   **효율적인 필터링 (Predicate Pushdown)**: 쿼리 조건(예: `WHERE category = 'A'`)이 특정 컬럼에만 적용될 경우, Parquet은 해당 컬럼의 메타데이터를 활용하여 조건에 맞지 않는 데이터 블록을 아예 읽지 않고 건너뛸 수 있습니다(Predicate Pushdown). 이는 데이터 로딩 시간을 더욱 단축시킵니다.

*   **2.1.2. 높은 압축률 및 인코딩 효율성**:
    *   컬럼 기반 저장 방식은 동일한 데이터 타입의 값들이 한 곳에 모여 있게 합니다. 이는 데이터 중복이 많거나 패턴이 있는 경우(예: `category` 컬럼의 'A', 'B', 'C' 반복) **매우 효율적인 압축 알고리즘**을 적용할 수 있게 합니다 (예: Run-Length Encoding, Dictionary Encoding).
    *   또한, 숫자형 데이터는 텍스트가 아닌 이진 형태로 저장되므로, CSV에 비해 훨씬 적은 공간을 차지합니다. 결과적으로 Parquet 파일은 CSV 파일보다 훨씬 작아 디스크 공간을 절약하고 네트워크 전송 비용을 줄입니다.

*   **2.1.3. 스키마(Schema) 정보 포함**:
    *   Parquet 파일은 데이터 자체뿐만 아니라, 각 컬럼의 이름, 데이터 타입, 중첩 구조 등 **완전한 스키마 정보를 파일 내에 포함**합니다. 이는 CSV처럼 파일을 읽을 때마다 데이터 타입을 추론할 필요가 없어 로딩 시간을 단축시키고, 데이터 타입 추론 오류를 방지합니다.
    *   스키마 정보는 데이터의 일관성과 무결성을 유지하는 데 도움을 줍니다.

*   **2.1.4. 빅데이터 생태계와의 통합**:
    *   Parquet은 Apache Spark, Apache Hive, Apache Impala, Dask 등 다양한 빅데이터 처리 프레임워크 및 분산 시스템과 완벽하게 호환됩니다. 이러한 시스템들은 Parquet의 컬럼 기반 특성을 활용하여 대규모 데이터셋에 대한 병렬 처리 및 분석 성능을 극대화합니다.
    *   클라우드 기반 데이터 웨어하우스(예: Amazon Redshift Spectrum, Google BigQuery, Azure Synapse Analytics)에서도 Parquet을 기본적으로 지원하여 효율적인 데이터 쿼리를 가능하게 합니다.

*   **2.1.5. 언어 독립적**: Parquet은 특정 프로그래밍 언어에 종속되지 않는 개방형 표준입니다. Python, Java, Scala, R 등 다양한 언어에서 Parquet 파일을 생성하고 읽을 수 있습니다.

#### 2.2. Pandas를 이용한 Parquet 입출력

Pandas는 `read_parquet()` 함수와 `DataFrame.to_parquet()` 메서드를 통해 Parquet 파일과의 손쉬운 입출력을 지원합니다. 이를 사용하려면 `pyarrow` 또는 `fastparquet` 라이브러리 중 하나가 설치되어 있어야 합니다. `pyarrow`가 더 광범위하게 사용되고 성능이 우수하여 일반적으로 권장됩니다.

**필수 라이브러리 설치:**
```bash
pip install pyarrow # 권장
# 또는
pip install fastparquet
```

**예시 코드:**
대규모 `DataFrame`을 생성하고 이를 Parquet 파일로 저장한 후 다시 읽어오는 과정을 보여줍니다. 파일 크기 및 로딩 시간의 효율성을 체감할 수 있습니다.

```python
import pandas as pd
import numpy as np
import os # 파일 삭제를 위해 os 모듈 임포트
import time # 시간 측정을 위해 time 모듈 임포트

# 1. 예시 DataFrame 생성 (100만 행 데이터)
# CSV/Excel의 한계를 체감하기 위해 대규모 데이터를 생성합니다.
with pd.option_context('display.max_rows', None, 'display.max_columns', None):
    df_large = pd.DataFrame({
        'id': np.arange(1_000_000),
        'value': np.random.rand(1_000_000),
        'category': np.random.choice(['A', 'B', 'C', 'D', 'E'], 1_000_000),
        'timestamp': pd.to_datetime(pd.date_range('2020-01-01', periods=1_000_000, freq='s'))
    })
print("\n1. 대규모 DataFrame 생성 완료 (1,000,000 행).")
print("DataFrame 정보:\n")
df_large.info()

# 2. Parquet 파일로 저장
parquet_file = 'large_data.parquet'

# index=False: DataFrame의 인덱스를 Parquet 파일에 저장하지 않습니다. 
# 일반적으로 인덱스는 분석에 필요하지 않거나, 데이터베이스의 기본 인덱스와 충돌할 수 있으므로 False로 설정하는 것이 좋습니다.
print(f"\n2. '{parquet_file}' 파일로 저장 중...")
start_time = time.time()
df_large.to_parquet(parquet_file, index=False)
end_time = time.time()
print(f"저장 완료. 소요 시간: {end_time - start_time:.4f} 초")
print(f"파일 크기: {os.path.getsize(parquet_file) / (1024 * 1024):.2f} MB")

# (참고) 동일 데이터를 CSV로 저장 시 파일 크기 비교
# csv_file = 'large_data.csv'
# df_large.to_csv(csv_file, index=False)
# print(f"CSV 파일 크기: {os.path.getsize(csv_file) / (1024 * 1024):.2f} MB")
# os.remove(csv_file)

# 3. Parquet 파일 읽기
print(f"\n3. '{parquet_file}' 파일 읽기 중...")
start_time = time.time()
df_from_parquet = pd.read_parquet(parquet_file)
end_time = time.time()
print(f"읽기 완료. 소요 시간: {end_time - start_time:.4f} 초")

print("Read from Parquet - Head:\n", df_from_parquet.head())
print("Read from Parquet - Info:\n")
df_from_parquet.info()

# 4. 특정 컬럼만 읽기 (Column Pruning 효과 확인)
# Parquet의 가장 큰 장점 중 하나인 Column Pruning을 확인합니다.
# 'id'와 'category' 컬럼만 읽어옵니다.
print("\n4. Parquet 파일에서 'id'와 'category' 컬럼만 읽기 중...")
start_time = time.time()
df_partial_parquet = pd.read_parquet(parquet_file, columns=['id', 'category'])
end_time = time.time()
print(f"부분 읽기 완료. 소요 시간: {end_time - start_time:.4f} 초")
print("Read from Parquet (partial) - Head:\n", df_partial_parquet.head())
print("Read from Parquet (partial) - Info:\n")
df_partial_parquet.info()

# 예시 파일 삭제
if os.path.exists(parquet_file):
    os.remove(parquet_file)
    print(f"\n'{parquet_file}' 파일 삭제 완료.")
```

**결과 설명:**
*   **파일 크기**: Parquet 파일은 동일한 데이터를 CSV로 저장했을 때보다 훨씬 작은 크기를 가집니다. 이는 효율적인 이진 저장과 압축 덕분입니다.
*   **읽기/쓰기 속도**: Parquet은 CSV나 Excel에 비해 훨씬 빠른 읽기/쓰기 속도를 보여줍니다. 특히 대규모 데이터셋에서 그 차이가 두드러집니다.
*   **데이터 타입 유지**: `read_parquet()`로 불러온 `DataFrame`은 원본 `DataFrame`의 데이터 타입을 정확히 유지합니다. 이는 스키마 정보가 파일 내에 포함되어 있기 때문입니다.
*   **컬럼 선택적 읽기 (Column Pruning)**: `columns` 옵션을 사용하여 특정 컬럼만 읽어올 때, Parquet은 해당 컬럼의 데이터만 디스크에서 읽어오므로 전체 파일을 읽는 것보다 훨씬 빠르게 로드됩니다. 이는 분석에 필요한 데이터만 효율적으로 가져올 수 있게 합니다.

Parquet 포맷은 대규모 데이터 분석 파이프라인에서 데이터 저장 및 교환의 핵심적인 역할을 수행하며, 성능과 효율성 측면에서 압도적인 이점을 제공합니다.

### 3. Feather 포맷

Feather는 Python(Pandas)과 R 언어 간의 데이터 교환을 위해 설계된 **경량(lightweight)**의 **컬럼 기반(columnar)** 이진 파일 포맷입니다. Apache Arrow 프로젝트의 일부로 개발되었으며, 특히 인메모리(in-memory) 데이터 전송에 최적화되어 있어 Pandas `DataFrame`을 다른 시스템이나 언어로 매우 빠르게 직렬화(serialize)하고 역직렬화(deserialize)할 수 있습니다.

#### 3.1. Feather의 주요 특징 및 장점

*   **3.1.1. 매우 빠른 읽기/쓰기 속도**:
    *   Feather의 가장 큰 장점은 압도적인 읽기/쓰기 속도입니다. 인메모리 데이터 구조를 거의 그대로 디스크에 매핑하는 방식으로 설계되어, 데이터 파싱이나 복잡한 인코딩/디코딩 과정이 최소화됩니다.
    *   이는 특히 Python 환경 내에서 Pandas `DataFrame`을 파일로 저장했다가 다시 불러오는 작업, 또는 Python과 R과 같은 다른 언어 간에 `DataFrame`을 주고받을 때 빛을 발합니다.

*   **3.1.2. 컬럼 기반 저장 (Columnar Storage)**:
    *   Parquet과 마찬가지로 데이터를 컬럼 단위로 저장합니다. 이로 인해 특정 컬럼만 읽거나 필터링할 때 효율적입니다.
    *   하지만 Parquet처럼 복잡한 압축 알고리즘이나 Predicate Pushdown 기능은 상대적으로 단순합니다. Feather는 주로 "빠른 데이터 전송"에 초점을 맞춥니다.

*   **3.1.3. 간단한 스키마 정보 포함**:
    *   Feather 파일은 컬럼명과 데이터 타입 등 기본적인 스키마 정보를 포함합니다. 이는 `read_feather()` 시 데이터 타입 추론 없이 빠르게 `DataFrame`을 재구성할 수 있게 합니다.
    *   Parquet에 비해 스키마 기능이 단순하며, 주로 Pandas `DataFrame`의 스키마를 그대로 반영하는 데 적합합니다.

*   **3.1.4. 언어 간 호환성 (Cross-language Compatibility)**:
    *   Python(Pandas)과 R(data.frame) 사용자 간에 대규모 `DataFrame`을 쉽고 빠르게 공유할 수 있도록 설계되었습니다. 이는 이기종 분석 환경에서 협업할 때 매우 유용합니다.

*   **3.1.5. 경량 및 단순성**:
    *   파일 포맷 자체가 비교적 단순하고 경량입니다. 이는 구현 복잡성을 줄이고 빠른 성능을 달성하는 데 기여합니다.

#### 3.2. Feather의 한계

*   **분산 처리 기능 부족**: Parquet과 달리 Feather는 대규모 분산 처리 시스템(예: Hadoop, Spark)에서의 사용을 염두에 두고 설계되지 않았습니다. 따라서 빅데이터 파이프라인의 최종 저장 형식으로는 Parquet이 더 적합합니다.
*   **압축 효율성**: Parquet만큼 강력한 압축 기능을 제공하지는 않습니다. 따라서 디스크 공간 절약이 최우선 목표라면 Parquet이 더 유리할 수 있습니다.
*   **데이터 수정의 어려움**: Feather 파일은 한 번 저장되면 데이터를 부분적으로 수정하기 어렵습니다. 전체 파일을 다시 쓰고 읽어야 하는 경우가 많습니다.

#### 3.3. Pandas를 이용한 Feather 입출력

Pandas는 `read_feather()` 함수와 `DataFrame.to_feather()` 메서드를 통해 Feather 파일과의 손쉬운 입출력을 지원합니다. Feather 파일 처리를 위해서는 `pyarrow` 라이브러리가 설치되어 있어야 합니다.

**예시 코드:**
대규모 `DataFrame`을 생성하고 이를 Feather 파일로 저장한 후 다시 읽어오는 과정을 보여줍니다. Parquet 예시와 동일한 `df_large`를 사용하여 성능을 비교할 수 있습니다.

```python
import pandas as pd
import numpy as np
import os # 파일 삭제를 위해 os 모듈 임포트
import time # 시간 측정을 위해 time 모듈 임포트

# 1. 예시 DataFrame 생성 (Parquet 예시와 동일한 데이터 사용)
# 이 DataFrame은 이미 메모리에 있다고 가정합니다.
df_large = pd.DataFrame({
    'id': np.arange(1_000_000),
    'value': np.random.rand(1_000_000),
    'category': np.random.choice(['A', 'B', 'C', 'D', 'E'], 1_000_000),
    'timestamp': pd.to_datetime(pd.date_range('2020-01-01', periods=1_000_000, freq='s'))
})
print("\n1. 대규모 DataFrame 생성 완료 (1,000,000 행).")
print("DataFrame 정보:\n")
df_large.info()

# 2. Feather 파일로 저장
feather_file = 'large_data.feather'

# Feather는 기본적으로 인덱스를 저장하지 않습니다. (to_feather는 index=False 옵션이 없음)
print(f"\n2. '{feather_file}' 파일로 저장 중...")
start_time = time.time()
df_large.to_feather(feather_file) 
end_time = time.time()
print(f"저장 완료. 소요 시간: {end_time - start_time:.4f} 초")
print(f"파일 크기: {os.path.getsize(feather_file) / (1024 * 1024):.2f} MB")

# (참고) 동일 데이터를 CSV로 저장 시 파일 크기 비교
# csv_file = 'large_data_feather_comp.csv'
# df_large.to_csv(csv_file, index=False)
# print(f"CSV 파일 크기: {os.path.getsize(csv_file) / (1024 * 1024):.2f} MB")
# os.remove(csv_file)

# 3. Feather 파일 읽기
print(f"\n3. '{feather_file}' 파일 읽기 중...")
start_time = time.time()
df_from_feather = pd.read_feather(feather_file)
end_time = time.time()
print(f"읽기 완료. 소요 시간: {end_time - start_time:.4f} 초")

print("Read from Feather - Head:\n", df_from_feather.head())
print("Read from Feather - Info:\n")
df_from_feather.info()

# 예시 파일 삭제
if os.path.exists(feather_file):
    os.remove(feather_file)
    print(f"\n'{feather_file}' 파일 삭제 완료.")
```

**결과 설명:**
*   **파일 크기**: Feather 파일은 Parquet보다는 약간 클 수 있지만, CSV에 비해서는 훨씬 작은 크기를 가집니다. 이는 효율적인 이진 저장 방식 덕분입니다.
*   **읽기/쓰기 속도**: Feather는 인메모리 데이터 전송에 최적화되어 있어, Parquet과 유사하거나 경우에 따라 더 빠른 읽기/쓰기 속도를 보여줍니다. 특히 Python 환경 내에서의 빠른 데이터 직렬화/역직렬화에 강점을 가집니다.
*   **데이터 타입 유지**: `read_feather()`로 불러온 `DataFrame`은 원본 `DataFrame`의 데이터 타입을 정확히 유지합니다.

Feather 포맷은 주로 Python과 R과 같은 언어 간에 `DataFrame`을 빠르고 효율적으로 교환하거나, 분석 파이프라인 내에서 중간 결과물을 빠르게 저장하고 불러와야 할 때 매우 유용합니다. 장기 저장이나 분산 처리 환경에서는 Parquet이 더 적합할 수 있습니다.


### 4. 기타 고성능 포맷 (간략히)

-   **HDF5 (Hierarchical Data Format 5)**: 복잡하고 계층적인 데이터 구조를 저장하는 데 적합합니다. 대규모 과학 데이터 저장에 많이 사용됩니다. Pandas는 `read_hdf()`, `to_hdf()`를 제공합니다.
-   **Pickle**: Python 객체를 직렬화(serialize)하여 파일로 저장하는 Python 고유의 포맷입니다. Pandas DataFrame도 Pickle로 저장할 수 있지만, Python 환경에 종속적이며 보안에 취약할 수 있습니다.

-   **인간 가독성 및 소규모 데이터**: 여전히 **CSV**나 **Excel**이 편리할 수 있습니다.
