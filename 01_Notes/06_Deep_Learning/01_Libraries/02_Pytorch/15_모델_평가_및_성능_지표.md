## 1. 모델 평가의 중요성 및 기본 개념

### 1.1. 왜 모델을 평가해야 하는가?
딥러닝 모델을 학습시키는 것은 최종 목표가 아닙니다. 학습된 모델이 실제 문제에서 얼마나 잘 작동하는지, 즉 **일반화(Generalization)** 능력이 얼마나 뛰어난지를 평가하는 것이 중요합니다. 모델 평가는 다음과 같은 이유로 필수적입니다.
- **모델 성능 검증**: 학습된 모델이 새로운, 보지 못한 데이터에 대해 얼마나 정확하게 예측하는지 확인합니다.
- **모델 선택**: 여러 모델 중 가장 좋은 성능을 보이는 모델을 선택하는 기준이 됩니다.
- **과적합/과소적합 진단**: 모델이 데이터에 너무 과하게 학습되었는지(과적합) 또는 충분히 학습되지 않았는지(과소적합)를 파악합니다.
- **모델 개선 방향 제시**: 어떤 부분이 부족하고, 어떻게 개선해야 할지 힌트를 얻습니다.

### 1.2. 과적합(Overfitting)과 과소적합(Underfitting)
- **과소적합 (Underfitting)**: 모델이 너무 단순하거나 학습이 충분히 이루어지지 않아 훈련 데이터의 패턴조차 제대로 학습하지 못한 상태입니다. 훈련 데이터와 테스트 데이터 모두에서 성능이 낮게 나타납니다.
- **과적합 (Overfitting)**: 모델이 훈련 데이터에 너무 과하게 학습되어 훈련 데이터에서는 높은 성능을 보이지만, 새로운(테스트) 데이터에서는 성능이 급격히 떨어지는 상태입니다. 모델이 훈련 데이터의 노이즈나 특정 패턴까지 외워버린 경우 발생합니다.

### 1.3. 데이터셋 분할: 훈련, 검증, 테스트
모델의 일반화 성능을 정확하게 평가하기 위해 데이터셋을 세 가지로 분할하는 것이 일반적입니다.
- **훈련 세트 (Training Set)**: 모델을 학습시키는 데 사용되는 데이터입니다. 모델은 이 데이터를 통해 패턴을 학습하고 가중치를 업데이트합니다.
- **검증 세트 (Validation Set)**: 모델의 하이퍼파라미터 튜닝, 조기 종료(Early Stopping) 등 모델 학습 과정에서 성능을 모니터링하고 최적의 모델을 선택하는 데 사용됩니다. 훈련 과정에 직접적으로 사용되지는 않지만, 모델 선택에 영향을 미치므로 테스트 세트와는 독립적이어야 합니다.
- **테스트 세트 (Test Set)**: 모델 학습 및 하이퍼파라미터 튜닝이 모두 완료된 후, 모델의 최종 성능을 단 한 번만 평가하는 데 사용됩니다. 이 데이터는 모델 학습 과정에서 절대 사용되어서는 안 됩니다.

## 2. 분류 모델 성능 지표

### 2.1. 혼동 행렬 (Confusion Matrix)
혼동 행렬은 분류 모델의 성능을 시각적으로 요약해주는 표입니다. 실제 클래스와 모델이 예측한 클래스 간의 관계를 보여줍니다. 이진 분류의 경우 다음과 같이 구성됩니다.
- **True Positive (TP)**: 실제 양성(Positive)을 양성으로 올바르게 예측
- **True Negative (TN)**: 실제 음성(Negative)을 음성으로 올바르게 예측
- **False Positive (FP)**: 실제 음성을 양성으로 잘못 예측 (1종 오류)
- **False Negative (FN)**: 실제 양성을 음성으로 잘못 예측 (2종 오류)

### 2.2. 정확도 (Accuracy)
정확도는 전체 예측 중 올바르게 예측한 비율입니다. 가장 직관적인 지표이지만, 데이터셋이 불균형할 경우 모델의 실제 성능을 왜곡할 수 있습니다.
`Accuracy = (TP + TN) / (TP + TN + FP + FN)`

### 2.3. 정밀도 (Precision), 재현율 (Recall), F1-점수 (F1-Score)
정확도의 한계를 보완하기 위해 사용되는 지표들입니다.
- **정밀도 (Precision)**: 모델이 양성으로 예측한 것들 중에서 실제로 양성인 비율입니다. FP를 줄이는 것이 중요할 때 사용됩니다. (예: 스팸 메일 분류 - 스팸이 아닌 메일을 스팸으로 분류하면 안 됨)
  `Precision = TP / (TP + FP)`
- **재현율 (Recall) / 민감도 (Sensitivity)**: 실제 양성인 것들 중에서 모델이 올바르게 양성으로 예측한 비율입니다. FN을 줄이는 것이 중요할 때 사용됩니다. (예: 암 진단 - 실제 암 환자를 놓치면 안 됨)
  `Recall = TP / (TP + FN)`
- **F1-점수 (F1-Score)**: 정밀도와 재현율의 조화 평균입니다. 두 지표가 모두 중요할 때 사용됩니다.
  `F1-Score = 2 * (Precision * Recall) / (Precision + Recall)`

### 2.4. ROC 곡선 (Receiver Operating Characteristic Curve) 및 AUC (Area Under the Curve)
ROC 곡선은 분류 모델의 임계값(threshold) 변화에 따른 재현율(True Positive Rate, TPR)과 위양성률(False Positive Rate, FPR)의 관계를 시각화한 것입니다.
- **TPR (재현율)**: `TP / (TP + FN)`
- **FPR**: `FP / (FP + TN)`
AUC는 ROC 곡선 아래 면적을 의미하며, 0부터 1까지의 값을 가집니다. 1에 가까울수록 좋은 모델이며, 0.5는 무작위 분류와 같습니다. AUC는 모델의 전반적인 분류 성능을 나타내는 좋은 지표입니다.

### 2.5. 다중 클래스 분류 지표
다중 클래스 분류에서는 각 클래스에 대한 정밀도, 재현율, F1-점수를 계산한 후, 이를 평균하여 전체 성능을 평가합니다.
- **Macro Average**: 각 클래스의 지표를 계산한 후 단순 평균합니다. 클래스 불균형에 민감합니다.
- **Micro Average**: 모든 클래스의 TP, FP, FN을 합산한 후 지표를 계산합니다. 클래스 불균형의 영향을 덜 받습니다.
- **Weighted Average**: 각 클래스의 샘플 수에 따라 가중치를 부여하여 평균합니다.

## 3. 회귀 모델 성능 지표

### 3.1. 평균 제곱 오차 (Mean Squared Error, MSE)
MSE는 예측값과 실제값 차이의 제곱에 대한 평균입니다. 오차가 클수록 제곱으로 인해 페널티가 커지므로, 큰 오차에 민감하게 반응합니다.
`MSE = (1/n) * Σ(y_i - ŷ_i)²`

### 3.2. 평균 절대 오차 (Mean Absolute Error, MAE)
MAE는 예측값과 실제값 차이의 절댓값에 대한 평균입니다. MSE와 달리 이상치에 덜 민감하며, 오차의 크기를 직관적으로 이해하기 쉽습니다.
`MAE = (1/n) * Σ|y_i - ŷ_i|`

### 3.3. R-제곱 (R-squared, R²)
R-제곱은 모델이 분산의 몇 퍼센트를 설명하는지를 나타내는 지표입니다. 0부터 1까지의 값을 가지며, 1에 가까울수록 모델이 데이터를 잘 설명한다고 볼 수 있습니다.
`R² = 1 - (MSE / Variance(y))`

## 5. 모델 평가 시 고려 사항 및 고급 주제

### 5.1. 불균형 데이터셋 처리
클래스 불균형이 심한 데이터셋에서는 정확도만으로 모델 성능을 판단하기 어렵습니다. 이 경우 정밀도, 재현율, F1-점수, ROC-AUC와 같은 지표를 활용하고, 오버샘플링(SMOTE), 언더샘플링, 가중치 부여(class weighting) 등의 기법을 사용하여 모델이 소수 클래스를 더 잘 학습하도록 유도해야 합니다.

### 5.2. 교차 검증 (Cross-Validation)
데이터셋이 작거나, 훈련/검증/테스트 분할 방식에 따른 편향을 줄이고 싶을 때 교차 검증을 사용합니다. K-Fold 교차 검증은 데이터셋을 K개의 폴드(fold)로 나눈 후, K번의 학습을 수행하여 각 폴드를 한 번씩 검증 세트로 사용합니다. 이를 통해 모델 성능에 대한 더 신뢰할 수 있는 추정치를 얻을 수 있습니다.

### 5.3. 모델 해석 가능성 (Interpretability)
모델이 왜 특정 예측을 했는지 이해하는 것은 모델의 신뢰성을 높이고, 잠재적인 편향을 발견하며, 도메인 전문가의 통찰력을 얻는 데 중요합니다. SHAP, LIME, Grad-CAM과 같은 기술들은 딥러닝 모델의 '블랙박스'를 열어 예측에 영향을 미친 요소를 시각화하고 설명하는 데 도움을 줍니다.

### 5.4. 실전 배포 시 성능 지표
모델을 실제 서비스에 배포할 때는 오프라인 평가 지표 외에도 다음과 같은 실전 지표들을 고려해야 합니다.
- **추론 속도 (Inference Speed)**: 모델이 예측을 수행하는 데 걸리는 시간.
- **메모리 사용량 (Memory Usage)**: 모델이 사용하는 메모리 양.
- **처리량 (Throughput)**: 단위 시간당 처리할 수 있는 요청 수.
- **안정성 (Stability)**: 장시간 운영 시 모델의 성능 저하 여부.
- **비용 (Cost)**: 모델 운영에 필요한 컴퓨팅 자원 비용.
