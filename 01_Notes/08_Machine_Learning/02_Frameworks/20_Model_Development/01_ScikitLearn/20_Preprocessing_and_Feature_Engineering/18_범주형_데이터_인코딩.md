## 1. 데이터 전처리 (Data Preprocessing)

데이터 전처리는 머신러닝 모델의 성능에 결정적인 영향을 미치는 중요한 단계입니다. Scikit-learn은 다양한 전처리 도구를 제공하여 원시 데이터를 모델 학습에 적합한 형태로 변환할 수 있도록 돕습니다.

### 1.1. 범주형 데이터 인코딩 (Categorical Data Encoding)

머신러닝 모델은 대부분 숫자형 데이터를 입력으로 받기 때문에, '남', '여', '서울', '부산', '상', '중', '하'와 같은 범주형 데이터를 숫자형으로 변환하는 과정이 필수적입니다. 이 과정을 **인코딩(Encoding)**이라고 합니다. 범주형 데이터는 명목형(Nominal, 순서 없음)과 순서형(Ordinal, 순서 있음)으로 나눌 수 있으며, 각 유형에 따라 적절한 인코딩 방법을 선택해야 합니다. Scikit-learn은 `sklearn.preprocessing` 모듈을 통해 다양한 인코딩 방법을 제공합니다.

#### 1.1.1. `LabelEncoder`
`LabelEncoder`는 범주형 변수의 각 고유한 값에 0부터 N-1까지의 정수 레이블을 할당합니다. 예를 들어, ['red', 'green', 'blue']는 [0, 1, 2]로 변환됩니다.

*   **주요 사용처:** 주로 타겟 변수(종속 변수, `y`)와 같이 순서가 없는 범주형 데이터를 인코딩할 때 사용됩니다. 예를 들어, 분류 문제에서 클래스 레이블을 숫자로 변환할 때 유용합니다.
*   **주의사항:** 특성(독립 변수, `X`)에 `LabelEncoder`를 직접 적용할 경우, 모델이 범주 간에 임의의 순서 관계(예: 0 < 1 < 2)가 있다고 잘못 학습할 수 있습니다. 이는 모델의 성능에 부정적인 영향을 미칠 수 있으므로, 특성 인코딩에는 `OneHotEncoder`와 같은 다른 방법을 고려해야 합니다.

```python
import numpy as np
from sklearn.preprocessing import LabelEncoder

# 범주형 데이터 (1차원 배열 형태)
data = np.array(['red', 'green', 'blue', 'red', 'green'])
print("원본 데이터:", data)

# LabelEncoder 객체 생성
encoder = LabelEncoder()
# fit_transform(): 훈련 데이터로부터 고유한 범주를 학습(fit)하고, 데이터를 정수 레이블로 변환(transform)합니다.
data_encoded = encoder.fit_transform(data)
print("
인코딩된 데이터:", data_encoded)
# encoder.classes_: 학습된 고유한 범주(원본 레이블)의 순서를 확인할 수 있습니다.
print("클래스 (원본 레이블):", encoder.classes_)

# 인코딩된 데이터를 다시 원본으로 디코딩
# inverse_transform(): 인코딩된 정수 레이블을 다시 원래의 범주형 값으로 되돌립니다.
data_decoded = encoder.inverse_transform(data_encoded)
print("
디코딩된 데이터:", data_decoded)
```

#### 1.1.2. `OneHotEncoder`
`OneHotEncoder`는 범주형 변수를 '원-핫(One-Hot)' 벡터로 변환합니다. 각 범주를 독립적인 이진(0 또는 1) 특성으로 표현하여, 모델이 범주 간의 잘못된 순서 관계를 학습하는 것을 방지합니다. 예를 들어, ['red', 'green', 'blue']는 각각 [1, 0, 0], [0, 1, 0], [0, 0, 1]과 같은 벡터로 변환됩니다.

*   **주요 사용처:** 주로 특성 변수(독립 변수, `X`)에 사용됩니다. 특히 명목형 범주(순서가 없는 범주)를 인코딩할 때 필수적입니다.
*   **장점:** 범주 간의 순서 관계를 모델에 부여하지 않아 모델의 오해를 방지합니다. 각 범주가 독립적인 특성으로 표현되므로, 선형 모델과 같이 특성 간의 선형 관계를 가정하는 모델에 적합합니다.
*   **단점:** 범주의 개수가 많아질수록 생성되는 특성의 수가 급격히 증가하여 데이터셋의 차원(Dimensionality)이 커지고, 메모리 사용량이 늘어날 수 있습니다 (차원의 저주).

```python
import numpy as np
from sklearn.preprocessing import OneHotEncoder

# 범주형 데이터 (OneHotEncoder는 2차원 배열 형태를 입력으로 받습니다.)
data = np.array([['red'], ['green'], ['blue'], ['red'], ['green']])
print("원본 데이터:\n", data)

# OneHotEncoder 객체 생성
# sparse_output=False로 설정하여 NumPy 배열로 반환합니다. (기본값은 희소 행렬)
# handle_unknown='ignore': 훈련 데이터에 없던 새로운 범주가 테스트 데이터에 나타날 경우, 해당 범주를 무시하고 0으로 채웁니다.
encoder = OneHotEncoder(sparse_output=False, handle_unknown='ignore')
# fit_transform(): 훈련 데이터로부터 고유한 범주를 학습하고, 데이터를 원-핫 인코딩된 배열로 변환합니다.
data_encoded = encoder.fit_transform(data)
print("\n원-핫 인코딩된 데이터:\n", data_encoded)
# encoder.categories_: 학습된 고유한 범주(원본 레이블)의 순서를 확인할 수 있습니다.
print("카테고리 (원본 레이블):", encoder.categories_)

# 새로운 데이터에 적용
# 훈련 데이터로 fit된 encoder를 사용하여 새로운 데이터를 변환합니다. (transform만 사용)
new_data = np.array([['blue'], ['red'], ['yellow']]) # 'yellow'는 훈련 데이터에 없던 새로운 범주
new_data_encoded = encoder.transform(new_data)
print("\n새로운 데이터에 적용된 원-핫 인코딩:\n", new_data_encoded)
# 'yellow'가 0으로 처리된 것을 확인할 수 있습니다.
```

#### 1.1.3. 고급 범주형 인코딩

`LabelEncoder`와 `OneHotEncoder`는 가장 기본적인 인코딩 방법이지만, 범주의 수가 매우 많거나(High Cardinality) 특정 모델에 더 적합한 인코딩이 필요할 때 고급 인코딩 기법을 고려할 수 있습니다. `category_encoders` 라이브러리는 이러한 다양한 고급 인코딩 방법을 제공합니다.

##### 1.1.3.1. 타겟 인코딩 (Target Encoding / Mean Encoding)

타겟 인코딩은 범주형 특성의 각 범주를 해당 범주에 속하는 샘플들의 타겟 변수(종속 변수)의 평균(회귀 문제) 또는 비율(분류 문제)로 대체하는 방법입니다. 이는 범주형 특성과 타겟 변수 간의 관계를 직접적으로 반영하므로, 모델이 이 관계를 더 쉽게 학습할 수 있도록 돕습니다.

*   **장점:**
    *   차원 증가가 없습니다 (하나의 숫자 특성으로 변환).
    *   범주형 특성과 타겟 변수 간의 관계를 직접적으로 반영하여 모델 성능 향상에 기여할 수 있습니다.
    *   범주의 수가 매우 많을 때(High Cardinality) 특히 효과적입니다.
*   **단점:**
    *   **데이터 누수(Data Leakage) 위험:** 훈련 데이터에서 타겟 변수의 정보를 사용하여 인코딩하므로, 테스트 데이터나 새로운 데이터에 적용할 때 데이터 누수가 발생할 수 있습니다. 이를 방지하기 위해 교차 검증(Cross-Validation) 기반의 타겟 인코딩(예: Leave-One-Out Encoding)을 사용해야 합니다.
    *   과적합 위험이 있습니다.

```python
import pandas as pd
from category_encoders import TargetEncoder
from sklearn.model_selection import train_test_split

# 예시 데이터 (분류 문제)
data_target = pd.DataFrame({
    'City': ['Seoul', 'Busan', 'Seoul', 'Jeju', 'Busan', 'Seoul', 'Jeju'],
    'Target': [1, 0, 1, 0, 1, 0, 1]
})

print("원본 데이터 (타겟 인코딩 예시):\n", data_target)

# 훈련/테스트 데이터 분할 (데이터 누수 방지를 위해)
X = data_target[['City']]
y = data_target['Target']
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

# TargetEncoder 객체 생성
# smoothing: 과적합을 줄이기 위한 스무딩 파라미터 (클수록 평균에 가까워짐)
encoder_target = TargetEncoder(cols=['City'], smoothing=0.1)

# 훈련 데이터에 fit_transform
X_train_encoded = encoder_target.fit_transform(X_train, y_train)
print("\n훈련 데이터 타겟 인코딩 결과:\n", X_train_encoded)

# 테스트 데이터에 transform (훈련 데이터로 학습된 인코더 사용)
X_test_encoded = encoder_target.transform(X_test)
print("\n테스트 데이터 타겟 인코딩 결과:\n", X_test_encoded)
```

##### 1.1.3.2. Leave-One-Out 인코딩 (LeaveOneOut Encoding)

Leave-One-Out 인코딩은 타겟 인코딩의 한 변형으로, 데이터 누수 문제를 완화하기 위해 사용됩니다. 특정 샘플의 범주를 인코딩할 때, 해당 샘플을 제외한 나머지 샘플들의 타겟 변수 평균/비율을 사용합니다. 이는 훈련 데이터 내에서 발생하는 데이터 누수를 방지합니다.

*   **장점:** 타겟 인코딩의 장점을 유지하면서 데이터 누수 위험을 크게 줄입니다.
*   **단점:** 계산 비용이 타겟 인코딩보다 높을 수 있습니다. 각 샘플마다 계산을 수행해야 하기 때문입니다.

```python
import pandas as pd
from category_encoders import LeaveOneOutEncoder
from sklearn.model_selection import train_test_split

# 예시 데이터 (분류 문제)
data_loo = pd.DataFrame({
    'City': ['Seoul', 'Busan', 'Seoul', 'Jeju', 'Busan', 'Seoul', 'Jeju'],
    'Target': [1, 0, 1, 0, 1, 0, 1]
})

X = data_loo[['City']]
y = data_loo['Target']
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

# LeaveOneOutEncoder 객체 생성
encoder_loo = LeaveOneOutEncoder(cols=['City'])

# 훈련 데이터에 fit_transform
X_train_encoded_loo = encoder_loo.fit_transform(X_train, y_train)
print("\n훈련 데이터 Leave-One-Out 인코딩 결과:\n", X_train_encoded_loo)

# 테스트 데이터에 transform
X_test_encoded_loo = encoder_loo.transform(X_test)
print("\n테스트 데이터 Leave-One-Out 인코딩 결과:\n", X_test_encoded_loo)
```

##### 1.1.3.3. 빈도 인코딩 (Frequency Encoding / Count Encoding)

빈도 인코딩은 범주형 특성의 각 범주를 해당 범주가 데이터셋에 나타나는 빈도(횟수) 또는 비율로 대체하는 방법입니다. 이는 타겟 변수의 정보를 사용하지 않으므로 데이터 누수 위험이 없습니다.

*   **장점:**
    *   데이터 누수 위험이 없습니다.
    *   차원 증가가 없습니다.
    *   계산이 간단하고 빠릅니다.
    *   범주의 수가 매우 많을 때 효과적입니다.
*   **단점:**
    *   동일한 빈도를 가지는 다른 범주들을 구분할 수 없습니다.
    *   타겟 변수와의 직접적인 관계를 반영하지 않습니다.

```python
import pandas as pd
from category_encoders import CountEncoder

# 예시 데이터
data_freq = pd.DataFrame({
    'City': ['Seoul', 'Busan', 'Seoul', 'Jeju', 'Busan', 'Seoul', 'Jeju'],
    'Target': [1, 0, 1, 0, 1, 0, 1]
})

print("원본 데이터 (빈도 인코딩 예시):\n", data_freq)

# CountEncoder 객체 생성
encoder_freq = CountEncoder(cols=['City'])

# 데이터에 fit_transform
data_encoded_freq = encoder_freq.fit_transform(data_freq[['City']])
print("\n빈도 인코딩 결과:\n", data_encoded_freq)
```

#### 1.1.4. 인코딩 방법 선택 가이드

*   **타겟 변수(y) 인코딩:** `LabelEncoder`를 사용합니다. 모델이 예측해야 하는 클래스 레이블은 순서가 중요하지 않으며, 대부분의 분류 모델은 정수형 레이블을 잘 처리합니다.
*   **특성 변수(X) 인코딩:**
    *   **명목형 범주 (순서 없음):**
        *   **범주 수가 적을 때**: `OneHotEncoder`를 사용합니다. 가장 안전하고 일반적인 방법입니다.
        *   **범주 수가 많을 때 (High Cardinality)**: `TargetEncoder` (데이터 누수 주의), `LeaveOneOutEncoder`, `CountEncoder` 등을 고려합니다. 이들은 차원 증가 없이 범주형 특성을 처리할 수 있습니다.
    *   **순서형 범주 (순서 있음):** `LabelEncoder`를 사용할 수 있지만, 범주 간의 실제 순서 관계를 반영하도록 수동으로 매핑하거나, Scikit-learn의 `OrdinalEncoder`를 사용하는 것이 더 좋습니다. 예를 들어, '소', '중', '대'와 같은 순서형 범주는 [0, 1, 2]로 인코딩될 수 있습니다.
    *   **트리 기반 모델:** 의사결정 트리, 랜덤 포레스트, 부스팅 모델과 같은 트리 기반 모델은 `LabelEncoder`로 인코딩된 특성도 잘 처리하는 경향이 있습니다. 이들은 내부적으로 분할 기준을 찾을 때 순서 관계에 덜 민감하기 때문입니다. 하지만 `OneHotEncoder`나 타겟 기반 인코딩을 사용하는 것이 더 안전하거나 성능 향상에 도움이 될 수 있습니다.

인코딩 방법의 선택은 모델의 성능과 해석 가능성에 영향을 미치므로, 데이터의 특성과 모델의 요구사항을 고려하여 신중하게 결정해야 합니다. 특히 `category_encoders` 라이브러리는 다양한 고급 인코딩 옵션을 제공하여 복잡한 범주형 데이터를 효과적으로 다룰 수 있도록 돕습니다.
