## 1. 결측치(Missing Values) 처리

### 1.1. 왜 결측치를 처리해야 하는가?
결측치(Missing Values)는 데이터셋에 값이 누락된 부분을 의미하며, 현실 세계의 데이터에서는 매우 흔하게 발생합니다. 데이터 수집 과정의 오류, 설문 응답 누락, 시스템 문제 등 다양한 원인으로 인해 발생할 수 있습니다. 이러한 결측치를 적절히 처리하는 것은 머신러닝 프로젝트의 성공에 매우 중요합니다.

결측치를 처리해야 하는 주요 이유는 다음과 같습니다:

1.  **모델 학습의 제약:** 대부분의 머신러닝 알고리즘(예: 선형 회귀, SVM, 신경망)은 결측치가 있는 데이터를 직접 처리할 수 없습니다. 즉, 입력 데이터에 `NaN` (Not a Number)과 같은 결측치가 포함되어 있으면 모델 학습 과정에서 오류가 발생하거나, 해당 샘플을 단순히 무시하게 됩니다. 이는 모델 학습을 불가능하게 하거나, 데이터 손실을 야기합니다.

2.  **성능 저하:** 결측치를 부적절하게 처리하거나 무시할 경우, 모델의 예측 성능이 크게 저하될 수 있습니다. 모델이 불완전한 데이터로부터 패턴을 학습하게 되므로, 실제 데이터의 복잡한 관계를 제대로 파악하지 못하게 됩니다.

3.  **통계적 편향 발생:** 결측치가 무작위로 발생하는 것이 아니라 특정 패턴을 가지고 발생하는 경우(예: 특정 그룹의 사람들이 특정 질문에 응답하지 않는 경향), 결측치를 단순히 제거하면 데이터셋에 통계적 편향(Bias)이 발생할 수 있습니다. 이는 모델이 편향된 데이터로부터 학습하여 잘못된 결론을 내리게 할 수 있습니다.

4.  **데이터셋의 완전성 및 일관성 유지:** 결측치 처리는 데이터셋의 완전성을 높이고, 분석 및 모델링을 위한 일관된 데이터 형식을 보장합니다. 이는 데이터 분석의 신뢰성을 높이는 데 기여합니다.

**결측치 처리(Imputation)**는 누락된 값을 합리적인 값으로 채워 넣어 데이터셋의 완전성을 높이는 과정입니다. 어떤 방법으로 결측치를 채울지는 결측치의 유형, 데이터의 특성, 그리고 문제의 도메인 지식에 따라 신중하게 결정해야 합니다. 잘못된 결측치 처리는 오히려 모델의 성능을 저하시키거나 잘못된 패턴을 학습하게 할 수 있습니다.

### 1.2. `SimpleImputer`
`SimpleImputer`는 Scikit-learn에서 제공하는 가장 기본적인 결측치 처리 도구입니다. 이는 각 특성(컬럼)별로 독립적으로 결측치를 대체하며, 평균(mean), 중앙값(median), 최빈값(most_frequent), 또는 상수(constant)와 같은 간단한 통계량으로 결측치를 채웁니다. 사용하기 쉽고 계산 비용이 낮다는 장점이 있지만, 특성 간의 관계를 고려하지 않는다는 한계가 있습니다.

```python
import numpy as np
from sklearn.impute import SimpleImputer
import pandas as pd

# 결측치가 포함된 데이터 (DataFrame 사용)
# 예시를 위해 Pandas DataFrame을 생성합니다. 실제 데이터는 CSV 파일 등에서 로드될 수 있습니다.
data = pd.DataFrame({
    'feature1': [1, 2, np.nan, 4, 5], # 숫자형 특성, 결측치 포함
    'feature2': [np.nan, 10, 11, 12, 13], # 숫자형 특성, 결측치 포함
    'feature3': [20, 21, 22, np.nan, 24], # 숫자형 특성, 결측치 포함
    'feature4': ['A', 'B', np.nan, 'A', 'C'] # 범주형 특성, 결측치 포함
})

print("원본 데이터:\n", data)

# 숫자형 특성 결측치 처리 (평균으로 대체)
# strategy='mean': 해당 특성의 평균값으로 결측치를 대체합니다.
# fit_transform(): 훈련 데이터로부터 대체할 값을 학습(fit)하고, 즉시 데이터를 변환(transform)합니다.
# 데이터프레임의 특정 컬럼을 선택할 때는 `data[['column_name']]`과 같이 2차원 배열 형태로 전달해야 합니다.
imputer_mean = SimpleImputer(strategy='mean')
data['feature1'] = imputer_mean.fit_transform(data[['feature1']])
data['feature3'] = imputer_mean.fit_transform(data[['feature3']])
print("\n평균으로 대체된 데이터 (feature1, feature3):\n", data)

# 범주형 특성 결측치 처리 (최빈값으로 대체)
# strategy='most_frequent': 해당 특성의 가장 자주 나타나는 값(최빈값)으로 결측치를 대체합니다.
imputer_most_frequent = SimpleImputer(strategy='most_frequent')
data['feature4'] = imputer_most_frequent.fit_transform(data[['feature4']])
print("\n최빈값으로 대체된 데이터 (feature4):\n", data)

# 참고: `strategy='median'` (중앙값)은 이상치에 덜 민감하여 숫자형 특성에 유용합니다.
# `strategy='constant'`는 `fill_value` 파라미터로 지정된 상수로 결측치를 대체합니다.
```

**`SimpleImputer` 사용 시 고려사항:**
*   **데이터 유형:** 숫자형 특성에는 `mean`, `median`, `constant` 전략을, 범주형 특성에는 `most_frequent` 또는 `constant` 전략을 주로 사용합니다.
*   **데이터 누수 방지:** `fit()` 메서드는 반드시 훈련 데이터에만 적용해야 합니다. 테스트 데이터나 새로운 데이터에 대해서는 훈련 데이터로 `fit`된 `imputer` 객체의 `transform()` 메서드를 사용해야 합니다. `fit_transform()`은 훈련 데이터에만 사용하고, 테스트 데이터에는 `transform()`만 사용해야 합니다.
*   **단순성:** 특성 간의 복잡한 관계를 고려하지 않으므로, 결측치 패턴이 단순하거나 결측치 비율이 낮을 때 적합합니다. 그렇지 않으면 모델에 편향을 도입할 수 있습니다.


### 1.3. `KNNImputer`
`KNNImputer`는 K-최근접 이웃(K-Nearest Neighbors) 알고리즘을 사용하여 결측치를 대체합니다. 이는 `SimpleImputer`와 달리 특성 간의 관계를 고려하여 결측치를 추정하므로, 더 정교한 대체가 가능합니다. 결측치가 있는 샘플과 가장 유사한(가까운) K개의 이웃 샘플들의 값을 기반으로 결측치를 채웁니다.

*   **작동 원리:**
    1.  결측치가 없는 특성들을 사용하여 각 샘플 간의 거리를 계산합니다.
    2.  결측치가 있는 샘플에 대해, 거리가 가장 가까운 K개의 이웃 샘플을 찾습니다.
    3.  해당 결측치를 이 K개 이웃 샘플들의 해당 특성 값의 평균(숫자형) 또는 최빈값(범주형)으로 대체합니다.

```python
from sklearn.impute import KNNImputer
import numpy as np # np.nan 사용을 위해 필요

# 결측치가 포함된 데이터 (가상 데이터)
# KNNImputer는 기본적으로 숫자형 데이터에 사용됩니다.
data_knn = np.array([
    [1, 2, np.nan, 4],
    [5, np.nan, 7, 8],
    [9, 10, 11, np.nan],
    [13, 14, 15, 16],
    [2, 3, 4, np.nan]
])

print("원본 데이터 (KNNImputer 예시):\n", data_knn)

# KNNImputer를 사용하여 결측치 대체
# n_neighbors=2: 가장 가까운 2개의 이웃을 사용하여 결측치를 추정합니다.
# weights='uniform': 모든 이웃에 동일한 가중치를 부여합니다. ('distance'는 거리에 반비례하여 가중치 부여)
imputer_knn = KNNImputer(n_neighbors=2, weights='uniform')
# fit_transform(): 훈련 데이터로부터 이웃을 학습하고, 데이터를 변환합니다.
data_imputed_knn = imputer_knn.fit_transform(data_knn)
print("\nKNNImputer로 대체된 데이터 (n_neighbors=2):\n", data_imputed_knn)
```

**`KNNImputer` 사용 시 고려사항:**
*   **계산 비용:** `SimpleImputer`보다 계산 비용이 높습니다. 특히 데이터셋의 크기가 크거나 특성 수가 많을수록 계산 시간이 오래 걸릴 수 있습니다.
*   **특성 스케일:** 거리 기반 알고리즘이므로, 특성들의 스케일이 다를 경우 `StandardScaler`와 같은 스케일링 전처리가 필요합니다. 그렇지 않으면 스케일이 큰 특성이 거리에 더 큰 영향을 미쳐 잘못된 이웃을 찾을 수 있습니다.
*   **범주형 데이터:** `KNNImputer`는 기본적으로 숫자형 데이터에 최적화되어 있습니다. 범주형 특성에 적용하려면 원-핫 인코딩(One-Hot Encoding)과 같은 전처리가 필요할 수 있습니다.
*   **`n_neighbors` 선택:** `n_neighbors` 값은 중요한 하이퍼파라미터입니다. 너무 작으면 노이즈에 민감하고, 너무 크면 과도하게 스무딩되어 정보 손실이 발생할 수 있습니다. 교차 검증을 통해 최적의 값을 찾는 것이 좋습니다.


### 1.4. `IterativeImputer` (MICE)
`IterativeImputer`는 다변량 결측치 처리(Multivariate Imputation by Chained Equations, MICE)의 한 형태로, 각 특성의 결측치를 다른 특성들을 사용하여 예측하는 방식으로 반복적으로 채워 넣습니다. 이는 `SimpleImputer`나 `KNNImputer`보다 더 복잡하고 정교한 대체가 가능하며, 특성 간의 관계를 고려한다는 장점이 있습니다.

*   **작동 원리 (MICE):**
    1.  **초기 대체:** 먼저 `SimpleImputer`와 같은 간단한 방법으로 모든 결측치를 초기 대체합니다.
    2.  **반복적 예측 및 대체:**
        *   데이터셋의 각 특성(컬럼)을 순회합니다.
        *   현재 처리할 특성을 타겟 변수로 설정하고, 나머지 모든 특성들을 독립 변수로 사용하여 예측 모델을 훈련합니다.
        *   훈련된 모델을 사용하여 현재 특성의 결측치를 예측하고 대체합니다.
        *   이 과정을 모든 특성에 대해 반복하고, 지정된 `max_iter` 횟수만큼 반복하거나 수렴할 때까지 계속합니다.
    이러한 반복적인 예측 및 대체 과정을 통해 특성 간의 복잡한 관계를 반영하여 결측치를 채울 수 있습니다.

```python
from sklearn.experimental import enable_iterative_imputer # IterativeImputer 사용을 위해 필요
from sklearn.impute import IterativeImputer
from sklearn.linear_model import BayesianRidge # 예측 모델로 사용될 수 있음 (기본값)
import numpy as np # np.nan 사용을 위해 필요

# 결측치가 포함된 데이터 (가상 데이터)
# IterativeImputer는 숫자형 데이터에 사용됩니다.
data_iterative = np.array([
    [1, 2, np.nan, 4],
    [5, np.nan, 7, 8],
    [9, 10, 11, np.nan],
    [13, 14, 15, 16],
    [np.nan, 3, 4, 5]
])

print("원본 데이터 (IterativeImputer 예시):\n", data_iterative)

# IterativeImputer를 사용하여 결측치 대체
# estimator: 각 특성의 결측치를 예측하는 데 사용될 모델을 지정합니다. (기본값은 BayesianRidge)
# max_iter: 반복 횟수. 충분히 큰 값으로 설정하여 수렴을 보장합니다.
# random_state: 재현성을 위한 난수 시드.
imputer_iterative = IterativeImputer(estimator=BayesianRidge(), max_iter=10, random_state=42)
# fit_transform(): 훈련 데이터로부터 예측 모델을 학습하고, 데이터를 변환합니다.
data_imputed_iterative = imputer_iterative.fit_transform(data_iterative)
print("\nIterativeImputer로 대체된 데이터:\n", data_imputed_iterative)
```

**`IterativeImputer` 사용 시 고려사항:**
*   **정교함:** `SimpleImputer`나 `KNNImputer`보다 더 정교하고 정확한 결측치 대체를 제공합니다. 특히 특성 간에 강한 상관관계가 있을 때 유용합니다.
*   **계산 비용:** 반복적인 학습 과정을 거치므로 계산 비용이 가장 높습니다. 대규모 데이터셋에서는 학습 시간이 오래 걸릴 수 있습니다.
*   **데이터 유형:** 기본적으로 숫자형 데이터에 사용됩니다. 범주형 특성을 포함하는 경우, 원-핫 인코딩과 같은 전처리가 필요하며, `estimator` 선택에 주의해야 합니다.
*   **`estimator` 선택:** `estimator` 파라미터를 통해 결측치 예측에 사용할 모델을 지정할 수 있습니다. `BayesianRidge` 외에도 `RandomForestRegressor`, `ExtraTreesRegressor` 등 다양한 회귀 모델을 사용할 수 있습니다. 모델 선택은 대체 성능에 영향을 미칩니다.
*   **데이터 누수 방지:** 다른 Imputer와 마찬가지로, `fit()`은 훈련 데이터에만, `transform()`은 훈련 및 테스트 데이터 모두에 적용해야 합니다.


## 2. 이상치(Outliers) 처리 전략

### 2.1. 이상치란?
**이상치(Outliers)**는 대부분의 데이터와는 동떨어져 있는, 극단적인 값을 가지는 데이터 포인트입니다. 이들은 데이터셋의 일반적인 패턴에서 벗어나 매우 작거나 큰 값을 가집니다. 이상치는 단일 특성에서 나타날 수도 있고(단변량 이상치), 여러 특성의 조합에서 비정상적인 패턴을 보일 수도 있습니다(다변량 이상치).

**이상치의 발생 원인:**
*   **데이터 입력 오류:** 데이터 수동 입력 시의 오타, 센서 오작동, 데이터 전송 오류 등으로 인해 잘못된 값이 기록될 수 있습니다.
*   **측정 오류:** 측정 장비의 결함이나 환경적 요인으로 인해 부정확한 측정값이 발생할 수 있습니다.
*   **실제 현상의 희귀한 발생:** 드물게 발생하는 합법적인 데이터 포인트일 수 있습니다. 예를 들어, 특정 질병의 매우 드문 사례나, 특정 주식의 급격한 가격 변동 등은 실제 현상이지만 일반적인 패턴에서 벗어날 수 있습니다.
*   **데이터 처리 오류:** 데이터 병합, 변환 과정에서 의도치 않게 이상치가 생성될 수 있습니다.

**왜 이상치가 문제인가?**
이상치는 모델 학습에 부정적인 영향을 미쳐 모델의 성능을 저하시키거나 잘못된 패턴을 학습하게 할 수 있습니다. 특히 다음과 같은 문제점을 야기합니다:
*   **모델 성능 저하:** 선형 회귀나 K-평균 클러스터링과 같이 평균이나 분산에 민감한 모델은 이상치에 의해 크게 영향을 받아 잘못된 결정 경계나 클러스터를 형성할 수 있습니다.
*   **통계적 추정 왜곡:** 평균, 표준편차와 같은 통계량은 이상치에 의해 크게 왜곡될 수 있습니다. 이는 데이터의 실제 분포를 잘못 이해하게 만들 수 있습니다.
*   **모델의 일반화 능력 저해:** 이상치에 과도하게 맞춰 학습된 모델은 새로운 데이터에 대한 예측 성능(일반화 능력)이 떨어질 수 있습니다.

따라서 이상치를 적절히 탐지하고 처리하는 것은 머신러닝 모델의 견고성과 예측 성능을 확보하는 데 매우 중요한 단계입니다.

### 2.2. 이상치 탐지 방법
이상치를 처리하기 전에 먼저 탐지해야 합니다. 이상치 탐지는 데이터의 특성과 이상치의 정의에 따라 다양한 방법이 사용될 수 있습니다.

*   **통계적 방법:** 데이터의 분포에 대한 가정을 기반으로 이상치를 식별합니다.
    *   **Z-점수(Z-score):** 데이터 포인트가 평균으로부터 얼마나 떨어져 있는지를 표준편차 단위로 나타냅니다. 일반적으로 Z-점수가 특정 임계값(예: 2 또는 3)을 초과하는 데이터를 이상치로 간주합니다. 이 방법은 데이터가 정규 분포를 따른다고 가정할 때 효과적입니다.
        *   수식: $ Z = \frac{x - \mu}{\sigma} $
    *   **IQR(Interquartile Range):** 데이터의 사분위수(Quartile)를 사용하여 이상치 범위를 정의합니다. IQR은 3사분위수(Q3)와 1사분위수(Q1)의 차이입니다. 일반적으로 $Q1 - 1.5 \times IQR$보다 작거나 $Q3 + 1.5 \times IQR$보다 큰 데이터를 이상치로 간주합니다. 이 방법은 데이터가 정규 분포를 따르지 않거나 이상치가 많을 때 Z-점수보다 더 견고합니다.

*   **시각화:** 데이터를 시각적으로 표현하여 이상치를 직관적으로 확인하는 방법입니다.
    *   **상자 그림(Box Plot):** 데이터의 사분위수, 중앙값, 이상치를 시각적으로 보여줍니다. IQR 기반의 이상치 탐지에 매우 유용합니다.
    *   **산점도(Scatter Plot):** 두 특성 간의 관계에서 벗어나는 데이터 포인트를 식별하는 데 유용합니다. 다변량 이상치를 탐지하는 데 도움이 될 수 있습니다.
    *   **히스토그램(Histogram):** 단일 특성의 분포를 보여주며, 극단적인 빈도를 가지는 구간을 통해 이상치를 파악할 수 있습니다.

*   **모델 기반 방법:** 특정 알고리즘을 사용하여 데이터의 패턴을 학습하고, 이 패턴에서 벗어나는 데이터를 이상치로 식별합니다. Scikit-learn은 다양한 이상 탐지 알고리즘을 제공합니다.
    *   **Isolation Forest:** 데이터를 무작위로 분할하여 이상치를 고립시키는 트리 기반의 알고리즘입니다. 정상 데이터보다 이상치가 더 적은 분할로 빠르게 고립된다는 아이디어를 사용합니다.
    *   **One-Class SVM:** 훈련 데이터의 대부분을 포함하는 결정 경계를 학습하고, 이 경계 밖에 있는 데이터를 이상치로 간주합니다. 주로 정상 데이터만으로 모델을 훈련할 수 있을 때 사용됩니다.
    *   **LOF (Local Outlier Factor):** 데이터 포인트의 지역 밀도를 계산하여, 주변 이웃보다 밀도가 현저히 낮은 데이터를 이상치로 식별합니다. 이는 군집 내의 이상치(local outlier)를 탐지하는 데 효과적입니다.
    *   (자세한 내용은 `17_이상_탐지.md` 문서 참조)

이상치 탐지 방법은 데이터의 특성, 이상치의 정의, 그리고 문제의 도메인 지식에 따라 적절히 선택되어야 합니다. 여러 방법을 조합하여 사용하는 것이 더 효과적일 수 있습니다.

### 2.3. 이상치 처리 전략
이상치를 탐지한 후에는 문제의 특성과 이상치의 원인에 따라 적절한 처리 전략을 선택해야 합니다. 이상치 처리 전략은 크게 다음과 같이 나눌 수 있습니다.

1.  **제거 (Removal):**
    *   **방법:** 이상치로 판단된 데이터 포인트를 데이터셋에서 완전히 제거합니다. 이는 해당 행(샘플) 전체를 삭제하거나, 특정 특성(컬럼)의 이상치만 제거하는 방식이 될 수 있습니다.
    *   **장점:** 모델에 미치는 부정적인 영향을 직접적으로 제거하여 모델의 정확도를 높일 수 있습니다. 구현이 간단합니다.
    *   **단점:** 데이터 손실이 발생하며, 특히 데이터셋이 작거나 이상치가 많을 경우 정보 손실이 커져 모델의 일반화 성능에 악영향을 미칠 수 있습니다. 또한, 이상치가 특정 패턴을 가지고 발생한다면 편향을 유발할 수 있습니다.
    *   **사용 시기:** 이상치가 명백한 데이터 입력 오류나 측정 오류일 때, 또는 데이터셋이 충분히 커서 일부 데이터 손실이 모델 성능에 큰 영향을 미치지 않을 때 적합합니다.

2.  **변환 (Transformation):**
    *   **방법:** 데이터의 분포를 변경하는 수학적 변환(예: 로그 변환(Log Transformation), 제곱근 변환(Square Root Transformation), 역수 변환 등)을 통해 이상치의 영향을 줄입니다. 이러한 변환은 데이터의 왜곡을 줄이고 분포를 정규화하는 데 도움이 됩니다.
    *   **장점:** 데이터 손실 없이 이상치의 영향을 완화할 수 있습니다. 데이터가 심하게 왜곡되어 있거나, 이상치가 실제 현상을 반영하는 경우에 유용합니다.
    *   **단점:** 변환된 데이터는 원래 데이터의 해석을 어렵게 만들 수 있습니다. 모델의 결과가 직관적으로 이해되지 않을 수 있습니다.
    *   **사용 시기:** 이상치가 실제 현상을 반영하지만 모델에 미치는 영향을 줄이고 싶을 때, 또는 데이터의 분포를 정규화해야 할 때.

3.  **대체 (Imputation):**
    *   **방법:** 이상치를 다른 값(예: 해당 특성의 평균, 중앙값, 또는 이상치 경계 값)으로 대체합니다. 예를 들어, IQR 방법을 사용하여 이상치로 판단된 값을 IQR 경계 값으로 클리핑(Capping)하거나, 해당 특성의 평균/중앙값으로 대체할 수 있습니다.
    *   **장점:** 데이터 손실이 없어 데이터셋의 크기를 유지할 수 있습니다.
    *   **단점:** 이상치를 대체하는 과정에서 새로운 편향이 도입될 수 있으며, 데이터의 원래 분포를 왜곡할 수 있습니다.
    *   **사용 시기:** 이상치가 오류일 가능성이 높지만, 데이터 손실을 최소화해야 할 때, 또는 이상치가 모델에 미치는 영향을 완화하면서도 데이터의 양을 보존해야 할 때.

4.  **모델 선택 (Model Selection):**
    *   **방법:** 이상치에 덜 민감한 머신러닝 모델을 사용합니다. 일부 모델은 이상치의 영향을 자연스럽게 완화하는 특성을 가집니다.
    *   **장점:** 별도의 복잡한 전처리 과정 없이 모델이 이상치의 영향을 스스로 완화합니다. 모델 개발 워크플로우를 단순화할 수 있습니다.
    *   **단점:** 모든 모델이 이상치에 강한 것은 아니며, 모델의 선택이 제한될 수 있습니다. 또한, 모델의 해석이 어려워질 수 있습니다.
    *   **사용 시기:** 이상치를 직접 처리하기 어렵거나, 모델의 견고성(robustness)이 중요할 때. 예를 들어, 트리 기반 모델(의사결정 트리, 랜덤 포레스트, 부스팅 모델)은 이상치에 비교적 덜 민감합니다.

**이상치 처리 전략 선택 시 실무적 가이드라인:**

이상치 처리 방법은 데이터의 특성, 이상치의 원인, 그리고 문제의 도메인 지식에 따라 신중하게 결정해야 합니다. 다음은 실무에서 이상치 처리 전략을 선택할 때 고려해야 할 사항들입니다.

1.  **이상치의 원인 파악이 최우선**: 이상치가 단순한 데이터 입력 오류인지, 측정 오류인지, 아니면 실제 현상의 극단적인 값이지만 중요한 정보인지 파악하는 것이 가장 중요합니다. 도메인 전문가와의 협업이 필수적입니다.
    *   **오류로 인한 이상치**: 명백한 오류(예: 사람의 나이가 200세)라면 제거하거나 합리적인 값으로 대체하는 것이 적절합니다.
    *   **실제 현상 반영 이상치**: 실제 현상을 반영하는 이상치(예: 특정 주식의 급등락)라면, 단순히 제거하기보다는 변환을 통해 영향을 줄이거나, 이상치에 강건한 모델을 사용하는 것을 고려해야 합니다. 이러한 이상치는 중요한 정보를 담고 있을 수 있기 때문입니다.

2.  **데이터셋의 크기 고려**: 데이터셋의 크기가 작을수록 이상치 제거는 신중해야 합니다. 소수의 이상치를 제거하는 것만으로도 전체 데이터 분포가 크게 변하거나, 중요한 정보가 손실될 수 있습니다. 데이터가 충분히 크다면 제거가 비교적 안전한 선택일 수 있습니다.

3.  **모델의 민감도 고려**: 사용하려는 머신러닝 모델이 이상치에 얼마나 민감한지 고려해야 합니다.
    *   **민감한 모델**: 선형 회귀, 로지스틱 회귀, K-평균 클러스터링, SVM 등은 이상치에 민감하므로, 이상치 처리가 모델 성능에 큰 영향을 미칠 수 있습니다.
    *   **덜 민감한 모델**: 의사결정 트리, 랜덤 포레스트, 그레디언트 부스팅과 같은 트리 기반 모델은 이상치에 비교적 강건합니다. 이들은 분할 기준으로 이상치를 고립시키는 경향이 있어, 전체 모델에 미치는 영향이 적습니다.

4.  **평가 지표에 미치는 영향 고려**: 이상치 처리 방법이 모델의 평가 지표에 어떤 영향을 미치는지 확인해야 합니다. 예를 들어, MSE는 이상치에 매우 민감하므로, 이상치를 제거하거나 변환하면 MSE가 크게 감소할 수 있습니다. 반면 MAE는 MSE보다 이상치에 덜 민감합니다.

5.  **재현성 및 파이프라인 통합**: 이상치 처리 과정도 데이터 전처리 파이프라인에 통합하여 재현성을 확보하고, 훈련 데이터에서 학습된 이상치 탐지/처리 규칙이 테스트 데이터 및 실제 서비스 데이터에도 일관되게 적용되도록 해야 합니다.

6.  **실험적 접근**: 가장 좋은 이상치 처리 방법은 문제와 데이터에 따라 다릅니다. 여러 가지 방법을 시도해보고, 교차 검증(Cross-validation)을 통해 각 방법이 모델의 일반화 성능에 미치는 영향을 비교하여 최적의 전략을 찾는 **실험적인 접근**이 중요합니다.

결론적으로, 이상치 처리는 단순히 기술적인 단계를 넘어 데이터에 대한 깊은 이해와 비판적인 사고를 요구하는 과정입니다. 신중한 이상치 처리는 모델의 견고성과 예측 성능을 크게 향상시킬 수 있습니다.
이상치를 탐지한 후에는 문제의 특성과 이상치의 원인에 따라 적절한 처리 전략을 선택해야 합니다. 이상치 처리 전략은 크게 다음과 같이 나눌 수 있습니다.

1.  **제거 (Removal):**
    *   **방법:** 이상치로 판단된 데이터 포인트를 데이터셋에서 완전히 제거합니다. 이는 해당 행(샘플) 전체를 삭제하거나, 특정 특성(컬럼)의 이상치만 제거하는 방식이 될 수 있습니다.
    *   **장점:** 모델에 미치는 부정적인 영향을 직접적으로 제거하여 모델의 정확도를 높일 수 있습니다. 구현이 간단합니다.
    *   **단점:** 데이터 손실이 발생하며, 특히 데이터셋이 작거나 이상치가 많을 경우 정보 손실이 커져 모델의 일반화 성능에 악영향을 미칠 수 있습니다. 또한, 이상치가 특정 패턴을 가지고 발생한다면 편향을 유발할 수 있습니다.
    *   **사용 시기:** 이상치가 명백한 데이터 입력 오류나 측정 오류일 때, 또는 데이터셋이 충분히 커서 일부 데이터 손실이 모델 성능에 큰 영향을 미치지 않을 때 적합합니다.

2.  **변환 (Transformation):**
    *   **방법:** 데이터의 분포를 변경하는 수학적 변환(예: 로그 변환(Log Transformation), 제곱근 변환(Square Root Transformation), 역수 변환 등)을 통해 이상치의 영향을 줄입니다. 이러한 변환은 데이터의 왜곡을 줄이고 분포를 정규화하는 데 도움이 됩니다.
    *   **장점:** 데이터 손실 없이 이상치의 영향을 완화할 수 있습니다. 데이터가 심하게 왜곡되어 있거나, 이상치가 실제 현상을 반영하는 경우에 유용합니다.
    *   **단점:** 변환된 데이터는 원래 데이터의 해석을 어렵게 만들 수 있습니다. 모델의 결과가 직관적으로 이해되지 않을 수 있습니다.
    *   **사용 시기:** 이상치가 실제 현상을 반영하지만 모델에 미치는 영향을 줄이고 싶을 때, 또는 데이터의 분포를 정규화해야 할 때.

3.  **대체 (Imputation):**
    *   **방법:** 이상치를 다른 값(예: 해당 특성의 평균, 중앙값, 또는 이상치 경계 값)으로 대체합니다. 예를 들어, IQR 방법을 사용하여 이상치로 판단된 값을 IQR 경계 값으로 클리핑(Capping)하거나, 해당 특성의 평균/중앙값으로 대체할 수 있습니다.
    *   **장점:** 데이터 손실이 없어 데이터셋의 크기를 유지할 수 있습니다.
    *   **단점:** 이상치를 대체하는 과정에서 새로운 편향이 도입될 수 있으며, 데이터의 원래 분포를 왜곡할 수 있습니다.
    *   **사용 시기:** 이상치가 오류일 가능성이 높지만, 데이터 손실을 최소화해야 할 때, 또는 이상치가 모델에 미치는 영향을 완화하면서도 데이터의 양을 보존해야 할 때.

4.  **모델 선택 (Model Selection):**
    *   **방법:** 이상치에 덜 민감한 머신러닝 모델을 사용합니다. 일부 모델은 이상치의 영향을 자연스럽게 완화하는 특성을 가집니다.
    *   **장점:** 별도의 복잡한 전처리 과정 없이 모델이 이상치의 영향을 스스로 완화합니다. 모델 개발 워크플로우를 단순화할 수 있습니다.
    *   **단점:** 모든 모델이 이상치에 강한 것은 아니며, 모델의 선택이 제한될 수 있습니다. 또한, 모델의 해석이 어려워질 수 있습니다.
    *   **사용 시기:** 이상치를 직접 처리하기 어렵거나, 모델의 견고성(robustness)이 중요할 때. 예를 들어, 트리 기반 모델(의사결정 트리, 랜덤 포레스트, 부스팅 모델)은 이상치에 비교적 덜 민감합니다.

이상치 처리 전략을 선택할 때는 항상 **도메인 지식**을 활용하여 이상치의 원인을 파악하고, 각 전략의 장단점 및 데이터 손실과 정보 왜곡 사이의 **트레이드오프**를 고려해야 합니다. 단일 전략보다는 여러 전략을 조합하거나, 교차 검증을 통해 최적의 방법을 찾는 것이 중요합니다.

## 3. 결론: 결측치 및 이상치 처리 시 고려사항

결측치와 이상치 처리는 머신러닝 프로젝트에서 매우 중요하지만, 정답이 정해져 있지 않은 복잡한 과정입니다. 성공적인 데이터 전처리를 위해서는 다음과 같은 사항들을 항상 고려해야 합니다.

*   **도메인 지식 활용:**
    *   결측치나 이상치의 발생 원인을 파악하는 데 도메인 지식(Domain Knowledge)은 필수적입니다. 예를 들어, 특정 센서의 결측치가 주기적으로 발생한다면 이는 시스템 오류일 가능성이 높으므로 제거하거나 특정 값으로 대체하는 것이 합리적일 수 있습니다. 반면, 특정 질병의 매우 드문 사례가 이상치로 탐지되었다면, 이는 중요한 정보일 수 있으므로 제거해서는 안 됩니다.
    *   도메인 지식을 통해 어떤 결측치/이상치가 실제 의미를 가지는지, 어떤 것이 단순한 오류인지를 구분하고, 가장 적절한 처리 방법을 선택해야 합니다.

*   **데이터 손실 vs. 정보 왜곡 (Bias-Variance Trade-off):**
    *   결측치/이상치 처리 방법은 항상 데이터 손실과 정보 왜곡 사이의 트레이드오프를 가집니다. 데이터를 제거하면 정보 손실이 발생하고, 데이터를 대체하거나 변환하면 원래 데이터의 분포나 관계가 왜곡될 수 있습니다.
    *   데이터의 양, 이상치의 비율, 그리고 문제의 특성을 고려하여 이 트레이드오프를 현명하게 관리해야 합니다. 데이터가 적을수록 제거보다는 대체나 변환을 고려하는 것이 좋습니다.

*   **파이프라인 통합 (Pipeline Integration):**
    *   전처리 단계는 Scikit-learn의 `Pipeline`에 통합하는 것이 매우 중요합니다. `Pipeline`을 사용하면 데이터 전처리(스케일링, 결측치 처리 등)와 모델 학습 과정을 하나의 객체로 묶을 수 있습니다.
    *   이는 **데이터 누수(Data Leakage)**를 방지하고, 코드의 재현성(Reproducibility)과 유지보수성을 높이는 데 기여합니다. `fit()`은 훈련 데이터에만, `transform()`은 훈련 및 테스트 데이터 모두에 적용하는 원칙을 `Pipeline`이 자동으로 지켜줍니다.

*   **반복적인 과정 (Iterative Process):**
    *   결측치 및 이상치 처리는 한 번에 완벽하게 끝나는 것이 아니라, 모델 학습 및 평가 과정에서 반복적으로 개선될 수 있는 과정입니다. 초기 모델의 성능을 평가한 후, 결측치/이상치 처리 방법을 변경하거나 조정하여 모델 성능이 향상되는지 확인하는 실험적인 접근이 필요합니다.
    *   다양한 처리 방법을 시도해보고, 교차 검증(Cross-validation)을 통해 각 방법이 모델의 일반화 성능에 미치는 영향을 평가해야 합니다.

결론적으로, 결측치와 이상치 처리는 단순히 기술적인 문제를 넘어 데이터에 대한 깊은 이해와 비판적인 사고를 요구하는 과정입니다. 이러한 전처리 단계를 신중하게 수행함으로써, 더 견고하고 신뢰할 수 있는 머신러닝 모델을 구축할 수 있습니다.
