## 1. 모델 검증(Model Validation)의 중요성

머신러닝 모델을 개발하는 목표는 단순히 주어진 데이터를 잘 설명하는 모델을 만드는 것을 넘어, **새로운 데이터(unseen data)에 대해서도 정확한 예측을 수행하는 모델을 만드는 것**입니다. 모델 검증은 바로 이 "일반화(Generalization)" 성능을 객관적으로 측정하고 보장하기 위한 핵심적인 과정이며, 다음과 같은 중요한 이유 때문에 반드시 필요합니다.

### 1.1. 일반화 성능 측정

모델을 학습시킨 훈련 데이터(training data)에 대한 성능은 모델의 실제 성능을 나타내지 못합니다. 모델은 이미 정답을 알고 있는 훈련 데이터에 대해서는 높은 정확도를 보일 수 있지만, 이는 마치 학생이 답안지를 모두 외워서 시험을 잘 보는 것과 같습니다. 실제 중요한 것은 그 학생이 처음 보는 문제도 잘 풀 수 있는지, 즉 모델이 한 번도 보지 못한 새로운 데이터에 대해 얼마나 잘 작동하는지를 평가하는 것입니다. 모델 검증은 훈련 과정에서 사용되지 않은 별도의 데이터를 사용하여 이러한 **일반화 성능**을 객관적으로 측정하는 역할을 합니다.

### 1.2. 과적합(Overfitting)과 과소적합(Underfitting) 방지

모델 검증은 머신러닝에서 가장 흔하게 발생하는 문제인 과적합과 과소적합을 진단하고 방지하는 데 필수적입니다.

*   **과적합 (Overfitting):**
    *   **정의:** 모델이 훈련 데이터에 너무 과도하게 최적화되어, 데이터의 실제 패턴뿐만 아니라 노이즈(noise)나 우연한 패턴까지 모두 학습해버린 상태를 말합니다.
    *   **증상:** 훈련 데이터에 대해서는 거의 완벽에 가까운 성능을 보이지만, 새로운 데이터(검증 데이터 또는 테스트 데이터)에 대해서는 성능이 급격히 떨어집니다.
    *   **원인:** 모델이 데이터에 비해 지나치게 복잡하거나, 훈련 데이터의 양이 부족할 때 주로 발생합니다.
    *   **역할:** 모델 검증을 통해 훈련 성능과 검증 성능의 차이를 확인함으로써 과적합 여부를 진단하고, 규제(regularization)나 하이퍼파라미터 튜닝 등을 통해 이를 해결할 수 있습니다.

*   **과소적합 (Underfitting):**
    *   **정의:** 모델이 너무 단순하여 훈련 데이터에 내재된 실제 패턴을 제대로 학습하지 못한 상태를 말합니다.
    *   **증상:** 훈련 데이터에 대한 성능과 검증 데이터에 대한 성능이 모두 낮게 나타납니다.
    *   **원인:** 데이터에 비해 모델이 너무 단순할 때 발생합니다.
    *   **역할:** 모델 검증을 통해 모델이 데이터로부터 충분히 학습하지 못하고 있음을 파악하고, 더 복잡한 모델을 사용하거나 다른 특성을 추가하는 등의 조치를 취할 수 있습니다.

### 1.3. 신뢰성 있는 모델 선택 및 하이퍼파라미터 튜닝

대부분의 머신러닝 모델은 성능에 큰 영향을 미치는 여러 **하이퍼파라미터(Hyperparameter)**를 가지고 있습니다. 예를 들어, 결정 트리에서는 트리의 최대 깊이를, 서포트 벡터 머신에서는 비용(C)이나 커널(kernel) 등을 조정해야 합니다.

모델 검증은 이러한 하이퍼파라미터의 다양한 조합을 시도하고, 그중에서 **가장 좋은 일반화 성능을 내는 최적의 조합을 찾는 과정**의 기준이 됩니다. 검증 데이터를 사용하여 각 하이퍼파라미터 조합의 성능을 객관적으로 평가함으로써, 단순히 훈련 데이터에만 잘 맞는 조합이 아닌, 실제 환경에서도 좋은 성능을 보일 것으로 기대되는 최적의 모델을 선택할 수 있습니다. 이 과정을 통해 최종 모델의 신뢰도를 높이고, 안정적인 예측 성능을 확보할 수 있습니다.

## 2. 데이터 분할(Data Splitting)

모델의 일반화 성능을 올바르게 측정하기 위한 가장 기본적인 방법은 주어진 데이터셋을 서로 다른 목적을 가진 여러 개의 서브셋(subset)으로 나누는 것입니다. 이를 데이터 분할이라고 합니다.

### 2.1. 훈련, 검증, 테스트 세트

일반적으로 전체 데이터셋은 다음과 같이 3가지 종류로 분할됩니다.

*   **훈련 세트 (Training Set):**
    *   **목적:** 모델을 학습시키는 데 사용되는 데이터입니다. 모델은 훈련 세트의 패턴과 관계를 학습하여 가중치(weights)나 규칙 등을 결정합니다.
    *   **비유:** 학생이 공부하는 데 사용하는 교과서나 문제집과 같습니다.
    *   **비율:** 일반적으로 전체 데이터의 약 60% ~ 80%를 차지합니다.

*   **검증 세트 (Validation Set):**
    *   **목적:** 학습된 모델의 성능을 중간 점검하고, 모델의 하이퍼파라미터를 튜닝하는 데 사용됩니다. 여러 모델 후보군(예: 하이퍼파라미터가 다른 모델들) 중에서 가장 좋은 성능을 보이는 모델을 선택하는 기준이 됩니다.
    *   **비유:** 학생이 실전 시험 전에 자신의 실력을 점검하기 위해 푸는 모의고사와 같습니다.
    *   **주의:** 검증 세트의 성능을 기준으로 하이퍼파라미터를 계속 튜닝하다 보면, 모델이 검증 세트에 과적합될 위험이 있습니다.

*   **테스트 세트 (Test Set):**
    *   **목적:** 모델 개발의 **최종 단계**에서 단 한 번만 사용되는 데이터입니다. 훈련과 검증 과정에서 전혀 사용되지 않은 데이터를 통해 모델의 최종 성능, 즉 일반화 성능을 객관적으로 평가합니다.
    *   **비유:** 학생의 최종 실력을 평가하는 대학수학능력시험과 같습니다.
    *   **주의:** 테스트 세트는 모델 튜닝이나 개선에 절대 사용되어서는 안 됩니다. 테스트 세트의 성능을 보고 모델을 수정하는 것은 답안지를 보고 시험공부를 하는 것과 같아서, 성능을 올바르게 측정할 수 없게 됩니다.

### 2.2. Scikit-learn을 이용한 데이터 분할

Scikit-learn 라이브러리의 `train_test_split` 함수를 사용하면 데이터셋을 훈련 세트와 테스트 세트로 쉽게 분할할 수 있습니다. 검증 세트가 필요한 경우, 훈련 세트를 다시 한번 분할하여 만들 수 있습니다.

```python
from sklearn.model_selection import train_test_split
from sklearn.datasets import load_iris

# 1. 데이터 로드
iris = load_iris()
X = iris.data  # 특성 데이터
y = iris.target # 레이블 데이터

# 2. 훈련 세트와 테스트 세트로 분할 (예: 80% 훈련, 20% 테스트)
X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,    # 테스트 세트의 비율 (20%)
    random_state=42,  # 재현성을 위한 난수 시드
    stratify=y        # 클래스 비율을 유지하며 분할 (분류 문제에서 중요)
)

print(f"전체 데이터 크기: {X.shape}, {y.shape}")
print(f"훈련 세트 크기: {X_train.shape}, {y_train.shape}")
print(f"테스트 세트 크기: {X_test.shape}, {y_test.shape}")

# (선택) 훈련 세트를 다시 분할하여 검증 세트 만들기 (예: 훈련 75%, 검증 25%)
X_train_sub, X_val, y_train_sub, y_val = train_test_split(
    X_train, y_train,
    test_size=0.25,   # 훈련 세트(X_train)의 25%를 검증 세트로 사용 (전체의 20%)
    random_state=42,
    stratify=y_train
)

print(f"\n세분화된 훈련 세트 크기: {X_train_sub.shape}, {y_train_sub.shape}")
print(f"검증 세트 크기: {X_val.shape}, {y_val.shape}")
```

**주요 파라미터:**
*   `test_size`: 테스트 세트로 분할할 데이터의 비율 또는 개수를 지정합니다.
*   `random_state`: 동일한 `random_state` 값을 사용하면 항상 같은 방식으로 데이터가 분할되어 결과를 재현할 수 있습니다.
*   `stratify`: (분류 문제에서) 이 옵션에 타겟 데이터(y)를 전달하면, 원본 데이터의 클래스 비율을 훈련 세트와 테스트 세트 모두에 동일하게 유지해 줍니다. 데이터 불균형이 심할 때 특히 중요합니다.

## 3. 교차 검증(Cross-Validation)

데이터를 훈련, 검증, 테스트 세트로 나누는 방식은 간단하지만 몇 가지 단점이 있습니다. 특히 데이터셋의 크기가 작을 경우, 어떤 데이터가 검증 세트로 선택되느냐에 따라 모델의 성능 평가 결과가 크게 달라질 수 있습니다. 또한, 검증 세트로 분할된 데이터는 모델 학습에 사용되지 못하므로 데이터 손실이 발생합니다.

**교차 검증**은 이러한 문제들을 해결하기 위한 더 안정적이고 신뢰성 있는 모델 검증 방법입니다.

### 3.1. 교차 검증의 원리

교차 검증은 훈련 세트 전체를 **여러 번에 걸쳐 다른 검증 세트로 활용**하는 방법입니다. 이를 통해 모든 데이터가 최소 한 번은 검증 과정에 참여하게 되어, 모델의 성능을 보다 일반화된 관점에서 평가할 수 있습니다.

**장점:**
*   **안정적인 성능 평가:** 데이터를 어떻게 분할하든 상관없이 안정적인 성능 평가 결과를 얻을 수 있습니다.
*   **데이터 효율성:** 모든 데이터 포인트를 훈련과 검증에 사용하므로, 데이터가 적을 때 특히 유용합니다.
*   **과적합 방지:** 모델이 특정 데이터 분할에만 과적합되는 것을 방지하고 일반화 성능을 높이는 데 도움이 됩니다.

### 3.2. K-Fold 교차 검증

K-Fold 교차 검증은 가장 널리 사용되는 교차 검증 기법입니다.

**작동 방식:**
1.  훈련 데이터셋을 **K개의 동일한 크기를 가진 서브셋(subset)**으로 나눕니다. 이 서브셋을 **폴드(fold)**라고 부릅니다.
2.  첫 번째 폴드를 **검증 세트**로 사용하고, 나머지 K-1개의 폴드를 **훈련 세트**로 사용하여 모델을 학습하고 성능을 평가합니다.
3.  두 번째 폴드를 검증 세트로, 나머지 폴드들을 훈련 세트로 사용하여 모델을 다시 학습하고 평가합니다.
4.  이 과정을 K번 반복하여 모든 폴드가 한 번씩 검증 세트로 사용되도록 합니다.
5.  최종적으로 K개의 성능 평가 점수(예: 정확도)를 얻게 되며, 이 점수들의 **평균**을 모델의 최종 성능으로 간주합니다.

일반적으로 K는 5 또는 10을 많이 사용합니다.

### 3.3. Stratified K-Fold 교차 검증

분류 문제에서는 각 폴드의 클래스(레이블) 분포가 원본 데이터셋의 클래스 분포와 유사하게 유지되는 것이 매우 중요합니다. 특히 데이터 불균형(imbalanced data)이 심한 경우, 일반 K-Fold를 사용하면 특정 폴드에는 특정 클래스가 전혀 포함되지 않는 문제가 발생할 수 있습니다.

**Stratified K-Fold**는 이러한 문제를 해결하기 위해 각 폴드를 나눌 때 **원본 데이터의 클래스 비율을 그대로 유지**하도록 데이터를 분할합니다. 예를 들어, 원본 데이터에 A 클래스가 70%, B 클래스가 30% 있다면, Stratified K-Fold로 생성된 모든 폴드에도 A 클래스와 B 클래스가 거의 7:3 비율로 포함됩니다.

따라서 회귀(regression) 문제에서는 일반 K-Fold를 사용해도 무방하지만, **분류(classification) 문제에서는 Stratified K-Fold를 사용하는 것이 훨씬 더 안정적이고 신뢰성 있는 검증 결과를 제공**합니다.

### 3.4. 고급 교차 검증 전략

표준 K-Fold나 Stratified K-Fold는 대부분의 정형 데이터 문제에 적합하지만, 특정 데이터 유형이나 문제 상황에서는 데이터의 특성을 고려한 고급 교차 검증 전략이 필요합니다. Scikit-learn은 이러한 특수한 상황을 위한 다양한 교차 검증 분할기(splitter)를 제공합니다.

#### 3.4.1. 시계열 데이터 분할 (TimeSeriesSplit)

**시계열 데이터(Time Series Data)**는 시간 순서에 따라 데이터 포인트가 종속성을 가지는 데이터입니다 (예: 주가, 기온, 판매량). 이러한 데이터에서는 미래의 데이터를 예측하기 위해 과거의 데이터만을 사용해야 합니다. 따라서 일반적인 무작위 분할이나 K-Fold 교차 검증을 사용하면 **데이터 누수(Data Leakage)**가 발생하여 모델 성능이 과대평가될 수 있습니다.

`TimeSeriesSplit`은 이러한 시계열 데이터의 특성을 고려하여 훈련 세트와 검증 세트를 시간 순서대로 분할합니다. 즉, 훈련 세트는 항상 검증 세트보다 시간적으로 앞선 데이터를 포함합니다.

*   **작동 원리:**
    *   데이터를 시간 순서대로 정렬합니다.
    *   각 폴드에서 훈련 세트는 이전 시점까지의 모든 데이터를 포함하고, 검증 세트는 그 다음 시점의 데이터를 포함합니다.
    *   훈련 세트의 크기는 각 폴드마다 점진적으로 증가합니다.

*   **주요 파라미터:**
    *   `n_splits`: 생성할 폴드의 개수 (최소 1).
    *   `max_train_size`: 각 훈련 세트의 최대 크기를 제한할 수 있습니다 (선택 사항).

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import TimeSeriesSplit
import matplotlib.pyplot as plt

# 가상 시계열 데이터 생성
# 100개의 데이터 포인트와 1개의 특성
X = np.arange(100).reshape(-1, 1) # 시간 순서대로 증가하는 특성
y = np.sin(np.arange(100) / 10) + np.random.randn(100) * 0.1 # 시계열 타겟

print("원본 시계열 데이터 형태:", X.shape, y.shape)

# TimeSeriesSplit 객체 생성 (5개의 폴드)
tscv = TimeSeriesSplit(n_splits=5)

plt.figure(figsize=(12, 6))
plt.plot(y, label='Original Time Series')

# 각 폴드별 훈련/검증 세트 시각화
for i, (train_index, val_index) in enumerate(tscv.split(X)):
    X_train, X_val = X[train_index], X[val_index]
    y_train, y_val = y[train_index], y[val_index]

    print(f"\nFold {i+1}:")
    print(f"  훈련 세트 인덱스 범위: {train_index.min()} ~ {train_index.max()} (크기: {len(train_index)})")
    print(f"  검증 세트 인덱스 범위: {val_index.min()} ~ {val_index.max()} (크기: {len(val_index)})")

    # 시각화
    plt.plot(train_index, y[train_index], label=f'Fold {i+1} Train', alpha=0.7)
    plt.plot(val_index, y[val_index], label=f'Fold {i+1} Validation', linestyle='--', alpha=0.7)

plt.title('TimeSeriesSplit 교차 검증 분할')
plt.xlabel('시간 인덱스')
plt.ylabel('값')
plt.legend()
plt.grid(True)
plt.show()
```

**고려사항:**
*   **데이터 정렬:** `TimeSeriesSplit`을 사용하기 전에 데이터가 반드시 시간 순서대로 정렬되어 있어야 합니다.
*   **데이터 누수 방지:** 시계열 예측 모델의 성능을 현실적으로 평가하는 데 필수적입니다.
*   **훈련 세트 크기 증가:** 각 폴드에서 훈련 세트의 크기가 점진적으로 증가하므로, 초기 폴드에서는 훈련 데이터가 적을 수 있습니다.

#### 3.4.2. 그룹 데이터 분할 (GroupKFold, LeaveOneGroupOut)

일부 데이터셋에서는 데이터 포인트들이 특정 그룹에 속하며, 이 그룹 내의 데이터들은 서로 독립적이지 않고 강한 상관관계를 가질 수 있습니다 (예: 동일 환자의 여러 방문 기록, 동일 지역의 여러 상점 데이터). 이러한 경우, 일반적인 K-Fold 교차 검증을 사용하면 **그룹 내 데이터가 훈련 세트와 검증 세트에 동시에 포함되어 데이터 누수가 발생**할 수 있습니다.

`GroupKFold`와 `LeaveOneGroupOut`은 이러한 그룹화된 데이터의 특성을 고려하여, **동일한 그룹의 데이터가 훈련 세트와 검증 세트에 동시에 나타나지 않도록** 데이터를 분할합니다.

*   **`GroupKFold`:**
    *   **작동 원리:** 데이터를 K개의 폴드로 분할하되, 각 그룹의 데이터는 항상 하나의 폴드에만 속하도록 합니다. 즉, 동일 그룹의 데이터는 훈련 세트와 검증 세트에 동시에 나타나지 않습니다.
    *   **주요 파라미터:** `n_splits` (생성할 폴드의 개수).

*   **`LeaveOneGroupOut` (LOGO):**
    *   **작동 원리:** 각 반복에서 하나의 그룹 전체를 검증 세트로 사용하고, 나머지 모든 그룹을 훈련 세트로 사용합니다. 그룹의 수가 많을 때 유용합니다.

```python
import numpy as np
from sklearn.model_selection import GroupKFold, LeaveOneGroupOut
from sklearn.datasets import make_blobs
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

# 가상 그룹 데이터 생성
# 100개의 샘플, 2개의 특성, 5개의 그룹
X, y, groups = make_blobs(n_samples=100, n_features=2, centers=5, random_state=42, return_centers=False, cluster_std=1.0)
# groups 배열은 각 샘플이 속한 그룹 ID를 나타냅니다.
# 여기서는 make_blobs의 centers를 그룹으로 활용합니다.
# 실제 시나리오에서는 환자 ID, 지역 ID 등이 groups가 될 수 있습니다.

# 그룹 ID를 0부터 시작하도록 매핑 (make_blobs의 centers는 0부터 시작하지 않을 수 있음)
unique_groups = np.unique(groups)
group_mapping = {g: i for i, g in enumerate(unique_groups)}
groups_mapped = np.array([group_mapping[g] for g in groups])

print(f"원본 데이터 형태: {X.shape}, 그룹 형태: {groups_mapped.shape}")
print(f"고유 그룹 ID: {np.unique(groups_mapped)}")

# GroupKFold 교차 검증
gkf = GroupKFold(n_splits=3) # 3개의 폴드로 분할

print("\n--- GroupKFold 분할 ---" )
for i, (train_index, val_index) in enumerate(gkf.split(X, y, groups=groups_mapped)):
    train_groups = np.unique(groups_mapped[train_index])
    val_groups = np.unique(groups_mapped[val_index])
    print(f"Fold {i+1}:")
    print(f"  훈련 세트 그룹: {train_groups}")
    print(f"  검증 세트 그룹: {val_groups}")
    print(f"  겹치는 그룹: {np.intersect1d(train_groups, val_groups)}") # 겹치는 그룹이 없어야 함

# LeaveOneGroupOut 교차 검증
logo = LeaveOneGroupOut()

print("\n--- LeaveOneGroupOut 분할 ---" )
for i, (train_index, val_index) in enumerate(logo.split(X, y, groups=groups_mapped)):
    train_groups = np.unique(groups_mapped[train_index])
    val_groups = np.unique(groups_mapped[val_index])
    print(f"Fold {i+1}:")
    print(f"  훈련 세트 그룹: {train_groups}")
    print(f"  검증 세트 그룹: {val_groups}")
    print(f"  겹치는 그룹: {np.intersect1d(train_groups, val_groups)}") # 겹치는 그룹이 없어야 함

# GroupKFold를 이용한 모델 평가 예시
model = LogisticRegression(random_state=42, max_iter=1000)
scores_gkf = []
for train_index, val_index in gkf.split(X, y, groups=groups_mapped):
    X_train, X_val = X[train_index], X[val_index]
    y_train, y_val = y[train_index], y[val_index]
    model.fit(X_train, y_train)
    scores_gkf.append(accuracy_score(y_val, model.predict(X_val)))

print(f"\nGroupKFold를 이용한 평균 정확도: {np.mean(scores_gkf):.4f}")
```

**고려사항:**
*   **데이터 누수 방지:** 그룹화된 데이터에서 `GroupKFold`나 `LeaveOneGroupOut`을 사용하지 않으면, 훈련 세트에서 학습된 그룹 특성이 검증 세트에 유출되어 모델 성능이 과대평가될 수 있습니다.
*   **그룹 ID의 중요성:** `groups` 파라미터에 각 샘플이 속한 그룹 ID를 정확하게 전달해야 합니다.
*   **그룹 수:** `GroupKFold`의 `n_splits`는 고유 그룹의 수보다 작거나 같아야 합니다.

## 4. 실습: 교차 검증을 통한 모델 성능 평가

이번 실습에서는 Scikit-learn을 사용하여 `StratifiedKFold`와 `cross_val_score`를 이용해 모델의 성능을 교차 검증하는 방법을 알아봅니다.

### 4.1. StratifiedKFold를 이용한 직접 구현

먼저 `StratifiedKFold`를 사용하여 교차 검증 과정을 직접 구현해 보겠습니다.

```python
import numpy as np
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import StratifiedKFold
from sklearn.metrics import accuracy_score

# 1. 데이터 및 모델 준비
iris = load_iris()
X = iris.data
y = iris.target
dt_clf = DecisionTreeClassifier(random_state=42)

# 2. Stratified K-Fold 교차 검증 객체 생성 (5-fold)
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
cv_accuracy = []
n_iter = 0

# 3. 교차 검증 수행
# skf.split()는 훈련용/검증용 데이터의 인덱스를 반환
for train_index, val_index in skf.split(X, y):
    n_iter += 1
    # 훈련용, 검증용 데이터 분할
    X_train, X_val = X[train_index], X[val_index]
    y_train, y_val = y[train_index], y[val_index]

    # 모델 학습 및 예측
    dt_clf.fit(X_train, y_train)
    pred = dt_clf.predict(X_val)

    # 정확도 계산 및 저장
    accuracy = np.round(accuracy_score(y_val, pred), 4)
    cv_accuracy.append(accuracy)
    
    print(f"{n_iter}번째 교차 검증:")
    print(f"  검증 데이터 클래스 비율: {np.bincount(y_val) / len(y_val)}")
    print(f"  정확도: {accuracy}\n")

# 4. 최종 결과 출력
print(f"각 폴드별 정확도: {cv_accuracy}")
print(f"평균 정확도: {np.mean(cv_accuracy):.4f}")
```
위 코드에서 `np.bincount()`를 통해 각 폴드의 클래스 비율이 원본 데이터와 유사하게 유지되는 것을 확인할 수 있습니다.

### 4.2. cross_val_score를 이용한 간편 구현

Scikit-learn의 `cross_val_score` 함수를 사용하면 위에서 직접 구현한 교차 검증 과정을 단 몇 줄의 코드로 간단하게 수행할 수 있습니다.

```python
from sklearn.model_selection import cross_val_score

# 1. 데이터 및 모델 준비 (위와 동일)
iris = load_iris()
X = iris.data
y = iris.target
dt_clf = DecisionTreeClassifier(random_state=42)

# 2. 교차 검증 수행
# cv=5: 5-fold 교차 검증을 의미 (분류 문제의 경우 자동으로 StratifiedKFold 사용)
# scoring='accuracy': 평가 지표를 정확도로 설정
scores = cross_val_score(dt_clf, X, y, scoring='accuracy', cv=5)

# 3. 최종 결과 출력
print(f"각 폴드별 정확도: {np.round(scores, 4)}")
print(f"평균 정확도: {np.mean(scores):.4f}")
```

`cross_val_score`는 내부적으로 `StratifiedKFold` (분류) 또는 `KFold` (회귀)를 사용하여 데이터를 분할하고, 훈련 및 평가를 자동으로 수행한 후 각 폴드의 평가 점수 리스트를 반환해 줍니다. 이처럼 교차 검증은 모델의 성능을 보다 안정적이고 객관적으로 평가할 수 있게 해주는 필수적인 도구입니다.
