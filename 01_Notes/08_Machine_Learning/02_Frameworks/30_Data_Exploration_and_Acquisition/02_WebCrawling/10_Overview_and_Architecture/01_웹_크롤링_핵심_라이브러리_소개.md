## 1. 웹 크롤링의 4단계 프로세스

모든 웹 크롤링 작업은 크게 4단계로 나눌 수 있습니다.

1.  **콘텐츠 요청 (Fetching):** 목표 웹사이트에 HTTP 요청을 보내 HTML, JSON 등의 원본 데이터를 받아옵니다.
2.  **파싱 (Parsing):** 받아온 원본 데이터를 다루기 쉬운 자료구조(e.g., 트리 구조)로 변환합니다.
3.  **데이터 추출 (Extraction):** 파싱된 데이터 구조를 탐색하여 우리가 원하는 특정 정보(e.g., 제목, 가격, 날짜)를 뽑아냅니다.
4.  **저장 (Storing):** 추출된 데이터를 파일(CSV, JSON)이나 데이터베이스 등 원하는 형태로 저장합니다.

## 2. 파이썬 크롤링 라이브러리 생태계

각 라이브러리는 위 4단계 중 특정 역할을 전문적으로 수행합니다.

- **`Requests`**: 1번(요청)을 담당하는 가장 기본적인 라이브러리입니다.
- **`BeautifulSoup`**: 2번(파싱)과 3번(추출)을 담당하며, 망가진 HTML도 잘 처리해줍니다.
- **`Selenium`**: 1, 2, 3번을 모두 수행할 수 있으며, 특히 자바스크립트로 동적으로 생성되는 콘텐츠를 수집하는 데 특화되어 있습니다.
- **`Scrapy`**: 1, 2, 3, 4번 전 과정을 아우르는 종합 프레임워크로, 대규모 크롤링에 적합합니다.

## 3. 핵심 라이브러리 상세 분석

### 3.1. `Requests` - 인간을 위한 HTTP
- **역할:** HTTP 통신
- **장점:** 사용법이 매우 간단하고 직관적입니다. API 서버와 통신하거나 정적인 웹 페이지를 가져오는 데 최적입니다.
- **단점:** 자바스크립트를 실행하지 못하므로, 동적 콘텐츠는 수집할 수 없습니다.

### 3.2. `BeautifulSoup` - 관대한 HTML 파서
- **역할:** HTML/XML 파싱 및 데이터 추출
- **장점:** 문법이 약간 틀리거나 망가진 HTML 문서도 유연하게 잘 처리합니다. CSS 선택자 등 사용법이 쉬워 초보자가 배우기 좋습니다.
- **단점:** 자체적인 HTTP 요청 기능이 없어 항상 `Requests`와 같은 라이브러리와 함께 사용해야 합니다.

### 3.3. `Selenium` - 웹 브라우저 자동화의 표준
- **역할:** 브라우저 자동화를 통한 동적 콘텐츠 수집
- **장점:** 실제 브라우저를 직접 제어하므로, 자바스크립트로 렌더링되는 거의 모든 콘텐츠를 수집할 수 있습니다. 클릭, 로그인 등 사람의 행동을 흉내 낼 수 있습니다.
- **단점:** 실제 브라우저를 띄우므로 매우 느리고 많은 시스템 리소스(메모리, CPU)를 사용합니다.

### 3.4. `Scrapy` - 올인원 크롤링 프레임워크
- **역할:** 크롤링 전 과정을 위한 시스템 구축
- **장점:** 비동기 기반으로 동작하여 성능이 매우 뛰어납니다. 데이터 처리(Pipeline), 요청 관리(Scheduler) 등 대규모 크롤링에 필요한 기능들이 체계적으로 갖춰져 있습니다.
- **단점:** 라이브러리에 비해 초기 학습 곡선이 가파르고, 간단한 작업에는 과하게 느껴질 수 있습니다.

## 4. 상황별 최적의 라이브러리 선택 가이드

| 목표 | 추천 조합 | 이유 |
| --- | --- | --- |
| **정부 API의 JSON 데이터 가져오기** | `Requests` 단독 사용 | API 통신은 정해진 규격의 데이터를 주고받는 것이므로 `Requests`만으로 충분합니다. |
| **블로그의 특정 게시물 제목과 내용 수집** | `Requests` + `BeautifulSoup` | 블로그는 대부분 정적 페이지이며, 두 라이브러리의 조합이 가장 간단하고 효율적입니다. |
| **쇼핑몰의 '더보기' 버튼을 눌러야 나오는 상품 목록 수집** | `Selenium` (+ `BeautifulSoup`) | '더보기'는 자바스크립트로 동작하므로, `Selenium`으로 버튼을 클릭한 후, 변경된 페이지 소스를 파싱해야 합니다. |
| **뉴스 사이트 전체 기사를 매일 수집하여 DB에 저장** | `Scrapy` | 대규모의 데이터를 주기적으로, 빠르게 수집하고, 후처리(DB 저장)까지 자동화해야 하므로 프레임워크 사용이 필수적입니다. |
