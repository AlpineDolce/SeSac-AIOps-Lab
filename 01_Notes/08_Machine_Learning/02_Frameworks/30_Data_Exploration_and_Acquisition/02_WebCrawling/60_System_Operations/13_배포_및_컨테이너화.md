## 1. 왜 배포가 필요한가?

지금까지 우리는 로컬 컴퓨터에서 크롤러를 개발하고 실행했습니다. 하지만 크롤러의 진짜 가치는 **자동으로, 주기적으로, 안정적으로** 실행될 때 발휘됩니다. 내 개인 컴퓨터는 꺼져 있을 수도 있고, 네트워크가 불안정할 수도 있으며, 다른 작업으로 인해 바쁠 수도 있습니다. 따라서 완성된 크롤러는 24시간 동작하는 서버 환경으로 옮겨져야 하는데, 이 과정을 **배포(Deployment)**라고 합니다.

## 2. "제 컴퓨터에서는 되는데요?" 문제의 해결사, Docker

배포 과정에서 가장 흔하게 발생하는 문제는 개발 환경(내 컴퓨터)과 서버 환경의 차이 때문에 코드가 제대로 동작하지 않는 것입니다. (e.g., 파이썬 버전 불일치, 라이브러리 버전 충돌, 운영체제 의존성 누락 등)

**도커(Docker)**는 이 문제를 해결하는 컨테이너 기술의 표준입니다. 도커는 애플리케이션(우리의 Scrapy 프로젝트)과 그 실행에 필요한 모든 것(파이썬 인터프리터, 라이브러리, 시스템 도구 등)을 **컨테이너(Container)**라는 격리된 공간에 함께 포장합니다.

- **컨테이너의 장점:**
    - **이식성:** 이 컨테이너는 노트북, 데스크톱, 클라우드 서버 등 도커가 설치된 곳이라면 어디서든 **완벽하게 동일하게** 동작합니다.
    - **격리성:** 컨테이너는 호스트 시스템이나 다른 컨테이너에 영향을 주지 않는 독립된 환경을 가집니다.
    - **재현성:** `Dockerfile`이라는 설계도만 있으면 언제 어디서든 똑같은 환경을 가진 컨테이너를 만들 수 있습니다.

## 3. `Dockerfile`: 컨테이너 설계도 작성하기

`Dockerfile`은 내 크롤러 컨테이너를 어떻게 만들지 순서대로 적어놓은 텍스트 파일입니다. 프로젝트의 루트 디렉토리에 `Dockerfile`이라는 이름으로 파일을 생성합니다.

**Scrapy 프로젝트를 위한 `Dockerfile` 예시:**
```dockerfile
# 1. 베이스 이미지 선택 (Python 3.9의 가벼운 버전)
FROM python:3.9-slim

# 2. 컨테이너 내의 작업 디렉토리 설정
WORKDIR /app

# 3. 의존성 파일을 먼저 복사하여 설치 (빌드 캐시 활용으로 속도 향상)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 4. 프로젝트 소스 코드 전체를 작업 디렉토리로 복사
COPY . .

# 5. 컨테이너가 시작될 때 실행할 기본 명령어 설정
# 예: scrapy crawl quotes
CMD ["scrapy", "crawl", "quotes"]
```

**설명:**
- `FROM`: 어떤 베이스 이미지에서 시작할지 지정합니다. (e.g., 특정 버전의 파이썬이 설치된 이미지)
- `WORKDIR`: 컨테이너 내부에서 명령을 실행할 기본 경로를 설정합니다.
- `COPY`: 내 컴퓨터의 파일/폴더를 컨테이너 내부로 복사합니다.
- `RUN`: 이미지를 빌드하는 과정에서 실행할 명령입니다. 주로 라이브러리 설치에 사용됩니다.
- `CMD`: 빌드된 이미지로부터 컨테이너를 실행할 때 기본으로 수행될 명령입니다.

## 4. 이미지 빌드 및 컨테이너 실행

`Dockerfile` 작성이 완료되면, 이 설계도를 바탕으로 **이미지(Image)**를 빌드하고, 그 이미지로부터 **컨테이너(Container)**를 실행합니다.

**1. 이미지 빌드:**
`Dockerfile`이 있는 프로젝트 루트 디렉토리에서 다음 명령을 실행합니다.
```bash
# -t 옵션으로 이미지에 이름(mycrawler-image)과 태그(latest)를 부여
# . 은 현재 디렉토리의 Dockerfile을 사용하라는 의미
docker build -t mycrawler-image:latest .
```

**2. 컨테이너 실행:**
빌드된 이미지를 바탕으로 컨테이너를 실행합니다.
```bash
# mycrawler-image:latest 이미지를 사용해 컨테이너를 실행
# --rm : 컨테이너 실행이 끝나면 자동으로 삭제
# -v $(pwd)/data:/app/data : 내 컴퓨터의 data 폴더와 컨테이너의 /app/data 폴더를 연결(마운트)
docker run --rm -v $(pwd)/data:/app/data mycrawler-image:latest
```
- **볼륨 마운트 (`-v` 옵션)의 중요성:** 컨테이너는 격리된 공간이므로, 내부에서 생성된 파일은 컨테이너가 삭제될 때 함께 사라집니다. `-v` 옵션은 컨테이너의 특정 경로를 내 컴퓨터의 경로와 연결하여, 컨테이너가 해당 경로에 파일을 저장하면 실제로는 내 컴퓨터에 저장되도록 만듭니다. 이를 통해 크롤링 결과를 영구적으로 보존할 수 있습니다.

---

**핵심 요약:** **`Dockerfile`을 작성**하여 크롤러와 모든 의존성을 패키징하고, **`docker build`로 이미지**를 만듭니다. 그리고 **`docker run`으로 컨테이너를 실행**하여 어디서든 동일한 환경에서 크롤러를 동작시킬 수 있습니다. 이것이 바로 현대적인 애플리케이션 배포의 기본입니다.
