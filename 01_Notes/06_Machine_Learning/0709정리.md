# 6. 모델 배포 및 유지보수 (Model Deployment & Maintenance)

### 6.1. 모델 직렬화 (Model Serialization)
- **목적:** 학습이 완료된 모델 객체(Scaler, Encoder, Model 등)를 파일 형태로 저장하여 재사용
- **방법:**
  - `pickle`: 파이썬 객체를 직렬화하는 표준 라이브러리
  - `joblib`: NumPy 배열과 같은 대용량 데이터를 다룰 때 `pickle`보다 효율적

### 6.2. 배포 전략 (Deployment Strategies)
- **배치 예측 (Batch Prediction):**
  - **방식:** 정해진 주기(예: 매일 밤)마다 대량의 데이터를 한 번에 예측
  - **적용 사례:** 일일 리포트 생성, 사용자 타겟팅 광고 리스트 업데이트
- **실시간 예측 (Real-time Inference):**
  - **방식:** 사용자 요청이 있을 때마다 즉시 예측 결과를 반환 (API 형태)
  - **적용 사례:** 상품 추천, 사기 거래 실시간 탐지, 챗봇

### 6.3. 서빙 인프라 구축 (Building Serving Infrastructure)
- **API 서버 개발:**
  - **웹 프레임워크:**
    - **Flask:** 가볍고 간단하여 프로토타이핑 및 소규모 서비스에 적합
    - **FastAPI:** 현대적이고 고성능이며, 자동 API 문서 생성 기능 제공
- **컨테이너화 (Containerization):**
  - **Docker:** 모델과 실행 환경(라이브러리, 의존성 등)을 하나의 이미지로 패키징하여 어떤 환경에서든 동일하게 실행되도록 보장
- **서버리스 (Serverless):**
  - **AWS Lambda, Google Cloud Functions:** 서버 관리 없이 코드(예측 함수)만 배포하여 요청이 있을 때만 실행. 트래픽이 적거나 불규칙할 때 비용 효율적.
- **클라우드 ML 플랫폼:**
  - **AWS SageMaker, Google AI Platform, Azure Machine Learning:** 모델 배포, 스케일링, 모니터링 등 MLOps 전반을 지원하는 통합 서비스

### 6.4. MLOps: 모니터링 및 유지보수 (Monitoring & Maintenance)
- **성능 모니터링:**
  - 배포된 모델의 예측 성능(정확도, F1-score 등)을 지속적으로 추적
  - 예측 응답 시간, 서버 리소스(CPU, Memory) 사용량 모니터링
- **데이터 드리프트 (Data Drift) 감지:**
  - **정의:** 시간이 지남에 따라 입력 데이터의 통계적 분포가 변하는 현상
  - **감지:** 현재 입력 데이터의 분포와 학습 시 데이터의 분포를 비교 (예: KS 검정)
- **개념 드리프트 (Concept Drift) 감지:**
  - **정의:** 데이터의 분포는 같지만, 입력 변수와 타겟 변수 간의 관계가 변하는 현상
  - **감지:** 모델 성능이 지속적으로 하락하는 것으로 감지
- **로깅 및 알림 (Logging & Alerting):**
  - 모델의 예측 입력값과 결과값을 로그로 기록
  - 성능 저하 또는 시스템 오류 발생 시 담당자에게 알림(Alert) 전송

### 6.5. 재학습 파이프라인 (Retraining Pipeline)
- **재학습 트리거:**
  - **주기적 재학습:** 정해진 스케줄(예: 매주, 매월)에 따라 자동 재학습
  - **성능 기반 재학습:** 모델 성능이 특정 임계값 이하로 떨어지면 재학습
  - **데이터 기반 재학습:** 새로운 데이터가 일정량 이상 수집되면 재학습
- **자동화 파이프라인 구축:**
  - **도구:** Airflow, Kubeflow, MLflow 등
  - **프로세스:** 데이터 수집 → 전처리 → 모델 학습 → 평가 → 배포의 전 과정을 자동화하여 지속적인 모델 업데이트 및 유지보수(CI/CD for ML) 구현
