## 1. 웹 크롤링 소개

### 1.1. 웹 크롤링이란?

웹 크롤링(Web Crawling) 또는 웹 스크래핑(Web Scraping)은 웹 페이지를 자동으로 탐색하고, 필요한 데이터를 추출하여 구조화된 형태로 저장하는 기술입니다. 마치 거미(Spider)가 웹(Web)을 기어 다니며 정보를 수집하는 것과 같다고 하여 '크롤링'이라는 이름이 붙었습니다.

*   **목적:**
    *   **데이터 수집:** 뉴스 기사, 상품 정보, 주가 데이터, 소셜 미디어 게시물 등 웹에 공개된 방대한 양의 데이터를 자동으로 수집합니다.
    *   **시장 조사 및 경쟁 분석:** 특정 산업의 트렌드, 경쟁사 제품 가격, 고객 반응 등을 모니터링하여 비즈니스 전략 수립에 활용합니다.
    *   **콘텐츠 통합:** 여러 웹사이트에 흩어진 정보를 한곳에 모아 새로운 서비스를 제공합니다.
    *   **머신러닝 데이터셋 구축:** AI 모델 학습에 필요한 대규모 텍스트, 이미지, 숫자 데이터를 웹에서 수집하여 활용합니다.

*   **동작 원리:**
    1.  **HTTP 요청 (Request):** 웹 크롤러는 특정 웹 페이지의 URL로 HTTP 요청(GET, POST 등)을 보냅니다. 이는 웹 브라우저가 웹 서버에 페이지를 요청하는 것과 유사합니다.
    2.  **HTML 응답 (Response):** 웹 서버는 요청에 대한 응답으로 해당 웹 페이지의 HTML, CSS, JavaScript 등의 소스 코드를 반환합니다.
    3.  **HTML 파싱 (Parsing):** 수신된 HTML 소스 코드에서 필요한 데이터를 추출하기 위해 HTML 구조를 분석(파싱)합니다. 이 과정에서 특정 태그, 클래스, ID 등을 기준으로 데이터를 찾아냅니다.
    4.  **데이터 추출 및 저장:** 파싱된 데이터 중 필요한 정보(텍스트, 이미지 URL, 링크 등)를 추출하여 CSV, JSON, 데이터베이스 등 원하는 형태로 저장합니다.
    5.  **링크 탐색 (Optional):** 현재 페이지에서 다른 관련 페이지로 이동할 수 있는 링크(URL)를 찾아 다음 크롤링 대상으로 추가합니다. 이를 통해 웹사이트 전체를 탐색할 수 있습니다.

> **[실무 노트] 크롤링 vs. API:**
> 웹 데이터를 수집하는 가장 좋은 방법은 해당 웹사이트에서 공식적으로 제공하는 API(Application Programming Interface)를 사용하는 것입니다. API는 구조화된 데이터를 안정적이고 효율적으로 제공하며, 사용 정책이 명확합니다. 하지만 모든 웹사이트가 API를 제공하는 것은 아니며, 제공하더라도 필요한 모든 데이터를 얻을 수 없는 경우가 많습니다. 이럴 때 웹 크롤링이 대안이 됩니다. 크롤링은 API가 없는 웹사이트나 API가 제공하지 않는 특정 데이터를 수집할 때 유용하지만, 웹사이트 구조 변경에 취약하고, 서버에 부담을 줄 수 있으며, 윤리적/법적 문제를 야기할 수 있다는 점을 항상 인지해야 합니다.

### 1.2. 웹 크롤링의 중요성

현대 사회에서 데이터는 '새로운 석유'라고 불릴 만큼 중요한 자원입니다. 웹 크롤링은 이러한 데이터를 대규모로 수집할 수 있는 강력한 수단이며, 다양한 산업과 분야에서 데이터 기반 의사결정을 가능하게 하는 핵심적인 역할을 합니다.

*   **시장 동향 및 경쟁 분석:**
    *   경쟁사 제품 가격, 프로모션, 고객 리뷰, 신제품 출시 정보 등을 실시간으로 수집하여 시장 변화에 빠르게 대응하고 경쟁 우위를 확보할 수 있습니다.
    *   특정 산업의 뉴스, 블로그, 포럼 데이터를 분석하여 시장 트렌드와 소비자 심리를 파악합니다.
*   **비즈니스 인텔리전스 (BI) 및 의사결정:**
    *   고객 피드백, 소셜 미디어 언급, 뉴스 기사 등을 크롤링하여 기업의 평판 관리, 위기 감지, 마케팅 전략 수립에 필요한 인사이트를 얻습니다.
    *   부동산 가격, 채용 공고, 여행 상품 가격 등 특정 분야의 데이터를 수집하여 예측 모델을 구축하거나 최적의 의사결정을 지원합니다.
*   **콘텐츠 수집 및 분석:**
    *   뉴스 포털, 블로그, 학술 논문 등에서 텍스트 데이터를 수집하여 자연어 처리(NLP) 모델 학습에 활용하거나, 특정 주제에 대한 여론 분석을 수행합니다.
    *   이미지, 비디오 등 멀티미디어 콘텐츠를 수집하여 컴퓨터 비전 모델 학습에 사용합니다.
*   **자동화된 데이터 파이프라인 구축:**
    *   수동으로 데이터를 수집하는 데 드는 시간과 노력을 절감하고, 정기적으로 자동화된 크롤링을 통해 항상 최신 데이터를 확보할 수 있습니다. 이는 데이터 분석 및 머신러닝 모델의 성능 유지에 필수적입니다.
*   **학술 연구 및 사회 과학:**
    *   방대한 웹 데이터를 활용하여 사회 현상, 문화 트렌드, 경제 지표 등을 분석하고 새로운 가설을 검증하는 데 기여합니다.

> **[실무 노트] 데이터 과학자에게 웹 크롤링이 필수적인 이유:**
> 데이터 과학자는 단순히 주어진 데이터를 분석하는 것을 넘어, 필요한 데이터를 직접 확보하고 가공하는 능력까지 갖춰야 합니다. 웹 크롤링은 데이터 과학자가 '데이터를 만드는' 가장 강력한 도구 중 하나입니다.
>
> *   **데이터 확보 능력:** 실제 비즈니스 문제 해결에 필요한 데이터는 종종 외부에 공개되어 있지만, API 형태로 제공되지 않는 경우가 많습니다. 이때 크롤링 능력은 데이터 과학자가 직접 필요한 데이터를 수집하여 분석 프로젝트를 시작할 수 있게 합니다.
> *   **문제 해결 능력 확장:** 크롤링 과정에서 발생하는 다양한 기술적 문제(웹사이트 구조 변경, 봇 차단, 동적 콘텐츠)를 해결하는 경험은 데이터 과학자의 문제 해결 능력을 향상시킵니다.
> *   **도메인 지식 심화:** 특정 웹사이트의 데이터를 크롤링하고 분석하는 과정에서 해당 도메인에 대한 깊이 있는 이해를 얻을 수 있습니다.
> *   **경쟁력 강화:** 웹 크롤링 능력은 데이터 과학자로서의 경쟁력을 높여주며, 더 넓은 범위의 프로젝트에 참여할 기회를 제공합니다.

### 1.3. 윤리적 고려사항 및 법적 측면

웹 크롤링은 강력한 데이터 수집 도구이지만, 잘못 사용될 경우 웹사이트 운영자에게 피해를 주거나 법적 문제에 휘말릴 수 있습니다. 따라서 크롤링을 시작하기 전에 반드시 윤리적 고려사항과 법적 측면을 충분히 이해해야 합니다.

*   **`robots.txt` 파일 준수:**
    *   대부분의 웹사이트는 `robots.txt` 파일을 통해 어떤 웹 크롤러가 웹사이트의 어떤 부분에 접근할 수 있는지 명시합니다. 이는 웹사이트 운영자의 명시적인 요청이므로, 크롤링 전에 반드시 확인하고 준수해야 합니다.
    *   `robots.txt`는 `http://www.example.com/robots.txt`와 같이 웹사이트 도메인 뒤에 `/robots.txt`를 붙여 접근할 수 있습니다.
*   **서버 부하 최소화:**
    *   과도한 요청은 웹사이트 서버에 부하를 주어 서비스 장애를 유발할 수 있습니다. 요청 간 적절한 지연 시간(delay)을 두거나, 동시 요청 수를 제한하여 서버에 부담을 주지 않도록 해야 합니다.
    *   일반적인 웹 브라우저 사용자의 행동을 모방하여 자연스러운 요청 패턴을 유지하는 것이 좋습니다.
*   **개인 정보 보호:**
    *   웹 크롤링을 통해 개인 식별 정보(PII: Personally Identifiable Information)를 수집하는 것은 매우 민감한 문제입니다. 개인 정보 보호법(GDPR, CCPA 등)을 위반할 경우 심각한 법적 처벌을 받을 수 있습니다.
    *   수집된 데이터에 개인 정보가 포함되어 있다면, 반드시 비식별화(anonymization) 또는 가명화(pseudonymization) 처리하고, 해당 법규를 준수해야 합니다.
*   **저작권 및 데이터 소유권:**
    *   웹에 공개된 데이터라도 저작권이 있을 수 있습니다. 수집된 데이터를 상업적으로 이용하거나 재배포할 경우 저작권 침해 문제가 발생할 수 있으므로, 웹사이트의 이용 약관(Terms of Service)을 확인해야 합니다.
    *   데이터베이스 저작권, 스크린 스크래핑 금지 조항 등 웹사이트마다 다른 정책을 가질 수 있습니다.
*   **로그인 및 인증:**
    *   로그인이 필요한 페이지를 크롤링할 경우, 해당 웹사이트의 이용 약관에 명시된 정책을 따라야 합니다. 무단으로 계정을 생성하거나 타인의 계정을 이용하는 것은 불법입니다.
*   **데이터의 정확성 및 최신성:**
    *   크롤링된 데이터는 웹사이트의 구조 변경이나 업데이트에 따라 부정확해지거나 오래될 수 있습니다. 데이터의 품질을 유지하기 위한 주기적인 검증 및 업데이트 프로세스가 필요합니다.

> **[실무 노트] 크롤링 전 체크리스트:**
> 웹 크롤링 프로젝트를 시작하기 전에 다음 체크리스트를 반드시 확인하여 불필요한 위험을 줄여야 합니다.
>
> 1.  **`robots.txt` 확인:** 크롤링하려는 URL의 `robots.txt` 파일을 확인하여 허용된 범위 내에서만 크롤링을 진행합니다.
> 2.  **이용 약관(Terms of Service) 검토:** 웹사이트의 이용 약관에 크롤링 또는 데이터 사용에 대한 명시적인 금지 조항이 있는지 확인합니다.
> 3.  **서버 부하 테스트:** 소규모 테스트 크롤링을 통해 웹사이트 서버에 무리가 가지 않는지 확인하고, 요청 간 적절한 지연 시간을 설정합니다.
> 4.  **데이터 사용 목적 명확화:** 수집된 데이터를 어떤 목적으로 사용할 것인지 명확히 하고, 해당 목적이 윤리적/법적으로 문제가 없는지 검토합니다.
> 5.  **개인 정보 포함 여부 확인:** 수집될 데이터에 개인 정보가 포함될 가능성이 있다면, 비식별화/가명화 처리 계획을 수립하고 관련 법규를 준수합니다.
> 6.  **데이터 품질 관리 계획:** 웹사이트 구조 변경에 대비하여 크롤링 스크립트 유지보수 및 데이터 유효성 검증 계획을 세웁니다.
>
> 이 체크리스트를 준수하는 것은 데이터 과학자로서 책임감 있는 크롤링을 수행하는 기본 자세입니다.

### 1.4. 파이썬 웹 크롤링 생태계 개요

파이썬은 간결한 문법과 풍부한 라이브러리 생태계 덕분에 웹 크롤링 분야에서 가장 널리 사용되는 언어입니다. 다양한 라이브러리들이 각기 다른 웹 크롤링 요구사항을 충족시키며, 이들을 조합하여 복잡한 크롤링 시스템을 구축할 수 있습니다.

*   **Requests:**
    *   **역할:** HTTP 요청을 보내고 응답을 받는 가장 기본적인 라이브러리입니다. 웹 페이지의 HTML 소스 코드를 가져오는 데 사용됩니다.
    *   **특징:** 사용하기 쉽고 직관적인 API를 제공하며, GET, POST 등 다양한 HTTP 메서드를 지원합니다. 세션 관리, 인증, 파일 업로드 등 복잡한 요청도 쉽게 처리할 수 있습니다.
    *   **적합한 시나리오:** 정적인 웹 페이지의 HTML을 가져올 때, API 호출을 통해 데이터를 수집할 때.
*   **BeautifulSoup:**
    *   **역할:** Requests 등으로 가져온 HTML 또는 XML 문서를 파싱(Parsing)하여 원하는 데이터를 쉽게 추출할 수 있도록 돕는 라이브러리입니다.
    *   **특징:** HTML 구조를 트리 형태로 변환하여 탐색하기 쉽게 만들며, 태그 이름, 속성, CSS 선택자 등을 이용하여 데이터를 검색하고 추출하는 강력한 기능을 제공합니다.
    *   **적합한 시나리오:** 정적인 웹 페이지에서 특정 텍스트, 이미지 URL, 링크 등을 추출할 때.
*   **Selenium:**
    *   **역할:** 웹 브라우저를 직접 제어하여 웹 페이지와 상호작용하는 자동화 도구입니다. JavaScript로 동적으로 로딩되는 콘텐츠, 로그인, 버튼 클릭, 스크롤 등 복잡한 사용자 행동을 모방할 수 있습니다.
    *   **특징:** 실제 브라우저(Chrome, Firefox 등)를 실행하여 웹 페이지를 렌더링하므로, JavaScript 실행 결과로 생성되는 동적 콘텐츠를 크롤링할 수 있습니다. 웹 테스트 자동화에도 널리 사용됩니다.
    *   **적합한 시나리오:** 동적인 웹 페이지 크롤링, 로그인 후 데이터 수집, 무한 스크롤 페이지 처리 등.
*   **Scrapy:**
    *   **역할:** 웹 크롤링 프로젝트를 위한 강력한 프레임워크입니다. 대규모 웹사이트를 효율적으로 크롤링하고, 데이터 처리 파이프라인을 구축하는 데 필요한 모든 기능을 제공합니다.
    *   **특징:** 비동기 처리, 요청 스케줄링, 미들웨어, 파이프라인 등 복잡한 크롤링 시스템을 위한 구조를 제공합니다. 분산 크롤링도 지원합니다.
    *   **적합한 시나리오:** 대규모 웹사이트 크롤링, 정기적인 데이터 수집, 복잡한 크롤링 로직이 필요한 프로젝트.

> **[실무 노트] 라이브러리 조합 전략:**
> 실무에서는 단일 라이브러리만 사용하는 경우보다 여러 라이브러리를 조합하여 사용하는 경우가 많습니다.
>
> *   **정적 페이지:** `Requests`로 HTML을 가져오고, `BeautifulSoup`으로 데이터를 파싱 및 추출하는 조합이 가장 일반적이고 효율적입니다.
> *   **동적 페이지:** `Selenium`으로 웹 페이지를 렌더링하고 필요한 상호작용을 수행한 후, `Selenium`이 가져온 페이지 소스(또는 `BeautifulSoup`을 함께 사용하여)에서 데이터를 추출합니다.
> *   **대규모/복잡한 프로젝트:** `Scrapy` 프레임워크를 사용하여 전체 크롤링 프로세스를 관리하고, 필요에 따라 `Requests`, `BeautifulSoup`, `Selenium` 등의 기능을 통합하여 사용합니다.
>
> 각 라이브러리의 장단점과 적합한 사용 시나리오를 이해하고, 크롤링하려는 웹사이트의 특성(정적/동적, 규모, 복잡성)에 맞춰 최적의 조합을 선택하는 것이 중요합니다.
