## 1. OOP의 4대 원칙

객체 지향 프로그래밍의 핵심을 이루는 네 가지 원칙은 코드의 구조화, 재사용성, 유지보수성, 확장성을 높이는 데 기여합니다.

### 1.1 캡슐화 (Encapsulation)

**캡슐화**는 데이터(속성)와 데이터를 처리하는 메서드(행동)를 하나의 단위(클래스)로 묶고, 외부에서 객체 내부의 데이터에 직접 접근하는 것을 제한하여 데이터의 무결성을 보호하는 개념입니다. 이는 곧 **정보 은닉(Information Hiding)**을 통해 객체의 내부 구현을 숨기고, 외부에는 잘 정의된 인터페이스만을 노출하는 것을 목표로 합니다. 파이썬은 다른 언어처럼 `private`나 `protected`와 같은 엄격한 접근 제어자를 제공하지 않지만, 개발자 간의 약속(컨벤션)과 신뢰를 바탕으로 하는 **"성인들의 합의(Consenting Adults)"** 철학에 따라 캡슐화를 구현합니다.

- **단일 언더스코어 (`_variable`):** 내부적으로만 사용될 변수나 메서드임을 나타내는 컨벤션입니다. 외부에서 접근은 가능하지만, 개발자에게 "이것은 내부용이니 직접 건드리지 마세요"라고 알리는 역할을 합니다.
- **이중 언더스코어 (`__variable`):** "이름 맹글링(Name Mangling)"이라는 파이썬의 특수 기능으로, 클래스 외부에서 직접 접근하기 어렵게 만듭니다. `_클래스명__변수명` 형태로 변수명이 변경되어 충돌을 방지합니다. 완전히 private한 것은 아니지만, 의도치 않은 외부 접근을 막는 데 효과적입니다.
- **접근자 (Accessor)와 변경자 (Mutator):**
  - **게터 (Getter):** 객체의 속성 값을 읽어오는 메서드입니다. (예: `get_balance()`, `@property`)
  - **세터 (Setter):** 객체의 속성 값을 설정하는 메서드입니다. 이때 유효성 검사 등의 로직을 포함할 수 있습니다. (예: `set_balance(amount)`, `@property`의 `setter`)
  이러한 메서드를 통해 속성에 직접 접근하는 대신 간접적으로 접근하여 데이터의 무결성을 유지하고, 속성 변경 시 추가적인 로직을 수행할 수 있습니다.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance # 이중 언더스코어: 외부에서 직접 접근 제한

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"{amount}원 입금. 현재 잔액: {self.__balance}원")
        else:
            print("0원보다 큰 금액을 입금해주세요.")

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            print(f"{amount}원 출금. 현재 잔액: {self.__balance}원")
        else:
            print("잔액이 부족하거나 유효하지 않은 금액입니다.")

    def get_balance(self):
        return self.__balance

# 인스턴스 생성
account = BankAccount("김철수", 10000)

# 메서드를 통한 접근 (권장)
account.deposit(5000)
account.withdraw(2000)
print(f"최종 잔액: {account.get_balance()}원")

# 직접 접근 시도 (이름 맹글링으로 인해 접근 어려움)
# print(account.__balance) # AttributeError

# 이름 맹글링된 이름으로 접근 (권장하지 않음)
print(f"맹글링된 이름으로 접근: {account._BankAccount__balance}원")
```

### 1.2 상속 (Inheritance)

**상속**은 기존 클래스(부모 클래스 또는 기반 클래스)의 속성과 메서드를 새로운 클래스(자식 클래스 또는 파생 클래스)가 물려받아 재사용하고 확장하는 개념입니다. 코드 재사용성을 높이고, 계층적인 관계를 모델링하는 데 사용됩니다.

- **`super()`:** 자식 클래스에서 부모 클래스의 메서드를 호출할 때 사용합니다. 특히 부모 클래스의 `__init__` 메서드를 호출하여 부모의 속성을 초기화하는 데 필수적입니다.

```python
# 부모 클래스
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError("자식 클래스에서 구현해야 합니다.")

# 자식 클래스 (Animal을 상속)
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name) # 부모 클래스의 __init__ 호출
        self.breed = breed

    def speak(self):
        return f"{self.name}가 멍멍!"

class Cat(Animal):
    def __init__(self, name, color):
        super().__init__(name)
        self.color = color

    def speak(self):
        return f"{self.name}가 야옹!"

# 인스턴스 생성 및 사용
my_dog = Dog("바둑이", "진돗개")
my_cat = Cat("나비", "삼색")

print(my_dog.speak())
print(my_cat.speak())

print(f"내 강아지 품종: {my_dog.breed}")
print(f"내 고양이 색깔: {my_cat.color}")
```
- **다중 상속 (Multiple Inheritance):**
  파이썬은 여러 부모 클래스로부터 상속받는 **다중 상속**을 지원합니다. 이는 강력한 기능이지만, 클래스 계층 구조가 복잡해지고 메서드 탐색 순서(Method Resolution Order, MRO)에 따라 예상치 못한 동작을 할 수 있는 **다이아몬드 문제(Diamond Problem)**와 같은 복잡성을 야기할 수 있습니다. `super()` 함수는 MRO에 따라 다음 부모 클래스의 메서드를 호출하며, 특히 다중 상속 환경에서 협력적인(cooperative) 메서드 호출을 가능하게 합니다.
  ```python
  class A:
      def method(self): print("Method A")

  class B(A):
      def method(self): print("Method B")

  class C(A):
      def method(self): print("Method C")

  class D(B, C):
      pass

  d = D()
  d.method() # Method B (MRO에 따라 B가 먼저 탐색됨)
  print(D.__mro__) # MRO 확인
  ```
  **실무적 의미:** 다중 상속은 신중하게 사용해야 하며, 복잡성을 피하기 위해 컴포지션(Composition)을 선호하는 것이 일반적입니다.


### 1.3 다형성 (Polymorphism)

**다형성**은 동일한 이름의 메서드가 다른 클래스(특히 상속 관계에 있는 클래스)에서 다르게 동작하는 능력을 의미합니다. 이를 통해 코드를 더 유연하고 확장 가능하게 만들 수 있습니다. 주로 **메서드 오버라이딩(Method Overriding)**을 통해 구현됩니다. 또한, 파이썬의 **연산자 오버로딩**(`__add__`, `__mul__` 등 특수 메서드 구현)도 다형성의 한 형태로, 동일한 연산자가 다른 객체 타입에 따라 다르게 동작하도록 정의할 수 있습니다.

- **메서드 오버라이딩:** 자식 클래스에서 부모 클래스에 정의된 메서드를 자신의 필요에 맞게 재정의하는 것입니다.

```python
class Shape:
    def area(self):
        raise NotImplementedError("자식 클래스에서 area() 메서드를 구현해야 합니다.")

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius ** 2

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

# 다형성 활용
shapes = [Circle(5), Rectangle(4, 6)]

for shape in shapes:
    # 각 객체의 타입에 맞는 area() 메서드가 호출됨
    print(f"도형의 넓이: {shape.area():.2f}")
```

### 1.4 추상화 (Abstraction)

**추상화**는 복잡한 구현 세부 사항을 숨기고, 사용자에게 필요한 핵심 기능(인터페이스)만 노출하는 개념입니다. 이를 통해 시스템의 복잡도를 줄이고, 사용자가 특정 기능을 사용할 때 내부 동작을 알 필요 없이 간편하게 사용할 수 있도록 합니다. 파이썬에서는 `abc` (Abstract Base Classes) 모듈을 사용하여 추상 클래스와 추상 메서드를 구현할 수 있습니다.

- **추상 클래스:** 직접 인스턴스를 생성할 수 없고, 반드시 상속받아 구현해야 하는 클래스입니다.
- **추상 메서드:** 선언만 있고 구현은 없는 메서드로, 추상 클래스를 상속받는 자식 클래스에서 반드시 오버라이딩하여 구현해야 합니다.

```python
from abc import ABC, abstractmethod

class Vehicle(ABC): # 추상 클래스 선언
    def __init__(self, name):
        self.name = name

    @abstractmethod
    def start(self):
        """차량을 시동하는 추상 메서드"""
        pass

    @abstractmethod
    def stop(self):
        """차량을 정지하는 추상 메서드"""
        pass

    def get_name(self):
        return self.name

class Car(Vehicle):
    def start(self):
        print(f"{self.name}가 시동을 걸었습니다.")

    def stop(self):
        print(f"{self.name}가 정지했습니다.")

class Motorcycle(Vehicle):
    def start(self):
        print(f"{self.name}가 시동을 걸고 출발합니다.")

    def stop(self):
        print(f"{self.name}가 멈췄습니다.")

# vehicle = Vehicle("일반 차량") # TypeError: Can't instantiate abstract class Vehicle with abstract methods start, stop

my_car = Car("내 자동차")
my_motorcycle = Motorcycle("내 오토바이")

my_car.start()
my_car.stop()
my_motorcycle.start()
my_motorcycle.stop()
```

### 1.5 컴포지션 (Composition) vs 상속 (Inheritance)

객체 지향 설계에서 클래스 간의 관계를 설정하는 두 가지 주요 방법은 상속(Inheritance)과 컴포지션(Composition)입니다.

-   **상속 (Inheritance):** "~은(는) ~이다 (is-a)" 관계를 나타냅니다. (예: `Dog` is-a `Animal`). 코드 재사용성을 높이지만, 부모 클래스의 변경이 자식 클래스에 영향을 미칠 수 있고, 다중 상속의 복잡성 문제가 발생할 수 있습니다.

-   **컴포지션 (Composition):** "~은(는) ~을(를) 가진다 (has-a)" 관계를 나타냅니다. (예: `Car` has-a `Engine`). 클래스가 다른 클래스의 인스턴스를 속성으로 포함하여 기능을 재사용합니다. 상속보다 유연하고 견고한 설계를 가능하게 하며, 결합도를 낮추고 응집도를 높이는 데 유리합니다.

**실무적 의미:**

-   **"상속보다 컴포지션을 선호하라 (Prefer composition over inheritance)"**는 객체 지향 설계의 중요한 원칙 중 하나입니다. 이는 상속이 클래스 간의 강한 결합을 만들고 유연성을 저해할 수 있기 때문입니다.
-   컴포지션을 사용하면 특정 기능을 가진 객체를 "조립"하여 더 복잡한 객체를 만들 수 있으며, 필요에 따라 기능을 쉽게 교체하거나 확장할 수 있습니다.

```python
# 컴포지션 예시
class Engine:
    def start(self):
        return "엔진 시동!"

    def stop(self):
        return "엔진 정지!"

class Car:
    def __init__(self, brand, engine: Engine):
        self.brand = brand
        self.engine = engine # Car는 Engine 객체를 가집니다 (has-a 관계)

    def start_car(self):
        print(f"{self.brand} 자동차: {self.engine.start()}")

    def stop_car(self):
        print(f"{self.brand} 자동차: {self.engine.stop()}")

# 사용
my_engine = Engine()
my_car = Car("Tesla", my_engine)
my_car.start_car()
my_car.stop_car()

# 엔진을 다른 종류로 쉽게 교체 가능
class ElectricEngine:
    def start(self):
        return "전기 모터 가동!"

    def stop(self):
        return "전기 모터 정지!"

e_car = Car("Hyundai", ElectricEngine())
e_car.start_car()
e_car.stop_car()
```
- **믹스인 (Mixin) 클래스:**
  믹스인은 특정 기능을 제공하지만 독립적으로 인스턴스화될 목적이 없는 클래스입니다. 주로 다중 상속과 함께 사용되어 여러 클래스에 공통된 행동을 주입하는 데 활용됩니다. 이는 상속과 컴포지션의 장점을 결합한 패턴으로, 특히 **행동의 수평적 재사용(Horizontal Reuse)**을 달성하는 데 유용합니다.
  ```python
  class SerializableMixin:
      def to_json(self):
          import json
          return json.dumps(self.__dict__)

  class User(SerializableMixin):
      def __init__(self, name, email):
          self.name = name
          self.email = email

  user = User("Alice", "alice@example.com")
  print(f"User to JSON: {user.to_json()}")
  ```


## 2. 프로퍼티 (`@property`)를 이용한 캡슐화

`@property` 데코레이터는 클래스의 속성(attribute)에 접근하거나 값을 설정할 때 특정 로직을 실행하도록 하는 파이썬의 강력한 기능입니다. 이를 통해 속성에 대한 직접적인 접근을 제어하고, 유효성 검사, 계산된 속성 등을 구현하여 캡슐화를 강화할 수 있습니다.

- **게터 (Getter):** 속성 값을 읽을 때 호출되는 메서드.
- **세터 (Setter):** 속성 값을 설정할 때 호출되는 메서드.
- **딜리터 (Deleter):** 속성을 삭제할 때 호출되는 메서드.

```python
class Person:
    def __init__(self, name, age):
        self._name = name # 내부적으로 사용될 변수 (컨벤션)
        self._age = age

    @property
    def name(self):
        """이름을 반환하는 게터"""
        return self._name

    @name.setter
    def name(self, new_name):
        """이름을 설정하는 세터 (유효성 검사 포함)"""
        if not isinstance(new_name, str) or len(new_name) == 0:
            raise ValueError("이름은 비어있지 않은 문자열이어야 합니다.")
        self._name = new_name

    @property
    def age(self):
        """나이를 반환하는 게터"""
        return self._age

    @age.setter
    def age(self, new_age):
        """나이를 설정하는 세터 (유효성 검사 포함)"""
        if not isinstance(new_age, (int, float)) or new_age < 0:
            raise ValueError("나이는 0보다 크거나 같은 숫자여야 합니다.")
        self._age = new_age

# 인스턴스 생성
p = Person("Alice", 30)

# 프로퍼티를 통한 값 접근 (게터 호출)
print(f"이름: {p.name}, 나이: {p.age}")

# 프로퍼티를 통한 값 설정 (세터 호출)
p.name = "Bob"
p.age = 31
print(f"변경된 이름: {p.name}, 변경된 나이: {p.age}")

# 유효성 검사 실패 예시
try:
    p.age = -5
except ValueError as e:
    print(f"에러: {e}")

try:
    p.name = ""
except ValueError as e:
    print(f"에러: {e}")
```

## 3. 특수 메서드 (Special Methods / Dunder Methods)

특수 메서드(Special Methods)는 이름이 두 개의 언더스코어(`__`)로 시작하고 끝나는 메서드들을 의미하며, "던더 메서드(Dunder Methods)"라고도 불립니다. 이 메서드들은 파이썬의 내장 함수나 연산자(예: `+`, `==`, `len()`, `[]`)와 연동하여 객체의 특정 동작을 정의하고 사용자 정의 클래스가 파이썬의 기본 타입처럼 동작하도록 만듭니다. 이를 통해 "파이썬스러운(Pythonic)" 코드를 작성할 수 있습니다.

### 3.1 `__str__`과 `__repr__` (복습)

(이 내용은 0507정리.md에서 자세히 다루었으므로 간략히 복습합니다.)

- **`__str__(self)`:** 객체의 사용자 친화적인 문자열 표현을 반환합니다. `print()`나 `str()` 호출 시 사용됩니다.
- **`__repr__(self)`:** 객체의 개발자 친화적인 문자열 표현을 반환합니다. 객체를 다시 생성할 수 있는 형태의 문자열을 권장하며, `repr()` 호출 시 사용됩니다.

```python
class MyObject:
    def __init__(self, value):
        self.value = value

    def __str__(self):
        return f"MyObject with value: {self.value}"

    def __repr__(self):
        return f"MyObject({self.value})"

obj = MyObject(123)
print(obj) # __str__
print(repr(obj)) # __repr__
```

### 3.2 비교 연산자 오버로딩 (`__eq__`, `__lt__` 등)

객체 간의 비교 연산(`==`, `!=`, `<`, `<=`, `>`, `>=`)이 어떻게 동작할지 정의합니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `==` | `__eq__(self, other)` | 같음 |
| `!=` | `__ne__(self, other)` | 같지 않음 |
| `<` | `__lt__(self, other)` | 작음 |
| `<=` | `__le__(self, other)` | 작거나 같음 |
| `>` | `__gt__(self, other)` | 큼 |
| `>=` | `__ge__(self, other)` | 크거나 같음 |

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        # x 좌표가 다르면 x로 비교, 같으면 y로 비교
        return self.x < other.x or (self.x == other.x and self.y < other.y)

p1 = Point(1, 2)
p2 = Point(1, 2)
p3 = Point(3, 1)

print(f"p1 == p2: {p1 == p2}") # True
print(f"p1 == p3: {p1 == p3}") # False
print(f"p1 < p3: {p1 < p3}")   # True
```

### 3.3 산술 연산자 오버로딩 (`__add__`, `__mul__` 등)

객체 간의 산술 연산(`+`, `-`, `*`, `/` 등)이 어떻게 동작할지 정의합니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `+` | `__add__(self, other)` | 덧셈 |
| `-` | `__sub__(self, other)` | 뺄셈 |
| `*` | `__mul__(self, other)` | 곱셈 |
| `/` | `__truediv__(self, other)` | 나눗셈 |
| `//` | `__floordiv__(self, other)` | 몫 |
| `%` | `__mod__(self, other)` | 나머지 |
| `**` | `__pow__(self, other)` | 거듭제곱 |

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector(self.x * scalar, self.y * scalar)

    def __str__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)

v_sum = v1 + v2
print(f"벡터 덧셈: {v_sum}") # Vector(4, 6)

v_scaled = v1 * 3
print(f"벡터 스칼라 곱셈: {v_scaled}") # Vector(3, 6)
```

### 3.4 컨테이너 타입 메서드 (`__len__`, `__getitem__`, `__setitem__` 등)

객체가 시퀀스(리스트, 튜플)나 매핑(딕셔너리)처럼 동작하도록 정의합니다.

| 연산/함수 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `len(obj)` | `__len__(self)` | 객체의 길이 반환 (음수가 아닌 정수여야 함) |
| `obj[key]` | `__getitem__(self, key)` | 인덱스/키로 요소 접근 |
| `obj[key] = value` | `__setitem__(self, key, value)` | 인덱스/키로 요소 설정 |
| `del obj[key]` | `__delitem__(self, key)` | 인덱스/키로 요소 삭제 |
| `key in obj` | `__contains__(self, key)` | 요소 포함 여부 확인 |

```python
class MyList:
    def __init__(self, data):
        self._data = list(data)

    def __len__(self):
        return len(self._data)

    def __getitem__(self, index):
        return self._data[index]

    def __setitem__(self, index, value):
        self._data[index] = value

    def __str__(self):
        return str(self._data)

ml = MyList([10, 20, 30, 40])

print(f"길이: {len(ml)}") # __len__ 호출
print(f"인덱스 1의 요소: {ml[1]}") # __getitem__ 호출

ml[1] = 25 # __setitem__ 호출
print(f"수정 후: {ml}")

# for 루프도 __getitem__과 __len__을 사용하여 동작할 수 있습니다.
for item in ml:
    print(item, end=' ')
print()
```

### 3.5 `__call__` 메서드: 객체를 함수처럼 호출하기

`__call__` 메서드를 구현하면 클래스의 인스턴스를 함수처럼 호출할 수 있게 됩니다. 이는 객체에 상태를 저장하고, 이 상태를 기반으로 특정 작업을 수행하는 함수 객체(functor)를 만들 때 유용합니다. 특히 데코레이터나 콜백 함수를 구현할 때 강력한 패턴으로 활용될 수 있습니다.

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, number):
        """객체를 함수처럼 호출할 때 실행되는 메서드"""
        return number * self.factor

# 인스턴스 생성
double = Multiplier(2)
triple = Multiplier(3)

# 객체를 함수처럼 호출
print(f"double(5): {double(5)}")   # Output: 10
print(f"triple(5): {triple(5)}")   # Output: 15

# 데코레이터로 활용 예시 (고급)
class LogCalls:
    def __init__(self, func):
        self.func = func

    def __call__(self, *args, **kwargs):
        print(f"Calling {self.func.__name__} with args: {args}, kwargs: {kwargs}")
        result = self.func(*args, **kwargs)
        print(f"{self.func.__name__} returned: {result}")
        return result

@LogCalls
def add(a, b):
    return a + b

add(10, 20)
```

**실무적 의미:**
-   **상태를 가진 함수:** 특정 상태(예: 설정값, 캐시)를 유지하면서 함수처럼 동작하는 객체를 만들 때 유용합니다.
-   **데코레이터 클래스:** 함수를 감싸서 추가 기능을 부여하는 데코레이터를 클래스 형태로 구현할 때 `__call__` 메서드가 핵심적으로 사용됩니다.
-   **머신러닝 모델:** 학습된 머신러닝 모델을 클래스로 구현하고 `__call__` 메서드를 사용하여 새로운 입력 데이터에 대한 예측을 수행하도록 만들 수 있습니다. (예: `model(input_data)`)
-   **함수형 프로그래밍 패턴:** `__call__` 메서드는 특정 상태를 캡슐화하고 함수처럼 동작하는 객체를 생성하여, 함수형 프로그래밍에서 콜백, 전략 패턴 등을 구현하는 데 유용하게 사용됩니다.

### 3.6 속성 접근 제어 메서드 (`__getattr__`, `__setattr__`, `__delattr__`)

파이썬은 객체의 속성(attribute)에 접근, 설정, 삭제하는 방식을 커스터마이징할 수 있는 특수 메서드들을 제공합니다. 이를 통해 동적인 속성 관리, 유효성 검사, 로깅, 프록시 객체 구현 등 다양한 고급 기능을 구현할 수 있습니다.

-   **`__getattr__(self, name)`:** 객체에 존재하지 않는 속성에 접근하려고 할 때 호출됩니다. 기본 `AttributeError`를 방지하고 동적으로 속성을 생성하거나 다른 곳에서 가져올 때 사용됩니다.
-   **`__setattr__(self, name, value)`:** 객체의 속성을 설정하려고 할 때마다 호출됩니다. 속성 설정에 대한 유효성 검사, 로깅, 또는 특정 속성 변경 시 다른 작업을 트리거할 때 사용됩니다.
-   **`__delattr__(self, name)`:** 객체의 속성을 삭제하려고 할 때 호출됩니다.

```python
class DynamicAttributes:
    def __init__(self):
        self._data = {}

    def __getattr__(self, name):
        """존재하지 않는 속성에 접근 시 호출"""
        if name in self._data:
            return self._data[name]
        raise AttributeError(f"'{self.__class__.__name__}' object has no attribute '{name}'")

    def __setattr__(self, name, value):
        """속성 설정 시 호출"""
        if name == '_data': # 무한 재귀 방지
            super().__setattr__(name, value)
        else:
            print(f"Setting attribute '{name}' to '{value}'")
            self._data[name] = value

    def __delattr__(self, name):
        """속성 삭제 시 호출"""
        if name in self._data:
            print(f"Deleting attribute '{name}'")
            del self._data[name]
        else:
            raise AttributeError(f"'{self.__class__.__name__}' object has no attribute '{name}'")

# 인스턴스 생성
dyn_obj = DynamicAttributes()

# __setattr__ 호출
dyn_obj.name = "Test"
dyn_obj.age = 10

# __getattr__ 호출
print(f"dyn_obj.name: {dyn_obj.name}")
print(f"dyn_obj.age: {dyn_obj.age}")

# 존재하지 않는 속성 접근 시 __getattr__ 호출 후 AttributeError 발생
try:
    print(dyn_obj.non_existent)
except AttributeError as e:
    print(f"Error: {e}")

# __delattr__ 호출
del dyn_obj.name

# 삭제된 속성 접근 시도
try:
    print(dyn_obj.name)
except AttributeError as e:
    print(f"Error: {e}")
```

**실무적 의미:**
-   **ORM (Object-Relational Mapping):** 데이터베이스의 컬럼을 객체의 속성처럼 다룰 때 내부적으로 이러한 메커니즘이 사용될 수 있습니다.
-   **프록시 객체 및 지연 로딩 (Lazy Loading):** 실제 객체에 대한 접근을 가로채서 추가적인 로직(예: 캐싱, 권한 검사)을 수행하는 프록시 객체를 만들거나, 필요한 시점에만 데이터를 로드하는 지연 로딩 메커니즘을 구현할 때 이러한 특수 메서드들이 핵심적으로 활용됩니다.
-   **동적 설정 객체:** 런타임에 속성이 동적으로 추가되거나 변경되는 설정 객체(예: 설정 파일에서 로드되는 설정)를 설계할 때 유용합니다.
-   **동적 설정:** 런타임에 속성이 동적으로 추가되거나 변경되는 시스템을 설계할 때 유용합니다.
