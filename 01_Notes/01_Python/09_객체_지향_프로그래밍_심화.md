## 1. OOP의 4대 원칙

객체 지향 프로그래밍의 핵심을 이루는 네 가지 원칙은 코드의 구조화, 재사용성, 유지보수성, 확장성을 높이는 데 기여합니다.

### 1.1 캡슐화 (Encapsulation)

**캡슐화**는 객체 지향 프로그래밍의 가장 기본이 되는 원칙으로, **데이터(속성)와 해당 데이터를 처리하는 함수(메서드)를 하나의 단위인 '클래스'로 묶는 것**을 의미합니다. 더 나아가, 객체의 중요한 데이터가 외부에서 임의로 변경되지 않도록 보호하고, 오직 클래스 내부에 정의된 메서드를 통해서만 접근하고 수정하도록 제한하는 **정보 은닉(Information Hiding)**의 개념을 포함합니다.

**핵심 목표:**

*   **데이터 보호:** 객체의 내부 상태를 외부로부터 숨겨, 의도치 않은 값의 변경이나 오용을 방지하고 데이터의 무결성을 유지합니다.
*   **복잡성 감소:** 사용자는 객체의 복잡한 내부 구현을 알 필요 없이, 외부에 공개된 메서드(인터페이스)만 사용하여 객체를 조작할 수 있습니다. 이는 시스템의 복잡도를 낮추고 유지보수성을 높입니다.

#### 1.1.1 파이썬에서의 캡슐화: 컨벤션과 이름 맹글링

Java나 C++과 달리, 파이썬은 `public`, `private`, `protected`와 같이 외부 접근을 강제로 막는 접근 제어자를 제공하지 않습니다. 대신, 개발자들 간의 **"성인들의 합의(Consenting Adults)"** 라는 철학에 따라, 변수명의 컨벤션을 통해 접근 수준을 암시합니다.

*   **`public` 멤버:** 언더스코어 없이 시작하는 모든 변수와 메서드는 기본적으로 `public`입니다. 외부 어디서든 자유롭게 접근할 수 있습니다.

*   **`_protected` 멤버 (단일 언더스코어):** 변수나 메서드 이름이 **단일 언더스코어(`_`)**로 시작하면, 이는 "내부적으로 사용되지만, 자식 클래스에서는 접근해도 괜찮다"는 의미의 `protected` 멤버임을 나타내는 **컨벤션**입니다. 파이썬 인터프리터가 접근을 막지는 않지만, 개발자에게 "이것은 내부용이니 가급적 직접 건드리지 마세요"라고 알리는 신호입니다.

*   **`__private` 멤버 (이중 언더스코어):** 변수나 메서드 이름이 **이중 언더스코어(`__`)**로 시작하면, 파이썬은 **이름 맹글링(Name Mangling)**이라는 기술을 적용합니다. 이는 변수명을 `_클래스명__변수명` 형태로 바꾸어, 클래스 외부에서 일반적인 방법으로는 직접 접근하기 어렵게 만듭니다. 상속 관계에서 발생할 수 있는 이름 충돌을 방지하고, 의도치 않은 외부 접근을 막는 데 효과적입니다.

#### 1.1.2 실무 예제: 데이터 로더 클래스

데이터 분석 파이프라인에서 데이터 로더를 클래스로 구현하는 상황을 가정해 봅시다. 이 클래스는 데이터 경로, 로드된 데이터, 캐시 상태 등 내부적으로 관리해야 할 중요한 상태 정보들을 가집니다. 캡슐화를 통해 이러한 내부 상태를 안전하게 보호할 수 있습니다.

```python
import pandas as pd

class DataLoader:
    def __init__(self, file_path: str):
        self.public_source = file_path  # 외부에서 참조 가능한 공개 속성
        self._file_path = file_path     # 내부용 속성 (protected 컨벤션)
        self.__cache = None             # 캐시된 데이터 (private 컨벤션)
        self.__is_loaded = False        # 로드 상태 (private 컨벤션)

    def __load_data(self) -> pd.DataFrame:
        """실제 데이터를 로드하는 내부 전용 메서드"""
        print(f"'{self._file_path}'에서 데이터를 로드합니다... (시간이 오래 걸리는 작업)")
        # 예시: 실제로는 pd.read_csv(self._file_path) 등을 사용
        df = pd.DataFrame({'col1': [1, 2, 3], 'col2': [4, 5, 6]})
        self.__cache = df
        self.__is_loaded = True
        return df

    def get_data(self) -> pd.DataFrame:
        """외부에 공개된 데이터 접근용 메서드 (Accessor/Getter 역할)"""
        print("데이터 요청을 받았습니다.")
        if not self.__is_loaded:
            # 캐시가 없으면 내부 로드 메서드를 호출
            return self.__load_data()
        else:
            # 캐시가 있으면 즉시 반환
            print("캐시된 데이터를 반환합니다.")
            return self.__cache

    def get_status(self) -> str:
        """객체의 내부 상태를 알려주는 공개 메서드"""
        return f"로드 상태: {'완료' if self.__is_loaded else '대기'}"

# 데이터 로더 인스턴스 생성
loader = DataLoader("my_large_dataset.csv")

# 1. 공개된 인터페이스 사용
print(f"데이터 소스: {loader.public_source}")
print(f"현재 상태: {loader.get_status()}")

# 2. get_data()를 처음 호출 -> __load_data()가 내부적으로 실행됨
data1 = loader.get_data()
print("\n--- 첫 번째 데이터 요청 ---")
print(data1.head())
print(f"현재 상태: {loader.get_status()}")

# 3. get_data()를 다시 호출 -> 캐시된 데이터가 즉시 반환됨
data2 = loader.get_data()
print("\n--- 두 번째 데이터 요청 ---")
print(data2.head())

# 4. 내부 속성에 직접 접근 시도
print(f"\n내부 속성 접근: {loader._file_path}") # 접근은 되지만, 권장되지 않음

try:
    print(loader.__cache) # 이름 맹글링으로 인해 AttributeError 발생
except AttributeError as e:
    print(f"오류: {e}")

# 이름 맹글링된 이름으로는 접근 가능 (하지만 절대 사용해서는 안 됨)
# print(loader._DataLoader__cache)
```

이 예제에서 `__cache`와 `__is_loaded` 같은 내부 상태는 외부에서 직접 수정할 수 없으며, 오직 `get_data`라는 잘 정의된 메서드를 통해서만 데이터에 접근할 수 있습니다. 이를 통해 "데이터 로드는 한 번만 수행된다"는 중요한 비즈니스 로직을 강제하고, 객체의 일관성을 유지할 수 있습니다.

### 1.2 상속 (Inheritance)

**상속**은 기존 클래스(부모 클래스, 슈퍼 클래스, 기반 클래스)의 속성과 메서드를 새로운 클래스(자식 클래스, 서브 클래스, 파생 클래스)가 물려받아 재사용하고 확장하는 개념입니다. 상속은 **"~은(는) ~이다 (is-a)"** 관계를 모델링하며, 코드의 재사용성을 극대화하고 클래스 간의 계층 구조를 명확하게 표현하는 데 사용됩니다.

**핵심 목표:**

*   **코드 재사용:** 부모 클래스에 구현된 공통 기능을 자식 클래스에서 다시 작성할 필요 없이 그대로 사용할 수 있습니다.
*   **계층 구조:** 클래스들을 논리적인 계층 구조로 구성하여 코드의 구조를 더 잘 이해하고 관리할 수 있습니다.
*   **기능 확장:** 자식 클래스는 부모의 기능을 물려받는 동시에, 자신만의 새로운 기능을 추가하거나 기존 기능을 변경(오버라이딩)할 수 있습니다.

#### 1.2.1 기본 상속과 `super()`

자식 클래스는 클래스 이름 뒤 괄호 안에 부모 클래스의 이름을 명시하여 상속 관계를 표현합니다. 자식 클래스의 생성자(`__init__`)에서는 반드시 `super().__init__()`을 호출하여 부모 클래스의 생성자를 명시적으로 실행해야 합니다. 이를 통해 부모 클래스에서 정의된 속성들이 올바르게 초기화됩니다.

모든 머신러닝 모델이 공통적으로 가져야 할 `train`, `predict`, `save`와 같은 기본 기능을 `BaseModel`이라는 부모 클래스에 정의하고, 각 세부 모델(예: `LinearRegression`, `LogisticRegression`)이 이를 상속받아 자신만의 특화된 학습 로직을 구현하는 시나리오입니다.

```python
class LinearRegression(BaseModel):
    def _fit(self, X, y):
        print("선형 회귀에 맞는 경사 하강법으로 가중치를 학습합니다...")
        # ... (선형 회귀 학습 로직) ...
        self._weights = np.random.rand(X.shape[1]) # 예시 가중치

    def _predict_proba(self, X):
        print("학습된 가중치를 사용하여 예측값을 계산합니다.")
        return X @ self._weights

# 자식 클래스 2: 로지스틱 회귀 모델
class LogisticRegression(BaseModel):
    def _fit(self, X, y):
        print("로지스틱 회귀에 맞는 경사 하강법으로 가중치를 학습합니다...")
        # ... (로지스틱 회귀 학습 로직) ...
        self._weights = np.random.rand(X.shape[1]) # 예시 가중치

    def _predict_proba(self, X):
        print("학습된 가중치와 시그모이드 함수를 사용하여 확률을 예측합니다.")
        logits = X @ self._weights
        return 1 / (1 + np.exp(-logits)) # Sigmoid

# 사용 예시
X_train = np.array([[1, 2], [2, 3], [3, 4]])
y_train = np.array([1, 2, 3])

# 선형 회귀 모델
lr = LinearRegression(learning_rate=0.001, epochs=50)
lr.train(X_train, y_train)
predictions = lr.predict(X_train)
print(f"선형 회귀 예측 결과: {predictions}")

# 로지스틱 회귀 모델
log_reg = LogisticRegression()
log_reg.train(X_train, y_train)
probabilities = log_reg.predict(X_train)
print(f"\n로지스틱 회귀 예측 결과: {probabilities}")
```

#### 1.2.2 다중 상속과 메서드 해결 순서 (MRO)

파이썬은 여러 부모 클래스로부터 상속받는 **다중 상속**을 지원합니다. 이는 강력한 기능이지만, 클래스 계층 구조가 복잡해지고 메서드 탐색 순서에 따라 예상치 못한 동작을 할 수 있는 **다이아몬드 문제(Diamond Problem)**와 같은 복잡성을 야기할 수 있습니다.

파이썬은 **MRO(Method Resolution Order)**라는 규칙에 따라 메서드를 탐색할 순서를 결정합니다. `클래스명.__mro__` 또는 `클래스명.mro()`를 통해 이 순서를 확인할 수 있습니다. `super()` 함수는 MRO에 따라 다음 부모 클래스의 메서드를 정확히 호출해주므로, 다중 상속 환경에서도 협력적인 메서드 호출이 가능합니다.

```python
class A:
    def who_am_i(self): print("I am A")

class B(A):
    def who_am_i(self): 
        print("I am B")
        super().who_am_i()

class C(A):
    def who_am_i(self): 
        print("I am C")
        super().who_am_i()

class D(B, C):
    def who_am_i(self): 
        print("I am D")
        super().who_am_i()

d = D()
d.who_am_i()
# 출력 순서: D -> B -> C -> A

# D 클래스의 MRO 확인
print(f"\nMRO for D: {D.__mro__}")
# (<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>, <class '__main__.A'>, <class 'object'>)
```

**실무적 의미:** 다중 상속은 강력하지만 복잡성을 크게 증가시킬 수 있습니다. 따라서 꼭 필요한 경우가 아니라면, 기능의 조합이 필요할 때는 **상속보다 컴포지션(Composition)이나 믹스인(Mixin) 패턴을 사용하는 것이 더 나은 설계일 수 있습니다.**


### 1.3 다형성 (Polymorphism)

**다형성(Polymorphism)**은 그리스어로 "많은 형태를 가진다"는 의미로, **서로 다른 클래스의 객체가 동일한 이름의 메서드 호출에 대해 각자의 방식대로 다르게 응답**하는 능력을 말합니다. 이는 코드를 더 유연하고 확장 가능하게 만드는 핵심 원칙입니다.

**핵심 목표:**

*   **유연성 및 확장성:** 새로운 클래스가 추가되더라도, 기존 코드는 수정할 필요 없이 새로운 클래스의 객체를 동일한 인터페이스로 처리할 수 있습니다. 이는 코드의 확장성을 크게 향상시킵니다.
*   **코드 간소화:** 객체의 구체적인 타입에 따라 `if/elif/else`로 분기하여 처리할 필요 없이, 동일한 메서드 호출(예: `object.render()`, `model.evaluate()`)로 다양한 객체를 일관되게 다룰 수 있습니다.

다형성은 주로 **메서드 오버라이딩(Method Overriding)**을 통해 구현됩니다. 또한, 파이썬의 **연산자 오버로딩**(`__add__`, `__mul__` 등 특수 메서드 구현)도 다형성의 한 형태로, 동일한 연산자가 다른 객체 타입에 따라 다르게 동작하도록 정의할 수 있습니다.

#### 1.3.1 메서드 오버라이딩 (Method Overriding)

메서드 오버라이딩은 자식 클래스에서 부모 클래스로부터 물려받은 메서드를 자신만의 방식으로 **재정의**하는 것입니다. 이를 통해 자식 클래스는 부모의 기본 동작을 따르면서도, 자신에게 특화된 행동을 할 수 있습니다.

**실무 예제: 데이터 시각화 객체**

다양한 종류의 데이터(테이블, 시계열, 이미지)를 시각화하는 상황을 가정해 봅시다. 모든 데이터 객체는 공통적으로 `draw()`라는 메서드를 가지지만, 각 데이터의 특성에 맞게 시각화 방식은 달라야 합니다.

```python
import matplotlib.pyplot as plt
import pandas as pd
import numpy as np

class Plottable:
    """시각화 가능한 모든 객체의 부모 클래스"""
    def __init__(self, title):
        self.title = title

    def draw(self):
        raise NotImplementedError("자식 클래스에서 draw() 메서드를 구현해야 합니다.")

class TableData(Plottable):
    """테이블 형태의 데이터를 막대 그래프로 시각화"""
    def __init__(self, title, data: pd.DataFrame):
        super().__init__(title)
        self._data = data

    def draw(self):
        print(f"--- {self.title} (Bar Chart) ---")
        self._data.plot(kind='bar', title=self.title)
        plt.show()

class TimeSeriesData(Plottable):
    """시계열 데이터를 선 그래프로 시각화"""
    def __init__(self, title, data: pd.Series):
        super().__init__(title)
        self._data = data

    def draw(self):
        print(f"--- {self.title} (Line Chart) ---")
        self._data.plot(kind='line', title=self.title)
        plt.show()

# 다형성을 활용한 시각화 함수
def visualize_all(drawable_objects):
    """객체의 실제 타입에 신경 쓰지 않고, draw() 메서드만 호출"""
    for obj in drawable_objects:
        obj.draw() # 이 한 줄의 코드가 다양한 객체를 처리함

# 데이터 준비
table = TableData("월별 판매량", pd.DataFrame({'판매량': [100, 150, 120]}, index=['1월', '2월', '3월']))
time_series = TimeSeriesData("주가 변동", pd.Series([1000, 1100, 1050, 1200], index=pd.to_datetime(['2023-01-01', '2023-01-02', '2023-01-03', '2023-01-04'])))

# 다형적 실행
visualize_all([table, time_series])
```

위 `visualize_all` 함수는 리스트에 담긴 객체가 `TableData`인지 `TimeSeriesData`인지 전혀 신경 쓰지 않습니다. 오직 각 객체가 `draw()` 메서드를 가지고 있다는 사실에만 의존합니다. 이것이 다형성의 힘입니다. 만약 나중에 `ImageData`라는 새로운 클래스가 추가되더라도, `visualize_all` 함수는 단 한 줄도 수정할 필요가 없습니다.

#### 1.3.2 연산자 오버로딩 (Operator Overloading)

연산자 오버로딩은 `+`, `*`, `==`와 같은 내장 연산자에 사용자 정의 객체가 반응하도록 특수 메서드(예: `__add__`, `__mul__`, `__eq__`)를 구현하는 것입니다. 이는 다형성의 한 형태로, 동일한 연산자가 피연산자(객체)의 타입에 따라 다르게 동작하게 만듭니다.

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        """'+' 연산자를 벡터 덧셈으로 오버로딩"""
        if not isinstance(other, Vector):
            return NotImplemented # 다른 타입과는 덧셈을 지원하지 않음
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        """'*' 연산자를 스칼라 곱셈으로 오버로딩"""
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector(self.x * scalar, self.y * scalar)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)

# '+' 연산자가 Vector 객체에 대해 __add__ 메서드를 호출 (다형적 행동)
result_add = v1 + v2
print(f"{v1} + {v2} = {result_add}")

# '*' 연산자가 Vector 객체에 대해 __mul__ 메서드를 호출 (다형적 행동)
result_mul = v1 * 3
print(f"{v1} * 3 = {result_mul}")
```

### 1.4 추상화 (Abstraction)

**추상화**는 복잡한 현실 세계의 대상을 **핵심적인 특징과 기능만을 간추려 표현**하고, 불필요한 세부 사항은 숨기는 것을 의미합니다. 캡슐화가 데이터와 메서드를 하나로 묶고 내부 구현을 숨기는 데 중점을 둔다면, 추상화는 **클래스들이 따라야 할 공통적인 "계약" 또는 "청사진"을 정의**하는 데 더 중점을 둡니다.

**핵심 목표:**

*   **복잡성 관리:** 사용자는 객체의 복잡한 내부 동작 원리를 몰라도, 외부에 공개된 단순한 인터페이스를 통해 객체를 사용할 수 있습니다. (예: 자동차 운전자는 엔진의 내부 구조를 몰라도 액셀을 밟아 가속할 수 있습니다.)
*   **표준화된 인터페이스:** 여러 클래스들이 공통적으로 가져야 할 메서드를 강제하여, 시스템 전체의 일관성을 유지하고 예측 가능한 코드를 작성하도록 돕습니다.

파이썬에서는 **추상 기본 클래스(Abstract Base Classes, ABC)**를 사용하여 추상화를 구현합니다. `abc` 모듈의 `ABC` 클래스를 상속하고, 자식 클래스가 반드시 구현해야 하는 메서드에 `@abstractmethod` 데코레이터를 붙여 추상 메서드로 선언합니다.

*   **추상 클래스 (Abstract Class):** 하나 이상의 추상 메서드를 가진 클래스입니다. 직접 인스턴스를 생성할 수 없습니다.
*   **추상 메서드 (Abstract Method):** 선언만 있고 실제 구현 내용이 없는 메서드입니다. 추상 클래스를 상속받는 모든 자식 클래스는 반드시 이 메서드를 오버라이딩하여 구현해야 하며, 그렇지 않으면 `TypeError`가 발생합니다.

#### 1.4.1 실무 예제: 데이터 전처리기(Preprocessor)의 표준화

데이터 분석 프로젝트에서는 다양한 유형의 데이터를 처리하기 위해 여러 전처리기(결측치 처리, 스케일링, 인코딩 등)를 사용합니다. 이 전처리기들이 모두 `fit()`과 `transform()`이라는 동일한 메서드 이름을 사용하도록 강제하면, 파이프라인에서 이들을 일관되게 교체하며 사용할 수 있습니다. `scikit-learn`의 `Transformer`들이 이러한 원칙을 따릅니다.

```python
from abc import ABC, abstractmethod
import numpy as np

# 추상 클래스: 모든 전처리기들이 따라야 할 "계약"을 정의
class Preprocessor(ABC):
    def __init__(self, name):
        self.name = name
        print(f"--- {self.name} 전처리기 생성 ---")

    @abstractmethod
    def fit(self, data):
        """데이터로부터 필요한 정보를 학습하는 추상 메서드"""
        pass

    @abstractmethod
    def transform(self, data):
        """학습된 정보를 바탕으로 데이터를 변환하는 추상 메서드"""
        pass

    def fit_transform(self, data):
        """fit과 transform을 순차적으로 수행하는 일반 메서드"""
        self.fit(data)
        return self.transform(data)

# 자식 클래스 1: 표준 스케일러
class StandardScaler(Preprocessor):
    def __init__(self):
        super().__init__("StandardScaler")
        self._mean = None
        self._std = None

    def fit(self, data):
        print("데이터의 평균과 표준편차를 계산합니다.")
        self._mean = np.mean(data, axis=0)
        self._std = np.std(data, axis=0)

    def transform(self, data):
        if self._mean is None or self._std is None:
            raise RuntimeError("transform() 전에 fit()을 먼저 호출해야 합니다.")
        print("데이터를 표준화합니다.")
        return (data - self._mean) / (self._std + 1e-8)

# 자식 클래스 2: 최소-최대 스케일러
class MinMaxScaler(Preprocessor):
    def __init__(self):
        super().__init__("MinMaxScaler")
        self._min = None
        self._max = None

    def fit(self, data):
        print("데이터의 최소값과 최대값을 계산합니다.")
        self._min = np.min(data, axis=0)
        self._max = np.max(data, axis=0)

    def transform(self, data):
        if self._min is None or self._max is None:
            raise RuntimeError("transform() 전에 fit()을 먼저 호출해야 합니다.")
        print("데이터를 0과 1 사이로 스케일링합니다.")
        return (data - self._min) / (self._max - self._min + 1e-8)

# 추상 클래스는 인스턴스화할 수 없음
# preprocessor = Preprocessor("base") # TypeError 발생

# 사용 예시
data = np.array([[10, 1], [20, 2], [30, 3]])

# 전처리기 리스트 (다형성 활용)
preprocessors = [StandardScaler(), MinMaxScaler()]

for p in preprocessors:
    # 어떤 전처리기든 fit_transform 이라는 동일한 인터페이스로 사용 가능
    transformed_data = p.fit_transform(data)
    print(f"{p.name} 변환 결과:\n{transformed_data}\n")
```

이처럼 추상화를 통해 `StandardScaler`와 `MinMaxScaler`가 반드시 `fit`과 `transform` 메서드를 구현하도록 강제할 수 있습니다. 덕분에 이들을 사용하는 코드는 각 전처리기의 내부 구현을 신경 쓸 필요 없이, `preprocessor.fit_transform()`이라는 일관된 방식으로 모든 전처리기를 다룰 수 있게 됩니다. 이는 코드의 유연성과 재사용성을 크게 높여줍니다.

### 1.5 컴포지션 (Composition) vs 상속 (Inheritance)

객체 지향 설계에서 클래스 간에 기능을 재사용하고 관계를 맺는 두 가지 주요 방법은 상속과 컴포지션입니다. 이 둘의 차이를 이해하고 상황에 맞게 사용하는 것은 유연하고 확장 가능한 소프트웨어를 만드는 데 매우 중요합니다.

*   **상속 (Inheritance):** **"~은 ~이다 (is-a)"** 관계를 표현합니다. 자식 클래스가 부모 클래스의 모든 속성과 메서드를 물려받아, 부모 클래스의 한 종류로서 동작합니다. (예: `StandardScaler`는 `Preprocessor`의 한 종류이다.)

*   **컴포지션 (Composition):** **"~은 ~을 가진다 (has-a)"** 관계를 표현합니다. 한 클래스가 다른 클래스의 인스턴스를 자신의 속성으로 포함하여, 그 인스턴스의 기능을 사용하는 방식입니다. (예: `ModelPipeline`은 `DataLoader`와 `Preprocessor`를 가진다.)

객체 지향 설계에서는 **"상속보다 컴포지션을 선호하라 (Prefer Composition Over Inheritance)"**는 유명한 원칙이 있습니다. 그 이유는 다음과 같습니다.

| 비교 항목 | 상속 (Inheritance) | 컴포지션 (Composition) |
| :--- | :--- | :--- |
| **결합도 (Coupling)** | **강한 결합 (Tight Coupling)**: 자식 클래스가 부모의 내부 구현에 의존하게 되어, 부모 클래스의 변경이 자식 클래스에 예기치 않은 영향을 줄 수 있습니다. | **느슨한 결합 (Loose Coupling)**: 각 객체는 잘 정의된 인터페이스를 통해 상호작용하므로, 한 객체의 내부 구현이 변경되어도 다른 객체에 미치는 영향이 적습니다. |
| **유연성 (Flexibility)** | **낮음**: 컴파일 타임(코드 작성 시점)에 관계가 고정됩니다. 런타임에 부모를 바꿀 수 없습니다. | **높음**: 런타임에 다른 종류의 객체를 주입하여 동적으로 행동을 변경할 수 있습니다. (의존성 주입) |
| **재사용성** | **화이트박스 재사용**: 부모의 내부를 알아야 제대로 확장할 수 있습니다. | **블랙박스 재사용**: 객체의 내부 구현을 몰라도, 공개된 인터페이스만으로 기능을 재사용할 수 있습니다. |

#### 1.5.1 실무 예제: 머신러닝 파이프라인 설계

데이터 로딩, 전처리, 모델 학습, 평가로 이어지는 머신러닝 파이프라인을 설계하는 상황을 생각해 봅시다.

*   **상속을 사용한 잘못된 설계 (가정):**
    만약 `Pipeline`이 `DataLoader`와 `StandardScaler`를 모두 상속받는다면, "파이프라인은 데이터로더인가?" 또는 "파이프라인은 스케일러인가?"와 같은 어색한 관계가 형성됩니다. 이는 논리적으로 맞지 않으며, 다른 로더나 스케일러로 교체하기 매우 어렵습니다.

*   **컴포지션을 사용한 올바른 설계:**
    `ModelPipeline` 클래스가 `DataLoader`, `Preprocessor`, `BaseModel`의 **인스턴스를 속성으로 "소유"**하도록 설계합니다. 이를 통해 각 컴포넌트의 역할을 명확히 분리하고, 필요에 따라 다른 컴포넌트로 쉽게 교체할 수 있습니다.

```python
# 위에서 정의한 DataLoader, Preprocessor, BaseModel 등을 재사용한다고 가정
# (실제 실행을 위해서는 위 예제들의 클래스 정의가 필요합니다)

class ModelPipeline:
    def __init__(self, loader: DataLoader, preprocessor: Preprocessor, model: BaseModel):
        """파이프라인은 로더, 전처리기, 모델 객체를 '소유'합니다 (Composition)."""
        self.loader = loader
        self.preprocessor = preprocessor
        self.model = model
        print("\n--- ModelPipeline이 구성되었습니다 ---")

    def run(self):
        """파이프라인의 각 단계를 순차적으로 실행"""
        # 1. 데이터 로딩 (DataLoader 객체에 위임)
        raw_data = self.loader.get_data()

        # 2. 데이터 전처리 (Preprocessor 객체에 위임)
        processed_data = self.preprocessor.fit_transform(raw_data)

        # 3. 모델 학습 (BaseModel 객체에 위임)
        # 예시를 위해 마지막 열을 타겟(y)으로 가정
        X = processed_data[:, :-1]
        y = processed_data[:, -1]
        self.model.train(X, y)

        print("\n--- 파이프라인 실행 완료 ---")

# --- 파이프라인 조립 및 실행 ---

# 1. 각 컴포넌트 인스턴스 생성
data_loader = DataLoader('./data.csv')
scaler = StandardScaler()
model = LinearRegression(learning_rate=0.05)

# 2. 컴포넌트들을 주입하여 파이프라인 생성 (의존성 주입)
pipeline = ModelPipeline(loader=data_loader, preprocessor=scaler, model=model)

# 3. 파이프라인 실행
pipeline.run()

# 4. 다른 전처리기로 쉽게 교체 가능!
print("\n=========================================")
print("MinMaxScaler로 교체하여 파이프라인 재실행")
pipeline.preprocessor = MinMaxScaler()
pipeline.run()
```

이처럼 컴포지션을 사용하면, 각 객체의 역할을 명확히 분리(높은 응집도)하고, 객체 간의 의존성을 낮추어(느슨한 결합) 유연하고 확장 가능한 시스템을 만들 수 있습니다.

#### 1.5.2 믹스인 (Mixin) 클래스

믹스인은 특정 기능을 제공하지만 독립적으로 인스턴스화될 목적이 없는 클래스입니다. 주로 다중 상속과 함께 사용되어 여러 클래스에 공통된 행동을 "섞어 넣는(mix-in)" 데 활용됩니다. 이는 상속과 컴포지션의 장점을 결합한 패턴으로, 특히 **행동의 수평적 재사용(Horizontal Reuse)**을 달성하는 데 유용합니다.

```python
class SerializableMixin:
    """객체를 딕셔너리나 JSON으로 변환하는 기능을 믹스인"""
    def to_dict(self):
        # dataclasses.asdict와 유사한 기능
        return self.__dict__

    def to_json(self):
        import json
        return json.dumps(self.to_dict())

class LoggableMixin:
    """간단한 로깅 기능을 믹스인"""
    def log(self, message):
        print(f"LOG: [{self.__class__.__name__}] {message}")

# 믹스인을 사용하여 클래스에 기능 추가
class User(SerializableMixin, LoggableMixin):
    def __init__(self, name, email):
        self.name = name
        self.email = email
        self.log(f"'{self.name}' 사용자가 생성되었습니다.")

user = User("Alice", "alice@example.com")
print(f"User to JSON: {user.to_json()}")
```
### 1.6 디자인 패턴 소개 (팩토리, 싱글턴 등)

**디자인 패턴(Design Pattern)**은 소프트웨어 설계에서 반복적으로 발생하는 문제들에 대한 검증된 해결책의 모음입니다. 이는 특정 문제를 해결하기 위한 코드의 청사진과 같아서, 코드의 재사용성, 유지보수성, 확장성을 높이고 다른 개발자와의 원활한 소통을 돕습니다. 여기서는 객체 생성과 관련된 대표적인 패턴인 **팩토리 패턴**과 **싱글턴 패턴**을 소개합니다.

#### 1.6.1 팩토리 패턴 (Factory Pattern)

**팩토리 패턴**은 객체를 생성하는 과정을 캡슐화하여, 클라이언트 코드가 구체적인 클래스 이름에 직접 의존하지 않고 객체를 생성할 수 있도록 하는 패턴입니다. 조건이나 설정에 따라 생성해야 할 객체의 종류가 달라지는 경우에 매우 유용합니다.

**핵심 목표:**
*   **결합도 감소:** 객체를 사용하는 코드(클라이언트)와 객체를 생성하는 코드를 분리하여, 새로운 클래스가 추가되더라도 클라이언트 코드의 변경을 최소화합니다.
*   **유연성 및 확장성:** 새로운 종류의 객체를 추가하고 싶을 때, 팩토리 내부만 수정하면 되므로 시스템 확장이 용이합니다.

**실무 예제: 데이터 전처리기 팩토리**

다양한 종류의 데이터 전처리(스케일링, 인코딩 등)를 설정값에 따라 동적으로 선택하여 생성하는 팩토리를 구현하는 상황입니다.

```python
from abc import ABC, abstractmethod
import numpy as np

# (이전 예제의 Preprocessor, StandardScaler, MinMaxScaler 클래스 정의가 필요)
class Preprocessor(ABC):
    @abstractmethod
    def fit_transform(self, data):
        pass

class StandardScaler(Preprocessor):
    def fit_transform(self, data):
        print("StandardScaler로 데이터 변환")
        return (data - np.mean(data)) / np.std(data)

class MinMaxScaler(Preprocessor):
    def fit_transform(self, data):
        print("MinMaxScaler로 데이터 변환")
        return (data - np.min(data)) / (np.max(data) - np.min(data))

class RobustScaler(Preprocessor):
    def fit_transform(self, data):
        print("RobustScaler로 데이터 변환")
        # 간단한 구현 예시
        return data / np.median(np.abs(data - np.median(data)))

# 팩토리 클래스
class PreprocessorFactory:
    def __init__(self):
        self._preprocessors = {
            "standard": StandardScaler,
            "minmax": MinMaxScaler,
            "robust": RobustScaler
        }

    def get(self, preprocessor_type: str) -> Preprocessor:
        """문자열 키를 받아 해당하는 전처리기 인스턴스를 생성하여 반환"""
        preprocessor_class = self._preprocessors.get(preprocessor_type)
        if not preprocessor_class:
            raise ValueError(f"'{preprocessor_type}'은(는) 지원되지 않는 전처리기입니다.")
        return preprocessor_class()

# --- 팩토리 사용 --- 
factory = PreprocessorFactory()

# 설정에 따라 필요한 객체를 팩토리로부터 받아서 사용
config = {"preprocessing_method": "robust"}
data = np.array([10, 20, 30, 40, 100])

# 클라이언트 코드는 StandardScaler, MinMaxScaler 등의 구체적인 클래스를 알 필요가 없음
preprocessor = factory.get(config["preprocessing_method"])

# 다형성에 의해 동일한 인터페이스로 사용 가능
transformed_data = preprocessor.fit_transform(data)
print(f"변환된 데이터: {transformed_data}")
```

#### 1.6.2 싱글턴 패턴 (Singleton Pattern)

**싱글턴 패턴**은 특정 클래스의 인스턴스가 **프로그램 전체에서 오직 하나만 생성**되도록 보장하고, 이 인스턴스에 대한 전역적인 접근점을 제공하는 패턴입니다.

**핵심 목표:**
*   **유일성 보장:** 데이터베이스 연결, 설정 관리자, 로거(Logger)와 같이 시스템 전체에서 단 하나의 인스턴스만 존재해야 하는 경우에 사용됩니다.
*   **자원 관리:** 공유 자원에 대한 접근을 제어하고 불필요한 자원 낭비를 막습니다.

파이썬에서는 `__new__` 메서드를 오버라이딩하여 싱글턴을 구현할 수 있습니다.

**실무 예제: 프로젝트 설정 관리자**

프로젝트의 모든 부분에서 동일한 설정(`config.json` 등)을 공유해야 하는 경우, 설정 관리자 클래스를 싱글턴으로 만들어 어디서든 동일한 설정 객체에 접근하도록 할 수 있습니다.

```python
import json

class AppConfig:
    _instance = None

    def __new__(cls, *args, **kwargs):
        # 클래스의 인스턴스가 아직 생성되지 않았다면 새로 생성
        if not cls._instance:
            cls._instance = super().__new__(cls)
            print("AppConfig 인스턴스를 새로 생성합니다.")
        else:
            print("기존 AppConfig 인스턴스를 반환합니다.")
        return cls._instance

    def __init__(self, config_path="config.json"):
        # __init__은 __new__가 호출될 때마다 실행되므로, 초기화는 한 번만 수행하도록 방지
        if not hasattr(self, '_initialized'):
            print("설정 파일을 로드하여 초기화합니다.")
            # 예시: 실제로는 파일에서 설정을 로드
            # with open(config_path, 'r') as f:
            #     self._settings = json.load(f)
            self._settings = {"db_host": "localhost", "timeout": 30}
            self._initialized = True

    def get_setting(self, key):
        return self._settings.get(key)

# --- 싱글턴 사용 --- 

# 첫 번째 호출: 인스턴스가 새로 생성되고 초기화됨
config1 = AppConfig()
print(f"DB 호스트 (config1): {config1.get_setting('db_host')}")

# 두 번째 호출: 기존에 생성된 인스턴스가 그대로 반환됨
config2 = AppConfig()
print(f"타임아웃 (config2): {config2.get_setting('timeout')}")

# 두 변수는 동일한 인스턴스를 참조함
print(f"\nconfig1과 config2는 같은 객체인가? {config1 is config2}")
```

## 2. 프로퍼티 (`@property`)를 이용한 파이썬다운 캡슐화

앞서 배운 캡슐화는 `get_`이나 `set_` 접두사를 붙인 메서드(게터/세터)를 사용하여 속성에 접근하고 수정하는 고전적인 방식입니다. 하지만 파이썬에서는 `@property` 데코레이터를 사용하여 훨씬 더 간결하고 파이썬스러운(Pythonic) 방식으로 캡슐화를 구현할 수 있습니다.

`@property`는 **메서드를 클래스의 일반 속성(attribute)처럼 호출할 수 있게** 만들어주는 강력한 기능입니다. 이를 통해 사용자는 일반 속성에 접근하는 것처럼 편리하게 값을 얻거나 설정할 수 있지만, 내부적으로는 메서드가 호출되어 유효성 검사나 계산 로직 등 복잡한 처리를 수행할 수 있습니다.

**핵심 목표:**

*   **파이썬다운 인터페이스:** `obj.get_value()`나 `obj.set_value(10)` 대신, `obj.value`나 `obj.value = 10`과 같이 직관적이고 간결한 코드로 속성을 다룰 수 있게 합니다.
*   **계산된 속성(Computed Property):** 다른 속성 값에 따라 동적으로 계산되는 속성을 만들 수 있습니다.
*   **안전한 리팩토링:** 처음에는 단순한 public 속성으로 시작했다가, 나중에 유효성 검사 등의 로직이 필요해졌을 때 `@property`를 추가하여도 기존의 접근 방식을 그대로 유지할 수 있어 코드의 하위 호환성을 지킬 수 있습니다.

### 2.1 `@property` 기본 구조

`@property`는 주로 세 가지 데코레이터의 조합으로 사용됩니다.

1.  **게터 (Getter):** `@property` 데코레이터만 사용하여 정의합니다. 속성 값을 읽을 때 호출됩니다.
2.  **세터 (Setter):** `@<속성이름>.setter` 데코레이터를 사용하여 정의합니다. 속성 값을 할당할 때 호출됩니다.
3.  **딜리터 (Deleter):** `@<속성이름>.deleter` 데코레이터를 사용하여 정의합니다. `del` 키워드로 속성을 삭제할 때 호출됩니다.

### 2.2 실무 예제: 데이터 프레임 래퍼(Wrapper) 클래스

Pandas DataFrame을 감싸서 특정 열에 대한 접근을 제어하고, 새로운 파생 변수를 동적으로 계산하여 제공하는 클래스를 만들어 보겠습니다.

```python
import pandas as pd

class ExperimentData:
    def __init__(self, data: pd.DataFrame):
        # 내부적으로 원본 데이터를 저장 (외부에서 직접 수정 방지)
        self._data = data
        if 'price' not in self._data.columns or 'quantity' not in self._data.columns:
            raise ValueError("데이터에 'price'와 'quantity' 열이 필요합니다.")

    @property
    def data(self) -> pd.DataFrame:
        """데이터의 복사본을 반환하는 게터 (원본 데이터 보호)"""
        print("데이터 접근: 원본을 보호하기 위해 복사본을 반환합니다.")
        return self._data.copy()

    @property
    def revenue(self) -> pd.Series:
        """'revenue'라는 계산된 속성 (읽기 전용)"""
        print("'revenue' 속성 계산 중...")
        return self._data['price'] * self._data['quantity']

    @property
    def price(self) -> pd.Series:
        """'price' 열에 접근하기 위한 게터"""
        return self._data['price']

    @price.setter
    def price(self, new_prices):
        """'price' 열을 설정하는 세터 (유효성 검사 포함)"""
        print("'price' 속성 설정 중...")
        if len(new_prices) != len(self._data):
            raise ValueError("새로운 가격 데이터의 길이가 기존 데이터와 일치하지 않습니다.")
        if any(p < 0 for p in new_prices):
            raise ValueError("가격은 음수일 수 없습니다.")
        
        self._data['price'] = new_prices
        print("'price'가 성공적으로 업데이트되었습니다.")

# 데이터 준비
df = pd.DataFrame({'price': [1000, 1500, 2000], 'quantity': [5, 10, 7]})
exp_data = ExperimentData(df)

# 1. 게터 사용: 메서드처럼 ()를 붙이지 않고 속성처럼 접근
print("--- 게터(Getter) 사용 예제 ---")
print(f"현재 가격 데이터:\n{exp_data.price}\n")

# 2. 계산된 속성 사용: revenue 속성에 접근하면 내부적으로 계산 로직이 실행됨
print("--- 계산된 속성 예제 ---")
print(f"총 수익:\n{exp_data.revenue}\n")

# 3. 세터 사용: 속성에 값을 할당하는 것처럼 사용하면 세터 메서드가 호출됨
print("--- 세터(Setter) 사용 예제 ---")
exp_data.price = [1200, 1400, 2100] # 세터 호출
print(f"\n업데이트된 수익:\n{exp_data.revenue}\n")

# 4. 유효성 검사 실패 예시
try:
    exp_data.price = [-100, 1400, 2100]
except ValueError as e:
    print(f"오류 발생: {e}")
```

이처럼 `@property`를 사용하면, 사용자는 `exp_data.price`와 같이 직관적으로 속성에 접근하지만, 내부적으로는 데이터 유효성 검사, 계산, 원본 데이터 보호 등 복잡한 로직이 수행됩니다. 이는 파이썬에서 캡슐화를 우아하게 구현하는 핵심적인 방법입니다.

## 3. 특수 메서드 (Special Methods / Dunder Methods)

특수 메서드(Special Methods)는 이름이 두 개의 언더스코어(`__`)로 시작하고 끝나는 메서드들을 의미하며, "던더 메서드(Dunder Methods)"라고도 불립니다. 이 메서드들은 파이썬의 내장 함수나 연산자(예: `+`, `==`, `len()`, `[]`)와 연동하여 객체의 특정 동작을 정의하고 사용자 정의 클래스가 파이썬의 기본 타입처럼 동작하도록 만듭니다. 이를 통해 "파이썬스러운(Pythonic)" 코드를 작성할 수 있습니다.

### 3.1 `__str__`과 `__repr__` (복습)

(이 내용은 [08_객체_지향_프로그래밍_기초.md](./08_객체_지향_프로그래밍_기초.md)에서 자세히 다루었으므로 간략히 복습합니다.)

- **`__str__(self)`:** 객체의 사용자 친화적인 문자열 표현을 반환합니다. `print()`나 `str()` 호출 시 사용됩니다.
- **`__repr__(self)`:** 객체의 개발자 친화적인 문자열 표현을 반환합니다. 객체를 다시 생성할 수 있는 형태의 문자열을 권장하며, `repr()` 호출 시 사용됩니다.

```python
class MyObject:
    def __init__(self, value):
        self.value = value

    def __str__(self):
        return f"MyObject with value: {self.value}"

    def __repr__(self):
        return f"MyObject({self.value})"

obj = MyObject(123)
print(obj) # __str__
print(repr(obj)) # __repr__
```

### 3.2 비교 연산자 오버로딩 (`__eq__`, `__lt__` 등)

객체 간의 비교 연산(`==`, `!=`, `<`, `<=`, `>`, `>=`)이 어떻게 동작할지 정의합니다. 이를 통해 사용자 정의 객체를 정렬하거나, 조건문에서 의미 있는 비교를 수행할 수 있습니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `==` | `__eq__(self, other)` | 같음 (Equal) |
| `!=` | `__ne__(self, other)` | 같지 않음 (Not Equal) |
| `<` | `__lt__(self, other)` | 미만 (Less Than) |
| `<=` | `__le__(self, other)` | 이하 (Less than or Equal to) |
| `>` | `__gt__(self, other)` | 초과 (Greater Than) |
| `>=` | `__ge__(self, other)` | 이상 (Greater than or Equal to) |

**`NotImplemented`의 역할:** 비교가 불가능한 타입의 객체가 들어왔을 때, `NotImplemented`를 반환하는 것이 좋습니다. 이는 파이썬이 반대편 객체의 비교 메서드(예: `other.__eq__(self)`)를 시도하도록 하는 신호입니다.

**`@functools.total_ordering`**: `__eq__` 메서드와 하나의 순서 비교 메서드(예: `__lt__`)만 정의하면, 나머지 비교 메서드(`__le__`, `__gt__`, `__ge__`)를 자동으로 생성해주는 매우 유용한 데코레이터입니다.

#### 3.2.1 실무 예제: 모델 성능 객체 비교

머신러닝 실험에서 얻은 여러 모델의 성능(예: 정확도, F1 점수)을 객체로 관리하고, 이 객체들을 직접 비교하여 최상의 모델을 선택하는 상황을 가정해 봅시다.

```python
import functools

@functools.total_ordering
class ModelPerformance:
    def __init__(self, model_name: str, accuracy: float, f1_score: float):
        self.model_name = model_name
        self.accuracy = accuracy
        self.f1_score = f1_score

    def __repr__(self):
        return f"Model(name={self.model_name}, acc={self.accuracy:.2f}, f1={self.f1_score:.2f})"

    def __eq__(self, other):
        """두 모델 성능이 완전히 동일한지 비교 (==)"""
        if not isinstance(other, ModelPerformance):
            return NotImplemented
        return (self.accuracy == other.accuracy and self.f1_score == other.f1_score)

    def __lt__(self, other):
        """주요 지표인 accuracy를 기준으로 모델 성능을 비교 (<)"""
        if not isinstance(other, ModelPerformance):
            return NotImplemented
        # 정확도가 낮으면 성능이 낮은 것으로 간주
        if self.accuracy < other.accuracy:
            return True
        # 정확도가 같으면 F1 점수로 2차 비교
        if self.accuracy == other.accuracy and self.f1_score < other.f1_score:
            return True
        return False

# 모델 성능 객체 생성
model_A = ModelPerformance("ResNet", 0.92, 0.91)
model_B = ModelPerformance("EfficientNet", 0.95, 0.94)
model_C = ModelPerformance("VisionTransformer", 0.95, 0.95)
model_D = ModelPerformance("ResNet_copy", 0.92, 0.91)

# 1. 동등성 비교 (__eq__ 호출)
print(f"A == B: {model_A == model_B}") # False
print(f"A == D: {model_A == model_D}") # True

# 2. 순서 비교 (__lt__와 @total_ordering 호출)
print(f"\nA < B: {model_A < model_B}")   # True (정확도가 낮음)
print(f"B < C: {model_B < model_C}")   # True (정확도는 같지만, F1 점수가 낮음)
print(f"C > B: {model_C > model_B}")   # True (자동 생성된 __gt__)
print(f"B >= A: {model_B >= model_A}") # True (자동 생성된 __ge__)

# 3. 리스트 정렬
performance_list = [model_A, model_C, model_B]
print(f"\n정렬 전: {performance_list}")

# sorted() 함수는 내부적으로 __lt__를 사용하여 객체를 정렬함
performance_list.sort(reverse=True) # 성능이 좋은 순 (내림차순)으로 정렬
print(f"정렬 후: {performance_list}")
print(f"최고 성능 모델: {performance_list[0]}")
```

이처럼 비교 연산자를 오버로딩하면, 사용자 정의 객체를 파이썬의 내장 타입처럼 자연스럽게 다룰 수 있게 되어 코드의 가독성과 활용성이 크게 향상됩니다.


### 3.3 산술 연산자 오버로딩 (`__add__`, `__mul__` 등)

객체 간의 산술 연산(`+`, `-`, `*`, `/` 등)이 어떻게 동작할지 정의합니다. 이를 통해 사용자 정의 객체를 숫자나 다른 객체와 자연스럽게 연산하여 코드의 가독성을 높이고, 수학적 개념을 직관적으로 표현할 수 있습니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `+` | `__add__(self, other)` | 덧셈 |
| `-` | `__sub__(self, other)` | 뺄셈 |
| `*` | `__mul__(self, other)` | 곱셈 |
| `/` | `__truediv__(self, other)` | 나눗셈 (`/`) |
| `//` | `__floordiv__(self, other)` | 몫 나눗셈 (`//`) |
| `%` | `__mod__(self, other)` | 나머지 (`%`) |
| `**` | `__pow__(self, other)` | 거듭제곱 (`**`) |

또한, 피연산자의 순서가 바뀌는 경우(예: `3 * vector`)를 처리하기 위해 **반사 연산자(Reflected Operator)** 메서드(예: `__radd__`, `__rmul__`)를 구현할 수 있습니다.

#### 3.3.1 실무 예제: 다항식(Polynomial) 클래스

데이터 분석에서 다항 회귀(Polynomial Regression)나 특성 공학(Feature Engineering)에 사용될 수 있는 다항식 객체를 만들어 보겠습니다. 이 객체는 덧셈, 뺄셈, 곱셈과 같은 기본적인 산술 연산을 지원합니다.

```python
class Polynomial:
    def __init__(self, *coeffs):
        # 계수를 내림차순으로 저장 (예: 3x^2 + 2x + 1 -> [3, 2, 1])
        self.coeffs = list(coeffs)

    def __repr__(self):
        return f"Polynomial{tuple(self.coeffs)}"

    def __str__(self):
        terms = []
        degree = len(self.coeffs) - 1
        for i, coeff in enumerate(self.coeffs):
            if coeff == 0: continue
            
            term = str(coeff)
            if degree - i > 0:
                term += f"x^{degree - i}"
            terms.append(term)
        return " + ".join(terms).replace("+ -", "- ")

    def __add__(self, other):
        """다항식 덧셈 (+) 오버로딩"""
        if not isinstance(other, Polynomial):
            return NotImplemented

        # 두 다항식의 길이를 맞춤
        max_len = max(len(self.coeffs), len(other.coeffs))
        c1 = [0] * (max_len - len(self.coeffs)) + self.coeffs
        c2 = [0] * (max_len - len(other.coeffs)) + other.coeffs

        new_coeffs = [c1[i] + c2[i] for i in range(max_len)]
        return Polynomial(*new_coeffs)

    def __mul__(self, other):
        """다항식 곱셈 (*) 오버로딩"""
        if isinstance(other, (int, float)):
            # 스칼라 곱셈
            new_coeffs = [c * other for c in self.coeffs]
            return Polynomial(*new_coeffs)
        elif isinstance(other, Polynomial):
            # 다항식 간의 곱셈
            n = len(self.coeffs)
            m = len(other.coeffs)
            new_coeffs = [0] * (n + m - 1)
            for i in range(n):
                for j in range(m):
                    new_coeffs[i + j] += self.coeffs[i] * other.coeffs[j]
            return Polynomial(*new_coeffs)
        else:
            return NotImplemented

# 다항식 생성: P1(x) = 2x^2 + 3x + 1
p1 = Polynomial(2, 3, 1)
# 다항식 생성: P2(x) = x - 2
p2 = Polynomial(1, -2)

print(f"P1(x) = {p1}")
print(f"P2(x) = {p2}")

# 1. 덧셈 연산 (__add__ 호출)
p_sum = p1 + p2
print(f"P1 + P2 = {p_sum}")

# 2. 곱셈 연산 (__mul__ 호출)
# 2.1 스칼라 곱셈
p_scaled = p1 * 3
print(f"P1 * 3 = {p_scaled}")

# 2.2 다항식 간 곱셈
p_prod = p1 * p2
print(f"P1 * P2 = {p_prod}")
```

이 예제는 산술 연산자 오버로딩을 통해 사용자 정의 객체가 수학적 개념을 얼마나 직관적으로 표현할 수 있는지 보여줍니다. `numpy`와 같은 라이브러리에서 배열 간의 연산이 자연스럽게 동작하는 것도 모두 이러한 특수 메서드들이 잘 구현되어 있기 때문입니다.

### 3.4 컨테이너 타입 메서드 (`__len__`, `__getitem__`, `__setitem__` 등)

사용자 정의 객체가 파이썬의 내장 컨테이너(리스트, 튜플, 딕셔너리 등)처럼 동작하게 만들 수 있습니다. 이를 통해 `len()`, 인덱싱(`[]`), 슬라이싱, `for` 루프 등 파이썬의 직관적인 문법을 사용자 정의 객체에 그대로 적용할 수 있습니다.

| 연산/함수 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `len(obj)` | `__len__(self)` | 객체의 길이(항목 수)를 반환합니다. `for` 루프의 종료 조건을 암시하는 데도 사용됩니다. |
| `obj[key]` | `__getitem__(self, key)` | 인덱싱 또는 키를 사용하여 항목에 접근할 때 호출됩니다. 슬라이싱도 이 메서드를 통해 처리됩니다. |
| `obj[key] = value` | `__setitem__(self, key, value)` | 인덱싱 또는 키를 사용하여 항목의 값을 설정할 때 호출됩니다. |
| `del obj[key]` | `__delitem__(self, key)` | `del` 키워드로 항목을 삭제할 때 호출됩니다. |
| `key in obj` | `__contains__(self, key)` | `in` 연산자로 항목의 존재 여부를 확인할 때 호출됩니다. |
| `for x in obj` | `__iter__(self)` | `for` 루프 등에서 객체를 순회할 때 이터레이터를 반환합니다. (구현되지 않으면 `__getitem__`을 대신 사용) |

#### 3.4.1 실무 예제: 미니 배치(Mini-batch) 데이터셋

머신러닝에서 대용량 데이터셋을 한 번에 메모리에 올리기 어려울 때, 데이터를 작은 배치(batch) 단위로 나누어 처리합니다. `__len__`과 `__getitem__`을 구현하면, 이러한 데이터셋 객체를 `for` 루프나 `len()` 함수와 함께 파이썬 리스트처럼 자연스럽게 사용할 수 있습니다. 이는 PyTorch의 `Dataset` 클래스의 핵심 원리이기도 합니다.

```python
import numpy as np

class TimeSeriesDataSet:
    """시계열 데이터 배치를 관리하는 컨테이너 클래스"""
    def __init__(self, all_series_data, batch_size):
        self.all_series_data = all_series_data
        self.batch_size = batch_size
        print(f"총 {len(all_series_data)}개의 시계열 데이터로 데이터셋 생성 (배치 크기: {batch_size})")

    def __len__(self) -> int:
        """데이터셋의 총 배치(batch) 수를 반환"""
        return (len(self.all_series_data) + self.batch_size - 1) // self.batch_size

    def __getitem__(self, index: int) -> np.ndarray:
        """주어진 인덱스에 해당하는 미니 배치를 반환"""
        if index >= len(self):
            raise IndexError("데이터셋 인덱스 범위를 벗어났습니다.")
        
        start = index * self.batch_size
        end = start + self.batch_size
        return self.all_series_data[start:end]

    def __repr__(self) -> str:
        return f"<TimeSeriesDataSet: {len(self.all_series_data)} samples, {len(self)} batches>"

# 100개의 시계열 데이터 생성 (예시)
raw_data = np.random.rand(100, 10) # (샘플 수, 시계열 길이)

# 데이터셋 객체 생성
dataset = TimeSeriesDataSet(raw_data, batch_size=32)

# 1. __len__ 호출: 데이터셋에 몇 개의 배치가 있는지 확인
print(f"총 배치 수: {len(dataset)}")

# 2. __getitem__ 호출: 특정 인덱스의 배치를 가져옴
first_batch = dataset[0]
print(f"첫 번째 배치의 형태: {first_batch.shape}")

# 3. __iter__가 없으면, for 루프는 __getitem__을 0부터 순차적으로 호출
print("\n--- 데이터셋 순회 (배치 단위) ---")
for i, batch in enumerate(dataset):
    print(f"Batch #{i}, Shape: {batch.shape}")
    # 이 배치 데이터를 사용하여 모델 학습 수행
    # model.train_on_batch(batch)
```

이처럼 컨테이너 타입 메서드를 구현하면, 복잡한 데이터 처리 로직을 클래스 내부에 캡슐화하면서도, 사용자에게는 파이썬의 기본 자료구조처럼 친숙하고 일관된 인터페이스를 제공할 수 있습니다.

### 3.5 `__call__` 메서드: 객체를 함수처럼 호출하기

`__call__` 메서드를 구현하면 클래스의 인스턴스를 **함수처럼 괄호 `()`를 붙여 호출**할 수 있게 됩니다. 이렇게 호출 가능한 객체(Callable Object)는 일반 함수와 달리 **내부적으로 상태(state)를 가질 수 있다**는 강력한 장점이 있습니다. 이를 "함수 객체(Functor)"라고도 부릅니다.

**핵심 목표:**

*   **상태를 가진 함수:** 특정 상태(예: 설정값, 누적된 값, 캐시)를 유지하면서 함수처럼 동작하는 객체를 만들 때 매우 유용합니다.
*   **일관된 인터페이스:** 일반 함수를 사용하는 곳에 `__call__`을 구현한 객체를 동일하게 전달하여 사용할 수 있습니다. (예: 콜백 함수, 고차 함수)

#### 3.5.1 실무 예제: 상태를 가지는 데이터 변환기

데이터 전처리 파이프라인에서, 특정 변환(Transformation)을 수행하면서 몇 번의 변환이 일어났는지, 또는 어떤 값들이 들어왔는지 기록해야 하는 경우를 생각해 봅시다. `__call__`을 사용하면 변환 로직과 상태 추적을 하나의 클래스로 깔끔하게 캡슐화할 수 있습니다.

```python
class StatefulTransformer:
    """데이터를 변환하면서 호출 횟수와 입력값을 기록하는 변환기"""
    def __init__(self, transformation_func):
        self.transformation = transformation_func
        self._call_count = 0
        self._recent_inputs = []

    def __call__(self, data):
        """객체를 함수처럼 호출하여 데이터 변환을 수행"""
        print(f"'{self.transformation.__name__}' 변환을 수행합니다...")
        
        # 상태 업데이트
        self._call_count += 1
        self._recent_inputs.append(data)
        if len(self._recent_inputs) > 3: # 최근 3개만 유지
            self._recent_inputs.pop(0)

        # 실제 변환 로직 수행
        return self.transformation(data)

    @property
    def call_count(self) -> int:
        """총 호출 횟수"""
        return self._call_count

    @property
    def recent_inputs(self) -> list:
        """최근 입력된 데이터"""
        return self._recent_inputs

# 변환에 사용할 함수 정의
def scale_by_10(x):
    return x * 10

def add_5(x):
    return x + 5

# 1. 상태를 가지는 변환기(함수 객체) 생성
scaler = StatefulTransformer(scale_by_10)
adder = StatefulTransformer(add_5)

# 2. 객체를 함수처럼 호출
result1 = scaler(10)
print(f"변환 결과: {result1}")
print(f"호출 횟수: {scaler.call_count}") # 상태 확인: 1

result2 = scaler(20)
print(f"\n변환 결과: {result2}")
print(f"호출 횟수: {scaler.call_count}") # 상태 확인: 2

adder(100) # adder 객체 호출

# 3. 각 객체는 자신만의 독립적인 상태를 가짐
print(f"\nScaler 호출 횟수: {scaler.call_count}")
print(f"Adder 호출 횟수: {adder.call_count}")
print(f"Scaler 최근 입력: {scaler.recent_inputs}")
```

**실무적 의미:**

*   **머신러닝 모델 클래스:** PyTorch와 같은 딥러닝 프레임워크에서 모델 클래스는 `__call__`을 구현합니다. `model(input_data)`와 같이 객체를 직접 호출하면, 내부적으로 `forward` 메서드가 실행되어 예측을 수행합니다. 이는 모델이 학습된 가중치(상태)를 가지면서도 함수처럼 간결하게 사용될 수 있게 합니다.
*   **데코레이터 클래스:** 함수를 감싸서 추가 기능을 부여하는 데코레이터를 클래스 형태로 구현할 때 `__init__`으로 원본 함수를 받고, `__call__`에서 추가 로직과 함께 원본 함수를 실행하는 패턴이 널리 사용됩니다.
*   **콜백(Callback) 함수:** 특정 이벤트가 발생했을 때 실행될 함수를 전달해야 하는 경우, 상태를 저장하고 관리해야 한다면 일반 함수보다 `__call__`을 구현한 클래스 인스턴스를 전달하는 것이 더 효과적일 수 있습니다.


### 3.6 속성 접근 제어 메서드 (`__getattr__`, `__setattr__`, `__delattr__`)

파이썬은 객체의 속성(attribute)에 접근, 설정, 삭제하는 방식을 커스터마이징할 수 있는 매우 강력한 특수 메서드들을 제공합니다. 이를 통해 일반적인 속성 접근을 넘어서는 동적인 행동을 구현할 수 있습니다.

*   **`__getattr__(self, name)`:** 객체에 **존재하지 않는** 속성에 접근하려고 할 때만 호출됩니다. `AttributeError`를 발생시키는 대신, 이 메서드가 호출되어 동적으로 값을 계산하거나 다른 곳에서 가져오는 등의 처리를 할 수 있습니다.
*   **`__getattribute__(self, name)`:** `__getattr__`과 달리, **모든** 속성 접근 시도에 대해 가장 먼저 호출됩니다. 매우 강력하지만, 잘못 사용하면 무한 재귀에 빠지기 쉬우므로(`self.x`와 같은 접근도 이 메서드를 다시 호출함) `super().__getattribute__(name)`을 통해 조심스럽게 다루어야 합니다.
*   **`__setattr__(self, name, value)`:** 속성을 설정하려고 할 때마다(예: `obj.x = 10`) 호출됩니다. 속성 값에 대한 유효성 검사, 로깅, 또는 특정 속성 변경 시 다른 작업을 트리거하는 데 사용됩니다. 무한 재귀를 피하려면 `super().__setattr__(name, value)`를 사용해야 합니다.
*   **`__delattr__(self, name)`:** `del obj.x`와 같이 속성을 삭제하려고 할 때 호출됩니다.

#### 3.6.1 실무 예제: 동적 실험 파라미터 관리자

머신러닝 실험을 진행할 때, 수많은 하이퍼파라미터를 딕셔너리 형태로 관리하는 경우가 많습니다. 이 파라미터들을 딕셔너리 키(`params['learning_rate']`)가 아닌, 객체의 속성(`params.learning_rate`)처럼 더 편리하게 접근하고 싶을 때 이 메서드들을 유용하게 사용할 수 있습니다.

```python
class DynamicAttributes:
    def __init__(self):
        self._data = {}

    def __getattr__(self, name):
        """존재하지 않는 속성에 접근 시 호출"""
        if name in self._data:
            return self._data[name]
        raise AttributeError(f"'{self.__class__.__name__}' object has no attribute '{name}'")

    def __setattr__(self, name, value):
        """속성 설정 시 호출"""
        if name == '_data': # 무한 재귀 방지
            super().__setattr__(name, value)
        else:
            print(f"Setting attribute '{name}' to '{value}'")
            self._data[name] = value

    def __delattr__(self, name):
        """속성 삭제 시 호출"""
        if name in self._data:
            print(f"Deleting attribute '{name}'")
            del self._data[name]
        else:
            raise AttributeError(f"'{self.__class__.__name__}' object has no attribute '{name}'")

# 인스턴스 생성
dyn_obj = DynamicAttributes()

# __setattr__ 호출
dyn_obj.name = "Test"
dyn_obj.age = 10

# __getattr__ 호출
print(f"dyn_obj.name: {dyn_obj.name}")
print(f"dyn_obj.age: {dyn_obj.age}")

# 존재하지 않는 속성 접근 시 __getattr__ 호출 후 AttributeError 발생
try:
    print(dyn_obj.non_existent)
except AttributeError as e:
    print(f"Error: {e}")

# __delattr__ 호출
del dyn_obj.name

# 삭제된 속성 접근 시도
try:
    print(dyn_obj.name)
except AttributeError as e:
    print(f"Error: {e}")
```
