## 1. 객체 지향 프로그래밍 (OOP) 개요

객체 지향 프로그래밍(Object-Oriented Programming, OOP)은 프로그램을 **독립적인 단위인 '객체'들의 집합**으로 파악하고, 이 객체들이 서로 메시지를 주고받으며 상호작용하는 방식으로 프로그램을 설계하는 프로그래밍 패러다임입니다. 데이터와 해당 데이터를 처리하는 함수(메서드)를 하나로 묶어 '객체'로 만들고, 이 객체들을 조합하여 더 크고 복잡한 시스템을 구축합니다.

절차 지향 프로그래밍이 데이터와 함수를 분리하여 순차적으로 처리하는 방식에 중점을 둔다면, OOP는 **데이터와 그 데이터를 다루는 행동을 하나로 캡슐화**하여 코드의 구조를 더 직관적이고 유연하게 만듭니다.

### 1.1 절차 지향 vs 객체 지향: 패러다임의 전환

OOP의 필요성을 이해하기 위해 간단한 예시를 통해 두 패러다임의 차이를 살펴보겠습니다.

*   **절차 지향 방식 (Procedural Programming):**
    데이터(학생 정보)와 해당 데이터를 처리하는 함수(정보 출력)가 분리되어 있습니다. 데이터 구조가 변경되면(예: `student` 딕셔너리에 'email' 추가), `print_student_info` 함수도 함께 수정해야 할 가능성이 높습니다.

    ```python
    # 데이터와 함수가 분리됨
    student_name = "Alice"
    student_grade = 3

    def print_student_info(name, grade):
        print(f"이름: {name}, 학년: {grade}")

    print_student_info(student_name, student_grade)
    ```

*   **객체 지향 방식 (Object-Oriented Programming):**
    학생의 데이터(이름, 학년)와 행동(정보 출력)이 `Student`라는 하나의 '객체' 안에 캡슐화되어 있습니다. 관련된 데이터와 기능이 하나의 단위로 묶여 있어 코드가 더 명확하고, 다른 곳에서 `Student` 객체를 재사용하기 용이합니다.

    ```python
    # 데이터와 함수(메서드)가 'Student' 클래스 안에 캡슐화됨
    class Student:
        def __init__(self, name, grade):
            self.name = name
            self.grade = grade

        def display_info(self):
            print(f"이름: {self.name}, 학년: {self.grade}")

    # 객체(인스턴스) 생성 및 메서드 호출
    student1 = Student("Alice", 3)
    student1.display_info()
    ```

### 1.2 OOP의 핵심 장점 및 실무적 필요성

| 핵심 장점 | 설명 | 실무적 필요성 (데이터 과학 관점) |
| :--- | :--- | :--- |
| **코드 조직화 및 가독성** | 관련된 데이터와 기능을 클래스로 묶어 코드의 구조를 명확하게 만듭니다. | 여러 데이터 소스, 전처리 단계, 모델을 다룰 때 각 요소를 클래스로 정의하면 전체 파이프라인의 구조를 이해하기 쉽고, 다른 팀원과의 협업이 용이해집니다. |
| **재사용성 (Reusability)** | 한 번 잘 정의된 클래스는 다른 프로젝트나 프로그램의 다른 부분에서 쉽게 재사용할 수 있습니다. | 특정 데이터셋을 로드하고 전처리하는 클래스, 특정 모델(예: `CustomLinearRegression`)을 구현한 클래스 등을 만들어두면, 여러 실험이나 프로젝트에서 반복적인 코딩 없이 재사용할 수 있습니다. |
| **유지보수 용이성** | 기능 수정이 필요할 때, 관련된 클래스 내부만 수정하면 되므로 다른 코드에 미치는 영향을 최소화할 수 있습니다. | 모델의 특정 기능(예: 예측 방식, 평가 지표)을 변경하고 싶을 때, 해당 모델 클래스만 수정하면 되므로 전체 분석 코드의 안정성을 해치지 않고 쉽게 유지보수할 수 있습니다. |
| **확장성 (Extensibility)** | 기존 클래스를 상속하여 새로운 기능을 추가하거나 수정하는 것이 용이합니다. (상속은 심화 과정에서 다룸) | 기본 모델 클래스를 만든 후, 이를 상속하여 규제(Regularization)가 추가된 모델, 특성 선택 기능이 추가된 모델 등 다양한 변형 모델을 쉽게 만들 수 있습니다. |
| **현실 세계 모델링** | 현실 세계의 개념(고객, 제품, 센서 등)을 코드로 직접 표현하여 문제를 더 직관적으로 해결할 수 있습니다. | 고객 데이터를 `Customer` 클래스로, 금융 상품을 `Product` 클래스로 모델링하면, 비즈니스 로직을 코드에 더 명확하게 반영하고 분석할 수 있습니다. |

### 1.3 클래스(Class), 객체(Object), 인스턴스(Instance)의 관계

파이썬에서는 모든 것이 객체입니다. 숫자, 문자열, 함수, 심지어 클래스 자체도 객체입니다. 이러한 객체들은 특정 클래스의 인스턴스로 존재합니다.

- **클래스 (Class):** 객체를 생성하기 위한 **설계도** 또는 **틀(template)**입니다. 객체가 가져야 할 속성(데이터, 변수)과 행동(기능, 메서드)을 정의합니다. (예: `붕어빵 틀`, `자동차 설계도`)
- **객체 (Object):** 클래스에 의해 생성된 **실체(thing)**입니다. 클래스의 정의에 따라 메모리에 할당된 실체이며, 파이썬에서 다루는 모든 것을 포괄하는 일반적인 용어입니다. (예: `실제 붕어빵`, `실제 자동차`)
- **인스턴스 (Instance):** 특정 클래스로부터 생성된 객체를 지칭할 때 사용되는, **관계**를 강조하는 용어입니다. '객체'는 '인스턴스'보다 더 일반적인 개념입니다. (예: `팥 붕어빵`과 `슈크림 붕어빵`은 `붕어빵 틀`의 인스턴스들이다.)

> **요약:** `클래스`는 설계도, `객체`는 설계도로 만든 실체, `인스턴스`는 '어떤 클래스로부터 만들어진 객체'라는 관계를 나타내는 말입니다. 보통 '객체'와 '인스턴스'는 거의 동일한 의미로 혼용되어 사용됩니다.

```python
# Class (설계도)
class Dog:
    # 클래스 변수 (모든 Dog 인스턴스가 공유)
    species = "Canis lupus familiaris"

# my_dog는 Dog 클래스의 '인스턴스'이자 하나의 '객체'입니다.
my_dog = Dog()

# your_dog 역시 Dog 클래스의 또 다른 '인스턴스'이자 별개의 '객체'입니다.
your_dog = Dog()

# type() 함수로 어떤 클래스의 인스턴스인지 확인
print(f"my_dog 객체는 {type(my_dog)} 클래스의 인스턴스입니다.")

# 'is' 연산자로 두 객체가 동일한 메모리 주소를 가리키는지 확인
print(f"my_dog와 your_dog는 같은 객체인가? {my_dog is your_dog}") # False, 서로 다른 메모리 공간에 할당된 별개의 객체

# id() 함수로 실제 메모리 주소 확인
print(f"my_dog의 메모리 주소 (id): {id(my_dog)}")
print(f"your_dog의 메모리 주소 (id): {id(your_dog)}")
```

## 2. 클래스 정의 및 인스턴스 생성

클래스는 객체의 청사진 역할을 하며, `class` 키워드를 사용하여 정의합니다. 클래스 정의는 객체가 가질 데이터(속성)와 기능(메서드)을 명시하는 과정입니다. 이렇게 정의된 클래스를 바탕으로, 우리는 메모리 상에 실제적인 객체, 즉 인스턴스를 생성하여 사용할 수 있습니다.

### 2.1 기본 클래스 구조

클래스를 정의하는 가장 기본적인 형태와, 그 클래스로부터 인스턴스를 만드는 과정은 다음과 같습니다.

*   **클래스 정의:** `class` 키워드와 클래스 이름을 사용합니다. 클래스 이름은 관례적으로 각 단어의 첫 글자를 대문자로 쓰는 **파스칼 케이스(PascalCase)**를 따릅니다.
*   **인스턴스화 (Instantiation):** 클래스 이름 뒤에 괄호 `()`를 붙여 함수처럼 호출하면, 해당 클래스의 새로운 인스턴스가 생성됩니다.

```python
class Person:
    # 클래스 속성 (모든 인스턴스가 공유)
    species = "Human"

    # 메서드 (클래스 내부에 정의된 함수)
    def say_hello(self):
        print("안녕하세요!")

# 인스턴스 생성
p1 = Person()
p2 = Person()

# 클래스 속성 접근
print(f"p1의 종: {p1.species}")
print(f"p2의 종: {p2.species}")

# 메서드 호출
p1.say_hello()
p2.say_hello()
```

### 2.2 생성자 (`__init__`)

`__init__` 메서드는 클래스의 **생성자(constructor)** 역할을 하는 특별한 메서드입니다. 클래스의 인스턴스가 생성될 때 **자동으로 호출**되며, 주로 인스턴스가 처음 만들어질 때 가져야 할 초기 속성(인스턴스 변수)을 설정하는 데 사용됩니다.

*   **`self`의 의미:** `__init__` 메서드의 첫 번째 매개변수는 항상 `self`여야 합니다. `self`는 **생성되는 인스턴스 자신**을 가리키는 참조입니다. 파이썬이 메서드를 호출할 때 `self` 인자를 자동으로 전달해주므로, 우리는 `self`를 통해 각 인스턴스의 고유한 속성에 접근하고 값을 할당할 수 있습니다.

```python
class Car:
    def __init__(self, brand, model, year):
        """Car 클래스의 생성자"""
        self.brand = brand    # 인스턴스 변수
        self.model = model
        self.year = year
        self.is_running = False

    def start_engine(self):
        self.is_running = True
        print(f"{self.brand} {self.model} 엔진이 시작되었습니다.")

    def stop_engine(self):
        self.is_running = False
        print(f"{self.brand} {self.model} 엔진이 정지되었습니다.")

# 인스턴스 생성 시 __init__ 호출
my_car = Car("Hyundai", "Sonata", 2020)
your_car = Car("Kia", "K5", 2022)

print(f"내 차: {my_car.brand} {my_car.model} ({my_car.year})")
print(f"네 차: {your_car.brand} {your_car.model} ({your_car.year})")

my_car.start_engine()
print(f"내 차 엔진 상태: {my_car.is_running}")
```

#### 2.2.1 `__new__` 메서드 (참고)

객체 생성 과정에서 `__init__`보다 먼저 호출되는 특별한 메서드로 `__new__`가 있습니다. `__new__`는 클래스의 **인스턴스 자체를 생성하고 반환**하는 역할을 합니다. 반면 `__init__`은 `__new__`가 생성한 인스턴스를 받아서 초기화하는 역할을 합니다. 

일반적으로 `__new__`를 직접 재정의할 필요는 거의 없지만, 다음과 같은 특수한 경우에 사용될 수 있습니다:
*   **싱글턴 패턴(Singleton Pattern):** 클래스의 인스턴스가 오직 하나만 존재하도록 보장해야 할 때
*   **불변(Immutable) 객체 커스터마이징:** `tuple`, `str`과 같은 불변 타입을 상속받아 새로운 클래스를 만들 때
*   **조건부 인스턴스 반환:** 특정 조건에 따라 다른 클래스의 인스턴스를 반환해야 할 때

#### 2.2.2 가변 기본값 주의 (재강조)

함수 정의와 마찬가지로, 생성자 매개변수의 기본값으로 리스트(`[]`)나 딕셔너리(`{}`) 같은 **가변 객체(mutable object)**를 사용하면 모든 인스턴스가 동일한 객체를 공유하게 되어 심각한 버그를 유발할 수 있습니다. 

**해결책:** 기본값으로 `None`을 사용하고, 생성자 내부에서 초기화하는 것이 안전하고 표준적인 방법입니다.

```python
class StudentSafe:
    def __init__(self, name, courses=None):
        self.name = name
        # courses가 None이면 새로운 리스트를 생성, 아니면 전달된 리스트 사용
        if courses is None:
            self.courses = []
        else:
            self.courses = courses
```

#### 2.2.3 생성자 내 데이터 유효성 검사

생성자는 객체가 생성되는 시점에 호출되므로, 잘못된 데이터로 객체가 생성되는 것을 막기 위한 **유효성 검사(validation)**를 수행하기에 좋은 위치입니다. 이를 통해 객체는 항상 일관되고 유효한 상태를 유지할 수 있습니다.

```python
class Circle:
    def __init__(self, radius):
        # 데이터 유효성 검사
        if not isinstance(radius, (int, float)):
            raise TypeError("반지름은 숫자여야 합니다.")
        if radius <= 0:
            raise ValueError("반지름은 0보다 커야 합니다.")
        self.radius = radius
```

### 2.3 인스턴스 메서드와 `self`

**인스턴스 메서드**는 클래스 내에 정의된 함수로, 해당 클래스의 인스턴스만이 호출할 수 있는 기능입니다. 인스턴스 메서드는 **인스턴스의 상태(인스턴스 변수)를 조작하거나, 그 상태를 기반으로 특정 작업을 수행**합니다.

*   **`self`의 역할:** 모든 인스턴스 메서드는 첫 번째 매개변수로 `self`를 가집니다. `self`는 메서드를 호출한 인스턴스 자신을 가리킵니다. 이를 통해 메서드는 자신이 속한 인스턴스의 데이터(예: `self.brand`, `self.is_running`)에 접근하고 수정할 수 있습니다.

```python
class Student:
    def __init__(self, name, student_id):
        self.name = name
        self.student_id = student_id
        self.grades = []

    def add_grade(self, grade):
        """학생의 성적을 추가하는 메서드"""
        self.grades.append(grade)
        print(f"{self.name}의 성적 {grade}가 추가되었습니다.")

    def get_average_grade(self):
        """학생의 평균 성적을 계산하여 반환하는 메서드"""
        if not self.grades:
            return 0
        return sum(self.grades) / len(self.grades)

# 인스턴스 생성
s1 = Student("김철수", "2023001")

# 인스턴스 메서드 호출
s1.add_grade(90)
s1.add_grade(85)
s1.add_grade(95)

print(f"{s1.name}의 평균 성적: {s1.get_average_grade():.2f}")
```

### 2.4 클래스 메서드 (`@classmethod`)

인스턴스가 아닌 **클래스 자체**에 작용하는 메서드입니다. `@classmethod` 데코레이터를 사용하여 정의하며, 첫 번째 인자로 클래스 자신(`cls`)을 받습니다. 주로 클래스 변수를 조작하거나, 다양한 방식으로 인스턴스를 생성하는 **팩토리 메서드(Factory Method)**를 만들 때 사용됩니다.

```python
class MyClass:
    class_variable = 0

    def __init__(self, value):
        self.instance_variable = value

    @classmethod
    def increment_class_variable(cls):
        cls.class_variable += 1
        print(f"클래스 변수 증가: {cls.class_variable}")

    @classmethod
    def create_from_string(cls, data_string):
        """문자열로부터 MyClass 인스턴스를 생성하는 팩토리 메서드"""
        value = int(data_string.split('-')[1])
        return cls(value)

# 클래스 메서드 호출
MyClass.increment_class_variable() # 클래스를 통해 호출

obj1 = MyClass(10)
obj2 = MyClass.create_from_string("data-20") # 팩토리 메서드 사용

print(f"obj1 인스턴스 변수: {obj1.instance_variable}")
print(f"obj2 인스턴스 변수: {obj2.instance_variable}")
```

### 2.5 정적 메서드 (`@staticmethod`)

클래스나 인스턴스의 상태(`self` 또는 `cls`)에 전혀 접근하지 않는 메서드입니다. `@staticmethod` 데코레이터를 사용하여 정의하며, 클래스 이름 공간 안에 논리적으로 묶어두고 싶은 유틸리티 함수를 정의할 때 사용됩니다.

```python
class MathUtil:
    @staticmethod
    def add(x, y):
        """두 숫자를 더하는 정적 메서드"""
        return x + y

    @staticmethod
    def multiply(x, y):
        """두 숫자를 곱하는 정적 메서드"""
        return x * y

# 정적 메서드 호출 (클래스 또는 인스턴스를 통해 호출 가능)
print(f"덧셈: {MathUtil.add(5, 3)}")
print(f"곱셈: {MathUtil.multiply(4, 2)}")
```

### 2.6 객체의 문자열 표현 (`__str__`, `__repr__`)

객체를 `print()` 함수로 출력하거나 디버깅할 때, 객체에 대한 유용한 정보를 보여주도록 문자열 표현을 정의할 수 있습니다. 이는 코드의 가독성과 디버깅 효율을 크게 향상시킵니다.

*   **`__str__(self)`:** `print(obj)`나 `str(obj)`처럼 **사용자**가 보기 좋은 비공식적인 문자열을 반환할 때 사용됩니다.
*   **`__repr__(self)`:** `repr(obj)`나 인터랙티브 셸에서 객체를 출력할 때처럼, **개발자**가 객체를 명확하게 식별하고, 가능하다면 객체를 다시 생성할 수 있는 형태의 공식적인 문자열을 반환할 때 사용됩니다. `__str__`이 정의되지 않았다면 `__repr__`이 대신 사용됩니다.

> **Best Practice:** `__repr__`은 항상 정의하고, 필요에 따라 더 사용자 친화적인 `__str__`을 추가로 정의하는 것이 좋습니다.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):
        """사용자 친화적인 문자열 표현"""
        return f"Point({self.x}, {self.y})"

    def __repr__(self):
        """개발자 친화적인 문자열 표현 (객체 재현 가능)"""
        return f"Point(x={self.x}, y={self.y})"

p = Point(10, 20)

print(f"print(p): {p}") # __str__ 호출
print(f"str(p): {str(p)}") # __str__ 호출
print(f"repr(p): {repr(p)}") # __repr__ 호출
```

#### 2.6.1 `__format__` 메서드 (참고)
`f-string`이나 `str.format()` 메서드에서 객체를 특정 형식으로 포매팅할 때 호출되는 메서드입니다. 이를 구현하면 사용자가 객체를 다양한 형식으로 출력할 수 있습니다.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __format__(self, format_spec):
        if format_spec == 'r': # 반지름-각도 형태
            r = (self.x**2 + self.y**2)**0.5
            return f"(r={r:.2f})"
        return f"({self.x}, {self.y})" # 기본 형식

p = Point(3, 4)
print(f"기본 출력: {p}")
print(f"반지름 형태 출력: {p:r}")
```

### 2.7 `dataclasses` 모듈: 데이터 클래스 간결하게 만들기

파이썬 3.7부터 도입된 `dataclasses` 모듈은 주로 데이터를 담는 용도의 클래스를 매우 간결하게 작성할 수 있도록 도와줍니다. `@dataclass` 데코레이터를 클래스 위에 붙이기만 하면, 개발자가 반복적으로 작성해야 했던 `__init__`, `__repr__`, `__eq__`(동등성 비교)와 같은 필수적인 "보일러플레이트" 메서드들을 **자동으로 생성**해줍니다.

#### 2.7.1 `@dataclass`의 마법: 코드 비교

`@dataclass`의 강력함을 이해하는 가장 좋은 방법은 일반 클래스와 직접 비교하는 것입니다. 학생 정보를 저장하는 간단한 `Student` 클래스를 두 가지 방식으로 구현해 보겠습니다.

**1. 일반 클래스로 구현 (직접 작성)**

`__init__` (생성자), `__repr__` (문자열 표현), `__eq__` (동등성 비교) 메서드를 모두 직접 작성해야 합니다.

```python
class RegularStudent:
    def __init__(self, name: str, student_id: int, grade: float):
        self.name = name
        self.student_id = student_id
        self.grade = grade

    def __repr__(self) -> str:
        # 객체를 명확하게 표현하기 위한 __repr__
        return f"RegularStudent(name='{self.name}', student_id={self.student_id}, grade={self.grade})"

    def __eq__(self, other) -> bool:
        # 두 객체의 내용이 같은지 비교하기 위한 __eq__
        if not isinstance(other, RegularStudent):
            return NotImplemented
        return (
            self.name == other.name and
            self.student_id == other.student_id and
            self.grade == other.grade
        )

# 객체 생성
student_a = RegularStudent("Alice", 101, 3.5)

# __repr__ 확인
print(f"일반 클래스 출력: {student_a}")

# __eq__ 확인
student_b = RegularStudent("Alice", 101, 3.5)
print(f"두 학생은 같은가? {student_a == student_b}")
```

**2. 데이터 클래스로 구현 (`@dataclass` 사용)**

`@dataclass` 데코레이터와 타입 힌트만으로 필드를 선언하면, 위의 모든 메서드가 자동으로 생성됩니다.

```python
from dataclasses import dataclass

@dataclass
class DataStudent:
    name: str
    student_id: int
    grade: float

# 객체 생성 (자동 생성된 __init__ 사용)
student_c = DataStudent("Alice", 101, 3.5)

# __repr__ 확인 (자동 생성된 __repr__)
print(f"\n데이터 클래스 출력: {student_c}")

# __eq__ 확인 (자동 생성된 __eq__)
student_d = DataStudent("Alice", 101, 3.5)
print(f"두 학생은 같은가? {student_c == student_d}")
```

**결론:**

두 방식의 결과는 동일하지만, `@dataclass`를 사용한 코드가 훨씬 간결하고 명확합니다. 필드를 추가하거나 수정할 때도 데이터 클래스는 해당 필드 선언만 변경하면 되지만, 일반 클래스는 `__init__`, `__repr__`, `__eq__` 메서드를 모두 수동으로 수정해야 하는 번거로움이 있습니다. 이처럼 `@dataclass`는 데이터 중심 객체를 다룰 때 개발 생산성을 크게 향상시켜 줍니다.



#### 2.7.1 `attrs` 라이브러리 (참고)
`dataclasses`는 `attrs`라는 매우 강력하고 성숙한 외부 라이브러리에서 영감을 받았습니다. `attrs`는 `dataclasses`보다 더 많은 기능(예: 변환기, 유효성 검사기)과 유연성을 제공하며, 구형 파이썬 버전과도 호환됩니다. 복잡한 데이터 클래스가 필요하다면 `attrs` 사용을 고려해볼 수 있습니다. (`pip install attrs`)

### 2.8 객체 불변성 (Object Immutability) 설계

**불변 객체(Immutable Object)**는 생성된 후에 그 상태를 변경할 수 없는 객체를 말합니다. 파이썬의 `int`, `str`, `tuple`이 대표적인 예입니다. 불변 객체를 사용하면 다음과 같은 장점이 있습니다:

*   **예측 가능성:** 객체의 상태가 변하지 않으므로 코드의 동작을 예측하기 쉽고 버그 발생 가능성이 줄어듭니다.
*   **안전한 공유:** 여러 부분에서 객체를 참조하더라도 한 곳에서 상태를 변경하여 다른 곳에 영향을 미칠 걱정이 없습니다.
*   **딕셔너리 키/집합 요소:** 해시 가능한(hashable) 상태가 되므로 딕셔너리의 키나 집합의 요소로 사용할 수 있습니다.

`dataclasses` 모듈에서 `frozen=True`를 설정하면 손쉽게 불변 객체를 만들 수 있습니다.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class ImmutablePoint:
    x: int
    y: int

p = ImmutablePoint(10, 20)
point_set = {p} # 집합의 요소로 사용 가능
print(f"생성된 불변 객체: {p}")

try:
    p.x = 30 # 속성 변경 시도
except Exception as e:
    print(f"오류 발생: {e}") # dataclasses.FrozenInstanceError 발생
```

## 3. 변수의 종류: 인스턴스 변수와 클래스 변수

클래스 내에서 변수를 정의하는 위치와 목적에 따라 **인스턴스 변수(Instance Variables)**와 **클래스 변수(Class Variables)**로 나뉩니다. 이 둘의 차이점을 이해하는 것은 객체의 상태를 올바르게 관리하고 메모리를 효율적으로 사용하는 데 매우 중요합니다.

### 3.1 인스턴스 변수 (Instance Variables)

인스턴스 변수는 **각 인스턴스에 독립적으로 속한 변수**입니다. 즉, 모든 객체가 자신만의 값을 가집니다. 주로 `__init__` 생성자 내에서 `self.변수명` 형태로 정의되며, 각 객체의 고유한 상태를 나타냅니다.

*   **정의:** `__init__` 메서드 내에서 `self.변수명 = 값` 형태로 정의됩니다.
*   **소유:** 각 인스턴스가 독립적으로 소유합니다.
*   **특징:** 한 인스턴스에서 값을 변경해도 다른 인스턴스에 전혀 영향을 주지 않습니다.
*   **용도:** 객체마다 달라져야 하는 고유한 데이터(예: 학생의 이름, 자동차의 모델명, 모델의 학습 가중치)를 저장하는 데 사용됩니다.

```python
class Dog:
    def __init__(self, name, breed):
        # 아래 변수들은 각 Dog 인스턴스에 고유하게 속합니다.
        self.name = name   # 인스턴스 변수
        self.breed = breed # 인스턴스 변수

dog1 = Dog("바둑이", "진돗개")
dog2 = Dog("초코", "푸들")

# 각 인스턴스는 자신만의 name 값을 가집니다.
print(f"Dog1 이름: {dog1.name}") # 바둑이
print(f"Dog2 이름: {dog2.name}") # 초코

# dog1의 이름을 변경해도 dog2에는 영향이 없습니다.
dog1.name = "메리"
print(f"Dog1 이름 변경 후: {dog1.name}") # 메리
print(f"Dog2 이름: {dog2.name}") # 초코 (변경 없음)
```

### 3.2 클래스 변수 (Class Variables)

클래스 변수는 해당 **클래스의 모든 인스턴스가 공유하는 변수**입니다. 클래스 정의 블록 바로 아래, 메서드 외부에 정의됩니다. 모든 인스턴스가 공통으로 참조하는 상수나, 클래스 전체에 걸쳐 관리되어야 할 상태를 나타낼 때 유용합니다.

*   **정의:** 클래스 정의 블록 내, 메서드 외부에 `변수명 = 값` 형태로 정의됩니다.
*   **소유:** 클래스 자체가 소유하며, 모든 인스턴스가 이 변수를 공유합니다.
*   **특징:** 클래스를 통해 값을 변경하면 모든 인스턴스에 변경 사항이 반영됩니다.
*   **용도:** 모든 인스턴스가 공유하는 공통 속성(예: 모든 자동차의 바퀴 수), 클래스 전체에서 사용되는 상수(예: 원주율), 생성된 인스턴스의 총 개수 등을 저장하는 데 사용됩니다.

### 3.3 실무 예제: 데이터 정규화 클래스

데이터 과학에서 특성(feature)의 스케일을 조정하는 정규화(Normalization) 클래스를 만든다고 가정해 봅시다. 이 클래스는 여러 데이터셋에 적용될 수 있지만, 모든 정규화 작업에 동일한 상수(예: 아주 작은 값 `epsilon`)를 사용하고, 생성된 정규화기(Normalizer)의 총 개수를 추적해야 할 수 있습니다.

```python
class Normalizer:
    # 클래스 변수: 모든 Normalizer 인스턴스가 공유
    # 1. 상수 값: 0으로 나누는 것을 방지하기 위한 작은 값
    EPSILON = 1e-8 
    # 2. 상태 추적: 생성된 Normalizer 인스턴스의 총 개수
    total_normalizers_created = 0

    def __init__(self, data_column):
        # 인스턴스 변수: 각 Normalizer 인스턴스는 자신만의 통계치를 가짐
        self.mean = sum(data_column) / len(data_column)
        self.std = (sum((x - self.mean) ** 2 for x in data_column) / len(data_column)) ** 0.5
        
        # 인스턴스가 생성될 때마다 클래스 변수를 1 증가시킴
        Normalizer.total_normalizers_created += 1
        print(f"Normalizer 생성됨. (평균: {self.mean:.2f}, 표준편차: {self.std:.2f})")

    def normalize(self, value):
        # 클래스 변수(EPSILON)와 인스턴스 변수(mean, std)를 모두 사용
        return (value - self.mean) / (self.std + self.EPSILON)

# 데이터 준비
feature1_data = [10, 20, 30, 40, 50]
feature2_data = [150, 155, 160, 165, 170]

# 각 특성에 대한 Normalizer 인스턴스 생성
# 각 인스턴스는 자신만의 mean, std 값을 가짐 (인스턴스 변수)
normalizer_f1 = Normalizer(feature1_data)
normalizer_f2 = Normalizer(feature2_data)

# 클래스 변수는 모든 인스턴스에서 동일하게 접근 가능
print(f"\n모든 Normalizer가 공유하는 EPSILON 값: {normalizer_f1.EPSILON}")
print(f"총 생성된 Normalizer 개수: {Normalizer.total_normalizers_created}")

# 각 인스턴스의 메서드는 자신만의 인스턴스 변수를 사용하여 값을 정규화
original_value = 35
normalized_f1 = normalizer_f1.normalize(original_value)
normalized_f2 = normalizer_f2.normalize(original_value)

print(f"\n{original_value} -> F1 정규화: {normalized_f1:.2f}")
print(f"{original_value} -> F2 정규화: {normalized_f2:.2f}")
```

### 3.4 네임스페이스와 변수 접근 규칙

*   **접근:** 인스턴스는 `self.변수명` 또는 `인스턴스.변수명`으로 인스턴스 변수에 먼저 접근합니다. 만약 해당 이름의 인스턴스 변수가 없으면, 파이썬은 **클래스 변수**에서 같은 이름의 변수를 찾아봅니다. 이것이 `normalizer_f1.EPSILON`과 같이 인스턴스를 통해 클래스 변수에 접근할 수 있는 이유입니다.
*   **변경 시 주의사항:** 클래스 변수는 반드시 `클래스명.변수명` 형태로 변경해야 합니다. 만약 `인스턴스.클래스변수명 = 값` 형태로 값을 할당하면, 공유되는 클래스 변수를 변경하는 것이 아니라, **해당 인스턴스에만 새로운 인스턴스 변수가 생성**됩니다.

```python
class Test:
    class_var = 100

t1 = Test()
t2 = Test()

print(f"초기값: t1.class_var={t1.class_var}, t2.class_var={t2.class_var}, Test.class_var={Test.class_var}")

# 잘못된 방법: 인스턴스를 통해 클래스 변수 변경 시도
t1.class_var = 200 # 't1'에만 새로운 인스턴스 변수 class_var가 생성됨

print(f"t1 변경 후: t1.class_var={t1.class_var}, t2.class_var={t2.class_var}, Test.class_var={Test.class_var}")

# 올바른 방법: 클래스를 통해 클래스 변수 변경
Test.class_var = 300

print(f"Test 변경 후: t1.class_var={t1.class_var}, t2.class_var={t2.class_var}, Test.class_var={Test.class_var}")
# t1은 자신만의 인스턴스 변수 200을 계속 사용하고, t2는 변경된 클래스 변수 300을 참조함
```

### 3.5 두 변수의 차이점과 사용 사례

| 구분 | 인스턴스 변수 (Instance Variables) | 클래스 변수 (Class Variables) |
| :--- | :--- | :--- |
| **정의 위치** | `__init__` 메서드 내 `self.변수명` | 클래스 정의 블록 내, 메서드 외부 |
| **유효 범위** | 각 인스턴스에 독립적 | 모든 인스턴스가 공유 |
| **접근 방법** | `인스턴스.변수명` | `클래스명.변수명` 또는 `인스턴스.변수명` |
| **변경 시** | 해당 인스턴스에만 영향 | 모든 인스턴스에 영향 (클래스 통해 변경 시) |
| **주요 용도** | 인스턴스별 고유 데이터 (예: 이름, 나이, 모델) | 모든 인스턴스가 공유하는 공통 데이터 (예: 바퀴 수, 총 생성 개수, 상수) |

**사용 사례:**

- **인스턴스 변수:** 사용자 이름, 계좌 잔액, 특정 자동차의 색상, 학생의 성적 등 각 객체마다 달라지는 정보.
- **클래스 변수:** 모든 자동차가 가지는 바퀴의 개수, 특정 게임의 총 플레이어 수, 원주율(PI)과 같은 상수, 클래스 인스턴스의 총 개수 등 클래스 전체에 걸쳐 공유되거나 변하지 않는 정보.
