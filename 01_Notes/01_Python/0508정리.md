## 1. OOP의 4대 원칙

객체 지향 프로그래밍의 핵심을 이루는 네 가지 원칙은 코드의 구조화, 재사용성, 유지보수성, 확장성을 높이는 데 기여합니다.

### 1.1 캡슐화 (Encapsulation)

**캡슐화**는 데이터(속성)와 데이터를 처리하는 메서드(행동)를 하나의 단위(클래스)로 묶고, 외부에서 객체 내부의 데이터에 직접 접근하는 것을 제한하여 데이터의 무결성을 보호하는 개념입니다. 파이썬은 다른 언어처럼 `private`나 `protected`와 같은 엄격한 접근 제어자를 제공하지 않지만, 다음과 같은 컨벤션을 통해 캡슐화를 구현합니다.

- **단일 언더스코어 (`_variable`):** 내부적으로만 사용될 변수나 메서드임을 나타내는 컨벤션입니다. 외부에서 접근은 가능하지만, 개발자에게 "이것은 내부용이니 직접 건드리지 마세요"라고 알리는 역할을 합니다.
- **이중 언더스코어 (`__variable`):** "이름 맹글링(Name Mangling)"이라는 파이썬의 특수 기능으로, 클래스 외부에서 직접 접근하기 어렵게 만듭니다. `_클래스명__변수명` 형태로 변수명이 변경되어 충돌을 방지합니다. 완전히 private한 것은 아니지만, 의도치 않은 외부 접근을 막는 데 효과적입니다.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance # 이중 언더스코어: 외부에서 직접 접근 제한

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"{amount}원 입금. 현재 잔액: {self.__balance}원")
        else:
            print("0원보다 큰 금액을 입금해주세요.")

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            print(f"{amount}원 출금. 현재 잔액: {self.__balance}원")
        else:
            print("잔액이 부족하거나 유효하지 않은 금액입니다.")

    def get_balance(self):
        return self.__balance

# 인스턴스 생성
account = BankAccount("김철수", 10000)

# 메서드를 통한 접근 (권장)
account.deposit(5000)
account.withdraw(2000)
print(f"최종 잔액: {account.get_balance()}원")

# 직접 접근 시도 (이름 맹글링으로 인해 접근 어려움)
# print(account.__balance) # AttributeError

# 이름 맹글링된 이름으로 접근 (권장하지 않음)
print(f"맹글링된 이름으로 접근: {account._BankAccount__balance}원")
```

### 1.2 상속 (Inheritance)

**상속**은 기존 클래스(부모 클래스 또는 기반 클래스)의 속성과 메서드를 새로운 클래스(자식 클래스 또는 파생 클래스)가 물려받아 재사용하고 확장하는 개념입니다. 코드 재사용성을 높이고, 계층적인 관계를 모델링하는 데 사용됩니다.

- **`super()`:** 자식 클래스에서 부모 클래스의 메서드를 호출할 때 사용합니다. 특히 부모 클래스의 `__init__` 메서드를 호출하여 부모의 속성을 초기화하는 데 필수적입니다.

```python
# 부모 클래스
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError("자식 클래스에서 구현해야 합니다.")

# 자식 클래스 (Animal을 상속)
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name) # 부모 클래스의 __init__ 호출
        self.breed = breed

    def speak(self):
        return f"{self.name}가 멍멍!"

class Cat(Animal):
    def __init__(self, name, color):
        super().__init__(name)
        self.color = color

    def speak(self):
        return f"{self.name}가 야옹!"

# 인스턴스 생성 및 사용
my_dog = Dog("바둑이", "진돗개")
my_cat = Cat("나비", "삼색")

print(my_dog.speak())
print(my_cat.speak())

print(f"내 강아지 품종: {my_dog.breed}")
print(f"내 고양이 색깔: {my_cat.color}")
```

### 1.3 다형성 (Polymorphism)

**다형성**은 동일한 이름의 메서드가 다른 클래스(특히 상속 관계에 있는 클래스)에서 다르게 동작하는 능력을 의미합니다. 이를 통해 코드를 더 유연하고 확장 가능하게 만들 수 있습니다. 주로 **메서드 오버라이딩(Method Overriding)**을 통해 구현됩니다.

- **메서드 오버라이딩:** 자식 클래스에서 부모 클래스에 정의된 메서드를 자신의 필요에 맞게 재정의하는 것입니다.

```python
class Shape:
    def area(self):
        raise NotImplementedError("자식 클래스에서 area() 메서드를 구현해야 합니다.")

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius ** 2

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

# 다형성 활용
shapes = [Circle(5), Rectangle(4, 6)]

for shape in shapes:
    # 각 객체의 타입에 맞는 area() 메서드가 호출됨
    print(f"도형의 넓이: {shape.area():.2f}")
```

### 1.4 추상화 (Abstraction)

**추상화**는 복잡한 구현 세부 사항을 숨기고, 사용자에게 필요한 핵심 기능(인터페이스)만 노출하는 개념입니다. 이를 통해 시스템의 복잡도를 줄이고, 사용자가 특정 기능을 사용할 때 내부 동작을 알 필요 없이 간편하게 사용할 수 있도록 합니다. 파이썬에서는 `abc` (Abstract Base Classes) 모듈을 사용하여 추상 클래스와 추상 메서드를 구현할 수 있습니다.

- **추상 클래스:** 직접 인스턴스를 생성할 수 없고, 반드시 상속받아 구현해야 하는 클래스입니다.
- **추상 메서드:** 선언만 있고 구현은 없는 메서드로, 추상 클래스를 상속받는 자식 클래스에서 반드시 오버라이딩하여 구현해야 합니다.

```python
from abc import ABC, abstractmethod

class Vehicle(ABC): # 추상 클래스 선언
    def __init__(self, name):
        self.name = name

    @abstractmethod
    def start(self):
        """차량을 시동하는 추상 메서드"""
        pass

    @abstractmethod
    def stop(self):
        """차량을 정지하는 추상 메서드"""
        pass

    def get_name(self):
        return self.name

class Car(Vehicle):
    def start(self):
        print(f"{self.name}가 시동을 걸었습니다.")

    def stop(self):
        print(f"{self.name}가 정지했습니다.")

class Motorcycle(Vehicle):
    def start(self):
        print(f"{self.name}가 시동을 걸고 출발합니다.")

    def stop(self):
        print(f"{self.name}가 멈췄습니다.")

# vehicle = Vehicle("일반 차량") # TypeError: Can't instantiate abstract class Vehicle with abstract methods start, stop

my_car = Car("내 자동차")
my_motorcycle = Motorcycle("내 오토바이")

my_car.start()
my_car.stop()
my_motorcycle.start()
my_motorcycle.stop()
```

### 1.5 컴포지션 (Composition) vs 상속 (Inheritance)

객체 지향 설계에서 클래스 간의 관계를 설정하는 두 가지 주요 방법은 상속(Inheritance)과 컴포지션(Composition)입니다.

-   **상속 (Inheritance):** "~은(는) ~이다 (is-a)" 관계를 나타냅니다. (예: `Dog` is-a `Animal`). 코드 재사용성을 높이지만, 부모 클래스의 변경이 자식 클래스에 영향을 미칠 수 있고, 다중 상속의 복잡성 문제가 발생할 수 있습니다.

-   **컴포지션 (Composition):** "~은(는) ~을(를) 가진다 (has-a)" 관계를 나타냅니다. (예: `Car` has-a `Engine`). 클래스가 다른 클래스의 인스턴스를 속성으로 포함하여 기능을 재사용합니다. 상속보다 유연하고 견고한 설계를 가능하게 하며, 결합도를 낮추고 응집도를 높이는 데 유리합니다.

**실무적 의미:**

-   **"상속보다 컴포지션을 선호하라 (Prefer composition over inheritance)"**는 객체 지향 설계의 중요한 원칙 중 하나입니다. 이는 상속이 클래스 간의 강한 결합을 만들고 유연성을 저해할 수 있기 때문입니다.
-   컴포지션을 사용하면 특정 기능을 가진 객체를 "조립"하여 더 복잡한 객체를 만들 수 있으며, 필요에 따라 기능을 쉽게 교체하거나 확장할 수 있습니다.

```python
# 컴포지션 예시
class Engine:
    def start(self):
        return "엔진 시동!"

    def stop(self):
        return "엔진 정지!"

class Car:
    def __init__(self, brand, engine: Engine):
        self.brand = brand
        self.engine = engine # Car는 Engine 객체를 가집니다 (has-a 관계)

    def start_car(self):
        print(f"{self.brand} 자동차: {self.engine.start()}")

    def stop_car(self):
        print(f"{self.brand} 자동차: {self.engine.stop()}")

# 사용
my_engine = Engine()
my_car = Car("Tesla", my_engine)
my_car.start_car()
my_car.stop_car()

# 엔진을 다른 종류로 쉽게 교체 가능
class ElectricEngine:
    def start(self):
        return "전기 모터 가동!"

    def stop(self):
        return "전기 모터 정지!"

e_car = Car("Hyundai", ElectricEngine())
e_car.start_car()
e_car.stop_car()
```

## 2. 프로퍼티 (`@property`)를 이용한 캡슐화

`@property` 데코레이터는 클래스의 속성(attribute)에 접근하거나 값을 설정할 때 특정 로직을 실행하도록 하는 파이썬의 강력한 기능입니다. 이를 통해 속성에 대한 직접적인 접근을 제어하고, 유효성 검사, 계산된 속성 등을 구현하여 캡슐화를 강화할 수 있습니다.

- **게터 (Getter):** 속성 값을 읽을 때 호출되는 메서드.
- **세터 (Setter):** 속성 값을 설정할 때 호출되는 메서드.
- **딜리터 (Deleter):** 속성을 삭제할 때 호출되는 메서드.

```python
class Person:
    def __init__(self, name, age):
        self._name = name # 내부적으로 사용될 변수 (컨벤션)
        self._age = age

    @property
    def name(self):
        """이름을 반환하는 게터"""
        return self._name

    @name.setter
    def name(self, new_name):
        """이름을 설정하는 세터 (유효성 검사 포함)"""
        if not isinstance(new_name, str) or len(new_name) == 0:
            raise ValueError("이름은 비어있지 않은 문자열이어야 합니다.")
        self._name = new_name

    @property
    def age(self):
        """나이를 반환하는 게터"""
        return self._age

    @age.setter
    def age(self, new_age):
        """나이를 설정하는 세터 (유효성 검사 포함)"""
        if not isinstance(new_age, (int, float)) or new_age < 0:
            raise ValueError("나이는 0보다 크거나 같은 숫자여야 합니다.")
        self._age = new_age

# 인스턴스 생성
p = Person("Alice", 30)

# 프로퍼티를 통한 값 접근 (게터 호출)
print(f"이름: {p.name}, 나이: {p.age}")

# 프로퍼티를 통한 값 설정 (세터 호출)
p.name = "Bob"
p.age = 31
print(f"변경된 이름: {p.name}, 변경된 나이: {p.age}")

# 유효성 검사 실패 예시
try:
    p.age = -5
except ValueError as e:
    print(f"에러: {e}")

try:
    p.name = ""
except ValueError as e:
    print(f"에러: {e}")
```

## 3. 특수 메서드 (Special Methods / Dunder Methods)

특수 메서드(Special Methods)는 이름이 두 개의 언더스코어(`__`)로 시작하고 끝나는 메서드들을 의미하며, "던더 메서드(Dunder Methods)"라고도 불립니다. 이 메서드들은 파이썬의 내장 함수나 연산자(예: `+`, `==`, `len()`, `[]`)와 연동하여 객체의 특정 동작을 정의하고 사용자 정의 클래스가 파이썬의 기본 타입처럼 동작하도록 만듭니다. 이를 통해 "파이썬스러운(Pythonic)" 코드를 작성할 수 있습니다.

### 3.1 `__str__`과 `__repr__` (복습)

(이 내용은 0507정리.md에서 자세히 다루었으므로 간략히 복습합니다.)

- **`__str__(self)`:** 객체의 사용자 친화적인 문자열 표현을 반환합니다. `print()`나 `str()` 호출 시 사용됩니다.
- **`__repr__(self)`:** 객체의 개발자 친화적인 문자열 표현을 반환합니다. 객체를 다시 생성할 수 있는 형태의 문자열을 권장하며, `repr()` 호출 시 사용됩니다.

```python
class MyObject:
    def __init__(self, value):
        self.value = value

    def __str__(self):
        return f"MyObject with value: {self.value}"

    def __repr__(self):
        return f"MyObject({self.value})"

obj = MyObject(123)
print(obj) # __str__
print(repr(obj)) # __repr__
```

### 3.2 비교 연산자 오버로딩 (`__eq__`, `__lt__` 등)

객체 간의 비교 연산(`==`, `!=`, `<`, `<=`, `>`, `>=`)이 어떻게 동작할지 정의합니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `==` | `__eq__(self, other)` | 같음 |
| `!=` | `__ne__(self, other)` | 같지 않음 |
| `<` | `__lt__(self, other)` | 작음 |
| `<=` | `__le__(self, other)` | 작거나 같음 |
| `>` | `__gt__(self, other)` | 큼 |
| `>=` | `__ge__(self, other)` | 크거나 같음 |

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        # x 좌표가 다르면 x로 비교, 같으면 y로 비교
        return self.x < other.x or (self.x == other.x and self.y < other.y)

p1 = Point(1, 2)
p2 = Point(1, 2)
p3 = Point(3, 1)

print(f"p1 == p2: {p1 == p2}") # True
print(f"p1 == p3: {p1 == p3}") # False
print(f"p1 < p3: {p1 < p3}")   # True
```

### 3.3 산술 연산자 오버로딩 (`__add__`, `__mul__` 등)

객체 간의 산술 연산(`+`, `-`, `*`, `/` 등)이 어떻게 동작할지 정의합니다.

| 연산자 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `+` | `__add__(self, other)` | 덧셈 |
| `-` | `__sub__(self, other)` | 뺄셈 |
| `*` | `__mul__(self, other)` | 곱셈 |
| `/` | `__truediv__(self, other)` | 나눗셈 |
| `//` | `__floordiv__(self, other)` | 몫 |
| `%` | `__mod__(self, other)` | 나머지 |
| `**` | `__pow__(self, other)` | 거듭제곱 |

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector(self.x * scalar, self.y * scalar)

    def __str__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)

v_sum = v1 + v2
print(f"벡터 덧셈: {v_sum}") # Vector(4, 6)

v_scaled = v1 * 3
print(f"벡터 스칼라 곱셈: {v_scaled}") # Vector(3, 6)
```

### 3.4 컨테이너 타입 메서드 (`__len__`, `__getitem__`, `__setitem__` 등)

객체가 시퀀스(리스트, 튜플)나 매핑(딕셔너리)처럼 동작하도록 정의합니다.

| 연산/함수 | 특수 메서드 | 설명 |
| :--- | :--- | :--- |
| `len(obj)` | `__len__(self)` | 객체의 길이 반환 |
| `obj[key]` | `__getitem__(self, key)` | 인덱스/키로 요소 접근 |
| `obj[key] = value` | `__setitem__(self, key, value)` | 인덱스/키로 요소 설정 |
| `del obj[key]` | `__delitem__(self, key)` | 인덱스/키로 요소 삭제 |
| `key in obj` | `__contains__(self, key)` | 요소 포함 여부 확인 |

```python
class MyList:
    def __init__(self, data):
        self._data = list(data)

    def __len__(self):
        return len(self._data)

    def __getitem__(self, index):
        return self._data[index]

    def __setitem__(self, index, value):
        self._data[index] = value

    def __str__(self):
        return str(self._data)

ml = MyList([10, 20, 30, 40])

print(f"길이: {len(ml)}") # __len__ 호출
print(f"인덱스 1의 요소: {ml[1]}") # __getitem__ 호출

ml[1] = 25 # __setitem__ 호출
print(f"수정 후: {ml}")

# for 루프도 __getitem__과 __len__을 사용하여 동작할 수 있습니다.
for item in ml:
    print(item, end=' ')
print()
```
