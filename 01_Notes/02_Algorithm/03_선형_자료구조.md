## 2. 선형 자료구조

선형 자료구조는 데이터를 순차적으로 저장하고 관리하는 방식입니다. 각 요소가 선형적인 순서로 연결되어 있어, 데이터의 접근 및 조작 방식이 비교적 직관적입니다.

### 2.1. 배열 (Array) 및 파이썬 리스트 (List)

배열은 **동일한 타입의 원소들을 메모리의 연속된 공간에 저장**하는 가장 기본적인 자료구조입니다. 이러한 구조적 특성 덕분에 인덱스를 통한 빠른 접근이 가능합니다. 파이썬의 `리스트(List)`는 일반적인 배열의 개념을 계승하면서, 크기가 동적으로 조절되는 **동적 배열(Dynamic Array)**로 구현되어 편의성을 크게 향상시켰습니다.

#### 2.1.1. 배열의 핵심 특징과 메모리 구조

배열의 성능 특성은 메모리상에 데이터가 어떻게 배치되는지와 직접적인 관련이 있습니다.

-   **연속된 메모리 할당 (Contiguous Memory Allocation):**
    -   배열의 모든 원소는 메모리 주소상에서 차례대로 나열됩니다. 예를 들어, 4바이트 정수형 배열의 첫 번째 원소가 `0x1000` 번지에 저장되었다면, 두 번째 원소는 `0x1004`, 세 번째 원소는 `0x1008`에 위치합니다.
    -   이러한 구조 덕분에 특정 인덱스 `i`에 위치한 원소의 주소는 `배열의 시작 주소 + (i * 원소의 크기)` 공식을 통해 `O(1)` 시간 복잡도로 즉시 계산할 수 있습니다. 이를 **임의 접근(Random Access)**이라고 합니다.

-   **시간 복잡도 분석:**
    | 연산 | 시간 복잡도 | 설명 |
    | :--- | :--- | :--- |
    | **접근 (Access)** | `O(1)` | 인덱스를 통해 메모리 주소를 직접 계산하여 한 번에 접근합니다. |
    | **탐색 (Search)** | `O(n)` | 특정 값을 찾기 위해서는 첫 원소부터 순차적으로 비교해야 합니다. |
    | **맨 끝 삽입/삭제** | `O(1)` (동적 배열) | 추가 공간이 있다면 마지막 위치에 데이터를 추가/삭제하기만 하면 됩니다. |
    | **중간 삽입/삭제** | `O(n)` | 특정 인덱스에 원소를 삽입/삭제하면, 그 뒤의 모든 원소를 한 칸씩 뒤로/앞으로 이동시켜야 합니다. |

-   **장점과 단점:**
    -   **장점:**
        -   인덱스를 통한 접근 속도가 매우 빠릅니다 (`O(1)`).
        -   데이터가 메모리에 밀집해 있어 캐시 효율성(Cache Locality)이 좋습니다.
    -   **단점:**
        -   생성 시 크기가 고정되어 유연성이 떨어집니다 (C++, Java의 기본 배열).
        -   중간에 데이터를 삽입하거나 삭제하는 비용이 높습니다 (`O(n)`).

#### 2.1.2. 파이썬 리스트: 강력한 동적 배열

파이썬의 리스트는 이러한 전통적인 배열의 단점을 극복한 동적 배열입니다.

-   **동적 크기 조절 (Dynamic Sizing):**
    -   리스트가 가득 찼을 때 `append()` 연산이 발생하면, 파이썬은 현재 크기보다 더 큰 새로운 메모리 블록을 할당합니다 (보통 1.125배 또는 2배).
    -   그 후, 기존의 모든 원소를 새로운 메모리 공간으로 **복사**하고, 마지막으로 새 원소를 추가합니다.
-   **상환 분석 (Amortized Analysis):**
    -   크기 재할당이 발생하는 `append()`는 `O(n)`의 비용이 들지만, 이 과정은 자주 일어나지 않습니다.
    -   대부분의 `append()` 연산은 `O(1)`에 완료되므로, 전체 연산 비용을 n으로 나눈 평균, 즉 **상환 시간 복잡도는 O(1)**이 됩니다. 이 덕분에 사용자는 리스트의 크기 관리에 신경 쓰지 않고도 효율적으로 원소를 추가할 수 있습니다.

#### 2.1.3. 리스트(List)와 튜플(Tuple)의 비교와 선택

| 구분 | 리스트 (List) - Mutable | 튜플 (Tuple) - Immutable |
| :--- | :--- | :--- |
| **정의** | 변경 가능한 순서가 있는 컬렉션 | 변경 불가능한 순서가 있는 컬렉션 |
| **문법** | `my_list = [1, 2, 3]` | `my_tuple = (1, 2, 3)` |
| **메모리** | 더 많은 메모리 사용 (오버헤드) | 더 적은 메모리 사용 (고정 크기) |
| **성능** | 생성 및 접근 속도가 튜플보다 약간 느림 | 크기가 작고, 내부적으로 최적화되어 빠름 |
| **사용 시점** | - 원소의 추가, 삭제, 수정이 필요할 때<br>- 데이터의 양이 가변적일 때 | - 데이터를 안전하게 보호하고 싶을 때 (상수 집합)<br>- 딕셔너리의 키(Key)로 사용해야 할 때 |

- **언제 무엇을 써야 할까?**
프로그램 실행 중 내용이 계속 변경되어야 한다면 **리스트**를, 한 번 정의된 후 바뀌지 않아야 할 데이터(예: 함수의 반환 값, 좌표, 설정 값)라면 **튜플**을 사용하는 것이 바람직합니다. 튜플은 불변성을 보장하므로 코드의 안정성을 높여줍니다.

#### 2.1.4. 파이썬 리스트의 주요 연산과 시간 복잡도

알고리즘 문제 해결 시, 각 메서드의 시간 복잡도를 이해하는 것은 최적의 솔루션을 설계하는 데 필수적입니다.

| 연산 | 예시 | 시간 복잡도 | 설명 |
| :--- | :--- | :--- | :--- |
| `append()` | `L.append(x)` | `O(1)` (Amortized) | 리스트의 맨 끝에 원소를 추가합니다. |
| `pop()` | `L.pop()` | `O(1)` | 리스트의 맨 끝 원소를 제거하고 반환합니다. |
| `pop(i)` | `L.pop(0)` | `O(n)` | `i` 인덱스의 원소를 제거하고, 뒤따르는 원소들을 앞으로 당깁니다. |
| `insert(i, x)`| `L.insert(0, x)`| `O(n)` | `i` 인덱스에 원소를 삽입하고, 기존 원소들을 뒤로 밀어냅니다. |
| `in` | `x in L` | `O(n)` | 원소 `x`가 리스트에 있는지 순차 탐색합니다. |
| `sort()` | `L.sort()` | `O(n log n)` | Timsort 알고리즘을 사용하여 리스트를 정렬합니다. |
| `[::-1]` | `L[::-1]` | `O(n)` | 리스트의 모든 원소를 복사하여 새로운 역순 리스트를 생성합니다. |

#### 2.1.5. 리스트 활용 문제 해결 전략

##### 2.1.5.1. 정수 배열에서 가장 큰 두 수 찾기

-   **전략:** 배열을 한 번만 순회하면서 가장 큰 수(`max1`)와 두 번째로 큰 수(`max2`)를 추적합니다. 새로운 수가 `max1`보다 크면 기존 `max1`은 `max2`가 되고, 새로운 수가 `max1`이 됩니다. 새로운 수가 `max1`보다는 작지만 `max2`보다 크면 `max2`만 업데이트합니다.
-   **복잡도:** 시간 `O(n)`, 공간 `O(1)`

```python
def find_two_largest(arr):
    """배열을 한 번 순회하여 가장 큰 두 수를 찾습니다."""
    if len(arr) < 2:
        raise ValueError("Array must contain at least two elements.")

    # 가장 큰 두 수를 음의 무한대로 초기화
    max1 = float('-inf')
    max2 = float('-inf')

    for num in arr:
        if num > max1:
            # 현재 num이 가장 크므로, 기존 max1은 두 번째로 큰 수가 됨
            max2 = max1
            max1 = num
        elif num > max2 and num != max1: # 중복된 가장 큰 수를 피하기 위함
            # 현재 num이 두 번째로 큰 경우
            max2 = num
            
    return max1, max2

# print(find_two_largest([1, 5, 2, 8, 3, 9])) # 결과: (9, 8)
```

##### 2.1.5.2. 회문(Palindromes) 판별하기

-   **전략:** 주어진 문자열에서 알파벳과 숫자만 추출하여 모두 소문자로 변환합니다. 그 후, 정제된 문자열이 자신의 역순과 같은지 비교합니다. 파이썬의 슬라이싱(`[::-1]`)을 사용하면 간결하게 구현할 수 있습니다.
-   **복잡도:** 시간 `O(n)`, 공간 `O(n)` (정제된 새 문자열 생성)

```python
def is_palindrome(s: str) -> bool:
    """문자열이 회문인지 판별합니다."""
    # 1. 정규식 또는 isalnum()을 사용하여 유효한 문자만 필터링하고 소문자로 변환
    cleaned_s = ''.join(char.lower() for char in s if char.isalnum())
    
    # 2. 정제된 문자열과 그 역순을 비교
    return cleaned_s == cleaned_s[::-1]

# print(is_palindrome("A man, a plan, a canal: Panama")) # True
```

##### 2.1.5.3. 0과 1로 구성된 배열 정렬하기

-   **전략 (Two-Pointer):** 배열의 양 끝에서 두 개의 포인터(`left`, `right`)를 시작합니다. `left` 포인터는 오른쪽으로 이동하며 `1`을 찾고, `right` 포인터는 왼쪽으로 이동하며 `0`을 찾습니다. 두 포인터가 `0`과 `1`을 각각 찾으면 두 원소의 위치를 교환(swap)합니다. 이 과정은 `left`가 `right`를 교차할 때까지 반복됩니다.
-   **복잡도:** 시간 `O(n)`, 공간 `O(1)`

```python
def sort_zeros_ones(arr):
    """투 포인터 전략을 사용하여 0과 1로 구성된 배열을 제자리 정렬합니다."""
    left, right = 0, len(arr) - 1

    while left < right:
        # left 포인터는 1을 만날 때까지 오른쪽으로 이동
        while arr[left] == 0 and left < right:
            left += 1
        # right 포인터는 0을 만날 때까지 왼쪽으로 이동
        while arr[right] == 1 and left < right:
            right -= 1
        
        # 교환 조건이 만족되면 두 원소를 교환
        if left < right:
            arr[left], arr[right] = arr[right], arr[left]
            left += 1
            right -= 1
            
    return arr

# print(sort_zeros_ones([0, 1, 0, 1, 1, 0])) # [0, 0, 0, 1, 1, 1]
```

##### 2.1.5.4. 제시된 합을 가진 연속된 부분 배열 찾기

-   **전략 (Sliding Window):** 두 개의 포인터(`start_index`, `i`)를 사용하여 '윈도우'를 정의합니다. 윈도우는 `arr[start_index:i+1]`를 나타냅니다. `i`를 오른쪽으로 이동시키며 윈도우의 합(`current_sum`)을 계속 더해나갑니다. 만약 `current_sum`이 `target_sum`을 초과하면, 합이 작아질 때까지 `start_index`를 오른쪽으로 이동시키며 윈도우를 축소합니다. `current_sum`이 `target_sum`과 같아지는 순간의 윈도우를 반환합니다.
-   **복잡도:** 시간 `O(n)` (각 원소가 최대 두 번 방문됨), 공간 `O(1)`

```python
def subarray_with_given_sum(arr, target_sum):
    """슬라이딩 윈도우 기법으로 특정 합을 가지는 연속 부분 배열을 찾습니다."""
    current_sum = 0
    start_index = 0
    
    for i in range(len(arr)):
        current_sum += arr[i]
        
        # 현재 합이 목표 합보다 크면, 윈도우의 시작점을 오른쪽으로 이동
        while current_sum > target_sum and start_index <= i:
            current_sum -= arr[start_index]
            start_index += 1
            
        # 목표 합을 찾으면 해당 부분 배열 반환
        if current_sum == target_sum:
            return arr[start_index : i + 1]
            
    return None # 찾지 못한 경우

# print(subarray_with_given_sum([1, 4, 20, 3, 10, 5], 33)) # [20, 3, 10]
```

### 2.2. 스택 (Stack)

스택은 데이터를 일시적으로 저장하는 데 사용되는 선형 자료구조입니다. 마치 접시를 쌓아 올리거나 동전을 쌓는 것과 유사하게, **가장 마지막에 들어온 요소가 가장 먼저 나가는 (Last-In, First-Out, LIFO)** 원칙을 따릅니다. 이러한 특성 때문에 스택은 특정 순서로 데이터를 처리해야 하는 다양한 알고리즘과 시스템에서 핵심적인 역할을 합니다.

#### 2.2.1. LIFO (Last-In, First-Out) 원리 및 개념

-   **개념:** 스택은 한쪽 끝에서만 데이터의 삽입(Push)과 삭제(Pop)가 일어나는 제한적인 접근 방식을 가집니다. 이 끝을 '스택의 맨 위(Top)'라고 부릅니다.
-   **비유:**
    -   **접시 쌓기:** 새로 쌓는 접시는 항상 맨 위에 놓이고, 접시를 가져갈 때도 맨 위에서부터 가져갑니다.
    -   **동전 쌓기:** 가장 나중에 올린 동전이 가장 먼저 사용됩니다.

#### 2.2.2. 스택의 주요 연산 및 시간 복잡도

스택의 모든 핵심 연산은 스택의 맨 위에서 이루어지므로, 일반적으로 `O(1)`의 시간 복잡도를 가집니다.

| 연산 | 설명 | 시간 복잡도 |
| :--- | :--- | :--- |
| **Push** | 스택의 맨 위에 새로운 요소를 추가합니다. | `O(1)` |
| **Pop** | 스택의 맨 위 요소를 제거하고 그 값을 반환합니다. 스택이 비어있으면 오류가 발생할 수 있습니다. | `O(1)` |
| **Peek (Top)** | 스택의 맨 위 요소를 제거하지 않고 그 값을 반환합니다. 스택이 비어있으면 오류가 발생할 수 있습니다. | `O(1)` |
| **isEmpty** | 스택이 비어있는지 여부를 확인합니다. | `O(1)` |
| **Size** | 스택에 현재 저장된 요소의 개수를 반환합니다. | `O(1)` |

#### 2.2.3. 파이썬을 이용한 스택 구현

파이썬에서 스택을 구현하는 가장 일반적인 방법은 내장 `list`를 사용하는 것입니다. `append()` 메서드는 `Push` 연산에, `pop()` 메서드는 `Pop` 연산에 해당합니다.

```python
class Stack:
    """파이썬 리스트를 기반으로 한 스택 구현."""
    def __init__(self):
        self.items = []

    def push(self, item):
        """스택의 맨 위에 요소를 추가합니다."""
        self.items.append(item)

    def pop(self):
        """스택의 맨 위 요소를 제거하고 반환합니다. 스택이 비어있으면 IndexError를 발생시킵니다."""
        if self.is_empty():
            raise IndexError("pop from empty stack")
        return self.items.pop()

    def peek(self):
        """스택의 맨 위 요소를 제거하지 않고 반환합니다. 스택이 비어있으면 IndexError를 발생시킵니다."""
        if self.is_empty():
            raise IndexError("peek from empty stack")
        return self.items[-1]

    def is_empty(self):
        """스택이 비어있는지 여부를 반환합니다."""
        return len(self.items) == 0

    def size(self):
        """스택에 있는 요소의 개수를 반환합니다."""
        return len(self.items)

# 예시 사용법
# my_stack = Stack()
# my_stack.push(10)
# my_stack.push(20)
# print(f"스택의 맨 위: {my_stack.peek()}") # 출력: 스택의 맨 위: 20
# print(f"제거된 요소: {my_stack.pop()}")  # 출력: 제거된 요소: 20
# print(f"현재 스택 크기: {my_stack.size()}") # 출력: 현재 스택 크기: 1
# print(f"스택이 비어있는가?: {my_stack.is_empty()}") # 출력: 스택이 비어있는가?: False
# my_stack.pop()
# print(f"스택이 비어있는가?: {my_stack.is_empty()}") # 출력: 스택이 비어있는가?: True
# # my_stack.pop() # IndexError: pop from empty stack
```

- **참고: `collections.deque`를 이용한 스택 구현**
파이썬의 `list`는 동적 배열이므로 `append()`와 `pop()`은 효율적이지만, `list.insert(0, item)`나 `list.pop(0)`처럼 리스트의 맨 앞에서 삽입/삭제하는 연산은 `O(n)`의 시간 복잡도를 가집니다. 스택은 항상 맨 끝에서만 작업하므로 `list`로 구현해도 성능 문제가 없습니다. 하지만 양쪽 끝에서의 빠른 삽입/삭제가 필요한 경우 (예: 큐 구현 시), `collections` 모듈의 `deque` (double-ended queue)가 더 효율적입니다. `deque`는 양쪽 끝에서 `O(1)` 연산을 보장합니다.

#### 2.2.4. 스택의 다양한 활용 사례

스택의 LIFO 특성은 다양한 컴퓨터 과학 문제와 시스템에서 유용하게 활용됩니다.

-   **괄호 매칭 (Parenthesis Matching):**
    -   수식이나 코드에서 괄호(`()`, `{}`, `[]`)의 열림과 닫힘이 올바르게 짝을 이루는지 검사할 때 사용됩니다.
    -   열린 괄호가 나오면 스택에 `Push`하고, 닫힌 괄호가 나오면 스택의 맨 위에서 짝이 맞는 열린 괄호를 `Pop`하여 비교합니다. 짝이 맞지 않거나 스택이 비어있는데 닫힌 괄호가 나오면 오류입니다.
-   **함수 호출 스택 (Call Stack):**
    -   프로그램이 함수를 호출할 때, 현재 함수의 실행 상태(지역 변수, 반환 주소 등)가 스택에 `Push`됩니다.
    -   함수 실행이 완료되면 스택의 맨 위에서 해당 함수의 상태를 `Pop`하여 이전 호출 지점으로 돌아갑니다. 재귀 함수 호출도 이 스택 원리를 따릅니다.
-   **깊이 우선 탐색 (DFS - Depth-First Search):**
    -   그래프나 트리를 탐색할 때, 현재 노드에서 갈 수 있는 가장 깊은 경로를 먼저 탐색하는 알고리즘입니다.
    -   방문할 노드를 스택에 `Push`하고, 스택에서 `Pop`하여 방문하는 방식으로 구현할 수 있습니다.
-   **실행 취소/다시 실행 (Undo/Redo) 기능:**
    -   텍스트 편집기나 그래픽 도구에서 사용자의 작업을 기록하고 되돌리는 기능에 스택이 활용됩니다.
    -   각 작업을 스택에 `Push`하고, '실행 취소' 시 스택에서 작업을 `Pop`하여 이전 상태로 되돌립니다. '다시 실행'을 위해서는 별도의 스택을 사용하여 취소된 작업을 저장합니다.
-   **수식 계산 (Postfix/Prefix Notation Evaluation):**
    -   후위 표기법(Postfix Notation, RPN)이나 전위 표기법(Prefix Notation)으로 표현된 수식을 계산할 때 스택이 사용됩니다.

#### 2.2.5. 스택의 장단점 및 고려사항

-   **장점:**
    -   데이터의 삽입과 삭제가 매우 빠릅니다 (`O(1)`).
    -   구현이 간단하고 직관적입니다.
    -   특정 순서(LIFO)로 데이터를 처리해야 하는 문제에 적합합니다.
-   **단점:**
    -   중간에 있는 요소에 직접 접근할 수 없습니다. 오직 맨 위 요소만 접근 가능합니다.
    -   스택의 크기가 제한될 수 있으며, 너무 많은 요소를 `Push`하면 **스택 오버플로우(Stack Overflow)**가 발생할 수 있습니다 (특히 재귀 호출이 깊어질 때).
-   **주의사항:**
    -   `pop()`이나 `peek()` 연산을 호출하기 전에 스택이 비어있는지 (`is_empty()`) 항상 확인하여 `IndexError`와 같은 런타임 오류를 방지해야 합니다.

#### 2.2.6. 스택 활용 문제 해결: 올바른 괄호 문자열 판별

주어진 문자열 `s`가 올바른 괄호 문자열인지 판별하는 함수를 작성하세요. 올바른 괄호 문자열은 다음 조건을 만족해야 합니다.

1.  열린 괄호는 같은 종류의 닫힌 괄호로 닫혀야 합니다.
2.  열린 괄호는 올바른 순서로 닫혀야 합니다.
3.  모든 닫힌 괄호에는 해당 열린 괄호가 있어야 합니다.

-   **전략:** 스택을 사용하여 열린 괄호를 추적합니다. 문자열을 순회하면서 열린 괄호(`(`, `{`, `[`)를 만나면 스택에 `Push`합니다. 닫힌 괄호(`, `}`, `]`)를 만나면 스택이 비어있는지 확인하고, 비어있지 않다면 스택의 맨 위 요소가 현재 닫힌 괄호와 짝이 맞는지 확인합니다. 짝이 맞으면 스택에서 `Pop`하고, 짝이 맞지 않거나 스택이 비어있으면 올바르지 않은 괄호 문자열입니다. 문자열 순회가 끝난 후 스택이 비어있으면 올바른 괄호 문자열입니다.
-   **복잡도:** 시간 `O(n)` (문자열을 한 번 순회), 공간 `O(n)` (최악의 경우 모든 괄호가 열린 괄호일 때 스택에 저장)

```python
def is_valid_parentheses(s: str) -> bool:
    """주어진 문자열이 올바른 괄호 문자열인지 판별합니다."""
    stack = []
    # 괄호 짝을 매핑하는 딕셔너리
    mapping = {")": "(", "}": "{", "]": "["}

    for char in s:
        if char in mapping.values(): # 열린 괄호인 경우
            stack.append(char)
        elif char in mapping.keys(): # 닫힌 괄호인 경우
            # 스택이 비어있거나 짝이 맞지 않으면 False
            if not stack or mapping[char] != stack.pop():
                return False
        # 괄호가 아닌 다른 문자는 무시 (문제 조건에 따라 처리 방식 변경 가능)

    # 모든 문자를 처리한 후 스택이 비어있으면 올바른 괄호 문자열
    return not stack

# 예시

# print(is_valid_parentheses("([{}])")) # True
# print(is_valid_parentheses("(]"))    # False
# print(is_valid_parentheses("({[})")) # False
# print(is_valid_parentheses("{"))     # False
# print(is_valid_parentheses(""))      # True
```

### 2.3. 큐 (Queue)

큐는 스택과 마찬가지로 데이터를 일시적으로 저장하는 데 사용되는 선형 자료구조입니다. 스택이 LIFO(Last-In, First-Out) 원칙을 따르는 반면, 큐는 **가장 먼저 들어온 요소가 가장 먼저 나가는 (First-In, First-Out, FIFO)** 원칙을 따릅니다. 이는 현실 세계의 '줄 서기'와 매우 유사합니다.

#### 2.3.1. FIFO (First-In, First-Out) 원리 및 개념

-   **개념:** 큐는 한쪽 끝(rear 또는 tail)에서는 데이터가 추가되고, 다른 쪽 끝(front 또는 head)에서는 데이터가 제거되는 구조를 가집니다. 데이터가 들어오는 곳을 '입구', 나가는 곳을 '출구'라고 생각할 수 있습니다.
-   **비유:**
    -   **은행 대기열:** 먼저 온 고객이 먼저 서비스를 받습니다.
    -   **프린터 인쇄 대기열:** 먼저 요청된 문서가 먼저 인쇄됩니다.

#### 2.3.2. 큐의 주요 연산 및 시간 복잡도

큐의 모든 핵심 연산은 양쪽 끝에서 이루어지므로, 일반적으로 `O(1)`의 시간 복잡도를 가집니다.

| 연산 | 설명 | 시간 복잡도 |
| :--- | :--- | :--- |
| **Enqueue (Put)** | 큐의 뒤(rear)에 새로운 요소를 추가합니다. | `O(1)` |
| **Dequeue (Get)** | 큐의 앞(front)에서 요소를 제거하고 그 값을 반환합니다. 큐가 비어있으면 오류가 발생할 수 있습니다. | `O(1)` |
| **Peek (Front)** | 큐의 맨 앞 요소를 제거하지 않고 그 값을 반환합니다. 큐가 비어있으면 오류가 발생할 수 있습니다. | `O(1)` |
| **isEmpty** | 큐가 비어있는지 여부를 확인합니다. | `O(1)` |
| **Size** | 큐에 현재 저장된 요소의 개수를 반환합니다. | `O(1)` |

#### 2.3.3. 파이썬을 이용한 큐 구현: `collections.deque`의 활용

파이썬에서 큐를 구현할 때 내장 `list`를 사용하는 것은 효율적이지 않습니다. `list.append()`는 `O(1)`이지만, `list.pop(0)` (맨 앞 요소 제거)는 나머지 모든 요소를 한 칸씩 앞으로 당겨야 하므로 `O(n)`의 시간 복잡도를 가집니다. 이는 큐의 핵심 연산인 `Dequeue`에 치명적입니다.

따라서 파이썬에서는 `collections` 모듈의 `deque` (double-ended queue)를 사용하여 큐를 구현하는 것이 가장 효율적입니다. `deque`는 양쪽 끝에서의 삽입(`append`, `appendleft`)과 삭제(`pop`, `popleft`)를 모두 `O(1)` 시간 복잡도로 지원합니다.

```python
from collections import deque

class Queue:
    """collections.deque를 기반으로 한 큐 구현."""
    def __init__(self):
        self.items = deque()

    def enqueue(self, item):
        """큐의 뒤에 요소를 추가합니다."""
        self.items.append(item)

    def dequeue(self):
        """큐의 앞에서 요소를 제거하고 반환합니다. 큐가 비어있으면 IndexError를 발생시킵니다."""
        if self.is_empty():
            raise IndexError("dequeue from empty queue")
        return self.items.popleft()

    def peek(self):
        """큐의 맨 앞 요소를 제거하지 않고 반환합니다. 큐가 비어있으면 IndexError를 발생시킵니다."""
        if self.is_empty():
            raise IndexError("peek from empty queue")
        return self.items[0]

    def is_empty(self):
        """큐가 비어있는지 여부를 반환합니다."""
        return len(self.items) == 0

    def size(self):
        """큐에 있는 요소의 개수를 반환합니다."""
        return len(self.items)

# 예시 사용법
# my_queue = Queue()
# my_queue.enqueue(10)
# my_queue.enqueue(20)
# print(f"큐의 맨 앞: {my_queue.peek()}")   # 출력: 큐의 맨 앞: 10
# print(f"제거된 요소: {my_queue.dequeue()}") # 출력: 제거된 요소: 10
# print(f"현재 큐 크기: {my_queue.size()}")   # 출력: 현재 큐 크기: 1
```

#### 2.3.4. 큐의 다양한 활용 사례

큐의 FIFO 특성은 순서가 중요한 다양한 컴퓨터 과학 문제와 시스템에서 활용됩니다.

-   **너비 우선 탐색 (BFS - Breadth-First Search):**
    -   그래프나 트리를 탐색할 때, 현재 노드에서 인접한 모든 노드를 먼저 방문한 후 다음 레벨의 노드를 방문하는 알고리즘입니다.
    -   방문할 노드를 큐에 `Enqueue`하고, 큐에서 `Dequeue`하여 방문하는 방식으로 구현됩니다. 최단 경로를 찾을 때 유용합니다.
-   **작업 스케줄링 (Task Scheduling):**
    -   운영체제에서 CPU가 처리할 프로세스들을 관리하거나, 프린터, 네트워크 요청 등 공유 자원에 대한 접근 순서를 관리할 때 큐가 사용됩니다.
    -   먼저 요청된 작업이 먼저 처리되는 '선입선출' 방식에 적합합니다.
-   **버퍼 (Buffer) 구현:**
    -   데이터를 임시로 저장하는 공간으로, 생산자와 소비자 간의 속도 차이를 완충하는 역할을 합니다.
    -   예를 들어, 스트리밍 비디오 플레이어는 데이터를 버퍼에 저장하고, 재생 속도와 네트워크 속도 차이를 조절합니다.
-   **캐시 (Cache) 관리:**
    -   LRU(Least Recently Used) 캐시와 같은 알고리즘에서, 가장 오래된(가장 먼저 들어온) 항목을 제거할 때 큐의 원리가 활용될 수 있습니다.

#### 2.3.5. 큐의 변형 구조

큐의 기본 원리에서 파생된 다양한 변형들이 존재하며, 특정 요구사항에 맞춰 사용됩니다.

-   **우선순위 큐 (Priority Queue):**
    -   일반 큐와 달리, 요소들이 우선순위를 가지고 있으며, 가장 높은 우선순위의 요소가 먼저 제거됩니다.
    -   주로 힙(Heap) 자료구조를 사용하여 구현됩니다. (예: 다익스트라 알고리즘, 최소 신장 트리 알고리즘)
-   **덱 (Deque, Double-Ended Queue):**
    -   'Double-Ended Queue'의 줄임말로, 양쪽 끝(앞과 뒤)에서 모두 삽입과 삭제가 가능한 큐입니다.
    -   파이썬의 `collections.deque`가 대표적인 예시이며, 스택과 큐의 기능을 모두 수행할 수 있습니다.
-   **원형 큐 (Circular Queue):**
    -   배열을 사용하여 큐를 구현할 때, 배열의 끝에 도달하면 다시 처음으로 돌아가 공간을 재활용하는 방식입니다.
    -   메모리 효율성을 높이고 오버플로우/언더플로우 문제를 효과적으로 관리할 수 있습니다.

#### 2.3.6. 스택과 큐 비교

| 특징 | 스택 (Stack) | 큐 (Queue) |
| :--- | :--- | :--- |
| **원칙** | LIFO (Last-In, First-Out) | FIFO (First-In, First-Out) |
| **삽입** | Push (맨 위) | Enqueue (맨 뒤) |
| **삭제** | Pop (맨 위) | Dequeue (맨 앞) |
| **활용** | 함수 호출 스택, 괄호 매칭, DFS, 실행 취소/다시 실행 | 작업 스케줄링, BFS, 버퍼, 캐시 |

#### 2.3.7. 큐 활용 문제 해결: 이진 트리 레벨 순서 탐색 (BFS)

주어진 이진 트리를 레벨 순서(Level Order)로 탐색하여 각 레벨의 노드 값을 리스트에 담아 반환하는 함수를 작성하세요. (BFS 활용)

-   **전략:** 큐를 사용하여 트리의 노드를 레벨별로 탐색합니다. 먼저 루트 노드를 큐에 넣고, 큐가 빌 때까지 다음 과정을 반복합니다. 큐에서 노드를 하나 꺼내고, 해당 노드의 값을 결과 리스트에 추가합니다. 그 후, 꺼낸 노드의 왼쪽 자식과 오른쪽 자식이 존재하면 순서대로 큐에 넣습니다. 이 과정을 통해 큐에는 항상 현재 레벨의 노드들이 먼저 들어가고, 다음 레벨의 노드들이 그 뒤에 추가되어 레벨 순서 탐색이 가능해집니다.
-   **복잡도:** 시간 `O(N)` (모든 노드를 한 번씩 방문), 공간 `O(W)` (최대 너비 `W`만큼 큐에 노드 저장)

```python
from collections import deque

# 트리 노드 정의 (문제 해결을 위한 간단한 클래스)
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def level_order_traversal(root: TreeNode) -> list[list[int]]:
    """이진 트리를 레벨 순서로 탐색하여 각 레벨의 노드 값을 반환합니다."""
    if not root:
        return []

    result = []
    queue = deque([root]) # 큐 초기화: 루트 노드를 넣음

    while queue:
        level_size = len(queue) # 현재 레벨의 노드 수
        current_level_nodes = []

        for _ in range(level_size):
            node = queue.popleft() # 큐에서 노드를 하나 꺼냄
            current_level_nodes.append(node.val) # 현재 레벨 리스트에 값 추가

            # 왼쪽 자식이 있으면 큐에 추가
            if node.left:
                queue.append(node.left)
            # 오른쪽 자식이 있으면 큐에 추가
            if node.right:
                queue.append(node.right)
        
        result.append(current_level_nodes) # 현재 레벨의 모든 노드 처리 후 결과에 추가

    return result

# 예시 트리 생성:
#       3
#      / \
#     9  20
#       /  \
#      15   7
# root = TreeNode(3)
# root.left = TreeNode(9)
# root.right = TreeNode(20)
# root.right.left = TreeNode(15)
# root.right.right = TreeNode(7)

# print(level_order_traversal(root)) # 출력: [[3], [9, 20], [15, 7]]
```

### 2.4. 링크드 리스트 (Linked List)

링크드 리스트는 데이터를 '노드(Node)' 단위로 저장하며, 각 노드가 다음 노드의 주소를 가리키는 방식으로 연결된 선형 자료구조입니다. 배열과 달리 요소들이 메모리상에 연속적으로 위치하지 않아도 되므로, 동적인 데이터 관리에 유연성을 제공합니다.

#### 2.4.1. 개념 및 배열과의 근본적인 차이점

-   **개념:**
    -   링크드 리스트는 일련의 **노드(Node)**들로 구성됩니다. 각 노드는 최소한 두 부분으로 나뉩니다:
        -   **데이터(Data):** 노드가 저장하는 실제 값.
        -   **포인터(Pointer) 또는 참조(Reference):** 다음 노드의 메모리 주소를 가리킵니다. (마지막 노드는 `None`을 가리킴)
    -   리스트의 시작은 항상 **헤드(Head)** 노드가 가리키며, 헤드를 통해 전체 리스트에 접근할 수 있습니다.

-   **배열과의 근본적인 차이점:**
    | 특징 | 배열 (Array) | 링크드 리스트 (Linked List) |
    | :--- | :--- | :--- |
    | **메모리 할당** | 연속적인 메모리 공간 | 비연속적인 메모리 공간 (각 노드가 독립적으로 할당) |
    | **크기** | 고정 (동적 배열은 재할당 필요) | 동적 (필요에 따라 노드 추가/삭제) |
    | **삽입/삭제** | `O(n)` (원소 이동 필요) | `O(1)` (연결만 변경, 단, 탐색 시간 제외) |
    | **접근 (Random Access)** | `O(1)` (인덱스 기반 직접 접근) | `O(n)` (순차 탐색 필요) |
    | **메모리 오버헤드** | 낮음 (데이터만 저장) | 높음 (데이터 + 포인터 저장) |
    | **캐시 효율성** | 높음 (데이터가 밀집) | 낮음 (데이터가 분산) |

#### 2.4.2. 단일 링크드 리스트 (Singly Linked List)

각 노드가 데이터와 다음 노드를 가리키는 하나의 포인터(`next`)를 가집니다. 가장 기본적인 형태의 링크드 리스트입니다.

##### 2.4.2.1. 노드 구조 및 기본 연산

-   **노드 (Node):**
    ```python
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None # 다음 노드를 가리키는 포인터
    ```
-   **기본 연산의 시간 복잡도:**
    | 연산 | 설명 | 시간 복잡도 |
    | :--- | :--- | :--- |
    | **탐색 (Search)** | 특정 값을 가진 노드를 찾기 위해 헤드부터 순차적으로 탐색합니다. | `O(n)` |
    | **맨 앞 삽입 (Prepend)** | 헤드 노드를 변경하여 새로운 노드를 맨 앞에 추가합니다. | `O(1)` |
    | **맨 뒤 삽입 (Append)** | 리스트의 끝까지 탐색한 후 새로운 노드를 추가합니다. | `O(n)` |
    | **중간 삽입 (Insert After)** | 특정 노드 뒤에 새로운 노드를 삽입합니다. (해당 노드를 찾은 후) | `O(1)` |
    | **맨 앞 삭제** | 헤드 노드를 다음 노드로 변경합니다. | `O(1)` |
    | **중간/맨 뒤 삭제** | 삭제할 노드를 찾고, 이전 노드의 `next` 포인터를 변경합니다. (해당 노드를 찾은 후) | `O(1)` |

##### 2.4.2.2. 파이썬 구현

```python
class Node:
    """단일 링크드 리스트의 노드 클래스."""
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    """단일 링크드 리스트 클래스."""
    def __init__(self):
        self.head = None # 리스트의 시작을 가리키는 헤드 포인터

    def append(self, data):
        """리스트의 맨 뒤에 노드를 추가합니다."""
        new_node = Node(data)
        if self.head is None:
            self.head = new_node
            return
        last_node = self.head
        while last_node.next: # 마지막 노드를 찾을 때까지 순회
            last_node = last_node.next
        last_node.next = new_node

    def prepend(self, data):
        """리스트의 맨 앞에 노드를 추가합니다."""
        new_node = Node(data)
        new_node.next = self.head # 새 노드가 기존 헤드를 가리키도록 함
        self.head = new_node      # 새 노드를 헤드로 설정

    def insert_after(self, prev_node_data, new_data):
        """특정 데이터 값을 가진 노드 뒤에 새 노드를 삽입합니다."""
        current = self.head
        while current and current.data != prev_node_data:
            current = current.next
        
        if current is None: # 이전 노드를 찾지 못한 경우
            print(f"Error: Node with data {prev_node_data} not found.")
            return

        new_node = Node(new_data)
        new_node.next = current.next
        current.next = new_node

    def delete_node(self, key):
        """주어진 키 값을 가진 노드를 삭제합니다."""
        current_node = self.head

        # 헤드 노드가 삭제 대상인 경우
        if current_node and current_node.data == key:
            self.head = current_node.next
            current_node = None # 노드 연결 해제
            return

        prev_node = None
        # 삭제할 노드를 찾을 때까지 순회
        while current_node and current_node.data != key:
            prev_node = current_node
            current_node = current_node.next

        if current_node is None: # 키를 찾지 못한 경우
            print(f"Error: Node with key {key} not found.")
            return

        # 이전 노드의 next 포인터를 삭제할 노드의 다음 노드로 연결
        prev_node.next = current_node.next
        current_node = None # 노드 연결 해제

    def search(self, key):
        """주어진 키 값을 가진 노드를 찾아 반환합니다."""
        current = self.head
        while current:
            if current.data == key:
                return current
            current = current.next
        return None # 찾지 못한 경우

    def print_list(self):
        """리스트의 모든 노드 데이터를 출력합니다."""
        current_node = self.head
        elements = []
        while current_node:
            elements.append(str(current_node.data))
            current_node = current_node.next
        print(" -> ".join(elements) + " -> None")

# 예시 사용법
# my_list = LinkedList()
# my_list.append(1)
# my_list.append(2)
# my_list.prepend(0)
# my_list.print_list() # 0 -> 1 -> 2 -> None
# my_list.insert_after(1, 1.5)
# my_list.print_list() # 0 -> 1 -> 1.5 -> 2 -> None
# my_list.delete_node(1)
# my_list.print_list() # 0 -> 1.5 -> 2 -> None
# found_node = my_list.search(2)
# if found_node: print(f"Found: {found_node.data}")
```

#### 2.4.3. 이중 링크드 리스트 (Doubly Linked List)

단일 링크드 리스트와 달리, 각 노드가 데이터와 함께 이전 노드(`prev`)와 다음 노드(`next`)를 가리키는 두 개의 포인터를 가집니다. 이로 인해 양방향 탐색이 가능해집니다.

##### 2.4.3.1. 개념 및 장점

-   **노드 (DoublyNode):**
    ```python
    class DoublyNode:
        def __init__(self, data):
            self.data = data
            self.next = None # 다음 노드를 가리키는 포인터
            self.prev = None # 이전 노드를 가리키는 포인터
    ```
-   **장점:**
    -   **양방향 탐색:** `head`에서 `tail` 방향으로, 또는 `tail`에서 `head` 방향으로 모두 탐색이 가능합니다. 특정 노드에서 앞뒤로 이동하기 편리합니다.
    -   **효율적인 삭제:** 특정 노드를 삭제할 때, 이전 노드를 쉽게 찾을 수 있으므로 단일 링크드 리스트보다 삭제 연산이 더 효율적입니다. (단일 링크드 리스트는 이전 노드를 찾기 위해 `O(n)` 탐색이 필요할 수 있음)
-   **단점:**
    -   각 노드에 포인터가 하나 더 추가되므로, 단일 링크드 리스트보다 메모리 사용량이 많습니다.
    -   삽입 및 삭제 시 포인터 업데이트가 더 복잡합니다 (두 개의 포인터를 관리해야 함).

##### 2.4.3.2. 파이썬 구현

```python
class DoublyNode:
    """이중 링크드 리스트의 노드 클래스."""
    def __init__(self, data):
        self.data = data
        self.next = None
        self.prev = None

class DoublyLinkedList:
    """이중 링크드 리스트 클래스."""
    def __init__(self):
        self.head = None
        self.tail = None # 이중 링크드 리스트는 tail 포인터를 유지하는 것이 일반적

    def append(self, data):
        """리스트의 맨 뒤에 노드를 추가합니다."""
        new_node = DoublyNode(data)
        if self.head is None: # 리스트가 비어있는 경우
            self.head = new_node
            self.tail = new_node
            return
        
        self.tail.next = new_node # 현재 꼬리 노드의 다음을 새 노드로 연결
        new_node.prev = self.tail  # 새 노드의 이전을 현재 꼬리 노드로 연결
        self.tail = new_node      # 꼬리 노드를 새 노드로 업데이트

    def prepend(self, data):
        """리스트의 맨 앞에 노드를 추가합니다."""
        new_node = DoublyNode(data)
        if self.head is None:
            self.head = new_node
            self.tail = new_node
            return
        
        new_node.next = self.head # 새 노드의 다음을 현재 헤드로 연결
        self.head.prev = new_node # 현재 헤드의 이전을 새 노드로 연결
        self.head = new_node      # 헤드 노드를 새 노드로 업데이트

    def delete_node(self, key):
        """주어진 키 값을 가진 노드를 삭제합니다."""
        current = self.head

        while current:
            if current.data == key:
                # 헤드 노드인 경우
                if current == self.head:
                    self.head = current.next
                    if self.head: # 새로운 헤드가 있다면 이전 포인터 해제
                        self.head.prev = None
                    else: # 리스트가 비게 되는 경우
                        self.tail = None
                # 꼬리 노드인 경우
                elif current == self.tail:
                    self.tail = current.prev
                    if self.tail: # 새로운 꼬리가 있다면 다음 포인터 해제
                        self.tail.next = None
                    else: # 리스트가 비게 되는 경우
                        self.head = None
                # 중간 노드인 경우
                else:
                    current.prev.next = current.next
                    current.next.prev = current.prev
                
                current.next = None # 삭제할 노드의 연결 해제
                current.prev = None
                return
            current = current.next
        print(f"Error: Node with key {key} not found.")

    def print_list_forward(self):
        """리스트를 앞에서 뒤로 출력합니다."""
        current_node = self.head
        elements = []
        while current_node:
            elements.append(str(current_node.data))
            current_node = current_node.next
        print(" <-> ".join(elements) + " <-> None")

    def print_list_backward(self):
        """리스트를 뒤에서 앞으로 출력합니다."""
        current_node = self.tail
        elements = []
        while current_node:
            elements.append(str(current_node.data))
            current_node = current_node.prev
        print("None <-> " + " <-> ".join(reversed(elements)))

```

#### 2.4.4. 링크드 리스트의 활용 사례

링크드 리스트는 데이터의 동적인 추가/삭제가 빈번하거나, 순차적인 접근이 주로 이루어지는 상황에서 유용하게 사용됩니다.

-   **음악 플레이리스트 / 웹 브라우저의 방문 기록:**
    -   이전 곡/다음 곡으로 이동하거나, 웹 페이지의 '뒤로 가기'/ '앞으로 가기' 기능을 구현할 때 이중 링크드 리스트가 적합합니다. 각 페이지/곡이 노드가 되고, 이전/다음 페이지/곡으로의 링크를 가집니다.
-   **LRU (Least Recently Used) 캐시 구현:**
    -   가장 최근에 사용된 항목을 빠르게 접근하고, 캐시가 가득 찼을 때 가장 오래된(가장 적게 사용된) 항목을 효율적으로 제거해야 하는 경우에 링크드 리스트와 해시 테이블을 조합하여 사용합니다.
-   **메모리 관리 (운영체제):**
    -   운영체제에서 사용 가능한 메모리 블록들을 관리할 때 링크드 리스트를 사용하여 할당 및 해제된 메모리 공간을 추적합니다.
-   **다항식 표현:**
    -   각 항(계수와 지수)을 노드로 표현하여 다항식을 링크드 리스트로 나타낼 수 있습니다. 항의 추가/삭제가 용이합니다.

#### 2.4.5. 성능 및 메모리 최적화 고려사항

-   **메모리 오버헤드:**
    -   각 노드가 데이터 외에 하나 이상의 포인터를 저장해야 하므로, 동일한 양의 데이터를 저장할 때 배열보다 더 많은 메모리를 사용합니다. 특히 작은 크기의 데이터를 많이 저장할 경우 이 오버헤드가 커집니다.
-   **캐시 비효율성:**
    -   링크드 리스트의 노드들은 메모리상에 연속적으로 배치되지 않고 흩어져 있을 수 있습니다. 이로 인해 CPU 캐시의 효율성이 떨어져, 순차 접근 시 배열보다 느릴 수 있습니다.
-   **적절한 선택:**
    -   **삽입/삭제가 빈번하고 데이터의 크기가 가변적일 때:** 링크드 리스트가 유리합니다.
    -   **인덱스를 통한 임의 접근이 잦고 데이터의 크기가 고정적일 때:** 배열이 더 적합합니다.

#### 2.4.6. 링크드 리스트 활용 문제 해결: 링크드 리스트 뒤집기

주어진 단일 링크드 리스트를 뒤집는 함수를 작성하세요. (예: `1 -> 2 -> 3 -> 4 -> None`을 `4 -> 3 -> 2 -> 1 -> None`으로 변경)

-   **전략 (반복적 방법):** 세 개의 포인터(`prev`, `current`, `next_node`)를 사용합니다. `current`는 현재 처리 중인 노드를 가리키고, `prev`는 `current`의 이전에 뒤집힌 부분을 가리키며, `next_node`는 `current`의 원래 다음 노드를 임시로 저장합니다. `current` 노드의 `next` 포인터를 `prev`로 변경하고, `prev`와 `current`를 한 칸씩 앞으로 이동시키는 과정을 리스트의 끝까지 반복합니다. 최종적으로 `prev`가 새로운 헤드가 됩니다.
-   **복잡도:** 시간 `O(n)` (리스트를 한 번 순회), 공간 `O(1)` (추가적인 공간 사용 없음)

```python
# Node 클래스는 2.4.2.2 섹션의 Node 클래스를 재사용합니다.
# class Node:
#     def __init__(self, data):
#         self.data = data
#         self.next = None

def reverse_linked_list(head: Node) -> Node:
    """단일 링크드 리스트를 뒤집습니다."""
    prev = None
    current = head

    while current:
        next_node = current.next # 1. 다음 노드를 임시 저장
        current.next = prev      # 2. 현재 노드의 next를 이전 노드로 변경 (뒤집기)
        prev = current           # 3. prev를 현재 노드로 이동
        current = next_node      # 4. current를 다음 노드로 이동

    return prev # 뒤집힌 리스트의 새로운 헤드
```
