## 1. 힙 (Heap) 및 우선순위 큐 (Priority Queue)

힙은 완전 이진 트리의 일종으로, 우선순위 큐를 구현하는 데 주로 사용되는 자료구조입니다. 부모 노드의 키가 자식 노드의 키보다 항상 크거나(최대 힙) 항상 작은(최소 힙) 특징을 가집니다.

### 1.1. 힙의 개념과 종류 (최대 힙, 최소 힙)

*   **개념:** 힙은 **완전 이진 트리(Complete Binary Tree)**의 한 종류로, 우선순위 큐를 구현하는 데 주로 사용되는 자료구조입니다. 논리적으로는 트리 구조이지만, 물리적으로는 **배열**을 사용하여 효율적으로 표현합니다.
    - **[참고]** 자료구조로서의 힙(Heap)은 동적 메모리 할당 영역을 의미하는 '힙 메모리(Heap Memory)'와는 다른 개념입니다. 이름은 같지만 우연의 일치이며, 서로 관련이 없습니다.

*   **힙의 두 가지 핵심 속성:**
    1.  **힙 속성 (Heap Property):** 부모 노드의 키가 자식 노드의 키보다 항상 크거나 같습니다(**최대 힙**), 또는 항상 작거나 같습니다(**최소 힙**). 이 속성에 의해 루트 노드는 항상 힙 내에서 가장 크거나 가장 작은 값을 가집니다.
    2.  **완전 이진 트리 속성 (Complete Binary Tree Property):** 마지막 레벨을 제외한 모든 레벨이 완전히 채워져 있고, 마지막 레벨은 왼쪽부터 채워져 있습니다. 이 속성 덕분에 배열을 사용한 효율적인 구현이 가능합니다.

*   **힙의 시각적 표현 (최소 힙):**
    ```
      (논리적 트리 구조)             (물리적 배열 구조, 1-based index)
            10                      [ 10, 15, 20, 17, 25, 30 ]
           /  \                     Index: 1   2   3     5   6
          15  20
         /  \  /
        17  25 30
    ```

#### 1.1.1. 배열을 이용한 힙의 부모/자식 관계

힙은 배열로 구현될 때, 특정 인덱스의 노드 `i`에 대해 부모와 자식 노드의 인덱스를 다음과 같이 간단한 수식으로 계산할 수 있습니다. (1-based 인덱싱이 수식이 더 깔끔하여 많이 사용됩니다.)

| 관계 | 1-based 인덱싱 | 0-based 인덱싱 (Python) |
| :--- | :--- | :--- |
| **부모 `i`의 왼쪽 자식** | `2 * i` | `2 * i + 1` |
| **부모 `i`의 오른쪽 자식**| `2 * i + 1` | `2 * i + 2` |
| **자식 `i`의 부모** | `i // 2` | `(i - 1) // 2` |

*   **종류:**
    *   **최대 힙 (Max Heap):** 부모 노드의 키가 자식 노드의 키보다 항상 크거나 같습니다. (루트가 가장 큰 값)
    *   **최소 힙 (Min Heap):** 부모 노드의 키가 자식 노드의 키보다 항상 작거나 같습니다. (루트가 가장 작은 값)

### 1.2. 힙의 주요 연산 (삽입, 삭제)

*   **삽입 (Insertion):** 새로운 요소를 힙의 마지막 위치(배열의 끝)에 추가한 후, 힙 속성을 만족할 때까지 부모 노드와 비교하여 위치를 위로 올립니다. 이 과정을 **Heapify-up** (또는 percolate up, bubble up)이라고 합니다. 시간 복잡도는 트리의 높이에 비례하여 `O(log n)`입니다.
    -   **삽입 과정 시각화 (최소 힙에 `8` 삽입):**
        ```
           1. 마지막에 삽입          2. 부모(15)와 교환         3. 부모(10)와 교환 (완료)

                10                     10                      8
               /  \                   /  \                    /  \
              15  20                 8   20                  10  20
             /  \  / \              / \  / \                / \  / \
            17  25 30  8          17  25 30 15            17  15 30 25
        ```

*   **삭제 (Deletion):** 힙에서는 보통 루트 노드(최대값 또는 최소값)를 삭제합니다. 루트를 제거한 후, 힙의 마지막 요소를 루트 위치로 옮기고, 힙 속성을 만족할 때까지 자식 노드와 비교하여 위치를 아래로 내립니다. 이 과정을 **Heapify-down** (또는 percolate down, bubble down)이라고 합니다. 시간 복잡도는 `O(log n)`입니다.
    -   **삭제 과정 시각화 (최소 힙에서 루트 `10` 삭제):**
        ```
           1. 루트(10) 제거         2. 마지막 노드(30)를      3. 더 작은 자식(15)과      더 작은 자식(17)과
              마지막 노드 준비         루트로 이동              교환                     교환 (완료)

                10                     30                      15                      15
               /  \                   /  \                    /  \                    /  \
              15  20                 15  20                  30  20                  17  20
             /                      /                       /   
            17  25                 17  25                  30  25
        ```

*   **힙 생성 (Build Heap):** `n`개의 요소로 힙을 처음 생성하는 데는 `O(n)`의 시간 복잡도가 소요됩니다. 이는 n개의 원소를 하나씩 삽입하는 `O(n log n)` 방식과 달리, 배열 전체를 두고 마지막 부모 노드부터 루트까지 거슬러 올라가며 `Heapify-down`을 적용하는 방식으로 최적화할 수 있기 때문입니다. 이 경우 대부분의 노드가 트리의 하단에 위치하여 연산 횟수가 적으므로, 전체 시간 복잡도는 선형 시간인 `O(n)`에 수렴합니다.

### 1.3. 힙의 파이썬 구현

#### 1.3.1. 직접 구현으로 이해하는 힙 (Min Heap)

힙의 동작 원리를 깊이 이해하기 위해, 파이썬 클래스로 최소 힙을 직접 구현해볼 수 있습니다. 이 코드는 `heapify-up`과 `heapify-down`이 실제로 어떻게 동작하는지 보여줍니다.

```python
class MinHeap:
    def __init__(self):
        # 0번 인덱스를 비워두어 인덱스 계산을 편리하게 함 (1-based indexing)
        self.heap = [0]

    def _swap(self, i, j):
        self.heap[i], self.heap[j] = self.heap[j], self.heap[i]

    def _heapify_up(self):
        current_idx = len(self.heap) - 1
        parent_idx = current_idx // 2
        while current_idx > 1 and self.heap[current_idx] < self.heap[parent_idx]:
            self._swap(current_idx, parent_idx)
            current_idx = parent_idx
            parent_idx = current_idx // 2

    def _heapify_down(self, idx):
        current_idx = idx
        while True:
            left_child_idx = current_idx * 2
            right_child_idx = current_idx * 2 + 1
            smallest_idx = current_idx

            if left_child_idx < len(self.heap) and self.heap[left_child_idx] < self.heap[smallest_idx]:
                smallest_idx = left_child_idx
            if right_child_idx < len(self.heap) and self.heap[right_child_idx] < self.heap[smallest_idx]:
                smallest_idx = right_child_idx

            if smallest_idx == current_idx:
                break
            self._swap(current_idx, smallest_idx)
            current_idx = smallest_idx

    def push(self, value):
        """힙에 원소를 추가합니다. (삽입)"""
        self.heap.append(value)
        self._heapify_up()

    def pop(self):
        """힙에서 최소값을 제거하고 반환합니다. (삭제)"""
        if len(self.heap) <= 1:
            return None
        min_value = self.heap[1]
        self.heap[1] = self.heap[-1]
        del self.heap[-1]
        self._heapify_down(1)
        return min_value

    def build_heap(self, arr):
        """O(n) 시간에 리스트로 힙을 구성합니다."""
        self.heap = [0] + arr
        last_parent_idx = (len(self.heap) - 1) // 2
        for i in range(last_parent_idx, 0, -1):
            self._heapify_down(i)

# # 예시

# heap.push(
# heap.push(1)
# heap.push(7)
# heap.push(2)
# print(heap.heap) # [0, 1, 2, 7, 
# print(heap.pop())  # 1
# print(heap.heap) # [0, 2,  7]
```

### 1.3.2. `heapq` 모듈 활용 (권장)

직접 구현은 학습에 도움이 되지만, 실제 코드에서는 파이썬이 제공하는 `heapq` 모듈을 사용하는 것이 성능과 안정성 면에서 훨씬 효율적입니다. `heapq`는 일반 리스트를 최소 힙처럼 다룰 수 있게 해주는 함수들의 모음입니다.

*   **최소 힙:** `heapq` 모듈은 기본적으로 최소 힙을 지원합니다.
*   **최대 힙:** 최대 힙은 각 원소에 음수 부호를 붙여 최소 힙에 저장하고, 값을 꺼낼 때 다시 부호를 바꾸는 방식으로 간단히 구현할 수 있습니다.
*   **`heapify`:** 기존 리스트를 `O(n)` 시간에 힙으로 변환합니다.

```python
import heapq

# 최소 힙
min_heap = []
heapq.heappush(min_heap, 
heapq.heappush(min_heap, 1)
heapq.heappush(min_heap, 7)
heapq.heappush(min_heap, 2)
print("Min Heap:", min_heap) # Min Heap: [1, 2, 7, 
print("Popped:", heapq.heappop(min_heap)) # Popped: 1

# 최대 힙 (음수 부호 활용)
max_heap = []
heapq.heappush(max_heap, -
heapq.heappush(max_heap, -1)
heapq.heappush(max_heap, -7)
heapq.heappush(max_heap, -2)
print("Max Heap (negated):", max_heap) # Max Heap (negated): [-7, - -2, -1]
print("Popped:", -heapq.heappop(max_heap)) # Popped: 7

# 리스트를 한 번에 힙으로 변환
data = [ 1, 7, 2, 5, 9]
heapq.heapify(data)
print("Heapified list:", data) # Heapified list: [1, 2, 7,  5, 9]
```

### 1.4. 우선순위 큐로서의 힙 활용

우선순위 큐는 요소들이 우선순위를 가지고, 가장 높은 우선순위의 요소가 먼저 제거되는 추상 자료형입니다. 힙은 우선순위 큐를 구현하는 가장 효율적인 방법 중 하나입니다. `heapq` 모듈은 최소 힙을 기반으로 우선순위 큐 기능을 제공하며, `O(log n)` 시간 복잡도로 원소를 추가하고 삭제(가장 우선순위 높은 원소)할 수 있습니다.

#### 1.4.1. 코드 예시: `heapq`로 우선순위 큐 사용하기

`heapq`에 튜플 `(우선순위, 데이터)`를 저장하면, 파이썬은 튜플의 첫 번째 요소인 우선순위를 기준으로 최소 힙을 구성합니다. 이를 통해 간단히 우선순위 큐를 사용할 수 있습니다.

```python
import heapq

# (우선순위, 작업) 형태의 튜플
tasks = [(3, '문서 작성'), (1, '버그 수정'), (2, '자료 조사')]
pq = []

for task in tasks:
    heapq.heappush(pq, task)

print("작업 목록 (우선순위 순):")
while pq:
    priority, task_name = heapq.heappop(pq)
    print(f"  - 우선순위 {priority}: {task_name}")
# 출력:
# 작업 목록 (우선순위 순):
#   - 우선순위 1: 버그 수정
#   - 우선순위 2: 자료 조사
#   - 우선순위 3: 문서 작성
```

*   **주요 활용 사례:**
    *   최단 경로 알고리즘 (다익스트라, A*)
    *   최소 신장 트리 알고리즘 (프림)
    *   허프만 코딩 (Huffman Coding)
    *   운영체제의 작업 스케줄링
    *   네트워크 트래픽 관리

### 1.5. 힙 정렬 (Heap Sort)

힙 정렬은 힙 자료구조를 활용한 `O(n log n)` 시간 복잡도의 효율적인 정렬 알고리즘입니다. 추가적인 저장 공간 없이 **제자리 정렬(In-place Sort)**이 가능하다는 장점이 있습니다.

힙 정렬은 크게 두 단계로 나뉩니다.

1.  **힙 구성 (Build Heap):** 주어진 배열을 최대 힙(Max Heap)으로 변환합니다. 이 과정은 `O(n)` 시간에 수행됩니다.
2.  **정렬 (Sorting Phase):** `O(n log n)` 시간에 수행됩니다.
    a. 힙의 루트(가장 큰 값)와 힙의 마지막 노드를 교환합니다.
    b. 이 교환으로 가장 큰 값이 배열의 맨 뒤에 위치하게 되어 정렬이 완료됩니다.
    c. 힙의 크기를 1 줄이고, 루트 노드에 대해 `heapify-down`을 수행하여 힙 속성을 복원합니다.
    d. 힙의 크기가 1이 될 때까지 이 과정을 반복합니다.

#### 1.5.1. 파이썬 구현

```python
def heapify_down(arr, n, i):
    """특정 노드를 루트로 하는 서브트리를 최대 힙으로 만듭니다."""
    largest = i      # 현재 서브트리의 루트
    left = 2 * i + 1   # 왼쪽 자식
    right = 2 * i + 2  # 오른쪽 자식

    # 왼쪽 자식이 존재하고, 루트보다 크면 largest 업데이트
    if left < n and arr[i] < arr[left]:
        largest = left

    # 오른쪽 자식이 존재하고, 현재 largest보다 크면 largest 업데이트
    if right < n and arr[largest] < arr[right]:
        largest = right

    # largest가 루트가 아니라면, 루트와 largest를 교환하고 재귀적으로 heapify
    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        heapify_down(arr, n, largest)

def heap_sort(arr):
    """주어진 배열을 힙 정렬합니다."""
    n = len(arr)

    # 1. 최대 힙 구성 (Build Max Heap)
    # 마지막 부모 노드부터 시작하여 역순으로 heapify_down 수행
    for i in range(n // 2 - 1, -1, -1):
        heapify_down(arr, n, i)

    # 2. 정렬 (Sorting Phase)
    # 힙에서 하나씩 요소를 추출하여 배열의 뒤부터 채움
    for i in range(n - 1, 0, -1):
        arr[i], arr[0] = arr[0], arr[i]  # 루트(최대값)와 현재 힙의 마지막 요소 교환
        heapify_down(arr, i, 0)  # 크기가 줄어든 힙에 대해 heapify_down 수행
    
    return arr

# 예시
# data = [12, 11, 13, 5, 6, 7]
# print("정렬된 배열:", heap_sort(data))
# # 출력: 정렬된 배열: [5, 6, 7, 11, 12, 13]
```

## 2. 해싱 (Hashing) 및 해시 테이블 (Hash Table)

해싱은 데이터를 효율적으로 저장하고 검색하기 위한 기법이며, 해시 테이블은 이를 구현한 자료구조입니다. 키-값 쌍을 저장하며, 평균적으로 `O(1)`의 시간 복잡도로 삽입, 삭제, 검색을 수행할 수 있어 매우 빠른 데이터 관리가 가능합니다.

### 2.1. 해싱의 개념과 원리

-   **해싱 (Hashing):** 임의의 크기를 가진 데이터(Key)를 고정된 크기의 값(해시 값 또는 해시 코드)으로 변환하는 과정입니다. 이 변환을 수행하는 함수를 **해시 함수(Hash Function)**라고 합니다.
-   **원리:** 키를 해시 함수에 넣어 해시 값을 얻고, 이 해시 값을 배열의 인덱스로 변환하여 데이터를 저장하거나 검색합니다. 이 덕분에 키 값을 통해 데이터가 저장된 위치를 즉시 계산할 수 있습니다.

#### 2.1.1. 좋은 해시 함수의 조건

효율적인 해시 테이블은 좋은 해시 함수에 크게 의존합니다.

-   **결정론적 (Deterministic):** 동일한 입력값에 대해서는 항상 동일한 해시 값을 반환해야 합니다.
-   **빠른 계산:** 해시 값 계산이 빨라야 전체 성능 저하를 막을 수 있습니다.
-   **균일한 분포 (Uniform Distribution):** 키들이 해시 테이블의 버킷에 최대한 균등하게 분배되어야 충돌을 줄일 수 있습니다. 특정 값에 치우치면 성능이 저하됩니다.
-   **눈사태 효과 (Avalanche Effect):** 입력값의 미세한 변경이 해시 값 전체에 큰 변화를 일으켜야 합니다. 이는 유사한 키들이 서로 다른 해시 값을 갖도록 보장하여 충돌을 방지합니다.

### 2.2. 해시 테이블의 구조와 동작

-   **구조:** 해시 테이블은 키-값 쌍을 저장하는 배열(버킷 또는 슬롯)로 구성됩니다. 각 버킷은 해시 함수의 결과인 **해시 값(Hash Value)**에 해당하는 인덱스에 위치합니다.
-   **동작:**
    1.  **삽입:** 키를 해시 함수에 넣어 해시 값을 얻고, 해당 해시 값을 인덱스로 변환하여 데이터를 저장합니다.
    2.  **검색:** 키를 해시 함수에 넣어 해시 값을 얻고, 해당 인덱스에서 값을 찾습니다.
    3.  **삭제:** 키를 해시 함수에 넣어 해시 값을 얻고, 해당 인덱스에서 값을 제거합니다.
-   **적재율 (Load Factor):** 해시 테이블에 저장된 데이터의 수와 버킷의 총 수의 비율입니다. 적재율이 너무 높아지면 충돌이 잦아져 성능이 저하되므로, 적절한 시점에 해시 테이블의 크기를 늘리는 **리사이징(resizing)**이 필요합니다.

### 2.3. 충돌 해결 전략 (Collision Resolution)

서로 다른 키가 동일한 해시 값을 생성하는 경우를 '충돌(Collision)'이라고 합니다. 충돌은 피할 수 없으므로, 이를 효과적으로 해결하는 전략이 필수적입니다.

-   **체이닝 (Chaining):** 동일한 해시 값을 가지는 모든 키-값 쌍을 해당 버킷에 연결된 **링크드 리스트(Linked List)**에 저장합니다. 삽입은 간단하지만, 한 버킷에 데이터가 몰리면 해당 버킷의 검색 성능이 저하될 수 있습니다.
    -   **시각화:**
        ```
        [Bucket 0] -> None
        [Bucket 1] -> [KeyA, ValA] -> [KeyC, ValC] -> None
        [Bucket 2] -> [KeyB, ValB] -> None
        ... 
        (hash(KeyA) % size = 1, hash(KeyC) % size = 1, hash(KeyB) % size = 2)
        ```

-   **개방 주소법 (Open Addressing):** 충돌이 발생하면 미리 정해진 규칙에 따라 다른 비어있는 버킷을 찾아 데이터를 저장합니다. 추가적인 저장 공간 없이 해시 테이블 내에서 충돌을 해결하지만, 특정 영역에 데이터가 몰리는 **군집화(Clustering)** 문제가 발생할 수 있습니다.
    -   **선형 탐사 (Linear Probing):** 충돌 시 다음 버킷을 순차적으로 탐사합니다. `(hash(key) + i) % table_size`
    -   **제곱 탐사 (Quadratic Probing):** 충돌 시 제곱만큼 떨어진 버킷을 탐사합니다. `(hash(key) + i^2) % table_size`
    -   **이중 해싱 (Double Hashing):** 두 번째 해시 함수를 사용하여 탐사 간격을 결정하여 군집화 문제를 완화합니다.
    -   **시각화 (선형 탐사):**
        ```
        [Bucket 0]: empty
        [Bucket 1]: [KeyA, ValA]  (hash(KeyA) % size = 1)
        [Bucket 2]: [KeyC, ValC]  (hash(KeyC) % size = 1, collision! -> move to 2)
        [Bucket 3]: [KeyB, ValB]  (hash(KeyB) % size = 2, collision! -> move to 3)
        ... 
        ```

### 2.4. 파이썬을 이용한 해시 테이블 직접 구현

파이썬의 내장 `dict` 외에, 체이닝 방식을 이용하여 해시 테이블을 직접 구현해볼 수 있습니다. 이를 통해 해시 테이블의 내부 동작을 더 깊이 이해할 수 있습니다.

-   **내장 `hash()` 함수 활용:** 파이썬은 객체에 대한 해시 값을 쉽게 얻을 수 있는 `hash()` 함수를 제공합니다. 이 함수는 정수, 문자열, 튜플 등 변경 불가능한(immutable) 객체에 대해 일관된 해시 값을 반환합니다.
-   **키 중복 처리:** 해시 테이블에서 키는 고유해야 합니다. 따라서 새로운 키-값 쌍을 삽입할 때 이미 동일한 키가 존재한다면, 기존 값을 새로운 값으로 덮어쓰는 방식으로 처리합니다.

```python
class HashTable:
    """
    체이닝(Chaining)을 이용한 기본적인 해시 테이블 구현.
    """
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(self.size)] # 체이닝을 위해 각 버킷을 리스트로 초기화

    def _hash_function(self, key):
        """내장 hash() 함수를 사용하여 해시 값을 계산하고, 테이블 크기로 나눈 나머지를 인덱스로 사용합니다."""
        return hash(key) % self.size

    def put(self, key, value):
        """
        키-값 쌍을 해시 테이블에 삽입하거나 업데이트합니다.
        키가 이미 존재하면 값을 덮어씁니다.
        """
        hash_index = self._hash_function(key)
        bucket = self.table[hash_index]

        # 키가 이미 버킷에 있는지 확인 (업데이트)
        for i, (existing_key, _) in enumerate(bucket):
            if existing_key == key:
                bucket[i] = (key, value) # 값 업데이트
                return
        
        # 새로운 키-값 쌍 추가
        bucket.append((key, value))

    def get(self, key):
        """
        주어진 키에 해당하는 값을 반환합니다. 키가 없으면 KeyError를 발생시킵니다.
        """
        hash_index = self._hash_function(key)
        bucket = self.table[hash_index]

        for existing_key, value in bucket:
            if existing_key == key:
                return value
        
        # 키를 찾지 못한 경우
        raise KeyError(f"Key not found: {key}")

    def delete(self, key):
        """
        주어진 키에 해당하는 키-값 쌍을 삭제합니다.
        """
        hash_index = self._hash_function(key)
        bucket = self.table[hash_index]

        for i, (existing_key, _) in enumerate(bucket):
            if existing_key == key:
                del bucket[i]
                return
        
        # 키를 찾지 못한 경우
        raise KeyError(f"Key not found: {key}")

    def __str__(self):
        """해시 테이블의 내용을 문자열로 표현합니다."""
        elements = []
        for i, bucket in enumerate(self.table):
            if bucket:
                elements.append(f"Bucket {i}: {bucket}")
        return "\n".join(elements)
```

### 2.5. 파이썬 딕셔너리(dict)와의 관계

파이썬의 딕셔너리(`dict`)는 고도로 최적화된 해시 테이블의 구현체입니다. 내부적으로는 **개방 주소법과 최적화된 탐사 기법**을 사용하여 효율적인 성능을 제공합니다. 우리가 직접 구현한 `HashTable` 클래스는 해시 테이블의 기본 원리를 이해하는 데 도움을 주지만, 실제 애플리케이션에서는 성능과 안정성이 검증된 파이썬의 내장 `dict`와 `set`을 사용하는 것이 좋습니다.

### 2.6. 해시 테이블의 시간 복잡도 및 활용 사례

-   **시간 복잡도:**
    -   **평균:** 삽입, 삭제, 검색 모두 `O(1)`
    -   **최악:** `O(n)` (모든 키가 동일한 해시 값을 가질 경우, 즉 해시 함수가 좋지 않거나 충돌 해결 전략이 비효율적일 때)
-   **활용 사례:**
    -   **데이터베이스 인덱싱:** 빠른 데이터 검색 및 접근을 위해 사용됩니다.
    -   **캐시 구현:** 웹 브라우저, 서버 등에서 자주 접근하는 데이터를 빠르게 찾기 위해 사용됩니다.
    -   **심볼 테이블 (컴파일러):** 변수 이름과 해당 변수의 정보를 매핑하는 데 사용됩니다.
    -   **중복 데이터 제거:** 집합(Set) 자료구조 구현에 활용되어 중복을 허용하지 않는 데이터를 효율적으로 관리합니다.
    -   **암호화:** 해시 함수는 데이터의 무결성을 검증하거나 비밀번호를 저장하는 등 암호화 분야에서 중요한 역할을 합니다.
    -   **분산 시스템의 데이터 분배:** 일관성 해싱(Consistent Hashing)과 같은 기법을 통해 데이터를 여러 서버에 효율적으로 분배하는 데 사용됩니다.

## 3. 트라이 (Trie, Prefix Tree)

트라이는 문자열을 저장하고 효율적으로 검색하기 위한 트리 형태의 자료구조입니다. 특히 접두사(Prefix)를 기반으로 한 검색에 매우 강력합니다.

### 3.1. 트라이의 개념과 구조

*   **개념:** 트라이는 문자열을 저장하고 효율적으로 검색하기 위한 트리 형태의 자료구조입니다. 특히 접두사(Prefix)를 기반으로 한 검색에 매우 강력합니다. 'Trie'라는 이름은 'Retrieval'에서 유래했습니다. 각 노드가 하나의 문자를 나타내며, 루트부터 특정 노드까지의 경로가 하나의 단어 또는 접두사를 나타냅니다.
*   **구조:**
    *   **TrieNode:** 트라이의 각 노드는 다음과 같은 요소를 가집니다.
        *   `children`: 자식 노드들을 저장하는 맵(딕셔너리) 또는 배열입니다. 키는 다음 문자를 나타내고, 값은 해당 문자에 해당하는 `TrieNode` 객체입니다. (예: 영어 알파벳의 경우 26개의 배열을 사용할 수 있지만, 파이썬에서는 딕셔너리가 더 유연합니다.)
        *   `is_end_of_word`: 현재 노드에서 끝나는 단어가 존재하는지 여부를 나타내는 불리언 플래그입니다. 이 플래그가 `True`이면 루트부터 현재 노드까지의 경로가 하나의 완전한 단어를 형성함을 의미합니다.
    *   루트 노드는 비어있는 문자열을 나타내며, 트라이의 시작점입니다.
*   **구조 시각화 (예: "ape", "apple", "apply" 저장)**:
    ``` 
        (root)
          |
          a
          |
          p
         / \
        e*  p
            |
            l
           / \
          e*  y*
    (*는 단어의 끝을 의미)
    ```
*   **장단점:**
    *   **장점:**
        *   **빠른 접두사 기반 검색:** 단어의 길이를 `L`이라 할 때, 검색, 삽입, 삭제 모두 `O(L)` 시간에 완료됩니다. 이는 해시 테이블의 `O(1)` 평균 시간 복잡도와 유사하지만, 접두사 검색이나 정렬된 순서로의 접근이 가능하다는 장점이 있습니다.
        *   **정렬된 순서 유지:** 트라이에 저장된 모든 단어는 사전순으로 정렬된 상태를 유지합니다.
        *   **공통 접두사 활용:** 공통 접두사를 가진 단어들은 트라이에서 경로를 공유하므로, 공간을 효율적으로 사용할 수 있습니다.
    *   **단점:**
        *   **공간 복잡도:** 트라이는 각 노드가 자식 노드에 대한 포인터를 모두 저장해야 하므로, 저장하는 문자열의 총 길이에 비해 많은 메모리를 사용할 수 있습니다. 특히 알파벳의 크기가 크고 공통 접두사가 적을 경우 공간 효율성이 떨어집니다. (최악의 경우 O(알파벳크기 * 총 노드 수)). 이는 해시 테이블보다 공간 효율이 떨어질 수 있는 주요 원인입니다.



### 3.2. 트라이의 주요 연산 (삽입, 검색, 접두사 검색, 삭제)

*   **삽입 (Insertion):** 단어를 구성하는 각 문자를 따라가며 노드를 생성하거나 이동합니다. 단어의 끝에 도달하면 해당 노드를 단어의 끝으로 표시합니다. 시간 복잡도는 단어의 길이에 비례하여 `O(L)` (L은 단어의 길이)입니다.
*   **검색 (Search):** 단어를 구성하는 각 문자를 따라가며 노드를 탐색합니다. 모든 문자를 성공적으로 따라가고 마지막 노드가 단어의 끝으로 표시되어 있다면 단어가 존재합니다. 시간 복잡도는 `O(L)`입니다.
*   **접두사 검색 (Prefix Search):** 특정 접두사를 구성하는 문자를 따라가며 노드를 탐색합니다. 접두사에 해당하는 노드를 찾으면, 해당 노드를 루트로 하는 서브트리에서 모든 단어를 찾습니다. 시간 복잡도는 `O(L + K)` (L은 접두사의 길이, K는 접두사를 가진 단어들의 총 길이)입니다.

#### 3.2.1. 삭제 (Deletion)

트라이에서 단어를 삭제하는 것은 단순히 노드를 제거하는 것보다 복잡합니다. 삭제할 단어가 다른 단어의 접두사이거나, 다른 단어가 삭제할 단어를 접두사로 사용하는 경우를 고려해야 합니다.

*   **핵심 아이디어:**
    1.  삭제할 단어의 끝 노드를 찾아 `is_end_of_word` 플래그를 `False`로 변경합니다.
    2.  이후, 해당 노드부터 루트 방향으로 거슬러 올라가면서, 더 이상 어떤 단어의 일부도 아닌 노드들을 제거합니다. 노드를 제거할 수 있는 조건은 다음과 같습니다.
        *   `is_end_of_word` 플래그가 `False`이고,
        *   자식 노드가 없는 경우.
*   **시간 복잡도:** 단어의 길이에 비례하여 `O(L)` (L은 단어의 길이)입니다.

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end_of_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for char in word:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.is_end_of_word = True

    def search(self, word: str) -> bool:
        node = self.root
        for char in word:
            if char not in node.children:
                return False
            node = node.children[char]
        return node.is_end_of_word

    def starts_with(self, prefix: str) -> bool:
        node = self.root
        for char in prefix:
            if char not in node.children:
                return False
            node = node.children[char]
        return True

    def _find_all_words_from_node(self, node, current_word, result):
        if node.is_end_of_word:
            result.append(current_word)
        for char, child_node in node.children.items():
            self._find_all_words_from_node(child_node, current_word + char, result)

    def get_all_words_with_prefix(self, prefix: str) -> list[str]:
        node = self.root
        for char in prefix:
            if char not in node.children:
                return []
            node = node.children[char]
        
        result = []
        self._find_all_words_from_node(node, prefix, result)
        return result

    def delete(self, word: str) -> bool:
        """
        트라이에서 단어를 삭제합니다.
        단어가 존재하고 성공적으로 삭제되면 True, 아니면 False를 반환합니다.
        """
        # 재귀적으로 삭제를 수행하는 헬퍼 함수
        def _delete_recursive(current_node, word_part, depth):
            if depth == len(word_part):
                # 단어의 끝에 도달했지만, 해당 단어가 존재하지 않으면 삭제할 수 없음
                if not current_node.is_end_of_word:
                    return False
                current_node.is_end_of_word = False # 단어의 끝 플래그 해제
                # 현재 노드가 다른 단어의 접두사가 아니고 자식도 없으면 제거 가능
                return len(current_node.children) == 0

            char = word_part[depth]
            child_node = current_node.children.get(char)

            if not child_node: # 삭제할 단어가 트라이에 없음
                return False

            # 재귀 호출: 다음 문자로 이동
            should_delete_current_node = _delete_recursive(child_node, word_part, depth + 1)

            # 자식 노드가 삭제되어야 한다면
            if should_delete_current_node:
                del current_node.children[char] # 자식 노드 제거
                # 현재 노드도 다른 단어의 끝이 아니고 자식도 없으면 제거 가능
                return not current_node.is_end_of_word and len(current_node.children) == 0
            return False # 자식 노드가 삭제되지 않았거나, 현재 노드를 삭제할 수 없음

        return _delete_recursive(self.root, word, 0)
```

### 3.3. 트라이의 활용 사례 (자동 완성, 사전, 스펠링 체크)

*   **자동 완성 (Autocomplete):** 검색창이나 메시지 입력 시 사용자가 입력하는 접두사를 기반으로 가능한 단어 목록을 실시간으로 추천하여 입력 효율을 높입니다.
*   **사전 (Dictionary) 및 맞춤법 검사기 (Spell Checker):** 대량의 단어를 저장하고, 특정 단어의 존재 여부를 빠르게 확인하거나, 오타를 감지하고 올바른 단어를 제안하는 데 사용됩니다.
*   **IP 라우팅:** IP 주소는 계층적인 구조를 가지므로, 트라이를 사용하여 IP 주소의 접두사를 기반으로 최적의 라우팅 경로를 빠르게 찾는 데 활용됩니다.
*   **데이터 압축:** 공통 접두사를 공유하는 문자열을 효율적으로 저장하여 공간을 절약할 수 있습니다.
*   **바이오인포매틱스:** DNA 서열 분석 등에서 패턴 매칭에 사용될 수 있습니다.

## 5. 세그먼트 트리 (Segment Tree)

세그먼트 트리는 배열의 특정 '구간(Segment)'에 대한 질의(Query)를 효율적으로 처리하기 위한 트리 기반 자료구조입니다. 구간 합, 구간 최솟값/최댓값 등 다양한 구간 쿼리에 사용됩니다.

### 5.1. 세그먼트 트리의 개념과 구조

*   **개념:** 세그먼트 트리는 배열의 특정 '구간(Segment)'에 대한 질의(Query)를 효율적으로 처리하기 위한 트리 기반 자료구조입니다. 이는 특히 배열의 요소가 자주 변경되는 상황에서 유용합니다.
*   **구조:** 세그먼트 트리는 주어진 배열을 이진 트리 형태로 분할하여 표현합니다. 각 노드는 원본 배열의 특정 구간에 대한 정보를 저장합니다.
    *   **루트 노드:** 전체 배열 구간(`[0, n-1]`)에 대한 정보를 가집니다.
    *   **내부 노드:** 자신의 자식 노드들이 나타내는 구간의 정보를 결합하여 저장합니다. (예: 왼쪽 자식의 합 + 오른쪽 자식의 합)
    *   **리프 노드:** 원본 배열의 개별 요소를 나타냅니다.
*   **구조 시각화 (배열 `[1, 3, 5, 7, 9, 11]`의 구간 합 트리):**
    ```
                [0-5] (36)
                /      \
            [0-2] (9)   [3-5] (27)
            /    \      /     \
        [0-1]( [2-2](5) [3-(16) [5-5](11)
        /   \
    [0-0](1) [1-1](3)
    ```
    *(각 노드는 [구간](구간합)을 의미)*

### 5.2. 세그먼트 트리의 연산 (구간 합, 구간 최솟값/최댓값)

세그먼트 트리의 모든 주요 연산은 트리의 높이에 비례하는 시간 복잡도를 가집니다. 트리의 높이는 `log n`이므로, 모든 연산은 `O(log n)`의 효율성을 보입니다.

*   **구축 (Build):** 원본 배열로부터 세그먼트 트리를 재귀적으로 생성합니다. 리프 노드부터 시작하여 부모 노드로 올라가면서 구간 정보를 결합합니다. 시간 복잡도는 `O(n)`입니다.
*   **업데이트 (Update):** 원본 배열의 특정 요소 값이 변경될 때, 해당 변경이 영향을 미치는 트리의 노드들을 루트부터 리프까지 찾아가면서 갱신합니다. 시간 복잡도는 `O(log n)`입니다.
*   **쿼리 (Query):** 주어진 쿼리 구간에 대해 트리를 탐색하여 필요한 정보를 수집합니다. 쿼리 구간이 노드의 구간과 완전히 일치하거나 겹치는 경우, 해당 노드의 정보를 활용하여 결과를 계산합니다. 시간 복잡도는 `O(log n)`입니다.

-   **쿼리 동작 방식 예시 (`query(1, `):**
    1.  **루트 (node=1, range=[0, 5]):** 쿼리 구간 `[1, `가 현재 노드 구간 `[0, 5]`에 부분적으로 겹치므로, 자식 노드로 탐색을 계속합니다.
    2.  **왼쪽 자식 (node=2, range=[0, 2]):** 쿼리 구간 `[1, `가 `[0, 2]`에 부분적으로 겹칩니다. 다시 자식으로 내려갑니다.
    3.  **오른쪽 자식 (node=3, range=[3, 5]):** 쿼리 구간 `[1, `가 `[3, 5]`에 부분적으로 겹칩니다. 다시 자식으로 내려갑니다.
      `node=2`의 자식들:
        -   `node= range=[0, 1]`: `[1, `와 부분적으로 겹침 -> 재귀.
        -   `node=5, range=[2, 2]`: `[1, `에 완전히 포함됨. **값 5를 반환.**
    5.  `node=3`의 자식들:
        -   `node=6, range=[3, `: `[1, `에 완전히 포함됨. **값 16을 반환.**
        -   `node=7, range=[5, 5]`: `[1, `와 겹치지 않음. 0을 반환.
    6.  `node=의 자식들:
        -   `node=8, range=[0, 0]`: `[1, `와 겹치지 않음. 0을 반환.
        -   `node=9, range=[1, 1]`: `[1, `에 완전히 포함됨. **값 3을 반환.**
    7.  최종적으로 각 부분에서 반환된 값들을 합산하여 `3 + 5 + 16 = 2가 결과가 됩니다.

### 5.3. 세그먼트 트리의 파이썬 구현 개요

```python
# 트리를 저장할 배열의 크기는 원본 배열 크기 `n`의 약 로 설정하는 것이 일반적입니다.
# 이는 완전 이진 트리의 특성상 노드 수가 `2 * 2^ceil(log2(n)) - 1`이 될 수 있고,
# 배열 인덱싱의 편의성을 고려한 넉넉한 크기입니다。
class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (* self.n) # 트리를 저장할 배열 초기화
        self._build(arr, 1, 0, self.n - 1) # 트리 구축 시작 (node_idx=1, range=[0, n-1])

    # 트리 구축 함수
    # arr: 원본 배열
    # node: 현재 노드의 인덱스 (트리 배열 내)
    # start, end: 현재 노드가 담당하는 구간 (원본 배열 기준)
    def _build(self, arr, node, start, end):
        if start == end: # 리프 노드인 경우
            self.tree[node] = arr[start]
        else:
            mid = (start + end) // 2
            self._build(arr, 2 * node, start, mid)
            self._build(arr, 2 * node + 1, mid + 1, end)
            self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    # 값 업데이트 함수
    def update(self, idx, val):
        self._update(1, 0, self.n - 1, idx, val)

    def _update(self, node, start, end, idx, val):
        if start == end:
            self.tree[node] = val
        else:
            mid = (start + end) // 2
            if start <= idx <= mid:
                self._update(2 * node, start, mid, idx, val)
            else:
                self._update(2 * node + 1, mid + 1, end, idx, val)
            self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    # 구간 쿼리 함수
    def query(self, l, r):
        return self._query(1, 0, self.n - 1, l, r)

    def _query(self, node, start, end, l, r):
        if r < start or end < l:
            return 0 # 쿼리 구간과 겹치지 않으면 0 반환
        if l <= start and end <= r:
            return self.tree[node] # 쿼리 구간이 현재 노드 구간을 완전히 포함하면 현재 노드 값 반환
        
        mid = (start + end) // 2
        p1 = self._query(2 * node, start, mid, l, r)
        p2 = self._query(2 * node + 1, mid + 1, end, l, r)
        return p1 + p2

# 예시
# arr = [1, 3, 5, 7, 9, 11]
# st = SegmentTree(arr)
# print(st.query(1, ) # 3 + 5 + 7 + 9 = 24
# st.update(2, 10) # arr[2]를 10으로 변경
# print(st.query(1, ) # 3 + 10 + 7 + 9 = 29
```

### 5.4. 활용 사례 (구간 쿼리 문제)

*   **구간 합/최솟값/최댓값:** 배열의 특정 구간에 대한 합, 최솟값, 최댓값 등을 빠르게 계산해야 할 때 가장 대표적으로 사용됩니다.
*   **데이터 변경이 잦은 배열:** 배열의 요소가 자주 변경되면서 구간 쿼리가 필요한 경우, 세그먼트 트리는 효율적인 솔루션을 제공합니다.
*   **게임 개발:** 게임 맵의 특정 영역에 대한 정보 조회, 캐릭터 능력치 관리, 충돌 감지 등 다양한 게임 로직에 활용될 수 있습니다.
*   **데이터베이스 시스템:** 특정 범위의 데이터를 빠르게 집계하거나 필터링하는 데 사용될 수 있습니다.
*   **경쟁 프로그래밍:** 다양한 구간 쿼리 문제(예: 구간 내 특정 값의 개수, 구간 내 K번째 작은 값 등)를 해결하는 데 필수적인 자료구조입니다。

### 5.5. 고급 기법: 지연 전파 (Lazy Propagation)

기본 세그먼트 트리는 단일 요소 업데이트에 효율적입니다. 하지만 특정 '구간' 전체에 값을 더하거나 변경하는 연산(Range Update)이 필요할 경우, 해당 구간의 모든 요소를 하나씩 업데이트하면 O(n log n)의 비효율적인 시간이 소요됩니다.

**지연 전파(Lazy Propagation)**는 이러한 구간 업데이트를 O(log n)으로 최적화하는 기법입니다. 아이디어는 노드의 값을 즉시 업데이트하지 않고, 변경 사항을 특정 노드에 '지연(lazy)'시켜 저장해두는 것입니다. 나중에 해당 노드나 그 자식 노드에 접근할 필요가 생겼을 때, 저장해 둔 변경 사항을 전파하여 적용합니다. 이 기법을 통해 구간 업데이트가 빈번한 문제도 효율적으로 해결할 수 있습니다.

## 6. 펜윅 트리 (Fenwick Tree, Binary Indexed Tree)

펜윅 트리(Fenwick Tree) 또는 이진 인덱스 트리(Binary Indexed Tree, BIT)는 배열의 **누적 합(Prefix Sum)**을 효율적으로 계산하고, 배열의 요소 값을 동적으로 업데이트하는 데 사용되는 자료구조입니다. 세그먼트 트리와 유사한 문제를 해결하지만, 구현이 더 간단하고 공간 효율성이 높다는 장점이 있습니다.

### 6.1. 펜윅 트리의 개념과 원리

*   **개념:** 펜윅 트리는 `O(n)`의 공간 복잡도를 가지며, 세그먼트 트리가 `O()` 또는 `O(2n)` 공간을 사용하는 것에 비해 공간 효율적입니다. 또한, 연산의 상수 인자가 작아 실제 수행 시간도 더 빠른 경향이 있습니다.
*   **원리:** 각 인덱스의 이진 표현에서 **가장 낮은 비트(Lowest Set Bit, LSB)**를 이용하여 부모-자식 관계와 같은 계층 구조를 형성하고, 이를 통해 구간 합을 계산하거나 값을 업데이트합니다.
    *   **가장 낮은 비트(LSB) 계산:** 인덱스 `i`의 LSB는 `i & -i`로 간단히 계산할 수 있습니다. 컴퓨터에서 음수는 2의 보수(`~i + 1`)로 표현되는데, 이 원리를 이용하면 `i & -i` 연산은 `i`의 이진 표현에서 가장 오른쪽에 있는 1비트만 남기는 효과를 가집니다. 예를 들어, `i=6 (0110)`일 때, `-i`는 `1010`이 되고, `0110 & 1010 = 0010` (2) 이므로 LSB는 2가 됩니다.
*   **구조 시각화:** 펜윅 트리의 각 인덱스 `i`는 특정 구간의 합을 담당합니다. `tree[i]`는 원본 배열에서 `i - (i & -i) + 1`부터 `i`까지의 합을 저장합니다. (1-based index 기준)

    -   `tree[1]` = `arr[1]`
    -   `tree[2]` = `arr[1]` ~ `arr[2]`
    -   `tree[3]` = `arr[3]`
    -   `tree[` = `arr[1]` ~ `arr[`
    -   `tree[5]` = `arr[5]`
    -   `tree[6]` = `arr[5]` ~ `arr[6]`
    -   `tree[7]` = `arr[7]`
    -   `tree[8]` = `arr[1]` ~ `arr[8]`

    ```
    (1-based index 기준)
    tree[8] ------------------------------------ (range: 1~8)
          |
    tree[ -----------       tree[6] ---       (range: 1~ 5~6)
          |             |           |
    tree[2] ---   tree[3]   tree[5]   tree[7]   (range: 1~2, 3~3, 5~5, 7~7)
          |
    tree[1]
    ```

### 6.2. 펜윅 트리의 연산 (누적 합, 값 업데이트)

*   **값 업데이트 (Update):** `update(idx, val)`는 `arr[idx]`의 값을 `val`만큼 변경하고, 이에 영향을 받는 펜윅 트리 노드들을 `O(log n)` 시간에 갱신합니다. 이 연산은 `idx`에서 시작하여 `idx += (idx & -idx)`를 반복하며 부모 노드 방향으로 올라가면서 값을 업데이트합니다.
*   **누적 합 (Prefix Sum):** `query(idx)`는 `arr[0]`부터 `arr[idx]`까지의 합을 `O(log n)` 시간에 계산합니다. 이 연산은 `idx`에서 시작하여 `idx -= (idx & -idx)`를 반복하며 왼쪽(또는 하위) 구간들의 합을 더해 나갑니다.

-   **쿼리 동작 방식 예시 (`query(7)`):**
    인덱스 7까지의 누적 합(1~7의 합)을 구하는 과정은 다음과 같습니다.
    1.  `idx = 7 (0111)`: `sum += tree[7]`. 다음 인덱스는 `7 - (7 & -7)` = `7 - 1` = `6`.
    2.  `idx = 6 (0110)`: `sum += tree[6]`. 다음 인덱스는 `6 - (6 & -6)` = `6 - 2` = `.
    3.  `idx = (0100)`: `sum += tree[`. 다음 인덱스는 `- (& -` = `-  = `0`.
      `idx`가 0이 되어 반복이 종료됩니다. 최종 결과는 `tree[7] + tree[6] + tree[`가 됩니다.

### 6.3. 펜윅 트리의 파이썬 구현 개요

```python
class FenwickTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1) # 1-based indexing을 위해 크기를 n+1로 설정

    # 배열의 특정 인덱스(idx)에 값(val)을 더하고, 펜윅 트리를 업데이트합니다。
    # 시간 복잡도: O(log n)
    def update(self, idx, val):
        idx += 1 # 0-based index를 1-based index로 변환
        while idx <= self.n:
            self.tree[idx] += val # 현재 노드에 값 추가
            idx += (idx & -idx) # 다음 업데이트할 노드로 이동 (가장 낮은 비트를 더함)

    # 배열의 0부터 특정 인덱스(idx)까지의 누적 합을 반환합니다。
    # 시간 복잡도: O(log n)
    def query(self, idx):
        idx += 1 # 0-based index를 1-based index로 변환
        s = 0
        while idx > 0:
            s += self.tree[idx] # 현재 노드의 값(누적 합)을 더함
            idx -= (idx & -idx) # 다음 쿼리할 노드로 이동 (가장 낮은 비트를 뺌)
        return s

    # 배열의 특정 구간(l부터 r까지)의 합을 반환합니다。
    # query(r) - query(l-1)을 통해 구간 합을 계산합니다。
    # 시간 복잡도: O(log n)
    def range_query(self, l, r):
        return self.query(r) - self.query(l - 1)

# ft = FenwickTree(len(arr))
# for i, val in enumerate(arr):

# print(ft.range_query(1, ) # arr[1]~arr[의 합 (3+5+7+9 = 2
# ft.update(2, 5) # arr[2]를 5만큼 증가 (원래 5였으므로 10이 됨)
# print(ft.query() # 1+3+10+7+9 = 30
```

### 6.4. 활용 사례 (구간 합, 빈도 계산)

*   **구간 합 쿼리:** 배열의 특정 구간 합을 빠르게 계산하고 업데이트해야 할 때 가장 효율적인 방법 중 하나입니다。
*   **빈도 계산:** 특정 값의 출현 빈도를 효율적으로 추적하고 쿼리할 때 사용됩니다. (예: 특정 범위 내의 숫자 개수)
*   **역전쌍 (Inversion Count):** 배열에서 역전쌍의 개수를 세는 문제와 같이, 순서가 중요한 문제에서 활용됩니다。
*   **동적 배열 문제:** 요소의 삽입/삭제가 빈번하게 일어나는 배열에서 구간 쿼리를 처리해야 할 때 유용합니다。

## 7. 희소 테이블 (Sparse Table)

희소 테이블은 배열의 특정 구간에 대한 질의(Query)를 `O(1)` 시간에 처리하기 위한 자료구조입니다. 주로 RMQ(Range Minimum Query) 문제와 같이 변경이 없는(정적) 배열에서 구간 쿼리가 빈번할 때 사용됩니다.

### 7.1. 희소 테이블의 개념과 원리

*   **개념:** 희소 테이블은 배열의 특정 구간에 대한 질의(Query)를 `O(1)` 시간에 처리하기 위한 자료구조입니다. 주로 RMQ(Range Minimum Query) 문제와 같이 **변경이 없는(정적) 배열**에서 구간 쿼리가 빈번할 때 사용됩니다. 이는 배열의 요소가 한 번 결정되면 변경되지 않는다는 가정을 전제로 합니다。
*   **원리:** 동적 계획법(DP)을 활용하여 미리 계산된 구간 정보를 저장하는 2차원 배열입니다. `st[i][j]`는 인덱스 `i`부터 시작하여 길이가 `2^j`인 구간(즉, `[i, i + 2^j - 1]`)에 대한 쿼리 결과(예: 최솟값)를 저장합니다. 모든 가능한 구간을 저장하는 대신, 길이가 2의 거듭제곱인 구간들에 대한 정보를 저장하여, 임의의 구간을 이들의 조합으로 표현합니다。
*   **구조 시각화 (`st[i][j]` = `arr[i]`부터 `2^j`개 원소의 최솟값):
    ```
    arr = [7, 2, 3, 0, 5, 10, 8, 1]

    j=0 (2^0=1개): st[i][0] = arr[i]
    j=1 (2^1=2개): st[0][1]=min(arr[0],arr[1])=2, st[1][1]=min(arr[1],arr[2])=2, ...
    j=2 (2^2=): st[0][2]=min(arr[0]..arr[3])=0, st[1][2]=min(arr[1]..arr[)=0, ...

    [st 테이블 예시]
          j=0  j=1  j=2  j=3
    i=0 | 7 |  2  |  0  |  0  |
    i=1 | 2 |  2  |  0  |  0  |
    i=2 | 3 |  0  |  0  |  1  |
    i=3 | 0 |  0  |  1  | ... |
    i=| 5 |  5  |  1  | ... |
    i=5 | 10|  8  | ... | ... |
    i=6 | 8 |  1  | ... | ... |
    i=7 | 1 | ... | ... | ... |
    ```

### 7.2. 희소 테이블의 구축 및 쿼리 (RMQ 문제)

*   **구축 (Build):** 희소 테이블을 구축하는 데 `O(n log n)` 시간이 소요됩니다。
    *   `st[i][0]`은 `arr[i]` 자체의 값입니다。
    *   `st[i][j]`는 `i`부터 `i + 2^j - 1`까지의 구간에 대한 쿼리 결과(예: 최솟값)를 저장합니다. 이는 `st[i][j-1]` (길이 `2^(j-1)`의 왼쪽 절반 구간)과 `st[i + 2^(j-1)][j-1]` (길이 `2^(j-1)`의 오른쪽 절반 구간)의 결과를 결합하여 계산됩니다. (RMQ 예시: `st[i][j] = min(st[i][j-1], st[i + (1 << (j-1))][j-1])`)
*   **쿼리 (Query):** 희소 테이블을 이용한 쿼리는 `O(1)` 시간에 수행됩니다。
    *   구간 `[L, R]`에 대한 쿼리는 먼저 `k = floor(log2(R - L + 1))` 값을 계산합니다. 이 `k`는 쿼리 구간 `[L, R]`을 완전히 덮는 가장 큰 `2^k` 길이의 구간을 찾기 위함입니다。
    *   쿼리 결과는 `min(st[L][k], st[R - (1 << k) + 1][k])`로 계산됩니다. 이는 쿼리 구간을 두 개의 **겹치는** `2^k` 길이 구간으로 나누어 처리하는 방식입니다。

-   **`O(1)` 쿼리의 핵심 원리 (멱등성):**
    희소 테이블의 `O(1)` 쿼리는 두 구간을 겹치게 하여 전체 범위를 포함하는 아이디어에 기반합니다. 이 방법은 연산이 **멱등성(Idempotent)**을 가질 때만 유효합니다. 멱등성이란 연산을 여러 번 적용해도 결과가 같은 성질(예: `min(x, x) = x`)을 의미합니다. `min`, `max`, `GCD`(최대공약수) 등은 멱등성을 가지므로 희소 테이블로 `O(1)` 쿼리가 가능합니다. 하지만 `sum`과 같은 연산은 멱등성이 없으므로(`sum(x, x) != x`), 겹치는 구간의 합을 구하면 중복 계산이 발생하여 올바른 결과를 얻을 수 없습니다. 따라서 구간 합 문제에는 희소 테이블을 이 방식 그대로 적용할 수 없습니다.

```python
import math

class SparseTable:
    def __init__(self, arr):
        self.n = len(arr)
        self.log_table = [0] * (self.n + 1) # log_table[i] = floor(log2(i))
        for i in range(2, self.n + 1):
            self.log_table[i] = self.log_table[i // 2] + 1

        self.k = self.log_table[self.n] + 1 # log2(n)의 올림값
        self.st = [[0] * self.k for _ in range(self.n)] # Sparse Table

        # Sparse Table 구축 (Build)
        # st[i][j]는 arr[i]부터 arr[i + 2^j - 1]까지의 구간에 대한 최솟값
        for i in range(self.n):
            self.st[i][0] = arr[i] # 길이가 2^0 = 1인 구간 (자기 자신)

        for j in range(1, self.k): # j는 2의 거듭제곱 지수 (1, 2,  ...)
            for i in range(self.n - (1 << j) + 1): # 현재 길이(2^j)의 구간이 배열 범위를 벗어나지 않도록
                # 현재 구간을 두 개의 절반 구간으로 나누어 최솟값 계산
                self.st[i][j] = min(self.st[i][j-1], self.st[i + (1 << (j-1))][j-1])

    # 구간 [L, R]에 대한 최솟값 쿼리 (RMQ)
    # 시간 복잡도: O(1)
    def query(self, L, R):
        # 쿼리 구간 [L, R]을 완전히 덮는 가장 큰 2의 거듭제곱 k를 찾음
        k = self.log_table[R - L + 1]
        # 쿼리 구간을 두 개의 겹치는 2^k 길이 구간으로 나누어 최솟값 반환
        return min(self.st[L][k], self.st[R - (1 << k) + 1][k])

# 예시
# arr = [7, 2, 3, 0, 5, 10, 8, 1]
# st_rmq = SparseTable(arr)
# print(st_rmq.query(0, 7)) # 전체 구간 [0, 7]의 최솟값: 0
# print(st_rmq.query(1, ) # 구간 [1,  (2, 3, 0, 5)의 최솟값: 0
# print(st_rmq.query(0, 2)) # 구간 [0, 2] (7, 2, 3)의 최솟값: 2
```

### 7.3. 희소 테이블의 장단점 및 활용 사례

*   **장점:**
    *   `O(1)` 쿼리 시간으로 매우 빠릅니다. 이는 세그먼트 트리나 펜윅 트리보다 빠른 쿼리 성능을 제공합니다.
    *   구현이 비교적 간단합니다.
*   **단점:**
    *   배열의 요소가 변경될 경우 희소 테이블을 재구축해야 하므로, **정적 배열(Static Array)**에만 적합합니다. 동적인 배열에는 적합하지 않습니다.
    *   `O(n log n)`의 공간 복잡도를 가집니다. 이는 `n`이 매우 클 경우 메모리 사용량이 많아질 수 있습니다.
*   **활용 사례:**
    *   **RMQ (Range Minimum Query) 문제:** 특정 구간 내의 최솟값(또는 최댓값)을 찾는 문제에 최적화되어 있습니다.
    *   **LCA (Lowest Common Ancestor) 문제의 전처리:** 트리에서 두 노드의 가장 낮은 공통 조상을 찾는 문제의 전처리 과정에 활용될 수 있습니다.
    *   **정적 배열에서의 구간 쿼리:** 배열의 내용이 변하지 않는 상황에서 다양한 종류의 구간 쿼리(합, 곱, XOR 등)를 `O(1)`에 처리해야 할 때 유용합니다。

## 8. 제곱근 분할 (SQRT Decomposition)

제곱근 분할은 배열을 `sqrt(n)` 크기의 블록으로 나누어 구간 쿼리 및 업데이트를 처리하는 기법입니다. 세그먼트 트리나 펜윅 트리보다 느리지만, 구현이 더 간단하고 다양한 유형의 문제에 유연하게 적용할 수 있는 장점이 있습니다.

### 8.1. 제곱근 분할의 개념과 원리

*   **개념:** 배열을 `sqrt(n)` 크기의 여러 블록으로 나누고, 각 블록에 대한 요약 정보(예: 합, 최솟값)를 미리 계산하여 별도의 배열에 저장해 둡니다.
*   **원리:** 구간 쿼리 시, 쿼리 구간에 완전히 포함되는 블록들은 미리 계산된 요약 정보를 사용하고, 부분적으로 걸치는 양 끝의 블록들만 직접 순회하여 계산합니다. 블록의 크기를 `sqrt(n)`으로 설정하는 이유는 쿼리 시 순회해야 하는 블록의 수와 블록 내에서 순회해야 하는 요소의 수가 모두 최대 `sqrt(n)`에 비례하도록 하여, 전체 시간 복잡도를 `O(sqrt(n))`으로 최적화하기 위함입니다.
*   **원리 시각화 (배열을 `sqrt(n)` 크기의 블록으로 분할):**
    ```
    arr = [1, 2, 3, |  5, 6, | 7, 8, 9, | 10] (n=10, block_size=3)
           Block 0  |  Block 1  |  Block 2  | Block 3

    blocks = [6, 15, 2 10] (각 블록의 합)

    [ 쿼리 예시: query(2, 8) ]
    arr = [1, 2, [3, |  5, 6, | 7, 8,] 9, | 10]
                 ^      ^---^      ^---^
                 |        |          |
    부분 순회 (start)   블록 전체 사용   부분 순회 (end)
    ```

### 8.2. 제곱근 분할을 이용한 구간 쿼리 및 업데이트

*   **구축 (Build):** 배열을 `sqrt(n)` 크기의 블록으로 나누고, 각 블록의 합(또는 다른 요약 정보)을 미리 계산합니다. 시간 복잡도는 `O(n)`입니다。
*   **업데이트 (Update):** 특정 요소 `arr[idx]`의 값이 변경되면, 해당 요소가 속한 블록의 요약 정보만 갱신합니다. 시간 복잡도는 **`O(1)`** 입니다. (단, 블록 전체를 재계산해야 하는 복잡한 연산의 경우 `O(sqrt(n))`이 될 수 있습니다.)
*   **쿼리 (Query):** 특정 구간 `[L, R]`에 대한 쿼리 시, 쿼리 구간을 세 부분으로 나눕니다。
    1.  **시작 블록의 부분:** `L`이 속한 블록의 일부.
    2.  **완전히 포함되는 중간 블록들:** `L`이 속한 블록 다음부터 `R`이 속한 블록 이전까지의 모든 블록.
    3.  **끝 블록의 부분:** `R`이 속한 블록의 일부.
    부분적으로 걸치는 블록은 직접 순회하고, 완전히 포함되는 블록은 미리 계산된 요약 정보를 사용합니다. 시간 복잡도는 **`O(sqrt(n))`** 입니다.

```python
import math

class SqrtDecomposition:
    def __init__(self, arr):
        self.n = len(arr)
        self.block_size = int(math.sqrt(self.n)) # 블록 크기
        self.num_blocks = (self.n + self.block_size - 1) // self.block_size # 블록 개수
        self.blocks = [0] * self.num_blocks # 각 블록의 합 (또는 다른 요약 정보)
        self.arr = list(arr) # 원본 배열 복사

        # 블록 구축 (Build)
        for i in range(self.n):
            self.blocks[i // self.block_size] += self.arr[i]

    # 값 업데이트
    # idx: 업데이트할 원본 배열의 인덱스
    # val: 새로운 값
    def update(self, idx, val):
        block_idx = idx // self.block_size
        self.blocks[block_idx] += (val - self.arr[idx]) # 블록 합 갱신 (O(1))
        self.arr[idx] = val # 원본 배열 값 갱신 (O(1))

    # 구간 쿼리 (예: 구간 합)
    # l: 쿼리 구간 시작 인덱스
    # r: 쿼리 구간 끝 인덱스
    def query(self, l, r):
        total_sum = 0
        start_block = l // self.block_size
        end_block = r // self.block_size

        if start_block == end_block: # 쿼리 구간이 하나의 블록 내에 있을 때
            for i in range(l, r + 1):
                total_sum += self.arr[i]
        else:
            # 1. 시작 블록의 나머지 부분 처리
            for i in range(l, (start_block + 1) * self.block_size):
                total_sum += self.arr[i]
            # 2. 완전히 포함되는 중간 블록들 처리
            for i in range(start_block + 1, end_block):
                total_sum += self.blocks[i]
            # 3. 끝 블록의 시작 부분 처리
            for i in range(end_block * self.block_size, r + 1):
                total_sum += self.arr[i]
            
        return total_sum

# 예시
# arr = [1, 2, 3,  5, 6, 7, 8, 9, 10]
# sqd = SqrtDecomposition(arr)

# print(sqd.query(0, 9)) # 전체 합: 55
# print(sqd.query(2, 7)) # 구간 [3,  5, 6, 7, 8]의 합: 33

# sqd.update(3, 100) # arr[3] (원래 를 100으로 변경
# print(sqd.query(2, 7)) # 구간 [3, 100, 5, 6, 7, 8]의 합: 129
```

### 8.3. 제곱근 분할의 장단점 및 활용 사례

*   **장점:**
    *   구현이 세그먼트 트리나 펜윅 트리에 비해 상대적으로 간단합니다.
    *   **적용 유연성:** 부분적으로 걸치는 블록은 직접 순회하여 처리하므로, 세그먼트 트리 등으로 구현하기 까다로운 복잡한 조건의 쿼리(예: 구간 내 특정 값보다 작은 소수의 개수)도 비교적 쉽게 구현할 수 있습니다.
    *   온라인 쿼리(쿼리가 실시간으로 들어오는 경우)와 오프라인 쿼리(모든 쿼리가 미리 주어지는 경우) 모두에 적용할 수 있습니다.
*   **단점:**
    *   세그먼트 트리나 펜윅 트리가 `O(log n)`의 시간 복잡도를 가지는 반면, 제곱근 분할은 `O(sqrt(n))`으로 더 느립니다. `n`이 커질수록 성능 차이가 두드러집니다.
*   **활용 사례:**
    *   **구간 합, 구간 최솟값/최댓값 쿼리:** 배열의 요소가 자주 변경되면서 구간 쿼리가 필요한 경우에 사용될 수 있습니다.
    *   **오프라인 쿼리 (Mo's Algorithm 등):** 모든 쿼리가 미리 주어지는 오프라인 문제에서 Mo's Algorithm과 같은 기법의 기반으로 활용되어 효율적인 쿼리 처리를 가능하게 합니다.
    *   **복잡한 구간 연산:** 세그먼트 트리나 펜윅 트리로 구현하기 어려운 복잡한 구간 연산(예: 구간 내 고유한 요소의 개수)을 처리할 때 유용합니다。
