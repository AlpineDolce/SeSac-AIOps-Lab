## 1. 재귀 (Recursion)

재귀는 **자기 자신을 다시 호출하는 함수**를 사용하여 문제를 해결하는 강력한 프로그래밍 패러다임입니다. 복잡한 문제를 더 작고, 동일한 구조의 하위 문제(subproblem)로 나눌 수 있을 때 특히 유용하며, '분할 정복(Divide and Conquer)' 전략의 핵심 원리이기도 합니다.

마치 러시아 인형(마트료시카)을 여는 것처럼, 큰 인형을 열면 그 안에 똑같이 생긴 작은 인형이 있고, 그 과정을 반복하다가 더 이상 열 수 없는 가장 작은 인형을 만나면 멈추는 것과 같습니다.

### 1.1. 재귀의 핵심 원리: 기저 조건과 재귀 호출

모든 재귀 함수는 두 가지 필수적인 부분으로 구성됩니다.

1.  **기저 조건 (Base Case):**
    *   재귀 호출의 '탈출구' 역할을 합니다. 즉, 더 이상 자기 자신을 호출하지 않고 특정 값을 반환하여 재귀의 연쇄를 멈추는 조건입니다.
    *   기저 조건이 없으면 함수는 무한히 자기 자신을 호출하다가 **스택 오버플로우(Stack Overflow)** 오류를 발생시킵니다.

2.  **재귀 호출 (Recursive Call / Recursive Step):**
    *   문제를 더 작은 단위로 나누기 위해 함수가 자기 자신을 호출하는 부분입니다.
    *   호출할 때마다 문제의 범위가 점진적으로 줄어들어 결국 기저 조건에 도달하도록 설계해야 합니다.

**예시: 팩토리얼 계산**
`n! = n * (n-1) * (n-2) * ... * 1`은 `n! = n * (n-1)!` 이라는 재귀적 관계로 정의할 수 있습니다.

```python
def factorial(n):
    # 1. 기저 조건: n이 0이면 재귀를 멈추고 1을 반환
    if n == 0:
        return 1
    # 2. 재귀 호출: n과 n-1의 팩토리얼 결과를 곱함
    else:
        return n * factorial(n - 1)

# print(factorial(5)) # 결과: 120
```

### 1.2. 재귀와 호출 스택 (Call Stack)

재귀 함수가 호출될 때마다, 해당 함수의 정보(매개변수, 지역 변수, 반환 주소 등)가 **호출 스택(Call Stack)** 이라는 메모리 공간에 차곡차곡 쌓입니다.

`factorial(3)`의 호출 과정을 스택으로 시각화하면 다음과 같습니다.

1.  `factorial(3)` 호출 -> 스택: `[factorial(3)]`
2.  `factorial(2)` 호출 -> 스택: `[factorial(3), factorial(2)]`
3.  `factorial(1)` 호출 -> 스택: `[factorial(3), factorial(2), factorial(1)]`
4.  `factorial(0)` 호출 -> 스택: `[factorial(3), factorial(2), factorial(1), factorial(0)]`
5.  `factorial(0)`이 기저 조건에 도달하여 `1`을 반환. 스택에서 제거됨.
    *   스택: `[factorial(3), factorial(2), factorial(1)]`
  `factorial(1)`은 `1 * factorial(0)`의 결과인 `1`을 반환. 스택에서 제거됨.
    *   스택: `[factorial(3), factorial(2)]`
7.  `factorial(2)`는 `2 * factorial(1)`의 결과인 `2`를 반환. 스택에서 제거됨.
    *   스택: `[factorial(3)]`
8.  `factorial(3)`은 `3 * factorial(2)`의 결과인 `을 반환. 스택에서 제거됨.
    *   스택: `[]` (비어 있음)

이처럼 스택은 재귀 호출의 깊이가 깊어질수록 많은 메모리를 사용하며, 한계를 초과하면 스택 오버플로우가 발생합니다.

### 1.3. 재귀 vs 반복 (장단점 비교)

| 특징          | 재귀 (Recursion)                                       | 반복 (Iteration)                                     |
| :------------ | :----------------------------------------------------- | :--------------------------------------------------- |
| **가독성**    | 문제가 재귀적으로 정의될 때 (예: 트리 순회, 분할 정복) 코드가 매우 직관적이고 간결해짐. | 로직이 순차적일 때 더 명확하고 이해하기 쉬움.        |
| **성능**      | 함수 호출에 따른 오버헤드가 발생하며, 스택 메모리를 추가로 사용함. | 함수 호출 오버헤드가 없어 일반적으로 더 빠르고 메모리 효율적. |
| **구현 복잡도** | 기저 조건과 재귀 관계를 명확히 정의하는 것이 중요. 잘못하면 무한 루프에 빠지기 쉬움. | 루프의 초기화, 조건, 업데이트를 정확하게 관리해야 함. |
| **스택 관리** | 재귀 깊이가 깊어지면 스택 오버플로우 발생 위험이 있음. | 스택 오버플로우 위험이 없음.                         |

### 1.4. 꼬리 재귀 최적화 (Tail Recursion Optimization)

**꼬리 재귀**는 재귀 호출이 함수의 **가장 마지막 연산**으로 수행되는 형태를 말합니다. 즉, 재귀 호출의 반환 값이 추가적인 연산 없이 그대로 반환되는 구조입니다.

```python
# 일반 재귀 (마지막 연산은 곱셈)
def factorial(n):
    if n == 0: return 1
    return n * factorial(n - 1)

# 꼬리 재귀 (마지막 연산은 재귀 호출 자체)
def factorial_tail(n, accumulator=1):
    if n == 0:
        return accumulator
    return factorial_tail(n - 1, n * accumulator)
```

일부 언어의 컴파일러는 꼬리 재귀를 발견하면, 이를 내부적으로 반복문으로 변환하여 스택 프레임을 새로 쌓지 않도록 최적화합니다. 이를 통해 스택 오버플로우를 방지하고 성능을 향상시킬 수 있습니다.

- 파이썬은 공식적으로 꼬리 재귀 최적화(Tail Recursion Optimization, TRO)를 지원하지 않습니다. 따라서 파이썬에서 재귀 깊이가 너무 깊어지면 `RecursionError`가 발생할 수 있습니다.

### 1.5. 재귀 활용 문제

재귀는 다양한 문제 해결에 우아한 코드를 제공하지만, 항상 효율적인 것은 아닙니다.

*   **팩토리얼 (Factorial):** `n! = n * (n-1)!`
    *   **동작 과정 (예시: `factorial(3)`)**
        1.  `factorial(3)` 호출
        2.  `3 * factorial(2)`
        3.  `3 * (2 * factorial(1))`
        4.  `3 * (2 * (1 * factorial(0)))`
        5.  `factorial(0)`은 기저 조건에 따라 `1` 반환
          `3 * (2 * (1 * 1))`
        7.  `3 * (2 * 1)`
        8.  `3 * 2`
        9.  ` 반환

*   **문자열 뒤집기:**
    ```python
    def reverse_string(s):
        if len(s) <= 1:
            return s
        return reverse_string(s[1:]) + s[0]
    # print(reverse_string("hello")) # "olleh"
    ```
    *   **동작 과정 (예시: `reverse_string("abc")`)**
        1.  `reverse_string("abc")` 호출
        2.  `reverse_string("bc")` + `"a"`
        3.  (`reverse_string("c")` + `"b"`) + `"a"`
        4.  ((`"c"`) + `"b"`) + `"a"` (기저 조건 `len(s) <= 1`에 따라 "c" 반환)
        5.  `"cb"` + `"a"`
          `"cba"` 반환

*   **피보나치 수열 (Fibonacci Sequence):** `F(n) = F(n-1) + F(n-2)`
    ```python
    # 비효율적인 재귀의 대표적인 예
    def fibonacci(n):
        if n <= 1:
            return n
        return fibonacci(n - 1) + fibonacci(n - 2)
    ```
    *   **동작 과정 (예시: `fibonacci(4)`)**
        1.  `fibonacci(4)`
        2.  `fibonacci(3)` + `fibonacci(2)`
        3.  (`fibonacci(2)` + `fibonacci(1)`) + (`fibonacci(1)` + `fibonacci(0)`)
        4.  ((`fibonacci(1)` + `fibonacci(0)`) + `1`) + (`1` + `0`)
        5.  ((`1` + `0`) + `1`) + `1`
          (`1` + `1`) + `1`
        7.  `2` + `1`
        8.  `3` 반환

    위 피보나치 함수는 `fibonacci(3)`을 계산하기 위해 `fibonacci(2)`와 `fibonacci(1)`을 호출하고, `fibonacci(2)`는 다시 `fibonacci(1)`과 `fibonacci(0)`을 호출하는 등 **동일한 계산을 엄청나게 반복**합니다. 이로 인해 시간 복잡도가 `O(2^n)`에 달하는 매우 비효율적인 코드가 됩니다.

이러한 **중복 계산 문제**는 재귀 사용 시 반드시 고려해야 할 점이며, 이를 해결하기 위해 **메모이제이션(Memoization)** 기법을 도입한 **동적 계획법(Dynamic Programming)**으로 이어지게 됩니다.

### 1.6. 재귀의 특징

*   **간결성:** 복잡한 문제를 몇 줄의 코드로 간결하게 표현할 수 있습니다.
*   **우아함:** 문제의 정의 자체가 재귀적일 때, 재귀 함수는 문제 해결 과정을 자연스럽게 반영하여 코드가 우아해집니다.
*   **분할 정복:** 큰 문제를 작은 하위 문제로 나누어 해결하는 분할 정복 패러다임에 적합합니다.

### 1.7. 재귀의 장점 및 단점

*   **장점:**
    *   **코드의 가독성 및 간결성:** 재귀적으로 정의된 문제(예: 트리 순회, 팩토리얼, 피보나치)를 해결할 때, 반복문보다 훨씬 직관적이고 간결한 코드를 작성할 수 있습니다.
    *   **문제 해결 방식의 자연스러운 표현:** 특정 알고리즘(예: DFS, 분할 정복)은 재귀를 통해 그 논리를 가장 자연스럽게 표현할 수 있습니다.
    *   **복잡한 자료구조 처리:** 트리, 그래프와 같은 재귀적 정의를 가진 자료구조를 처리하는 데 매우 효과적입니다.

*   **단점:**
    *   **성능 오버헤드:** 함수 호출 시마다 스택 프레임을 생성하고 제거하는 오버헤드가 발생하여 반복문보다 느릴 수 있습니다.
    *   **메모리 사용량:** 재귀 호출의 깊이가 깊어질수록 호출 스택에 많은 메모리가 쌓여 메모리 사용량이 증가합니다.
    *   **스택 오버플로우 위험:** 재귀 깊이가 시스템이 허용하는 최대치를 초과하면 `Stack Overflow Error`가 발생하여 프로그램이 비정상적으로 종료될 수 있습니다.
    *   **중복 계산 문제:** 동일한 하위 문제를 여러 번 계산하는 경우가 발생할 수 있으며, 이는 성능 저하의 주된 원인이 됩니다 (예: 순수 재귀 피보나치). 이를 해결하기 위해 메모이제이션 등의 기법이 필요합니다.
    *   **디버깅의 어려움:** 호출 스택의 흐름을 추적하기 어려워 디버깅이 복잡할 수 있습니다.

## 2. 동적 계획법 (Dynamic Programming)

동적 계획법(Dynamic Programming, DP)은 복잡한 문제를 여러 개의 더 작고 중복되는 하위 문제로 나누어 해결하고, 각 하위 문제의 해답을 한 번만 계산하여 저장해 둠으로써 전체 문제의 효율적인 해결을 가능하게 하는 알고리즘 기법입니다. 특히, 재귀적으로 정의되는 문제에서 발생하는 **중복 계산의 비효율성**을 극복하기 위해 사용됩니다.

이전에 재귀 섹션에서 살펴본 비효율적인 피보나치 수열 계산(`fibonacci(n-1) + fibonacci(n-2)`)이 동적 계획법이 필요한 대표적인 예시입니다. `fibonacci(5)`를 계산할 때 `fibonacci(3)`이 여러 번 계산되는 것처럼, 동일한 하위 문제가 반복적으로 호출되어 불필요한 연산이 많아집니다. 동적 계획법은 이러한 중복 계산을 제거하여 시간 복잡도를 크게 개선합니다.

### 2.1. 동적 계획법의 핵심 조건: 최적 부분 구조와 중복 부분 문제

동적 계획법을 적용할 수 있는 문제는 다음 두 가지 속성을 만족해야 합니다.

1.  **최적 부분 구조 (Optimal Substructure):**
    *   큰 문제의 최적 해가 그 하위 문제의 최적 해로부터 구성될 수 있어야 합니다. 즉, 전체 문제의 해답을 얻기 위해 하위 문제의 최적 해답을 조합할 수 있어야 합니다.
    *   예: 최단 경로 문제에서, `A`에서 `C`로 가는 최단 경로는 `A`에서 `B`로 가는 최단 경로와 `B`에서 `C`로 가는 최단 경로의 합으로 이루어집니다.

2.  **중복 부분 문제 (Overlapping Subproblems):**
    *   동일한 하위 문제가 여러 번 반복하여 계산되어야 합니다. 만약 하위 문제가 한 번만 계산된다면 동적 계획법의 이점이 사라집니다.
    *   예: 피보나치 수열 계산에서 `F(3)`이 `F(5)`를 계산할 때와 `F(4)`를 계산할 때 모두 필요하여 여러 번 호출됩니다.

### 2.2. 동적 계획법의 두 가지 접근 방식: 상향식(Bottom-up)과 하향식(Top-down)

동적 계획법은 문제를 해결하는 방식에 따라 크게 두 가지 접근법으로 나뉩니다.

1.  **상향식 (Bottom-up, Tabulation):**
    *   가장 작은 하위 문제부터 해결하여 그 결과를 테이블(배열)에 저장하고, 이 결과를 이용하여 점진적으로 더 큰 문제의 해답을 구축해 나가는 방식입니다.
    *   주로 반복문(for/while loop)을 사용하여 구현하며, 모든 하위 문제를 계산합니다.
    *   **장점:** 재귀 호출 오버헤드가 없어 일반적으로 더 빠르고 메모리 효율적입니다. 스택 오버플로우 위험이 없습니다.
    *   **단점:** 모든 하위 문제를 계산하므로, 실제로 필요하지 않은 하위 문제까지 계산할 수 있습니다.

    **예시: 피보나치 수열 (상향식)**
    ```python
    def fibonacci_bottom_up(n):
        if n <= 1:
            return n
        
        dp = [0] * (n + 1) # 결과를 저장할 테이블 (배열)
        dp[0] = 0
        dp[1] = 1
        
        for i in range(2, n + 1):
            dp[i] = dp[i - 1] + dp[i - 2] # 작은 문제의 해를 이용해 큰 문제 해결
            
        return dp[n]

    # print(fibonacci_bottom_up(10)) # 55
    ```
    *   **동작 과정 (예시: `fibonacci_bottom_up(5)`)**
        *   `dp` 테이블 초기화: `[0, 1, 0, 0, 0, 0]` (크기  인덱스 0~5)
        *   `dp[0] = 0`, `dp[1] = 1`
        *   `i = 2`: `dp[2] = dp[1] + dp[0] = 1 + 0 = 1`. `dp = [0, 1, 1, 0, 0, 0]`
        *   `i = 3`: `dp[3] = dp[2] + dp[1] = 1 + 1 = 2`. `dp = [0, 1, 1, 2, 0, 0]`
        *   `i = 4`: `dp[4] = dp[3] + dp[2] = 2 + 1 = 3`. `dp = [0, 1, 1, 2, 3, 0]`
        *   `i = 5`: `dp[5] = dp[4] + dp[3] = 3 + 2 = 5`. `dp = [0, 1, 1, 2, 3, 5]`
        *   결과: `dp[5]`인 `5` 반환.

2.  **하향식 (Top-down, Memoization):**
    *   재귀적으로 문제를 해결하되, 이미 계산된 하위 문제의 해답은 저장(메모이제이션)해두고, 동일한 하위 문제가 다시 호출될 경우 저장된 값을 재사용하는 방식입니다.
    *   **메모이제이션(Memoization):** 계산된 결과를 저장해두는 기법. 보통 딕셔너리나 배열을 사용합니다.
    *   **장점:** 재귀 호출의 자연스러운 흐름을 따르므로 구현이 직관적일 수 있습니다. 실제로 필요한 하위 문제만 계산합니다.
    *   **단점:** 재귀 호출 오버헤드가 발생할 수 있으며, 재귀 깊이가 깊어지면 스택 오버플로우 위험이 있습니다.

    **예시: 피보나치 수열 (하향식)**
    ```python
    memo = {} # 결과를 저장할 딕셔너리 (메모)

    def fibonacci_top_down(n):
        if n <= 1:
            return n
        
        if n in memo: # 이미 계산된 값이 있으면 재사용
            return memo[n]
            
        # 계산하고 메모에 저장
        memo[n] = fibonacci_top_down(n - 1) + fibonacci_top_down(n - 2)
        return memo[n]

    # print(fibonacci_top_down(10)) # 55
    ```
    *   **동작 과정 (예시: `fibonacci_top_down(5)`)**
        *   `fibonacci_top_down(5)` 호출
        *   `memo`에 `5` 없음. `fibonacci_top_down(4)` + `fibonacci_top_down(3)` 호출
        *   `fibonacci_top_down(4)` 호출
            *   `memo`에 `4` 없음. `fibonacci_top_down(3)` + `fibonacci_top_down(2)` 호출
            *   `fibonacci_top_down(3)` 호출
                *   `memo`에 `3` 없음. `fibonacci_top_down(2)` + `fibonacci_top_down(1)` 호출
                *   `fibonacci_top_down(2)` 호출
                    *   `memo`에 `2` 없음. `fibonacci_top_down(1)` (반환 1) + `fibonacci_top_down(0)` (반환 0) 호출
                    *   `memo[2] = 1 + 0 = 1`. `memo = {0:0, 1:1, 2:1}`
                    *   `fibonacci_top_down(2)` 반환 1
                *   `fibonacci_top_down(1)` 반환 1
                *   `memo[3] = 1 + 1 = 2`. `memo = {0:0, 1:1, 2:1, 3:2}`
                *   `fibonacci_top_down(3)` 반환 2
            *   `fibonacci_top_down(2)` 호출 (이미 `memo[2]`에 1 저장되어 있으므로 1 반환)
            *   `memo[4] = 2 + 1 = 3`. `memo = {0:0, 1:1, 2:1, 3:2, 4:3}`
            *   `fibonacci_top_down(4)` 반환 3
        *   `fibonacci_top_down(3)` 호출 (이미 `memo[3]`에 2 저장되어 있으므로 2 반환)
        *   `memo[5] = 3 + 2 = 5`. `memo = {0:0, 1:1, 2:1, 3:2, 4:3, 5:5}`
        *   `fibonacci_top_down(5)` 반환 5.

### 2.3. 동적 계획법 문제 해결 단계

동적 계획법 문제를 해결하기 위한 일반적인 접근 방식은 다음과 같습니다.

1.  **문제의 재귀적 관계 정의:** 주어진 문제를 더 작은 하위 문제로 어떻게 나눌 수 있는지, 그리고 하위 문제의 해답이 어떻게 전체 문제의 해답에 기여하는지 재귀적 점화식으로 표현합니다.
2.  **기저 조건(Base Case) 식별:** 재귀 호출이 멈추는 가장 작은 문제의 해답을 정의합니다.
3.  **중복 부분 문제 확인:** 동일한 하위 문제가 여러 번 계산되는지 확인합니다. (이것이 DP를 사용하는 주된 이유입니다.)
4.  **최적 부분 구조 확인:** 하위 문제의 최적 해가 전체 문제의 최적 해를 구성하는지 확인합니다.
5.  **메모이제이션 또는 타뷸레이션 선택:** 문제의 특성과 선호도에 따라 하향식(메모이제이션) 또는 상향식(타뷸레이션) 접근 방식을 선택합니다.
  **DP 테이블(배열) 정의 및 초기화:** 하위 문제의 해답을 저장할 데이터 구조(배열, 딕셔너리 등)를 정의하고 초기화합니다.
7.  **점화식 구현:** 정의된 재귀적 관계와 기저 조건을 바탕으로 DP 테이블을 채워나갑니다.

### 2.4. 동적 계획법의 특징

*   **최적화 문제 해결:** 주로 최댓값, 최솟값, 경우의 수 등을 찾는 최적화 문제에 사용됩니다.
*   **중복 계산 제거:** 동일한 하위 문제를 한 번만 계산하고 결과를 재사용하여 효율성을 높입니다.
*   **점화식 기반:** 문제의 해를 점화식(재귀적 관계)으로 표현하는 것이 중요합니다.

### 2.5. 동적 계획법의 장점 및 단점

*   **장점:**
    *   **효율성:** 중복 계산을 제거하여 지수 시간 복잡도를 가지는 문제를 다항 시간 복잡도로 줄여 효율적인 해결이 가능합니다.
    *   **최적해 보장:** 최적 부분 구조와 중복 부분 문제 속성을 만족하는 문제에 대해 항상 최적해를 찾습니다.
    *   **다양한 문제 적용:** 최단 경로, 배낭 문제, 문자열 편집 거리 등 다양한 유형의 문제에 적용될 수 있습니다.

*   **단점:**
    *   **구현의 복잡성:** 점화식을 세우고 DP 테이블을 설계하는 것이 어려울 수 있습니다.
    *   **메모리 사용량:** 하위 문제의 해답을 저장하기 위한 DP 테이블이 필요하므로, 문제의 크기에 따라 상당한 메모리를 사용할 수 있습니다.
    *   **모든 문제에 적용 불가:** 최적 부분 구조와 중복 부분 문제 속성을 만족하지 않는 문제에는 적용할 수 없습니다.

### 2.6. 동적 계획법 활용 문제

동적 계획법은 다양한 최적화 문제에 적용됩니다.

*   **피보나치 수열:** 가장 기본적인 예시로, `O(n)` 시간 복잡도로 해결 가능합니다.
*   **배낭 문제 (Knapsack Problem):**
    *   제한된 용량의 배낭에 물건을 담아 가치의 합을 최대로 만드는 문제입니다.
    *   **0/1 배낭 문제:** 각 물건을 넣거나 넣지 않거나 둘 중 하나만 선택할 수 있습니다.
    *   **개념:** `dp[i][w]`를 `i`번째 물건까지 고려했을 때, 배낭의 용량이 `w`일 때 얻을 수 있는 최대 가치로 정의합니다.
    *   **점화식:** `dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])` (물건 `i`를 넣는 경우와 넣지 않는 경우 중 최댓값)
*   **최장 공통 부분 수열 (Longest Common Subsequence, LCS):** 두 수열의 가장 긴 공통 부분 수열을 찾는 문제.
*   **최단 경로 문제 (Shortest Path Problem):** 특정 조건 하에서 (예: 음수 간선이 없는 DAG) 최단 경로를 찾는 데 사용될 수 있습니다. (벨만-포드 알고리즘, 플로이드-워셜 알고리즘 등)
*   **행렬 곱셈 순서 (Matrix Chain Multiplication):** 여러 행렬을 곱할 때 최소 곱셈 횟수를 찾는 문제.
*   **동전 거스름돈 문제 (Coin Change Problem):** 주어진 동전들로 특정 금액을 만들 수 있는 최소 동전 개수 또는 방법의 수를 찾는 문제.

## 3. 그리디 알고리즘 (Greedy Algorithm)

그리디 알고리즘(Greedy Algorithm)은 **매 순간 가장 최적이라고 판단되는 선택을 하는 방식**으로 문제를 해결하는 알고리즘입니다. 즉, 현재 상황에서 가장 좋아 보이는 선택을 하고, 이 선택이 나중에 전체 문제의 최적 해를 가져올 것이라고 가정합니다. '탐욕적인(Greedy)'이라는 이름처럼, 당장의 이득만을 추구하는 전략입니다.

예를 들어, 거스름돈을 줄 때 가장 큰 단위의 동전부터 사용하는 것이 그리디 전략입니다. 500원, 100원, 50원, 10원짜리 동전이 있을 때 0원을 거슬러 준다면, 500원 1개, 100원 1개, 50원 1개, 10원 2개를 주는 식입니다.

### 3.1. 그리디 알고리즘의 특징

그리디 알고리즘이 최적의 해를 보장하기 위해서는 다음 두 가지 속성을 만족해야 합니다.

1.  **탐욕적 선택 속성 (Greedy Choice Property):**
    *   현재 단계에서 내린 최적의 선택이 이후 단계의 선택에 영향을 주지 않으며, 전체 문제의 최적 해를 찾는 데 항상 포함된다는 속성입니다.
    *   즉, 현재의 선택이 미래의 최적 해를 망치지 않는다는 확신이 있어야 합니다.
    *   예: 활동 선택 문제에서, 가장 빨리 끝나는 활동을 먼저 선택하는 것이 전체 활동 수를 최대로 만드는 데 항상 최적입니다.

2.  **최적 부분 구조 (Optimal Substructure):**
    *   전체 문제의 최적 해가 하위 문제의 최적 해로 구성될 수 있다는 속성입니다. 동적 계획법과 공유하는 속성이지만, 그리디에서는 하위 문제의 해답을 조합하는 방식이 더 단순합니다.

### 3.2. 그리디 알고리즘의 한계 (언제 최적해를 보장하지 못하는가?)

그리디 알고리즘은 항상 최적의 해를 보장하지는 않습니다. 이는 현재의 최적 선택이 전체적인 최적 해로 이어지지 않는 경우가 있기 때문입니다. 그리디 알고리즘이 최적해를 보장하는지 여부는 문제의 특성에 따라 달라지며, 이를 증명하는 것이 중요합니다.

**반례: 비표준 동전 거스름돈 문제**

만약 동전 단위가 1원, 4원, 이고 8원을 거슬러 주어야 한다고 가정해 봅시다.

*   **그리디 방식:** 가장 큰 동전인 짜리 1개, 그리고 남은 2원을 위해 1원짜리 2개. 총 3개 (1+1).
*   **최적 해:** 4원짜리 2개. 총 2개 (4+4).

이 경우 그리디 방식은 최적 해를 찾지 못합니다. 이는 '탐욕적 선택 속성'이 이 문제의 동전 단위에서는 성립하지 않기 때문입니다. 짜리를 선택하는 순간, 4원짜리 2개로 8원을 만들 수 있는 더 좋은 기회를 놓치게 됩니다.

### 3.3. 그리디 알고리즘 활용 문제

그리디 알고리즘은 특정 조건 하에서 최적의 해를 보장하며, 구현이 비교적 간단하고 실행 속도가 빠르다는 장점이 있습니다.

*   **거스름돈 문제 (Coin Change Problem):**
    *   일반적인 동전 단위(예: 500, 100, 50, 10원)에서는 그리디 방식이 최적해를 보장합니다. 이는 각 동전 단위가 그 다음 작은 동전 단위들의 합으로 표현될 수 없기 때문입니다.
    *   **동작 과정 (예시: `amount = 0`, `coins = [500, 100, 50, 10]`)**
        1.  **동전 정렬:** 동전을 내림차순으로 정렬합니다: `[500, 100, 50, 10]`
        2.  **거스름돈 계산:**
            *   **500원:** `0 >= 500` 이므로 500원 1개 사용. `amount = 170`. `result = [500]`
            *   **100원:** `170 >= 100` 이므로 100원 1개 사용. `amount = 70`. `result = [500, 100]`
            *   **50원:** `70 >= 50` 이므로 50원 1개 사용. `amount = 20`. `result = [500, 100, 50]`
            *   **10원:** `20 >= 10` 이므로 10원 1개 사용. `amount = 10`. `result = [500, 100, 50, 10]`
            *   **10원:** `10 >= 10` 이므로 10원 1개 사용. `amount = 0`. `result = [500, 100, 50, 10, 10]`
        3.  **종료:** `amount`가 0이 되었으므로 종료. 최종 `result = [500, 100, 50, 10, 10]`

    *   **예시 코드 (파이썬):**
        ```python
        def greedy_coin_change(amount, coins):
            coins.sort(reverse=True) # 큰 단위부터 사용
            result = []
            for coin in coins:
                while amount >= coin:
                    result.append(coin)
                    amount -= coin
            return result

        # print(greedy_coin_change(0, [500, 100, 50, 10])) # [500, 100, 50, 10, 10]
        # print(greedy_coin_change(8, [1, 4, )) # [ 1, 1] (최적 아님)
        ```

*   **활동 선택 문제 (Activity Selection Problem):**
    *   서로 겹치지 않으면서 최대한 많은 활동을 선택하는 문제입니다. 활동들을 종료 시간 기준으로 정렬한 후, 가장 빨리 끝나는 활동부터 선택하는 그리디 전략이 최적해를 보장합니다.
*   **최소 신장 트리 (Minimum Spanning Tree, MST):**
    *   **크루스칼(Kruskal) 알고리즘**과 **프림(Prim) 알고리즘**은 모두 그리디 전략을 사용하여 그래프의 최소 신장 트리를 찾습니다. 크루스칼은 가장 가중치가 작은 간선부터 선택하고, 프림은 현재 연결된 정점에서 가장 가중치가 작은 간선을 선택합니다.
*   **부분 배낭 문제 (Fractional Knapsack Problem):**
    *   물건을 쪼갤 수 있는 경우, 단위 무게당 가치가 가장 높은 물건부터 담는 그리디 전략이 최적해를 보장합니다. (0/1 배낭 문제는 동적 계획법으로 해결해야 합니다.)

그리디 알고리즘은 직관적이고 구현이 간단하지만, 문제에 적용하기 전에 해당 문제가 그리디 속성을 만족하는지 신중하게 검토하고, 가능하다면 수학적으로 증명하는 과정이 필요합니다.

### 3.4. 그리디 알고리즘의 장점 및 단점

*   **장점:**
    *   **구현의 단순성:** 알고리즘의 논리가 직관적이고 단순하여 구현하기 쉽습니다.
    *   **빠른 실행 속도:** 매 순간 최적의 선택을 하므로, 일반적으로 동적 계획법이나 완전 탐색보다 실행 속도가 빠릅니다.
    *   **특정 문제에 대한 최적해 보장:** 탐욕적 선택 속성과 최적 부분 구조를 만족하는 문제에 대해서는 항상 최적해를 보장합니다.

*   **단점:**
    *   **최적해를 보장하지 못하는 경우:** 문제의 특성상 현재의 최적 선택이 전체적인 최적 해로 이어지지 않는 경우가 많습니다. (예: 비표준 동전 거스름돈 문제)
    *   **증명의 어려움:** 그리디 알고리즘이 최적해를 보장하는지 여부를 증명하는 것이 어려울 수 있습니다.
    *   **적용 범위의 제한:** 모든 문제에 적용할 수 있는 만능 해결책이 아닙니다.


  ## 4. 백트래킹 (Backtracking)

백트래킹(Backtracking)은 해를 찾는 과정에서 **조건에 맞지 않거나 해가 될 가능성이 없는 경로를 발견하면 즉시 탐색을 중단하고 이전 단계로 돌아가(Backtrack) 다른 경로를 탐색하는** 알고리즘 기법입니다. 주로 모든 가능한 경우의 수를 탐색해야 하는 문제(완전 탐색)에서 불필요한 경로를 제거하여 효율성을 높일 때 사용됩니다.

미로를 탐색하는 것에 비유할 수 있습니다. 한 길을 따라 깊이 들어가다가 막다른 길에 도달하면, 더 이상 진행하지 않고 이전 갈림길로 되돌아와 다른 길을 시도하는 것과 같습니다.

### 4.1. 백트래킹의 개념 및 탐색 과정

백트래킹은 재귀 함수를 기반으로 하며, 다음 세 가지 핵심 요소로 구성됩니다.

1.  **상태 공간 트리 (State Space Tree):**
    *   문제를 해결하기 위한 모든 가능한 선택과 그 결과로 형성되는 상태들을 트리 형태로 표현한 것입니다. 트리의 각 노드는 문제의 부분 해(partial solution)를 나타내고, 루트에서 리프까지의 경로는 하나의 완전한 해(또는 해가 될 수 있는 후보)를 나타냅니다.
    *   백트래킹은 이 상태 공간 트리를 깊이 우선 탐색(DFS) 방식으로 탐색합니다.

2.  **깊이 우선 탐색 (DFS):**
    *   백트래킹은 기본적으로 DFS를 사용하여 상태 공간 트리의 한 경로를 가능한 한 깊이 탐색합니다. 이는 하나의 부분 해를 완성하기 위해 필요한 모든 선택을 순차적으로 시도하는 것을 의미합니다.

3.  **가지치기 (Pruning):**
    *   백트래킹의 핵심이자 효율성을 결정하는 부분입니다. 현재까지 구성된 부분 해가 더 이상 완전한 해로 발전할 가능성이 없다고 판단되면, 해당 경로를 따라 더 깊이 탐색하는 것을 중단하고 이전 노드로 되돌아갑니다.
    *   가지치기 조건은 문제의 제약 조건에 따라 달라집니다. 예를 들어, N-Queen 문제에서는 퀸을 놓았을 때 다른 퀸을 공격하는 위치라면 해당 경로를 가지치기합니다.

**일반적인 백트래킹 알고리즘 구조 (의사 코드):**

```
function backtrack(현재_상태, 선택_목록):
    if 현재_상태가_해답_조건을_만족하는가:
        해답을_기록하고_반환 (또는 다른 해답 탐색 계속)
        return

    for 각_선택 in 선택_목록:
        if 선택이_유효한가(현재_상태, 각_선택): # 가지치기 조건
            현재_상태에_선택을_적용
            backtrack(새로운_상태, 다음_선택_목록)
            현재_상태에서_선택을_제거 (백트랙: 상태 복원)
```

### 4.2. 백트래킹 활용 문제 및 예시

백트래킹은 모든 가능한 해를 찾아야 하거나, 특정 제약 조건을 만족하는 해를 찾아야 하는 문제에 주로 사용됩니다.

*   **N-Queen 문제:** N개의 퀸을 N*N 체스판에 서로 공격할 수 없도록 배치하는 모든 경우의 수를 찾는 문제.
*   **스도쿠 (Sudoku):** 스도쿠 퍼즐의 빈칸을 채워 유효한 스도쿠를 완성하는 문제.
*   **조합 (Combination) 및 순열 (Permutation) 생성:** 주어진 원소들로 만들 수 있는 모든 조합이나 순열을 찾는 문제.
*   **부분집합의 합 (Subset Sum):** 주어진 집합의 부분집합 중 합이 특정 값이 되는 모든 부분집합을 찾는 문제.

**예시: 모든 부분집합 생성 (Python)**

주어진 숫자 리스트 `nums`의 모든 부분집합을 생성하는 백트래킹 예시입니다.

*   **동작 과정 (예시: `nums = [1, 2]`)**
    1.  `find_subsets([1, 2])` 호출
    2.  `backtrack(0)` 호출 (index = 0)
        *   `result.append([])` -> `result = [[]]`
        *   `i = 0` (nums[0] = 1)
            *   `current_subset.append(1)` -> `current_subset = [1]`
            *   `backtrack(1)` 호출 (index = 1)
                *   `result.append([1])` -> `result = [[], [1]]`
                *   `i = 1` (nums[1] = 2)
                    *   `current_subset.append(2)` -> `current_subset = [1, 2]`
                    *   `backtrack(2)` 호출 (index = 2)
                        *   `result.append([1, 2])` -> `result = [[], [1], [1, 2]]`
                        *   `for` 루프 종료 (index = 2, len(nums) = 2)
                    *   `current_subset.pop()` -> `current_subset = [1]` (백트랙)
                *   `for` 루프 종료 (index = 1, len(nums) = 2)
            *   `current_subset.pop()` -> `current_subset = []` (백트랙)
        *   `i = 1` (nums[1] = 2)
            *   `current_subset.append(2)` -> `current_subset = [2]`
            *   `backtrack(2)` 호출 (index = 2)
                *   `result.append([2])` -> `result = [[], [1], [1, 2], [2]]`
                *   `for` 루프 종료
            *   `current_subset.pop()` -> `current_subset = []` (백트랙)
        *   `for` 루프 종료
    *   최종 `result` 반환: `[[], [1], [1, 2], [2]]`

```python
def find_subsets(nums):
    result = []
    current_subset = []

    def backtrack(index):
        # 현재까지의 부분집합을 결과에 추가
        result.append(list(current_subset))

        # 현재 인덱스부터 끝까지 탐색
        for i in range(index, len(nums)):
            # 1. 선택: 현재 숫자를 부분집합에 추가
            current_subset.append(nums[i])
            
            # 2. 재귀 호출: 다음 숫자를 선택하기 위해 재귀
            backtrack(i + 1)
            
            # 3. 백트랙: 현재 숫자를 부분집합에서 제거 (다른 경로 탐색을 위해 상태 복원)
            current_subset.pop()

    backtrack(0) # 0번 인덱스부터 탐색 시작
    return result

# print(find_subsets([1, 2, 3]))
# 예상 출력: [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

### 4.3. 백트래킹의 성능

백트래킹 알고리즘의 최악의 경우 시간 복잡도는 일반적으로 지수적(exponential)입니다. 이는 모든 가능한 경로를 탐색해야 할 수도 있기 때문입니다. 그러나 **가지치기(Pruning)**를 통해 불필요한 탐색 공간을 효과적으로 줄일 수 있다면, 실제 실행 시간은 훨씬 빨라질 수 있습니다. 가지치기 조건이 얼마나 강력한지에 따라 성능이 크게 좌우됩니다.

### 4.4. 백트래킹의 장점 및 단점

*   **장점:**
    *   **모든 해 또는 최적해 탐색:** 모든 가능한 해를 찾아야 하거나, 특정 제약 조건을 만족하는 최적해를 찾아야 하는 문제에 효과적입니다.
    *   **가지치기를 통한 효율성:** 불필요한 탐색 경로를 조기에 차단하여 탐색 공간을 크게 줄일 수 있습니다.
    *   **재귀적 구조의 자연스러운 표현:** 재귀를 사용하여 문제의 탐색 과정을 직관적으로 표현할 수 있습니다.

*   **단점:**
    *   **시간 복잡도:** 최악의 경우 지수적인 시간 복잡도를 가지므로, 문제의 크기가 커지면 비효율적일 수 있습니다.
    *   **구현의 복잡성:** 상태 관리, 가지치기 조건, 백트랙 로직 등을 정확하게 구현하는 것이 어려울 수 있습니다.
    *   **메모리 사용량:** 재귀 호출로 인해 스택 메모리를 많이 사용할 수 있습니다.

## 5. 분리 집합 (Disjoint Set Union, DSU)

분리 집합(Disjoint Set Union, DSU) 또는 서로소 집합(Union-Find)은 **서로 겹치지 않는(서로소) 집합들의 모음을 관리하는 자료구조**입니다. 이 자료구조는 원소들이 어떤 집합에 속하는지, 그리고 두 원소가 같은 집합에 속하는지 등을 매우 효율적으로 판단하고, 필요에 따라 두 집합을 합치는(Union) 연산을 수행하는 데 사용됩니다. 주로 그래프 알고리즘에서 연결된 구성 요소를 추적하거나, 네트워크 연결성을 관리하는 등의 문제에 활용됩니다.

**분리 집합의 개념, 연산, 최적화 기법 및 상세 구현에 대한 더 자세한 내용은 [분리 집합 문서](./10_분리_집합.md)를 참조하십시오.**

## 6. Meet-in-the-Middle

Meet-in-the-Middle (MITM)은 **탐색 공간이 너무 커서 모든 경우의 수를 직접 탐색하기 어려울 때, 탐색 공간을 대략 절반으로 나누어 각각 탐색한 후 중간에서 만나는 방식으로 문제를 해결하는 알고리즘 기법**입니다. 주로 `O(2^N)`과 같이 지수적인 시간 복잡도를 가지는 완전 탐색 문제에서 `N`이 너무 커서 `2^N` 계산이 불가능할 때, `2^(N/2)`는 가능한 경우에 사용됩니다.

예를 들어, `N=40`인 문제에서 `2^40`은 너무 크지만, `2^20`은 약 100만으로 충분히 계산 가능합니다. MITM은 이 `2^(N/2)`의 아이디어를 활용하여 문제를 해결합니다.

### 6.1. 개념 및 활용 (탐색 공간 절반으로 줄이기)

Meet-in-the-Middle의 핵심 아이디어는 다음과 같습니다.

1.  **문제 분할:** 전체 문제를 두 개의 독립적인 하위 문제로 나눕니다. 예를 들어, `N`개의 원소를 다루는 문제라면, `N/2`개의 원소를 다루는 두 개의 하위 문제로 나눕니다.
2.  **독립적 탐색:** 각 하위 문제에 대해 가능한 모든 해(또는 필요한 정보)를 독립적으로 탐색하고 저장합니다. 이 과정에서 각각 `O(2^(N/2))`의 시간 복잡도가 소요됩니다.
3.  **결과 결합:** 두 하위 문제에서 얻은 결과들을 효율적인 방법(예: 정렬 후 투 포인터, 이진 탐색, 해시 테이블 등)으로 결합하여 전체 문제의 해를 찾습니다. 이 결합 과정은 일반적으로 `O(2^(N/2) * log(2^(N/2)))` 또는 `O(2^(N/2))`의 시간 복잡도를 가집니다.

이를 통해 전체 시간 복잡도는 `O(2^(N/2))` 또는 `O(2^(N/2) * N)` 정도로 줄어들게 됩니다. 하지만, 두 개의 `2^(N/2)` 크기의 결과를 저장해야 하므로 **공간 복잡도 또한 `O(2^(N/2))`**가 됩니다.

### 6.2. Meet-in-the-Middle 활용 문제 (예: 부분집합 합)

주어진 집합의 부분집합 중 합이 특정 값(target)이 되는 부분집합을 찾는 문제는 MITM의 대표적인 활용 사례입니다.

**문제:** `N`개의 정수로 이루어진 배열 `arr`에서, 부분집합의 합이 `target`이 되는 경우의 수를 찾으시오. (`N`이 최대 40 정도)

**MITM 적용 단계:**

1.  **배열 분할:** `arr`을 대략 절반 크기의 두 부분 배열 `arr1`과 `arr2`로 나눕니다.
    *   `arr1`: `arr[0]`부터 `arr[N/2 - 1]`까지
    *   `arr2`: `arr[N/2]`부터 `arr[N-1]`까지
2.  **부분합 계산:**
    *   `arr1`의 모든 부분집합 합을 계산하여 리스트 `sums1`에 저장합니다.
    *   `arr2`의 모든 부분집합 합을 계산하여 리스트 `sums2`에 저장합니다.
    *   이 과정은 각각 `O(2^(N/2))`의 시간 복잡도를 가집니다.
3.  **결과 결합:**
    *   `sums2`를 정렬합니다. (`O(2^(N/2) * N)`) 
    *   `sums1`의 각 원소 `s1`에 대해, `sums2`에서 `target - s1`을 이진 탐색(또는 투 포인터)으로 찾습니다.
    *   `sums2`에서 `target - s1`을 찾는 과정은 `O(log(2^(N/2))) = O(N/2)`이므로, 총 결합 시간은 `O(2^(N/2) * N)`이 됩니다.

**예시 코드: 부분집합 합 (Python)**

```python
def solve_subset_sum_mitm(arr, target):
    n = len(arr)
    mid = n // 2

    # 1. 배열을 두 부분으로 나눔
    arr1 = arr[:mid]
    arr2 = arr[mid:]

    # 2. 각 부분 배열의 모든 부분집합 합을 계산
    sums1 = []
    for i in range(1 << len(arr1)): # 2^len(arr1) 만큼 반복
        current_sum = 0
        for j in range(len(arr1)):
            if (i >> j) & 1: # j번째 원소가 포함되는지 확인
                current_sum += arr1[j]
        sums1.append(current_sum)

    sums2 = []
    for i in range(1 << len(arr2)): # 2^len(arr2) 만큼 반복
        current_sum = 0
        for j in range(len(arr2)):
            if (i >> j) & 1:
                current_sum += arr2[j]
        sums2.append(current_sum)

    # 3. sums2를 정렬하여 이진 탐색 준비
    sums2.sort()

    count = 0
    # 4. sums1의 각 합에 대해 sums2에서 보완하는 합을 찾음
    for s1 in sums1:
        # target - s1을 sums2에서 찾기 (이진 탐색)
        # sums2에서 target - s1과 같은 값의 개수를 효율적으로 찾기 위해 bisect_left, bisect_right 사용
        from bisect import bisect_left, bisect_right
        
        lower_bound = bisect_left(sums2, target - s1)
        upper_bound = bisect_right(sums2, target - s1)
        
        count += (upper_bound - lower_bound)
        
    return count

# 예시 사용
# arr = [1, 2, 3, 4, 5,  7, 8, 9, 10, 11, 12, 13, 14, 15, 1 17, 18, 19, 20, 21, 22, 23, 24, 25, 2 27, 28, 29, 30, 31, 32, 33, 34, 35, 3 37, 38, 39, 40]
# target = 200
# print(solve_subset_sum_mitm(arr, target)) # N=40일 때 2^40은 불가능, 2^20은 가능
```

### 6.3. 다른 활용 사례

*   **XOR 합 문제:** 특정 XOR 합을 만드는 부분집합을 찾는 문제.
*   **두 부분의 합이 같은 문제:** 배열을 두 부분으로 나누어 각 부분의 합이 같도록 하는 문제.
*   **최소 차이 부분합:** 배열을 두 부분으로 나누어 두 부분합의 차이가 최소가 되도록 하는 문제.

Meet-in-the-Middle은 지수 시간 복잡도를 가지는 완전 탐색 문제의 효율을 크게 향상시킬 수 있는 강력한 기법이지만, `O(2^(N/2))`의 공간 복잡도를 고려해야 합니다.

## 7. 확률적 알고리즘 (Randomized Algorithms)

확률적 알고리즘(Randomized Algorithms)은 **알고리즘의 동작 과정에 의도적으로 무작위성(randomness)을 도입하여 문제를 해결하는 기법**입니다. 이는 결정론적(deterministic) 알고리즘이 너무 복잡하거나 비효율적일 때, 또는 근사 해(approximate solution)를 빠르게 찾아야 할 때 유용하게 사용됩니다. 무작위성은 입력 데이터가 아닌, 알고리즘 자체의 논리 흐름에 사용됩니다.

### 7.1. 개념 및 특징 (라스베이거스, 몬테카를로)

확률적 알고리즘은 결과의 정확성 또는 실행 시간의 보장 여부에 따라 크게 두 가지 유형으로 나뉩니다.

1.  **라스베이거스 알고리즘 (Las Vegas Algorithm):**
    *   **항상 올바른 답을 찾습니다.** 즉, 결과의 정확성은 100% 보장됩니다.
    *   하지만, **실행 시간은 확률적**입니다. 최악의 경우 실행 시간이 매우 길어질 수 있지만, 평균적으로는 효율적입니다.
    *   **예시:** **랜덤화 퀵정렬 (Randomized Quicksort)**. 피벗을 무작위로 선택하여 최악의 경우(O(N^2))가 나타날 확률을 줄이고 평균적으로 O(N log N)의 성능을 보장합니다.

2.  **몬테카를로 알고리즘 (Monte Carlo Algorithm):**
    *   **실행 시간은 결정론적**으로 고정되어 있습니다.
    *   하지만, **정답을 찾을 확률이 있습니다.** 즉, 일정 확률로 오답을 반환할 수 있습니다.
    *   **오류 확률 감소:** 알고리즘을 여러 번 반복 실행하여 얻은 결과를 종합하면 오류 확률을 원하는 만큼 낮출 수 있습니다.
    *   **예시:** **밀러-라빈 소수 판별법 (Miller-Rabin Primality Test)**. 주어진 큰 수가 소수인지 아닌지 판별하는 데 사용되며, 일정 확률로 합성수를 소수라고 잘못 판별할 수 있습니다.

### 7.2. 활용 사례

확률적 알고리즘은 다양한 분야에서 활용됩니다.

*   **Quickselect (랜덤화 선택):**
    *   정렬되지 않은 배열에서 k번째로 작은(또는 큰) 요소를 찾는 알고리즘입니다. 퀵정렬과 유사하게 피벗을 무작위로 선택하여 평균적으로 `O(N)`의 시간 복잡도를 가집니다.
    *   **동작 과정 (예시: `arr = [3, 2, 1, 5, 4]`, `k = 2` (0-indexed, 3번째로 작은 값))**
        1.  **초기 호출:** `quickselect([3, 2, 1, 5, 4], 2)`
        2.  **피벗 선택:** `random.choice(arr)`를 통해 예를 들어 `3`이 피벗으로 선택됩니다.
        3.  **분할:**
            *   `less = [2, 1]`
            *   `equal = [3]`
            *   `greater = [5, 4]`
        4.  **k와 부분 배열 길이 비교:**
            *   `k (2)`는 `len(less) (2)`보다 작지 않습니다. (`2 < 2`는 거짓)
            *   `k (2)`는 `len(less) + len(equal) (2 + 1 = 3)`보다 작습니다. (`2 < 3`은 참)
            *   따라서 `equal` 부분에 k번째 요소가 있습니다. `equal[0]`인 `3`을 반환합니다.

        *   **다른 예시: `arr = [9, 8, 7,  5, 4, 3, 2, 1]`, `k = 4` (0-indexed, 5번째로 작은 값)**
            1.  **초기 호출:** `quickselect([9, 8, 7,  5, 4, 3, 2, 1], 4)`
            2.  **피벗 선택:** 예를 들어 `이 피벗으로 선택됩니다.
            3.  **분할:**
                *   `less = [5, 4, 3, 2, 1]`
                *   `equal = [`
                *   `greater = [9, 8, 7]`
            4.  **k와 부분 배열 길이 비교:**
                *   `k (4)`는 `len(less) (5)`보다 작습니다. (`4 < 5`는 참)
                *   재귀 호출: `quickselect(less, k)` 즉, `quickselect([5, 4, 3, 2, 1], 4)`
            5.  **재귀 호출 내부:** `quickselect([5, 4, 3, 2, 1], 4)`
                *   **피벗 선택:** 예를 들어 `4`가 피벗으로 선택됩니다.
                *   **분할:**
                    *   `less = [3, 2, 1]`
                    *   `equal = [4]`
                    *   `greater = [5]`
                *   **k와 부분 배열 길이 비교:**
                    *   `k (4)`는 `len(less) (3)`보다 작지 않습니다. (`4 < 3`은 거짓)
                    *   `k (4)`는 `len(less) + len(equal) (3 + 1 = 4)`보다 작지 않습니다. (`4 < 4`는 거짓)
                    *   `k (4)`는 `len(less) + len(equal) (4)`보다 크거나 같습니다.
                    *   재귀 호출: `quickselect(greater, k - len(less) - len(equal))` 즉, `quickselect([5], 4 - 3 - 1)` -> `quickselect([5], 0)`
                  **재귀 호출 내부:** `quickselect([5], 0)`
                    *   **피벗 선택:** `5`가 피벗으로 선택됩니다.
                    *   **분할:**
                        *   `less = []`
                        *   `equal = [5]`
                        *   `greater = []`
                    *   **k와 부분 배열 길이 비교:**
                        *   `k (0)`는 `len(less) (0)`보다 작지 않습니다. (`0 < 0`은 거짓)
                        *   `k (0)`는 `len(less) + len(equal) (0 + 1 = 1)`보다 작습니다. (`0 < 1`은 참)
                        *   따라서 `equal` 부분에 k번째 요소가 있습니다. `equal[0]`인 `5`를 반환합니다.
            7.  최종적으로 `5`가 반환됩니다.

    *   **예시 코드: Quickselect (랜덤 피벗 선택)**
        ```python
        import random

        def quickselect(arr, k):
            if not arr:
                return None

            pivot = random.choice(arr) # 무작위 피벗 선택
            
            # 피벗을 기준으로 세 부분으로 분할
            less = [x for x in arr if x < pivot]
            equal = [x for x in arr if x == pivot]
            greater = [x for x in arr if x > pivot]

            if k < len(less): # k가 less 부분에 있다면
                return quickselect(less, k)
            elif k < len(less) + len(equal): # k가 equal 부분에 있다면
                return equal[0] # 피벗이 k번째 요소
            else: # k가 greater 부분에 있다면
                return quickselect(greater, k - len(less) - len(equal))

        # print(quickselect([3, 2, 1, 5, 4], 2)) # 0-indexed, 2번째로 작은 값 (3)
        # print(quickselect([9, 8, 7,  5, 4, 3, 2, 1], 4)) # 4번째로 작은 값 (5)
        ```

*   **Miller-Rabin 소수 판별법 (Miller-Rabin Primality Test):**
    *   매우 큰 수가 소수인지 아닌지 판별하는 데 사용되는 몬테카를로 알고리즘입니다. 특정 횟수만큼 테스트를 수행하여 소수일 확률을 높입니다. 완벽한 정확성은 아니지만, 실용적으로 충분히 높은 신뢰도를 제공합니다.

*   **해싱 (Hashing):**
    *   해시 테이블에서 충돌을 줄이기 위해 무작위 해시 함수를 사용하거나, 유니버설 해싱과 같은 기법을 사용합니다.

*   **로드 밸런싱 (Load Balancing):**
    *   네트워크 트래픽을 여러 서버에 무작위로 분산하여 부하를 균등하게 만듭니다.

*   **암호학 (Cryptography):**
    *   안전한 키 생성, 난수 생성 등 다양한 암호학적 응용에 무작위성이 필수적으로 사용됩니다.

### 7.3. 장점과 단점

*   **장점:**
    *   **단순성:** 결정론적 알고리즘보다 구현이 더 간단할 수 있습니다.
    *   **효율성:** 특정 문제에서 결정론적 알고리즘보다 평균적으로 훨씬 빠를 수 있습니다.
    *   **복잡성 감소:** 복잡한 문제의 해결책을 찾는 데 도움이 될 수 있습니다.
*   **단점:**
    *   **비결정론적 결과:** 몬테카를로 알고리즘의 경우 항상 정확한 답을 보장하지 않습니다.
    *   **실행 시간 변동:** 라스베이거스 알고리즘의 경우 실행 시간이 예측 불가능할 수 있습니다.
    *   **난수 생성:** 진정한 무작위성을 얻기 위한 고품질 난수 생성기가 필요합니다.

## 8. 수론 (Number Theory) 및 수학적 알고리즘

수론(Number Theory) 및 수학적 알고리즘은 정수론, 조합론, 행렬 등 수학적 개념을 활용하여 문제를 해결하는 기법입니다. 이들은 암호학, 최적화, 확률 계산, 그리고 특히 경쟁 프로그래밍에서 다양한 문제 해결의 핵심 도구로 사용됩니다.
