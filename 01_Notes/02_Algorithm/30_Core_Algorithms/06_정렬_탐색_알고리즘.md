## 1. 정렬 알고리즘 (Sorting Algorithms)

정렬 알고리즘은 데이터를 특정 기준에 따라 순서대로 나열하는 알고리즘입니다. 효율적인 정렬은 데이터 처리 및 검색 성능에 큰 영향을 미칩니다.

### 1.1. 버블 정렬 (Bubble Sort)

버블 정렬은 인접한 두 요소를 비교하여 정렬하는 가장 간단한 정렬 알고리즘입니다. 비효율적이지만 개념 이해에 용이합니다. 각 패스(pass)에서 가장 큰(또는 작은) 요소가 배열의 끝으로 '거품처럼' 이동합니다.

*   **개념:** 배열의 첫 요소부터 인접한 두 요소를 비교하여 정렬 순서에 맞게 교환합니다. 가장 큰(또는 작은) 요소가 배열의 끝으로 '거품처럼' 이동합니다.

*   **동작 과정:**
    1.  첫 번째 요소부터 시작하여 인접한 두 요소를 비교합니다.
    2.  정렬 순서에 맞지 않으면 두 요소를 교환합니다. (예: 오름차순 정렬 시, 앞의 요소가 뒤의 요소보다 크면 교환)
    3.  이 과정을 배열의 끝까지 반복하면, 가장 큰(또는 작은) 요소가 배열의 마지막 위치로 이동합니다. 이를 '첫 번째 패스'라고 합니다.
    4.  다음 패스에서는 마지막에 정렬된 요소를 제외한 나머지 배열에 대해 1~3단계를 반복합니다.
    5.  이 과정을 배열의 모든 요소가 정렬될 때까지 반복합니다.

*   **시각적 이해를 위한 단계별 예시:**
    작은 배열 `[5, 1, 4, 2, 8]`을 예시로 들어 단계별 동작 과정을 시각적으로 설명합니다.

    **예시 배열: `[5, 1, 4, 2, 8]`**

    **1단계: 첫 번째 패스 (가장 큰 값 8이 마지막으로 이동)**
    *   `(5, 1)` 비교 -> `5 > 1` 이므로 교환: `[1, 5, 4, 2, 8]`
    *   `(5, 4)` 비교 -> `5 > 4` 이므로 교환: `[1, 4, 5, 2, 8]`
    *   `(5, 2)` 비교 -> `5 > 2` 이므로 교환: `[1, 4, 2, 5, 8]`
    *   `(5, 8)` 비교 -> `5 < 8` 이므로 교환 없음: `[1, 4, 2, 5, 8]`
    *   **결과:** `[1, 4, 2, 5, | 8]` (8은 정렬 완료)

    **2단계: 두 번째 패스 (두 번째로 큰 값 5가 제자리로 이동)**
    *   `[1, 4, 2, 5]` 에 대해 반복
    *   `(1, 4)` 비교 -> 교환 없음: `[1, 4, 2, 5, 8]`
    *   `(4, 2)` 비교 -> `4 > 2` 이므로 교환: `[1, 2, 4, 5, 8]`
    *   `(4, 5)` 비교 -> 교환 없음: `[1, 2, 4, 5, 8]`
    *   **결과:** `[1, 2, 4, | 5, 8]` (5, 8은 정렬 완료)

    **3단계: 세 번째 패스 (세 번째로 큰 값 4가 제자리로 이동)**
    *   `[1, 2, 4]` 에 대해 반복
    *   `(1, 2)` 비교 -> 교환 없음: `[1, 2, 4, 5, 8]`
    *   `(2, 4)` 비교 -> 교환 없음: `[1, 2, 4, 5, 8]`
    *   **결과:** `[1, 2, | 4, 5, 8]` (4, 5, 8은 정렬 완료)

    **4단계: 네 번째 패스 (네 번째로 큰 값 2가 제자리로 이동)**
    *   `[1, 2]` 에 대해 반복
    *   `(1, 2)` 비교 -> 교환 없음: `[1, 2, 4, 5, 8]`
    *   **결과:** `[1, | 2, 4, 5, 8]` (2, 4, 5, 8은 정렬 완료)

    **최종 정렬된 배열: `[1, 2, 4, 5, 8]`**

*   **시간 복잡도:**
    *   **최선 `O(n)`:** 배열이 이미 정렬되어 있는 경우 (최적화된 버블 정렬, 즉 한 번의 패스에서 교환이 전혀 일어나지 않으면 정렬이 완료된 것으로 판단하여 종료).
    *   **최악 `O(n^2)`:** 배열이 역순으로 정렬되어 있는 경우.
    *   **평균 `O(n^2)`:** 대부분의 경우 `n^2`에 비례합니다.
    *   이중 반복문 구조를 가집니다. 외부 루프가 `n-1`번 반복하고, 내부 루프는 `(n-1), (n-2), ..., 1`번의 비교를 수행합니다. 총 비교 횟수는 `(n-1) + (n-2) + ... + 1 = n(n-1)/2` 이므로, `O(n^2)`의 시간 복잡도를 가집니다.

*   **구현:**
```python
def bubble_sort(arr):
    n = len(arr)
    # 배열의 크기만큼 반복 (패스)
    for i in range(n):
        # 한 패스 동안 교환이 발생했는지 확인하는 플래그
        swapped = False
        # 마지막 i개 요소는 이미 정렬되었으므로 제외
        # j는 0부터 n-i-1까지 반복
        for j in range(0, n - i - 1):
            # 현재 요소가 다음 요소보다 크면 교환 (오름차순 정렬)
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True # 교환 발생
        
        # 한 패스 동안 교환이 전혀 없었다면, 배열은 이미 정렬된 상태이므로 종료
        if not swapped:
            break
    return arr

# 예시
# print(bubble_sort([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
# print(bubble_sort([5, 1, 4, 2, 8])) # [1, 2, 4, 5, 8]
```
*   **특징:**
    *   **안정 정렬(Stable Sort):** 값이 같은 요소들의 상대적인 순서가 정렬 후에도 유지됩니다. 인접한 요소만 비교하고 교환하기 때문에 같은 값의 순서가 바뀌지 않습니다.
    *   **제자리 정렬(In-place Sort):** 정렬을 위한 추가적인 저장 공간이 거의 필요하지 않아 공간 복잡도는 `O(1)`입니다.

*   **장점 및 단점:**
    *   **장점:**
        *   알고리즘의 동작 방식이 매우 직관적이고 이해하기 쉽습니다.
        *   구현이 간단합니다.
        *   거의 정렬된 배열에 대해서는 효율적일 수 있습니다 (최적화된 버블 정렬의 경우).
    *   **단점:**
        *   데이터의 양이 많아질수록 성능이 `O(n^2)`으로 급격히 저하되어 비효율적입니다.
        *   최악의 경우(역순 정렬)에는 모든 비교와 교환이 발생하여 성능이 가장 나쁩니다.
        *   실제 응용에서는 거의 사용되지 않습니다. 교육용으로 주로 활용됩니다.

### 1.2. 선택 정렬 (Selection Sort)

선택 정렬은 이름 그대로 정렬되지 않은 데이터 중에서 **가장 작은(또는 가장 큰) 원소를 선택**하여 정렬된 부분의 맨 뒤로 보내는 과정을 반복하는 알고리즘입니다. 전체 배열을 정렬된 부분과 정렬되지 않은 부분으로 나누어 동작하며, 구현이 간단하다는 특징이 있습니다.

*   **동작 과정:**
    1.  전체 배열에서 최솟값을 찾습니다.
    2.  찾은 최솟값을 배열의 첫 번째 요소와 교환합니다. 이제 첫 번째 요소는 정렬된 것으로 간주합니다.
    3.  첫 번째 요소를 제외한 나머지(정렬되지 않은 부분)에서 다시 최솟값을 찾습니다.
    4.  찾은 최솟값을 정렬되지 않은 부분의 첫 번째 요소(전체 배열에서는 두 번째 요소)와 교환합니다.
    5.  이 과정을 정렬되지 않은 부분이 없어질 때까지 반복합니다.

*   **시각적 이해를 위한 단계별 예시:**
    선택 정렬의 동작을 더 명확하게 이해하기 위해, 작은 배열 `[5, 2, 4, 1, 3]`을 예시로 들어 단계별 동작 과정을 시각적으로 설명합니다.
    선택 정렬은 배열을 **정렬된 부분**과 **정렬되지 않은 부분**으로 나누어 진행합니다.

    **예시 배열: `[5, 2, 4, 1, 3]`**

    **1단계: 첫 번째 요소 정렬 (인덱스 0)**
    *   **정렬되지 않은 부분:** `[5, 2, 4, 1, 3]`
    *   **목표:** 정렬되지 않은 부분에서 가장 작은 값(1)을 찾아 현재 위치(인덱스 0)의 값(5)과 교환합니다.
        *   `5`와 `2` 비교 -> `2`가 더 작음
        *   `2`와 `4` 비교 -> `2`가 더 작음
        *   `2`와 `1` 비교 -> `1`이 더 작음 (현재 최솟값: 1, 인덱스: 3)
        *   `1`과 `3` 비교 -> `1`이 더 작음
    *   **최솟값:** `1` (인덱스 3)
    *   **교환:** `arr[0]` (5) 와 `arr[3]` (1) 교환
    *   **결과 배열:** `[1, 2, 4, 5, 3]`
    *   **상태:** `[1]` (정렬됨) `[2, 4, 5, 3]` (정렬되지 않음)

    **2단계: 두 번째 요소 정렬 (인덱스 1)**
    *   **정렬되지 않은 부분:** `[2, 4, 5, 3]`
    *   **목표:** 정렬되지 않은 부분에서 가장 작은 값(2)을 찾아 현재 위치(인덱스 1)의 값(2)과 교환합니다.
        *   `2`와 `4` 비교 -> `2`가 더 작음
        *   `2`와 `5` 비교 -> `2`가 더 작음
        *   `2`와 `3` 비교 -> `2`가 더 작음
    *   **최솟값:** `2` (인덱스 1)
    *   **교환:** `arr[1]` (2) 와 `arr[1]` (2) 교환 (자기 자신과 교환, 변화 없음)
    *   **결과 배열:** `[1, 2, 4, 5, 3]`
    *   **상태:** `[1, 2]` (정렬됨) `[4, 5, 3]` (정렬되지 않음)

    **3단계: 세 번째 요소 정렬 (인덱스 2)**
    *   **정렬되지 않은 부분:** `[4, 5, 3]`
    *   **목표:** 정렬되지 않은 부분에서 가장 작은 값(3)을 찾아 현재 위치(인덱스 2)의 값(4)과 교환합니다.
        *   `4`와 `5` 비교 -> `4`가 더 작음
        *   `4`와 `3` 비교 -> `3`이 더 작음 (현재 최솟값: 3, 인덱스: 4)
    *   **최솟값:** `3` (인덱스 4)
    *   **교환:** `arr[2]` (4) 와 `arr[4]` (3) 교환
    *   **결과 배열:** `[1, 2, 3, 5, 4]`
    *   **상태:** `[1, 2, 3]` (정렬됨) `[5, 4]` (정렬되지 않음)

    **4단계: 네 번째 요소 정렬 (인덱스 3)**
    *   **정렬되지 않은 부분:** `[5, 4]`
    *   **목표:** 정렬되지 않은 부분에서 가장 작은 값(4)을 찾아 현재 위치(인덱스 3)의 값(5)과 교환합니다.
        *   `5`와 `4` 비교 -> `4`가 더 작음 (현재 최솟값: 4, 인덱스: 4)
    *   **최솟값:** `4` (인덱스 4)
    *   **교환:** `arr[3]` (5) 와 `arr[4]` (4) 교환
    *   **결과 배열:** `[1, 2, 3, 4, 5]`
    *   **상태:** `[1, 2, 3, 4]` (정렬됨) `[5]` (정렬되지 않음)

    **5단계: 마지막 요소 (인덱스 4)**
    *   마지막 요소는 자동으로 정렬된 상태가 됩니다.

    **최종 정렬된 배열: `[1, 2, 3, 4, 5]`**

*   **시간 복잡도:** `O(n^2)` (최선, 최악, 평균 모두)
    *   이중 반복문 구조를 가집니다. 외부 루프가 `n-1`번 반복하고, 내부 루프는 최솟값을 찾기 위해 `(n-1), (n-2), ..., 1`번의 비교를 수행합니다. 총 비교 횟수는 `(n-1) + (n-2) + ... + 1 = n(n-1)/2` 이므로, `O(n^2)`의 시간 복잡도를 가집니다. 데이터의 초기 상태와 관계없이 항상 같은 횟수의 비교를 수행합니다.

*   **구현:**
```python
def selection_sort(arr):
    n = len(arr)
    # 배열의 전체 길이에 대해 반복
    for i in range(n):
        # 현재 인덱스(i)를 최솟값의 인덱스로 가정
        min_idx = i
        # i+1부터 배열의 끝까지 순회하며 실제 최솟값의 인덱스를 찾음
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j

        # 찾은 최솟값(arr[min_idx])을 현재 정렬 위치(arr[i])와 교환
        # 이 교환은 i번째 원소를 올바른 위치에 놓는 것을 의미
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

# 예시
# print(selection_sort([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
```
*   **특징:**
    *   **불안정 정렬(Unstable Sort):** 값이 같은 요소들의 상대적인 순서가 정렬 과정에서 바뀔 수 있습니다. 예를 들어, `[5a, 5b, 2]` 배열에서 첫 단계에 최솟값 `2`를 찾아 `5a`와 교환하면 `[2, 5b, 5a]`가 되어 `5a`와 `5b`의 순서가 바뀝니다.
    *   **제자리 정렬(In-place Sort):** 정렬을 위한 추가적인 저장 공간이 거의 필요하지 않아 공간 복잡도는 `O(1)`입니다.

*   **장점 및 단점:**
    *   **장점:** 알고리즘의 동작 방식이 직관적이고 구현이 매우 간단합니다. 추가 메모리 소비가 적습니다.
    *   **단점:** 데이터의 양이 많아질수록 성능이 `O(n^2)`으로 급격히 저하되어 비효율적입니다. 데이터가 이미 정렬되어 있어도 최선, 평균, 최악의 시간 복잡도가 모두 동일하다는 단점이 있습니다.

### 1.3. 퀵 정렬 (Quick Sort)

퀵 정렬은 **분할 정복(Divide and Conquer)** 방식을 사용하는 효율적인 정렬 알고리즘입니다. 평균적으로 매우 빠르며, 대부분의 실제 환경에서 가장 많이 사용되는 정렬 알고리즘 중 하나입니다.

*   **개념:**
    1.  **분할 (Divide):** 배열 내에서 '피벗(Pivot)' 요소를 선택합니다.
    2.  **정복 (Conquer):** 피벗을 기준으로 배열을 두 개의 부분 배열로 나눕니다. 피벗보다 작은 요소는 피벗의 왼쪽으로, 큰 요소는 피벗의 오른쪽으로 이동시킵니다. 이 과정을 통해 피벗은 최종 정렬 위치에 놓이게 됩니다.
    3.  **결합 (Combine):** 분할된 두 부분 배열에 대해 재귀적으로 퀵 정렬을 수행합니다. 부분 배열들이 더 이상 분할할 수 없을 때(요소가 0 또는 1개)까지 반복하며, 정렬된 부분 배열들이 자연스럽게 합쳐져 전체 정렬된 배열을 형성합니다.

*   **분할 (Partitioning) 과정:**
    피벗 선택 전략(예: 첫 번째 요소, 마지막 요소, 중간 요소, 랜덤 요소)에 따라 성능이 달라질 수 있습니다. 피벗을 선택한 후, 배열을 순회하며 피벗보다 작은 요소는 왼쪽으로, 큰 요소는 오른쪽으로 옮깁니다. 이 과정이 끝나면 피벗은 자신의 최종 정렬 위치에 놓이게 됩니다.

*   **동작 과정 (예시: `[64, 34, 25, 12, 22, 11, 90]`)**
    여기서는 구현의 편의를 위해 중간 요소를 피벗으로 선택하는 방식을 따릅니다.

    1.  **초기 배열:** `[64, 34, 25, 12, 22, 11, 90]`
        *   피벗 선택: `arr[len(arr) // 2]` = `arr[3]` = `12` (실제 구현에서는 `22`가 피벗이 될 수 있음. 여기서는 예시를 위해 `12`로 가정)
        *   피벗보다 작은 요소: `[11]`
        *   피벗과 같은 요소: `[12]`
        *   피벗보다 큰 요소: `[64, 34, 25, 22, 90]`
        *   **결과:** `quick_sort([11])` + `[12]` + `quick_sort([64, 34, 25, 22, 90])`

    2.  **좌측 재귀 호출:** `quick_sort([11])`
        *   길이가 1이므로 `[11]` 반환.

    3.  **우측 재귀 호출:** `quick_sort([64, 34, 25, 22, 90])`
        *   피벗 선택: `arr[len(arr) // 2]` = `arr[2]` = `25`
        *   피벗보다 작은 요소: `[22]`
        *   피벗과 같은 요소: `[25]`
        *   피벗보다 큰 요소: `[64, 34, 90]`
        *   **결과:** `quick_sort([22])` + `[25]` + `quick_sort([64, 34, 90])`

    4.  **... (재귀적으로 반복)**
        이런 식으로 부분 배열들이 계속 분할되고 정렬되어 최종적으로 모든 요소가 정렬됩니다.

*   **시간 복잡도:**
    *   **평균 `O(n log n)`:** 피벗이 배열을 거의 절반으로 나누는 경우에 발생합니다. 각 분할 단계에서 `n`개의 요소를 한 번씩 검사하므로 `O(n)` 시간이 걸리고, 이러한 분할이 `log n`번 발생하기 때문입니다.
    *   **최악 `O(n^2)`:** 피벗이 항상 가장 작은 요소나 가장 큰 요소로 선택되는 경우(예: 이미 정렬된 배열에서 첫 번째 요소를 피벗으로 선택) 발생합니다. 이 경우 한쪽 부분 배열은 비어있고 다른 쪽 부분 배열은 `n-1`개의 요소를 가지게 되어, 매 단계마다 `n`개의 요소를 검사하는 작업이 `n`번 반복됩니다.
    *   **공간 복잡도:** `O(log n)` (재귀 스택) - 최악의 경우 `O(n)`이 될 수 있습니다.

*   **구현 (Python의 리스트 컴프리헨션을 이용한 간결한 구현):**
```python
def quick_sort(arr):
    # 배열의 길이가 1 이하이면 이미 정렬된 것으로 간주하고 반환
    if len(arr) <= 1:
        return arr
    
    # 피벗 선택: 여기서는 배열의 중간 요소를 피벗으로 선택 (다양한 전략 가능)
    pivot = arr[len(arr) // 2] 
    
    # 피벗보다 작은 요소들로 이루어진 리스트
    left = [x for x in arr if x < pivot]
    # 피벗과 같은 요소들로 이루어진 리스트
    middle = [x for x in arr if x == pivot]
    # 피벗보다 큰 요소들로 이루어진 리스트
    right = [x for x in arr if x > pivot]
    
    # 재귀적으로 left와 right를 정렬한 후, middle과 합쳐서 반환
    return quick_sort(left) + middle + quick_sort(right)

# 예시
# print(quick_sort([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
```
*   **특징:**
    *   **불안정 정렬(Unstable Sort):** 일반적인 퀵 정렬 구현은 안정 정렬이 아닙니다. 피벗과의 비교 및 교환 과정에서 같은 값을 가진 요소들의 상대적인 순서가 바뀔 수 있습니다.
    *   **제자리 정렬(In-place Sort) 가능:** 위 Python 구현은 리스트 컴프리헨션을 사용하여 추가적인 공간을 사용하지만, 일반적인 퀵 정렬은 배열 내에서 직접 요소를 교환하는 방식으로 구현되어 제자리 정렬이 가능합니다.

*   **장점 및 단점:**
    *   **장점:** 평균적으로 가장 빠른 정렬 알고리즘 중 하나입니다. 대부분의 경우 `O(n log n)`의 성능을 보이며, 캐시 효율이 좋습니다.
    *   **단점:** 최악의 경우 `O(n^2)`의 성능을 보일 수 있습니다 (피벗 선택 전략에 따라 다름). 안정 정렬이 아니므로, 같은 값을 가진 요소들의 상대적인 순서가 중요할 때는 다른 정렬 알고리즘을 고려해야 합니다.

### 1.4. 기타 정렬 알고리즘 개요 (병합 정렬, 힙 정렬 등)

*   **병합 정렬 (Merge Sort):**

    병합 정렬은 **분할 정복(Divide and Conquer)** 방식을 사용하는 효율적인 정렬 알고리즘입니다. 데이터를 절반으로 계속 나누어 더 이상 나눌 수 없을 때까지 분할한 후, 분할된 부분들을 다시 정렬하면서 병합하는 과정을 반복하여 전체 배열을 정렬합니다.

    *   **개념:**
        1.  **분할 (Divide):** 정렬되지 않은 리스트를 하나의 요소만 남을 때까지 계속해서 절반으로 나눕니다.
        2.  **정복 (Conquer):** 분할된 각 부분 리스트를 정렬합니다. (요소가 하나인 리스트는 이미 정렬된 것으로 간주)
        3.  **결합 (Combine/Merge):** 정렬된 부분 리스트들을 다시 병합하여 더 큰 정렬된 리스트를 만듭니다. 이 병합 과정에서 두 부분 리스트의 요소들을 비교하여 올바른 순서로 새로운 리스트에 추가합니다.

    *   **동작 과정 (예시: `[38, 27, 43, 3, 9, 82, 10]`)**

        1.  **분할 단계:**
            *   `[38, 27, 43, 3, 9, 82, 10]`
            *   `[38, 27, 43, 3]` | `[9, 82, 10]`
            *   `[38, 27]` | `[43, 3]` | `[9, 82]` | `[10]`
            *   `[38]` | `[27]` | `[43]` | `[3]` | `[9]` | `[82]` | `[10]` (더 이상 분할 불가)

        2.  **병합 단계:**
            *   `[27, 38]` (27, 38 병합) | `[3, 43]` (3, 43 병합) | `[9, 82]` (9, 82 병합) | `[10]`
            *   `[3, 27, 38, 43]` (27,38과 3,43 병합) | `[9, 10, 82]` (9,82와 10 병합)
            *   `[3, 9, 10, 27, 38, 43, 82]` (최종 병합)

    *   **시간 복잡도:**
        *   **최선, 최악, 평균 모두 `O(n log n)`:**
            *   **분할:** 리스트를 절반으로 나누는 과정은 `log n`번 발생합니다.
            *   **병합:** 각 병합 단계에서 `n`개의 요소를 비교하고 이동하는 데 `O(n)` 시간이 걸립니다. `log n`번의 병합 단계가 있으므로 총 시간 복잡도는 `O(n log n)`이 됩니다.

    *   **구현:**
    ```python
    def merge_sort(arr):
        # 리스트의 길이가 1 이하이면 이미 정렬된 것으로 간주하고 반환
        if len(arr) <= 1:
            return arr
        
        # 리스트를 절반으로 분할
        mid = len(arr) // 2
        left_half = arr[:mid]
        right_half = arr[mid:]

        # 분할된 각 부분을 재귀적으로 정렬
        left = merge_sort(left_half)
        right = merge_sort(right_half)

        # 정렬된 두 부분을 병합하여 반환
        return merge(left, right)

    def merge(left, right):
        merged = []
        left_idx, right_idx = 0, 0

        # 두 리스트의 요소들을 비교하여 merged 리스트에 추가
        while left_idx < len(left) and right_idx < len(right):
            if left[left_idx] < right[right_idx]:
                merged.append(left[left_idx])
                left_idx += 1
            else:
                merged.append(right[right_idx])
                right_idx += 1

        # 남아있는 요소들을 모두 merged 리스트에 추가
        merged.extend(left[left_idx:])
        merged.extend(right[right_idx:])
        return merged

    # 예시
    # print(merge_sort([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
    ```

    *   **특징:**
        *   **안정 정렬(Stable Sort):** 값이 같은 요소들의 상대적인 순서가 정렬 후에도 유지됩니다. 병합 과정에서 같은 값을 가진 요소들의 순서를 보장할 수 있습니다.
        *   **제자리 정렬(In-place Sort) 아님:** 병합 과정에서 추가적인 임시 배열이 필요하므로 `O(n)`의 추가 공간 복잡도를 가집니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   데이터의 크기에 관계없이 항상 `O(n log n)`의 안정적인 성능을 보장합니다.
            *   안정 정렬이므로 같은 값을 가진 요소들의 상대적인 순서가 유지됩니다.
            *   외부 정렬(External Sorting)에 적합합니다 (메모리에 한 번에 로드할 수 없는 대용량 데이터 정렬).
        *   **단점:**
            *   추가적인 `O(n)`의 메모리 공간이 필요합니다. 이는 메모리 제약이 있는 환경에서는 단점이 될 수 있습니다.
            *   퀵 정렬에 비해 상수 인자가 커서 실제 성능이 약간 느릴 수 있습니다.
*   **힙 정렬 (Heap Sort):** 힙 자료구조를 활용한 정렬. `O(n log n)`. 제자리 정렬(In-place Sort)입니다.

    힙 정렬은 **힙(Heap)** 이라는 특수한 트리 기반 자료구조를 활용하는 정렬 알고리즘입니다. 배열을 힙 구조로 만든 후, 힙의 특성(최대 힙의 경우 루트 노드가 항상 최댓값)을 이용하여 정렬을 수행합니다.

    *   **개념:**
        1.  **힙 구성 (Heapify):** 주어진 배열을 최대 힙(Max Heap) 구조로 만듭니다. 최대 힙은 부모 노드의 값이 자식 노드의 값보다 항상 크거나 같은 완전 이진 트리입니다.
        2.  **정렬 (Sort):** 힙의 루트(가장 큰 값)를 배열의 마지막 요소와 교환하고, 힙의 크기를 1 줄입니다. 그리고 다시 힙 속성을 유지하도록 힙을 재구성(Heapify)합니다. 이 과정을 힙의 크기가 1이 될 때까지 반복합니다.

    *   **동작 과정 (예시: `[4, 10, 3, 5, 1]`)**

        1.  **초기 배열:** `[4, 10, 3, 5, 1]`

        2.  **힙 구성 (Max Heapify):**
            *   배열을 최대 힙으로 만듭니다. (일반적으로 배열의 중간부터 시작하여 아래에서 위로 힙 속성을 만족시킵니다.)
            *   `[10, 5, 3, 4, 1]` (최대 힙 구성 완료)
                *   (시각적으로는 다음과 같은 트리 구조)
                ```
                      10
                     /  \
                    5    3
                   / \
                  4   1
                ```

        3.  **정렬 단계:**

            *   **1회차:**
                *   루트(10)와 마지막 요소(1) 교환: `[1, 5, 3, 4, 10]`
                *   힙 크기 1 감소 (10은 정렬된 부분으로 간주)
                *   남은 힙 `[1, 5, 3, 4]`를 다시 힙 속성 유지하도록 재구성 (Heapify): `[5, 4, 3, 1]`
                *   **결과:** `[5, 4, 3, 1 | 10]`

            *   **2회차:**
                *   루트(5)와 마지막 요소(1) 교환: `[1, 4, 3, 5 | 10]`
                *   힙 크기 1 감소
                *   남은 힙 `[1, 4, 3]`를 재구성: `[4, 1, 3]`
                *   **결과:** `[4, 1, 3 | 5, 10]`

            *   **3회차:**
                *   루트(4)와 마지막 요소(3) 교환: `[3, 1, 4 | 5, 10]`
                *   힙 크기 1 감소
                *   남은 힙 `[3, 1]`를 재구성: `[3, 1]`
                *   **결과:** `[3, 1 | 4, 5, 10]`

            *   **4회차:**
                *   루트(3)와 마지막 요소(1) 교환: `[1, 3 | 4, 5, 10]`
                *   힙 크기 1 감소
                *   남은 힙 `[1]`를 재구성 (이미 정렬됨)
                *   **결과:** `[1 | 3, 4, 5, 10]`

        4.  **최종 정렬된 배열:** `[1, 3, 4, 5, 10]`

    *   **시간 복잡도:**
        *   **최선, 최악, 평균 모두 `O(n log n)`:**
            *   **힙 구성:** `n`개의 요소를 힙으로 만드는 데 `O(n)` 시간이 걸립니다.
            *   **정렬:** `n`번의 추출 및 힙 재구성(Heapify)이 발생합니다. 각 Heapify 작업은 힙의 높이(`log n`)에 비례하는 시간이 걸리므로, 총 `n * O(log n) = O(n log n)` 시간이 걸립니다.

    *   **구현:**
    ```python
    def heap_sort(arr):
        n = len(arr)

        # 1. 힙 구성 (Max Heapify)
        # 배열의 마지막 부모 노드부터 시작하여 루트까지 힙 속성을 만족시킴
        for i in range(n // 2 - 1, -1, -1):
            heapify(arr, n, i)

        # 2. 정렬
        # 힙의 루트(최댓값)를 배열의 마지막 요소와 교환하고 힙 재구성
        for i in range(n - 1, 0, -1):
            arr[i], arr[0] = arr[0], arr[i]  # 루트와 마지막 요소 교환
            heapify(arr, i, 0)  # 줄어든 힙에 대해 다시 힙 속성 유지

        return arr

    def heapify(arr, n, i):
        # i는 현재 부모 노드의 인덱스
        largest = i  # 가장 큰 값을 현재 부모로 가정
        left_child = 2 * i + 1  # 왼쪽 자식 노드의 인덱스
        right_child = 2 * i + 2  # 오른쪽 자식 노드의 인덱스

        # 왼쪽 자식이 존재하고, 현재 가장 큰 값보다 크면 largest 업데이트
        if left_child < n and arr[left_child] > arr[largest]:
            largest = left_child

        # 오른쪽 자식이 존재하고, 현재 가장 큰 값보다 크면 largest 업데이트
        if right_child < n and arr[right_child] > arr[largest]:
            largest = right_child

        # largest가 부모 노드(i)가 아니면, 교환하고 재귀적으로 힙 속성 유지
        if largest != i:
            arr[i], arr[largest] = arr[largest], arr[i]
            heapify(arr, n, largest) # 교환된 자식 노드에서 다시 힙 속성 검사
    ```

    *   **특징:**
        *   **불안정 정렬(Unstable Sort):** 힙 정렬은 일반적으로 불안정 정렬입니다. 요소의 교환 과정에서 같은 값을 가진 요소들의 상대적인 순서가 바뀔 수 있습니다.
        *   **제자리 정렬(In-place Sort):** 추가적인 메모리 공간 없이 배열 내에서 정렬이 이루어지므로 공간 복잡도는 `O(1)`입니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   항상 `O(n log n)`의 시간 복잡도를 보장합니다. 최악의 경우에도 성능 저하가 없습니다.
            *   제자리 정렬이므로 추가 메모리 사용이 매우 적습니다.
        *   **단점:**
            *   퀵 정렬이나 병합 정렬에 비해 상수 인자가 커서 실제 성능이 느릴 수 있습니다.
            *   캐시 효율이 좋지 않습니다. (데이터 접근 패턴이 지역적이지 않음)
            *   안정 정렬이 아닙니다.
*   **팀 정렬 (Timsort):**

    팀 정렬은 **병합 정렬(Merge Sort)**과 **삽입 정렬(Insertion Sort)**의 장점을 결합한 하이브리드 정렬 알고리즘입니다. 실제 데이터에서 뛰어난 성능을 발휘하도록 설계되었으며, Python, Java, Android 등 많은 프로그래밍 언어 및 플랫폼의 내장 정렬 함수로 사용됩니다.

    *   **개념:**
        1.  **런(Run) 생성:** 배열을 작은 '런(Run)'이라고 불리는 부분 배열들로 나눕니다. 각 런은 이미 정렬되어 있거나, 역순으로 정렬되어 있는 경우 뒤집어서 정렬된 상태로 만듭니다. 런의 최소 길이는 보통 32 또는 64로 설정됩니다.
        2.  **삽입 정렬 적용:** 런의 길이가 작을 때는 삽입 정렬을 사용하여 정렬합니다. 삽입 정렬은 작은 배열에서 효율적이기 때문입니다.
        3.  **병합 정렬 적용:** 정렬된 런들을 병합 정렬 방식으로 합쳐나갑니다. 이때, 병합 정렬의 효율성을 높이기 위해 스택을 사용하여 병합할 런들을 관리하고, 특정 조건을 만족할 때만 병합을 수행하여 불필요한 병합을 줄입니다.

    *   **동작 과정 (예시: `[5, 2, 8, 1, 9, 4, 7, 3]`, 최소 런 길이 4 가정)**

        1.  **런 생성 및 삽입 정렬:**
            *   `[5, 2, 8, 1]` -> 삽입 정렬 -> `[1, 2, 5, 8]` (런 1)
            *   `[9, 4, 7, 3]` -> 삽입 정렬 -> `[3, 4, 7, 9]` (런 2)
            *   **결과:** `[1, 2, 5, 8], [3, 4, 7, 9]`

        2.  **런 병합 (병합 정렬 방식):**
            *   런 1과 런 2를 병합합니다.
            *   `[1, 2, 5, 8]`과 `[3, 4, 7, 9]`를 병합
            *   **최종 결과:** `[1, 2, 3, 4, 5, 7, 8, 9]`

    *   **시간 복잡도:**
        *   **최선, 최악, 평균 모두 `O(n log n)`:**
            *   팀 정렬은 병합 정렬의 `O(n log n)` 성능을 유지하면서, 실제 데이터의 부분적인 정렬 상태를 활용하여 상수 인자를 줄여 더 빠르게 동작합니다.

    *   **구현 (개념적 설명, 실제 구현은 복잡함):**
    ```python
    # Python의 list.sort() 및 sorted() 함수는 Timsort를 사용합니다.
    # Timsort의 실제 구현은 매우 복잡하며, 여기서는 개념적인 동작을 설명합니다.

    def timsort_conceptual(arr):
        n = len(arr)
        min_run = 32 # 최소 런 길이 (일반적으로 32 또는 64)

        # 1. 런 생성 및 삽입 정렬
        # 배열을 min_run 크기의 런으로 나누고 삽입 정렬을 적용
        for i in range(0, n, min_run):
            # 현재 런의 끝 인덱스
            end = min(i + min_run - 1, n - 1)
            # 삽입 정렬 적용 (작은 배열에 효율적)
            # 실제 Timsort는 이 부분에서 이미 정렬된 런을 감지하고 역순 런을 뒤집는 로직 포함
            insertion_sort_for_timsort(arr, i, end)

        # 2. 런 병합 (병합 정렬 방식)
        # 런들을 점진적으로 병합하여 전체 배열을 정렬
        size = min_run
        while size < n:
            for start in range(0, n, 2 * size):
                mid = min(start + size - 1, n - 1)
                end = min(start + 2 * size - 1, n - 1)
                # 두 런을 병합
                # 실제 Timsort는 병합할 런들을 스택에 관리하며,
                # 특정 조건을 만족할 때만 병합하여 최적화
                if mid < end: # 병합할 두 번째 런이 존재할 경우
                    merge_for_timsort(arr, start, mid, end)
            size *= 2
        return arr

    # Timsort 내부에서 사용되는 삽입 정렬 (부분 배열 정렬)
    def insertion_sort_for_timsort(arr, left, right):
        for i in range(left + 1, right + 1):
            key = arr[i]
            j = i - 1
            while j >= left and key < arr[j]:
                arr[j + 1] = arr[j]
                j -= 1
            arr[j + 1] = key

    # Timsort 내부에서 사용되는 병합 함수
    def merge_for_timsort(arr, l, m, r):
        len1, len2 = m - l + 1, r - m
        left_arr, right_arr = [], []
        for i in range(len1):
            left_arr.append(arr[l + i])
        for i in range(len2):
            right_arr.append(arr[m + 1 + i])

        i, j, k = 0, 0, l
        while i < len1 and j < len2:
            if left_arr[i] <= right_arr[j]:
                arr[k] = left_arr[i]
                i += 1
            else:
                arr[k] = right_arr[j]
                j += 1
            k += 1

        while i < len1:
            arr[k] = left_arr[i]
            i += 1
            k += 1

        while j < len2:
            arr[k] = right_arr[j]
            j += 1
            k += 1

    # 예시
    # print(timsort_conceptual([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
    ```

    *   **특징:**
        *   **안정 정렬(Stable Sort):** 병합 정렬의 안정성을 유지하여 같은 값을 가진 요소들의 상대적인 순서가 정렬 후에도 유지됩니다.
        *   **하이브리드 정렬:** 작은 배열에는 삽입 정렬을, 큰 배열에는 병합 정렬을 사용하여 실제 데이터의 특성을 최대한 활용합니다.
        *   **실제 데이터에 최적화:** 부분적으로 정렬된 데이터에 대해 특히 효율적입니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   대부분의 실제 데이터에서 매우 빠른 성능을 보입니다.
            *   `O(n log n)`의 안정적인 시간 복잡도를 보장합니다.
            *   안정 정렬이므로 데이터의 상대적인 순서가 유지되어야 하는 경우에 적합합니다.
            *   부분적으로 정렬된 데이터에 대해 최적화되어 있습니다.
        *   **단점:**
            *   구현이 복잡합니다.
            *   병합 정렬과 유사하게 `O(n)`의 추가 메모리 공간이 필요할 수 있습니다 (임시 배열 사용).

*   **삽입 정렬 (Insertion Sort):**

    삽입 정렬은 배열의 모든 요소를 앞에서부터 하나씩 이미 정렬된 부분 배열에 삽입하면서 정렬하는 알고리즘입니다. 마치 카드 게임에서 새로운 카드를 손에 든 카드들(정렬된 부분)의 올바른 위치에 끼워 넣는 것과 유사합니다.

    *   **개념:** 배열을 정렬된 부분과 정렬되지 않은 부분으로 나눕니다. 정렬되지 않은 부분의 첫 번째 요소를 가져와 정렬된 부분의 올바른 위치에 삽입합니다.

    *   **동작 과정 (예시: `[5, 2, 4, 6, 1, 3]`)**

        1.  **초기 상태:** `[|5, 2, 4, 6, 1, 3]` (정렬된 부분: `[5]`, 정렬되지 않은 부분: `[2, 4, 6, 1, 3]`)

        2.  **두 번째 요소 (2) 삽입:**
            *   `2`를 가져와 `5`와 비교. `2 < 5`이므로 `5`를 뒤로 밀고 `2`를 삽입.
            *   **결과:** `[2, 5|4, 6, 1, 3]` (정렬된 부분: `[2, 5]`)

        3.  **세 번째 요소 (4) 삽입:**
            *   `4`를 가져와 `5`와 비교. `4 < 5`이므로 `5`를 뒤로 밀고 `4`를 `2`와 `5` 사이에 삽입.
            *   **결과:** `[2, 4, 5|6, 1, 3]` (정렬된 부분: `[2, 4, 5]`)

        4.  **네 번째 요소 (6) 삽입:**
            *   `6`을 가져와 `5`와 비교. `6 > 5`이므로 `6`은 `5` 뒤에 그대로 위치.
            *   **결과:** `[2, 4, 5, 6|1, 3]` (정렬된 부분: `[2, 4, 5, 6]`)

        5.  **다섯 번째 요소 (1) 삽입:**
            *   `1`을 가져와 `6, 5, 4, 2`와 차례로 비교하며 앞으로 이동.
            *   **결과:** `[1, 2, 4, 5, 6|3]` (정렬된 부분: `[1, 2, 4, 5, 6]`)

        6.  **여섯 번째 요소 (3) 삽입:**
            *   `3`을 가져와 `6, 5, 4`와 비교하며 이동. `2` 뒤에 삽입.
            *   **결과:** `[1, 2, 3, 4, 5, 6]` (정렬된 부분: `[1, 2, 3, 4, 5, 6]`)

    *   **시간 복잡도:**
        *   **최선 `O(n)`:** 배열이 이미 정렬되어 있는 경우. 각 요소를 한 번씩만 비교하고 이동이 거의 없으므로 선형 시간에 가깝습니다.
        *   **최악 `O(n^2)`:** 배열이 역순으로 정렬되어 있는 경우. 각 요소를 정렬된 부분의 맨 앞으로 이동시키기 위해 모든 요소를 비교하고 이동해야 합니다.
        *   **평균 `O(n^2)`:** 최악의 경우와 유사하게 `n^2`에 비례합니다.

    *   **구현:**
    ```python
    def insertion_sort(arr):
        # 두 번째 요소부터 시작하여 배열의 끝까지 반복
        for i in range(1, len(arr)):
            # 현재 삽입할 요소 (key)
            key = arr[i]
            # key를 삽입할 위치를 찾기 위해 key의 왼쪽 요소부터 비교 시작
            j = i - 1
            
            # j가 0 이상이고, key가 arr[j]보다 작으면 arr[j]를 오른쪽으로 한 칸 이동
            # 이는 key가 들어갈 공간을 만드는 과정
            while j >= 0 and key < arr[j]:
                arr[j + 1] = arr[j]
                j -= 1
            
            # 올바른 위치를 찾으면 key를 삽입
            arr[j + 1] = key
        return arr

    # 예시
    # print(insertion_sort([64, 34, 25, 12, 22, 11, 90])) # [11, 12, 22, 25, 34, 64, 90]
    ```

    *   **특징:**
        *   **안정 정렬(Stable Sort):** 값이 같은 요소들의 상대적인 순서가 정렬 후에도 유지됩니다.
        *   **제자리 정렬(In-place Sort):** 정렬을 위한 추가적인 저장 공간이 거의 필요하지 않아 공간 복잡도는 `O(1)`입니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   구현이 간단하고 직관적입니다.
            *   데이터의 양이 적거나, 대부분 정렬되어 있는 경우 효율적입니다.
            *   추가 메모리 사용이 거의 없습니다.
        *   **단점:**
            *   데이터의 양이 많아질수록 성능이 `O(n^2)`으로 급격히 저하되어 비효율적입니다.
            *   데이터가 역순으로 정렬되어 있는 경우 최악의 성능을 보입니다.
*   **계수 정렬 (Counting Sort):**

    계수 정렬은 **비교 정렬(Comparison Sort)**이 아닌 **분포 정렬(Distribution Sort)**의 일종으로, 데이터의 특정 범위 내에 있는 정수 값에 대해 매우 효율적인 정렬 알고리즘입니다. 각 숫자가 몇 번 나타나는지 세어(계수하여) 정렬합니다.

    *   **개념:**
        1.  입력 배열의 각 요소의 발생 횟수를 세어 별도의 계수 배열(Counting Array)에 저장합니다.
        2.  계수 배열을 수정하여 각 요소가 최종 정렬된 배열에서 어떤 위치에 놓여야 하는지를 나타내도록 누적 합을 계산합니다.
        3.  입력 배열을 뒤에서부터 순회하면서, 계수 배열의 정보를 이용하여 요소를 올바른 정렬 위치에 배치합니다.

    *   **전제 조건:**
        *   정렬할 데이터가 **음이 아닌 정수**여야 합니다.
        *   데이터의 **최댓값(k)이 너무 크지 않아야** 합니다. (k가 크면 계수 배열의 크기가 커져 메모리 비효율 발생)

    *   **동작 과정 (예시: `[1, 4, 1, 2, 7, 5, 2]`, 최댓값 k=7)**

        1.  **계수 배열 초기화 및 채우기:**
            *   입력 배열의 최댓값(7)을 기준으로 크기 `k+1` (0부터 7까지)의 계수 배열 `count`를 0으로 초기화합니다.
            *   `count = [0, 0, 0, 0, 0, 0, 0, 0]`
            *   입력 배열을 순회하며 각 숫자의 개수를 셉니다.
                *   1: 2개, 2: 2개, 4: 1개, 5: 1개, 7: 1개
            *   `count = [0, 2, 2, 0, 1, 1, 0, 1]` (인덱스는 숫자 값, 값은 개수)

        2.  **누적 합 계산:**
            *   `count` 배열의 각 요소에 이전 요소의 값을 더하여 누적 합을 계산합니다. 이는 각 숫자가 정렬된 배열에서 끝나는 위치를 나타냅니다.
            *   `count[0] = 0`
            *   `count[1] = count[0] + count[1] = 0 + 2 = 2`
            *   `count[2] = count[1] + count[2] = 2 + 2 = 4`
            *   `count[3] = count[2] + count[3] = 4 + 0 = 4`
            *   `count[4] = count[3] + count[4] = 4 + 1 = 5`
            *   `count[5] = count[4] + count[5] = 5 + 1 = 6`
            *   `count[6] = count[5] + count[6] = 6 + 0 = 6`
            *   `count[7] = count[6] + count[7] = 6 + 1 = 7`
            *   **결과 `count`:** `[0, 2, 4, 4, 5, 6, 6, 7]`

        3.  **출력 배열에 배치:**
            *   입력 배열과 같은 크기의 출력 배열 `output`을 생성합니다.
            *   입력 배열 `[1, 4, 1, 2, 7, 5, 2]`을 **뒤에서부터** 순회합니다. (안정 정렬을 위함)
                *   `arr[6] = 2`: `count[2]`는 4. `output[4-1]`에 2를 넣고 `count[2]`를 3으로 감소. `output = [_, _, _, 2, _, _, _]`
                *   `arr[5] = 5`: `count[5]`는 6. `output[6-1]`에 5를 넣고 `count[5]`를 5로 감소. `output = [_, _, _, 2, _, 5, _]`
                *   `arr[4] = 7`: `count[7]`는 7. `output[7-1]`에 7을 넣고 `count[7]`를 6으로 감소. `output = [_, _, _, 2, _, 5, 7]`
                *   `arr[3] = 2`: `count[2]`는 3. `output[3-1]`에 2를 넣고 `count[2]`를 2로 감소. `output = [_, 2, _, 2, _, 5, 7]`
                *   `arr[2] = 1`: `count[1]`는 2. `output[2-1]`에 1를 넣고 `count[1]`를 1로 감소. `output = [_, 1, 2, 2, _, 5, 7]`
                *   `arr[1] = 4`: `count[4]`는 5. `output[5-1]`에 4를 넣고 `count[4]`를 4로 감소. `output = [_, 1, 2, 2, 4, 5, 7]`
                *   `arr[0] = 1`: `count[1]`는 1. `output[1-1]`에 1를 넣고 `count[1]`를 0으로 감소. `output = [1, 1, 2, 2, 4, 5, 7]`
            *   **최종 정렬된 배열:** `[1, 1, 2, 2, 4, 5, 7]`

    *   **시간 복잡도:**
        *   **최선, 최악, 평균 모두 `O(n + k)`:**
            *   `n`: 입력 배열의 크기
            *   `k`: 입력 배열의 최댓값 (값의 범위)
            *   계수 배열 초기화 및 채우기: `O(n + k)`
            *   누적 합 계산: `O(k)`
            *   출력 배열에 배치: `O(n)`
            *   따라서 총 시간 복잡도는 `O(n + k)`입니다.

    *   **구현:**
    ```python
    def counting_sort(arr):
        n = len(arr)
        if n == 0:
            return []

        # 1. 입력 배열의 최댓값 찾기 (k)
        max_val = arr[0]
        for num in arr:
            if num > max_val:
                max_val = num

        # 2. 계수 배열 초기화 (크기: max_val + 1)
        count = [0] * (max_val + 1)

        # 3. 각 요소의 발생 횟수 세기
        for num in arr:
            count[num] += 1

        # 4. 계수 배열의 누적 합 계산
        for i in range(1, max_val + 1):
            count[i] += count[i - 1]

        # 5. 출력 배열에 요소 배치 (안정 정렬을 위해 뒤에서부터 순회)
        output = [0] * n
        for i in range(n - 1, -1, -1):
            num = arr[i]
            output[count[num] - 1] = num
            count[num] -= 1
            
        return output

    # 예시
    # print(counting_sort([1, 4, 1, 2, 7, 5, 2])) # [1, 1, 2, 2, 4, 5, 7]
    # print(counting_sort([0, 5, 3, 0, 2, 2, 1])) # [0, 0, 1, 2, 2, 3, 5]
    ```

    *   **특징:**
        *   **비교 정렬이 아님 (Non-comparison Sort):** 요소 간의 직접적인 비교 없이 정렬을 수행합니다.
        *   **안정 정렬(Stable Sort):** 같은 값을 가진 요소들의 상대적인 순서가 정렬 후에도 유지됩니다. (입력 배열을 뒤에서부터 순회하여 배치하는 방식으로 안정성을 보장)
        *   **제자리 정렬(In-place Sort) 아님:** 추가적인 계수 배열과 출력 배열이 필요하므로 `O(n + k)`의 공간 복잡도를 가집니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   데이터의 범위(k)가 작을 때 매우 빠르고 효율적입니다. `O(n + k)`의 선형 시간 복잡도를 가집니다.
            *   안정 정렬이므로 같은 값의 순서가 유지됩니다.
        *   **단점:**
            *   정렬할 데이터가 정수여야 하며, 음수가 포함될 경우 추가적인 처리가 필요합니다.
            *   데이터의 최댓값(k)이 매우 크면 계수 배열의 크기가 비례하여 커지므로 메모리 사용량이 많아지고 비효율적입니다.
            *   실수나 문자열과 같은 비정수 데이터에는 직접 적용할 수 없습니다.
*   **기수 정렬 (Radix Sort):**

    기수 정렬은 **비교 정렬(Comparison Sort)**이 아닌 **분포 정렬(Distribution Sort)**의 일종으로, 숫자의 자릿수(digit)를 기준으로 정렬하는 알고리즘입니다. 가장 낮은 자릿수부터 시작하여 가장 높은 자릿수까지 순차적으로 정렬을 반복합니다. 각 자릿수별 정렬에는 안정 정렬(예: 계수 정렬)이 사용됩니다.

    *   **개념:**
        1.  정렬할 숫자들의 최댓값을 찾아 가장 큰 자릿수(d)를 결정합니다.
        2.  가장 낮은 자릿수(일의 자리)부터 시작하여 각 자릿수별로 안정 정렬을 수행합니다.
        3.  모든 자릿수에 대해 정렬을 완료하면 전체 배열이 정렬됩니다.

    *   **전제 조건:**
        *   정렬할 데이터가 **음이 아닌 정수**여야 합니다.
        *   데이터의 **자릿수가 일정하거나, 최댓값의 자릿수가 너무 크지 않아야** 합니다.

    *   **동작 과정 (예시: `[170, 45, 75, 90, 802, 24, 2, 66]`)**

        1.  **최댓값의 자릿수 결정:** 최댓값은 802이므로, 가장 큰 자릿수는 100의 자리 (3자리)입니다. 따라서 3번의 패스를 수행합니다.

        2.  **일의 자리 (10^0) 정렬:** (계수 정렬 사용)
            *   `[170, 90, 802, 2, 24, 45, 66, 75]` (일의 자리 기준 정렬)

        3.  **십의 자리 (10^1) 정렬:** (계수 정렬 사용)
            *   `[802, 2, 24, 45, 66, 170, 75, 90]` (십의 자리 기준 정렬)

        4.  **백의 자리 (10^2) 정렬:** (계수 정렬 사용)
            *   `[2, 24, 45, 66, 75, 90, 170, 802]` (백의 자리 기준 정렬)

        *   **최종 정렬된 배열:** `[2, 24, 45, 66, 75, 90, 170, 802]`

    *   **시간 복잡도:**
        *   **최선, 최악, 평균 모두 `O(d * (n + k))`:**
            *   `d`: 숫자의 최대 자릿수 (또는 키의 길이)
            *   `n`: 입력 배열의 크기
            *   `k`: 각 자릿수(기수)의 범위 (예: 0-9까지의 숫자이므로 10)
            *   각 자릿수별로 계수 정렬을 `d`번 수행하므로, `d * O(n + k)`가 됩니다.

    *   **구현:**
    ```python
    def counting_sort_for_radix(arr, exp):
        n = len(arr)
        output = [0] * n
        count = [0] * 10 # 0-9까지의 숫자를 위한 계수 배열

        # 각 숫자의 현재 자릿수(exp) 값의 개수를 셉니다.
        for i in range(n):
            index = (arr[i] // exp) % 10
            count[index] += 1

        # 누적 합을 계산하여 각 숫자가 output 배열에서 차지할 위치를 결정합니다.
        for i in range(1, 10):
            count[i] += count[i - 1]

        # output 배열에 요소를 배치합니다. (안정 정렬을 위해 뒤에서부터 순회)
        i = n - 1
        while i >= 0:
            index = (arr[i] // exp) % 10
            output[count[index] - 1] = arr[i]
            count[index] -= 1
            i -= 1

        # 원본 배열을 정렬된 output 배열로 업데이트합니다.
        for i in range(n):
            arr[i] = output[i]

    def radix_sort(arr):
        n = len(arr)
        if n == 0:
            return []

        # 최댓값을 찾아 가장 큰 자릿수를 결정합니다.
        max_val = arr[0]
        for num in arr:
            if num > max_val:
                max_val = num

        # 자릿수(exp)를 1부터 시작하여 10배씩 증가시키며 각 자릿수별로 정렬합니다.
        exp = 1
        while max_val // exp > 0:
            counting_sort_for_radix(arr, exp)
            exp *= 10
        return arr

    # 예시
    # print(radix_sort([170, 45, 75, 90, 802, 24, 2, 66])) # [2, 24, 45, 66, 75, 90, 170, 802]
    # print(radix_sort([329, 457, 657, 839, 436, 720, 355])) # [329, 355, 436, 457, 657, 720, 839]
    ```

    *   **특징:**
        *   **비교 정렬이 아님 (Non-comparison Sort):** 요소 간의 직접적인 비교 없이 정렬을 수행합니다.
        *   **안정 정렬(Stable Sort):** 각 자릿수별 정렬에 안정 정렬(계수 정렬)을 사용하므로 전체적으로 안정 정렬입니다.
        *   **제자리 정렬(In-place Sort) 아님:** 각 자릿수별 정렬 시 임시 배열이 필요하므로 `O(n + k)`의 공간 복잡도를 가집니다.

    *   **장점 및 단점:**
        *   **장점:**
            *   데이터의 자릿수(d)와 기수(k)가 작을 때 매우 빠르고 효율적입니다. `O(d * (n + k))`의 선형 시간 복잡도를 가집니다.
            *   안정 정렬이므로 같은 값의 순서가 유지됩니다.
        *   **단점:**
            *   정렬할 데이터가 정수여야 하며, 음수가 포함될 경우 추가적인 처리가 필요합니다.
            *   자릿수(d)가 매우 크거나, 기수(k)가 매우 크면 효율성이 떨어질 수 있습니다.
            *   실수나 문자열과 같은 비정수 데이터에는 직접 적용하기 어렵습니다 (문자열의 경우 아스키 코드 등을 이용한 변형 가능).
            *   비교 정렬에 비해 상수 인자가 커서 작은 데이터셋에서는 다른 정렬 알고리즘보다 느릴 수 있습니다.

### 1.5. 정렬 알고리즘 성능 비교

| 알고리즘 | 시간 복잡도 (최악) | 시간 복잡도 (평균) | 공간 복잡도 | 안정성 |
| :--- | :--- | :--- | :--- | :--- |
| 버블 정렬 | `O(n^2)` | `O(n^2)` | `O(1)` | 안정 |
| 선택 정렬 | `O(n^2)` | `O(n^2)` | `O(1)` | 불안정 |
| 삽입 정렬 | `O(n^2)` | `O(n^2)` | `O(1)` | 안정 |
| 퀵 정렬 | `O(n^2)` | `O(n log n)` | `O(log n)` (재귀 스택) | 불안정 |
| 병합 정렬 | `O(n log n)` | `O(n log n)` | `O(n)` | 안정 |
| 힙 정렬 | `O(n log n)` | `O(n log n)` | `O(1)` | 불안정 |

실제 환경에서는 데이터의 특성(정렬 여부, 중복 여부, 크기 등)에 따라 각 정렬 알고리즘의 성능이 달라질 수 있습니다. 예를 들어, 대부분의 언어에서 제공하는 내장 정렬 함수는 퀵 정렬, 병합 정렬, 또는 팀 정렬(Timsort)과 같은 하이브리드 정렬 알고리즘을 사용합니다.

## 2. 탐색 알고리즘 (Searching Algorithms)

탐색 알고리즘은 주어진 데이터 컬렉션에서 특정 요소를 찾는 알고리즘입니다.

### 2.1. 선형 탐색 (Linear Search)

선형 탐색은 데이터를 처음부터 끝까지 순차적으로 비교하며 찾는 가장 간단한 탐색 알고리즘입니다. 데이터가 정렬되어 있지 않거나, 데이터의 양이 매우 적을 때 주로 사용됩니다.

*   **개념:** 배열의 모든 요소를 하나씩 확인하여 목표 값을 찾습니다.
*   **시간 복잡도:** `O(n)` (최악, 평균) - 배열의 모든 요소를 한 번씩 확인해야 할 수 있습니다.
*   **구현:**
```python
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i  # 요소를 찾으면 해당 인덱스 반환
    return -1 # 요소를 찾지 못하면 -1 반환

# 예시
# print(linear_search([10, 20, 80, 30, 60, 50, 110, 100, 130, 170], 110)) # 6
# print(linear_search([10, 20, 80, 30, 60, 50, 110, 100, 130, 170], 99))  # -1
```
*   **자세한 내용은 위 내용을 참조하십시오.**

### 2.2. 이진 탐색 (Binary Search)

이진 탐색은 **정렬된 배열**에서 탐색 범위를 절반씩 줄여가며 요소를 찾는 효율적인 탐색 알고리즘입니다. 데이터가 정렬되어 있다는 강력한 전제 조건이 있습니다.

*   **개념:** 탐색 범위의 중간 요소를 확인하여 목표 값과 비교합니다. 목표 값이 중간 요소보다 작으면 왼쪽 절반에서, 크면 오른쪽 절반에서 다시 탐색합니다. 이 과정을 목표 값을 찾거나 탐색 범위가 없어질 때까지 반복합니다.
*   **시간 복잡도:** `O(log n)` - 탐색 범위가 매 단계 절반으로 줄어들기 때문에 매우 효율적입니다.
*   **전제 조건:** 데이터가 반드시 정렬되어 있어야 합니다.
*   **구현 (반복문):**
```python
def binary_search_iterative(arr, target):
    low = 0
    high = len(arr) - 1

    while low <= high:
        mid = (low + high) // 2 # 중간 인덱스 계산
        if arr[mid] == target:
            return mid # 목표 값을 찾으면 인덱스 반환
        elif arr[mid] < target:
            low = mid + 1 # 중간 값보다 크면 오른쪽 절반 탐색
        else:
            high = mid - 1 # 중간 값보다 작으면 왼쪽 절반 탐색
    return -1 # 목표 값을 찾지 못하면 -1 반환

# 예시
# print(binary_search_iterative([11, 12, 22, 25, 34, 64, 90], 25)) # 3
# print(binary_search_iterative([11, 12, 22, 25, 34, 64, 90], 99)) # -1
```
*   **구현 (재귀):**
```python
def binary_search_recursive(arr, target, low, high):
    if low > high:
        return -1 # 탐색 범위가 유효하지 않으면 -1 반환

    mid = (low + high) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_recursive(arr, target, mid + 1, high)
    else:
        return binary_search_recursive(arr, target, low, mid - 1)

# 예시
# arr_rec = [11, 12, 22, 25, 34, 64, 90]
# print(binary_search_recursive(arr_rec, 25, 0, len(arr_rec) - 1)) # 3
# print(binary_search_recursive(arr_rec, 99, 0, len(arr_rec) - 1)) # -1
```
*   **변형:** 이진 탐색은 단순히 값의 존재 여부를 확인하는 것 외에도, 특정 값의 첫 번째/마지막 등장 위치 찾기, 특정 값보다 크거나 같은/작거나 같은 첫 번째 요소 찾기(Lower Bound/Upper Bound) 등 다양한 문제에 응용될 수 있습니다.
*   **자세한 내용은 위 내용을 참조하십시오.**

### 2.3. 삼분 탐색 (Ternary Search)

삼분 탐색은 단조성을 가지는 함수(볼록 함수 또는 오목 함수, 즉 Unimodal Function)에서 최댓값 또는 최솟값을 찾는 데 사용되는 탐색 기법입니다. 이진 탐색이 단조 함수에서 특정 값을 찾는 데 사용되는 반면, 삼분 탐색은 함수의 최적점(극점)을 찾는 데 특화되어 있습니다.

*   **개념:** 탐색 구간을 3등분하여 두 개의 중간점(m1, m2)을 설정하고, `f(m1)`과 `f(m2)`를 비교하여 최적점이 존재하지 않는 1/3 구간을 버립니다. 이 과정을 반복하여 최적점에 수렴합니다. 이진 탐색과 유사하게, 매 단계 탐색 범위를 줄여나갑니다.

*   **동작 과정 (최댓값 찾기 예시):**
    함수 `f(x) = -(x-5)^2 + 10` (x=5에서 최댓값 10을 가지는 위로 볼록한 포물선)을 구간 `[0, 10]`에서 탐색하는 예시입니다.

    1.  **초기 구간 설정:** `low = 0`, `high = 10`
    2.  **중간점 계산:**
        *   `m1 = low + (high - low) / 3 = 0 + (10 - 0) / 3 = 3.33`
        *   `m2 = high - (high - low) / 3 = 10 - (10 - 0) / 3 = 6.67`
    3.  **함수 값 비교:**
        *   `f(m1) = f(3.33) = -(3.33 - 5)^2 + 10 = -(-1.67)^2 + 10 = -2.7889 + 10 = 7.2111`
        *   `f(m2) = f(6.67) = -(6.67 - 5)^2 + 10 = -(1.67)^2 + 10 = -2.7889 + 10 = 7.2111`
        *   `f(m1)`과 `f(m2)`가 같습니다. (이 경우 어느 쪽을 버려도 무방하나, 일반적으로 `f(m1) < f(m2)`이면 `low = m1`, `f(m1) >= f(m2)`이면 `high = m2`로 설정합니다.) 여기서는 `f(m1) >= f(m2)`로 간주하여 `high = m2`로 설정합니다.
    4.  **구간 갱신:** `low = 0`, `high = 6.67`

    **반복 1:**
    1.  **구간:** `low = 0`, `high = 6.67`
    2.  **중간점 계산:**
        *   `m1 = 0 + (6.67 - 0) / 3 = 2.22`
        *   `m2 = 6.67 - (6.67 - 0) / 3 = 4.45`
    3.  **함수 값 비교:**
        *   `f(m1) = f(2.22) = -(2.22 - 5)^2 + 10 = -(-2.78)^2 + 10 = -7.7284 + 10 = 2.2716`
        *   `f(m2) = f(4.45) = -(4.45 - 5)^2 + 10 = -(-0.55)^2 + 10 = 9.6975`
        *   `f(m1) < f(m2)` 이므로, 최댓값은 `m1` 오른쪽에 있습니다.
    4.  **구간 갱신:** `low = m1 = 2.22`, `high = 6.67`

    **반복 2:**
    1.  **구간:** `low = 2.22`, `high = 6.67`
    2.  **중간점 계산:**
        *   `m1 = 2.22 + (6.67 - 2.22) / 3 = 2.22 + 1.48 = 3.70`
        *   `m2 = 6.67 - (6.67 - 2.22) / 3 = 6.67 - 1.48 = 5.19`
    3.  **함수 값 비교:**
        *   `f(m1) = f(3.70) = -(3.70 - 5)^2 + 10 = -(-1.3)^2 + 10 = 8.31`
        *   `f(m2) = f(5.19) = -(5.19 - 5)^2 + 10 = -(0.19)^2 + 10 = 9.9639`
        *   `f(m1) < f(m2)` 이므로, 최댓값은 `m1` 오른쪽에 있습니다.
    4.  **구간 갱신:** `low = m1 = 3.70`, `high = 6.67`

    이 과정을 `(high - low)`가 `epsilon`보다 작아질 때까지 반복하면 최적점에 수렴합니다.

*   **시간 복잡도:** `O(log3 n)` - 매 단계 탐색 범위가 1/3로 줄어들기 때문에 매우 효율적입니다. `n`은 탐색 구간의 크기입니다.

*   **활용:**
    *   최댓값/최솟값을 가지는 단조 함수에서 최적점을 찾을 때. (예: 포물선 함수의 꼭짓점 찾기, 삼차 함수의 극점 찾기)
    *   예: 특정 구간에서 함수의 최댓값 또는 최솟값을 찾는 문제.
    *   기하학 문제에서 최적의 위치를 찾을 때.

*   **구현 (최댓값 찾기 예시):**
```python
def ternary_search_max(f, low, high, epsilon=1e-7):
    # f: 단조성을 가지는 함수 (예: 위로 볼록한 함수)
    # low, high: 탐색 구간의 시작과 끝
    # epsilon: 허용 오차 (탐색 정밀도)

    while (high - low) > epsilon:
        m1 = low + (high - low) / 3
        m2 = high - (high - low) / 3

        if f(m1) < f(m2):
            low = m1 # m1보다 m2가 더 크므로, 최댓값은 m1 오른쪽에 있음
        else:
            high = m2 # m2보다 m1이 더 크거나 같으므로, 최댓값은 m2 왼쪽에 있음

    return (low + high) / 2 # 최적점 근사값 반환

# 예시 함수 (위로 볼록한 포물선)
# def example_function(x):
#     return -(x - 5)**2 + 10 # x=5에서 최댓값 10

# print(ternary_search_max(example_function, 0, 10)) # 5.0에 가까운 값 출력
```

*   **특징:**
    *   **단조 함수에만 적용 가능:** 반드시 볼록 함수 또는 오목 함수와 같이 단조성을 가지는 함수에만 적용할 수 있습니다.
    *   **근사값 탐색:** 이진 탐색과 달리 정확한 값을 찾는 것이 아니라, 최적점의 근사값을 찾습니다. `epsilon` 값에 따라 정밀도가 달라집니다.
    *   **비교 횟수:** 이진 탐색보다 한 단계에서 두 번의 함수 호출이 필요합니다.

*   **장점 및 단점:**
    *   **장점:**
        *   단조 함수에서 최적점을 효율적으로 찾을 수 있습니다.
        *   구현이 비교적 간단합니다.
    *   **단점:**
        *   적용할 수 있는 문제의 범위가 단조 함수로 제한됩니다.
        *   이진 탐색에 비해 한 단계에서 더 많은 함수 호출이 발생할 수 있습니다.
        *   정확한 최적점을 찾는 것이 아니라 근사값을 찾습니다.

## 3. 투 포인터 (Two Pointers)

투 포인터는 배열이나 리스트와 같은 선형 자료구조에서 두 개의 포인터(인덱스)를 사용하여 문제를 해결하는 알고리즘 기법입니다. 주로 정렬된 배열에서 특정 조건을 만족하는 쌍이나 부분 배열을 찾을 때 효율적입니다.

*   **개념:** 투 포인터는 배열이나 리스트와 같은 선형 자료구조에서 두 개의 포인터(인덱스)를 사용하여 문제를 해결하는 알고리즘 기법입니다. 이 두 포인터는 서로 다른 위치에서 시작하여(예: 양 끝에서 시작하여 안쪽으로 이동) 특정 조건을 만족하는 쌍이나 부분 배열을 효율적으로 탐색합니다. 또는 같은 위치에서 시작하여 한 방향으로 이동하며 특정 조건을 만족하는 구간을 찾기도 합니다.

*   **활용 조건:**
    *   데이터가 **정렬되어 있는 경우** (가장 일반적이고 효과적인 활용 사례).
    *   특정 조건을 만족하는 두 요소의 쌍(Pair)을 찾아야 할 때.
    *   부분 배열 또는 부분 문자열을 다룰 때.
    *   연결 리스트에서 사이클 감지, 중간 노드 찾기 등.
    *   배열에서 중복 요소 제거, 특정 값 이동 등.

*   **투 포인터 활용 문제 (예: 정렬된 배열에서 합 찾기)**

    정렬된 배열에서 합이 특정 값(target)이 되는 두 요소를 찾는 문제입니다.

    *   **동작 과정 (예시: `arr = [1, 2, 3, 4, 5]`, `target = 7`)**

        1.  **초기화:**
            *   `left` 포인터를 배열의 시작(`0`)에, `right` 포인터를 배열의 끝(`len(arr) - 1`)에 위치시킵니다.
            *   `arr = [1, 2, 3, 4, 5]`
            *   `left = 0` (값: `1`), `right = 4` (값: `5`)

        2.  **반복 (left < right 인 동안):**

            *   **1회차:**
                *   `current_sum = arr[left] + arr[right] = 1 + 5 = 6`
                *   `current_sum (6) < target (7)` 이므로, 합을 증가시켜야 합니다. `left` 포인터를 오른쪽으로 한 칸 이동합니다.
                *   `left = 1` (값: `2`), `right = 4` (값: `5`)

            *   **2회차:**
                *   `current_sum = arr[left] + arr[right] = 2 + 5 = 7`
                *   `current_sum (7) == target (7)` 이므로, 목표를 찾았습니다. `[2, 5]`를 반환하고 종료합니다.

    *   **시간 복잡도:** `O(n)` - 두 포인터가 배열을 한 번만 순회합니다. `left` 포인터는 오른쪽으로, `right` 포인터는 왼쪽으로 이동하며, 두 포인터가 만날 때까지 각 요소는 최대 한 번만 검사됩니다.
    *   **공간 복잡도:** `O(1)` - 추가적인 공간을 거의 사용하지 않습니다.

    *   **구현:**
    ```python
    def two_sum_sorted(arr, target):
        left, right = 0, len(arr) - 1 # 두 포인터를 배열의 양 끝에 초기화
        while left < right: # left 포인터가 right 포인터를 넘지 않을 때까지 반복
            current_sum = arr[left] + arr[right] # 현재 두 요소의 합 계산
            if current_sum == target:
                return [arr[left], arr[right]] # 합이 target과 같으면 결과 반환
            elif current_sum < target:
                left += 1 # 합이 target보다 작으면 left 포인터를 오른쪽으로 이동 (합을 증가)
            else:
                right -= 1 # 합이 target보다 크면 right 포인터를 왼쪽으로 이동 (합을 감소)
        return None # 조건을 만족하는 쌍을 찾지 못하면 None 반환

    # 예시
    # print(two_sum_sorted([1, 2, 3, 4, 5], 7)) # [2, 5]
    # print(two_sum_sorted([1, 2, 3, 4, 5], 10)) # None
    ```

*   **특징:**
    *   **효율성:** `O(n)`의 선형 시간 복잡도를 가지므로, `O(n^2)`의 이중 반복문 방식보다 훨씬 효율적입니다.
    *   **정렬된 데이터에 강점:** 대부분의 투 포인터 문제는 정렬된 배열에서 그 효율성이 극대화됩니다.
    *   **다양한 문제에 적용:** 특정 합 찾기, 중복 제거, 부분 배열/부분 문자열 찾기 등 다양한 문제에 응용될 수 있습니다.

*   **장점 및 단점:**
    *   **장점:**
        *   시간 복잡도가 뛰어나 `O(n)` 또는 `O(n log n)` (정렬이 필요한 경우)으로 문제를 해결할 수 있습니다.
        *   공간 복잡도가 `O(1)`로 매우 효율적입니다.
        *   알고리즘의 개념이 직관적이고 이해하기 쉽습니다.
    *   **단점:**
        *   주로 정렬된 배열에 적용될 때 가장 효과적입니다. 정렬되지 않은 배열에 적용하려면 먼저 정렬해야 하므로 정렬 비용이 추가됩니다.
        *   모든 문제에 적용할 수 있는 만능 해결책은 아닙니다.

## 4. 슬라이딩 윈도우 (Sliding Window)

슬라이딩 윈도우는 배열이나 문자열의 '연속된 부분(Subarray/Substring)'을 효율적으로 탐색하는 알고리즘 기법입니다. 고정된 크기 또는 가변적인 크기의 윈도우(부분 구간)를 이동시키면서 문제를 해결합니다.

*   **개념:** 슬라이딩 윈도우는 배열이나 문자열의 '연속된 부분(Subarray/Substring)'을 효율적으로 탐색하는 알고리즘 기법입니다. 고정된 크기 또는 가변적인 크기의 윈도우(부분 구간)를 이동시키면서 문제를 해결합니다. 매번 전체 구간을 다시 계산하는 대신, 윈도우를 한 칸씩 이동시키면서 윈도우 내의 데이터를 효율적으로 갱신하고 계산하여 `O(N)` 또는 `O(N log N)`의 시간 복잡도를 달성합니다.

*   **활용:**
    *   **고정 크기 윈도우:** 특정 길이의 부분 배열/문자열에서 최대/최소 합, 평균 등을 찾을 때. (예: 최대 부분 배열 합, 특정 길이의 부분 문자열에서 중복 없는 문자 개수)
    *   **가변 크기 윈도우:** 특정 조건을 만족하는 가장 짧거나 긴 부분 배열/문자열을 찾을 때. (예: K개의 고유 문자를 포함하는 가장 긴 부분 문자열, 합이 특정 값 이상인 가장 짧은 부분 배열)
    *   **문자열 패턴 매칭:** 특정 패턴이 문자열 내에 존재하는지 확인할 때.

*   **슬라이딩 윈도우 활용 문제 (예: 최대 부분 배열 합)**

    주어진 배열에서 길이가 `k`인 연속된 부분 배열의 최대 합을 찾는 문제입니다.

    *   **동작 과정 (예시: `arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]`, `k = 4`)**

        1.  **초기 윈도우 설정 및 합 계산:**
            *   첫 번째 윈도우(`arr[0]`부터 `arr[k-1]`)의 합을 계산합니다.
            *   `arr = [1, 4, 2, 10, 2, 3, 1, 0, 20]`, `k = 4`
            *   초기 윈도우: `[1, 4, 2, 10]`
            *   `current_sum = 1 + 4 + 2 + 10 = 17`
            *   `max_sum = 17`

        2.  **윈도우 슬라이딩:**
            *   윈도우를 배열의 끝까지 한 칸씩 오른쪽으로 이동시키면서 `current_sum`을 갱신하고 `max_sum`을 비교하여 업데이트합니다.
            *   새로운 요소는 더하고, 윈도우에서 벗어나는 가장 오래된 요소는 뺍니다.

            *   **1회차 (윈도우 `[4, 2, 10, 2]`):**
                *   `i = k = 4` (새로 추가될 요소의 인덱스)
                *   `arr[i] = arr[4] = 2` (새로 추가될 요소)
                *   `arr[i - k] = arr[0] = 1` (윈도우에서 빠질 요소)
                *   `current_sum = current_sum + arr[i] - arr[i - k] = 17 + 2 - 1 = 18`
                *   `max_sum = max(17, 18) = 18`
                *   윈도우: `[4, 2, 10, 2]`

            *   **2회차 (윈도우 `[2, 10, 2, 3]`):**
                *   `i = 5`
                *   `arr[i] = arr[5] = 3`
                *   `arr[i - k] = arr[1] = 4`
                *   `current_sum = 18 + 3 - 4 = 17`
                *   `max_sum = max(18, 17) = 18`
                *   윈도우: `[2, 10, 2, 3]`

            *   **3회차 (윈도우 `[10, 2, 3, 1]`):**
                *   `i = 6`
                *   `arr[i] = arr[6] = 1`
                *   `arr[i - k] = arr[2] = 2`
                *   `current_sum = 17 + 1 - 2 = 16`
                *   `max_sum = max(18, 16) = 18`
                *   윈도우: `[10, 2, 3, 1]`

            *   **4회차 (윈도우 `[2, 3, 1, 0]`):**
                *   `i = 7`
                *   `arr[i] = arr[7] = 0`
                *   `arr[i - k] = arr[3] = 10`
                *   `current_sum = 16 + 0 - 10 = 6`
                *   `max_sum = max(18, 6) = 18`
                *   윈도우: `[2, 3, 1, 0]`

            *   **5회차 (윈도우 `[3, 1, 0, 20]`):**
                *   `i = 8`
                *   `arr[i] = arr[8] = 20`
                *   `arr[i - k] = arr[4] = 2`
                *   `current_sum = 6 + 20 - 2 = 24`
                *   `max_sum = max(18, 24) = 24`
                *   윈도우: `[3, 1, 0, 20]`

        3.  **결과 반환:** 모든 윈도우를 탐색한 후, 최종 `max_sum`인 `24`를 반환합니다.

    *   **시간 복잡도:** `O(n)` - 배열을 한 번만 순회합니다. 초기 윈도우 합 계산에 `O(k)`가 들고, 이후 각 슬라이딩 단계에서 `O(1)` 연산만 수행하므로, 총 `O(n)`의 시간 복잡도를 가집니다.
    *   **공간 복잡도:** `O(1)` - 추가적인 공간을 거의 사용하지 않습니다.

    *   **구현:**
    ```python
    def max_subarray_sum_fixed_window(arr, k):
        if k > len(arr): return None # 윈도우 크기가 배열 길이보다 크면 유효하지 않음

        # 초기 윈도우의 합 계산
        current_sum = sum(arr[:k])
        max_sum = current_sum

        # 윈도우를 배열의 끝까지 슬라이딩
        for i in range(k, len(arr)):
            # 윈도우 이동: 새로운 요소 추가, 가장 오래된 요소 제거
            current_sum += arr[i] - arr[i - k]
            # 최대 합 갱신
            max_sum = max(max_sum, current_sum)
        return max_sum

    # 예시
    # print(max_subarray_sum_fixed_window([1, 4, 2, 10, 2, 3, 1, 0, 20], 4)) # 24 (4, 2, 10, 2)
    ```

*   **특징:**
    *   **효율적인 부분 구간 탐색:** 매번 부분 구간의 합이나 특성을 처음부터 다시 계산하는 대신, 윈도우를 이동시키면서 효율적으로 갱신하여 `O(N)` 시간 복잡도를 달성합니다.
    *   **연속된 데이터에 적용:** 배열이나 문자열과 같이 연속된 데이터 구조에서 특정 크기의 부분 구간을 다룰 때 유용합니다.
    *   **고정/가변 윈도우:** 문제의 요구사항에 따라 윈도우의 크기를 고정하거나 가변적으로 조절할 수 있습니다.

*   **장점 및 단점:**
    *   **장점:**
        *   `O(N)`의 선형 시간 복잡도를 통해 매우 효율적인 문제 해결이 가능합니다.
        *   `O(1)`의 공간 복잡도로 메모리 사용이 적습니다.
        *   다양한 유형의 부분 배열/부분 문자열 문제에 적용할 수 있습니다.
    *   **단점:**
        *   문제의 특성상 '연속된 부분'을 다룰 때만 적용 가능합니다.
        *   모든 문제에 적용할 수 있는 만능 해결책은 아닙니다.

## 5. 비트 연산 (Bit Manipulation)

비트 연산은 데이터를 비트(0과 1) 단위로 직접 조작하는 연산입니다. 매우 빠르고 효율적이며, 특정 문제 유형(집합 표현, 상태 관리, 최적화)에서 강력한 해결책을 제공합니다.

*   **개념:** 컴퓨터는 모든 데이터를 0과 1의 이진 형태로 처리합니다. 비트 연산은 이러한 이진 데이터의 개별 비트(bit)를 직접 조작하는 연산입니다.

### 5.1. 비트 연산자의 종류와 활용

비트 연산자는 정수형 데이터의 개별 비트(0 또는 1)를 직접 조작하는 연산입니다. 매우 빠르고 효율적이며, 특정 문제 유형(집합 표현, 상태 관리, 최적화)에서 강력한 해결책을 제공합니다.

*   `&` (AND): 두 비트가 모두 1일 때만 1을 반환합니다.
    *   **활용:** 특정 비트가 켜져 있는지 확인 (마스크 비트와 AND 연산), 특정 비트 끄기.
    *   **예시:** `5 (0101) & 3 (0011) = 1 (0001)`

*   `|` (OR): 두 비트 중 하나라도 1일 때 1을 반환합니다.
    *   **활용:** 특정 비트를 켜기 (마스크 비트와 OR 연산).
    *   **예시:** `5 (0101) | 3 (0011) = 7 (0111)`

*   `^` (XOR): 두 비트가 다를 때 1을 반환합니다.
    *   **활용:** 비트 반전, 두 값 교환 (임시 변수 없이), 중복되지 않는 요소 찾기.
    *   **예시:** `5 (0101) ^ 3 (0011) = 6 (0110)`

*   `~` (NOT): 비트를 반전시킵니다 (0은 1로, 1은 0으로). (보수 계산)
    *   **활용:** 보수 계산. (파이썬에서는 `~x`가 `-(x+1)`과 같습니다.)
    *   **예시:** `~5 (0101)` (32비트 시스템에서) `...11111111111111111111111111111010` (결과는 -6)

*   `<<` (Left Shift): 비트를 왼쪽으로 이동시킵니다. `x << n`은 `x * (2^n)`과 같습니다.
    *   **활용:** 2의 거듭제곱 곱셈, 비트 마스크 생성.
    *   **예시:** `5 (0101) << 1 = 10 (1010)`

*   `>>` (Right Shift): 비트를 오른쪽으로 이동시킵니다. `x >> n`은 `x // (2^n)`과 같습니다.
    *   **활용:** 2의 거듭제곱 나눗셈, 특정 비트 값 추출.
    *   **예시:** `5 (0101) >> 1 = 2 (0010)`

### 5.2. 비트 마스크 (Bit Mask)

비트 마스크는 비트 연산을 사용하여 여러 개의 불리언(True/False) 상태를 하나의 정수로 표현하고 관리하는 기법입니다. 각 비트가 특정 상태나 속성의 존재 여부를 나타내며, 이를 통해 효율적인 집합 연산이나 상태 관리가 가능합니다.

*   **활용:**
    *   **부분집합 표현:** `n`개의 요소로 구성된 집합의 모든 부분집합을 `2^n`개의 비트 마스크로 표현할 수 있습니다. 각 비트가 해당 요소의 포함 여부를 나타냅니다.
    *   **상태 관리:** 여러 개의 스위치나 옵션 상태를 하나의 정수 변수로 간결하게 관리할 수 있습니다. (예: 게임에서 플레이어의 아이템 소유 상태, 퍼즐의 특정 칸 방문 여부)
    *   **권한 관리:** 사용자 권한을 비트 플래그로 설정하여, 여러 권한을 동시에 부여하거나 확인하는 작업을 효율적으로 수행합니다.
    *   **동적 계획법 (Dynamic Programming):** 특정 상태를 비트 마스크로 표현하여 DP 테이블의 인덱스로 활용하는 경우가 많습니다. (예: 외판원 문제)

### 5.3. 비트 연산 활용 문제 (예: 부분집합, 상태 관리)

주어진 집합의 모든 부분집합을 생성하는 문제입니다.

*   **동작 과정 (예시: `nums = [1, 2, 3]`)**

    1.  **부분집합의 개수 결정:**
        *   집합의 요소가 `n`개일 때, 부분집합의 총 개수는 `2^n`개입니다.
        *   `nums = [1, 2, 3]` 이므로 `n = 3`. 부분집합의 개수는 `2^3 = 8`개입니다.
        *   각 부분집합은 `0`부터 `2^n - 1`까지의 이진수로 표현될 수 있습니다.
        *   `0` (000) ~ `7` (111)

    2.  **각 이진수(마스크)를 순회하며 부분집합 생성:**
        *   각 이진수의 `j`번째 비트가 1이면, `nums`의 `j`번째 요소를 현재 부분집합에 포함시킵니다.

        *   **`i = 0 (000)`:**
            *   0번째 비트 (0): `(0 >> 0) & 1 = 0`. `nums[0]` (1) 포함 안 함.
            *   1번째 비트 (0): `(0 >> 1) & 1 = 0`. `nums[1]` (2) 포함 안 함.
            *   2번째 비트 (0): `(0 >> 2) & 1 = 0`. `nums[2]` (3) 포함 안 함.
            *   **부분집합:** `[]`

        *   **`i = 1 (001)`:**
            *   0번째 비트 (1): `(1 >> 0) & 1 = 1`. `nums[0]` (1) 포함.
            *   1번째 비트 (0): `(1 >> 1) & 1 = 0`. `nums[1]` (2) 포함 안 함.
            *   2번째 비트 (0): `(1 >> 2) & 1 = 0`. `nums[2]` (3) 포함 안 함.
            *   **부분집합:** `[1]`

        *   **`i = 2 (010)`:**
            *   0번째 비트 (0): `(2 >> 0) & 1 = 0`. `nums[0]` (1) 포함 안 함.
            *   1번째 비트 (1): `(2 >> 1) & 1 = 1`. `nums[1]` (2) 포함.
            *   2번째 비트 (0): `(2 >> 2) & 1 = 0`. `nums[2]` (3) 포함 안 함.
            *   **부분집합:** `[2]`

        *   **`i = 3 (011)`:**
            *   0번째 비트 (1): `(3 >> 0) & 1 = 1`. `nums[0]` (1) 포함.
            *   1번째 비트 (1): `(3 >> 1) & 1 = 1`. `nums[1]` (2) 포함.
            *   2번째 비트 (0): `(3 >> 2) & 1 = 0`. `nums[2]` (3) 포함 안 함.
            *   **부분집합:** `[1, 2]`

        *   ... (이하 생략)

        *   **`i = 7 (111)`:**
            *   0번째 비트 (1): `(7 >> 0) & 1 = 1`. `nums[0]` (1) 포함.
            *   1번째 비트 (1): `(7 >> 1) & 1 = 1`. `nums[1]` (2) 포함.
            *   2번째 비트 (1): `(7 >> 2) & 1 = 1`. `nums[2]` (3) 포함.
            *   **부분집합:** `[1, 2, 3]`

    *   **최종 부분집합 목록:** `[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]`

*   **시간 복잡도:** `O(n * 2^n)` - `2^n` 개의 부분집합 각각에 대해 `n`개의 요소를 확인합니다.
*   **공간 복잡도:** `O(n * 2^n)` - 모든 부분집합을 저장합니다.

*   **구현:**
```python
def generate_subsets(nums):
    n = len(nums)
    subsets = []
    # 2^n 개의 부분집합을 생성하기 위해 0부터 (2^n - 1)까지 반복
    for i in range(1 << n): # (1 << n)은 2의 n승을 의미
        current_subset = []
        # 각 비트(j)가 nums의 j번째 요소의 포함 여부를 나타냄
        for j in range(n):
            if (i >> j) & 1: # i의 j번째 비트가 1이면 (해당 요소가 부분집합에 포함됨)
                current_subset.append(nums[j])
        subsets.append(current_subset)
    return subsets

# 예시
# print(generate_subsets([1, 2, 3]))
# [[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
```

*   **특징:**
    *   **빠른 연산:** 비트 연산은 CPU에서 직접 처리되므로 매우 빠릅니다.
    *   **메모리 효율성:** 여러 개의 불리언 상태를 하나의 정수로 표현하여 메모리를 절약할 수 있습니다.
    *   **집합 연산:** 비트 연산자를 사용하여 집합의 합집합, 교집합, 차집합 등을 효율적으로 구현할 수 있습니다.

*   **장점 및 단점:**
    *   **장점:**
        *   매우 빠른 실행 속도와 낮은 메모리 사용량으로 성능 최적화에 유리합니다.
        *   특정 유형의 문제(부분집합, 상태 관리, 권한 시스템 등)를 간결하고 효율적으로 해결할 수 있습니다.
    *   **단점:**
        *   코드의 가독성이 떨어질 수 있습니다. (비트 연산에 익숙하지 않은 경우)
        *   적용할 수 있는 문제의 범위가 제한적입니다. (주로 정수형 데이터에 적용)
        *   디버깅이 어려울 수 있습니다.
