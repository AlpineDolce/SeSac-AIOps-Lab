## 3. 비선형 자료구조 및 정렬/탐색 알고리즘

비선형 자료구조는 데이터를 계층적 또는 네트워크 형태로 저장하여, 복잡한 관계를 표현하고 효율적인 탐색 및 관리를 가능하게 합니다.

### 3.1. 트리 (Tree)

트리는 노드와 간선으로 이루어진 비선형 자료구조로, 사이클이 없는 연결 그래프의 한 종류입니다. 데이터를 계층적인 구조로 표현하며, 파일 시스템, 조직도, 데이터베이스 인덱스 등 다양한 분야에서 활용됩니다.

#### 3.1.1. 트리의 개념과 기본 용어

*   **노드 (Node):** 트리를 구성하는 기본 요소. 데이터를 저장합니다.
*   **루트 노드 (Root Node):** 트리의 가장 상위에 있는 노드. 유일하며, 부모가 없습니다.
*   **부모 노드 (Parent Node):** 특정 노드의 바로 위에 연결된 노드.
*   **자식 노드 (Child Node):** 특정 노드의 바로 아래에 연결된 노드.
*   **형제 노드 (Sibling Node):** 같은 부모를 가지는 노드들.
*   **리프 노드 (Leaf Node):** 자식이 없는 노드 (단말 노드). 트리의 가장 아래쪽에 위치합니다.
*   **내부 노드 (Internal Node):** 리프 노드가 아닌 노드. 하나 이상의 자식을 가집니다.
*   **간선 (Edge):** 노드들을 연결하는 선. 부모-자식 관계를 나타냅니다.
*   **경로 (Path):** 한 노드에서 다른 노드까지 간선들을 따라 이동하는 순서.
*   **깊이 (Depth):** 루트 노드로부터 특정 노드까지의 간선 수. 루트 노드의 깊이는 0입니다.
*   **높이 (Height):** 특정 노드로부터 해당 노드의 자손 리프 노드까지의 가장 긴 경로의 간선 수. 트리의 높이는 루트 노드의 높이와 같습니다.
*   **차수 (Degree):** 노드가 가지는 자식 노드의 수. 트리의 차수는 노드들의 차수 중 가장 큰 값입니다.

#### 3.1.2. 이진 트리 (Binary Tree)

이진 트리는 각 노드가 최대 두 개의 자식 노드(왼쪽 자식, 오른쪽 자식)를 가지는 트리입니다. 이는 데이터의 계층적 구조를 표현하고, 효율적인 탐색 및 정렬 알고리즘의 기반이 됩니다.

*   **종류:**
    *   **정 이진 트리 (Full Binary Tree):** 모든 노드가 0개 또는 2개의 자식 노드를 가집니다.
    *   **완전 이진 트리 (Complete Binary Tree):** 마지막 레벨을 제외한 모든 레벨이 완전히 채워져 있고, 마지막 레벨은 왼쪽부터 채워져 있습니다. **힙(Heap) 자료구조 구현에 효율적이며, 배열로 표현하기 용이합니다.**
    *   **포화 이진 트리 (Perfect Binary Tree):** 모든 내부 노드가 두 개의 자식을 가지고, 모든 리프 노드가 같은 깊이에 있습니다. **가장 균형 잡힌 형태의 이진 트리입니다.**
    *   **편향 이진 트리 (Skewed Binary Tree):** 모든 노드가 한쪽 방향(왼쪽 또는 오른쪽)으로만 자식을 가지는 트리입니다. 이 경우 트리의 높이가 노드 수에 비례하여 `O(n)`이 되며, 탐색 성능이 선형 탐색과 유사하게 저하됩니다. 이는 이진 탐색 트리의 최악의 경우 성능을 야기합니다.

#### 3.1.3. 이진 탐색 트리 (Binary Search Tree, BST)

이진 탐색 트리는 이진 트리의 일종으로, 효율적인 탐색, 삽입, 삭제를 위해 특정 규칙을 따릅니다.

*   **BST의 특징:**
    *   모든 노드의 왼쪽 서브트리에는 해당 노드의 값보다 작은 값만 있습니다.
    *   모든 노드의 오른쪽 서브트리에는 해당 노드의 값보다 큰 값만 있습니다.
    *   중복된 값은 허용되지 않거나, 특정 규칙에 따라 처리됩니다. (일반적으로 중복을 허용하지 않거나, 삽입 시 무시합니다.)

##### 3.1.3.1. BST의 특징과 연산 (삽입, 삭제, 탐색)

*   **탐색 (Search):** 루트부터 시작하여 값을 비교하며 왼쪽 또는 오른쪽 서브트리로 이동합니다. 평균 `O(log n)`, 최악 `O(n)`.
*   **삽입 (Insertion):** 탐색과 유사하게 적절한 위치(리프 노드)를 찾아 새 노드를 추가합니다. 평균 `O(log n)`, 최악 `O(n)`.
*   **삭제 (Deletion):** 노드를 삭제할 때 트리의 이진 탐색 트리 속성을 유지하는 것이 중요합니다. 삭제할 노드의 자식 수에 따라 세 가지 경우가 있습니다.
    1.  **자식 노드가 없는 경우 (리프 노드):** 단순히 해당 노드를 트리에서 제거합니다.
    2.  **자식 노드가 하나인 경우:** 삭제할 노드를 그 유일한 자식 노드로 대체합니다. (예: 삭제할 노드의 부모가 삭제할 노드의 자식을 가리키도록 변경)
    3.  **자식 노드가 두 개인 경우:** 삭제할 노드를 대체할 노드를 찾아야 합니다. 일반적으로 삭제할 노드의 오른쪽 서브트리에서 가장 작은 값(최소값, Inorder Successor)을 가진 노드 또는 왼쪽 서브트리에서 가장 큰 값(최대값, Inorder Predecessor)을 가진 노드를 찾아 삭제할 노드를 대체하고, 대체된 노드를 원래 위치에서 삭제합니다. 이 과정은 재귀적으로 처리될 수 있습니다.
*   **시간 복잡도:** 탐색, 삽입, 삭제 모두 평균 `O(log n)`, 최악 `O(n)`. (최악의 경우는 트리가 편향되었을 때 발생)

##### 3.1.3.2. 파이썬 구현

```python
class BSTNode:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

class BinarySearchTree:
    def __init__(self):
        self.root = None

    def insert(self, key):
        if self.root is None:
            self.root = BSTNode(key)
        else:
            self._insert_recursive(self.root, key)

    def _insert_recursive(self, node, key):
        if key < node.key:
            if node.left is None:
                node.left = BSTNode(key)
            else:
                self._insert_recursive(node.left, key)
        elif key > node.key:
            if node.right is None:
                node.right = BSTNode(key)
            else:
                self._insert_recursive(node.right, key)
        # else: key already exists, do nothing or handle duplicates

    def search(self, key):
        return self._search_recursive(self.root, key)

    def _search_recursive(self, node, key):
        if node is None or node.key == key:
            return node
        if key < node.key:
            return self._search_recursive(node.left, key)
        return self._search_recursive(node.right, key)

    def delete(self, key):
        self.root = self._delete_recursive(self.root, key)

    def _delete_recursive(self, node, key):
        if node is None:
            return node

        if key < node.key:
            node.left = self._delete_recursive(node.left, key)
        elif key > node.key:
            node.right = self._delete_recursive(node.right, key)
        else: # node.key == key, this is the node to be deleted
            # Case 1: No child or one child
            if node.left is None:
                return node.right
            elif node.right is None:
                return node.left
            
            # Case 2: Two children
            # Find the inorder successor (smallest in the right subtree)
            temp = self._min_value_node(node.right)
            node.key = temp.key # Copy the inorder successor's content to this node
            node.right = self._delete_recursive(node.right, temp.key) # Delete the inorder successor
        return node

    def _min_value_node(self, node):
        current = node
        while current.left is not None:
            current = current.left
        return current

    def inorder_traversal(self):
        # 중위 순회 (정렬된 순서로 노드 방문)
        result = []
        self._inorder_recursive(self.root, result)
        return result

    def _inorder_recursive(self, node, result):
        if node:
            self._inorder_recursive(node.left, result)
            result.append(node.key)
            self._inorder_recursive(node.right, result)
```

#### 3.1.4. B-트리 (B-Tree) 및 B+트리 (B+Tree)

B-트리와 B+트리는 대용량 데이터를 디스크에 저장하고 관리하는 데 최적화된 균형 탐색 트리입니다. 데이터베이스 인덱스 및 파일 시스템에서 널리 사용됩니다.

##### 3.1.4.1. B-트리의 개념과 특징 (디스크 기반 자료구조)

*   **개념:** 모든 리프 노드가 같은 레벨에 있도록 자동으로 균형을 맞추는 자가 균형(Self-balancing) 탐색 트리입니다. 각 노드는 여러 개의 키와 자식을 가질 수 있습니다.
*   **차수 (Order):** B-트리의 차수 `m`은 각 노드가 가질 수 있는 최대 자식 수와 키의 수를 결정합니다. `m`차 B-트리는 각 노드가 `m-1`개 이하의 키를 가집니다. 노드의 크기는 디스크 블록 크기에 맞춰 최적화됩니다.
*   **특징:**
    *   **다차원 노드:** 하나의 노드에 여러 개의 키와 자식 포인터를 저장하여 **디스크 블록 크기에 맞춰 노드 크기를 최적화함으로써** 디스크 I/O를 최소화합니다.
    *   **균형 유지:** 삽입 및 삭제 시 트리의 높이를 낮게 유지하여 모든 연산이 `O(log n)` 시간을 보장합니다. (여기서 `n`은 전체 키의 수)
    *   **내부 노드에 데이터 저장:** 키와 함께 실제 데이터 또는 데이터에 대한 포인터를 저장할 수 있습니다.

##### 3.1.4.2. B+트리의 개념과 특징 (데이터베이스 인덱스)

*   **개념:** B-트리의 변형으로, 모든 데이터는 리프 노드에만 저장되고, 리프 노드들은 서로 연결되어 있습니다. 내부 노드는 오직 키와 자식 포인터만을 가집니다.
*   **특징:**
    *   **리프 노드에만 데이터 저장:** 모든 데이터가 리프 노드에만 존재하므로, **모든 검색 경로가 리프 노드에서 끝나며**, 범위 검색(Range Query)에 매우 효율적입니다. 내부 노드는 인덱스 역할만 수행하여 더 많은 키를 저장할 수 있습니다.
    *   **리프 노드 연결:** 리프 노드들이 링크드 리스트처럼 연결되어 있어 **순차적인 데이터 접근(Sequential Scan)이 매우 빠릅니다.** 이는 데이터베이스에서 특정 범위의 데이터를 조회할 때 큰 장점입니다.
    *   **데이터베이스 인덱스:** 대부분의 관계형 데이터베이스 시스템에서 인덱스 구조로 B+트리를 사용합니다.


##### 3.1.4.3. B-트리/B+트리 활용 사례 (파일 시스템, 데이터베이스)

*   **파일 시스템:** 대용량 파일 시스템(예: NTFS, HFS+)에서 파일 및 디렉토리 구조를 관리하는 데 사용됩니다.
*   **데이터베이스 인덱스:** MySQL의 InnoDB, PostgreSQL 등 대부분의 관계형 데이터베이스에서 테이블의 인덱스를 구현하는 데 사용되어 빠른 데이터 검색을 가능하게 합니다.

### 3.2. 트리 순회 (Tree Traversal)

트리 순회는 트리의 모든 노드를 체계적으로 방문하는 방법입니다. 트리의 구조를 탐색하고 데이터를 처리하는 데 필수적이며, 깊이 우선 탐색(DFS: Depth-First Search)과 너비 우선 탐색(BFS: Breadth-First Search)의 두 가지 주요 접근 방식이 있습니다. 순회 방식에 따라 노드를 방문하는 순서가 달라지며, 이는 문제 해결에 중요한 영향을 미칩니다.

#### 3.2.1. 순회 종류와 특징 (전위, 중위, 후위, 레벨 순회)

트리 순회는 크게 깊이 우선 순회(DFS)와 너비 우선 순회(BFS)로 나눌 수 있습니다.

*   **깊이 우선 순회 (DFS: Depth-First Search):**
    *   **전위 순회 (Preorder Traversal):** **루트 노드를 먼저 방문한 후**, 왼쪽 서브트리를 전위 순회하고, 이어서 오른쪽 서브트리를 전위 순회합니다. (Root -> Left -> Right)
        *   활용: 트리를 복사하거나, 표현식 트리를 전위 표기법(Prefix Notation)으로 변환할 때, 트리의 구조를 그대로 출력할 때 유용합니다.
    *   **중위 순회 (Inorder Traversal):** 왼쪽 서브트리를 중위 순회한 후, **루트 노드를 방문하고**, 이어서 오른쪽 서브트리를 중위 순회합니다. (Left -> Root -> Right)
        *   활용: 이진 탐색 트리를 중위 순회하면 노드들이 **정렬된 순서로 방문**됩니다. 수식 트리를 중위 표기법(Infix Notation)으로 변환할 때 사용됩니다.
    *   **후위 순회 (Postorder Traversal):** 왼쪽 서브트리를 후위 순회한 후, 오른쪽 서브트리를 후위 순회하고, **마지막으로 루트 노드를 방문합니다.** (Left -> Right -> Root)
        *   활용: 트리를 삭제하거나, 표현식 트리를 후위 표기법(Postfix Notation)으로 변환할 때, 디렉토리의 파일 크기를 계산하는 등 자식 노드의 처리가 부모 노드보다 먼저 필요한 경우에 사용됩니다.

*   **너비 우선 순회 (BFS: Breadth-First Search):**
    *   **레벨 순회 (Level Order Traversal):** 트리의 각 레벨을 위에서 아래로, 왼쪽에서 오른쪽으로 순서대로 노드를 방문합니다. 큐(Queue) 자료구조를 사용하여 구현합니다.
        *   활용: 트리의 높이 계산, 최단 경로 탐색 (예: 미로 찾기), 네트워크의 최단 경로 탐색 등에 사용됩니다.

#### 3.2.2. 재귀적 순회 구현

트리 순회는 재귀적으로 구현하는 것이 가장 직관적이고 간결합니다. 재귀 호출은 내부적으로 시스템 스택을 사용하여 노드의 방문 순서를 관리합니다.

```python
# BSTNode 클래스 사용 (이전 섹션에서 정의된 BSTNode 사용)

def preorder_recursive(node, result):
    if node:
        result.append(node.key)
        preorder_recursive(node.left, result)
        preorder_recursive(node.right, result)

def inorder_recursive(node, result):
    if node:
        inorder_recursive(node.left, result)
        result.append(node.key)
        inorder_recursive(node.right, result)

def postorder_recursive(node, result):
    if node:
        postorder_recursive(node.left, result)
        postorder_recursive(node.right, result)
        result.append(node.key)
```

#### 3.2.3. 반복적 순회 구현 (스택/큐 활용)

재귀는 내부적으로 스택을 사용하므로, 명시적인 스택이나 큐를 사용하여 반복적으로 순회를 구현할 수도 있습니다. 이는 재귀 깊이 제한을 피하거나 성능 최적화가 필요할 때 유용합니다.

*   **전위 순회 (스택):**
    ```python
    def preorder_iterative(root):
        if not root: return []
        result = []
        stack = [root] # 스택에 루트 노드를 추가
        while stack:
            node = stack.pop() # 스택의 최상단 노드를 꺼냄
            result.append(node.key) # 노드 방문
            if node.right: stack.append(node.right) # 오른쪽 자식 먼저 스택에 넣어 나중에 처리 (LIFO)
            if node.left: stack.append(node.left)   # 왼쪽 자식 나중에 스택에 넣어 먼저 처리
        return result
    ```
*   **중위 순회 (스택):**
    ```python
    def inorder_iterative(root):
        result = []
        stack = []
        current = root
        while current or stack:
            while current:
                stack.append(current)
                current = current.left # 왼쪽 끝까지 이동하며 스택에 노드 추가
            current = stack.pop() # 왼쪽 끝 노드 (가장 작은 값) 꺼냄
            result.append(current.key) # 노드 방문
            current = current.right # 오른쪽 서브트리로 이동
        return result
    ```
*   **후위 순회 (스택):**
    ```python
    def postorder_iterative(root):
        if not root: return []
        result = []
        stack = [root]
        visited = set() # 이미 처리된 노드를 추적하기 위한 집합
        while stack:
            node = stack[-1] # 스택의 최상단 노드를 확인 (꺼내지 않음)
            # 왼쪽 자식이 있고 아직 방문하지 않았다면 왼쪽으로 이동
            if node.left and node.left not in visited:
                stack.append(node.left)
            # 오른쪽 자식이 있고 아직 방문하지 않았다면 오른쪽으로 이동
            elif node.right and node.right not in visited:
                stack.append(node.right)
            else: # 자식이 없거나 모두 방문했다면 현재 노드 방문
                result.append(stack.pop().key)
                visited.add(node) # 방문한 노드를 기록
        return result
    ```
*   **레벨 순회 (큐):**
    ```python
    from collections import deque

    def levelorder_iterative(root):
        if not root: return []
        result = []
        queue = deque([root]) # 큐에 루트 노드를 추가
        while queue:
            node = queue.popleft() # 큐의 맨 앞 노드를 꺼냄
            result.append(node.key) # 노드 방문
            if node.left: queue.append(node.left) # 왼쪽 자식 큐에 추가
            if node.right: queue.append(node.right) # 오른쪽 자식 큐에 추가
        return result
    ```

#### 3.2.4. 이진 트리의 배열 표현

완전 이진 트리의 경우, 배열을 사용하여 효율적으로 표현할 수 있습니다. 이는 힙(Heap) 구현에 주로 사용됩니다. 배열의 인덱스를 통해 부모-자식 관계를 쉽게 파악할 수 있습니다.

*   **인덱스 계산 (0-based index 기준):**
    *   루트 노드: 인덱스 0
    *   부모 노드 `i`의 왼쪽 자식: `2 * i + 1`
    *   부모 노드 `i`의 오른쪽 자식: `2 * i + 2`
    *   자식 노드 `j`의 부모: `(j - 1) // 2`
*   **예시:**
    ```
          A (0)
         / \
        B (1) C (2)
       / \
      D (3) E (4)
    ```
    배열 표현: `[A, B, C, D, E]`

#### 3.2.5. 수식 트리와 순회 (전위, 중위, 후위 표기법)

수식 트리는 연산자와 피연산자로 구성된 이진 트리로, 수식을 표현하는 데 사용됩니다. 순회 방식에 따라 수식의 표기법이 달라지며, 이는 컴파일러나 계산기 구현에 활용됩니다.

*   **예시 수식:** `(A + B) * C`
    *   **전위 표기법 (Prefix Notation):** 연산자 -> 피연산자1 -> 피연산자2 (예: `* + A B C`)
        *   수식 트리에서 전위 순회 시 얻어지는 순서입니다.
    *   **중위 표기법 (Infix Notation):** 피연산자1 -> 연산자 -> 피연산자2 (예: `A + B * C`)
        *   우리가 일반적으로 사용하는 수식 표기법입니다. 수식 트리에서 중위 순회 시 얻어지는 순서입니다. (괄호는 연산자 우선순위를 명확히 하기 위해 필요할 수 있습니다.)
    *   **후위 표기법 (Postfix Notation):** 피연산자1 -> 피연산자2 -> 연산자 (예: `A B + C *`)
        *   역폴란드 표기법(Reverse Polish Notation, RPN)이라고도 불리며, 스택을 사용하여 수식을 쉽게 계산할 수 있습니다. 수식 트리에서 후위 순회 시 얻어지는 순서입니다.


### 3.3. 균형 이진 탐색 트리 (Balanced Binary Search Tree)

이진 탐색 트리는 데이터가 편향되게 삽입될 경우 트리의 높이가 `O(n)`이 되어 탐색, 삽입, 삭제 성능이 `O(n)`으로 저하될 수 있습니다. 일반 이진 탐색 트리는 데이터가 정렬된 순서로 삽입될 경우 연결 리스트와 유사한 형태(편향 트리)가 되어, 탐색, 삽입, 삭제 연산의 시간 복잡도가 최악의 경우 `O(n)`까지 증가할 수 있습니다. 균형 이진 탐색 트리는 이러한 문제를 해결하기 위해 트리의 높이를 `O(log n)`으로 유지하는 자가 균형(Self-balancing) 트리입니다.

#### 3.3.1. 균형 이진 탐색 트리의 필요성

*   최악의 경우 `O(n)` 성능을 `O(log n)`으로 보장하여 안정적인 성능을 제공합니다.
*   대용량 데이터 처리 및 실시간 시스템에서 필수적입니다.
*   데이터의 삽입 순서에 관계없이 일관된 성능을 유지합니다.

#### 3.3.2. AVL 트리 (AVL Tree)

*   **개념:** 모든 노드의 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 1 이하인 이진 탐색 트리입니다. AVL 트리는 가장 엄격하게 균형을 유지하는 이진 탐색 트리 중 하나입니다.
*   **균형 인수 (Balance Factor):** `왼쪽 서브트리 높이 - 오른쪽 서브트리 높이` (값은 -1, 0, 1 중 하나). 이 균형 인수를 통해 트리의 균형 상태를 판단합니다.
*   **재균형:** 삽입 및 삭제 후 균형 인수가 1을 초과하면, 트리는 **회전(Rotation)** 연산을 통해 스스로 균형을 맞춥니다. 회전에는 LL (Left-Left), RR (Right-Right), LR (Left-Right), RL (Right-Left)의 네 가지 기본 유형이 있으며, 이들을 통해 트리의 높이를 효율적으로 재조정합니다. 각 회전은 `O(1)` 시간에 수행됩니다.

#### 3.3.3. 레드-블랙 트리 (Red-Black Tree)

*   **개념:** 노드를 빨간색 또는 검은색으로 색칠하여 균형을 유지하는 이진 탐색 트리입니다. AVL 트리보다 덜 엄격하게 균형을 유지하지만, 삽입/삭제 시 회전 횟수가 적어 실제 성능이 더 좋을 수 있습니다. 이는 대부분의 표준 라이브러리에서 맵(Map)과 셋(Set) 구현에 사용되는 이유이기도 합니다.
*   **규칙:** 레드-블랙 트리는 다음 다섯 가지 규칙을 항상 만족해야 합니다.
    1.  모든 노드는 빨간색 또는 검은색입니다.
    2.  루트 노드는 검은색입니다.
    3.  모든 리프 노드(NIL 노드, 실제 데이터가 없는 가상의 노드)는 검은색입니다.
    4.  빨간색 노드의 자식은 모두 검은색입니다. (즉, 빨간색 노드는 연속될 수 없으며, 모든 경로에서 빨간색 노드는 하나 건너 하나씩 나타납니다.)
    5.  어떤 노드로부터 그 노드의 자손 리프 노드까지의 모든 경로에는 같은 수의 검은색 노드가 있습니다. 이를 **검은 높이(Black Height)**라고 하며, 이 규칙이 트리의 균형을 보장하는 핵심입니다.

#### 3.3.4. 활용 사례 (맵, 셋 구현)

*   **맵 (Map) 및 셋 (Set) 구현:** C++의 `std::map`, `std::set`이나 Java의 `TreeMap`, `TreeSet` 등 많은 표준 라이브러리에서 균형 이진 탐색 트리를 사용하여 정렬된 키-값 쌍 또는 고유한 요소 집합을 효율적으로 관리합니다.
*   **데이터베이스 인덱스:** B-트리/B+트리와 함께 데이터베이스 인덱스 구현에 사용됩니다.
*   **운영체제 스케줄러:** 프로세스 스케줄링에 사용될 수 있습니다.
*   **네트워크 라우팅:** 라우팅 테이블 관리에 활용될 수 있습니다.
