# PyTorch 고급 디버깅 및 성능 프로파일링

## 1. 딥러닝 모델 디버깅의 필요성

### 1.1. 딥러닝 모델 디버깅의 어려움

딥러닝 모델은 복잡한 비선형 변환과 수많은 파라미터로 구성되어 있어, 마치 블랙박스처럼 동작하는 경우가 많습니다. 모델이 예상대로 작동하지 않거나 성능이 저조할 때, 문제의 원인을 파악하는 것은 매우 어려운 일입니다. 특히, PyTorch의 동적 계산 그래프(Dynamic Computational Graph)는 디버깅에 유연성을 제공하지만, 동시에 미묘한 버그를 숨기기도 합니다.

### 1.2. 흔히 발생하는 문제점

*   **손실(Loss)이 `NaN` (Not a Number) 또는 `Inf` (Infinity)가 됨**: 학습률이 너무 높거나, 데이터에 이상치(outlier)가 있거나, 특정 연산에서 수치적 불안정성이 발생할 때 나타납니다.
*   **손실이 감소하지 않음**: 학습률이 너무 낮거나, 모델 구조에 문제가 있거나, 데이터에 오류가 있을 때 발생할 수 있습니다.
*   **기울기 소실(Vanishing Gradients) 또는 기울기 폭주(Exploding Gradients)**: 역전파 과정에서 기울기 값이 너무 작아지거나 너무 커져 파라미터 업데이트가 제대로 이루어지지 않는 현상입니다.
*   **예측 결과가 잘못됨**: 모델이 학습은 되는 것 같지만, 실제 예측 결과가 기대와 다를 때 발생합니다.
*   **학습 속도가 느림**: GPU 활용률이 낮거나, 데이터 로딩이 병목 현상을 일으키거나, 비효율적인 연산이 있을 때 발생합니다.
*   **GPU 메모리 부족**: 모델이나 배치 크기가 너무 커서 GPU 메모리에 올릴 수 없을 때 발생합니다.

## 2. 고급 디버깅 기법

### 2.1. `pdb`를 이용한 Python 디버깅

PyTorch는 Python 기반이므로, 표준 Python 디버거인 `pdb`를 사용하여 코드를 단계별로 실행하고 변수 값을 검사할 수 있습니다. `import pdb; pdb.set_trace()`를 코드에 삽입하여 원하는 지점에서 실행을 멈출 수 있습니다.

```python

def simple_operation(x):
    y = x * 2
    # import pdb; pdb.set_trace() # 여기에 중단점 설정
    z = y + 1
    return z
```


### 2.5. 데이터 확인

데이터 로딩, 전처리, 증강 과정에서 오류가 발생하면 모델 학습에 큰 영향을 미칩니다. 데이터셋의 샘플을 시각화하거나, 통계량을 확인하여 데이터가 올바르게 로드되고 변환되었는지 검증해야 합니다.

### 2.6. `torch.set_printoptions`: Tensor 출력 설정

Tensor를 출력할 때 표시되는 정밀도, 과학적 표기법 사용 여부 등을 설정하여 디버깅에 더 유용한 정보를 얻을 수 있습니다.

```python
import torch

torch.set_printoptions(precision=4, sci_notation=False) # 소수점 4자리까지, 과학적 표기법 사용 안 함
x = torch.randn(3)
print(f"Tensor with custom print options: {x}")

torch.set_printoptions(profile="default") # 기본 설정으로 복원
```

## 3. 프로파일링 (Profiling) 기법

### 3.1. 프로파일링의 필요성

모델이 올바르게 학습되더라도, 학습 속도가 느리거나 추론 시간이 길다면 실제 서비스에 적용하기 어렵습니다. 프로파일링은 모델 학습 및 추론 과정에서 CPU, GPU, 메모리, I/O 등 어떤 부분에서 시간이 가장 많이 소요되는지(병목 현상)를 식별하여 성능 최적화의 방향을 제시합니다.

### 3.2. `torch.profiler`: PyTorch 내장 프로파일러

`torch.profiler`는 PyTorch 1.8부터 도입된 강력한 내장 프로파일러입니다. CPU 및 GPU 연산 시간, 메모리 사용량, 커널 실행 시간 등 상세한 정보를 수집할 수 있으며, TensorBoard와 연동하여 시각적으로 분석할 수 있습니다.


### 3.3. NVIDIA GPU 프로파일러 (`nvprof`, `Nsight Systems`)

NVIDIA GPU를 사용하는 경우, `nvprof` (레거시) 또는 `Nsight Systems` (권장)와 같은 저수준(low-level) GPU 프로파일러를 사용하여 GPU 커널 실행 시간, 메모리 전송, GPU 활용률 등 매우 상세한 GPU 성능 데이터를 수집할 수 있습니다. 이는 PyTorch 프로파일러보다 더 깊이 있는 GPU 레벨의 병목 현상을 분석하는 데 유용합니다.

### 3.4. Python 코드 프로파일러 (`cProfile`, `line_profiler`)

모델의 CPU 바운드(CPU-bound) 부분(예: 데이터 전처리, 커스텀 로직)에서 병목 현상이 발생할 경우, Python 표준 라이브러리의 `cProfile`이나 외부 라이브러리인 `line_profiler`를 사용하여 코드의 어떤 라인에서 시간이 가장 많이 소요되는지 분석할 수 있습니다.

## 4. 메모리 관리 및 최적화

### 4.1. GPU 메모리 사용량 확인

*   **`nvidia-smi`**: 터미널에서 GPU의 현재 메모리 사용량과 활용률을 확인할 수 있습니다.
*   **`torch.cuda.memory_allocated()`**: 현재 PyTorch가 할당한 GPU 메모리 양을 바이트 단위로 반환합니다.
*   **`torch.cuda.memory_reserved()`**: PyTorch가 현재 GPU에 예약해 둔 총 메모리 양을 바이트 단위로 반환합니다.

```python
import torch

if torch.cuda.is_available():
    # 더미 Tensor 생성
    a = torch.randn(1000, 1000).cuda()
    print(f"Memory allocated: {torch.cuda.memory_allocated() / (1024**2):.2f} MB")
    print(f"Memory reserved: {torch.cuda.memory_reserved() / (1024**2):.2f} MB")

    del a # Tensor 삭제
    torch.cuda.empty_cache() # 캐시된 메모리 해제
    print(f"Memory allocated after del and empty_cache: {torch.cuda.memory_allocated() / (1024**2):.2f} MB")
else:
    print("CUDA not available.")
```

### 4.2. 메모리 절약 팁

*   **배치 크기 줄이기**: 가장 직접적인 방법입니다.
*   **`torch.no_grad()` 사용**: 평가 및 추론 시 기울기 계산을 비활성화하여 메모리를 절약합니다.
*   **불필요한 Tensor 삭제**: `del` 키워드를 사용하여 더 이상 사용하지 않는 Tensor를 명시적으로 삭제하고, `torch.cuda.empty_cache()`를 호출하여 PyTorch의 GPU 메모리 캐시를 비웁니다.
*   **혼합 정밀도 학습 (AMP)**: FP16을 사용하여 메모리 사용량을 절반으로 줄입니다.
*   **기울기 누적 (Gradient Accumulation)**: 실제 배치 크기를 줄이면서 유효 배치 크기를 유지합니다.
*   **체크포인팅 (Checkpointing)**: 매우 깊은 모델의 경우, 중간 활성화 값을 저장하지 않고 필요할 때 재계산하여 메모리를 절약합니다 (`torch.utils.checkpoint`).

## 5. 결론

딥러닝 모델 개발은 단순히 코드를 작성하고 학습시키는 것을 넘어, 발생하는 문제들을 효과적으로 진단하고 성능을 최적화하는 과정이 필수적입니다. PyTorch는 `torch.autograd.set_detect_anomaly`, `torch.profiler`와 같은 강력한 내장 도구들을 제공하며, Python의 유연성과 GPU 프로파일러를 결합하여 복잡한 딥러닝 모델의 디버깅 및 성능 분석을 가능하게 합니다. 이러한 고급 디버깅 및 프로파일링 기법들을 숙달함으로써, 개발자는 더 견고하고 효율적이며 고성능의 딥러닝 모델을 성공적으로 구축할 수 있을 것입니다.
