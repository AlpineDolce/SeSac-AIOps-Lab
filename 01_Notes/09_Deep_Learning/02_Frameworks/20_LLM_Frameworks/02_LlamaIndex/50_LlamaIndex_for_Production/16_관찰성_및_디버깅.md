## 1. RAG 파이프라인은 블랙박스인가?

`query_engine.query("...")` 한 줄의 코드는 매우 편리하지만, 내부적으로는 수많은 일들이 일어납니다: 텍스트 분할, 임베딩 모델 호출, 노드 검색, LLM 호출 등. 만약 최종 답변의 품질이 만족스럽지 않을 때, 어느 단계에서 문제가 발생했는지 파악하기란 쉽지 않습니다. 마치 블랙박스를 들여다보는 것과 같습니다.

**관찰성**은 이 블랙박스를 투명한 유리 상자로 만드는 과정입니다. 파이프라인의 모든 단계에서 어떤 이벤트가 발생하고, 어떤 데이터가 오고 가는지 상세히 기록하여 문제의 원인을 쉽게 찾을 수 있도록 돕습니다.

## 2. LlamaIndex의 콜백 시스템

LlamaIndex는 파이프라인의 주요 지점에서 발생하는 이벤트들을 추적하기 위한 **콜백(Callback)** 시스템을 제공합니다. 특정 이벤트(예: 청킹 시작, LLM 호출 시작)가 발생할 때마다 등록된 핸들러(Handler) 함수를 호출하는 방식입니다.

### 2.1. `CallbackManager`와 `LlamaDebugHandler`
- **`CallbackManager`**: 어떤 콜백 핸들러를 사용할지 관리하는 중앙 관리자입니다.
- **`LlamaDebugHandler`**: LlamaIndex가 기본적으로 제공하는 디버깅용 핸들러입니다. 발생하는 모든 이벤트의 이름과 상세 정보를 콘솔에 보기 좋게 출력해줍니다.

## 3. 콜백을 이용한 디버깅 실습

### 3.1. 전역 콜백 매니저 설정
`LlamaIndex`의 `Settings` 객체를 통해 콜백 매니저를 전역적으로 설정하면, 이후의 모든 작업에 해당 콜백이 자동으로 적용됩니다.

```python
from llama_index.core import Settings
from llama_index.core.callbacks import CallbackManager, LlamaDebugHandler

# 1. 디버그 핸들러와 콜백 매니저 생성
llama_debug = LlamaDebugHandler(print_trace_on_end=True)
callback_manager = CallbackManager([llama_debug])

# 2. LlamaIndex 전역 설정에 콜백 매니저 할당
Settings.callback_manager = callback_manager

# 3. 평소처럼 인덱스 생성 및 쿼리 실행
# 이제부터 모든 내부 동작이 콘솔에 출력됨
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()
response = query_engine.query("질문...")
```

### 3.2. 이벤트 로그 분석
위 코드를 실행하면 콘솔에 다음과 같은 상세한 로그가 출력됩니다.

```
**********
STARTING EVENT: text-splitting
  - chunk_size: 1024
  - ...
ENDING EVENT: text-splitting
**********
STARTING EVENT: embedding
  - model: text-embedding-3-small
  - ...
ENDING EVENT: embedding
**********
STARTING EVENT: llm
  - prompt: ...
  - ...
ENDING EVENT: llm
**********
```

이 로그를 통해 우리는 다음과 같은 정보를 명확히 알 수 있습니다.
- 텍스트가 몇 개의 청크로 나뉘었는가?
- 임베딩 모델 호출에 얼마나 시간이 걸렸는가?
- Retriever가 어떤 노드들을 검색했는가?
- 최종적으로 LLM에 어떤 프롬프트가 전달되었는가?

이러한 정보는 RAG 파이프라인의 성능을 분석하고 병목 지점을 찾아 개선하는 데 결정적인 단서를 제공합니다.

## 4. 외부 관찰성 도구 연동

LlamaIndex는 `LlamaDebugHandler` 외에도, LangSmith, Arize, Phoenix 등 전문적인 LLM 관찰성 플랫폼과 쉽게 연동할 수 있는 다양한 콜백 핸들러를 제공합니다. 프로덕션 환경에서는 이러한 외부 도구를 활용하여 성능을 지속적으로 모니터링하고 관리하는 것이 일반적입니다.
