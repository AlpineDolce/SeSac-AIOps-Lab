## 1. LlamaIndex의 인덱스 개요

LlamaIndex에서 '인덱스(Index)'는 외부 데이터를 LLM이 효과적으로 질의하고 검색할 수 있도록 최적화된 구조로 변환하여 저장하는 것을 의미합니다. 인덱스는 RAG(Retrieval-Augmented Generation) 파이프라인의 핵심 구성 요소이며, 쿼리 엔진(Query Engine)이 데이터를 검색하는 기반이 됩니다.

### 1.1. 왜 다양한 인덱스가 필요한가?
데이터는 다양한 형태와 구조를 가집니다. 단순히 텍스트를 임베딩하여 벡터 저장소에 넣는 `VectorStoreIndex`만으로는 모든 쿼리 패턴이나 데이터 특성에 최적화된 성능을 내기 어렵습니다. 예를 들어, 긴 문서의 요약이 필요하거나, 특정 키워드를 포함하는 문서를 정확히 찾아야 하거나, 여러 문서 간의 관계를 파악해야 하는 경우 등 다양한 시나리오에 맞는 인덱스 전략이 필요합니다. LlamaIndex는 이러한 요구사항을 충족시키기 위해 여러 종류의 인덱스를 제공합니다.

## 2. 주요 인덱스 유형

### 2.1. VectorStoreIndex (복습)
가장 널리 사용되는 인덱스입니다. 문서를 임베딩 벡터로 변환하여 벡터 저장소(예: Chroma, Pinecone)에 저장하고, 쿼리 임베딩과의 유사도 검색을 통해 관련 문서를 찾습니다. 의미적 유사도 검색에 강점을 가집니다.

### 2.2. ListIndex: 순차적 탐색
`ListIndex`는 노드(문서 조각)들을 단순히 순서대로 연결된 리스트 형태로 저장합니다. 쿼리가 들어오면 리스트의 시작부터 순차적으로 노드를 탐색하며 LLM에게 전달합니다.

-   **특징**:
    *   모든 노드를 탐색하므로 정보 손실이 적습니다.
    *   긴 문서나 전체 문서의 요약, 특정 정보의 순차적 확인에 유용합니다.
    *   검색 속도는 느릴 수 있습니다.
-   **활용 시나리오**: 전체 문서의 포괄적인 요약, 특정 순서가 중요한 로그 파일 분석.

### 2.3. KeywordTableIndex: 키워드 기반 검색
`KeywordTableIndex`는 각 노드에서 키워드를 추출하고, 이 키워드와 노드를 매핑하는 테이블을 생성합니다. 쿼리가 들어오면 쿼리에서 키워드를 추출하여 해당 키워드와 연결된 노드를 검색합니다.

-   **특징**:
    *   정확한 키워드 매칭에 강합니다.
    *   특정 용어나 개념을 포함하는 문서를 빠르게 찾을 때 유용합니다.
    *   키워드 추출 전략이 중요합니다.
-   **활용 시나리오**: 특정 제품명, 코드 함수명, 고유명사 등을 포함하는 문서 검색.

### 2.4. TreeIndex: 계층적 요약 및 검색
`TreeIndex`는 문서들을 계층적인 트리 구조로 요약하여 저장합니다. 각 부모 노드는 자식 노드들의 요약을 포함하며, 쿼리가 들어오면 트리 구조를 따라 내려가며 가장 관련성 높은 리프 노드를 찾습니다.

-   **특징**:
    *   긴 문서나 여러 문서의 계층적 요약 및 검색에 유용합니다.
    *   전체 문서의 맥락을 유지하면서 특정 부분으로 드릴다운할 수 있습니다.
-   **활용 시나리오**: 긴 보고서, 책, 법률 문서 등 계층적 구조를 가진 문서에서 특정 정보 검색.

### 2.5. CompositeIndex: 여러 인덱스의 조합
`CompositeIndex`는 여러 종류의 인덱스를 조합하여 사용합니다. 예를 들어, `VectorStoreIndex`와 `KeywordTableIndex`를 함께 사용하여 의미적 유사도와 키워드 매칭을 동시에 활용할 수 있습니다.

-   **특징**:
    *   다양한 쿼리 패턴과 데이터 특성에 유연하게 대응할 수 있습니다.
    *   각 인덱스의 장점을 결합하여 검색 성능을 최적화합니다.
-   **활용 시나리오**: 복합적인 질문에 대해 다양한 검색 전략이 필요한 경우.

## 3. 인덱스 선택 가이드

인덱스 선택은 RAG 시스템의 성능에 큰 영향을 미칩니다. 데이터의 특성과 사용자의 쿼리 패턴을 고려하여 최적의 인덱스를 선택해야 합니다.

### 3.1. 데이터 특성 고려
-   **데이터의 길이**: 긴 문서의 요약이 필요하면 `TreeIndex`, 순차적 탐색이 필요하면 `ListIndex`.
-   **데이터의 구조**: 계층적이면 `TreeIndex`, 키워드 중심이면 `KeywordTableIndex`.
-   **데이터의 양**: 대규모 데이터에는 `VectorStoreIndex`가 효율적일 수 있습니다.

### 3.2. 쿼리 패턴 고려
-   **의미적 유사도**: "이 문서의 주제는 무엇인가?"와 같은 질문에는 `VectorStoreIndex`.
-   **정확한 키워드 매칭**: "특정 제품의 가격은 얼마인가?"와 같은 질문에는 `KeywordTableIndex`.
-   **포괄적 요약**: "이 보고서의 핵심 내용은?"과 같은 질문에는 `ListIndex` 또는 `TreeIndex`.
-   **복합적인 질문**: 여러 검색 전략이 필요하면 `CompositeIndex`.

## 4. 인덱스 구축 및 활용 예시

각 인덱스는 `from_documents` 메서드를 사용하여 문서를 기반으로 쉽게 구축할 수 있습니다.

### 4.1. ListIndex 예시
```python
from llama_index.core import SimpleDirectoryReader, ListIndex

# 문서 로드
documents = SimpleDirectoryReader(input_files=["./data/example.txt"]).load_data()

# ListIndex 구축
list_index = ListIndex.from_documents(documents)

# 쿼리 엔진 생성 및 질의
query_engine = list_index.as_query_engine()
response = query_engine.query("이 문서의 모든 내용을 요약해줘.")
print(response)
```

### 4.2. KeywordTableIndex 예시
```python
from llama_index.core import SimpleDirectoryReader, KeywordTableIndex

# 문서 로드
documents = SimpleDirectoryReader(input_files=["./data/example.txt"]).load_data()

# KeywordTableIndex 구축
keyword_index = KeywordTableIndex.from_documents(documents)

# 쿼리 엔진 생성 및 질의
query_engine = keyword_index.as_query_engine()
response = query_engine.query("이 문서에서 'LlamaIndex'에 대한 정보를 찾아줘.")
print(response)
```

### 4.3. TreeIndex 예시
```python
from llama_index.core import SimpleDirectoryReader, TreeIndex

# 문서 로드
documents = SimpleDirectoryReader(input_files=["./data/example.txt"]).load_data()

# TreeIndex 구축
tree_index = TreeIndex.from_documents(documents)

# 쿼리 엔진 생성 및 질의
query_engine = tree_index.as_query_engine()
response = query_engine.query("이 문서의 핵심 주제는 무엇인가?")
print(response)
```
