## 1. 쿼리 변환의 필요성

RAG(Retrieval-Augmented Generation) 시스템에서 검색 단계의 성능은 최종 답변의 품질에 결정적인 영향을 미칩니다. 하지만 사용자의 원본 쿼리는 종종 모호하거나, 너무 짧거나, 검색 시스템이 이해하기 어려운 형태로 주어질 수 있습니다. 이러한 쿼리는 관련성 높은 문서를 검색하는 데 어려움을 초래합니다.

### 1.1. 원본 쿼리의 한계
-   **모호성**: "그것의 장점은?"과 같이 이전 대화 맥락에 의존하는 질문.
-   **키워드 불일치**: 사용자가 사용하는 단어와 문서 내의 단어가 일치하지 않는 경우.
-   **복잡성**: 여러 정보를 조합해야 하는 복잡한 질문.
-   **짧은 길이**: 검색에 필요한 충분한 정보를 담지 못하는 짧은 질문.

### 1.2. LLM 기반 쿼리 변환의 역할
LLM 기반 쿼리 변환 기법은 이러한 원본 쿼리의 한계를 극복하기 위해 LLM의 추론 능력을 활용합니다. LLM은 원본 쿼리를 분석하여 검색에 더 효과적인 하나 이상의 새로운 쿼리를 생성하거나, 쿼리의 의미를 확장/압축하는 등의 작업을 수행합니다. 이를 통해 검색 시스템이 더 정확하고 관련성 높은 문서를 찾을 수 있도록 돕습니다.

## 2. HyDE (Hypothetical Document Embedding)

### 2.1. HyDE의 개념
HyDE는 "Hypothetical Document Embedding"의 약자로, 사용자의 쿼리에 대해 LLM이 **가상의(hypothetical) 답변 문서**를 먼저 생성하고, 이 가상 문서의 임베딩을 사용하여 실제 문서 저장소에서 검색을 수행하는 기법입니다. 사용자의 짧거나 모호한 쿼리 대신, LLM이 생성한 풍부한 컨텍스트의 가상 문서를 검색에 활용함으로써 검색 정확도를 높입니다.

-   **작동 방식**:
    1.  사용자 쿼리 입력.
    2.  LLM이 쿼리에 대한 가상의 답변 문서 생성 (실제 답변이 아니어도 됨).
    3.  가상 문서의 임베딩 생성.
    4.  생성된 임베딩을 사용하여 벡터 저장소에서 실제 문서 검색.
    5.  검색된 실제 문서를 기반으로 최종 답변 생성.

### 2.2. LlamaIndex에서 HyDE 구현
LlamaIndex는 `HydeRetriever`를 통해 HyDE 기법을 쉽게 구현할 수 있도록 지원합니다.

```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.retrievers import HydeRetriever
from llama_index.llms.openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

# 문서 로드 및 인덱스 구축 (예시)
documents = SimpleDirectoryReader(input_files=["./data/sample_docs.txt"])
index = VectorStoreIndex.from_documents(documents)

# HyDE Retriever 생성
hyde_retriever = HydeRetriever(
    vector_retriever=index.as_retriever(), # 기본 벡터 검색기
    llm=OpenAI(model="gpt-4o", temperature=0), # 가상 문서 생성을 위한 LLM
    hyde_template="다음 질문에 대한 가상의 답변을 생성해 주세요: {query_str}\n\n가상 답변:", # 가상 문서 생성 프롬프트
    include_hyde_query=True # 가상 쿼리도 함께 검색에 포함할지 여부
)

# 쿼리 엔진 생성 및 질의
query_engine = index.as_query_engine(retriever=hyde_retriever)
response = query_engine.query("LlamaIndex의 주요 기능은 무엇인가요?")
print(response)
```

## 3. Multi-query (다중 쿼리)

### 3.1. Multi-query의 개념
Multi-query는 사용자의 단일 쿼리에 대해 LLM이 **여러 개의 다양한 관점의 쿼리**를 생성하고, 이 모든 쿼리를 사용하여 검색을 수행한 후, 검색된 모든 결과를 통합하여 최종 답변을 생성하는 기법입니다. 이는 단일 쿼리로는 놓칠 수 있는 관련성 높은 문서를 찾을 확률을 높여줍니다.

-   **작동 방식**:
    1.  사용자 쿼리 입력.
    2.  LLM이 원본 쿼리에서 파생된 여러 개의 대체 쿼리 생성.
    3.  생성된 모든 쿼리를 사용하여 병렬적으로 문서 검색.
    4.  검색된 모든 결과를 통합하여 중복을 제거하고 관련성 높은 문서만 선별.
    5.  선별된 문서를 기반으로 최종 답변 생성.

### 3.2. LlamaIndex에서 Multi-query 구현
LlamaIndex는 `MultiQueryRetriever`를 통해 Multi-query 기법을 쉽게 구현할 수 있도록 지원합니다.

```python
from llama_index.core.retrievers import MultiQueryRetriever
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.llms.openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

# 문서 로드 및 인덱스 구축 (예시)
documents = SimpleDirectoryReader(input_files=["./data/sample_docs.txt"])
index = VectorStoreIndex.from_documents(documents)

# Multi-query Retriever 생성
multi_query_retriever = MultiQueryRetriever.from_defaults(
    retriever=index.as_retriever(), # 기본 벡터 검색기
    llm=OpenAI(model="gpt-4o", temperature=0), # 대체 쿼리 생성을 위한 LLM
    verbose=True # 생성된 쿼리 확인
)

# 쿼리 엔진 생성 및 질의
query_engine = index.as_query_engine(retriever=multi_query_retriever)
response = query_engine.query("LlamaIndex의 주요 기능과 장점은 무엇인가요?")
print(response)
```

## 4. 기타 쿼리 변환 기법

HyDE와 Multi-query 외에도 다양한 쿼리 변환 기법들이 있습니다.

### 4.1. 쿼리 재작성 (Query Rewriting)
대화형 RAG에서 주로 사용되며, 이전 대화 기록과 현재 질문을 바탕으로 검색에 더 적합한 독립적인 쿼리를 생성합니다. (예: "그것의 장점은?" -> "LlamaIndex의 장점은?")

### 4.2. 쿼리 확장 (Query Expansion)
원본 쿼리에 동의어, 관련 용어, 또는 추가적인 컨텍스트를 추가하여 검색 범위를 넓히는 기법입니다.

### 4.3. 쿼리 압축 (Query Compression)
원본 쿼리에서 불필요한 정보나 군더더기를 제거하여 핵심적인 검색 의도만 남기는 기법입니다. 주로 긴 질문이나 대화 기록에서 핵심 질문을 추출할 때 사용됩니다.

이러한 쿼리 변환 기법들은 LlamaIndex의 `QueryTransform` 모듈을 통해 구현하거나, `QueryEngine`의 `query_transform` 매개변수를 사용하여 적용할 수 있습니다.
