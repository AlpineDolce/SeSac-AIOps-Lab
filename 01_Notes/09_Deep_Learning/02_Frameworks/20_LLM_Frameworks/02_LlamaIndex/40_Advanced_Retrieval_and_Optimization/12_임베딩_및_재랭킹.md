## 1. 검색 정확도의 중요성

RAG 시스템의 전체 품질은 **"Garbage In, Garbage Out"** 원칙을 따릅니다. 만약 Retriever가 질문과 관련 없는 문서를 검색한다면, 아무리 뛰어난 LLM이라도 잘못된 정보를 기반으로 답변을 생성할 수밖에 없습니다. 따라서, 검색 단계에서 최대한 정확하고 관련성 높은 문서를 찾아내는 것이 RAG 시스템 성능의 핵심입니다.

## 2. 임베딩 모델 최적화

### 2.1. 임베딩 모델의 역할
임베딩 모델은 텍스트의 '의미'를 벡터로 변환하는 역할을 합니다. 어떤 임베딩 모델을 사용하느냐에 따라 텍스트 간의 의미적 유사도를 측정하는 방식이 달라지며, 이는 검색 결과에 직접적인 영향을 미칩니다.

- **OpenAI (기본값)**: `text-embedding-3-small`은 범용적으로 뛰어난 성능을 보이지만, 비용이 발생하고 특정 도메인이나 언어에 최적화되어 있지는 않을 수 있습니다.
- **오픈소스 모델 (Hugging Face)**: 특정 언어(예: 한국어)나 특정 도메인(예: 법률, 의료)에 특화된 임베딩 모델을 사용하면 해당 분야에서 더 높은 검색 성능을 기대할 수 있으며, 비용을 절감할 수 있습니다.

### 2.2. 커스텀 임베딩 모델 사용하기
LlamaIndex의 `Settings` 객체를 통해 전역적으로 임베딩 모델을 쉽게 변경할 수 있습니다.

```python
from llama_index.core import Settings, VectorStoreIndex, SimpleDirectoryReader
from llama_index.embeddings.huggingface import HuggingFaceEmbedding

# 전역 설정 변경
Settings.llm = ... # LLM 설정
Settings.embed_model = HuggingFaceEmbedding(model_name="jhgan/ko-sroberta-multitask")
Settings.node_parser = ... # 노드 파서 설정

# 이제부터 모든 인덱싱과 쿼리는 지정된 한국어 임베딩 모델을 사용함
documents = SimpleDirectoryReader("korean_data").load_data()
index = VectorStoreIndex.from_documents(documents)
```

## 3. 재랭킹 (Re-ranking)

### 3.1. 1차 검색의 한계와 재랭킹의 필요성
벡터 유사도 기반의 1차 검색(Retrieval)은 수백만 개의 문서 중에서도 빠르게 관련 후보군을 찾아내는 데 매우 효율적입니다. 하지만 속도를 위해 정확도에서 약간의 손해를 봅니다. 예를 들어, 상위 20개의 문서를 검색했을 때, 그 안에 정답과 관련된 핵심 문서가 포함되어 있지만 순위가 1~3위가 아닌 15위에 있을 수도 있습니다.

**재랭킹**은 이렇게 1차 검색된 소수의 후보군(예: 20개)을 대상으로, 더 강력하지만 계산 비용이 높은 모델을 사용하여 질문과의 관련도를 다시 정밀하게 계산하고 순서를 재조정하는 2차 과정입니다.

### 3.2. 재랭킹의 작동 원리
1.  **1차 검색 (Retrieval)**: 빠른 벡터 검색으로 상위 N개의 후보 노드를 가져옵니다. (예: `similarity_top_k=20`)
2.  **2차 재랭킹 (Re-ranking)**: 재랭킹 모델이 N개의 후보 노드 각각을 원본 질문과 비교하여 새로운 관련도 점수를 부여합니다.
3.  **선별**: 새로운 점수를 기준으로 가장 관련성이 높은 상위 K개의 노드(예: `top_n=5`)를 최종 결과로 선택하여 LLM에 전달합니다.

### 3.3. `SentenceTransformerRerank`를 이용한 재랭킹 구현
오픈소스 재랭킹 모델을 쉽게 사용할 수 있는 `SentenceTransformerRerank` 노드 후처리기(Postprocessor)를 활용합니다.

```bash
pip install sentence-transformers
```

```python
from llama_index.core.postprocessor import SentenceTransformerRerank

# 재랭커 초기화
# top_n: 재랭킹 후 최종적으로 선택할 노드의 수
reranker = SentenceTransformerRerank(
    model="jhgan/ko-sroberta-nli-sts", 
    top_n=3
)

# 쿼리 엔진 생성 시, node_postprocessors에 재랭커를 추가
query_engine = index.as_query_engine(
    similarity_top_k=10, # 1차로 10개를 검색하고
    node_postprocessors=[reranker] # 재랭커를 통해 3개로 추림
)

response = query_engine.query("질문...")
```
이처럼 재랭킹을 도입하면, 1차 검색에서 놓칠 수 있는 중요한 정보를 다시 상위로 끌어올려 RAG 시스템의 전반적인 답변 품질을 크게 향상시킬 수 있습니다.
