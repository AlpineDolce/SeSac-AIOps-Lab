## 1. 왜 노드 후처리가 필요한가?

Retriever는 벡터 유사도를 기반으로 관련성 높은 노드를 검색하지만, 그 결과가 항상 완벽하지는 않습니다.

- **관련성 낮은 노드 포함**: 유사도 점수가 낮아 실제로는 질문과 관련이 적은 노드가 검색 결과에 포함될 수 있습니다.
- **필수 정보 누락**: 검색된 노드들이 사용자가 원하는 특정 키워드나 정보를 포함하지 않을 수 있습니다.
- **순서의 부정확성**: 가장 중요한 내용이 담긴 노드가 최상위에 위치하지 않을 수 있습니다.

**노드 후처리기**는 이렇게 1차 검색된 노드 리스트를 입력으로 받아, 특정 로직에 따라 노드를 필터링, 재정렬, 변환하는 역할을 합니다. 이를 통해 LLM에게 더 깨끗하고 정제된 컨텍스트를 제공할 수 있습니다.

## 2. 기본 제공 후처리기

LlamaIndex는 일반적인 시나리오에 사용할 수 있는 다양한 후처리기를 기본으로 제공합니다.

### 2.1. `SimilarityPostprocessor`
- **역할**: 설정된 유사도 점수 임계값(threshold)보다 낮은 점수를 가진 노드를 결과에서 제외합니다.
- **사용 사례**: 쿼리와의 관련성이 일정 수준 이하인 노이즈성 정보를 제거하고 싶을 때 사용합니다.

```python
from llama_index.core.postprocessor import SimilarityPostprocessor

# 유사도 점수가 0.7 미만인 노드는 필터링
postprocessor = SimilarityPostprocessor(similarity_cutoff=0.7)
```

### 2.2. `KeywordNodePostprocessor`
- **역할**: 사용자가 지정한 필수 키워드(`required_keywords`)를 포함하지 않거나, 제외 키워드(`exclude_keywords`)를 포함하는 노드를 필터링합니다.
- **사용 사례**: "반드시 'LlamaIndex'라는 단어가 포함된 문서만 보여줘" 와 같은 특정 요구사항을 처리할 때 유용합니다.

```python
from llama_index.core.postprocessor import KeywordNodePostprocessor

postprocessor = KeywordNodePostprocessor(
    required_keywords=["LlamaIndex", "RAG"],
    exclude_keywords=["LangChain"]
)
```

### 2.3. `SentenceTransformerRerank` (재랭킹)
- **역할**: 1차 검색된 노드들을 대상으로, 더 정교한 재랭킹 모델을 사용하여 질문과의 관련도 순서를 다시 매깁니다. (상세 내용은 '12_임베딩_및_재랭킹.md' 참조)

## 3. 쿼리 엔진에 후처리기 적용하기

생성한 후처리기 객체를 `as_query_engine()` 메소드의 `node_postprocessors` 리스트에 전달하면 됩니다.

```python
from llama_index.core.postprocessor import SimilarityPostprocessor

# 후처리기 생성
similarity_filter = SimilarityPostprocessor(similarity_cutoff=0.75)

# 쿼리 엔진 생성 시 후처리기 리스트를 전달
query_engine = index.as_query_engine(
    similarity_top_k=5,
    node_postprocessors=[similarity_filter]
)

# 이제 쿼리 엔진은 5개의 노드를 검색한 후, 점수가 0.75 미만인 것을 제외하고 LLM에 전달함
response = query_engine.query("질문...")
```
여러 개의 후처리기를 리스트에 담아 전달하면 순차적으로 적용됩니다.

## 4. 커스텀 후처리기 만들기

`BaseNodePostprocessor` 클래스를 상속하여 우리만의 커스텀 후처리 로직을 구현할 수 있습니다.

```python
from llama_index.core.postprocessor.types import BaseNodePostprocessor
from llama_index.core.schema import NodeWithScore
from typing import List

class DuplicateNodePostprocessor(BaseNodePostprocessor):
    """중복된 텍스트를 가진 노드를 제거하는 커스텀 후처리기"""

    def _postprocess_nodes(
        self, nodes: List[NodeWithScore], **kwargs
    ) -> List[NodeWithScore]:
        unique_texts = set()
        unique_nodes = []
        for node in nodes:
            if node.text not in unique_texts:
                unique_texts.add(node.text)
                unique_nodes.append(node)
        return unique_nodes

# 사용법
custom_postprocessor = DuplicateNodePostprocessor()
query_engine = index.as_query_engine(
    node_postprocessors=[custom_postprocessor]
)
```
이처럼 노드 후처리기는 Retriever의 성능을 보완하고, 비즈니스 로직에 맞는 정제된 컨텍스트를 LLM에 제공하는 강력한 수단입니다.
