## 1. 라우팅은 언제 필요한가?

하나의 RAG 시스템이 서로 다른 종류의 질문을 모두 잘 처리하기는 어렵습니다. 예를 들어, 다음과 같은 상황을 생각해 볼 수 있습니다.

- **질문 1**: "LlamaIndex의 `VectorStoreIndex`에 대해 요약해줘." -> 위키피디아 같은 요약된 정보가 적합
- **질문 2**: "LlamaIndex의 `VectorStoreIndex` 클래스 생성자의 파라미터는 뭐가 있어?" -> API 레퍼런스나 소스 코드 같은 구조화된 정보가 적합

이처럼 질문의 성격에 따라 다른 데이터 소스나 다른 처리 방식을 사용해야 할 때, LLM이 스스로 판단하여 가장 적절한 경로로 질문을 보내주는 **라우팅(Routing)** 기능이 필요합니다.

## 2. 라우터 쿼리 엔진의 작동 원리

`RouterQueryEngine`은 여러 개의 `QueryEngineTool`을 입력으로 받습니다. 각 `QueryEngineTool`은 특정 데이터 소스에 대한 쿼리 엔진과, 그 쿼리 엔진이 무엇을 할 수 있는지 설명하는 메타데이터(설명)를 가지고 있습니다.

### 2.1. `Selector`의 역할
라우터 쿼리 엔진의 핵심은 내부의 `Selector` 컴포넌트입니다. `Selector`는 LLM을 사용하여 다음을 수행합니다.
1.  사용자의 쿼리를 분석합니다.
2.  제공된 모든 `QueryEngineTool`의 메타데이터(설명)를 읽어봅니다.
3.  쿼리의 내용과 가장 관련성이 높은 설명을 가진 **단 하나의 도구**를 선택합니다.
4.  선택된 도구(쿼리 엔진)에 사용자의 쿼리를 전달하여 최종 답변을 얻습니다.

## 3. 라우터 쿼리 엔진 구축 실습

### 3.1. 시나리오 설정
- **데이터 1**: `llama_index_summary.txt` (LlamaIndex에 대한 전반적인 요약 정보)
- **데이터 2**: `llama_index_api_reference.txt` (LlamaIndex의 구체적인 API 사용법 정보)
- **목표**: 사용자의 질문 유형에 따라 두 데이터 소스 중 더 적합한 곳에서 정보를 찾아 답변하는 시스템 구축

### 3.2. 데이터 및 도구 준비
각 데이터 소스에 대한 쿼리 엔진을 만들고, `QueryEngineTool`로 감싸줍니다. 이때 `description`을 명확하게 작성하는 것이 라우터의 성능에 결정적인 영향을 미칩니다.

```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.tools import QueryEngineTool, ToolMetadata

# 각 데이터 소스에 대한 쿼리 엔진 생성 (생략)
summary_engine = ...
api_engine = ...

# 각 쿼리 엔진을 Tool로 변환
tools = [
    QueryEngineTool(
        query_engine=summary_engine,
        metadata=ToolMetadata(
            name="summary_tool",
            description="LlamaIndex에 대한 일반적이고 요약된 정보를 제공합니다. 개념 설명에 유용합니다.",
        ),
    ),
    QueryEngineTool(
        query_engine=api_engine,
        metadata=ToolMetadata(
            name="api_tool",
            description="LlamaIndex의 특정 클래스나 함수 사용법 등 기술적인 API 정보를 제공합니다.",
        ),
    ),
]
```

### 3.3. 라우터 쿼리 엔진 생성 및 실행

`RouterQueryEngine`은 `Selector`와 도구 리스트를 받아 생성됩니다.

```python
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.selectors import PydanticSingleSelector

# LLM이 도구를 선택하도록 하는 Selector 생성
selector = PydanticSingleSelector.from_defaults()

# 라우터 쿼리 엔진 생성
query_engine = RouterQueryEngine(
    selector=selector,
    query_engine_tools=tools,
    verbose=True
)

# 실행 1: 요약 질문
response1 = query_engine.query("LlamaIndex가 무엇인지 간단히 설명해줘.")
# verbose 로그에 "Selecting tool: summary_tool"이 출력됨

# 실행 2: 기술 질문
response2 = query_engine.query("VectorStoreIndex를 어떻게 사용해?")
# verbose 로그에 "Selecting tool: api_tool"이 출력됨
```

## 4. 서브 쿼리 엔진 vs. 라우터 쿼리 엔진

두 엔진은 비슷해 보이지만 목적이 다릅니다.
- **라우터 쿼리 엔진**: 여러 도구 중 **가장 적합한 하나를 선택**하여 실행합니다. (OR 조건)
- **서브 쿼리 엔진**: 하나의 복잡한 질문을 **여러 개의 하위 질문으로 분해**하여 여러 도구를 모두 사용하고 결과를 종합합니다. (AND 조건)

따라서, 질문의 성격에 따라 하나의 경로로 분기해야 할 때는 라우터, 여러 소스의 정보를 종합해야 할 때는 서브 쿼리 엔진을 사용하는 것이 적합합니다.
