## 1. 왜 인덱스 저장이 필요한가?

`VectorStoreIndex.from_documents()`를 호출할 때마다 LlamaIndex는 문서를 읽고, 분할하고, 임베딩 모델을 호출하여 벡터로 변환하는 과정을 거칩니다. 문서의 양이 많거나 상용 임베딩 모델(예: OpenAI)을 사용하는 경우, 이 과정은 상당한 시간과 비용을 소모합니다.

애플리케이션을 시작할 때마다 이 과정을 반복하는 것은 매우 비효율적입니다. **인덱스 저장**은 이렇게 한 번 계산된 결과를 디스크에 파일 형태로 저장하여, 다음 번에 애플리케이션을 시작할 때는 계산 과정 없이 저장된 내용을 바로 불러와 사용할 수 있게 해줍니다.

## 2. 인덱스 저장 및 로드 방법

### 2.1. 저장: `storage_context.persist()`
인덱스 객체는 `storage_context`라는 속성을 가지고 있으며, 이 컨텍스트의 `persist()` 메소드를 호출하여 인덱스를 저장할 수 있습니다.

```python
# 인덱스 생성
index = VectorStoreIndex.from_documents(documents)

# 인덱스 저장 (기본적으로 ./storage 디렉터리에 저장됨)
index.storage_context.persist()

# 특정 위치에 저장하고 싶을 경우
index.storage_context.persist(persist_dir="./my_index_storage")
```

### 2.2. 로드: `load_index_from_storage()`
저장된 인덱스를 불러올 때는 `load_index_from_storage` 함수를 사용합니다. 이 함수는 `StorageContext`를 먼저 불러온 뒤, 이를 기반으로 인덱스 객체를 재구성합니다.

```python
from llama_index.core import StorageContext, load_index_from_storage

# 저장 컨텍스트 불러오기
storage_context = StorageContext.from_defaults(persist_dir="./my_index_storage")

# 저장된 내용으로부터 인덱스 객체 로드
index = load_index_from_storage(storage_context)
```

## 3. 실습 예제

### 3.1. 1단계: 인덱스 생성 및 저장

`create_index.py`
```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
import os

# 저장 디렉터리
PERSIST_DIR = "./my_index_storage"

if not os.path.exists(PERSIST_DIR):
    # 데이터 로딩 및 인덱스 생성
    documents = SimpleDirectoryReader("data").load_data()
    index = VectorStoreIndex.from_documents(documents)
    # 인덱스 저장
    index.storage_context.persist(persist_dir=PERSIST_DIR)
    print(f"인덱스를 '{PERSIST_DIR}'에 저장했습니다.")
else:
    print(f"'{PERSIST_DIR}'에 이미 인덱스가 존재합니다.")
```

### 3.2. 2단계: 저장된 인덱스 로드 및 사용

`query_from_storage.py`
```python
from llama_index.core import StorageContext, load_index_from_storage
from dotenv import load_dotenv

load_dotenv()

PERSIST_DIR = "./my_index_storage"

# 저장된 인덱스 불러오기
storage_context = StorageContext.from_defaults(persist_dir=PERSIST_DIR)
index = load_index_from_storage(storage_context)

# 쿼리 엔진 생성 및 쿼리 실행
query_engine = index.as_query_engine()
response = query_engine.query("What did the author do after college?")
print(response)
```
이제 `create_index.py`를 한 번만 실행해두면, `query_from_storage.py`는 문서를 다시 읽거나 임베딩을 계산할 필요 없이 매우 빠르게 실행됩니다.

## 4. 외부 벡터 DB와의 연동

ChromaDB나 Pinecone과 같은 외부 벡터 데이터베이스를 사용하는 경우, `persist()`의 작동 방식이 조금 다릅니다. 이 경우 `persist`는 벡터 데이터 자체(이미 DB에 저장되어 있음)가 아닌, 해당 DB에 다시 연결하는 데 필요한 **설정 정보나 메타데이터**를 주로 저장합니다. `load_index_from_storage`는 이 설정 정보를 읽어 기존 DB에 다시 연결하여 인덱스를 재구성하는 역할을 합니다. 따라서 데이터의 영속성은 LlamaIndex가 아닌 외부 벡터 데이터베이스가 직접 관리하게 됩니다.
