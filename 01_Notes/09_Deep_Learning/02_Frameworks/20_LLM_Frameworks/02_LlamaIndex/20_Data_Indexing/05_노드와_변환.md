## 1. 노드(Node)란 무엇인가?

`Node`는 LlamaIndex에서 데이터가 처리되는 **가장 기본적인 단위(atomic unit)**입니다. `Document`가 원본 문서 전체를 나타낸다면, `Node`는 그 문서에서 분할된 하나의 텍스트 조각(chunk)을 의미합니다.

`Node` 객체는 다음과 같은 중요한 정보를 담고 있습니다.
- `text`: 분할된 텍스트 조각의 내용
- `metadata`: 해당 노드의 출처(파일명, 페이지 번호 등)나 카테고리와 같은 추가 정보. 검색 시 필터링 조건으로 활용될 수 있습니다.
- `relationships`: 다른 노드와의 관계(이전 노드, 다음 노드 등) 정보. 고급 검색 전략에 사용됩니다.

## 2. 파싱 및 분할 파이프라인

로드된 `Document`를 바로 임베딩하여 인덱싱할 수도 있지만, 보통 너무 길어서 검색 효율이 떨어집니다. 따라서 의미 있는 단위로 잘게 나누는 과정이 필수적이며, 이를 **노드 파싱(Node Parsing)** 또는 **청킹(Chunking)**이라고 합니다.

### 2.1. `SentenceSplitter` 활용
LlamaIndex는 `SentenceSplitter` (이전의 `NodeParser`)를 통해 이 과정을 자동화합니다. `SentenceSplitter`는 문장, 단락 등 언어적 경계를 고려하여 텍스트를 분할합니다.

```python
from llama_index.core.node_parser import SentenceSplitter

# 파서 초기화
# chunk_size: 각 노드의 최대 토큰(또는 문자) 수
# chunk_overlap: 인접한 노드 간에 겹치게 할 토큰 수
parser = SentenceSplitter(chunk_size=1024, chunk_overlap=20)

# document 리스트를 파싱하여 node 리스트 생성
nodes = parser.get_nodes_from_documents(documents)
```

### 2.2. 청크 크기와 오버랩의 중요성
- **`chunk_size`**: 너무 크면 관련 없는 정보가 많이 포함되어 검색 정확도가 떨어지고, 너무 작으면 문맥이 잘려나가 의미를 잃을 수 있습니다. 사용하려는 임베딩 모델의 최대 토큰 길이를 고려하여 설정하는 것이 좋습니다.
- **`chunk_overlap`**: 문장의 중간에서 청크가 잘리는 경우, 중요한 의미가 손실될 수 있습니다. 오버랩은 인접한 청크가 일부 내용을 공유하게 만들어 이러한 문맥 단절을 방지하는 역할을 합니다.

## 3. 노드에 메타데이터 추가하기

### 3.1. 메타데이터의 역할
메타데이터는 각 노드에 '꼬리표'를 붙이는 것과 같습니다. 예를 들어, 파일명, 작성일, 카테고리 등의 메타데이터를 추가하면, 나중에 "2024년에 작성된 '기술' 카테고리 문서 중에서만 검색해줘"와 같은 **필터링 기반 검색**이 가능해져 RAG 시스템의 정확도를 크게 높일 수 있습니다.

### 3.2. 코드 예제
`Document` 객체 자체에 메타데이터를 추가하면, 파싱 과정에서 생성된 `Node`들이 이 메타데이터를 상속받습니다.

```python
from llama_index.core.schema import Document

# Document 생성 시 메타데이터 추가
docs = [
    Document(
        text="이것은 첫 번째 기술 문서입니다.",
        metadata={"category": "tech", "year": 2023}
    ),
    Document(
        text="이것은 두 번째 비즈니스 문서입니다.",
        metadata={"category": "business", "year": 2024}
    )
]

nodes = SentenceSplitter().get_nodes_from_documents(docs)

# 생성된 노드가 Document의 메타데이터를 상속받았는지 확인
print(nodes[0].metadata) # {'category': 'tech', 'year': 2023}
print(nodes[1].metadata) # {'category': 'business', 'year': 2024}
```

## 4. Ingestion Pipeline으로 전체 과정 자동화

LlamaIndex의 `IngestionPipeline`을 사용하면 로딩, 분할, 임베딩, 저장에 이르는 전체 데이터 수집 및 처리 과정을 하나의 파이프라인으로 묶어 체계적으로 관리할 수 있습니다.

```python
from llama_index.core.ingestion import IngestionPipeline
from llama_index.core.node_parser import SentenceSplitter
from llama_index.core.vector_stores import VectorStoreIndex

# 파이프라인 정의
pipeline = IngestionPipeline(
    transformations=[
        SentenceSplitter(chunk_size=512, chunk_overlap=20),
        OpenAIEmbedding(), # 임베딩 모델
    ],
    vector_store=vector_store # 데이터를 저장할 벡터 저장소
)

# 문서에 대해 파이프라인 실행
nodes = pipeline.run(documents=documents)
```
이처럼 노드 파싱은 원본 데이터를 LLM이 가장 잘 이해하고 검색할 수 있는 형태로 가공하는 RAG의 핵심 전처리 과정입니다.
