## 1. 인덱스란 무엇인가?

LlamaIndex에서 **인덱스(Index)**는 `Node` 객체들을 검색에 용이한 형태로 구조화하여 저장한 것입니다. 책의 맨 뒤에 있는 색인(index)이 특정 단어가 어느 페이지에 있는지 빠르게 찾아주는 것처럼, LlamaIndex의 인덱스는 특정 쿼리와 가장 관련성 높은 `Node`를 신속하게 찾아주는 역할을 합니다.

LlamaIndex는 다양한 종류의 인덱스(List Index, Tree Index, Keyword Table Index 등)를 제공하지만, 가장 널리 사용되는 것은 `VectorStoreIndex`입니다.

## 2. 벡터 검색의 원리

벡터 검색의 핵심 아이디어는 **"의미가 비슷한 텍스트는 벡터 공간에서도 가깝게 위치한다"**는 것입니다. `VectorStoreIndex`는 이 원리를 이용하여 다음과 같이 동작합니다.

1.  **인덱싱**: 모든 `Node`의 텍스트를 임베딩 모델을 사용하여 고차원의 벡터로 변환하고, 이 벡터들을 벡터 저장소(Vector Store)에 저장합니다.
2.  **쿼리**: 사용자의 쿼리 또한 동일한 임베딩 모델을 사용하여 벡터로 변환합니다.
3.  **유사도 계산**: 쿼리 벡터와 벡터 저장소에 있는 모든 노드 벡터 간의 유사도(보통 코사인 유사도)를 계산합니다.
4.  **검색**: 계산된 유사도 점수가 가장 높은, 즉 쿼리 벡터와 가장 가까운 상위 K개의 노드 벡터를 검색 결과로 반환합니다.

## 3. `VectorStoreIndex`의 작동 방식

### 3.1. 인덱스 생성 과정
`VectorStoreIndex.from_documents(documents)` 코드가 실행되면, 내부적으로 다음과 같은 일들이 순차적으로 일어납니다.
1.  입력된 `Document` 리스트를 `SentenceSplitter`를 사용해 `Node` 리스트로 분할합니다.
2.  각 `Node`의 텍스트를 임베딩 모델(기본값: OpenAI `text-embedding-3-small`)을 사용해 벡터로 변환합니다.
3.  변환된 벡터와 원본 `Node`를 벡터 저장소(기본값: 인-메모리 `SimpleVectorStore`)에 저장합니다.

### 3.2. 코드 예제
```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

# 데이터 로딩
documents = SimpleDirectoryReader("./data").load_data()

# 인덱스 생성
# 이 한 줄의 코드가 내부적으로 분할, 임베딩, 저장을 모두 수행
index = VectorStoreIndex.from_documents(documents)
```

## 4. 임베딩 모델 커스터마이징

LlamaIndex는 기본적으로 OpenAI의 임베딩 모델을 사용하지만, 필요에 따라 다른 모델로 쉽게 교체할 수 있습니다. 예를 들어, 비용을 절감하거나 특정 언어에 더 강한 오픈소스 모델을 사용할 수 있습니다.

```python
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.core import Settings

# HuggingFace에서 제공하는 한국어 임베딩 모델 사용 설정
# Settings를 통해 LlamaIndex 전역의 설정을 변경할 수 있음
Settings.embed_model = HuggingFaceEmbedding(
    model_name="jhgan/ko-sroberta-multitask"
)

# 이제부터 생성되는 모든 인덱스는 지정된 HuggingFace 모델을 사용함
index = VectorStoreIndex.from_documents(documents)
```

## 5. 외부 벡터 데이터베이스 연동

기본 인-메모리 벡터 저장소는 간단한 테스트에는 유용하지만, 애플리케이션이 재시작되면 인덱스가 사라지는 단점이 있습니다. 프로덕션 환경에서는 인덱스를 영구적으로 저장하고, 더 빠른 검색과 확장성을 제공하는 외부 벡터 데이터베이스(예: Chroma, Pinecone, Weaviate)를 사용하는 것이 일반적입니다.

**예시: ChromaDB 연동**

```bash
pip install llama-index-vector-stores-chroma chromadb
```

```python
import chromadb
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.core import StorageContext

# ChromaDB 클라이언트 초기화 및 컬렉션 생성
db = chromadb.PersistentClient(path="./chroma_db")
chroma_collection = db.get_or_create_collection("my_collection")

# LlamaIndex와 연동할 VectorStore 객체 생성
vector_store = ChromaVectorStore(chroma_collection=chroma_collection)

# StorageContext를 통해 인덱스가 사용할 저장소 지정
storage_context = StorageContext.from_defaults(vector_store=vector_store)

# 인덱스 생성 시 storage_context를 전달
# 이제 노드와 벡터는 메모리가 아닌 ChromaDB에 저장됨
index = VectorStoreIndex.from_documents(
    documents,
    storage_context=storage_context
)
```
이처럼 `VectorStoreIndex`는 LlamaIndex의 RAG 파이프라인에서 데이터의 의미를 저장하고 검색하는 핵심적인 역할을 담당합니다.
