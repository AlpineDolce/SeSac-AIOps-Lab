## 1. 응답 종합의 문제 (The Synthesis Problem)

Retriever는 보통 여러 개의 관련성 높은 노드(예: 3개)를 검색합니다. 이제 LLM은 이 3개의 노드에 담긴 정보를 모두 활용하여 사용자의 질문에 대한 하나의 일관된 답변을 만들어내야 합니다. 이 과정을 **응답 종합(Response Synthesis)**이라고 합니다.

LlamaIndex는 이 종합 과정을 처리하는 다양한 전략, 즉 **응답 모드**를 제공합니다.

## 2. LlamaIndex의 응답 모드

### 2.1. `refine`
- **작동 방식**: 검색된 노드들을 하나씩 순회하며 답변을 점진적으로 정제(refine)합니다. 첫 번째 노드로 초기 답변을 생성하고, 다음 노드의 내용을 보며 이전 답변을 수정하고 보완하는 방식입니다. 각 노드마다 LLM 호출이 일어날 수 있습니다.
- **장점**: 각 노드의 정보를 깊이 있게 반영하여 더 상세하고 풍부한 답변을 생성할 수 있습니다. 답변이 만들어지는 과정을 추적하기 용이합니다.
- **단점**: 여러 번 LLM을 호출하므로 비용과 시간이 많이 듭니다.
- **사용 사례**: 여러 문서의 내용을 비교 분석하거나, 하나의 주제에 대해 깊이 있는 답변을 요구할 때 적합합니다.

### 2.2. `compact` (기본값)
- **작동 방식**: LLM의 컨텍스트 윈도우(Context Window) 크기에 맞춰, 검색된 노드들을 가능한 한 많이 '채워넣어(stuff)' 한 번의 LLM 호출로 답변을 생성합니다. 만약 모든 노드를 한 번에 넣을 수 없다면, 여러 번에 나누어 `compact`와 `refine`을 조합하여 처리합니다.
- **장점**: LLM 호출 횟수를 최소화하여 비용과 시간을 절약합니다. 대부분의 경우 준수한 성능을 보입니다.
- **단점**: 너무 많은 정보를 한 번에 처리하다 보면 세부적인 내용을 놓칠 수 있습니다.
- **사용 사례**: 일반적인 Q&A 상황에서 가장 무난하게 사용할 수 있는 기본 모드입니다.

### 2.3. `tree_summarize`
- **작동 방식**: 검색된 노드들을 두 개씩 짝지어 요약하고, 다시 그 요약본들을 짝지어 요약하는 방식으로, 마치 나무(tree)처럼 계층적으로 요약하여 최종 답변을 만듭니다. 여러 번의 LLM 호출이 필요합니다.
- **장점**: 매우 많은 수의 문서를 종합하여 하나의 일관된 요약문을 만드는 데 매우 효과적입니다.
- **단점**: `refine` 모드처럼 비용과 시간이 많이 듭니다.
- **사용 사례**: 여러 개의 긴 보고서나 기사를 하나의 문서로 요약하는 작업에 적합합니다.

### 2.4. `simple_summarize`
- **작동 방식**: 각 노드에 대해 독립적으로 요약(또는 답변)을 생성하고, 이들을 단순히 합쳐서 최종 결과로 반환합니다. 각 노드마다 LLM 호출이 일어납니다.
- **단점**: 노드 간의 연관성을 고려하지 않아 답변의 일관성이 떨어질 수 있습니다.

## 3. 응답 모드 설정 및 선택 가이드

### 3.1. 쿼리 엔진에서 설정하기
`as_query_engine()` 메소드의 `response_mode` 파라미터를 통해 원하는 모드를 지정할 수 있습니다.

```python
# Refine 모드를 사용하는 쿼리 엔진 생성
query_engine_refine = index.as_query_engine(response_mode="refine")

# Tree Summarize 모드를 사용하는 쿼리 엔진 생성
query_engine_tree = index.as_query_engine(response_mode="tree_summarize")
```

### 3.2. 언제 어떤 모드를 써야 할까?

| 응답 모드 | 추천 사용 사례 | 장점 | 단점 |
| :--- | :--- | :--- | :--- |
| `compact` | 일반적인 Q&A, 빠른 응답 필요 시 | 빠르고 저렴함 | 세부 정보 누락 가능 |
| `refine` | 여러 문서의 비교/분석, 깊이 있는 답변 | 상세하고 풍부한 답변 | 느리고 비쌈 |
| `tree_summarize` | 다수 문서의 종합 요약 | 대규모 문서 요약에 탁월 | 느리고 비쌈 |

애플리케이션의 요구사항(답변 품질, 응답 속도, 비용)을 고려하여 최적의 응답 모드를 선택하는 것이 중요합니다.
