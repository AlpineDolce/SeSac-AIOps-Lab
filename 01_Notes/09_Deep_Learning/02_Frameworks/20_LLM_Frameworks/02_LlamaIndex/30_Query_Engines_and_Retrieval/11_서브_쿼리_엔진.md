## 1. 복잡한 질문의 한계

기존의 RAG 시스템은 보통 단일 데이터 소스(예: 하나의 문서 집합)에 대해 질문하는 것을 가정합니다. 하지만 실제 상황에서는 다음과 같이 여러 데이터 소스의 정보를 종합해야만 답변할 수 있는 복잡한 질문이 많습니다.

> "폴 그레이엄의 어린 시절 경험과, 우버의 초기 성장 전략을 비교 분석해줘."

이 질문에 답하기 위해서는 '폴 그레이엄 에세이' 문서와 '우버 투자 보고서'라는 두 개의 완전히 다른 데이터 소스를 모두 참조해야 합니다. 단일 쿼리 엔진으로는 이러한 작업을 효과적으로 수행하기 어렵습니다.

## 2. 서브 쿼리 엔진의 접근법

`SubQuestionQueryEngine`은 이러한 문제를 해결하기 위해 LLM의 추론 능력을 활용합니다.

### 2.1. 분해, 실행, 종합 (Decomposition, Execution, Synthesis)
1.  **분해 (Decomposition)**: LLM이 먼저 사용자의 복잡한 질문을 분석하여, 각 데이터 소스에 대해 독립적으로 질문할 수 있는 여러 개의 구체적인 **하위 질문(Sub-question)**으로 분해합니다.
2.  **실행 (Execution)**: 각 하위 질문에 가장 적합한 쿼리 엔진(도구)을 선택하여 실행하고, 각각의 답변을 얻습니다.
3.  **종합 (Synthesis)**: LLM이 마지막으로 각 하위 질문에 대한 답변들을 모두 모아, 사용자의 원래 복잡한 질문에 대한 최종적이고 종합적인 답변을 생성합니다.

## 3. 서브 쿼리 엔진 구축 실습

### 3.1. 시나리오 설정
- **문서 1**: `pg_essay.txt` (폴 그레이엄의 성장 과정에 대한 내용)
- **문서 2**: `uber_facts.txt` (우버의 역사와 비즈니스 모델에 대한 내용)
- **목표 질문**: "폴 그레이엄의 학창 시절과 우버의 초기 시절에 대해 알려줘."

### 3.2. 데이터 및 도구 준비
각 문서에 대한 별도의 쿼리 엔진을 만들고, 이를 `QueryEngineTool`로 감싸서 서브 쿼리 엔진이 사용할 수 있는 '도구'로 정의합니다.

```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.tools import QueryEngineTool, ToolMetadata

# 1. 각 문서 로드
pg_docs = SimpleDirectoryReader(input_files=["pg_essay.txt"]).load_data()
uber_docs = SimpleDirectoryReader(input_files=["uber_facts.txt"]).load_data()

# 2. 각 문서에 대한 인덱스 및 쿼리 엔진 생성
pg_index = VectorStoreIndex.from_documents(pg_docs)
uber_index = VectorStoreIndex.from_documents(uber_docs)

pg_engine = pg_index.as_query_engine(similarity_top_k=3)
uber_engine = uber_index.as_query_engine(similarity_top_k=3)

# 3. 각 쿼리 엔진을 Tool로 변환
# name과 description은 LLM이 언제 이 도구를 써야할지 판단하는 데 매우 중요
query_engine_tools = [
    QueryEngineTool(
        query_engine=pg_engine,
        metadata=ToolMetadata(
            name="pg_essay_tool",
            description="폴 그레이엄의 삶과 에세이에 대한 정보를 제공합니다.",
        ),
    ),
    QueryEngineTool(
        query_engine=uber_engine,
        metadata=ToolMetadata(
            name="uber_facts_tool",
            description="우버(Uber)의 역사와 비즈니스에 대한 정보를 제공합니다.",
        ),
    ),
]
```

### 3.3. 서브 쿼리 엔진 생성 및 실행

준비된 도구들을 사용하여 `SubQuestionQueryEngine`을 생성합니다.

```python
from llama_index.core.query_engine import SubQuestionQueryEngine

# 서브 쿼리 엔진 생성
s_query_engine = SubQuestionQueryEngine.from_defaults(
    query_engine_tools=query_engine_tools,
    use_async=True, # 하위 질문들을 비동기적으로 실행하여 속도 향상
)

# 쿼리 실행
response = s_query_engine.query("폴 그레이엄의 학창 시절과 우버의 초기 시절에 대해 알려줘.")

print(response)
```

`verbose=True`로 설정하고 실행하면, LLM이 다음과 같이 하위 질문을 생성하고 각 도구를 호출하는 과정을 볼 수 있습니다.

- **생성된 하위 질문 1**: "폴 그레이엄의 학창 시절은 어땠는가?" -> `pg_essay_tool` 사용
- **생성된 하위 질문 2**: "우버의 초기 시절은 어땠는가?" -> `uber_facts_tool` 사용

이처럼 서브 쿼리 엔진은 복잡한 사용자 질문을 지능적으로 분해하고, 가장 적합한 데이터 소스를 찾아 답변을 종합하는 강력한 기능을 제공하여 RAG 시스템의 활용 범위를 크게 넓혀줍니다.
