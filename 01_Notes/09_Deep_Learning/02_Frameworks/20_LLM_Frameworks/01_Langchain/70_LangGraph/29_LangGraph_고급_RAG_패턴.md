## 1. LangGraph와 고급 RAG 패턴

RAG(Retrieval-Augmented Generation)는 LLM의 환각을 줄이고 최신 정보를 반영하는 강력한 방법이지만, 단순한 RAG는 검색 결과의 품질, 질문의 복잡성 등에 따라 한계를 가질 수 있습니다. 고급 RAG 패턴은 이러한 한계를 극복하기 위해 LLM의 추론 능력을 검색 및 생성 과정에 더 깊이 통합합니다.

### 1.1. 왜 LangGraph가 고급 RAG에 필요한가?
고급 RAG 패턴은 대부분 조건부 로직, 반복적인 검색/생성 사이클, 그리고 LLM의 자체 평가 및 수정 과정을 포함합니다. LangGraph는 다음과 같은 특징으로 이러한 복잡한 흐름을 효과적으로 구현할 수 있습니다.
-   **조건부 분기**: LLM의 판단(예: 검색 결과의 관련성)에 따라 다음 단계를 동적으로 결정.
-   **순환**: 검색-생성 사이클을 반복하거나, 검색 결과가 불충분할 경우 재시도.
-   **명시적 상태 관리**: 각 단계의 중간 결과와 LLM의 추론 과정을 상태에 저장하여 투명하게 관리.

## 2. CRAG (Corrective RAG) 구현

### 2.1. CRAG의 개념
CRAG는 "Corrective RAG"의 약자로, 검색된 문서의 품질을 LLM이 스스로 평가하고, 만약 품질이 낮다고 판단되면 검색 쿼리를 수정하거나 다른 검색 전략을 시도하는 등 **자체 수정(self-correction)** 메커니즘을 포함하는 RAG 패턴입니다. 이를 통해 검색 결과의 신뢰성을 높이고 환각을 줄입니다.

### 2.2. LangGraph를 활용한 CRAG 워크플로우
CRAG는 LangGraph의 조건부 엣지와 순환 기능을 활용하여 구현할 수 있습니다.

#### 2.2.1. 관련성 평가 노드
-   **역할**: LLM이 검색된 문서와 원본 질문 간의 관련성을 평가합니다.
-   **출력**: '관련성 높음', '관련성 낮음', '불확실' 등.
-   **LangGraph 적용**: 이 노드의 출력에 따라 조건부 엣지를 사용하여 다음 노드로 분기합니다.

#### 2.2.2. 검색 재시도/확장 노드
-   **역할**: 관련성이 낮다고 평가되면, LLM이 검색 쿼리를 재작성하거나, 검색 범위를 확장(예: 웹 검색 추가)하여 다시 검색을 시도합니다.
-   **LangGraph 적용**: 이 노드에서 다시 검색 노드로 연결되는 순환 엣지를 만듭니다.

#### 2.2.3. 답변 생성 노드
-   **역할**: 최종적으로 검증된 검색 결과를 바탕으로 답변을 생성합니다.

## 3. Self-RAG 구현

### 3.1. Self-RAG의 개념
Self-RAG는 LLM이 검색된 문서와 생성된 답변의 품질을 스스로 평가하고, 필요에 따라 추가적인 검색이나 답변 수정을 지시하는 고급 RAG 패턴입니다. LLM이 '생각(Thought)' 토큰을 생성하여 자신의 추론 과정을 명시하고, 이를 바탕으로 행동을 결정합니다.

### 3.2. LangGraph를 활용한 Self-RAG 워크플로우
Self-RAG는 LLM의 자체 평가 및 조건부 행동이 핵심이므로, LangGraph의 유연한 제어 흐름이 필수적입니다.

#### 3.2.1. 자체 평가 노드
-   **역할**: LLM이 검색된 문서의 유용성, 생성된 답변의 정확성 등을 스스로 평가합니다.
-   **출력**: '만족', '불만족', '추가 검색 필요' 등.
-   **LangGraph 적용**: 이 노드의 출력에 따라 조건부 엣지를 사용하여 답변 생성, 추가 검색, 또는 수정 노드로 분기합니다.

#### 3.2.2. 조건부 생성/재시도
-   **역할**: 자체 평가 결과에 따라 LLM이 최종 답변을 생성하거나, 검색-생성 사이클을 다시 시작합니다.

## 4. 기타 고급 RAG 패턴

LangGraph는 위에서 언급된 패턴 외에도 다양한 고급 RAG 전략을 구현하는 데 활용될 수 있습니다.

### 4.1. 쿼리 변환 (Query Transformation)
사용자의 원본 질문을 LLM이 여러 개의 하위 질문으로 분해하거나, 검색에 더 적합한 형태로 재작성하는 기법입니다. LangGraph에서는 이를 별도의 노드로 구현하고, 그 결과에 따라 병렬 검색을 수행하는 등의 흐름을 만들 수 있습니다.

### 4.2. 하이브리드 검색 (Hybrid Search)
키워드 기반 검색(BM25 등)과 벡터 기반 검색(임베딩 유사도)을 결합하여 검색 정확도를 높이는 기법입니다. LangGraph에서는 두 가지 검색 노드를 병렬로 실행하고, 그 결과를 통합하는 노드를 추가하여 구현할 수 있습니다.

### 4.3. RAPTOR (Recursive Abstractive Processing for Tree-Organized Retrieval)
긴 문서를 계층적으로 요약하고 트리 구조로 저장하여, 질문에 따라 관련성 높은 요약 레벨을 찾아 검색하는 고급 기법입니다. LangGraph는 이러한 복잡한 데이터 처리 및 검색 로직을 노드와 엣지로 표현하여 구현할 수 있습니다.
