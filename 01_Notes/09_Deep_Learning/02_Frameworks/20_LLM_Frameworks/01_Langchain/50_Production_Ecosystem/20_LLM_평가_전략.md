## 1. LLM 평가의 중요성

LLM 기반 애플리케이션은 기존 소프트웨어와는 다른 복잡성을 가집니다. LLM의 비결정론적 특성, 환각(Hallucination) 문제, 그리고 다양한 사용자 입력에 대한 유연한 대응 능력 때문에, 단순히 기능 테스트만으로는 품질을 보장하기 어렵습니다. 체계적인 평가는 LLM 애플리케이션의 성능을 객관적으로 측정하고, 사용자 경험을 개선하며, 비즈니스 목표 달성에 기여하는 필수적인 과정입니다.

### 1.1. 왜 LLM 평가가 어려운가?
- **비결정론적 출력**: 동일한 입력에 대해서도 LLM은 매번 다른 출력을 생성할 수 있습니다.
- **주관성**: 답변의 '좋음'을 판단하는 기준이 주관적일 수 있습니다.
- **복잡한 오류 유형**: 단순히 틀린 답변을 넘어, 환각, 편향, 불완전한 답변 등 다양한 형태의 오류가 발생합니다.
- **컨텍스트 의존성**: 답변의 품질이 주어진 컨텍스트에 크게 의존합니다.

## 2. LLM 평가 방법론

LLM 평가는 크게 인간 평가와 자동화된 평가로 나눌 수 있습니다.

### 2.1. 인간 평가 (Human Evaluation)
가장 정확하고 신뢰할 수 있는 평가 방법입니다. 사람이 직접 LLM의 출력을 읽고, 관련성, 정확성, 유창성, 유용성 등을 기준으로 점수를 매기거나 순위를 부여합니다.

- **장점**: 가장 높은 신뢰도, 복잡하고 미묘한 품질 차이 식별 가능.
- **단점**: 시간과 비용이 많이 들고, 평가자 간의 일관성(inter-rater reliability) 확보가 어려울 수 있습니다.

### 2.2. 자동화된 평가 (Automated Evaluation)
인간 평가의 단점을 보완하기 위해 개발된 방법으로, 미리 정의된 지표나 다른 LLM을 활용하여 자동으로 평가를 수행합니다.

#### 2.2.1. 참조 기반 지표 (Reference-based Metrics)
정답(Reference)이 있는 경우, LLM의 출력과 정답을 비교하여 유사도를 측정합니다. 주로 요약, 번역 등 정답이 명확한 태스크에 사용됩니다.

-   **ROUGE (Recall-Oriented Understudy for Gisting Evaluation)**: 주로 요약 평가에 사용되며, 생성된 요약이 참조 요약과 얼마나 많은 단어/구/문장을 공유하는지 측정합니다.
-   **BLEU (Bilingual Evaluation Understudy)**: 주로 번역 평가에 사용되며, 생성된 번역이 참조 번역과 얼마나 유사한지 측정합니다.
-   **METEOR (Metric for Evaluation of Translation with Explicit Ordering)**: BLEU의 단점을 보완하여 동의어, 어간, 구문 구조 등을 고려합니다.

#### 2.2.2. 참조 없는 지표 (Reference-free Metrics)
정답이 없거나, 정답을 정의하기 어려운 생성 태스크(예: 챗봇 대화)에 주로 사용됩니다.

-   **LLM-as-a-Judge**: 강력한 LLM(예: GPT-4)을 사용하여 다른 LLM의 출력을 평가하는 방법입니다. LLM에게 평가 기준과 예시를 제공하여 객관적인 평가를 유도합니다.
-   **RAGas**: RAG(Retrieval-Augmented Generation) 애플리케이션에 특화된 평가 프레임워크입니다. 다음 지표들을 통해 RAG 시스템의 품질을 측정합니다.
    *   **Faithfulness (충실도)**: 생성된 답변이 검색된 컨텍스트에 얼마나 충실한가? (환각 여부)
    *   **Answer Relevance (답변 관련성)**: 생성된 답변이 질문에 얼마나 관련성이 높은가?
    *   **Context Relevance (컨텍스트 관련성)**: 검색된 컨텍스트가 질문에 얼마나 관련성이 높은가?
    *   **Context Recall (컨텍스트 재현율)**: 정답에 필요한 정보가 검색된 컨텍스트에 얼마나 포함되어 있는가?
-   **휴리스틱 기반 평가**: 특정 규칙이나 패턴을 사용하여 LLM의 출력을 평가합니다. (예: 특정 키워드 포함 여부, 길이 제한 준수 여부)
-   **임베딩 기반 평가**: LLM의 출력과 정답(또는 질문)의 임베딩 벡터 간의 코사인 유사도 등을 측정하여 의미적 유사성을 평가합니다.

## 3. LangChain 생태계의 평가 도구

LangChain은 자체적으로 평가 모듈을 제공하며, LangSmith와 같은 플랫폼을 통해 평가 과정을 통합 관리할 수 있습니다.

### 3.1. LangSmith를 활용한 평가
LangSmith는 LLM 애플리케이션의 개발, 디버깅, 테스트, 평가를 위한 플랫폼입니다. LangSmith를 통해 LLM 호출의 추적(trace) 데이터를 수집하고, 이를 기반으로 다양한 평가 지표를 계산하거나 인간 평가를 수행할 수 있습니다. 또한, 합성 데이터셋을 생성하고 이를 평가에 활용할 수 있습니다.

### 3.2. RAGas 프레임워크
RAGas는 LangChain과 통합되어 RAG 애플리케이션의 평가를 자동화하는 데 특화된 파이썬 라이브러리입니다. 위에서 설명한 Faithfulness, Answer Relevance 등의 지표를 쉽게 계산할 수 있습니다.

### 3.3. ARES 프레임워크
ARES (Automated RAG Evaluation System)는 RAG 시스템의 성능을 평가하기 위한 또 다른 자동화된 프레임워크입니다. RAGas와 유사하게 RAG 시스템의 다양한 측면을 평가합니다.

## 4. 실전 평가 전략

### 4.1. 합성 데이터셋 생성
실제 사용자 데이터를 충분히 확보하기 어렵거나, 특정 엣지 케이스를 테스트해야 할 때 LLM을 활용하여 질문-답변 쌍 또는 컨텍스트-질문-답변 쌍과 같은 합성 데이터셋을 생성할 수 있습니다. 이는 평가의 효율성을 크게 높여줍니다.

### 4.2. 실험 비교 (Experiment Comparison)
LangSmith와 같은 플랫폼을 활용하여 LLM 모델, 프롬프트, RAG 파이프라인 구성 등 다양한 실험 조건에 따른 애플리케이션의 성능 변화를 추적하고 비교합니다. 이를 통해 최적의 설정을 찾아낼 수 있습니다.

### 4.3. 지속적인 평가 (Continuous Evaluation)
애플리케이션 배포 후에도 지속적으로 사용자 피드백을 수집하고, 새로운 데이터를 기반으로 성능을 평가하며, 모델을 업데이트하는 파이프라인을 구축합니다. 온라인 평가(A/B 테스트 등)를 통해 실제 사용자 환경에서의 성능을 검증합니다.
