## 1. LLM 비용의 이해

### 1.1. 비용은 토큰으로부터
대부분의 상용 LLM 서비스(OpenAI, Google, Anthropic 등)는 사용한 **토큰(Token)** 의 양에 따라 비용을 청구합니다. 토큰은 모델이 텍스트를 처리하는 기본 단위로, 대략 단어나 글자에 해당합니다 (언어에 따라 다름).

중요한 점은 **입력 토큰**과 **출력 토큰** 모두에 대해 비용이 발생하며, 보통 출력 토큰의 비용이 더 높게 책정된다는 것입니다. 따라서 프롬프트를 간결하게 만들고, 불필요하게 긴 답변을 생성하지 않도록 제어하는 것이 비용 관리의 첫걸음입니다.

### 1.2. 토큰 사용량 계산하기
LangChain은 콜백(Callback) 기능을 제공하여 체인 실행 시 사용된 토큰의 양을 쉽게 계산할 수 있습니다.

```python
from langchain_openai import ChatOpenAI
from langchain.callbacks import get_openai_callback

llm = ChatOpenAI()

with get_openai_callback() as cb:
    response = llm.invoke("인공지능에 대한 긴 에세이를 작성해줘.")
    print(f"Total Tokens: {cb.total_tokens}")
    print(f"Prompt Tokens: {cb.prompt_tokens}")
    print(f"Completion Tokens: {cb.completion_tokens}")
    print(f"Total Cost (USD): ${cb.total_cost}")
```
이 기능을 사용하여 각 요청의 비용을 모니터링하고, 비용이 많이 드는 부분을 식별하여 최적화할 수 있습니다.

## 2. 캐싱 전략

### 2.1. 왜 캐싱이 중요한가?
사용자들은 종종 동일하거나 매우 유사한 질문을 반복적으로 합니다. 캐싱은 이전에 들어왔던 요청과 동일한 요청이 다시 들어왔을 때, LLM을 호출하지 않고 저장된 결과를 즉시 반환하는 기술입니다. 이를 통해 **API 비용을 크게 절감**하고, 사용자의 **응답 시간을 획기적으로 단축**할 수 있습니다.

### 2.2. 인-메모리 캐시 (In-Memory Cache)
가장 간단한 캐시 형태로, 실행 중인 애플리케이션의 메모리에 결과를 저장합니다. 애플리케이션이 재시작되면 캐시는 사라집니다. 테스트나 소규모 애플리케이션에 적합합니다.

```python
import langchain
from langchain.cache import InMemoryCache

# LangChain 전역 설정에 캐시 적용
langchain.llm_cache = InMemoryCache()

# 첫 번째 호출: LLM을 실제로 호출하고 결과를 캐시에 저장
llm.invoke("대한민국의 수도는?")

# 두 번째 호출: 동일한 입력에 대해서는 LLM을 호출하지 않고 캐시된 결과를 즉시 반환 (비용 0, 속도 향상)
llm.invoke("대한민국의 수도는?")
```

### 2.3. 시맨틱 캐시 (Semantic Cache)
인-메모리 캐시는 정확히 동일한 입력에만 작동하는 한계가 있습니다. 예를 들어, "대한민국의 수도는?"와 "한국의 수도는 어디야?"는 의미가 같지만, 캐시는 이를 다른 요청으로 인식합니다.

**시맨틱 캐시**는 이 문제를 해결합니다. 새로운 요청이 들어오면, 먼저 요청 문장의 의미(임베딩 벡터)를 계산하여 캐시에 저장된 질문들의 벡터와 비교합니다. 만약 의미적으로 유사한 질문이 캐시에 존재한다면, LLM을 호출하지 않고 해당 결과를 반환합니다.

- **구현**: `GPTCache`와 같은 외부 라이브러리를 LangChain과 연동하여 구현할 수 있습니다.
- **장점**: 비용 절감 효과를 극대화할 수 있습니다.
- **단점**: 임베딩 및 벡터 비교 과정에서 약간의 오버헤드가 발생할 수 있습니다.

## 3. 비용 효율적인 모델 선택

모든 작업에 가장 강력하고 비싼 모델(예: GPT-4)을 사용할 필요는 없습니다. 작업의 복잡도에 따라 적절한 모델을 선택하는 것이 중요합니다.

- **간단한 작업**: 텍스트 분류, 간단한 질의응답 등은 `gpt-3.5-turbo`나 더 작은 오픈소스 모델로도 충분히 처리할 수 있습니다.
- **복잡한 추론**: 여러 단계를 거쳐야 하는 복잡한 추론이나 코드 생성 등은 `gpt-4`와 같은 고성능 모델이 필요할 수 있습니다.

**라우터 체인(Router Chain)** 을 사용하여 사용자의 질문 유형에 따라 동적으로 다른 모델이나 체인을 호출하도록 설계하는 것도 좋은 비용 최적화 전략입니다. 예를 들어, 간단한 인사말은 저렴한 모델로, 복잡한 전문 지식 질문은 고성능 모델로 라우팅할 수 있습니다.
