## 1. 의존성 주입과 보안

FastAPI의 의존성 주입(Dependency Injection) 시스템은 경로 작업 함수(Path Operation Function)의 매개변수로 선언된 '의존성'을 자동으로 해결하고 주입해 줍니다. 이 강력한 메커니즘은 보안 로직을 구현하는 데 매우 효과적입니다.

### 1.1. 의존성 주입의 장점
-   **코드 재사용성**: 인증, 권한 검사, 데이터베이스 세션 관리 등 반복되는 로직을 별도의 함수로 분리하여 여러 경로 작업 함수에서 재사용할 수 있습니다.
-   **모듈성**: 보안 로직이 핵심 비즈니스 로직과 분리되어 코드의 가독성과 유지보수성이 향상됩니다.
-   **테스트 용이성**: 의존성을 쉽게 Mocking하거나 교체할 수 있어 테스트 작성이 용이합니다.
-   **자동 문서화**: 의존성으로 선언된 보안 요구사항이 자동으로 OpenAPI 문서에 반영됩니다.

### 1.2. 보안 로직의 재사용성
`Depends`를 사용하여 인증된 사용자 정보를 가져오거나, 특정 권한을 가진 사용자만 접근할 수 있도록 하는 로직을 구현할 수 있습니다.

```python
from fastapi import Depends, HTTPException, status
from typing import Annotated

# 이전 문서에서 정의된 get_current_user 함수 (JWT 토큰 검증 후 사용자 객체 반환)
# from .auth_utils import get_current_user
# from .models import User # 사용자 모델

# 예시를 위한 더미 get_current_user 함수와 User 모델
class User:
    def __init__(self, id: int, username: str, role: str):
        self.id = id
        self.username = username
        self.role = role

async def get_current_user_dummy(token: str = Depends(lambda: "fake_token")) -> User:
    if token != "fake_token":
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Invalid token")
    return User(id=1, username="testuser", role="user")

# Annotated를 사용하여 의존성 주입
CurrentUser = Annotated[User, Depends(get_current_user_dummy)]

@app.get("/users/me/")
async def read_users_me(current_user: CurrentUser):
    return {"username": current_user.username, "role": current_user.role}
```

## 2. 인증 의존성 주입

`get_current_user`와 같은 의존성 함수를 사용하여 요청에 포함된 인증 정보를 검증하고, 유효한 경우 현재 사용자 객체를 경로 작업 함수에 주입합니다.

### 2.1. 현재 사용자 가져오기
`get_current_user` 함수는 `Authorization` 헤더에서 JWT 토큰을 추출하고, 이를 검증하여 사용자 객체를 반환합니다. (자세한 구현은 `07_OAuth2_JWT_인증.md` 참조)

```python

# from jose import JWTError, jwt
# from fastapi import Depends, HTTPException, status
# from .config import SECRET_KEY, ALGORITHM
# from . import models, schemas

# async def get_current_user(token: str = Depends(oauth2_scheme), db: AsyncSession = Depends(get_db)):
#     # ... 토큰 검증 및 사용자 조회 로직 ...
#     return user
```

### 2.2. 인증 실패 처리
`get_current_user` 함수 내에서 인증에 실패하면 `HTTPException`을 발생시켜 `401 Unauthorized` 응답을 반환합니다. FastAPI는 이 예외를 자동으로 처리하여 클라이언트에게 적절한 HTTP 응답을 보냅니다.

## 3. 권한 부여 의존성 주입

인증된 사용자가 특정 리소스에 접근하거나 특정 작업을 수행할 권한이 있는지 확인하는 과정입니다. 의존성 주입을 사용하여 역할 기반 접근 제어(RBAC)를 구현할 수 있습니다.

### 3.1. 역할 기반 접근 제어 (RBAC)
RBAC는 사용자에게 직접 권한을 부여하는 대신, 역할을 부여하고 그 역할에 권한을 연결하는 방식입니다. (예: '관리자' 역할은 '게시글 생성', '사용자 관리' 권한을 가짐)

### 3.2. 역할 정의
사용자 모델에 `role` 필드를 추가하거나, 별도의 `Role` 모델을 정의하여 사용자와 연결합니다.

```python
# models.py (User 모델에 role 필드 추가 예시)
# from sqlalchemy import Column, Integer, String
# from sqlalchemy.orm import Mapped, mapped_column, DeclarativeBase

#     __tablename__ = "users"

#     username: Mapped[str] = mapped_column(String, unique=True, index=True)
#     role: Mapped[str] = mapped_column(String, default="user") # user, admin, editor 등
```

### 3.3. 역할 검증 의존성
특정 역할을 가진 사용자만 접근할 수 있도록 하는 의존성 함수를 정의합니다.

```python
from fastapi import Depends, HTTPException, status
from typing import Annotated

# get_current_user_dummy는 위에서 정의된 더미 함수 또는 실제 get_current_user 함수
# from .auth_utils import get_current_user # 실제 구현 시

# 관리자 역할 검증 의존성
async def get_current_admin_user(current_user: Annotated[User, Depends(get_current_user_dummy)]):
    if current_user.role != "admin":
        raise HTTPException(status_code=status.HTTP_403_FORBIDDEN, detail="관리자 권한이 필요합니다.")
    return current_user

# 에디터 역할 검증 의존성
async def get_current_editor_user(current_user: Annotated[User, Depends(get_current_user_dummy)]):
    if current_user.role not in ["admin", "editor"]:
        raise HTTPException(status_code=status.HTTP_403_FORBIDDEN, detail="편집자 또는 관리자 권한이 필요합니다.")
    return current_user

# 경로 작업 함수에 적용
@app.get("/admin_dashboard/")
async def admin_dashboard(admin_user: Annotated[User, Depends(get_current_admin_user)]):
    return {"message": f"환영합니다, 관리자 {admin_user.username}님!"}

@app.post("/articles/")
async def create_article(editor_user: Annotated[User, Depends(get_current_editor_user)]):
    return {"message": f"기사 작성 권한이 있습니다, {editor_user.username}님!"}
```

## 4. 고급 보안 의존성 패턴

### 4.1. 스코프 기반 권한 (OAuth2 Scopes)
OAuth2에서는 토큰에 '스코프(scope)'를 부여하여, 토큰이 접근할 수 있는 리소스의 범위를 제한할 수 있습니다. (예: `read:users`, `write:articles`). FastAPI는 `Security`와 `OAuth2PasswordBearer`를 사용하여 스코프 기반 권한을 구현할 수 있습니다.

```python
from fastapi.security import Security, OAuth2PasswordBearer, OAuth2PasswordRequestForm
from typing import Annotated

# OAuth2PasswordBearer 인스턴스 (토큰 URL은 실제 토큰 발급 엔드포인트)
oauth2_scheme_with_scopes = OAuth2PasswordBearer(tokenUrl="token", scopes={"read:users": "Read users info", "write:articles": "Write articles"})

# 스코프 검증 의존성
async def get_current_user_with_scopes(security_scopes: Security(oauth2_scheme_with_scopes, scopes=["write:articles"])):
    # 실제 토큰 검증 및 사용자 조회 로직
    # payload = jwt.decode(security_scopes, SECRET_KEY, algorithms=[ALGORITHM])
    # user_scopes = payload.get("scopes", [])
    # for scope in security_scopes.scopes:
    #     if scope not in user_scopes:
    #         raise HTTPException(status_code=status.HTTP_403_FORBIDDEN, detail="Not enough permissions")
    # return user
    return {"message": "스코프 검증 완료"}

@app.post("/articles/", dependencies=[Depends(get_current_user_with_scopes)])
async def create_article_with_scope():
    return {"message": "기사 작성 권한이 있습니다."}
```

### 4.2. 객체 수준 권한 (Object-level Permissions)
특정 객체(예: 게시글)에 대해 해당 객체의 소유자만 수정/삭제할 수 있도록 하는 권한입니다. 이는 경로 파라미터로 객체 ID를 받은 후, 데이터베이스에서 객체를 조회하여 현재 사용자가 해당 객체의 소유자인지 확인하는 방식으로 구현합니다.

```python
# main.py (예시)
from fastapi import Depends, HTTPException, status
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
# from .database import get_db
# from .models import Post # Post 모델 정의 필요

# 예시를 위한 더미 Post 모델
class Post:
    def __init__(self, id: int, title: str, author_id: int):
        self.id = id
        self.title = title
        self.author_id = author_id

async def get_post_or_404(post_id: int, db: AsyncSession = Depends(lambda: "fake_db_session")) -> Post:
    # 실제 DB에서 Post 객체를 조회하는 로직
    # post = await db.get(Post, post_id)
    # if post is None:
    #     raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Post not found")
    # return post
    if post_id == 1:
        return Post(id=1, title="테스트 게시글", author_id=1)
    raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Post not found")

async def verify_post_owner(post: Annotated[Post, Depends(get_post_or_404)], current_user: Annotated[User, Depends(get_current_user_dummy)]):
    if post.author_id != current_user.id:
        raise HTTPException(status_code=status.HTTP_403_FORBIDDEN, detail="게시글 수정 권한이 없습니다.")
    return post

@app.put("/posts/{post_id}")
async def update_post(post: Annotated[Post, Depends(verify_post_owner)]):
    return {"message": f"게시글 '{post.title}'이 수정되었습니다."}
```

### 4.3. 의존성 주입을 이용한 Rate Limiting
FastAPI의 의존성 주입 시스템을 사용하여 요청 횟수 제한(Rate Limiting)을 구현할 수 있습니다. `FastAPI-Limiter`와 같은 라이브러리를 활용하면 더욱 편리합니다.

```python
# main.py (예시)
from fastapi import FastAPI, Depends, Request
from fastapi_limiter import FastAPILimiter
from fastapi_limiter.depends import RateLimiter
import redis.asyncio as redis

# @app.on_event("startup")
# async def startup():
#     redis_connection = redis.from_url("redis://localhost:6379", encoding="utf8", decode_responses=True)
#     await FastAPILimiter.init(redis_connection)

@app.get("/limited_route", dependencies=[Depends(RateLimiter(times=1, seconds=5))])
async def limited_route():
    return {"message": "이 경로는 5초에 한 번만 접근 가능합니다."}
```
이처럼 FastAPI의 의존성 주입은 보안 로직을 유연하고 강력하게 구축하는 핵심 도구입니다.
