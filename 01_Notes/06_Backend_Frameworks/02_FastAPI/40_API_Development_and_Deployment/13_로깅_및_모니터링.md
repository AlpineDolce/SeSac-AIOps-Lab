## 1. 로깅 (Logging)

체계적인 로깅은 애플리케이션의 동작을 추적하고, 에러를 신속하게 진단하며, 성능 문제를 분석하는 데 필수적인 기반입니다.

### 1.1. 로깅의 필요성
-   **문제 진단**: 에러 발생 시 원인을 파악하고 해결하는 데 필요한 정보를 제공합니다.
-   **애플리케이션 동작 추적**: 사용자의 요청 흐름, 특정 기능의 실행 과정 등을 기록하여 애플리케이션의 동작을 이해하는 데 도움을 줍니다.
-   **성능 분석**: 특정 작업의 소요 시간, 자원 사용량 등을 기록하여 성능 병목을 식별합니다.
-   **보안 감사**: 비정상적인 접근 시도나 보안 이벤트 등을 기록하여 보안 감사를 수행할 수 있습니다.

### 1.2. 파이썬 표준 로깅 모듈
파이썬은 강력하고 유연한 내장 `logging` 모듈을 제공합니다. 이 모듈은 로거(Logger), 핸들러(Handler), 포매터(Formatter), 필터(Filter)의 네 가지 주요 구성 요소로 이루어집니다.

-   **로거 (Logger)**: 로그 메시지를 생성하고 전달하는 역할을 합니다.
-   **핸들러 (Handler)**: 로거로부터 받은 메시지를 실제로 어디에(콘솔, 파일, 네트워크 등) 보낼지 결정합니다.
-   **포매터 (Formatter)**: 로그 메시지의 출력 형식을 지정합니다.
-   **필터 (Filter)**: 로그 메시지를 특정 조건에 따라 필터링합니다.

### 1.3. FastAPI에서 로깅 설정
FastAPI는 Uvicorn을 통해 실행되며, Uvicorn은 기본적으로 `uvicorn.logging`을 사용하여 로그를 출력합니다. `logging` 모듈을 직접 설정하여 로깅을 커스터마이징할 수 있습니다.

```python
# main.py
import logging
from fastapi import FastAPI

app = FastAPI()

# 로거 인스턴스 생성
logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO) # INFO 레벨 이상의 로그만 처리

# 콘솔 핸들러 생성 및 포매터 설정
handler = logging.StreamHandler()
formatter = logging.Formatter("%(asctime)s - %(name)s - %(levelname)s - %(message)s")
handler.setFormatter(formatter)

# 로거에 핸들러 추가
logger.addHandler(handler)

@app.get("/")
async def read_root():
    logger.info("Root endpoint accessed.")
    return {"message": "Hello, FastAPI!"}

@app.get("/error")
async def trigger_error():
    try:
        1 / 0
    except Exception as e:
        logger.error(f"An error occurred: {e}", exc_info=True) # exc_info=True로 스택 트레이스 포함
        raise HTTPException(status_code=500, detail="Internal Server Error")
```

### 1.4. 구조화된 로깅 (Structured Logging)
JSON과 같은 구조화된 형식으로 로그를 기록하면, 로그 분석 시스템(예: ELK Stack, Grafana Loki)에서 로그를 쉽게 파싱하고 분석할 수 있습니다. `python-json-logger`와 같은 라이브러리를 사용할 수 있습니다.

```bash
pip install python-json-logger
```

```python
# main.py (구조화된 로깅 예시)
import logging
from pythonjsonlogger import jsonlogger
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()

# JSON 포매터 설정
formatter = jsonlogger.JsonFormatter(
    fmt='%(asctime)s %(levelname)s %(name)s %(message)s %(pathname)s %(lineno)d',
    json_ensure_ascii=False # 한글 깨짐 방지
)

# 콘솔 핸들러에 JSON 포매터 적용
json_handler = logging.StreamHandler()
json_handler.setFormatter(formatter)

# 루트 로거에 핸들러 추가 (Uvicorn 로그도 JSON으로 출력)
logging.basicConfig(handlers=[json_handler], level=logging.INFO)
logger = logging.getLogger(__name__)

@app.get("/structured_log")
async def structured_log(request: Request):
    logger.info("Structured log example", extra={"user_id": 123, "request_path": request.url.path})
    return {"message": "Check your logs!"}
```

## 2. 성능 모니터링 (Performance Monitoring)

애플리케이션 성능 저하는 사용자 경험에 치명적이며, 조용한 장애(silent failure)를 유발할 수 있습니다. 코드 변경이 없더라도 데이터의 양이나 트래픽 패턴 변화만으로 성능 문제가 발생할 수 있으므로, 개발 단계부터 운영까지 지속적인 모니터링이 중요합니다.

### 2.1. APM (Application Performance Monitoring)
APM 도구는 애플리케이션의 성능을 실시간으로 추적하고 병목 현상을 분석하는 데 사용됩니다. 주요 기능은 다음과 같습니다.
-   **트랜잭션 추적**: 각 요청의 시작부터 끝까지의 흐름과 소요 시간을 상세하게 기록합니다.
-   **오류 모니터링**: 애플리케이션에서 발생하는 오류를 실시간으로 감지하고 알림을 보냅니다.
-   **데이터베이스 쿼리 분석**: 느린 쿼리나 N+1 문제 등을 식별합니다.
-   **외부 서비스 호출 모니터링**: 외부 API 호출의 성능을 추적합니다.
-   **자원 사용량 모니터링**: CPU, 메모리, 디스크, 네트워크 사용량 등을 모니터링합니다.

주요 APM 도구로는 Sentry, Datadog, New Relic, Prometheus/Grafana 등이 있습니다.

### 2.2. FastAPI에서 APM 연동
APM 도구들은 일반적으로 미들웨어 형태로 FastAPI 애플리케이션에 연동됩니다.

```python
# main.py (Sentry 연동 예시)
import sentry_sdk
from sentry_sdk.integrations.asgi import SentryAsgiMiddleware
from fastapi import FastAPI, HTTPException

# Sentry 초기화 (DSN은 Sentry 프로젝트에서 발급받음)
sentry_sdk.init(
    dsn="YOUR_SENTRY_DSN",
    traces_sample_rate=1.0, # 트랜잭션 샘플링 비율 (운영에서는 0.1~0.01 권장)
    environment="development", # 환경 설정 (production, staging 등)
    release="my-fastapi-app@1.0.0", # 애플리케이션 버전
)

app = FastAPI()

# Sentry 미들웨어 추가 (가장 먼저 추가하는 것이 좋음)
app.add_middleware(SentryAsgiMiddleware)

@app.get("/sentry-test")
async def sentry_test():
    1 / 0 # 에러 발생시켜 Sentry에 전송되는지 확인
```

## 3. 헬스 체크 (Health Checks)

헬스 체크 엔드포인트는 서비스의 현재 상태를 외부에 알리는 통신 규약입니다. 로드 밸런서나 컨테이너 오케스트레이션 시스템(예: Kubernetes)은 이 엔드포인트를 주기적으로 호출하여, 애플리케이션이 정상적으로 요청을 처리할 수 있는 상태인지 확인합니다.

### 3.1. 헬스 체크의 필요성
-   **로드 밸런싱**: 헬스 체크에 실패한 인스턴스(서버)를 서비스에서 제외하여, 사용자 요청이 실패한 서버로 전달되는 것을 막습니다.
-   **무중단 배포**: 새 버전의 앱이 정상적으로 실행되는지 헬스 체크로 확인한 후 트래픽을 새 버전으로 전환합니다.
-   **자동 복구**: 서비스가 비정상 상태일 때, 오케스트레이션 시스템이 이를 감지하고 자동으로 해당 인스턴스를 재시작하여 서비스를 복구합니다.

### 3.2. FastAPI에서 헬스 체크 엔드포인트 구현
FastAPI에서 헬스 체크 엔드포인트를 구현하는 것은 매우 간단합니다. 서비스가 의존하는 핵심 시스템(DB, 캐시 등)의 상태를 점검하는 로직을 포함합니다.

```python
from fastapi import FastAPI, Response, status
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import text
# from .database import get_db # DB 세션 의존성 (이전 문서 참조)

app = FastAPI()

# 더미 get_db 함수 (실제 DB 연결 로직으로 대체)
async def get_db_dummy():
    yield "dummy_session"

@app.get("/health", status_code=status.HTTP_200_OK)
async def health_check(db: AsyncSession = Depends(get_db_dummy)):
    # 데이터베이스 연결 확인 (예시)
    try:
        # 실제 DB 쿼리 실행 (예: SELECT 1)
        # await db.execute(text("SELECT 1"))
        db_status = "ok"
    except Exception:
        db_status = "error"
    
    # 캐시 연결 확인 (예시)
    cache_status = "ok" # 실제 캐시 연결 확인 로직

    if db_status == "ok" and cache_status == "ok":
        return {"status": "healthy", "database": db_status, "cache": cache_status}
    else:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail={"status": "unhealthy", "database": db_status, "cache": cache_status}
        )
```

## 4. 알림 설정 (Alerting)

로깅과 모니터링 시스템이 문제를 감지했을 때, 이를 담당자에게 신속하게 전달하는 알림(Alerting) 시스템이 구축되어야 즉각적인 대응이 가능합니다.

### 4.1. 알림의 필요성
-   **신속한 대응**: 문제 발생 시 담당자에게 즉시 알려 서비스 중단을 최소화합니다.
-   **문제 인지**: 시스템의 비정상적인 동작을 개발팀이 빠르게 인지할 수 있도록 합니다.
-   **예방**: 특정 지표가 임계값을 초과하기 시작할 때 미리 알림을 보내어 잠재적인 문제를 예방합니다.

### 4.2. 알림 채널 연동 (Slack, Email)
주요 알림 채널로는 Slack, Email, PagerDuty 등이 있습니다. 파이썬에서는 `requests` 라이브러리를 사용하여 Slack 웹훅으로 알림을 보내거나, `smtplib`를 사용하여 이메일을 보낼 수 있습니다.

```python
# main.py (Slack 알림 예시)
import requests
import json
from fastapi import FastAPI, HTTPException

app = FastAPI()

SLACK_WEBHOOK_URL = "YOUR_SLACK_WEBHOOK_URL" # Slack 웹훅 URL (환경 변수로 관리)

def send_slack_notification(message: str):
    payload = {
        "text": message,
        "username": "FastAPI Bot",
        "icon_emoji": ":robot_face:"
    }
    try:
        response = requests.post(SLACK_WEBHOOK_URL, data=json.dumps(payload), headers={'Content-Type': 'application/json'})
        response.raise_for_status()
    except Exception as e:
        logger.error(f"Failed to send Slack notification: {e}") # 로깅 설정 필요

@app.post("/trigger_alert")
async def trigger_alert(message: str):
    send_slack_notification(f"🚨 긴급 알림: {message}")
    return {"message": "Alert triggered."}
```
APM 도구(Sentry, Datadog)는 자체적으로 강력한 알림 기능을 제공하며, 다양한 채널과 연동됩니다. 이를 활용하는 것이 가장 효율적인 알림 전략입니다.
