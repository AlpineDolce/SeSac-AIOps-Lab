## 1. 웹소켓(WebSocket)이란?

웹소켓은 웹 브라우저와 서버 간에 단일 TCP 연결을 통해 양방향(full-duplex) 통신 채널을 제공하는 프로토콜입니다. HTTP와 달리 한 번 연결이 수립되면 클라이언트와 서버가 언제든지 서로에게 데이터를 보낼 수 있어 실시간 애플리케이션에 매우 적합합니다.

### 1.1. HTTP 통신의 한계
HTTP는 기본적으로 단방향(half-duplex) 통신이며, 클라이언트가 요청을 보내야만 서버가 응답하는 '요청-응답' 모델을 따릅니다. 실시간 업데이트가 필요한 경우, 클라이언트는 다음과 같은 비효율적인 방법을 사용해야 했습니다.
-   **폴링(Polling)**: 클라이언트가 주기적으로 서버에 새로운 데이터가 있는지 요청. (서버 부하, 지연 발생)
-   **롱 폴링(Long Pol링)**: 클라이언트가 서버에 요청을 보내고, 서버는 새로운 데이터가 생길 때까지 응답을 지연. (연결 유지 비용, 복잡성)

### 1.2. 웹소켓의 특징
-   **양방향 통신**: 클라이언트와 서버가 동시에 서로에게 데이터를 보낼 수 있습니다.
-   **단일 연결**: 한 번 연결이 수립되면 연결이 유지되므로, 매번 연결을 새로 맺는 오버헤드가 없습니다.
-   **낮은 오버헤드**: HTTP 요청/응답에 비해 헤더가 작아 데이터 전송 효율이 높습니다.
-   **실시간성**: 채팅, 게임, 주식 시세, 알림, 실시간 협업 도구 등 즉각적인 데이터 업데이트가 필요한 애플리케이션에 적합합니다.

## 2. FastAPI에서 웹소켓 구현

FastAPI는 `WebSocket` 클래스와 `@app.websocket()` 데코레이터를 통해 웹소켓 통신을 쉽게 구현할 수 있도록 지원합니다.

### 2.1. `@app.websocket()` 데코레이터
경로 작업 데코레이터와 유사하게, 특정 URL 경로에 대한 웹소켓 연결을 처리할 함수를 지정합니다.

```python
from fastapi import FastAPI, WebSocket

app = FastAPI()

@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept() # 웹소켓 연결 수락
    while True:
        data = await websocket.receive_text() # 클라이언트로부터 텍스트 데이터 수신
        await websocket.send_text(f"Message text was: {data}") # 클라이언트에게 텍스트 데이터 전송
```

### 2.2. `WebSocket` 객체
웹소켓 연결이 수립되면, 경로 작업 함수의 인자로 `WebSocket` 객체가 주입됩니다. 이 객체를 통해 클라이언트와 데이터를 주고받을 수 있습니다.

-   `await websocket.accept()`: 클라이언트의 웹소켓 연결 요청을 수락합니다.
-   `await websocket.receive_text()`: 클라이언트로부터 텍스트 데이터를 수신합니다.
-   `await websocket.receive_bytes()`: 클라이언트로부터 바이너리 데이터를 수신합니다.
-   `await websocket.send_text(data)`: 클라이언트에게 텍스트 데이터를 전송합니다.
-   `await websocket.send_bytes(data)`: 클라이언트에게 바이너리 데이터를 전송합니다.
-   `await websocket.close()`: 웹소켓 연결을 종료합니다.

### 2.3. 데이터 송수신
`receive_text()`, `send_text()` 등을 사용하여 텍스트 데이터를 주고받을 수 있습니다. 클라이언트와 서버 간에 JSON 데이터를 주고받는 것이 일반적입니다.

## 3. 간단한 에코(Echo) 웹소켓 서버

클라이언트가 보낸 메시지를 그대로 다시 돌려주는 간단한 에코 웹소켓 서버를 구현해 봅시다.

### 3.1. 서버 코드
```python
# main.py
from fastapi import FastAPI, WebSocket

app = FastAPI()

@app.websocket("/ws/echo")
async def websocket_echo(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            data = await websocket.receive_text()
            await websocket.send_text(f"Echo: {data}")
    except Exception as e:
        print(f"WebSocket disconnected: {e}")
    finally:
        await websocket.close()
```

### 3.2. 클라이언트 코드 (HTML/JavaScript)
`index.html` 파일을 생성하고 다음 코드를 작성합니다.

```html
<!DOCTYPE html>
<html>
<head>
    <title>FastAPI WebSocket Echo</title>
</head>
<body>
    <h1>WebSocket Echo Test</h1>
    <input type="text" id="messageInput" placeholder="메시지를 입력하세요">
    <button onclick="sendMessage()">전송</button>
    <div id="messages"></div>

    <script>
        // WebSocket 연결
        const ws = new WebSocket("ws://localhost:8000/ws/echo");

        // 연결이 열렸을 때
        ws.onopen = (event) => {
            addMessage("Connected to WebSocket server.");
        };

        // 메시지를 받았을 때
        ws.onmessage = (event) => {
            addMessage(`Received: ${event.data}`);
        };

        // 에러 발생 시
        ws.onerror = (event) => {
            addMessage("WebSocket error observed:", event);
        };

        // 연결이 닫혔을 때
        ws.onclose = (event) => {
            addMessage("Disconnected from WebSocket server.");
        };

        // 메시지 전송 함수
        function sendMessage() {
            const input = document.getElementById("messageInput");
            const message = input.value;
            if (message) {
                ws.send(message);
                addMessage(`Sent: ${message}`);
                input.value = "";
            }
        }

        // 메시지를 화면에 추가하는 함수
        function addMessage(message) {
            const messagesDiv = document.getElementById("messages");
            const p = document.createElement("p");
            p.textContent = message;
            messagesDiv.appendChild(p);
        }
    </script>
</body>
</html>
```
서버(`uvicorn main:app --reload`)를 실행한 후, 브라우저에서 `index.html` 파일을 열고 테스트할 수 있습니다.

## 4. 채팅 애플리케이션 구현

여러 클라이언트가 접속하여 서로 메시지를 주고받는 간단한 채팅 애플리케이션을 구현해 봅시다. 이를 위해서는 서버에서 연결된 모든 클라이언트를 관리하고, 특정 클라이언트가 메시지를 보냈을 때 다른 모든 클라이언트에게 메시지를 브로드캐스팅하는 기능이 필요합니다.

### 4.1. 연결 관리
FastAPI는 연결된 웹소켓 클라이언트들을 직접 관리하는 기능을 제공하지 않으므로, 별도의 클래스를 만들어 연결된 `WebSocket` 객체들을 저장하고 관리해야 합니다.

```python
# app/websocket_manager.py
from typing import List
from fastapi import WebSocket

class ConnectionManager:
    def __init__(self):
        self.active_connections: List[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)

    async def send_personal_message(self, message: str, websocket: WebSocket):
        await websocket.send_text(message)

    async def broadcast(self, message: str):
        for connection in self.active_connections:
            await connection.send_text(message)

manager = ConnectionManager() # 전역 인스턴스
```

### 4.2. 메시지 브로드캐스팅
특정 클라이언트가 메시지를 보내면, `ConnectionManager`의 `broadcast` 메서드를 사용하여 연결된 모든 클라이언트에게 메시지를 전송합니다.

### 4.3. 서버 코드
```python
# main.py (채팅 애플리케이션)
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from app.websocket_manager import manager # 위에서 정의한 ConnectionManager 임포트

app = FastAPI()

@app.websocket("/ws/chat/{client_id}")
async def websocket_chat(websocket: WebSocket, client_id: int):
    await manager.connect(websocket) # 클라이언트 연결
    try:
        while True:
            data = await websocket.receive_text() # 메시지 수신
            message = f"Client #{client_id}: {data}"
            await manager.broadcast(message) # 모든 클라이언트에게 브로드캐스팅
    except WebSocketDisconnect: # 연결이 끊어졌을 때
        manager.disconnect(websocket)
        await manager.broadcast(f"Client #{client_id} left the chat")
    except Exception as e:
        print(f"WebSocket error for client {client_id}: {e}")
        manager.disconnect(websocket) # 오류 발생 시 연결 해제
```

### 4.4. 클라이언트 코드 (HTML/JavaScript)
`chat.html` 파일을 생성하고 다음 코드를 작성합니다.

## 5. 웹소켓 배포 고려사항

웹소켓 애플리케이션을 프로덕션 환경에 배포할 때는 몇 가지 추가적인 고려사항이 있습니다.

### 5.1. ASGI 서버
FastAPI는 ASGI(Asynchronous Server Gateway Interface)를 기반으로 하므로, 웹소켓 통신을 위해서는 Uvicorn과 같은 ASGI 서버가 필수적입니다. Gunicorn과 Uvicorn 워커를 조합하여 사용하는 것이 프로덕션 환경에서 권장됩니다.

### 5.2. 리버스 프록시 (Nginx)
Nginx와 같은 리버스 프록시를 사용할 경우, 웹소켓 연결을 위한 특별한 설정이 필요합니다. HTTP 연결을 웹소켓 연결로 업그레이드(Upgrade)하는 헤더를 전달해야 합니다.

```nginx
# /etc/nginx/sites-available/your_fastapi_app.conf (Nginx 설정 예시)

server {
    listen 80;
    server_name your_domain.com;

    location / {
        proxy_pass http://127.0.0.1:8000; # Uvicorn이 실행되는 주소와 포트
        proxy_http_version 1.1; # HTTP/1.1 사용
        proxy_set_header Upgrade $http_upgrade; # 웹소켓 업그레이드 헤더 전달
        proxy_set_header Connection "upgrade"; # 웹소켓 연결 유지
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
이러한 설정을 통해 FastAPI 웹소켓 애플리케이션을 안정적으로 배포할 수 있습니다.
