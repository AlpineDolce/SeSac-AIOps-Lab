## 1. 알고리즘과 자료구조의 기초

컴퓨터 과학에서 알고리즘과 자료구조는 문제 해결의 핵심 도구입니다. 이들을 이해하는 것은 효율적인 소프트웨어를 개발하고 복잡한 문제를 해결하는 데 필수적인 기반 지식입니다.

### 1.1. 알고리즘(Algorithm)이란?

알고리즘은 특정 문제를 해결하기 위한 유한하고 명확한 단계들의 집합입니다. 입력(Input)을 받아 출력(Output)을 생성하며, 각 단계는 모호함 없이 수행 가능해야 합니다.

#### 1.1.1. 알고리즘의 정의와 특성

*   **정의:** 문제를 해결하기 위한 절차나 방법.
*   **특성:**
    *   **정확성 (Correctness):** 주어진 입력에 대해 올바른 출력을 생성해야 합니다.
    *   **명확성 (Unambiguity):** 각 단계는 모호함 없이 명확하게 정의되어야 합니다.
    *   **유한성 (Finiteness):** 유한한 시간 내에 종료되어야 합니다.
    *   **효율성 (Efficiency):** 가능한 한 적은 자원(시간, 메모리)을 사용하여 문제를 해결해야 합니다.
    *   **입력 (Input):** 0개 이상의 외부에서 제공되는 값이 있어야 합니다.
    *   **출력 (Output):** 1개 이상의 결과가 생성되어야 합니다.

#### 1.1.2. 알고리즘의 중요성

알고리즘은 소프트웨어의 성능과 효율성을 결정하는 핵심 요소입니다. 동일한 문제를 해결하더라도 어떤 알고리즘을 사용하느냐에 따라 실행 시간과 메모리 사용량이 크게 달라질 수 있습니다. 이는 사용자 경험, 시스템 자원 활용, 그리고 비즈니스 비용에 직접적인 영향을 미칩니다.

### 1.2. 자료구조(Data Structure)란?

자료구조는 데이터를 효율적으로 저장하고 관리하며, 특정 연산을 수행하기 위한 조직적인 방법입니다. 알고리즘이 데이터를 처리하는 '방법'이라면, 자료구조는 데이터를 담는 '그릇'이라고 할 수 있습니다.

#### 1.2.1. 자료구조의 정의와 필요성

*   **정의:** 데이터의 효율적인 접근과 수정을 가능하게 하는 데이터의 조직, 관리, 저장 방식.
*   **필요성:**
    *   **효율적인 데이터 관리:** 데이터를 체계적으로 저장하여 검색, 삽입, 삭제 등의 연산을 빠르게 수행할 수 있도록 돕습니다.
    *   **문제 해결의 용이성:** 특정 문제에 적합한 자료구조를 선택함으로써 알고리즘 설계가 훨씬 쉬워지고 효율적인 해결책을 찾을 수 있습니다.
    *   **메모리 효율성:** 데이터를 효율적으로 배치하여 메모리 사용량을 최적화합니다.

#### 1.2.2. 추상 자료형(Abstract Data Type, ADT)

추상 자료형(ADT)은 자료구조가 제공하는 연산들의 집합과 각 연산의 동작 방식을 정의하지만, 그 연산들이 어떻게 구현되는지는 명시하지 않습니다. 이는 자료구조의 '무엇(What)'을 정의하고, '어떻게(How)'는 구현체에 맡기는 개념입니다.

*   **예시:** 스택(Stack) ADT는 `push`, `pop`, `peek` 등의 연산을 정의하지만, 이 연산들이 배열로 구현될지, 링크드 리스트로 구현될지는 ADT의 관심사가 아닙니다.

#### 1.2.3. 자료구조의 분류 (선형, 비선형)

자료구조는 데이터를 저장하는 방식에 따라 크게 선형 자료구조와 비선형 자료구조로 나눌 수 있습니다.

*   **선형 자료구조 (Linear Data Structures):** 데이터를 순차적으로 저장합니다.
    *   예: 배열, 리스트, 스택, 큐, 링크드 리스트
*   **비선형 자료구조 (Non-linear Data Structures):** 데이터를 계층적 또는 네트워크 형태로 저장합니다.
    *   예: 트리, 그래프, 해시 테이블

### 1.3. 알고리즘 성능 분석

알고리즘의 성능을 분석하는 것은 주어진 문제를 해결하는 데 얼마나 효율적인지를 평가하는 과정입니다. 주로 시간 복잡도와 공간 복잡도를 통해 평가합니다.

#### 1.3.1. 시간 복잡도 (Time Complexity)

알고리즘이 문제를 해결하는 데 걸리는 시간을 입력 크기(n)의 함수로 표현한 것입니다. 실제 실행 시간은 하드웨어, 프로그래밍 언어 등에 따라 달라지므로, 연산의 총 횟수를 추정하여 비교합니다.

##### 1.3.1.1. 빅-O 표기법 (Big-O Notation)

알고리즘의 시간 복잡도를 나타내는 가장 일반적인 방법으로, 입력 크기가 무한대로 커질 때 함수의 증가율을 나타냅니다. 최고차항만을 고려하며, 상수와 계수는 무시합니다.

*   **주요 빅-O 표기법:**
    *   `O(1)`: 상수 시간 (입력 크기에 관계없이 일정)
    *   `O(log n)`: 로그 시간 (입력 크기가 커질수록 효율이 급격히 좋아짐)
    *   `O(n)`: 선형 시간 (입력 크기에 비례)
    *   `O(n log n)`: 선형-로그 시간 (정렬 알고리즘에서 흔히 볼 수 있음)
    *   `O(n^2)`: 2차 시간 (입력 크기의 제곱에 비례)
    *   `O(2^n)`: 지수 시간 (입력 크기가 조금만 커져도 시간이 기하급수적으로 늘어남)
    *   `O(n!)`: 팩토리얼 시간 (매우 비효율적)

##### 1.3.1.2. 최선, 최악, 평균 케이스

알고리즘의 성능은 입력 데이터의 특성에 따라 달라질 수 있습니다.

*   **최선 케이스 (Best Case):** 알고리즘이 가장 빠르게 동작하는 경우.
*   **최악 케이스 (Worst Case):** 알고리즘이 가장 느리게 동작하는 경우. 코딩 테스트에서는 주로 최악 케이스를 기준으로 성능을 평가합니다.
*   **평균 케이스 (Average Case):** 모든 가능한 입력에 대한 평균적인 성능. 분석하기 가장 어렵지만, 실제 사용 환경을 가장 잘 반영합니다.

#### 1.3.2. 공간 복잡도 (Space Complexity)

알고리즘이 문제를 해결하는 데 필요한 메모리 공간의 양을 입력 크기(n)의 함수로 표현한 것입니다. 입력 데이터를 저장하는 공간과 알고리즘 실행 중 필요한 추가 공간을 모두 고려합니다.

#### 1.3.3. 상환 분석 (Amortized Analysis)

일련의 연산에 대한 평균적인 시간 복잡도를 분석하는 기법입니다. 특정 연산은 매우 비쌀 수 있지만, 전체 시퀀스에서 이러한 비싼 연산이 드물게 발생하여 평균 비용이 낮아지는 경우에 사용됩니다.

##### 1.3.3.1. 개념 및 필요성

*   **개념:** 단일 연산의 최악의 경우 비용이 아닌, 일련의 연산에 대한 평균 비용을 평가합니다.
*   **필요성:** 동적 배열의 크기 조정이나 해시 테이블의 충돌 해결과 같이, 가끔 발생하는 고비용 연산 때문에 전체 성능이 과소평가되는 것을 방지합니다.

##### 1.3.3.2. 활용 사례 (동적 배열, 해시 테이블)

*   **동적 배열 (Dynamic Array):** `append` 연산은 대부분 `O(1)`이지만, 배열이 가득 찼을 때 크기를 두 배로 늘리는 작업은 `O(n)`입니다. 하지만 이 `O(n)` 작업이 드물게 발생하므로, `n`번의 `append` 연산에 대한 상환 시간 복잡도는 `O(1)`이 됩니다.
*   **해시 테이블 (Hash Table):** `insert`, `delete`, `search` 연산은 평균적으로 `O(1)`이지만, 해시 충돌이 많아지거나 테이블 크기를 재조정(rehashing)하는 경우 `O(n)`이 될 수 있습니다. 하지만 상환 분석을 통해 평균 `O(1)` 성능을 보장합니다.

### 1.4. 파이썬 변수의 이해

파이썬은 다른 저수준 언어와는 다른 방식으로 변수를 다룹니다. 이를 이해하는 것은 파이썬으로 효율적인 알고리즘을 구현하는 데 중요합니다.

#### 1.4.1. C언어 변수와의 비교

*   **C언어:** 변수는 메모리 공간의 '이름'이며, 특정 데이터 타입에 맞는 크기의 메모리가 할당됩니다. 변수에 값을 할당하는 것은 해당 메모리 공간에 값을 '복사'하는 것입니다.
*   **파이썬:** 변수는 '객체'를 참조하는 이름표입니다. 값 자체가 변수에 저장되는 것이 아니라, 값이 저장된 메모리 주소를 가리킵니다. 데이터 타입은 객체에 속하며, 변수는 어떤 타입의 객체든 참조할 수 있습니다 (동적 타이핑).

#### 1.4.2. 파이썬의 객체 중심 데이터 표현

파이썬의 모든 데이터는 객체입니다. 숫자, 문자열, 리스트 등 모든 것이 객체로 존재하며, 변수는 이 객체들을 가리키는 참조(reference)입니다.

```python
a = 10       # 10이라는 int 객체를 생성하고 'a'가 이를 참조
b = a        # 'b'도 10이라는 같은 int 객체를 참조
c = 10       # 'c'도 10이라는 같은 int 객체를 참조 (파이썬은 작은 정수를 캐싱)

id(a) == id(b) # True
id(a) == id(c) # True

list1 = [1, 2, 3]
list2 = list1 # list2는 list1과 같은 리스트 객체를 참조

list2.append(4)
print(list1) # [1, 2, 3, 4] - list1도 변경됨
```

### 1.5. 알고리즘과 자료구조의 연결 이해

알고리즘과 자료구조는 서로 밀접하게 연결되어 있습니다. 특정 알고리즘의 효율성은 어떤 자료구조를 사용하느냐에 따라 크게 달라질 수 있으며, 반대로 특정 자료구조의 효율적인 활용은 적절한 알고리즘을 통해 가능해집니다.

*   **예시:**
    *   데이터 검색: 정렬된 배열에서는 이진 탐색(알고리즘)을 사용하여 `O(log n)` 시간에 검색할 수 있지만, 정렬되지 않은 배열에서는 선형 탐색(알고리즘)으로 `O(n)` 시간이 걸립니다.
    *   그래프 탐색: 너비 우선 탐색(BFS)은 큐(자료구조)를 사용하여 구현하고, 깊이 우선 탐색(DFS)은 스택(자료구조) 또는 재귀(알고리즘 기법)를 사용하여 구현합니다.

따라서 문제를 해결할 때는 문제의 특성을 파악하고, 가장 적합한 자료구조를 선택한 후, 그 자료구조를 효율적으로 활용할 수 있는 알고리즘을 설계하는 것이 중요합니다.
