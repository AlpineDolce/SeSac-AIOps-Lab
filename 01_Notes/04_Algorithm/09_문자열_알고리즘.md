### 8. 문자열 알고리즘

문자열 알고리즘은 텍스트 데이터에서 특정 패턴을 찾거나, 문자열을 효율적으로 처리하는 데 사용되는 알고리즘입니다.

#### 8.1. 문자열 매칭 (String Matching)

문자열 매칭은 긴 텍스트(Text) `T` 내에서 특정 패턴(Pattern) `P`가 나타나는 모든 시작 위치를 찾는 문제입니다. 이는 텍스트 편집기, 검색 엔진, 생물 정보학 등 다양한 분야에서 핵심적인 역할을 합니다.

##### 8.1.1. 나이브(Naive) 문자열 매칭

가장 간단한 문자열 매칭 알고리즘입니다. 텍스트의 모든 가능한 위치에서 패턴과 직접 비교합니다.

*   **동작 방식**: 텍스트의 첫 번째 문자부터 시작하여 패턴의 길이만큼 텍스트의 부분 문자열을 패턴과 비교합니다. 일치하지 않으면 텍스트에서 한 칸 옆으로 이동하여 다시 비교합니다.
*   **시간 복잡도**: 최악의 경우 `O((N-M+1)M)` 또는 `O(NM)` (N: 텍스트 길이, M: 패턴 길이). 예를 들어, "AAAAA"에서 "AAA"를 찾는 경우.
*   **장점**: 구현이 매우 간단합니다.
*   **단점**: 비효율적이며, 불필요한 비교가 많습니다.

##### 8.1.2. KMP (Knuth-Morris-Pratt) 알고리즘

KMP 알고리즘은 나이브 매칭의 비효율성을 개선한 알고리즘입니다. 패턴 자체의 구조(접두사와 접미사의 일치)를 이용하여 불필요한 비교를 건너뛰어 효율성을 높입니다.

*   **핵심 아이디어**: 패턴에서 불일치가 발생했을 때, 패턴을 단순히 한 칸 이동시키는 대신, 이미 비교했던 패턴의 부분 문자열 정보를 활용하여 패턴을 최대한 많이 이동시킵니다. 이를 위해 **부분 일치 테이블(Partial Match Table)** 또는 **LPS(Longest Proper Prefix which is also Suffix) 배열**을 미리 계산합니다.
    *   **LPS 배열**: `lps[i]`는 패턴의 `0`부터 `i`까지의 부분 문자열에서, 가장 긴 '진접두사(Proper Prefix)'가 '진접미사(Proper Suffix)'와 일치하는 길이입니다.
*   **동작 방식**:
    1.  **전처리 단계**: 패턴 `P`에 대한 LPS 배열을 `O(M)` 시간에 계산합니다.
    2.  **매칭 단계**: 텍스트 `T`와 패턴 `P`를 비교합니다. 불일치가 발생하면, LPS 배열을 참조하여 패턴을 이동시킵니다. `j`가 불일치가 발생한 패턴의 인덱스라면, 패턴을 `j - lps[j-1]`만큼 이동시킵니다.
*   **시간 복잡도**: `O(N + M)` (전처리 `O(M)`, 매칭 `O(N)`)
*   **공간 복잡도**: `O(M)` (LPS 배열 저장용)
*   **장점**: 최악의 경우에도 선형 시간 복잡도를 보장합니다.
*   **단점**: LPS 배열을 계산하는 전처리 과정이 필요합니다.

```python
def compute_lps_array(pattern):
    """KMP 알고리즘을 위한 LPS(Longest Proper Prefix which is also Suffix) 배열 계산"""
    M = len(pattern)
    lps = [0] * M
    length = 0 # 현재까지 일치하는 접두사-접미사의 길이
    i = 1

    while i < M:
        if pattern[i] == pattern[length]:
            length += 1
            lps[i] = length
            i += 1
        else:
            if length != 0:
                length = lps[length - 1]
            else:
                lps[i] = 0
                i += 1
    return lps

def kmp_search(text, pattern):
    """KMP 문자열 매칭 알고리즘"""
    N = len(text)
    M = len(pattern)
    lps = compute_lps_array(pattern) # LPS 배열 전처리

    i = 0 # 텍스트 인덱스
    j = 0 # 패턴 인덱스
    occurrences = [] # 패턴이 발견된 시작 인덱스 리스트

    while i < N:
        if pattern[j] == text[i]:
            i += 1
            j += 1

        if j == M: # 패턴을 찾았을 경우
            occurrences.append(i - j)
            j = lps[j - 1] # 다음 탐색을 위해 패턴 인덱스 조정
        elif i < N and pattern[j] != text[i]: # 불일치 발생
            if j != 0:
                j = lps[j - 1]
            else:
                i += 1 # 패턴의 첫 문자와도 불일치하면 텍스트 인덱스만 이동
    return occurrences

text_kmp = "ABABDABACDABABCABAB"
pattern_kmp = "ABABCABAB"
print(f"KMP 검색 결과 (텍스트: {text_kmp}, 패턴: {pattern_kmp}): {kmp_search(text_kmp, pattern_kmp)}")
# 예상 출력: [10]
print("\n")
```

##### 8.1.3. 라빈-카프 (Rabin-Karp) 알고리즘

라빈-카프 알고리즘은 해싱(Hashing)을 이용하여 문자열을 비교하는 알고리즘입니다. 텍스트의 부분 문자열과 패턴의 해시 값을 비교하여 일치 여부를 빠르게 확인합니다.

*   **핵심 아이디어**: 텍스트의 각 `M` 길이 부분 문자열의 해시 값을 계산하고, 이 해시 값을 패턴의 해시 값과 비교합니다. 해시 값이 일치하면 실제 문자열 비교를 수행하여 **해시 충돌(Hash Collision)**을 확인합니다. **롤링 해시(Rolling Hash)** 기법을 사용하여 텍스트의 다음 부분 문자열의 해시 값을 `O(1)` 시간에 효율적으로 계산합니다.
*   **동작 방식**:
    1.  **전처리 단계**: 패턴 `P`의 해시 값을 계산합니다. 텍스트 `T`의 첫 `M` 길이 부분 문자열의 해시 값을 계산합니다.
    2.  **매칭 단계**: 텍스트의 현재 부분 문자열 해시 값과 패턴의 해시 값을 비교합니다.
        *   해시 값이 일치하면, 실제 문자열 비교를 수행하여 오탐(false positive)을 제거합니다.
        *   해시 값이 일치하지 않으면, 텍스트의 다음 부분 문자열의 해시 값을 롤링 해시를 이용하여 `O(1)` 시간에 계산하고 다음 비교로 넘어갑니다.
*   **시간 복잡도**:
    *   평균적으로 `O(N + M)` (해시 충돌이 적을 경우)
    *   최악의 경우 `O(NM)` (해시 충돌이 빈번하게 발생할 경우, 예를 들어 모든 해시 값이 동일한 경우)
*   **공간 복잡도**: `O(1)` (해시 값만 저장)
*   **장점**:
    *   다중 패턴 매칭에 효율적입니다.
    *   평균적으로 빠른 성능을 보입니다.
*   **단점**:
    *   해시 충돌 가능성이 있으며, 최악의 경우 성능이 저하될 수 있습니다.
    *   적절한 해시 함수와 소수(prime number) 선택이 중요합니다.

```python
def rabin_karp_search(text, pattern, q=101): # q는 큰 소수
    """라빈-카프 문자열 매칭 알고리즘"""
    N = len(text)
    M = len(pattern)
    d = 256 # 아스키 문자 개수 (알파벳 크기)
    
    p_hash = 0 # 패턴의 해시 값
    t_hash = 0 # 텍스트 부분 문자열의 해시 값
    h = 1 # d^(M-1) % q

    # h = d^(M-1) % q 계산
    for i in range(M - 1):
        h = (h * d) % q

    # 패턴과 텍스트 첫 M 길이 부분 문자열의 해시 값 계산
    for i in range(M):
        p_hash = (d * p_hash + ord(pattern[i])) % q
        t_hash = (d * t_hash + ord(text[i])) % q

    occurrences = []

    # 텍스트를 슬라이딩 윈도우 방식으로 탐색
    for i in range(N - M + 1):
        if p_hash == t_hash: # 해시 값이 일치하면
            # 실제 문자열 비교 (해시 충돌 확인)
            if text[i:i+M] == pattern:
                occurrences.append(i)

        # 마지막 윈도우가 아니면 다음 윈도우의 해시 값 계산 (롤링 해시)
        if i < N - M:
            t_hash = (d * (t_hash - ord(text[i]) * h) + ord(text[i + M])) % q
            # 음수 해시 값 방지
            if t_hash < 0:
                t_hash += q
    return occurrences

text_rk = "GEEKSFORGEEKS"
pattern_rk = "GEEK"
print(f"라빈-카프 검색 결과 (텍스트: {text_rk}, 패턴: {pattern_rk}): {rabin_karp_search(text_rk, pattern_rk)}")
# 예상 출력: [0, 9]
print("\n")
```

##### 8.1.4. 보이어-무어 (Boyer-Moore) 알고리즘

보이어-무어 알고리즘은 실제 텍스트 검색에서 매우 효율적인 성능을 보이는 문자열 매칭 알고리즘입니다. 패턴의 끝에서부터 텍스트와 비교를 시작하며, 불일치가 발생했을 때 패턴을 크게 건너뛸 수 있는 규칙을 사용합니다.

*   **핵심 아이디어**: 
    1.  **나쁜 문자 규칙 (Bad Character Rule)**: 텍스트에서 불일치가 발생한 문자를 패턴 내에서 찾아, 패턴을 이동시켜 해당 문자가 일치하도록 합니다.
    2.  **좋은 접미사 규칙 (Good Suffix Rule)**: 패턴의 접미사가 텍스트와 일치했지만, 그 앞의 문자가 불일치했을 때, 패턴 내에서 해당 접미사와 일치하는 다른 위치를 찾아 패턴을 이동시킵니다.
*   **시간 복잡도**:
    *   최악의 경우 `O(NM)`
    *   평균적으로 `O(N/M)` 또는 `O(N)`에 가까운 매우 빠른 성능을 보입니다.
*   **장점**: 실제 응용에서 가장 빠른 문자열 매칭 알고리즘 중 하나입니다.
*   **단점**: 구현이 복잡합니다.

#### 8.2. 접미사 배열 (Suffix Array) 및 LCP 배열

접미사 배열(Suffix Array)과 LCP 배열(Longest Common Prefix Array)은 문자열 처리 및 생물 정보학 분야에서 매우 강력한 도구로 사용되는 자료구조입니다. 이들은 문자열 내의 패턴을 효율적으로 찾고, 반복되는 부분 문자열을 분석하는 데 핵심적인 역할을 합니다.

##### 8.2.1. 접미사 배열 (Suffix Array)

*   **개념**: 문자열 `S`의 모든 접미사(Suffix)를 사전순(lexicographical order)으로 정렬한 후, 각 접미사의 시작 인덱스를 저장한 배열입니다. 문자열 `S`의 길이가 `N`이라면, `N`개의 접미사가 존재하며, 접미사 배열 `SA`는 `N`개의 정수로 구성됩니다.
    *   예를 들어, 문자열 "banana"의 접미사는 "banana", "anana", "nana", "ana", "na", "a" 입니다.
    *   이들을 사전순으로 정렬하면 "a", "ana", "anana", "banana", "na", "nana"가 됩니다.
    *   각 접미사의 원래 시작 인덱스를 저장하면 접미사 배열이 됩니다. (0-indexed)
        *   "a" (인덱스 5)
        *   "ana" (인덱스 3)
        *   "anana" (인덱스 1)
        *   "banana" (인덱스 0)
        *   "na" (인덱스 4)
        *   "nana" (인덱스 2)
        *   따라서 `SA = [5, 3, 1, 0, 4, 2]`
*   **구축 알고리즘**:
    *   **나이브(Naive) 방법**: 모든 접미사를 추출하여 정렬하는 방식으로, `O(N^2 log N)`의 시간이 소요됩니다.
    *   **더블링(Doubling) 알고리즘**: 접미사의 길이를 2배씩 늘려가며 정렬하는 방식으로, `O(N log^2 N)` 또는 `O(N log N)`의 시간이 소요됩니다.
    *   **선형 시간 알고리즘**: SA-IS(Suffix Array - Induced Sorting)와 같은 알고리즘은 `O(N)`의 선형 시간에 접미사 배열을 구축할 수 있습니다.
*   **활용**:
    *   **문자열 검색 (패턴 매칭)**: 접미사 배열을 이진 탐색하여 패턴이 텍스트 내에 존재하는지, 존재한다면 어디에 존재하는지 `O(M log N)` 시간에 찾을 수 있습니다.
    *   **최장 반복 부분 문자열 (Longest Repeated Substring)**: LCP 배열과 함께 사용하여 찾을 수 있습니다.
    *   **최장 공통 부분 문자열 (Longest Common Substring, LCS)**: 두 개 이상의 문자열의 LCS를 찾는 데 활용됩니다.

##### 8.2.2. LCP 배열 (Longest Common Prefix Array)

*   **개념**: LCP 배열은 접미사 배열과 함께 사용되는 보조 배열입니다. `LCP[i]`는 접미사 배열 `SA[i-1]`가 가리키는 접미사와 `SA[i]`가 가리키는 접미사 간의 **최장 공통 접두사(Longest Common Prefix)**의 길이를 저장합니다. `LCP[0]`은 정의되지 않거나 0으로 설정됩니다.
    *   위 "banana" 예시에서 `SA = [5, 3, 1, 0, 4, 2]`
        *   `SA[0]` = "a" (인덱스 5)
        *   `SA[1]` = "ana" (인덱스 3)
        *   `LCP[1]` = LCP("a", "ana") = 1 ("a")
        *   `SA[1]` = "ana" (인덱스 3)
        *   `SA[2]` = "anana" (인덱스 1)
        *   `LCP[2]` = LCP("ana", "anana") = 3 ("ana")
        *   ...
        *   따라서 `LCP = [0, 1, 3, 0, 0, 2]` (예시)
*   **구축 알고리즘**: 접미사 배열이 주어진 경우, Kasai의 알고리즘을 사용하여 `O(N)`의 선형 시간에 LCP 배열을 구축할 수 있습니다.
*   **활용**:
    *   **최장 반복 부분 문자열**: LCP 배열의 최댓값이 최장 반복 부분 문자열의 길이가 됩니다.
    *   **최장 공통 부분 문자열**: 두 문자열을 합친 후 접미사 배열과 LCP 배열을 구축하여 찾을 수 있습니다.
    *   **문자열 압축**: 반복되는 패턴을 식별하여 압축 효율을 높이는 데 기여합니다.
    *   **문자열 통계**: 문자열 내의 다양한 패턴의 빈도수 등을 분석합니다.

##### 8.2.3. 접미사 배열과 LCP 배열의 관계 및 활용

접미사 배열과 LCP 배열은 함께 사용될 때 그 진가를 발휘합니다. LCP 배열은 접미사 배열에서 인접한 접미사들 간의 유사성 정보를 제공하여, 문자열 내의 반복 패턴이나 공통 부분 문자열을 효율적으로 찾을 수 있게 합니다.

*   **접미사 트리(Suffix Tree)와의 관계**: 접미사 트리는 문자열의 모든 접미사를 트리에 저장하는 자료구조로, 접미사 배열과 LCP 배열이 제공하는 대부분의 기능을 수행할 수 있습니다. 하지만 접미사 트리는 구현이 복잡하고 메모리 사용량이 많을 수 있습니다. 접미사 배열과 LCP 배열은 접미사 트리에 비해 공간 효율적이며, 많은 경우 접미사 트리를 대체할 수 있습니다.

#### 8.3. 문자열 압축 (예: Huffman Coding)

문자열 압축은 데이터의 크기를 줄여 저장 공간을 절약하고 전송 시간을 단축하기 위한 기법입니다. 이는 데이터의 중복성(redundancy)을 제거하거나 효율적으로 인코딩함으로써 달성됩니다. 압축 방식은 크게 **무손실 압축(Lossless Compression)**과 **손실 압축(Lossy Compression)**으로 나눌 수 있으며, 문자열 압축은 주로 원본 데이터를 완벽하게 복원할 수 있는 무손실 압축에 해당합니다.

##### 8.3.1. 허프만 코딩 (Huffman Coding)

허프만 코딩은 데이터에 나타나는 문자의 빈도수를 기반으로 가변 길이 코드를 할당하는 **통계적 무손실 압축 알고리즘**입니다. 빈도수가 높은 문자에는 짧은 코드를, 빈도수가 낮은 문자에는 긴 코드를 할당하여 전체 데이터의 평균 코드 길이를 최소화합니다.

*   **핵심 아이디어**: 가장 빈번하게 나타나는 문자에 가장 짧은 코드를 부여하고, 가장 적게 나타나는 문자에 가장 긴 코드를 부여하는 **탐욕(Greedy) 알고리즘**입니다. 이를 위해 이진 트리를 구성합니다.
*   **알고리즘 단계**:
    1.  **빈도수 계산**: 입력 문자열에 나타나는 각 문자의 빈도수를 계산합니다.
    2.  **리프 노드 생성**: 각 문자를 하나의 리프 노드로 만들고, 해당 문자의 빈도수를 노드의 가중치로 설정합니다. 이 노드들을 **최소 힙(Min-Priority Queue)**에 삽입합니다.
    3.  **트리 구축**:
        *   힙에서 가중치가 가장 작은 두 개의 노드를 추출합니다.
        *   이 두 노드를 자식으로 하는 새로운 내부 노드를 생성합니다. 새로운 내부 노드의 가중치는 두 자식 노드의 가중치 합으로 설정합니다.
        *   새로운 내부 노드를 다시 힙에 삽입합니다.
        *   힙에 하나의 노드(루트 노드)만 남을 때까지 이 과정을 반복합니다.
    4.  **코드 할당**: 구축된 허프만 트리에서 루트부터 리프 노드까지 순회하면서 코드를 할당합니다. 일반적으로 왼쪽 자식으로 이동할 때는 '0', 오른쪽 자식으로 이동할 때는 '1'을 부여합니다. 이렇게 생성된 코드는 **접두사 코드(Prefix Code)** 속성을 가집니다. (어떤 문자의 코드도 다른 문자의 코드의 접두사가 되지 않습니다.)
*   **특징**:
    *   **최적성**: 문자 단위 인코딩에서는 이론적으로 가장 효율적인 압축 방법 중 하나입니다.
    *   **가변 길이 코드**: 문자마다 길이가 다른 코드를 사용합니다.
    *   **무손실 압축**: 원본 데이터를 완벽하게 복원할 수 있습니다.
*   **시간 복잡도**: `O(N log N)` (N은 고유 문자의 개수). 힙 연산에 의해 결정됩니다.
*   **공간 복잡도**: `O(N)` (허프만 트리 및 코드 저장용).

```python
import heapq
from collections import Counter

class HuffmanNode:
    def __init__(self, char, freq):
        self.char = char
        self.freq = freq
        self.left = None
        self.right = None

    # 우선순위 큐에서 비교를 위한 메서드
    def __lt__(self, other):
        return self.freq < other.freq

def build_huffman_tree(text):
    """텍스트로부터 허프만 트리를 구축합니다."""
    frequency = Counter(text) # 각 문자의 빈도수 계산
    priority_queue = []

    # 각 문자를 리프 노드로 만들어 우선순위 큐에 삽입
    for char, freq in frequency.items():
        heapq.heappush(priority_queue, HuffmanNode(char, freq))

    # 힙에 하나의 노드만 남을 때까지 트리 구축
    while len(priority_queue) > 1:
        node1 = heapq.heappop(priority_queue)
        node2 = heapq.heappop(priority_queue)

        # 두 노드를 합쳐 새로운 내부 노드 생성
        merged_node = HuffmanNode(None, node1.freq + node2.freq)
        merged_node.left = node1
        merged_node.right = node2
        heapq.heappush(priority_queue, merged_node)

    return priority_queue[0] # 루트 노드 반환

def generate_huffman_codes(node, current_code, codes):
    """허프만 트리로부터 각 문자의 코드를 생성합니다."""
    if node is None:
        return

    if node.char is not None: # 리프 노드인 경우 (문자를 가짐)
        codes[node.char] = current_code
        return

    # 왼쪽 자식으로 이동 (0 추가)
    generate_huffman_codes(node.left, current_code + "0", codes)
    # 오른쪽 자식으로 이동 (1 추가)
    generate_huffman_codes(node.right, current_code + "1", codes)

def huffman_encode(text):
    """허프만 코딩을 사용하여 텍스트를 인코딩합니다."""
    if not text:
        return "", {}

    root = build_huffman_tree(text)
    codes = {}
    generate_huffman_codes(root, "", codes)

    encoded_text = "".join(codes[char] for char in text)
    return encoded_text, codes

def huffman_decode(encoded_text, codes):
    """허프만 코딩된 텍스트를 디코딩합니다."""
    if not encoded_text:
        return ""

    # 코드 딕셔너리를 역으로 (코드 -> 문자) 변환
    reverse_codes = {code: char for char, code in codes.items()}
    
    decoded_text = []
    current_code = ""
    for bit in encoded_text:
        current_code += bit
        if current_code in reverse_codes:
            decoded_text.append(reverse_codes[current_code])
            current_code = "" # 코드 매칭 후 초기화
    return "".join(decoded_text)

text_huffman = "this is an example for huffman encoding"
encoded_text, codes = huffman_encode(text_huffman)
print(f"원본 텍스트: {text_huffman}")
print(f"인코딩된 텍스트: {encoded_text}")
print(f"허프만 코드: {codes}")
decoded_text = huffman_decode(encoded_text, codes)
print(f"디코딩된 텍스트: {decoded_text}")
print("\n")
```

##### 8.3.2. 다른 문자열 압축 알고리즘

*   **런 길이 인코딩 (Run-Length Encoding, RLE)**: 동일한 문자가 연속해서 나타나는 경우, 해당 문자와 반복 횟수로 대체하여 압축하는 간단한 방법입니다. (예: "AAABBC" -> "A3B2C1") 이미지 압축 등에 사용됩니다.
*   **LZ77 및 LZ78 (Lempel-Ziv family)**: **사전 기반 압축(Dictionary-based Compression)** 알고리즘의 기초가 됩니다. 이미 나타난 문자열 패턴을 사전(dictionary)에 저장하고, 반복되는 패턴을 사전의 인덱스로 대체하여 압축합니다.
    *   **LZW (Lempel-Ziv-Welch)**: LZ78의 변형으로, GIF, TIFF, PDF 파일 형식 등에서 널리 사용됩니다.
*   **산술 코딩 (Arithmetic Coding)**: 허프만 코딩보다 더 높은 압축률을 제공할 수 있는 통계적 압축 방법입니다. 전체 메시지를 하나의 소수(fraction)로 인코딩합니다. 구현이 복잡합니다.

##### 8.3.3. 문자열 압축의 활용

*   **파일 압축**: ZIP, GZIP, RAR 등 다양한 파일 압축 형식의 핵심 기술입니다.
*   **데이터 전송**: 네트워크를 통해 데이터를 전송할 때 대역폭을 절약하기 위해 사용됩니다.
*   **데이터베이스**: 저장 공간을 효율적으로 사용하기 위해 데이터베이스 내의 텍스트 데이터를 압축합니다.
*   **멀티미디어**: 이미지(JPEG, PNG), 오디오(MP3), 비디오(MPEG) 등 멀티미디어 데이터 압축에 활용됩니다.
