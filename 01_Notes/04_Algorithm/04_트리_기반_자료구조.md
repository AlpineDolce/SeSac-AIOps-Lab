## 3. 비선형 자료구조 및 정렬/탐색 알고리즘

비선형 자료구조는 데이터를 계층적 또는 네트워크 형태로 저장하여, 복잡한 관계를 표현하고 효율적인 탐색 및 관리를 가능하게 합니다.

### 3.1. 트리 (Tree)

트리는 계층적인 관계를 표현하는 데 사용되는 비선형 자료구조입니다. 부모-자식 관계를 가지는 노드들로 구성되며, 사이클이 없는 연결 그래프의 한 종류입니다.

#### 3.1.1. 트리의 개념과 기본 용어

*   **노드 (Node):** 트리를 구성하는 기본 요소.
*   **루트 노드 (Root Node):** 트리의 가장 상위에 있는 노드 (부모가 없음).
*   **부모 노드 (Parent Node):** 특정 노드의 상위 노드.
*   **자식 노드 (Child Node):** 특정 노드의 하위 노드.
*   **형제 노드 (Sibling Node):** 같은 부모를 가지는 노드들.
*   **리프 노드 (Leaf Node):** 자식이 없는 노드 (단말 노드).
*   **간선 (Edge):** 노드들을 연결하는 선.
*   **경로 (Path):** 한 노드에서 다른 노드까지의 간선들의 순서.
*   **깊이 (Depth):** 루트 노드로부터 특정 노드까지의 간선 수.
*   **높이 (Height):** 특정 노드로부터 리프 노드까지의 가장 긴 경로의 간선 수.
*   **차수 (Degree):** 노드가 가지는 자식 노드의 수.

#### 3.1.2. 이진 트리 (Binary Tree)

이진 트리는 모든 노드가 최대 두 개의 자식 노드(왼쪽 자식, 오른쪽 자식)를 가지는 트리입니다.

*   **종류:**
    *   **정 이진 트리 (Full Binary Tree):** 모든 노드가 0개 또는 2개의 자식 노드를 가집니다.
    *   **완전 이진 트리 (Complete Binary Tree):** 마지막 레벨을 제외한 모든 레벨이 완전히 채워져 있고, 마지막 레벨은 왼쪽부터 채워져 있습니다. 배열로 효율적인 표현이 가능합니다.
    *   **포화 이진 트리 (Perfect Binary Tree):** 모든 내부 노드가 두 개의 자식을 가지고, 모든 리프 노드가 같은 깊이에 있습니다.

#### 3.1.3. 이진 탐색 트리 (Binary Search Tree, BST)

이진 탐색 트리는 이진 트리의 일종으로, 효율적인 탐색, 삽입, 삭제를 위해 특정 규칙을 따릅니다.

*   **BST의 특징:**
    *   모든 노드의 왼쪽 서브트리에는 해당 노드의 값보다 작은 값만 있습니다.
    *   모든 노드의 오른쪽 서브트리에는 해당 노드의 값보다 큰 값만 있습니다.
    *   중복된 값은 허용되지 않거나, 특정 규칙에 따라 처리됩니다.

##### 3.1.3.1. BST의 특징과 연산 (삽입, 삭제, 탐색)

*   **탐색 (Search):** 루트부터 시작하여 값을 비교하며 왼쪽 또는 오른쪽 서브트리로 이동합니다. 평균 `O(log n)`, 최악 `O(n)`.
*   **삽입 (Insertion):** 탐색과 유사하게 적절한 위치를 찾아 새 노드를 추가합니다. 평균 `O(log n)`, 최악 `O(n)`.
*   **삭제 (Deletion):** 노드를 삭제할 때 트리의 구조를 유지하는 것이 중요합니다. 삭제할 노드의 자식 수에 따라 처리 방식이 달라집니다.

##### 3.1.3.2. 파이썬 구현

```python
class BSTNode:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

class BinarySearchTree:
    def __init__(self):
        self.root = None

    def insert(self, key):
        if self.root is None:
            self.root = BSTNode(key)
        else:
            self._insert_recursive(self.root, key)

    def _insert_recursive(self, node, key):
        if key < node.key:
            if node.left is None:
                node.left = BSTNode(key)
            else:
                self._insert_recursive(node.left, key)
        elif key > node.key:
            if node.right is None:
                node.right = BSTNode(key)
            else:
                self._insert_recursive(node.right, key)
        # else: key already exists, do nothing or handle duplicates

    def search(self, key):
        return self._search_recursive(self.root, key)

    def _search_recursive(self, node, key):
        if node is None or node.key == key:
            return node
        if key < node.key:
            return self._search_recursive(node.left, key)
        return self._search_recursive(node.right, key)

    def inorder_traversal(self):
        # 중위 순회 (정렬된 순서로 노드 방문)
        result = []
        self._inorder_recursive(self.root, result)
        return result

    def _inorder_recursive(self, node, result):
        if node:
            self._inorder_recursive(node.left, result)
            result.append(node.key)
            self._inorder_recursive(node.right, result)

# 예시

# bst.insert(40)

# print(bst.search(40).key) # 40

```

##### 3.1.3.3. 트리와 이진 탐색 트리 비교

| 특징 | 일반 트리 | 이진 트리 | 이진 탐색 트리 (BST) |
| :--- | :--- | :--- | :--- |
| 자식 수 | 제한 없음 | 최대 2개 | 최대 2개 |
| 노드 값 순서 | 없음 | 없음 | 왼쪽 < 부모 < 오른쪽 |
| 탐색 효율 | `O(n)` (일반적으로) | `O(n)` (일반적으로) | 평균 `O(log n)` |
| 활용 | 파일 시스템, 조직도 | 힙, 표현식 트리 | 데이터 검색, 정렬 |

#### 3.1.4. B-트리 (B-Tree) 및 B+트리 (B+Tree)

B-트리와 B+트리는 대용량 데이터를 디스크에 저장하고 관리하는 데 최적화된 균형 탐색 트리입니다. 데이터베이스 인덱스 및 파일 시스템에서 널리 사용됩니다.

##### 3.1.4.1. B-트리의 개념과 특징 (디스크 기반 자료구조)

*   **개념:** 모든 리프 노드가 같은 레벨에 있도록 자동으로 균형을 맞추는 자가 균형(Self-balancing) 탐색 트리입니다. 각 노드는 여러 개의 키와 자식을 가질 수 있습니다.
*   **특징:**
    *   **다차원 노드:** 하나의 노드에 여러 개의 키와 자식 포인터를 저장하여 디스크 I/O를 최소화합니다.
    *   **균형 유지:** 삽입 및 삭제 시 트리의 높이를 낮게 유지하여 모든 연산이 `O(log n)` 시간을 보장합니다.
    *   **내부 노드에 데이터 저장:** 키와 함께 실제 데이터 또는 데이터에 대한 포인터를 저장할 수 있습니다.

##### 3.1.4.2. B+트리의 개념과 특징 (데이터베이스 인덱스)

*   **개념:** B-트리의 변형으로, 모든 데이터는 리프 노드에만 저장되고, 리프 노드들은 서로 연결되어 있습니다. 내부 노드는 오직 키와 자식 포인터만을 가집니다.
*   **특징:**
    *   **리프 노드에만 데이터 저장:** 모든 데이터가 리프 노드에만 존재하므로, 범위 검색(Range Query)에 매우 효율적입니다.
    *   **리프 노드 연결:** 리프 노드들이 링크드 리스트처럼 연결되어 있어 순차적인 데이터 접근이 빠릅니다.
    *   **데이터베이스 인덱스:** 대부분의 관계형 데이터베이스 시스템에서 인덱스 구조로 B+트리를 사용합니다.

##### 3.1.4.3. B-트리/B+트리 활용 사례 (파일 시스템, 데이터베이스)

*   **파일 시스템:** 대용량 파일 시스템(예: NTFS, HFS+)에서 파일 및 디렉토리 구조를 관리하는 데 사용됩니다.
*   **데이터베이스 인덱스:** MySQL의 InnoDB, PostgreSQL 등 대부분의 관계형 데이터베이스에서 테이블의 인덱스를 구현하는 데 사용되어 빠른 데이터 검색을 가능하게 합니다.

### 3.2. 트리 순회 (Tree Traversal)

트리 순회는 트리의 모든 노드를 방문하는 체계적인 방법입니다. 순회 방식에 따라 노드를 방문하는 순서가 달라지며, 이는 문제 해결에 중요한 영향을 미칩니다.

#### 3.2.1. 순회 종류와 특징 (전위, 중위, 후위, 레벨 순회)

*   **전위 순회 (Preorder Traversal):** 루트 -> 왼쪽 서브트리 -> 오른쪽 서브트리
    *   활용: 트리를 복사하거나, 표현식 트리를 전위 표기법으로 변환할 때.
*   **중위 순회 (Inorder Traversal):** 왼쪽 서브트리 -> 루트 -> 오른쪽 서브트리
    *   활용: 이진 탐색 트리를 중위 순회하면 정렬된 순서로 노드를 얻을 수 있습니다.
*   **후위 순회 (Postorder Traversal):** 왼쪽 서브트리 -> 오른쪽 서브트리 -> 루트
    *   활용: 트리를 삭제하거나, 표현식 트리를 후위 표기법으로 변환할 때.
*   **레벨 순회 (Level Order Traversal):** 레벨별로 노드를 방문 (BFS와 유사, 큐 사용).
    *   활용: 트리의 높이 계산, 최단 경로 탐색.

#### 3.2.2. 재귀적 순회 구현

트리 순회는 재귀적으로 구현하는 것이 가장 직관적이고 간결합니다.

```python
# BSTNode 클래스 사용

def preorder_recursive(node, result):
    if node:
        result.append(node.key)
        preorder_recursive(node.left, result)
        preorder_recursive(node.right, result)

def inorder_recursive(node, result):
    if node:
        inorder_recursive(node.left, result)
        result.append(node.key)
        inorder_recursive(node.right, result)

def postorder_recursive(node, result):
    if node:
        postorder_recursive(node.left, result)
        postorder_recursive(node.right, result)
        result.append(node.key)
```

#### 3.2.3. 반복적 순회 구현 (스택/큐 활용)

재귀는 내부적으로 스택을 사용하므로, 명시적인 스택이나 큐를 사용하여 반복적으로 순회를 구현할 수도 있습니다.

*   **전위 순회 (스택):**
    ```python
def preorder_iterative(root):
    if not root: return []
    result = []
    stack = [root]
    while stack:
        node = stack.pop()
        result.append(node.key)
        if node.right: stack.append(node.right)
        if node.left: stack.append(node.left)
    return result
    ```
*   **레벨 순회 (큐):**
    ```python
from collections import deque

def levelorder_iterative(root):
    if not root: return []
    result = []
    queue = deque([root])
    while queue:
        node = queue.popleft()
        result.append(node.key)
        if node.left: queue.append(node.left)
        if node.right: queue.append(node.right)
    return result
    ```

#### 3.2.4. 이진 트리의 배열 표현

완전 이진 트리의 경우, 배열을 사용하여 효율적으로 표현할 수 있습니다. 이는 힙(Heap) 구현에 주로 사용됩니다.

*   **인덱스 계산:**
    *   루트 노드: 인덱스 0 또는 1
    *   부모 노드 `i`의 왼쪽 자식: `2 * i + 1` (0-based) 또는 `2 * i` (1-based)
    *   부모 노드 `i`의 오른쪽 자식: `2 * i + 2` (0-based) 또는 `2 * i + 1` (1-based)
    *   자식 노드 `j`의 부모: `(j - 1) // 2` (0-based) 또는 `j // 2` (1-based)

#### 3.2.5. 수식 트리와 순회 (전위, 중위, 후위 표기법)

수식 트리는 연산자와 피연산자로 구성된 이진 트리로, 수식을 표현하는 데 사용됩니다. 순회 방식에 따라 수식의 표기법이 달라집니다.

*   **전위 표기법 (Prefix Notation):** 연산자 -> 피연산자1 -> 피연산자2 (예: `+ A B`)
*   **중위 표기법 (Infix Notation):** 피연산자1 -> 연산자 -> 피연산자2 (예: `A + B`)
*   **후위 표기법 (Postfix Notation):** 피연산자1 -> 피연산자2 -> 연산자 (예: `A B +`)

### 3.3. 균형 이진 탐색 트리 (Balanced Binary Search Tree)

이진 탐색 트리는 데이터가 편향되게 삽입될 경우 트리의 높이가 `O(n)`이 되어 탐색, 삽입, 삭제 성능이 `O(n)`으로 저하될 수 있습니다. 균형 이진 탐색 트리는 이러한 문제를 해결하기 위해 트리의 높이를 `O(log n)`으로 유지하는 자가 균형(Self-balancing) 트리입니다.

#### 3.3.1. 균형 이진 탐색 트리의 필요성

*   최악의 경우 `O(n)` 성능을 `O(log n)`으로 보장하여 안정적인 성능을 제공합니다.
*   대용량 데이터 처리 및 실시간 시스템에서 필수적입니다.

#### 3.3.2. AVL 트리 (AVL Tree)

*   **개념:** 모든 노드의 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 1 이하인 이진 탐색 트리입니다.
*   **균형 인수 (Balance Factor):** `왼쪽 서브트리 높이 - 오른쪽 서브트리 높이` (값은 -1, 0, 1 중 하나).
*   **재균형:** 삽입 및 삭제 후 균형 인수가 1을 초과하면 회전(Rotation) 연산을 통해 트리를 재균형합니다.

#### 3.3.3. 레드-블랙 트리 (Red-Black Tree)

*   **개념:** 노드를 빨간색 또는 검은색으로 색칠하여 균형을 유지하는 이진 탐색 트리입니다. AVL 트리보다 덜 엄격하게 균형을 유지하지만, 삽입/삭제 시 회전 횟수가 적어 실제 성능이 더 좋을 수 있습니다.
*   **규칙:**
    1.  모든 노드는 빨간색 또는 검은색입니다.
    2.  루트 노드는 검은색입니다.
    3.  모든 리프 노드(NIL 노드)는 검은색입니다.
    4.  빨간색 노드의 자식은 모두 검은색입니다. (빨간색 노드가 연속될 수 없음)
    5.  어떤 노드로부터 그 노드의 자손 리프 노드까지의 모든 경로에는 같은 수의 검은색 노드가 있습니다.

#### 3.3.4. 활용 사례 (맵, 셋 구현)

*   **맵 (Map) 및 셋 (Set) 구현:** C++의 `std::map`, `std::set`이나 Java의 `TreeMap`, `TreeSet` 등 많은 표준 라이브러리에서 균형 이진 탐색 트리를 사용하여 정렬된 키-값 쌍 또는 고유한 요소 집합을 효율적으로 관리합니다.
*   **데이터베이스 인덱스:** B-트리/B+트리와 함께 데이터베이스 인덱스 구현에 사용됩니다.
