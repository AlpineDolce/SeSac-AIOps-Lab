### 4.1. 재귀 (Recursion)

재귀는 함수가 자기 자신을 호출하여 문제를 해결하는 프로그래밍 기법입니다. 복잡한 문제를 더 작고 동일한 형태로 분할하여 해결할 때 유용합니다.

#### 4.1.1. 재귀의 기본 원리 (기저 조건, 재귀 호출)

*   **기저 조건 (Base Case):** 재귀 호출을 멈추는 조건입니다. 이 조건이 없으면 무한 루프에 빠집니다.
*   **재귀 호출 (Recursive Call):** 함수가 자기 자신을 호출하는 부분입니다. 이때 문제의 크기가 점진적으로 줄어들어야 합니다.

```python
def factorial(n):
    if n == 0:  # 기저 조건
        return 1
    else:
        return n * factorial(n - 1) # 재귀 호출

# print(factorial(5)) # 120
```

#### 4.1.2. 재귀와 스택 (Call Stack)

재귀 함수가 호출될 때마다 해당 함수의 실행 정보(매개변수, 지역 변수, 반환 주소 등)가 '호출 스택(Call Stack)'에 쌓입니다. 기저 조건에 도달하여 함수가 반환되면 스택에서 정보가 제거됩니다.

*   **스택 오버플로우 (Stack Overflow):** 재귀 호출이 너무 깊어지면 호출 스택의 메모리 한계를 초과하여 발생하는 오류입니다.

#### 4.1.3. 재귀 vs 반복 (장단점 비교)

| 특징 | 재귀 (Recursion) | 반복 (Iteration) |
| :--- | :--- | :--- |
| 가독성 | 특정 문제(예: 트리 순회)에서 더 직관적이고 간결 | 일반적으로 더 명확하고 예측 가능 |
| 성능 | 함수 호출 오버헤드, 스택 메모리 사용 | 오버헤드가 적고 메모리 효율적 |
| 구현 | 기저 조건과 재귀 호출 관계 설정이 중요 | 루프 조건과 변수 업데이트 관리가 중요 |
| 스택 | 스택 오버플로우 위험 | 스택 오버플로우 위험 없음 |

#### 4.1.4. 꼬리 재귀 (Tail Recursion)

꼬리 재귀는 재귀 호출이 함수의 마지막 연산인 형태입니다. 일부 컴파일러나 인터프리터는 꼬리 재귀를 최적화하여 반복문처럼 동작하게 함으로써 스택 오버플로우를 방지하고 성능을 향상시킵니다. (파이썬은 꼬리 재귀 최적화를 지원하지 않습니다.)

```python
def factorial_tail_recursive(n, accumulator=1):
    if n == 0:
        return accumulator
    else:
        return factorial_tail_recursive(n - 1, n * accumulator)

# print(factorial_tail_recursive(5)) # 120
```

#### 4.1.5. 재귀 활용 문제 (팩토리얼, 피보나치, 문자열 뒤집기)

*   **팩토리얼 (Factorial):** `n! = n * (n-1)!`
*   **피보나치 수열 (Fibonacci Sequence):** `F(n) = F(n-1) + F(n-2)`
*   **문자열 뒤집기:** 문자열의 첫 문자와 마지막 문자를 교환하고, 나머지 부분에 대해 재귀 호출.

### 4.4. 동적 계획법 (Dynamic Programming)

동적 계획법(DP)은 복잡한 문제를 여러 개의 작은 하위 문제로 나누어 해결하는 알고리즘 기법입니다. 하위 문제의 해답을 저장하여 중복 계산을 피하고 효율성을 높입니다.

#### 4.4.1. 개념 및 최적 부분 구조, 중복 부분 문제

*   **개념:** 큰 문제의 해답이 작은 문제의 해답에 의존하고, 동일한 작은 문제가 반복적으로 나타날 때 사용합니다.
*   **최적 부분 구조 (Optimal Substructure):** 문제의 최적 해가 그 하위 문제의 최적 해로부터 구성될 수 있습니다.
*   **중복 부분 문제 (Overlapping Subproblems):** 동일한 하위 문제가 여러 번 반복하여 계산됩니다.

#### 4.4.2. 상향식(Bottom-up)과 하향식(Top-down) 접근

*   **상향식 (Bottom-up, Tabulation):** 가장 작은 하위 문제부터 해결하여 점진적으로 큰 문제의 해답을 구축합니다. 반복문을 사용하며, 테이블에 결과를 저장합니다.
*   **하향식 (Top-down, Memoization):** 재귀적으로 문제를 해결하되, 이미 계산된 하위 문제의 해답은 저장(메모이제이션)해두고 재사용합니다.

#### 4.4.3. 동적 계획법 활용 문제 (예: 피보나치, 배낭 문제)

*   **피보나치 수열:** `F(n) = F(n-1) + F(n-2)` (메모이제이션 또는 타뷸레이션으로 `O(n)` 해결)
*   **배낭 문제 (Knapsack Problem):** 제한된 용량의 배낭에 물건을 담아 가치의 합을 최대로 만드는 문제.
*   **최장 공통 부분 수열 (Longest Common Subsequence, LCS):** 두 수열의 가장 긴 공통 부분 수열을 찾는 문제.

### 4.5. 그리디 알고리즘 (Greedy Algorithm)

그리디 알고리즘은 각 단계에서 현재 가장 최적이라고 생각되는 선택을 하는 알고리즘입니다. '당장 최선의 선택이 전체 최적의 해를 보장한다'는 가정을 합니다.

#### 4.5.1. 개념 및 특징

*   **개념:** 매 순간 최적의 선택을 하여 최종적인 해답에 도달합니다.
*   **특징:**
    *   탐욕적인 선택 (Greedy Choice Property): 현재의 선택이 나중에 나올 최적의 해에 영향을 주지 않습니다.
    *   최적 부분 구조 (Optimal Substructure): 문제의 최적 해가 하위 문제의 최적 해로 구성됩니다.

#### 4.5.2. 그리디 알고리즘의 한계

그리디 알고리즘은 항상 최적의 해를 보장하지는 않습니다. 동적 계획법과 달리, 현재의 선택이 미래의 선택에 미치는 영향을 고려하지 않기 때문입니다.

#### 4.5.3. 그리디 활용 문제 (예: 거스름돈, 활동 선택)

*   **거스름돈 문제:** 최소한의 동전 개수로 거스름돈을 주는 문제 (단, 동전 단위가 특정 조건을 만족할 때만 최적).
*   **활동 선택 문제:** 최대한 많은 활동을 선택하는 문제 (활동들이 시작 시간과 종료 시간을 가질 때).
*   **최소 신장 트리 (MST):** 크루스칼(Kruskal) 알고리즘은 그리디 전략을 사용합니다.

### 4.6. 백트래킹 (Backtracking)

백트래킹은 해를 찾는 도중에 '가지치기(Pruning)'를 통해 불필요한 경로를 제거하고, 해가 될 가능성이 없는 경로를 탐색하지 않는 알고리즘 기법입니다. 주로 모든 가능한 경우의 수를 탐색해야 하는 문제에 사용됩니다.

#### 4.6.1. 개념 및 탐색 과정

*   **개념:** 해를 찾아가는 과정에서 조건에 맞지 않으면 즉시 이전 단계로 돌아가(백트랙) 다른 경로를 탐색합니다.
*   **탐색 과정:**
    1.  **상태 공간 트리 (State Space Tree):** 모든 가능한 해를 포함하는 트리를 구성합니다.
    2.  **깊이 우선 탐색 (DFS):** 상태 공간 트리를 DFS 방식으로 탐색합니다.
    3.  **가지치기 (Pruning):** 현재 경로가 해가 될 가능성이 없으면 더 이상 탐색하지 않고 백트랙합니다.

#### 4.6.2. 백트래킹 활용 문제 (예: N-Queen, 스도쿠)

*   **N-Queen 문제:** N개의 퀸을 N*N 체스판에 서로 공격할 수 없도록 배치하는 문제.
*   **스도쿠 (Sudoku):** 스도쿠 퍼즐을 푸는 문제.
*   **조합 (Combination) 생성:** 특정 조건을 만족하는 조합을 모두 찾는 문제.

### 4.7. 분리 집합 (Disjoint Set Union, DSU)

분리 집합(Disjoint Set Union, DSU) 또는 서로소 집합(Union-Find)은 서로 겹치지 않는(서로소) 집합들의 모음을 관리하는 자료구조입니다. 주로 원소들이 어떤 집합에 속하는지, 두 원소가 같은 집합에 속하는지 등을 효율적으로 판단하는 데 사용됩니다.

#### 4.7.1. 분리 집합의 개념과 연산 (Union, Find)

*   **개념:** 각 집합을 트리의 형태로 표현하며, 각 트리의 루트 노드가 해당 집합의 '대표 원소'가 됩니다.
*   **주요 연산:**
    *   **`Find(x)`:** 원소 `x`가 속한 집합의 대표 원소를 찾습니다.
    *   **`Union(x, y)`:** 원소 `x`가 속한 집합과 원소 `y`가 속한 집합을 합칩니다.

#### 4.7.2. 경로 압축(Path Compression) 및 유니온 바이 랭크/사이즈(Union by Rank/Size)

분리 집합의 성능을 최적화하는 기법입니다.

*   **경로 압축 (Path Compression):** `Find` 연산 시, 탐색 경로에 있는 모든 노드들을 직접 루트에 연결하여 트리의 높이를 낮춥니다.
*   **유니온 바이 랭크/사이즈 (Union by Rank/Size):** `Union` 연산 시, 트리의 높이(랭크) 또는 크기(사이즈)를 기준으로 더 작은 트리를 큰 트리에 연결하여 트리의 균형을 유지합니다.

#### 4.7.3. 분리 집합의 파이썬 구현

```python
class DisjointSet:
    def __init__(self, n):
        self.parent = list(range(n)) # 각 원소의 부모를 저장
        self.rank = [0] * n          # 트리의 높이 (랭크) 저장

    def find(self, i):
        if self.parent[i] == i:
            return i
        # 경로 압축
        self.parent[i] = self.find(self.parent[i])
        return self.parent[i]

    def union(self, i, j):
        root_i = self.find(i)
        root_j = self.find(j)

        if root_i != root_j:
            # 유니온 바이 랭크
            if self.rank[root_i] < self.rank[root_j]:
                self.parent[root_i] = root_j
            elif self.rank[root_i] > self.rank[root_j]:
                self.parent[root_j] = root_i
            else:
                self.parent[root_j] = root_i
                self.rank[root_i] += 1
            return True
        return False

# 예시
# ds = DisjointSet(5) # 0, 1, 2, 3, 4
# ds.union(0, 1)
# ds.union(2, 3)
# print(ds.find(0) == ds.find(1)) # True
# print(ds.find(0) == ds.find(2)) # False
# ds.union(0, 2)
# print(ds.find(0) == ds.find(3)) # True
```

#### 4.7.4. 분리 집합의 활용 사례 (그래프 연결성, Kruskal 알고리즘)

*   **그래프 연결성:** 그래프에서 두 노드가 연결되어 있는지, 또는 사이클이 존재하는지 판별.
*   **최소 신장 트리 (MST):** 크루스칼(Kruskal) 알고리즘에서 간선을 추가할 때 사이클이 형성되는지 확인하는 데 사용됩니다.
*   **네트워크 연결:** 네트워크에서 연결된 컴퓨터 그룹을 관리.

### 4.8. 수론 (Number Theory) 및 수학적 알고리즘

수론 및 수학적 알고리즘은 정수론, 조합론, 행렬 등 수학적 개념을 활용하여 문제를 해결하는 기법입니다. 암호학, 최적화, 확률 계산 등 다양한 분야에서 응용됩니다.

#### 4.8.1. 소수 판별 (Prime Number Test)

주어진 수가 소수인지 판별하는 문제입니다.

##### 4.8.1.1. 에라토스테네스의 체 (Sieve of Eratosthenes)

특정 범위 내의 모든 소수를 찾는 효율적인 알고리즘입니다.

*   **개념:** 2부터 시작하여 배수들을 지워나가면서 소수를 판별합니다.
*   **시간 복잡도:** `O(n log log n)`

#### 4.8.2. 최대공약수 (GCD) 및 최소공배수 (LCM)

두 수의 최대공약수(GCD)와 최소공배수(LCM)를 찾는 문제입니다.

##### 4.8.2.1. 유클리드 호제법 (Euclidean Algorithm)

두 정수의 최대공약수를 찾는 가장 오래되고 효율적인 알고리즘입니다.

*   **개념:** `GCD(a, b) = GCD(b, a mod b)`를 반복하여 `a mod b`가 0이 될 때 `b`가 최대공약수입니다.
*   **시간 복잡도:** `O(log(min(a, b)))`
*   **LCM 계산:** `LCM(a, b) = (a * b) / GCD(a, b)`

#### 4.8.3. 모듈러 연산 (Modular Arithmetic)

나머지 연산을 기반으로 하는 수학 시스템입니다. 암호학, 해싱, 큰 수 연산 등에 사용됩니다.

*   **기본 성질:**
    *   `(A + B) % M = ((A % M) + (B % M)) % M`
    *   `(A * B) % M = ((A % M) * (B % M)) % M`
    *   `(A - B) % M = ((A % M) - (B % M) + M) % M`

##### 4.8.3.1. 모듈러 역원 (Modular Multiplicative Inverse)

`a * x ≡ 1 (mod m)`을 만족하는 `x`를 `a`의 모듈러 역원이라고 합니다. 나눗셈 연산을 모듈러 연산에서 수행할 때 사용됩니다.

##### 4.8.3.2. 페르마의 소정리 (Fermat's Little Theorem)

`p`가 소수이고 `a`가 `p`의 배수가 아니면, `a^(p-1) ≡ 1 (mod p)` 입니다. 이를 이용하여 모듈러 역원을 찾을 수 있습니다.

#### 4.8.4. 조합론 (Combinatorics)

경우의 수를 세는 수학 분야입니다. 순열, 조합 등을 다룹니다.

##### 4.8.4.1. 순열 (Permutation) 및 조합 (Combination)

*   **순열 (Permutation):** 서로 다른 `n`개의 원소에서 `r`개를 '선택하여 나열'하는 경우의 수. `nPr = n! / (n-r)!`
*   **조합 (Combination):** 서로 다른 `n`개의 원소에서 `r`개를 '선택'하는 경우의 수. `nCr = n! / (r! * (n-r)!)`

#### 4.8.5. 행렬 (Matrix) 연산

행렬을 이용한 연산은 선형대수학의 기본이며, 그래프, 동적 계획법, 선형 시스템 해결 등에 사용됩니다.

##### 4.8.5.1. 행렬 곱셈 (Matrix Multiplication)

두 행렬을 곱하는 연산입니다. `(m x n)` 행렬과 `(n x p)` 행렬의 곱은 `(m x p)` 행렬이 됩니다.

##### 4.8.5.2. 행렬을 이용한 피보나치 수열 계산

행렬의 거듭제곱을 이용하여 피보나치 수를 빠르게 계산할 수 있습니다. `O(log n)`.

### 4.9. Meet-in-the-Middle

Meet-in-the-Middle은 탐색 공간이 너무 커서 모든 경우의 수를 탐색하기 어려울 때, 탐색 공간을 절반으로 나누어 각각 탐색한 후 중간에서 만나는 방식으로 문제를 해결하는 알고리즘 기법입니다.

#### 4.9.1. 개념 및 활용 (탐색 공간 절반으로 줄이기)

*   **개념:** 전체 문제를 두 개의 하위 문제로 나누고, 각 하위 문제를 독립적으로 해결한 후, 두 하위 문제의 결과를 결합하여 전체 문제의 해를 찾습니다.
*   **활용:** 탐색 공간이 `O(2^n)`일 때, `O(2^(n/2))`로 줄일 수 있습니다.

#### 4.9.2. Meet-in-the-Middle 활용 문제 (예: 부분집합 합)

주어진 집합의 부분집합 중 합이 특정 값(target)이 되는 부분집합을 찾는 문제입니다.

### 4.10. 확률적 알고리즘 (Randomized Algorithms)

확률적 알고리즘은 알고리즘의 동작 과정에 무작위성을 도입하여 문제를 해결하는 기법입니다. 항상 최적의 해를 보장하지 않거나, 항상 정답을 보장하지는 않지만, 평균적으로 매우 효율적인 성능을 보여줍니다.

#### 4.10.1. 개념 및 특징 (라스베이거스, 몬테카를로)

*   **개념:** 난수를 사용하여 다음 단계를 결정하거나, 해를 찾는 과정에 무작위 요소를 도입합니다.
*   **종류:**
    *   **라스베이거스 알고리즘 (Las Vegas Algorithm):** 항상 정답을 찾지만, 실행 시간이 확률적입니다. (예: Randomized Quicksort)
    *   **몬테카를로 알고리즘 (Monte Carlo Algorithm):** 실행 시간은 결정론적이지만, 정답을 찾을 확률이 있습니다. (예: Miller-Rabin 소수 판별)

#### 4.10.2. 활용 사례 (Quickselect, Miller-Rabin 소수 판별)

*   **Quickselect:** 배열에서 k번째로 작은(또는 큰) 요소를 찾는 알고리즘. 평균 `O(n)`.
*   **Miller-Rabin 소수 판별:** 큰 수가 소수인지 아닌지 판별하는 확률적 알고리즘.
