## 1. 데이터 입력 (`INSERT INTO`)

`INSERT INTO` 문은 테이블에 새로운 데이터를 추가할 때 사용합니다. 데이터를 추가하는 방법은 여러 가지가 있습니다.

### 1.1. 단일 로우 삽입

가장 기본적인 형태로, 테이블의 모든 컬럼에 값을 지정하거나, 특정 컬럼에만 값을 지정하여 하나의 로우를 삽입합니다.

```sql
-- 모든 컬럼에 값 삽입 (컬럼 순서에 맞춰 모든 값을 제공해야 함)
INSERT INTO employees VALUES (1, 'John', 'Doe', 'john.doe@example.com', '123-456-7890', '2023-01-15', 'DEV', 60000.00, 1);

-- 특정 컬럼에만 값 삽입 (컬럼 이름을 명시해야 함)
INSERT INTO employees (employee_id, first_name, last_name, hire_date, job_id, salary, department_id)
VALUES (2, 'Jane', 'Smith', '2023-02-01', 'HR', 55000.00, 2);

-- AUTO_INCREMENT 컬럼은 값을 명시하지 않아도 자동으로 증가
INSERT INTO employees (first_name, last_name, hire_date, job_id, salary, department_id)
VALUES ('Alice', 'Johnson', '2023-03-10', 'MGR', 70000.00, 1);
```

### 1.2. 다중 로우 삽입

하나의 `INSERT INTO` 문으로 여러 개의 로우를 동시에 삽입할 수 있습니다. 이는 단일 로우를 여러 번 삽입하는 것보다 성능상 효율적입니다.

```sql
INSERT INTO employees (first_name, last_name, hire_date, job_id, salary, department_id)
VALUES
    ('Bob', 'Williams', '2023-04-05', 'DEV', 62000.00, 1),
    ('Charlie', 'Brown', '2023-05-20', 'HR', 58000.00, 2),
    ('David', 'Lee', '2023-06-01', 'MGR', 75000.00, 3);
```

### 1.3. 다른 테이블에서 데이터 삽입 (`INSERT INTO ... SELECT`)

다른 테이블에서 조회한 결과를 새로운 테이블에 삽입할 수 있습니다. 이는 데이터 마이그레이션이나 특정 조건에 맞는 데이터만 복사할 때 유용합니다.

```sql
-- 예시: old_employees 테이블에서 특정 조건을 만족하는 직원만 new_employees 테이블로 복사
-- (new_employees 테이블은 미리 생성되어 있어야 함)
INSERT INTO new_employees (employee_id, first_name, last_name, hire_date, job_id, salary)
SELECT employee_id, first_name, last_name, hire_date, job_id, salary
FROM old_employees
WHERE salary > 60000;
```

### 1.4. `INSERT ... ON DUPLICATE KEY UPDATE` (MySQL 특화)

`INSERT ... ON DUPLICATE KEY UPDATE` 문은 `PRIMARY KEY` 또는 `UNIQUE` 제약조건에 의해 중복된 키가 발생할 경우, `INSERT` 대신 `UPDATE`를 수행하도록 지시합니다. 이는 데이터 삽입과 업데이트를 하나의 쿼리로 처리할 수 있게 하여 데이터 로딩 및 동기화 시 유용합니다.

```sql
-- 예시: users 테이블에 username이 PRIMARY KEY 또는 UNIQUE로 설정되어 있다고 가정
-- (user_id INT PRIMARY KEY, username VARCHAR(50) UNIQUE, email VARCHAR(100))

-- 새로운 사용자 삽입
INSERT INTO users (user_id, username, email)
VALUES (1, 'john_doe', 'john.doe@example.com');

-- user_id가 1인 로우가 이미 존재하므로, email을 업데이트
INSERT INTO users (user_id, username, email)
VALUES (1, 'john_doe', 'john.doe.new@example.com')
ON DUPLICATE KEY UPDATE
    email = VALUES(email); -- VALUES(컬럼명)는 INSERT 시도된 값을 참조

-- username이 'jane_smith'인 로우가 이미 존재하므로, email과 user_id를 업데이트
INSERT INTO users (user_id, username, email)
VALUES (2, 'jane_smith', 'jane.smith.new@example.com')
ON DUPLICATE KEY UPDATE
    user_id = VALUES(user_id),
    email = VALUES(email);
```

### 1.5. `REPLACE` 문 (MySQL 특화)

`REPLACE` 문은 `INSERT`와 `UPDATE`의 기능을 결합한 것으로, `PRIMARY KEY` 또는 `UNIQUE` 제약조건에 의해 중복된 키가 발생할 경우 기존 로우를 삭제하고 새로운 로우를 삽입합니다. 중복이 없으면 `INSERT`와 동일하게 동작합니다. **주의할 점은 `REPLACE`는 내부적으로 `DELETE` 후 `INSERT`를 수행하므로, `AUTO_INCREMENT` 값이 증가하고, 관련 트리거가 동작하며, 기존 로우의 모든 컬럼 값이 새로운 값으로 대체된다는 것입니다.**

```sql
-- 예시: users 테이블에 user_id가 PRIMARY KEY로 설정되어 있다고 가정
-- (user_id INT PRIMARY KEY, username VARCHAR(50), email VARCHAR(100))

-- 새로운 사용자 삽입
REPLACE INTO users (user_id, username, email)
VALUES (3, 'new_user', 'new.user@example.com');

-- user_id가 3인 로우가 이미 존재하므로, 기존 로우를 삭제하고 새로운 값으로 대체
-- (username과 email이 모두 변경됨)
REPLACE INTO users (user_id, username, email)
VALUES (3, 'updated_user', 'updated.user@example.com');
```

### 1.6. `INSERT IGNORE` (MySQL 특화)

`INSERT IGNORE` 문은 `INSERT` 시 `PRIMARY KEY` 또는 `UNIQUE` 제약조건에 의해 중복된 키가 발생할 경우, 오류를 발생시키지 않고 해당 로우의 삽입을 무시합니다. 대량의 데이터를 로드할 때 중복된 로우를 조용히 건너뛰고 싶을 때 유용합니다.

```sql
-- 예시: users 테이블에 user_id가 PRIMARY KEY로 설정되어 있다고 가정

-- 새로운 사용자 삽입
INSERT IGNORE INTO users (user_id, username, email)
VALUES (4, 'test_user', 'test@example.com');

-- user_id가 4인 로우가 이미 존재하므로, 이 삽입 시도는 무시되고 오류가 발생하지 않음
INSERT IGNORE INTO users (user_id, username, email)
VALUES (4, 'test_user_duplicate', 'test_duplicate@example.com');

-- (확인) users 테이블에는 user_id가 4인 로우가 하나만 존재함
SELECT * FROM users WHERE user_id = 4;
```

## 2. 기본 데이터 조회 (`SELECT`) 마스터하기

`SELECT` 문은 데이터베이스에서 데이터를 조회하는 가장 기본적인 DML 명령어입니다. 데이터 분석가의 업무에서 가장 많이 사용되는 SQL 문입니다.

### 2.1. 모든 컬럼 조회 (`SELECT *`)

테이블의 모든 컬럼을 조회할 때 사용합니다. 간단하게 데이터를 확인할 때 유용하지만, 실제 운영 환경에서는 필요한 컬럼만 명시하는 것이 성능상 좋습니다.

```sql
SELECT * FROM employees;
```

### 2.1.1. [실무 노트] `SELECT *`는 정말 사용하면 안 될까?
> **결론부터 말하면, 프로덕션 코드(앱, 자동화 스크립트 등)에서는 절대 사용하면 안 됩니다.** 하지만 예외적으로 사용이 허용되는 경우도 있습니다.
>
> **`SELECT *`를 절대 쓰면 안 되는 이유:**
> 1.  **성능 저하:** 불필요한 컬럼까지 모두 읽어오므로 네트워크, 디스크 I/O, 메모리 등 모든 면에서 비효율적입니다. 특히 **커버링 인덱스**의 이점을 전혀 활용할 수 없게 만듭니다.
> 2.  **예측 불가능한 오류:** 테이블 스키마(컬럼 추가/삭제/순서 변경)가 바뀌면, `SELECT *`에 의존하는 코드는 예고 없이 오작동할 수 있습니다.
> 3.  **가독성 저하:** 쿼리가 어떤 데이터를 필요로 하는지 명확히 알 수 없어 동료와의 협업을 방해합니다.
>
> **예외적으로 `SELECT *`를 써도 괜찮을 때:**
> *   **순수한 탐색적 데이터 분석(EDA) 단계:** 테이블의 전체 구조와 내용을 빠르게 파악하기 위해 **GUI 툴(DBeaver 등)에서 직접 실행**할 때.
> *   **로우 수가 매우 적은 테이블을 확인할 때:** `LIMIT 10` 과 같이 결과 수를 제한하여 잠시 내용을 확인할 때.
>
> **핵심 습관:**
> **자동화되거나, 다른 사람과 공유되거나, 앱에서 사용될 코드에는 반드시 필요한 컬럼명을 명시적으로 모두 적는 습관**을 들여야 합니다.
`SELECT *`는 편리하지만, 실제 운영 환경이나 대규모 데이터 분석 시에는 여러 가지 문제점을 야기할 수 있으므로 사용을 지양하는 것이 좋습니다.

### 2.2. 특정 컬럼 조회 (`SELECT column1, column2`)

원하는 컬럼만 선택하여 조회할 수 있습니다. 이는 네트워크 트래픽을 줄이고, 불필요한 데이터를 가져오지 않아 성능에 도움이 됩니다.

```sql
SELECT first_name, last_name, salary FROM employees;
```

#### 2.2.1. `SELECT` 절의 산술/논리 연산

`SELECT` 절에서는 컬럼 값을 직접 사용하여 산술 연산(`+`, `-`, `*`, `/`)이나 논리 연산(`AND`, `OR`, `NOT`)을 수행할 수 있습니다. 이는 데이터를 조회하면서 동시에 가공할 때 유용합니다.

```sql
-- 급여를 10% 인상한 가상 컬럼 조회
SELECT employee_id, first_name, salary, salary * 1.10 AS increased_salary
FROM employees;

-- 급여가 60000 이상인지 여부를 불리언(0 또는 1)으로 표시
SELECT employee_id, first_name, salary, (salary >= 60000) AS is_high_salary
FROM employees;

-- 고용 기간을 개월 수로 계산 (MySQL의 TIMESTAMPDIFF 함수 활용)
SELECT employee_id, first_name, hire_date,
       TIMESTAMPDIFF(MONTH, hire_date, CURDATE()) AS months_employed
FROM employees;
```

### 2.3. 컬럼 별칭(Alias) 사용 (`AS`)

조회 결과의 컬럼 이름을 변경하여 가독성을 높일 수 있습니다. `AS` 키워드는 생략 가능합니다.

```sql
SELECT first_name AS 이름, last_name AS 성, salary AS 급여 FROM employees;
SELECT first_name 이름, last_name 성, salary 급여 FROM employees;
```

### 2.4. 중복 제거 (`DISTINCT`)

조회 결과에서 중복된 로우를 제거하고 고유한 값만 반환합니다. `SELECT` 키워드 바로 뒤에 위치합니다.

```sql
-- employees 테이블의 모든 job_id 중복 제거 후 조회
SELECT DISTINCT job_id FROM employees;

-- 여러 컬럼의 조합이 중복될 때 제거
SELECT DISTINCT job_id, department_id FROM employees;
```

### 2.5. 조건에 따른 데이터 필터링 (`WHERE`)

`WHERE` 절을 사용하여 특정 조건을 만족하는 로우만 조회할 수 있습니다. 이는 데이터 분석에서 가장 중요한 부분 중 하나입니다.

```sql
-- 급여가 60000 이상인 직원 조회
SELECT * FROM employees WHERE salary >= 60000;
```

#### 2.5.1. 비교 연산자 (`=`, `!=`, `>`, `<`, `>=`, `<=`)

두 값을 비교할 때 사용합니다. `!=` 대신 `<>`를 사용할 수도 있습니다.

```sql
-- department_id가 1인 직원 조회
SELECT * FROM employees WHERE department_id = 1;

-- job_id가 'DEV'가 아닌 직원 조회
SELECT * FROM employees WHERE job_id != 'DEV';
```

#### 2.5.2. 논리 연산자 (`AND`, `OR`, `NOT`)

여러 조건을 조합하여 더 복잡한 필터링을 수행합니다.

*   `AND`: 모든 조건이 참일 때 참.
*   `OR`: 하나 이상의 조건이 참일 때 참.
*   `NOT`: 조건의 결과를 반전.

```sql
-- department_id가 1이고 급여가 60000 이상인 직원 조회
SELECT * FROM employees WHERE department_id = 1 AND salary >= 60000;

-- department_id가 1이거나 job_id가 'HR'인 직원 조회
SELECT * FROM employees WHERE department_id = 1 OR job_id = 'HR';

-- department_id가 1이 아닌 직원 조회
SELECT * FROM employees WHERE NOT department_id = 1;
```

#### 2.5.3. [실무 노트] `NULL` 값: 분석의 함정을 피하는 법
> `NULL`은 `0`이나 `''`(빈 문자열)이 아닙니다. **"알 수 없는 값(Unknown)"**을 의미하는 특별한 존재입니다. `NULL`을 잘못 다루면 분석 결과 전체가 왜곡될 수 있으므로, 다음 두 가지 원칙을 반드시 기억해야 합니다.
>
> **원칙 1: `NULL`을 찾을 때는 `IS NULL` 또는 `IS NOT NULL`을 사용한다.**
> `WHERE column = NULL` 이나 `WHERE column != NULL`은 절대 원하는 결과를 반환하지 않습니다. `NULL`은 비교 연산의 대상이 될 수 없기 때문입니다.
>
> ```sql
> -- phone_number가 없는 직원 조회 (O)
> SELECT * FROM employees WHERE phone_number IS NULL;
>
> -- phone_number가 있는 직원 조회 (O)
> SELECT * FROM employees WHERE phone_number IS NOT NULL;
>
> -- 원하는 결과가 나오지 않음 (X)
> SELECT * FROM employees WHERE phone_number = NULL;
> ```
>
> **원칙 2: `NULL`을 다른 값으로 바꾸고 싶을 때는 `COALESCE`를 사용한다.**
> `COALESCE(A, B, C, ...)` 함수는 왼쪽부터 차례대로 값을 확인하여 **가장 먼저 만나는 `NULL`이 아닌 값**을 반환합니다. `IFNULL`(MySQL 전용)보다 표준이며, 여러 값을 처리할 수 있어 훨씬 유용합니다.
>
> ```sql
> -- commission_pct가 NULL이면 0으로, 아니면 원래 값으로 조회
> SELECT
>     employee_id,
>     salary,
>     commission_pct,
>     salary * (1 + COALESCE(commission_pct, 0)) AS final_salary
> FROM
>     employees;
> ```
>
> `NULL`을 제대로 이해하고 다루는 것은 정확한 데이터 분석의 가장 기본적이고 중요한 습관입니다.

#### 2.5.4. 정규 표현식 (`REGEXP` 또는 `RLIKE`) 활용

`LIKE`보다 더 복잡하고 유연한 패턴 매칭을 위해 정규 표현식(Regular Expression)을 사용할 수 있습니다. MySQL에서는 `REGEXP` 또는 `RLIKE` 연산자를 사용합니다.

*   **`REGEXP` (또는 `RLIKE`):** 정규 표현식 패턴과 일치하는지 확인합니다.

    ```sql
    -- 이름이 'J' 또는 'A'로 시작하는 직원 조회
    SELECT employee_id, first_name
    FROM employees
    WHERE first_name REGEXP '^[JA]';

    -- 이메일 주소가 특정 도메인(예: @example.com 또는 @test.org)으로 끝나는 직원 조회
    SELECT employee_id, email
    FROM employees
    WHERE email REGEXP '@(example\.com|test\.org)


#### 2.5.5. 서브쿼리를 활용한 필터링 (`EXISTS`, `NOT EXISTS`)

`EXISTS`와 `NOT EXISTS`는 서브쿼리의 결과가 존재하는지 여부를 확인하여 메인 쿼리의 로우를 필터링합니다. 특히 다른 테이블과의 관계를 기반으로 필터링할 때 유용하며, `IN` 연산자보다 성능상 이점을 가질 수 있습니다.

*   **`EXISTS`:** 서브쿼리가 하나 이상의 로우를 반환하면 `TRUE`를 반환합니다.
    ```sql
    -- 프로젝트에 배정된 직원 조회
    SELECT employee_id, first_name
    FROM employees e
    WHERE EXISTS (
        SELECT 1
        FROM project_assignments pa
        WHERE pa.employee_id = e.employee_id
    );
    ```

*   **`NOT EXISTS`:** 서브쿼리가 어떤 로우도 반환하지 않으면 `TRUE`를 반환합니다.
    ```sql
    -- 프로젝트에 배정되지 않은 직원 조회
    SELECT employee_id, first_name
    FROM employees e
    WHERE NOT EXISTS (
        SELECT 1
        FROM project_assignments pa
        WHERE pa.employee_id = e.employee_id
    );
    ```

    **`EXISTS` vs `IN` (성능 고려사항):**
    *   **`IN`:** 서브쿼리가 먼저 실행되어 모든 결과를 메모리에 로드한 후, 메인 쿼리의 각 로우와 비교합니다. 서브쿼리의 결과 집합이 작을 때 효율적입니다.
    *   **`EXISTS`:** 메인 쿼리의 각 로우에 대해 서브쿼리를 실행합니다. 서브쿼리는 조건에 맞는 첫 번째 로우를 찾으면 즉시 `TRUE`를 반환하고 실행을 멈춥니다. 서브쿼리의 결과 집합이 크거나, 서브쿼리 내에 `LIMIT`와 같은 최적화가 가능한 경우 효율적입니다.
    일반적으로 상관 서브쿼리(외부 쿼리의 컬럼을 참조하는 서브쿼리)의 경우 `EXISTS`가 `IN`보다 유리한 경우가 많습니다.

### 2.6. 결과 정렬 (`ORDER BY`)

`ORDER BY` 절을 사용하여 조회 결과를 특정 컬럼을 기준으로 정렬할 수 있습니다. 기본 정렬 순서는 오름차순(ASC)입니다.

```sql
-- 급여를 기준으로 오름차순 정렬
SELECT first_name, salary FROM employees ORDER BY salary;
```

#### 2.6.1. 오름차순 (`ASC`) 및 내림차순 (`DESC`)

*   `ASC`: 오름차순 (기본값, 생략 가능)
*   `DESC`: 내림차순

```sql
-- 급여를 기준으로 내림차순 정렬
SELECT first_name, salary FROM employees ORDER BY salary DESC;
```

#### 2.6.2. 여러 컬럼으로 정렬

여러 컬럼을 지정하여 다단계 정렬을 수행할 수 있습니다. 먼저 지정된 컬럼으로 정렬하고, 해당 컬럼의 값이 같을 경우 다음 컬럼으로 정렬합니다.

```sql
-- department_id로 오름차순 정렬 후, 같은 부서 내에서는 salary를 내림차순 정렬
SELECT first_name, department_id, salary
FROM employees
ORDER BY department_id ASC, salary DESC;
```

### 2.7. 결과 제한 (`LIMIT` / `OFFSET`)

`LIMIT` 절을 사용하여 조회할 로우의 수를 제한할 수 있습니다. 대규모 데이터셋에서 일부만 확인하거나, 페이지네이션(Pagination)을 구현할 때 유용합니다.

```sql
-- 상위 5개의 로우만 조회
SELECT * FROM employees LIMIT 5;

-- 3번째 로우부터 5개 로우 조회 (OFFSET은 0부터 시작)
-- LIMIT [offset], [count]
SELECT * FROM employees LIMIT 2, 5; -- 3번째 로우부터 5개

-- OFFSET 키워드 사용 (더 명확함)
SELECT * FROM employees LIMIT 5 OFFSET 2; -- 3번째 로우부터 5개
```

**`LIMIT`와 `OFFSET` 사용 시 성능 고려사항:**
`LIMIT`와 `OFFSET`은 페이지네이션에 유용하지만, `OFFSET` 값이 매우 커질 경우 성능 문제가 발생할 수 있습니다. 데이터베이스는 `OFFSET`까지의 모든 로우를 읽은 후 `LIMIT`만큼의 로우만 반환하기 때문에, `OFFSET`이 클수록 불필요한 로우를 읽는 오버헤드가 커집니다. 대규모 테이블에서 `OFFSET`이 큰 페이지네이션이 필요한 경우, 다음과 같은 대안을 고려할 수 있습니다.

1.  **마지막 조회 ID 기반 페이지네이션:**
    이전 페이지의 마지막 로우의 고유 ID(예: `employee_id`)를 기억하고, 다음 페이지를 조회할 때 `WHERE id > last_id LIMIT N`과 같이 사용하는 방식입니다. 이 방식은 인덱스를 효율적으로 사용하여 `OFFSET` 방식보다 훨씬 빠릅니다.
    ```sql
    -- 예시: 이전 페이지의 마지막 employee_id가 100이었다면
    SELECT * FROM employees
    WHERE employee_id > 100
    ORDER BY employee_id
    LIMIT 10;
    ```

2.  **커서(Cursor) 기반 페이지네이션:**
    데이터베이스 커서를 사용하여 특정 지점부터 데이터를 스트리밍하는 방식입니다. 애플리케이션 레벨에서 구현이 필요할 수 있습니다.

이러한 대안들은 특히 대규모 데이터셋에서 효율적인 페이지네이션을 구현하는 데 중요합니다.

## 3. 안전한 데이터 변경: `UPDATE`와 `DELETE`

> **[실무 노트] 데이터 변경 전, 세 번 확인하고 트랜잭션을 사용하세요!**
> 
> `UPDATE`와 `DELETE`는 **실행 취소가 불가능한(되돌리기 매우 어려운)** 명령어입니다. `WHERE` 절을 빠뜨린 `DELETE` 쿼리 한 줄로 수백만 건의 고객 데이터가 사라지는 끔찍한 사고는 실제로도 일어납니다. 데이터 분석가는 보통 운영 DB에 대한 변경 권한이 없지만, 샌드박스나 분석용 DB에서 작업할 때도 다음 안전 절차를 반드시 습관화해야 합니다.
> 
> **안전한 데이터 변경 3단계 절차:**
> 
> 1.  **`SELECT`로 먼저 확인:** `UPDATE`나 `DELETE`를 실행하기 전에, **동일한 `WHERE` 절을 사용한 `SELECT *` 쿼리**를 먼저 실행하여 내가 변경/삭제하려는 데이터가 정확히 맞는지 눈으로 확인합니다.
> 
>     ```sql
>     -- DELETE를 실행하기 전에...
>     SELECT * FROM employees WHERE hire_date < '2020-01-01';
>     -- (결과를 보고 내가 의도한 데이터가 맞는지 확인)
>     ```
> 
> 2.  **`START TRANSACTION`으로 시작:** 실제 변경/삭제 작업은 반드시 `START TRANSACTION;`으로 시작하여 안전장치를 마련합니다.
> 
> 3.  **`COMMIT` 또는 `ROLLBACK`:** `UPDATE`나 `DELETE` 실행 후, 변경된 결과를 다시 `SELECT`로 확인합니다.
>     *   **의도한 대로 변경되었다면 `COMMIT;`** 하여 변경 사항을 영구 저장합니다.
>     *   **실수했다면 `ROLLBACK;`** 하여 트랜잭션 시작 이전 상태로 안전하게 되돌립니다.
> 
> 이 세 가지 절차만 지켜도 데이터 유실 사고의 99%를 막을 수 있습니다.

`UPDATE`와 `DELETE` 문은 데이터베이스의 데이터를 직접 변경하거나 삭제하므로, 매우 신중하게 사용해야 합니다. 특히 `WHERE` 절을 생략하면 모든 로우에 영향을 미치므로 주의해야 합니다.

### 3.1. `UPDATE`: 데이터 수정의 원칙

`UPDATE` 문은 테이블의 기존 데이터를 수정할 때 사용합니다. `SET` 절에 수정할 컬럼과 값을 지정하고, `WHERE` 절로 수정할 로우를 지정합니다.

```sql
UPDATE 테이블명
SET 컬럼1 = 값1, 컬럼2 = 값2, ...
WHERE 조건;
```

#### 3.1.1. 특정 로우의 컬럼 값 수정

`PRIMARY KEY`나 `UNIQUE` 컬럼을 `WHERE` 절에 사용하여 특정 로우만 정확히 수정합니다.

```sql
-- employee_id가 1인 직원의 급여를 65000으로 수정
UPDATE employees
SET salary = 65000.00
WHERE employee_id = 1;

-- employee_id가 2인 직원의 이메일과 직무를 수정
UPDATE employees
SET email = 'jane.smith@newcorp.com', job_id = 'SENIOR_HR'
WHERE employee_id = 2;
```

#### 3.1.2. 여러 로우의 컬럼 값 일괄 수정

`WHERE` 절의 조건을 통해 여러 로우를 한 번에 수정할 수 있습니다.

```sql
-- department_id가 1인 모든 직원의 급여를 10% 인상
UPDATE employees
SET salary = salary * 1.10
WHERE department_id = 1;

-- job_id가 'DEV'인 직원의 job_id를 'SOFTWARE_ENGINEER'로 변경
UPDATE employees
SET job_id = 'SOFTWARE_ENGINEER'
WHERE job_id = 'DEV';
```

#### 3.1.3. 다른 테이블의 값을 참조하여 수정

`JOIN`을 사용하여 다른 테이블의 데이터를 참조하여 현재 테이블의 데이터를 수정할 수 있습니다. MySQL에서는 `UPDATE ... JOIN` 구문을 사용합니다.

```sql
-- 예시: departments 테이블의 location에 따라 employees 테이블의 salary를 조정
-- (예: 'New York' 부서 직원의 급여를 5% 추가 인상)
UPDATE employees e
JOIN departments d ON e.department_id = d.department_id
SET e.salary = e.salary * 1.05
WHERE d.location = 'New York';
```

### 3.2. `DELETE`: 데이터 삭제의 원칙

`DELETE` 문은 테이블에서 로우를 삭제할 때 사용합니다. `UPDATE`와 마찬가지로 `WHERE` 절을 사용하여 삭제할 로우를 지정합니다.

```sql
DELETE FROM 테이블명
WHERE 조건;
```

#### 3.2.1. 특정 로우 삭제

`PRIMARY KEY`나 `UNIQUE` 컬럼을 `WHERE` 절에 사용하여 특정 로우만 정확히 삭제합니다.

```sql
-- employee_id가 1인 직원 삭제
DELETE FROM employees
WHERE employee_id = 1;
```

#### 3.2.2. 모든 로우 삭제 (`TRUNCATE TABLE`과의 차이점)

`WHERE` 절을 생략하면 테이블의 모든 로우가 삭제됩니다.

```sql
-- employees 테이블의 모든 로우 삭제
DELETE FROM employees;
```

*   **`TRUNCATE TABLE` vs `DELETE FROM` (WHERE 절 없음):**
    *   `DELETE FROM 테이블명;`: 모든 로우를 삭제하지만, 각 로우를 개별적으로 삭제하는 방식으로 동작합니다. 트랜잭션 로그를 기록하며, `ROLLBACK`이 가능합니다. `AUTO_INCREMENT` 값은 초기화되지 않습니다.
    *   `TRUNCATE TABLE 테이블명;`: 테이블의 모든 로우를 삭제하고, 테이블 구조는 남겨둡니다. DDL 명령어로 분류되며, 테이블을 새로 생성하는 것과 유사하게 동작합니다. 트랜잭션 로그를 기록하지 않아 `DELETE`보다 훨씬 빠르며, `ROLLBACK`이 불가능합니다. `AUTO_INCREMENT` 값은 초기화됩니다.

**안전한 데이터 변경을 위한 팁:**
1.  **항상 `WHERE` 절을 먼저 작성:** `UPDATE`나 `DELETE` 문을 작성할 때는 `WHERE` 절을 먼저 작성하여 실수로 모든 데이터를 변경/삭제하는 것을 방지합니다.
2.  **`SELECT`로 먼저 확인:** `UPDATE`나 `DELETE`를 실행하기 전에, 동일한 `WHERE` 절을 사용하여 `SELECT` 문을 실행하여 어떤 로우들이 영향을 받을지 미리 확인합니다.
3.  **트랜잭션 사용 (가장 중요):** 중요한 변경 작업은 반드시 트랜잭션 내에서 수행하고, 변경 사항을 확인한 후 `COMMIT`하거나 문제가 발생하면 `ROLLBACK`합니다. 이는 실무에서 데이터 손실이나 불일치를 방지하는 가장 확실한 방법입니다. (자세한 내용은 [5. 트랜잭션: 데이터 일관성과 무결성 보장](#5-트랜잭션-데이터-일관성과-무결성-보장) 섹션을 참조하세요.)
    ```sql
    START TRANSACTION; -- 트랜잭션 시작

    -- 여기에 UPDATE 또는 DELETE 문 작성
    UPDATE employees SET salary = salary * 1.05 WHERE department_id = 1;

    -- 변경된 내용 확인 (선택 사항)
    SELECT * FROM employees WHERE department_id = 1;

    -- 변경 사항이 올바른지 확인 후 COMMIT 또는 ROLLBACK
    -- COMMIT;   -- 변경 사항 영구 반영
    -- ROLLBACK; -- 변경 사항 취소 (원래 상태로 되돌림)
    ```
4.  **백업:** 중요한 데이터를 변경하기 전에는 항상 백업을 수행합니다. 특히 대규모 데이터 변경 작업 전에는 필수적입니다.

**`DELETE`와 `JOIN`을 활용한 삭제 (MySQL 8.0.16+):**
MySQL 8.0.16 버전부터는 `DELETE` 문에서도 `JOIN`을 사용하여 다른 테이블의 조건을 기반으로 로우를 삭제할 수 있습니다. 이는 복잡한 조건으로 여러 테이블을 참조하여 데이터를 삭제해야 할 때 유용합니다.

```sql
-- 예시: 특정 프로젝트에 참여하지 않는 직원들 중에서 급여가 50000 미만인 직원 삭제
-- (employees 테이블과 project_assignments 테이블이 있다고 가정)
DELETE e FROM employees e
LEFT JOIN project_assignments pa ON e.employee_id = pa.employee_id
WHERE pa.employee_id IS NULL -- 프로젝트에 참여하지 않는 직원
  AND e.salary < 50000;

-- 또는 USING 절을 사용하여 더 간결하게 표현
DELETE e FROM employees AS e
USING employees AS e
LEFT JOIN project_assignments AS pa ON e.employee_id = pa.employee_id
WHERE pa.employee_id IS NULL
  AND e.salary < 50000;
