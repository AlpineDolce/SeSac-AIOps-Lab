## 1. 대량 데이터 처리 최적화

대량의 데이터를 파이썬에서 데이터베이스로 삽입하거나 업데이트할 때, 로우별로 개별 쿼리를 실행하는 것은 매우 비효율적입니다. 성능을 최적화하기 위한 다양한 방법이 있습니다.

**실무적 관점:** 대량 데이터 처리는 ETL 파이프라인의 핵심 성능 지표입니다. 로우별 `INSERT`는 피하고, 네트워크 왕복 횟수를 최소화하는 방법을 적극적으로 활용해야 합니다. 이는 데이터 적재 시간을 단축하고 데이터베이스 부하를 줄이는 데 결정적인 역할을 합니다.

### 1.1. 대량 데이터 삽입 (Bulk Insert)

*   **`executemany()` 활용:** DB-API 드라이버의 `executemany()` 메서드는 여러 로우를 한 번의 호출로 삽입할 수 있게 하여 네트워크 왕복 횟수를 줄여 성능을 향상시킵니다.

    ```python
    import pymysql
    import os
    from dotenv import load_dotenv

    load_dotenv()

    conn = pymysql.connect(host=os.getenv('DB_HOST'), user=os.getenv('DB_USER'), password=os.getenv('DB_PASSWORD'), db=os.getenv('DB_NAME'), charset='utf8mb4')

    try:
        with conn.cursor() as cursor:
            data_to_insert = [
                ('David', 'Kim', '2024-06-01', 'DEV', 70000.00, 1),
                ('Eve', 'Park', '2024-06-05', 'HR', 58000.00, 2),
                ('Frank', 'Lee', '2024-06-10', 'MGR', 80000.00, 3),
            ]
            insert_sql = "INSERT INTO employees (first_name, last_name, hire_date, job_id, salary, department_id) VALUES (%s, %s, %s, %s, %s, %s)"
            cursor.executemany(insert_sql, data_to_insert)
            conn.commit()
            print(f"Inserted {cursor.rowcount} rows using executemany.")
    finally:
        conn.close()
    ```

*   **`multi-insert` 구문 사용:** 단일 `INSERT` 문에 여러 `VALUES` 절을 포함하는 방식입니다. `executemany()`와 유사하게 네트워크 왕복 횟수를 줄입니다.

*   **`LOAD DATA INFILE` 활용 (MySQL 특화):** MySQL의 `LOAD DATA INFILE` 명령은 CSV 파일과 같은 외부 파일에서 대량의 데이터를 매우 빠르게 로드할 수 있는 강력한 기능입니다. 파이썬에서 이 명령을 실행할 수 있습니다.

    ```python
    # 이 기능은 MySQL 서버의 설정(local_infile=1)과 파일 권한 설정이 필요합니다.
    # 보안상의 이유로 기본적으로 비활성화되어 있을 수 있습니다. **운영 환경에서는 보안 위험을 신중하게 고려해야 합니다.**

    import pymysql
    import os
    from dotenv import load_dotenv

    load_dotenv()

    conn = pymysql.connect(host=os.getenv('DB_HOST'), user=os.getenv('DB_USER'), password=os.getenv('DB_PASSWORD'), db=os.getenv('DB_NAME'), charset='utf8mb4', local_infile=True)

    try:
        with conn.cursor() as cursor:
            # CSV 파일 생성 (예시)
            with open('temp_employees.csv', 'w', encoding='utf8') as f:
                f.write("first_name,last_name,hire_date,job_id,salary,department_id\n")
                f.write("George,Brown,2024-07-01,DEV,72000.00,1\n")
                f.write("Hannah,Green,2024-07-05,HR,59000.00,2\n")

            load_sql = """
            LOAD DATA LOCAL INFILE 'temp_employees.csv'
            INTO TABLE employees
            FIELDS TERMINATED BY ','
            ENCLOSED BY '"' -- Use double quotes for enclosure
            LINES TERMINATED BY '\n'
            IGNORE 1 ROWS;
            """
            cursor.execute(load_sql)
            conn.commit()
            print(f"Inserted {cursor.rowcount} rows using LOAD DATA INFILE.")

    finally:
        conn.close()
    ```

*   **ORM의 `bulk_insert_mappings` (SQLAlchemy):** SQLAlchemy ORM은 `session.bulk_insert_mappings()`와 같은 메서드를 제공하여 ORM 객체 리스트를 효율적으로 대량 삽입할 수 있습니다.

    ```python
    from sqlalchemy.orm import sessionmaker
    from sqlalchemy import create_engine
    from sqlalchemy.ext.declarative import declarative_base
    from sqlalchemy import Column, Integer, String, Date, DECIMAL, ForeignKey
    import datetime
    import os
    from dotenv import load_dotenv

    load_dotenv()

    DATABASE_URL = (
        f"mysql+pymysql://{os.getenv('DB_USER')}:
        {os.getenv('DB_PASSWORD')}@"
        f"{os.getenv('DB_HOST')}:3306/"
        f"{os.getenv('DB_NAME')}"
    )
    engine = create_engine(DATABASE_URL)
    SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
    Base = declarative_base()

    class Employee(Base):
        __tablename__ = 'employees'
        employee_id = Column(Integer, primary_key=True, autoincrement=True)
        first_name = Column(String(50), nullable=False)
        last_name = Column(String(50), nullable=False)
        hire_date = Column(Date, nullable=False)
        job_id = Column(String(10), nullable=False)
        salary = Column(DECIMAL(10, 2), nullable=False)
        department_id = Column(Integer, ForeignKey('departments.department_id'))

    session = SessionLocal()
    try:
        # 매핑 딕셔너리 리스트
        data_to_insert = [
            {'first_name': 'Ivan', 'last_name': 'Petrov', 'hire_date': datetime.date(2024, 8, 1), 'job_id': 'DEV', 'salary': 71000.00, 'department_id': 1},
            {'first_name': 'Julia', 'last_name': 'Sidorova', 'hire_date': datetime.date(2024, 8, 5), 'job_id': 'HR', 'salary': 59000.00, 'department_id': 2},
        ]
        session.bulk_insert_mappings(Employee, data_to_insert)
        session.commit()
        print("Inserted rows using bulk_insert_mappings.")
    finally:
        session.close()
    ```

### 1.2. 대량 데이터 업데이트/삭제

대량의 데이터를 업데이트하거나 삭제할 때도 개별 로우에 대해 쿼리를 실행하는 것은 비효율적입니다. `INSERT`와 마찬가지로 네트워크 왕복 횟수를 줄이고 데이터베이스의 부하를 최소화하는 전략이 필요합니다.

*   **`UPDATE ... WHERE IN (...)` 또는 `DELETE ... WHERE IN (...)`:** 가장 기본적인 대량 업데이트/삭제 방법입니다. 조건에 해당하는 여러 로우를 단일 쿼리로 처리하여 네트워크 왕복 횟수를 줄입니다.

*   **ORM의 `bulk_update_mappings()` 및 `bulk_delete_mappings()` (SQLAlchemy):** SQLAlchemy ORM은 대량 업데이트 및 삭제를 위한 효율적인 메서드를 제공합니다. 이들은 내부적으로 최적화된 SQL 쿼리를 생성하여 대량 작업을 수행합니다.

    ```python
    # SQLAlchemy bulk_update_mappings 예시
    from sqlalchemy.orm import sessionmaker
    from sqlalchemy import create_engine, Column, Integer, String, Date, DECIMAL, ForeignKey
    from sqlalchemy.ext.declarative import declarative_base
    import datetime
    import os
    from dotenv import load_dotenv

    load_dotenv()

    DATABASE_URL = (
        f"mysql+pymysql://{os.getenv('DB_USER')}:
        {os.getenv('DB_PASSWORD')}@"
        f"{os.getenv('DB_HOST')}:3306/"
        f"{os.getenv('DB_NAME')}"
    )
    engine = create_engine(DATABASE_URL)
    SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
    Base = declarative_base()

    class Employee(Base):
        __tablename__ = 'employees'
        employee_id = Column(Integer, primary_key=True, autoincrement=True)
        first_name = Column(String(50), nullable=False)
        last_name = Column(String(50), nullable=False)
        hire_date = Column(Date, nullable=False)
        job_id = Column(String(10), nullable=False)
        salary = Column(DECIMAL(10, 2), nullable=False)
        department_id = Column(Integer, ForeignKey('departments.department_id'))

    session = SessionLocal()
    try:
        data_to_update = [
            {'employee_id': 1, 'salary': 90000.00},
            {'employee_id': 2, 'salary': 60000.00},
        ]
        session.bulk_update_mappings(Employee, data_to_update)
        session.commit()
        print("Updated rows using bulk_update_mappings.")

        # SQLAlchemy bulk_delete_mappings 예시 (실제 사용 시 주의)
        # data_to_delete = [{'employee_id': 10}, {'employee_id': 11}]
        # session.bulk_delete_mappings(Employee, data_to_delete)
        # session.commit()
        # print("Deleted rows using bulk_delete_mappings.")

    except Exception as e:
        session.rollback()
        print(f"Error during bulk update/delete: {e}")
    finally:
        session.close()
    ```

**실무 팁: 성능 고려사항**
*   **트랜잭션:** 대량 업데이트/삭제는 반드시 단일 트랜잭션 내에서 수행되어야 합니다.
*   **잠금(Lock):** 대량 작업은 테이블이나 로우에 장시간 잠금을 유발하여 다른 트랜잭션의 성능에 영향을 줄 수 있습니다. 서비스 사용량이 적은 시간대에 실행하거나, 작은 배치 단위로 나누어 실행하는 것이 좋습니다.
*   **인덱스:** `WHERE` 절에 사용되는 컬럼에 인덱스가 잘 구축되어 있어야 효율적인 업데이트/삭제가 가능합니다.

## 2. 파이썬-SQL 연동 도구 선택 가이드

`pymysql`과 `SQLAlchemy`는 파이썬에서 SQL 데이터베이스와 상호작용하는 두 가지 주요 방식입니다. 각각의 장단점을 고려하여 프로젝트의 요구사항에 맞는 도구를 선택해야 합니다.

| 구분 | `pymysql` (DB-API 드라이버) | `SQLAlchemy` (ORM) |
| :--- | :--- | :--- |
| **추상화 수준** | 낮음 (SQL 쿼리 직접 작성) | 높음 (객체 지향적 접근) |
| **성능** | 직접 SQL 작성 시 최적의 성능 가능 | 일반적으로 `pymysql`보다 약간의 오버헤드, 하지만 최적화 기능 제공 |
| **학습 곡선** | 낮음 (SQL 지식만 있으면 됨) | 높음 (ORM 개념 및 SQLAlchemy API 학습 필요) |
| **유지보수성** | SQL 쿼리 변경 시 파이썬 코드도 변경 필요 | 객체 모델 변경 시 데이터베이스 스키마 변경에 유연하게 대응 |
| **생산성** | 간단한 쿼리에는 빠름 | 복잡한 쿼리 및 대규모 프로젝트에서 생산성 높음 |
| **DBMS 독립성** | 드라이버 교체 필요 | 추상화 계층 덕분에 DBMS 변경 용이 |
| **SQL Injection** | 파라미터화 필수 (수동 관리) | 자동으로 처리 (안전) |

**선택 가이드:**
*   **`pymysql`을 선택하는 경우:** 프로젝트가 작고 간단한 SQL 쿼리만 사용하며, 최고의 성능이 중요하고 SQL 쿼리를 직접 세밀하게 제어해야 하는 경우.
*   **`SQLAlchemy`를 선택하는 경우:** 프로젝트가 크고 복잡하며, 객체 지향적인 설계가 필요하고, 데이터베이스 스키마가 자주 변경될 가능성이 있으며, 개발 생산성과 코드의 유지보수성이 중요한 경우.

**데이터 분석가를 위한 선택 가이드: `SQLAlchemy Core` vs `ORM`**
*   **`SQLAlchemy ORM`:** 웹 애플리케이션의 백엔드처럼 정형화된 CRUD 작업이 많고, 데이터베이스 테이블과 파이썬 객체를 1:1로 명확하게 매핑하여 관리하고 싶을 때 강력합니다.
*   **`SQLAlchemy Core`:** 데이터 분석가는 종종 정형화되지 않은, 탐색적이고 복잡한 쿼리를 작성해야 합니다. 이런 경우, `SQLAlchemy Core`는 SQL 구문과 거의 유사한 방식으로 파이썬 코드를 통해 유연하게 쿼리를 조립할 수 있게 해주므로, 복잡한 분석 쿼리를 작성하는 데 더 직관적이고 강력한 도구가 될 수 있습니다.

데이터 분석가에게는 두 가지 방식 모두를 이해하고, 상황에 따라 적절한 도구를 선택하여 사용하는 능력이 중요합니다.

## 3. 데이터 파이프라인 자동화: 파이썬 스크립트와 스케줄러 활용

데이터 분석 프로젝트에서 데이터 추출, 변환, 적재(ETL) 과정은 반복적으로 수행되는 경우가 많습니다. 파이썬 스크립트와 외부 스케줄러를 활용하면 이러한 데이터 파이프라인을 자동화하여 효율성을 극대화하고, 수동 작업으로 인한 오류를 줄일 수 있습니다.

**실무적 관점:** 데이터 파이프라인 자동화는 데이터 분석가가 반복적인 수작업에서 벗어나 분석과 인사이트 도출에 집중할 수 있게 하는 핵심 역량입니다. 안정적이고 효율적인 ETL 파이프라인을 구축하고 스케줄링하는 능력은 데이터의 신뢰성을 확보하고, 비즈니스 의사결정을 위한 최신 데이터를 적시에 제공하는 데 필수적입니다.

### 3.1. 데이터 파이프라인의 구성 요소

일반적인 데이터 파이프라인은 다음과 같은 단계로 구성됩니다.

1.  **데이터 추출 (Extract):** 원본 데이터베이스, API, 파일 등에서 데이터를 가져옵니다.
2.  **데이터 변환 (Transform):** 추출된 데이터를 분석 목적에 맞게 정제, 가공, 통합합니다.
3.  **데이터 적재 (Load):** 변환된 데이터를 분석용 데이터베이스, 데이터 웨어하우스, 또는 파일 시스템에 저장합니다.

### 3.2. 파이썬 스크립트를 이용한 ETL 구현

파이썬은 다양한 라이브러리(Pandas, SQLAlchemy, requests 등)를 통해 ETL 각 단계를 유연하게 구현할 수 있습니다.

**실무 팁: 데이터 파이프라인의 견고성 - 멱등성(Idempotency)과 데이터 일관성**
데이터 파이프라인은 네트워크 오류, 시스템 장애, 데이터 문제 등 예상치 못한 오류 상황에 직면할 수 있습니다. 이러한 상황에서 파이프라인을 재실행하더라도 데이터의 중복, 누락, 불일치와 같은 문제가 발생하지 않도록 **멱등성(Idempotency)**을 갖추는 것이 중요합니다.

**멱등성 확보 전략:**
1.  **`TRUNCATE TABLE` 후 `INSERT INTO ... SELECT` (전체 재적재):** 가장 간단한 멱등성 전략입니다. 대상 테이블의 모든 데이터를 삭제한 후, 원본 데이터로부터 전체 데이터를 다시 계산하여 적재합니다.
2.  **`INSERT ... ON DUPLICATE KEY UPDATE` (Upsert):** 데이터를 삽입하려 할 때 `PRIMARY KEY` 또는 `UNIQUE` 제약조건에 의해 중복이 발생하면, 삽입 대신 기존 로우를 업데이트하는 방식입니다.
3.  **`DELETE` 후 `INSERT` (특정 기간/조건 데이터):** 특정 기간이나 조건에 해당하는 기존 데이터를 먼저 삭제한 후, 새로운 데이터를 삽입하는 방식입니다.

**파이썬 ETL 스크립트 예시 (`etl_script.py`):**

```python
import pandas as pd
from sqlalchemy import create_engine
import os
from dotenv import load_dotenv
import logging
import time # 재시도 대기 시간용

# 로깅 설정
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

load_dotenv()

DATABASE_URL = (
    f"mysql+pymysql://{os.getenv('DB_USER')}:
    {os.getenv('DB_PASSWORD')}@"
    f"{os.getenv('DB_HOST')}:3306/"
    f"{os.getenv('DB_NAME')}"
)

def run_etl():
    logging.info("ETL process started.")
    engine = None
    try:
        engine = create_engine(DATABASE_URL)

        # 1. 데이터 추출 (Extract)
        logging.info("Extracting data from employees table...")
        df_employees = pd.read_sql("SELECT employee_id, first_name, last_name, salary, hire_date FROM employees", engine)
        logging.info(f"Extracted {len(df_employees)} rows.")

        # 2. 데이터 변환 (Transform)
        logging.info("Transforming data...")
        df_employees['full_name'] = df_employees['first_name'] + ' ' + df_employees['last_name']
        df_employees['hire_year'] = pd.to_datetime(df_employees['hire_date']).dt.year
        df_employees['salary_usd'] = df_employees['salary'] * 0.75 # 가상의 환율 적용
        df_transformed = df_employees[['employee_id', 'full_name', 'hire_year', 'salary_usd']]
        logging.info("Data transformation complete.")

        # 3. 데이터 적재 (Load)
        # 새로운 테이블에 적재하거나, 기존 테이블 업데이트/교체
        target_table_name = 'transformed_employee_data'
        logging.info(f"Loading transformed data into {target_table_name} table...")
        df_transformed.to_sql(target_table_name, engine, if_exists='replace', index=False, method='multi')
        logging.info("Data loading complete.")

    except Exception as e:
        logging.error(f"ETL process failed: {e}")
        # 알림 전송 (예: Slack, 이메일)
        # send_notification(f"ETL Pipeline Failed: {e}", "critical")
        # 실패 시 재시도 로직 (간단한 예시)
        for i in range(3):
            try:
                logging.warning(f"Retrying ETL process... Attempt {i+1}")
                time.sleep(2**i) # 2, 4, 8초 대기
                # run_etl() # 재귀 호출 또는 별도 함수 호출 (주의: 무한 재귀 방지)
                # 실제로는 이 부분을 함수로 분리하여 호출하는 것이 좋습니다.
                # 예: _execute_etl_step(engine, df_employees)
                logging.info(f"Retry {i+1} successful.")
                break
            except Exception as retry_e:
                logging.error(f"Retry {i+1} failed: {retry_e}")
        else:
            logging.critical("ETL process failed after multiple retries.")

    finally:
        if engine:
            engine.dispose() # 연결 풀 닫기
        logging.info("ETL process finished.")

if __name__ == "__main__":
    run_etl()
```

### 3.3. 스케줄러를 이용한 자동화

작성된 파이썬 ETL 스크립트는 다양한 스케줄러를 통해 정기적으로 자동 실행될 수 있습니다. 스케줄러의 선택은 파이프라인의 복잡성, 규모, 의존성, 그리고 운영 환경에 따라 달라집니다.

1.  **Cron (Linux/macOS):** 가장 기본적인 스케줄러로, 특정 시간에 명령을 실행하도록 설정할 수 있습니다. 간단한 단일 스크립트 실행에 적합합니다.
2.  **Windows Task Scheduler:** Windows 환경에서 스크립트를 예약 실행할 수 있는 GUI 기반 도구입니다.
3.  **Apache Airflow:** 복잡한 데이터 파이프라인을 정의, 스케줄링, 모니터링하는 데 사용되는 **워크플로우 관리 플랫폼**입니다. DAG(Directed Acyclic Graph) 형태로 워크플로우를 시각화하고 관리할 수 있어 대규모 ETL 작업에 가장 적합합니다.
4.  **Luigi:** 데이터 파이프라인의 의존성을 관리하고, 실패 시 재시작, 로깅 등을 지원하는 파이썬 라이브러리입니다.
5.  **클라우드 기반 스케줄러:** AWS Lambda, Google Cloud Functions, Azure Functions와 같은 서버리스 함수와 Cloud Scheduler, EventBridge 등의 서비스를 조합하여 클라우드 환경에서 ETL 작업을 스케줄링할 수 있습니다.

**자동화의 이점:**
*   **반복 작업 제거:** 수동으로 데이터를 처리하는 시간을 절약하고 인적 오류를 줄입니다.
*   **데이터 최신성 유지:** 정기적인 업데이트를 통해 분석에 항상 최신 데이터를 활용할 수 있습니다.
*   **확장성:** 파이프라인이 복잡해지거나 데이터 볼륨이 증가해도 유연하게 대응할 수 있습니다.
*   **모니터링 및 알림:** 스케줄러와 로깅 시스템을 통해 파이프라인의 실행 상태를 모니터링하고, 실패 시 알림을 받을 수 있어 문제 발생 시 신속한 대응이 가능합니다.
*   **데이터 거버넌스:** 자동화된 파이프라인은 데이터 처리 과정을 표준화하고 문서화하는 데 도움이 되어 데이터 거버넌스를 강화합니다.
