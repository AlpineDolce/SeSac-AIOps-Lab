## 2. 내장 함수: 데이터 가공의 기술

SQL 내장 함수는 데이터를 조회하는 과정에서 값을 계산하거나, 형식을 변경하거나, 특정 정보를 추출하는 등 다양한 데이터 가공 작업을 수행할 수 있도록 돕습니다. 이는 데이터 분석가가 원본 데이터를 분석에 적합한 형태로 변환하고, 비즈니스 로직을 쿼리 내에서 구현하는 데 필수적입니다.

**실무적 관점:** 현업의 데이터는 완벽하게 정제되어 있지 않습니다. 불완전하거나 일관되지 않은 형태로 존재하며, 때로는 분석 목적에 맞게 새로운 형태로 가공해야 합니다. 내장 함수를 능숙하게 활용하는 것은 데이터 클렌징, 파생 변수 생성, 복잡한 비즈니스 규칙 적용 등 데이터 분석가의 핵심 역량입니다.

### 2.1. 문자열 함수: 텍스트 데이터의 정제와 변환

문자열 데이터는 가장 흔하게 접하는 데이터 타입 중 하나이며, 분석을 위해 다양한 형태로 정제하고 변환해야 합니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `CONCAT(str1, str2, ...)` | 여러 문자열을 연결 | `CONCAT('Hello', ' ', 'World')` | `'Hello World'` |
| `LENGTH(str)` | 문자열의 길이 (바이트) | `LENGTH('SQL')` | `3` |
| `CHAR_LENGTH(str)` | 문자열의 길이 (문자 수) | `CHAR_LENGTH('한글')` | `2` |
| `SUBSTRING(str, pos, len)` | 문자열의 부분 문자열 추출 | `SUBSTRING('Database', 4, 3)` | `'aba'` |
| `SUBSTRING_INDEX(str, delimiter, count)` | 구분자를 기준으로 문자열을 분리하여 특정 부분 추출 | `SUBSTRING_INDEX('apple.banana.com', '.', 2)` | `'apple.banana'` |
| `REPLACE(str, from_str, to_str)` | 문자열 내의 특정 부분을 다른 문자열로 교체 | `REPLACE('Hello World', 'World', 'SQL')` | `'Hello SQL'` |
| `TRIM([BOTH/LEADING/TRAILING] [remstr FROM] str)` | 문자열의 양쪽 끝, 앞, 뒤에서 특정 문자(기본 공백) 제거 | `TRIM('  SQL  ')` | `'SQL'` |
| `UPPER(str)` | 문자열을 대문자로 변환 | `UPPER('sql')` | `'SQL'` |
| `LOWER(str)` | 문자열을 소문자로 변환 | `LOWER('SQL')` | `'sql'` |
| `LEFT(str, len)` | 문자열의 왼쪽에서 `len`만큼 추출 | `LEFT('Database', 4)` | `'Data'` |
| `RIGHT(str, len)` | 문자열의 오른쪽에서 `len`만큼 추출 | `RIGHT('Database', 4)` | `'base'` |
| `INSTR(str, substr)` | 문자열 내에서 부분 문자열의 시작 위치 반환 | `INSTR('example@email.com', '@')` | `8` |
| `LPAD(str, len, padstr)` | 문자열을 `len` 길이로 만들고 왼쪽에 `padstr`로 채움 | `LPAD('123', 5, '0')` | `'00123'` |
| `RPAD(str, len, padstr)` | 문자열을 `len` 길이로 만들고 오른쪽에 `padstr`로 채움 | `RPAD('abc', 5, '-')` | `'abc--'` |
| `FORMAT(X, D)` | 숫자를 `D`자리까지 반올림하고 콤마 형식의 문자열로 변환 | `FORMAT(12345.678, 2)` | `'12,345.68'` |

```sql
-- 직원 이름과 성을 합쳐서 전체 이름 컬럼 생성
SELECT CONCAT(first_name, ' ', last_name) AS full_name, email
FROM employees;

-- 이메일 주소에서 도메인 부분만 추출 (예: 'example.com')
SELECT email, SUBSTRING_INDEX(SUBSTRING_INDEX(email, '@', -1), '.', 1) AS domain_name
FROM employees;

-- job_id에서 '_'를 공백으로 교체하고 대문자로 변환
SELECT job_id, REPLACE(UPPER(job_id), '_', ' ') AS formatted_job_title
FROM employees;

-- 상품 코드에 접두사 'PROD-'를 붙이고 총 10자리로 맞추기 (왼쪽 0으로 채움)
SELECT product_id, LPAD(CONCAT('PROD-', product_id), 10, '0') AS formatted_product_id
FROM products;

-- 급여를 콤마가 포함된 문자열로 포맷팅
SELECT employee_id, salary, FORMAT(salary, 0) AS formatted_salary
FROM employees;
```

**실무 팁: 문자열 데이터 정제 및 분석 전략**
*   **공백 제거 및 대소문자 통일:** 사용자 입력 오류나 데이터 수집 과정에서 발생하는 불필요한 공백(`TRIM()`)이나 일관성 없는 대소문자(`UPPER()`, `LOWER()`)는 데이터 분석의 정확성을 해칩니다. `WHERE` 절이나 `JOIN` 조건에서 비교하기 전에 반드시 통일하는 습관을 들여야 합니다.
    ```sql
    -- 컬럼 값의 앞뒤 공백 제거 및 대문자 통일
    UPDATE products SET product_name = UPPER(TRIM(product_name));
    ```
*   **특정 문자/패턴 제거 또는 교체:** 데이터 내에 분석에 방해가 되는 특수 문자나 패턴이 있을 수 있습니다. `REPLACE()` 함수를 사용하여 이를 제거하거나 다른 문자로 교체합니다. 더 복잡한 패턴은 `REGEXP_REPLACE` (MySQL 8.0 이상)를 고려합니다.
    ```sql
    -- 전화번호에서 하이픈 제거 (숫자만 남기기)
    UPDATE employees SET phone_number = REPLACE(REPLACE(REPLACE(phone_number, '-', ''), '(', ''), ')', '');

    -- (MySQL 8.0+) 숫자와 영문자만 남기고 모든 특수문자 제거
    SELECT REGEXP_REPLACE('Hello!@#World123', '[^a-zA-Z0-9]', '') AS cleaned_string;
    ```
*   **데이터 파싱 및 추출:** `SUBSTRING()`, `INSTR()`, `SUBSTRING_INDEX()` 등을 활용하여 이메일 주소에서 도메인을 추출하거나, 복합적인 코드에서 특정 정보를 파싱하는 등 필요한 부분만 정확히 추출합니다.
*   **`GROUP_CONCAT(expr)` (MySQL 특화):** `GROUP BY` 절과 함께 사용하여 그룹 내의 문자열 값을 하나의 문자열로 연결합니다. 이는 그룹별로 특정 속성들의 목록을 요약할 때 매우 유용합니다. (표준 SQL의 `STRING_AGG`와 유사)
    ```sql
    -- 부서별 직원 이름 목록을 콤마로 구분하여 조회
    SELECT
        d.department_name,
        GROUP_CONCAT(e.first_name ORDER BY e.first_name SEPARATOR ', ') AS employee_names
    FROM
        departments d
    JOIN
        employees e ON d.department_id = e.department_id
    GROUP BY
        d.department_name;
    ```
*   **정렬 및 비교 시 `COLLATE`:** 문자열 비교나 정렬 시 대소문자를 구분하지 않으려면 `COLLATE` 절을 사용하여 적절한 콜레이션(collation)을 지정할 수 있습니다. (예: `WHERE column_name COLLATE utf8mb4_general_ci = 'value'`)

### 2.2. 숫자 함수: 정량적 데이터의 계산과 분석

숫자 데이터는 계산, 통계, 비율 분석 등 정량적인 분석에 필수적입니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `ROUND(X, D)` | `X`를 소수점 `D`자리까지 반올림 (D 생략 시 정수) | `ROUND(123.456, 2)` | `123.46` |
| `CEIL(X)` | `X`보다 크거나 같은 가장 작은 정수 (올림) | `CEIL(123.45)` | `124` |
| `FLOOR(X)` | `X`보다 작거나 같은 가장 큰 정수 (내림) | `FLOOR(123.45)` | `123` |
| `TRUNCATE(X, D)` | `X`를 소수점 `D`자리에서 잘라냄 (반올림 없음) | `TRUNCATE(123.456, 2)` | `123.45` |
| `ABS(X)` | `X`의 절댓값 | `ABS(-10)` | `10` |
| `MOD(N, M)` | `N`을 `M`으로 나눈 나머지 (주기성 분석 등에 활용) | `MOD(10, 3)` | `1` |
| `POW(X, Y)` / `POWER(X, Y)` | `X`의 `Y` 제곱 | `POW(2, 3)` | `8` |
| `SQRT(X)` | `X`의 제곱근 | `SQRT(9)` | `3` |
| `SIGN(X)` | `X`의 부호 (-1, 0, 1) | `SIGN(-5)` | `-1` |
| `GREATEST(val1, val2, ...)` | 인자 중 가장 큰 값 반환 | `GREATEST(10, 20, 5)` | `20` |
| `LEAST(val1, val2, ...)` | 인자 중 가장 작은 값 반환 | `LEAST(10, 20, 5)` | `5` |

```sql
-- 급여를 소수점 첫째 자리에서 반올림
SELECT employee_id, salary, ROUND(salary) AS rounded_salary
FROM employees;

-- 급여를 10000으로 나눈 나머지를 계산 (예: 급여 등급 분류에 활용)
SELECT employee_id, salary, MOD(salary, 10000) AS salary_remainder
FROM employees;

-- 판매 가격에서 세금(10%)을 제외한 순수익 계산 (소수점 2자리에서 잘라냄)
SELECT order_id, total_amount, TRUNCATE(total_amount / 1.1, 2) AS net_income
FROM orders;

-- 최소 급여와 최대 급여를 비교하여 더 큰 값 선택
SELECT employee_id, salary, GREATEST(salary, 50000) AS adjusted_salary
FROM employees;
```

**실무 팁: 숫자 데이터 처리 시 주의사항 및 활용**
*   **부동 소수점 정밀도:** `FLOAT`나 `DOUBLE`과 같은 부동 소수점 타입은 미세한 오차를 가질 수 있습니다. 금융 계산과 같이 1원의 오차도 허용되지 않는 정밀한 계산이 필요한 경우에는 반드시 **`DECIMAL` (또는 `NUMERIC`) 타입을 사용**해야 합니다.
*   **반올림 규칙:** `ROUND` 함수는 데이터베이스 시스템마다 반올림 규칙(예: 0.5를 올릴지, 가장 가까운 짝수로 반올림할지)이 다를 수 있으므로, 특정 규칙이 필요하다면 명시적으로 구현해야 합니다.
*   **오버플로우/언더플로우:** 숫자 타입의 범위를 초과하는 값을 저장하려 하면 오버플로우(Overflow)가 발생할 수 있습니다. 반대로 너무 작은 값을 저장하려 하면 언더플로우(Underflow)가 발생할 수 있습니다. 컬럼의 데이터 타입을 신중하게 선택해야 합니다.
*   **`NULL` 값과 숫자 연산:** 숫자 컬럼에 `NULL`이 포함되어 있으면 연산 결과가 `NULL`이 될 수 있습니다. `COALESCE`나 `IFNULL`을 사용하여 `NULL`을 0 또는 다른 기본값으로 대체한 후 연산을 수행해야 합니다.
    ```sql
    -- commission_pct가 NULL이면 0으로 간주하여 최종 급여 계산
    SELECT employee_id, salary, COALESCE(commission_pct, 0) AS commission,
           salary * (1 + COALESCE(commission_pct, 0)) AS final_salary
    FROM employees;
    ```
*   **비율 및 백분율 계산:** 숫자 함수를 활용하여 성장률, 전환율, 점유율 등 다양한 비즈니스 지표를 계산할 수 있습니다.

### 2.3. 날짜 및 시간 함수: 시계열 데이터의 분석과 관리

날짜와 시간 데이터는 시계열 분석, 기간 계산, 이벤트 스케줄링 등 다양한 분석 및 애플리케이션 로직에 필수적입니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `NOW()` | 현재 날짜와 시간 (DATETIME) | `NOW()` | `2025-05-20 10:30:00` |
| `CURDATE()` | 현재 날짜 (DATE) | `CURDATE()` | `2025-05-20` |
| `CURTIME()` | 현재 시간 (TIME) | `CURTIME()` | `10:30:00` |
| `DATE_FORMAT(date, format)` | 날짜/시간을 지정된 형식의 문자열로 변환 | `DATE_FORMAT(NOW(), '%Y년 %m월 %d일')` | `'2025년 05월 20일'` |
| `STR_TO_DATE(str, format)` | 문자열을 지정된 형식에 따라 날짜/시간으로 변환 | `STR_TO_DATE('2025-05-20', '%Y-%m-%d')` | `2025-05-20` |
| `DATEDIFF(date1, date2)` | 두 날짜 간의 일수 차이 (`date1 - date2`) | `DATEDIFF('2025-05-20', '2025-05-10')` | `10` |
| `TIMESTAMPDIFF(unit, datetime_expr1, datetime_expr2)` | 두 날짜/시간 간의 지정된 단위(YEAR, MONTH, DAY, HOUR, MINUTE, SECOND) 차이 | `TIMESTAMPDIFF(MONTH, '2023-01-01', '2025-05-20')` | `28` |
| `DATE_ADD(date, INTERVAL expr unit)` | 날짜에 시간 간격을 더함 | `DATE_ADD(CURDATE(), INTERVAL 7 DAY)` | `CURDATE()`로부터 7일 후 |
| `DATE_SUB(date, INTERVAL expr unit)` | 날짜에서 시간 간격을 뺌 | `DATE_SUB(CURDATE(), INTERVAL 1 MONTH)` | `CURDATE()`로부터 1개월 전 |
| `YEAR(date)`, `MONTH(date)`, `DAY(date)` | 날짜에서 연도, 월, 일 추출 | `YEAR('2025-05-20')` | `2025` |
| `WEEK(date)` / `WEEKOFYEAR(date)` | 연간 주차 | `WEEK('2025-01-01')` | `0` 또는 `1` |
| `DAYOFWEEK(date)` | 요일 (1=일요일, ..., 7=토요일) | `DAYOFWEEK('2025-05-20')` | `3` (화요일) |
| `DAYNAME(date)` | 요일 이름 (예: 'Tuesday') | `DAYNAME('2025-05-20')` | `'Tuesday'` |
| `QUARTER(date)` | 분기 (1-4) | `QUARTER('2025-05-20')` | `2` |
| `LAST_DAY(date)` | 해당 월의 마지막 날짜 | `LAST_DAY('2025-02-15')` | `2025-02-28` |

```sql
-- 직원의 고용 기간 (일수) 계산
SELECT employee_id, first_name, hire_date, DATEDIFF(CURDATE(), hire_date) AS days_employed
FROM employees;

-- 직원의 고용 연도와 월 추출
SELECT employee_id, first_name, YEAR(hire_date) AS hire_year, MONTH(hire_date) AS hire_month
FROM employees;

-- 현재 날짜를 'YYYY-MM-DD HH:MM:SS' 형식으로 출력
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s') AS current_datetime;

-- 주문일로부터 30일 후의 배송 예정일 계산
SELECT order_id, order_date, DATE_ADD(order_date, INTERVAL 30 DAY) AS estimated_delivery_date
FROM orders;

-- 특정 날짜의 요일 이름 조회
SELECT CURDATE(), DAYNAME(CURDATE()) AS current_day_name;

-- 각 직원이 고용된 요일별 직원 수
SELECT DAYNAME(hire_date) AS hire_day_of_week, COUNT(*) AS employee_count
FROM employees
GROUP BY hire_day_of_week
ORDER BY employee_count DESC;
```

**실무 팁: 날짜 및 시간 데이터 분석 전략**
*   **기간 계산 및 시차 분석:** `DATEDIFF()`, `TIMESTAMPDIFF()`, `DATE_ADD()`, `DATE_SUB()`를 활용하여 고객의 서비스 이용 기간, 특정 이벤트 간의 시간 간격, 예상 완료일 등을 계산합니다.
*   **시계열 데이터 집계:** `YEAR()`, `MONTH()`, `DAY()`, `WEEK()`, `QUARTER()` 등을 사용하여 날짜/시간 컬럼을 연도, 월, 일, 주차, 분기 등으로 분할하여 `GROUP BY` 절에서 시계열 분석의 기준으로 활용합니다.
    ```sql
    -- 월별 매출 합계
    SELECT DATE_FORMAT(order_date, '%Y-%m') AS sales_month, SUM(total_amount) AS monthly_sales
    FROM orders
    GROUP BY sales_month
    ORDER BY sales_month;
    ```
*   **타임존 고려 (`DATETIME` vs `TIMESTAMP`):**
    *   `DATETIME`: 서버의 타임존에 영향을 받지 않고 입력된 값을 그대로 저장합니다. 특정 지역에 고정된 시간 정보를 저장할 때 적합합니다.
    *   `TIMESTAMP`: UTC 기준으로 저장되며, 조회 시 클라이언트의 타임존에 맞춰 변환됩니다. 전 세계 사용자를 대상으로 하는 서비스나, 타임존 변환이 필요한 경우에 사용합니다. **일반적으로 `TIMESTAMP` 사용을 권장**하며, 애플리케이션 레벨에서 타임존 처리를 명확히 해야 합니다.
*   **날짜/시간 형식 변환:** `DATE_FORMAT()`과 `STR_TO_DATE()`를 사용하여 날짜/시간 데이터를 다양한 형식의 문자열로 변환하거나, 문자열을 날짜/시간 타입으로 파싱합니다. 이는 데이터 통합이나 보고서 생성 시 유용합니다.
*   **날짜/시간 범위 쿼리 최적화:** `WHERE` 절에서 날짜/시간 컬럼을 필터링할 때, 인덱스를 활용할 수 있도록 함수 사용에 유의해야 합니다. (예: `WHERE DATE(column) = '...'` 보다는 `WHERE column BETWEEN '...' AND '...'` 또는 `WHERE column >= '...' AND column < '...' + INTERVAL 1 DAY`가 인덱스 활용에 유리)

### 2.4. 형 변환 함수 (`CAST`, `CONVERT`): 데이터 타입의 유연한 관리

데이터 타입을 다른 타입으로 명시적으로 변환할 때 사용합니다. 데이터 타입 불일치로 인한 오류를 방지하거나, 특정 연산을 수행하기 위해 필요합니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `CAST(expression AS type)` | 표현식을 지정된 타입으로 변환 (표준 SQL) | `CAST('123' AS SIGNED INTEGER)` | `123` (정수) |
| `CONVERT(expression, type)` | `CAST`와 유사하게 표현식을 지정된 타입으로 변환 (MySQL 특화) | `CONVERT('123.45', DECIMAL(5,2))` | `123.45` (DECIMAL) |

```sql
-- 문자열을 숫자로 변환하여 계산
SELECT '100' + 200; -- 결과: 300 (암시적 변환)
SELECT CAST('100' AS SIGNED INTEGER) + 200; -- 결과: 300 (명시적 변환)

-- 숫자를 문자열로 변환하여 연결
SELECT CONCAT('Salary: ', CAST(salary AS CHAR)) AS employee_salary_text
FROM employees;

-- 날짜를 특정 형식의 문자열로 변환
SELECT CAST(CURDATE() AS CHAR) AS current_date_str; -- 'YYYY-MM-DD' 형식의 문자열

-- 문자열 'TRUE'를 불리언(1)으로 변환
SELECT CAST('TRUE' AS BOOLEAN); -- 결과: 1
```

**실무적 관점: 명시적 vs 암시적 변환 (Implicit vs. Explicit Conversion)**
*   **암시적 변환 (Implicit Conversion):** 데이터베이스 시스템이 쿼리 실행 중 자동으로 데이터 타입을 변환하는 경우입니다. 편리할 수 있지만, **예상치 못한 결과나 심각한 성능 저하를 유발할 수 있습니다.** 특히 `JOIN` 조건이나 `WHERE` 절에서 암시적 변환이 발생하면 해당 컬럼에 인덱스가 있더라도 인덱스를 사용하지 못하게 되어 쿼리 성능이 심각하게 저하될 수 있습니다.
    ```sql
    -- 암시적 변환으로 인한 인덱스 미사용 예시 (salary 컬럼에 인덱스가 있어도 사용 안 될 수 있음)
    SELECT * FROM employees WHERE salary = '60000'; -- 문자열 '60000'과 숫자 salary 비교
    ```
*   **명시적 변환 (Explicit Conversion):** `CAST()` 또는 `CONVERT()` 함수를 사용하여 개발자가 직접 데이터 타입을 지정하여 변환합니다. 이는 데이터 타입 불일치로 인한 오류를 방지하고, 쿼리의 의도를 명확히 하며, 성능 저하를 피하는 데 중요합니다.
    ```sql
    -- 명시적 변환으로 인덱스 활용 가능성 높임
    SELECT * FROM employees WHERE salary = CAST('60000' AS DECIMAL);
    ```

**핵심 습관:** 항상 데이터 타입의 일관성을 유지하고, 필요할 때는 **명시적 변환을 사용하는 습관**을 들이는 것이 중요합니다. `EXPLAIN` 명령을 통해 쿼리 실행 계획을 확인하여 암시적 변환으로 인한 성능 문제가 발생하는지 주기적으로 확인해야 합니다. 데이터 로딩 시에도 원본 데이터의 타입을 정확히 파악하고 대상 테이블의 컬럼 타입과 일치시키거나 명시적으로 변환해야 합니다.

### 2.5. 조건 함수 (`IF`, `IFNULL`, `NULLIF`, `COALESCE`): 비즈니스 로직의 구현

쿼리 내에서 조건부 로직을 구현할 때 사용합니다. 데이터의 특정 상태에 따라 다른 값을 반환하거나 `NULL` 값을 처리하는 데 활용됩니다. `CASE` 문은 SQL에서 가장 강력하고 유연한 조건부 표현식으로, 복잡한 비즈니스 로직 구현에 필수적입니다. `CASE` 문에 대한 자세한 내용은 [06_서브쿼리와_CASE.md](./06_서브쿼리와_CASE.md)를 참조하세요.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `IF(condition, value_if_true, value_if_false)` | 조건이 참이면 첫 번째 값, 거짓이면 두 번째 값 반환 | `IF(10 > 5, 'True', 'False')` | `'True'` |
| `IFNULL(expr1, expr2)` | `expr1`이 `NULL`이 아니면 `expr1` 반환, `NULL`이면 `expr2` 반환 | `IFNULL(phone_number, 'N/A')` | `phone_number`가 `NULL`이면 `'N/A'` |
| `NULLIF(expr1, expr2)` | `expr1`과 `expr2`가 같으면 `NULL` 반환, 다르면 `expr1` 반환 | `NULLIF(salary, 0)` | `salary`가 0이면 `NULL` |
| `COALESCE(expr1, expr2, ...)` | 인자로 전달된 표현식들 중에서 첫 번째로 `NULL`이 아닌 값을 반환 | `COALESCE(phone_number, email, 'N/A')` | `phone_number`가 `NULL`이면 `email`을, `email`도 `NULL`이면 `'N/A'`를 반환 |

```sql
-- 급여가 60000 이상이면 'High', 아니면 'Low'로 분류
SELECT first_name, salary, IF(salary >= 60000, 'High', 'Low') AS salary_level
FROM employees;

-- phone_number가 NULL인 경우 'No Phone'으로 표시
SELECT first_name, IFNULL(phone_number, 'No Phone') AS contact_phone
FROM employees;

-- phone_number가 NULL이면 email을, email도 NULL이면 'N/A'를 반환
SELECT
    employee_id, first_name,
    COALESCE(phone_number, email, 'N/A') AS contact_info
FROM employees;

-- 판매량이 0이면 '재고 없음', 아니면 판매량 표시
SELECT product_name, NULLIF(stock_quantity, 0) AS available_stock
FROM products;
```

**실무 팁: 조건 함수 활용 및 `NULL` 처리의 중요성**
*   **`IF()` vs `CASE`:** `IF()` 함수는 MySQL에 특화된 간결한 조건 함수입니다. 하지만 복잡한 다중 조건이나 표준 SQL을 지향한다면 `CASE` 문을 사용하는 것이 더 유연하고 이식성이 높습니다. `CASE` 문은 데이터 분류, 조건부 집계 등 다양한 비즈니스 로직 구현에 필수적이므로, [06_서브쿼리와_CASE.md](./06_서브쿼리와_CASE.md)에서 심층적으로 학습하는 것을 권장합니다.
*   **`NULL` 처리:** `IFNULL()`과 `COALESCE()`는 `NULL` 값을 다른 값으로 대체하여 계산이나 보고서 출력 시 `NULL`로 인한 문제를 방지하는 데 필수적입니다. `COALESCE()`는 여러 대안 값을 순차적으로 검사할 수 있어 더 강력합니다.
*   **데이터 클렌징:** 조건 함수는 데이터 클렌징 과정에서 특정 조건에 따라 데이터를 수정하거나 분류하는 데 유용하게 사용됩니다.
*   **분석 오류 방지:** `NULL`은 비교 연산에서 `UNKNOWN`을 반환하므로, `WHERE column = NULL`과 같은 조건은 작동하지 않습니다. 반드시 `IS NULL` 또는 `IS NOT NULL`을 사용해야 합니다.
*   **보고서 가독성 향상:** `NULL` 값을 사용자 친화적인 문자열(예: 'N/A', '미정')로 대체하여 보고서의 가독성을 높입니다.
*   **계산의 정확성:** 집계 함수는 기본적으로 `NULL`을 제외하고 계산합니다. `NULL`을 특정 값(예: 0)으로 간주하여 계산에 포함시켜야 할 때는 `COALESCE` 등을 사용하여 `NULL` 값을 대체한 후 집계 함수를 적용해야 합니다.

### 2.6. JSON 함수

MySQL 5.7 이상에서 지원하는 JSON 데이터 타입과 관련된 함수들입니다. 반정형 데이터를 쿼리하고 조작하는 데 사용되며, 유연한 스키마를 가진 데이터를 다룰 때 매우 유용합니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `JSON_EXTRACT(json_doc, path)` | JSON 문서에서 특정 경로의 값 추출 | `JSON_EXTRACT('{"name": "Alice"}', '$.name')` | `"Alice"` |
| `JSON_UNQUOTE(json_val)` | JSON 문자열에서 따옴표 제거 | `JSON_UNQUOTE('"Alice" ')` | `'Alice'` |
| `JSON_SET(json_doc, path, val, ...)` | JSON 문서에 값을 추가하거나 기존 값을 업데이트 | `JSON_SET('{"a": 1}', '$.b', 2)` | `{"a": 1, "b": 2}` |
| `JSON_INSERT(json_doc, path, val, ...)` | JSON 문서에 값을 추가 (기존 경로에 값이 있으면 무시) | `JSON_INSERT('{"a": 1}', '$.a', 2)` | `{"a": 1}` |
| `JSON_REPLACE(json_doc, path, val, ...)` | JSON 문서의 기존 값을 업데이트 (경로에 값이 없으면 무시) | `JSON_REPLACE('{"a": 1}', '$.a', 2)` | `{"a": 2}` |
| `JSON_REMOVE(json_doc, path, ...)` | JSON 문서에서 특정 경로의 값 제거 | `JSON_REMOVE('{"a": 1, "b": 2}', '$.b')` | `{"a": 1}` |
| `JSON_ARRAY_APPEND(json_doc, path, val, ...)` | JSON 배열에 값 추가 | `JSON_ARRAY_APPEND('[1, 2]', '$', 3)` | `[1, 2, 3]` |
| `JSON_OBJECT(key, val, ...)` | 키-값 쌍으로 JSON 객체 생성 | `JSON_OBJECT('name', 'Bob', 'age', 30)` | `{"name": "Bob", "age": 30}` |
| `JSON_ARRAY(val, ...)` | 값으로 JSON 배열 생성 | `JSON_ARRAY('apple', 'banana')` | `["apple", "banana"]` |
| `JSON_CONTAINS(json_doc, json_val, path)` | JSON 문서에 특정 값이 포함되어 있는지 확인 | `JSON_CONTAINS('{"a": 1, "b": 2}', '1', '$.a')` | `1` (True) |
| `JSON_KEYS(json_doc, path)` | JSON 객체의 키를 배열로 반환 | `JSON_KEYS('{"a": 1, "b": 2}')` | `["a", "b"]` |

```sql
-- 예시: user_settings 테이블의 preferences JSON 컬럼 활용

-- JSON 컬럼에서 특정 속성 값 추출 (테마 설정)
SELECT user_id, JSON_UNQUOTE(JSON_EXTRACT(preferences, '$.theme')) AS user_theme
FROM user_settings;

-- JSON 배열에서 특정 요소가 포함된 로우 조회 (알림 설정에 이메일 알림이 활성화된 사용자)
SELECT user_id
FROM user_settings
WHERE JSON_CONTAINS(preferences, 'true', '$.notifications.email');

-- JSON 문서에 새로운 속성 추가 (언어 설정)
UPDATE user_settings
SET preferences = JSON_SET(preferences, '$.language', 'ko')
WHERE user_id = 1;

-- JSON 배열에 새로운 값 추가 (features 배열에 'Bluetooth' 추가)
-- (products 테이블에 details JSON 컬럼이 있고, features가 배열이라고 가정)
UPDATE products
SET details = JSON_ARRAY_APPEND(details, '$.features', 'Bluetooth')
WHERE product_id = 2;
```

**실무적 관점:**
*   **유연한 스키마:** `JSON` 타입은 스키마가 자주 변경되거나, 비정형 데이터를 저장할 때 매우 유용합니다. `ALTER TABLE`을 자주 수행하는 부담을 줄여줍니다.
*   **성능 고려:** `JSON` 컬럼 내의 특정 값으로 검색하거나 집계할 때는 일반 컬럼보다 성능이 떨어질 수 있습니다. 자주 검색되는 `JSON` 필드는 별도의 컬럼으로 분리하거나, `JSON` 인덱스(DBMS 지원 시)를 활용하는 것을 고려해야 합니다.
*   **데이터 모델링:** `JSON` 타입은 관계형 데이터베이스의 정규화 원칙을 일부 희생하는 대신 유연성과 개발 편의성을 제공합니다. 데이터 모델링 시 `JSON` 타입을 사용할지, 아니면 정규화된 테이블 구조를 유지할지 신중하게 결정해야 합니다.

## 3. 데이터 집계와 그룹 분석

데이터 집계는 여러 로우의 데이터를 요약하여 하나의 값으로 만드는 과정이며, `GROUP BY` 절과 함께 사용하면 특정 그룹별로 데이터를 집계하여 분석할 수 있습니다. 이는 데이터 분석에서 핵심적인 기술이자, 비즈니스 의사결정을 위한 인사이트 도출의 필수 단계입니다.

**실무적 관점:** 수많은 로우(Row) 데이터 속에서 의미 있는 패턴과 트렌드를 발견하려면 데이터를 요약하는 능력이 필수적입니다. `GROUP BY`와 `HAVING` 절은 비즈니스 질문에 대한 핵심적인 인사이트를 도출하는 데 사용되므로, 이들의 동작 원리를 정확히 이해하고 능숙하게 활용하는 것이 중요합니다.

### 3.1. 집계 함수 (Aggregate Functions): 데이터 요약의 핵심

집계 함수는 여러 로우의 값을 입력으로 받아 단일 값을 반환하는 함수입니다. `GROUP BY` 절 없이 사용하면 전체 테이블에 대해 집계하고, `GROUP BY` 절과 함께 사용하면 각 그룹별로 집계합니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `COUNT(*)` | `NULL`을 포함한 모든 로우의 수 | `COUNT(*)` | `100` |
| `COUNT(column)` | `NULL`을 제외한 특정 컬럼의 로우 수 | `COUNT(job_id)` | `95` |
| `COUNT(DISTINCT column)` | `NULL`을 제외한 특정 컬럼의 고유한 값의 수 | `COUNT(DISTINCT job_id)` | `5` |
| `SUM(column)` | 특정 컬럼 값의 합계 | `SUM(salary)` | `5000000` |
| `AVG(column)` | 특정 컬럼 값의 평균 | `AVG(salary)` | `50000` |
| `MIN(column)` | 특정 컬럼 값 중 최소값 | `MIN(salary)` | `30000` |
| `MAX(column)` | 특정 컬럼 값 중 최대값 | `MAX(salary)` | `80000` |
| `STDDEV(column)` / `STD(column)` | 표본 표준편차 | `STDDEV(salary)` | `10000` |
| `VAR(column)` / `VAR_SAMP(column)` / `VARIANCE(column)` | 표본 분산 | `VAR_SAMP(salary)` | `100000000` |
| `GROUP_CONCAT(column)` (MySQL) | 그룹 내 문자열을 연결 (표준 SQL: `STRING_AGG`) | `GROUP_CONCAT(first_name)` | `'John, Jane, Bob'` |

```sql
-- 전체 직원의 수, 평균 급여, 최고/최저 급여 조회
SELECT
    COUNT(*) AS total_employees,
    AVG(salary) AS average_salary,
    MAX(salary) AS max_salary,
    MIN(salary) AS min_salary
FROM employees;

-- 고유한 직무(job_id)의 개수와 직무별 평균 급여
SELECT
    COUNT(DISTINCT job_id) AS unique_job_count,
    job_id, AVG(salary) AS average_salary
FROM employees
GROUP BY job_id;

-- 부서별 급여의 표준편차와 분산
SELECT
    department_id,
    AVG(salary) AS avg_salary,
    STDDEV(salary) AS stddev_salary,
    VAR_SAMP(salary) AS var_salary
FROM employees
GROUP BY department_id;
```

**실무 팁: 집계 함수와 `NULL` 값 처리**
대부분의 집계 함수(`SUM`, `AVG`, `MIN`, `MAX`, `COUNT(컬럼명)`, `STDDEV`, `VAR`)는 `NULL` 값을 **자동으로 제외**하고 계산합니다. `COUNT(*)`만이 `NULL`을 포함한 모든 로우의 수를 셉니다. `NULL`을 특정 값(예: 0)으로 간주하여 집계에 포함시켜야 할 때는 `IFNULL`이나 `COALESCE` 함수를 사용하여 `NULL` 값을 대체한 후 집계 함수를 적용해야 합니다.

```sql
-- commission_pct가 NULL인 직원의 급여를 0으로 간주하여 총 급여 합계 계산
SELECT SUM(COALESCE(salary, 0)) AS total_salary_with_null_as_zero
FROM employees;
```

**실무 팁: `COUNT(DISTINCT ...)`의 성능 함정과 대안**
`COUNT(DISTINCT column_name)`은 고유한 값의 개수를 세는 데 매우 유용하지만, 일반 `COUNT(*)`보다 훨씬 많은 자원을 소모할 수 있습니다. 대규모 데이터셋에서 자주 사용해야 한다면 성능 저하를 고려해야 합니다.

*   **성능 저하 원인:** `DISTINCT` 연산을 위해 데이터베이스는 해당 컬럼의 모든 값을 읽어와 메모리나 디스크에 정렬하거나 해싱해야 합니다.
*   **실무적 대안:**
    1.  **서브쿼리와 `COUNT`:** `GROUP BY`를 사용하여 고유한 값 목록을 먼저 만든 후, 그 결과의 개수를 세는 방식입니다.
        ```sql
        SELECT COUNT(*) FROM (SELECT DISTINCT job_id FROM employees) AS unique_jobs;
        ```
    2.  **근사치 계산 (Approximate Count):** 정확한 값이 아닌, 매우 근사한 값으로도 충분한 경우 `APPROX_COUNT_DISTINCT`와 같은 함수를 사용합니다. (DBMS에 따라 지원 여부 다름)
    3.  **요약 테이블 (Pre-aggregation):** 매일 또는 매시간 배치 작업을 통해 고유 사용자 수를 미리 계산하여 요약 테이블에 저장해두는 방법입니다.

**실무 팁: 부동 소수점 연산의 위험성**
`FLOAT`나 `DOUBLE`과 같은 부동 소수점 타입은 미세한 오차가 발생할 수 있습니다. 금융 데이터와 같이 1원의 오차도 허용되지 않는 정확한 계산이 필요할 때는, 반드시 **`DECIMAL` (또는 `NUMERIC`) 데이터 타입을 사용**해야 합니다.

**실무 팁: 조건부 집계 (Conditional Aggregation)**
`CASE` 문과 집계 함수를 함께 사용하여 특정 조건에 맞는 로우에 대해서만 집계를 수행할 수 있습니다. 이는 데이터를 다양한 기준으로 분류하여 요약할 때 매우 유용합니다. MySQL에서는 `SUM(IF(condition, value_if_true, value_if_false))`와 같이 `IF()` 함수를 사용할 수도 있습니다. 표준 SQL에서는 `COUNT(*) FILTER (WHERE condition)`를 지원하는 DBMS도 많습니다.

```sql
-- 부서별 남성 직원 수와 여성 직원 수 조회
SELECT
    d.department_name,
    SUM(CASE WHEN e.gender = 'M' THEN 1 ELSE 0 END) AS male_employees,
    SUM(CASE WHEN e.gender = 'F' THEN 1 ELSE 0 END) AS female_employees,
    COUNT(*) AS total_employees
FROM
    departments d
LEFT JOIN
    employees e ON d.department_id = e.department_id
GROUP BY
    d.department_name;
```

### 3.2. `GROUP BY`: 데이터 그룹화의 원리

`GROUP BY` 절은 특정 컬럼의 값을 기준으로 로우들을 그룹으로 묶습니다. 집계 함수는 이 그룹별로 적용되어 각 그룹의 요약 값을 계산합니다. `GROUP BY` 절에 명시된 컬럼들은 `SELECT` 절에도 포함되어야 하며, `SELECT` 절의 다른 컬럼들은 반드시 집계 함수 내에 있거나 `GROUP BY` 절에 포함되어야 합니다.

```sql
-- 부서별 직원 수
SELECT department_id, COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;

-- 직무별 평균 급여
SELECT job_id, AVG(salary) AS average_salary
FROM employees
GROUP BY job_id;
```

**단일 컬럼 그룹화:** 하나의 컬럼을 기준으로 그룹을 나눕니다.

```sql
-- 고용 연도별 직원 수
SELECT YEAR(hire_date) AS hire_year, COUNT(*) AS employee_count
FROM employees
GROUP BY hire_year;
```

**다중 컬럼 그룹화:** 여러 컬럼을 조합하여 더 세분화된 그룹을 나눕니다. `GROUP BY` 절에 나열된 컬럼의 순서가 결과에 영향을 미치지는 않지만, 가독성을 위해 `ORDER BY` 절과 동일하게 정렬하는 것이 일반적입니다.

```sql
-- 부서별, 직무별 평균 급여
SELECT department_id, job_id, AVG(salary) AS average_salary
FROM employees
GROUP BY department_id, job_id
ORDER BY department_id, job_id;
```

**실무 팁: `GROUP BY` 사용 시 주의사항**
*   **`SELECT` 절의 제약:** `SELECT` 절에 오는 모든 비집계 컬럼은 반드시 `GROUP BY` 절에 포함되어야 합니다. 그렇지 않으면 SQL 에러가 발생합니다. (MySQL의 `ONLY_FULL_GROUP_BY` 모드)
*   **성능 고려:** `GROUP BY`는 데이터를 정렬하거나 해싱하는 작업을 포함하므로, 대규모 데이터셋에서는 성능에 영향을 미칠 수 있습니다. 적절한 인덱스 설정이 중요합니다.
*   **`GROUP BY`와 `ORDER BY`의 차이:** `GROUP BY`는 데이터를 그룹으로 묶는 것이고, `ORDER BY`는 결과를 정렬하는 것입니다. 두 절은 독립적으로 작동하며, `GROUP BY`가 먼저 실행된 후 `ORDER BY`가 적용됩니다.

### 3.3. `HAVING`: 그룹 필터링의 정교함

`HAVING` 절은 `GROUP BY` 절에 의해 생성된 그룹에 조건을 적용하여 필터링합니다. `WHERE` 절이 개별 로우를 필터링하는 반면, `HAVING` 절은 집계된 결과(그룹)를 필터링합니다. 즉, `HAVING` 절은 집계 함수가 적용된 결과에 조건을 걸 때 사용합니다.

```sql
-- 부서별 평균 급여가 60000 이상인 부서만 조회
SELECT department_id, AVG(salary) AS average_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) >= 60000;

-- 직무별 직원 수가 2명 이상인 직무의 평균 급여 조회
SELECT job_id, COUNT(*) AS employee_count, AVG(salary) AS average_salary
FROM employees
GROUP BY job_id
HAVING COUNT(*) >= 2;
```

**`WHERE`와 `HAVING`의 결정적인 차이점:**

| 구분 | `WHERE` 절 | `HAVING` 절 |
| :--- | :--- | :--- |
| **적용 시점** | `FROM` 절 이후, `GROUP BY` 전에 개별 로우에 적용 (데이터 필터링) | `GROUP BY` 후에 그룹화된 결과에 적용 (그룹 필터링) |
| **사용 가능 컬럼** | 원본 테이블의 모든 컬럼 | `GROUP BY` 컬럼 또는 집계 함수 결과 |
| **집계 함수 사용** | 직접 사용 불가 | 사용 가능 |
| **성능 영향** | 먼저 필터링하여 처리할 로우 수를 줄여 성능 향상 | 그룹화된 데이터에 적용되므로, `WHERE`로 먼저 필터링하는 것이 효율적 |

**실무 팁: `WHERE`와 `HAVING`의 최적화된 사용**
가능한 한 `WHERE` 절에서 먼저 데이터를 필터링하여 `GROUP BY` 연산이 처리해야 할 데이터의 양을 최소화하는 것이 성능상 가장 효율적입니다. `HAVING` 절은 `WHERE` 절로 필터링할 수 없는, 즉 집계된 결과에 대한 조건이 필요할 때만 사용합니다.

```sql
-- (비효율적) 모든 로우를 그룹화한 후 필터링
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id
HAVING department_id = 1 AND AVG(salary) >= 60000;

-- (효율적) 먼저 department_id가 1인 로우만 필터링 후 그룹화
SELECT department_id, AVG(salary)
FROM employees
WHERE department_id = 1
GROUP BY department_id
HAVING AVG(salary) >= 60000;
```

### 3.4. `WITH ROLLUP`: 그룹별 소계 및 총계 자동 생성

`WITH ROLLUP`은 `GROUP BY` 절과 함께 사용하여 그룹별 소계(Subtotal)와 전체 총계(Grand Total)를 계산하는 기능을 제공합니다. 계층적인 집계 결과를 한 번의 쿼리로 얻을 수 있어 보고서 작성 시 매우 유용합니다.

```sql
-- 부서별, 직무별 평균 급여와 소계, 총계
SELECT
    IFNULL(department_id, 'Total') AS department,
    IFNULL(job_id, 'Subtotal') AS job,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department_id, job_id WITH ROLLUP;
```

**실무 팁:** `IFNULL` 함수를 사용하여 `ROLLUP`으로 생성된 총계 로우의 `NULL` 값을 'Total'이나 'Subtotal'과 같은 의미 있는 문자열로 대체하여 가독성을 높일 수 있습니다. `GROUPING(column)` 함수를 사용하여 해당 로우가 총계 로우인지 여부를 확인할 수도 있습니다.

```sql
-- GROUPING 함수를 사용하여 총계 로우 식별
SELECT
    CASE WHEN GROUPING(department_id) = 1 THEN 'Total' ELSE department_id END AS department,
    CASE WHEN GROUPING(job_id) = 1 THEN 'Subtotal' ELSE job_id END AS job,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department_id, job_id WITH ROLLUP;
```

### 3.5. 데이터 샘플링 (Sampling): 대규모 데이터 탐색의 효율성

대규모 데이터셋을 다룰 때, 전체 데이터를 처리하는 것은 시간과 자원이 많이 소모될 수 있습니다. 이럴 때 데이터 샘플링은 전체 데이터의 특성을 대표하는 일부 데이터를 추출하여 빠르게 탐색적 분석을 수행하거나, 모델 학습을 위한 테스트 데이터를 생성하는 데 유용합니다.

```sql
-- employees 테이블에서 무작위로 10개의 로우 샘플링 (MySQL)
SELECT * FROM employees
ORDER BY RAND()
LIMIT 10;
```

**실무 팁: 효율적인 대규모 데이터 샘플링 전략**
`ORDER BY RAND()`는 테이블 전체를 읽고 정렬해야 하므로 대규모 테이블에서는 매우 비효율적입니다. 실무에서는 다음과 같은 더 효율적인 샘플링 전략을 고려해야 합니다.
1.  **기본 키(Primary Key) 기반 샘플링 (ID 기반 샘플링):** 기본 키의 범위를 무작위로 선택하여 해당 범위 내의 로우를 가져오는 방식입니다. (예: `WHERE id BETWEEN min_id AND max_id ORDER BY RAND() LIMIT N`)
2.  **테이블 스키마에 해시 컬럼 추가 (Consistent Hashing):** 미리 해시 함수를 사용하여 생성된 해시 값을 저장하는 컬럼을 추가하고, 이 해시 값을 기준으로 샘플링하는 방법입니다.
3.  **데이터 웨어하우스/분석 플랫폼의 샘플링 기능 활용 (`TABLESAMPLE`):** BigQuery, Redshift, Snowflake, PostgreSQL 등 최신 데이터 웨어하우스나 분석 플랫폼은 자체적으로 효율적인 샘플링 기능을 제공합니다. (예: `SELECT * FROM employees TABLESAMPLE SYSTEM (10 PERCENT);`)

### 3.6. 고급 그룹화: `CUBE`, `GROUPING SETS` (다차원 분석의 도구)

`CUBE`와 `GROUPING SETS`는 여러 그룹화 수준을 한 번의 쿼리로 생성하여 다양한 관점의 집계 결과를 얻을 수 있도록 돕습니다. 이는 특히 다차원 분석이나 보고서 생성 시 유용하며, `ROLLUP`보다 더 유연하거나 포괄적인 집계를 제공합니다.

*   **`CUBE`:** `GROUP BY` 절에 지정된 모든 컬럼의 가능한 **모든 조합**에 대해 집계 결과를 생성합니다. (예: (A, B), (A), (B), () 모든 조합)

```sql
-- 부서별, 직무별, 그리고 전체 총계까지 모든 조합에 대한 평균 급여 조회
SELECT
    IFNULL(department_id, 'Total') AS department,
    IFNULL(job_id, 'Subtotal') AS job,
    AVG(salary) AS average_salary
FROM employees
GROUP BY CUBE(department_id, job_id)
ORDER BY department_id, job_id;
```

*   **`GROUPING SETS`:** `GROUP BY` 절에 명시적으로 여러 그룹화 기준을 지정할 수 있도록 합니다. `CUBE`보다 더 유연하게 **원하는 그룹화 조합만 선택**하여 집계할 수 있습니다.

```sql
-- 부서별, 직무별 평균 급여와 부서별 총계, 그리고 전체 총계 조회
SELECT
    IFNULL(department_id, 'Total') AS department,
    IFNULL(job_id, 'Subtotal') AS job,
    AVG(salary) AS average_salary
FROM employees
GROUP BY GROUPING SETS (
    (department_id, job_id), -- 부서별, 직무별
    (department_id),         -- 부서별 총계
    ()                       -- 전체 총계
)
ORDER BY department_id, job_id;
```

**실무 팁: 성능 고려사항 (대규모 데이터셋)**
`CUBE`, `GROUPING SETS`, `ROLLUP`과 같은 고급 그룹화 기능은 매우 강력하지만, 대규모 데이터셋에 적용할 경우 상당한 시스템 자원을 소모하고 쿼리 실행 시간이 길어질 수 있습니다.

*   **성능 저하 원인:** 그룹화할 컬럼의 수가 늘어날수록 생성되는 그룹의 수가 기하급수적으로 증가하며, 내부적으로 많은 임시 테이블을 생성하고 정렬/해싱 작업을 수행해야 합니다.
*   **실무적 대안 및 최적화 전략:**
    1.  **사전 집계 (Pre-aggregation) / 요약 테이블:** 자주 조회되는 복잡한 집계 결과는 미리 계산하여 별도의 요약 테이블에 저장해둡니다.
    2.  **Materialized View (구체화된 뷰):** 일부 DBMS에서 제공하는 기능으로, 쿼리 결과를 물리적으로 저장해두고 원본 데이터 변경 시 갱신할 수 있습니다.
    3.  **쿼리 최적화 및 인덱스 튜닝:** 쿼리 실행 계획을 분석하여 병목 지점을 찾아 튜닝합니다.
    4.  **`GROUPING SETS`의 현명한 사용:** `CUBE` 대신 `GROUPING SETS`를 사용하여 필요한 그룹화 조합만 명시적으로 지정함으로써 불필요한 계산을 줄일 수 있습니다.
    5.  **데이터 웨어하우스/분석 플랫폼의 최적화 기능 활용:** BigQuery, Redshift, Snowflake 등 최신 데이터 웨어하우스는 이러한 고급 집계 쿼리에 대한 최적화된 실행 엔진을 제공하므로, 플랫폼의 기능을 최대한 활용합니다.

데이터 집계는 여러 로우의 데이터를 요약하여 하나의 값으로 만드는 과정입니다. `GROUP BY` 절과 함께 사용하면 특정 그룹별로 데이터를 집계하여 분석할 수 있습니다. 이는 데이터 분석에서 핵심적인 기술입니다.

**실무적 관점:** 데이터 분석의 꽃이라 할 수 있는 **집계(Aggregation)**와 **그룹화(Grouping)**를 다룹니다. 수많은 로우(Row) 데이터 속에서 의미 있는 패턴과 트렌드를 발견하려면 데이터를 요약하는 능력이 필수적입니다. 특히 `GROUP BY`와 `HAVING` 절은 비즈니스 질문에 대한 핵심적인 인사이트를 도출하는 데 사용되므로, 이들의 동작 원리를 정확히 이해하고 능숙하게 활용하는 것이 중요합니다.
