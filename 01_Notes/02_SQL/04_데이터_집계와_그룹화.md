## 1. 고급 `WHERE` 조건: 정교한 필터링

`WHERE` 절은 `SELECT`, `UPDATE`, `DELETE` 문에서 특정 조건을 만족하는 로우를 필터링하는 데 사용됩니다. 기본적인 비교 연산자 외에 다양한 고급 조건을 사용하여 데이터를 더욱 정교하게 선택할 수 있습니다.

### 1.1. 범위 조건 (`BETWEEN`, `NOT BETWEEN`)

특정 범위 내의 값을 조회할 때 사용합니다. 숫자, 날짜, 문자열 등 비교 가능한 모든 데이터 타입에 적용할 수 있습니다. `BETWEEN`은 시작 값과 끝 값을 모두 포함합니다.

```sql
-- 급여가 50000에서 70000 사이인 직원 조회 (50000과 70000 포함)
SELECT employee_id, first_name, salary
FROM employees
WHERE salary BETWEEN 50000 AND 70000;

-- 2023년 1월 1일부터 2023년 6월 30일 사이에 고용된 직원 조회
SELECT employee_id, first_name, hire_date
FROM employees
WHERE hire_date BETWEEN '2023-01-01' AND '2023-06-30';

-- 급여가 50000에서 70000 사이가 아닌 직원 조회
SELECT employee_id, first_name, salary
FROM employees
WHERE salary NOT BETWEEN 50000 AND 70000;
```

### 1.2. 목록 조건 (`IN`, `NOT IN`)

컬럼 값이 지정된 목록 중 하나와 일치하는지 확인할 때 사용합니다. 여러 `OR` 조건을 사용하는 것보다 간결하고 가독성이 좋습니다.

```sql
-- department_id가 1, 3, 5 중 하나인 직원 조회
SELECT employee_id, first_name, department_id
FROM employees
WHERE department_id IN (1, 3, 5);

-- job_id가 'DEV' 또는 'MGR'인 직원 조회
SELECT employee_id, first_name, job_id
FROM employees
WHERE job_id IN ('DEV', 'MGR');

-- department_id가 1, 3, 5 중 하나가 아닌 직원 조회
SELECT employee_id, first_name, department_id
FROM employees
WHERE department_id NOT IN (1, 3, 5);
```

### 1.3. 패턴 매칭 (`LIKE`, `NOT LIKE`)

문자열 컬럼에서 특정 패턴과 일치하는 값을 찾을 때 사용합니다. 와일드카드 문자와 함께 사용됩니다.

#### 1.3.1. 와일드카드 문자 (`%`, `_`) 활용

*   `%`: 0개 이상의 문자와 일치합니다. (예: `'%apple%'`은 'apple'을 포함하는 모든 문자열)
*   `_`: 정확히 1개의 문자와 일치합니다. (예: `'_pple'`은 'apple', 'bpple' 등 5글자 중 두 번째부터 'pple'인 문자열)

```sql
-- 이름이 'J'로 시작하는 직원 조회
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE 'J%';

-- 이름에 'an'이 포함된 직원 조회
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE '%an%';

-- 이름이 5글자이고 'e'로 끝나는 직원 조회
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE '____e';

-- 이메일 주소가 'example.com'으로 끝나지 않는 직원 조회
SELECT employee_id, email
FROM employees
WHERE email NOT LIKE '%@example.com';
```

**`LIKE` 연산자와 인덱스 성능 (실무적 관점):**
`LIKE` 연산자는 문자열 검색에 매우 유용하지만, 인덱스 사용 여부에 따라 쿼리 성능에 큰 영향을 미칩니다.

*   **인덱스 사용 가능 (`LIKE 'prefix%'`):**
    *   패턴이 **접두사(prefix)**로 시작하는 경우 (예: `LIKE 'J%'`, `LIKE 'SQL%'`)에는 해당 컬럼에 인덱스가 있다면 인덱스를 활용하여 빠르게 검색할 수 있습니다. 이는 인덱스가 정렬된 형태로 데이터를 저장하기 때문입니다.

*   **인덱스 사용 불가 (`LIKE '%suffix'`, `LIKE '%middle%'`, `LIKE '_pattern'`):**
    *   패턴이 **접두사로 시작하지 않는 경우** (예: `LIKE '%an%'`, `LIKE '%com'`, `LIKE '_pple'`)에는 인덱스를 사용할 수 없습니다. 이 경우 데이터베이스는 전체 테이블을 스캔(Full Table Scan)해야 하므로, 테이블의 크기가 클수록 쿼리 성능이 급격히 저하됩니다.
    *   이러한 경우에는 `Full-text Index`나 외부 검색 엔진(Elasticsearch 등)을 고려하거나, 애플리케이션 레벨에서 검색 로직을 최적화해야 합니다.
    *   **`OR` 조건과 `LIKE` 패턴 조합 시 최적화:** 만약 `WHERE name LIKE '%apple%' OR name LIKE '%banana%'`와 같이 `OR` 조건으로 여러 `LIKE` 패턴을 검색해야 하고, 이들이 인덱스를 활용할 수 없는 형태라면, `UNION ALL`을 사용하여 쿼리를 분리하는 것이 성능상 유리할 수 있습니다. 각 `SELECT` 문은 독립적으로 실행되어 더 효율적인 실행 계획을 가질 수 있습니다.
        ```sql
        -- 비효율적인 쿼리 (인덱스 활용 어려움)
        SELECT * FROM products WHERE product_name LIKE '%apple%' OR product_name LIKE '%banana%';

        -- UNION ALL을 활용한 최적화 (각 SELECT는 독립적으로 최적화될 가능성 높음)
        SELECT * FROM products WHERE product_name LIKE '%apple%'
        UNION ALL
        SELECT * FROM products WHERE product_name LIKE '%banana%' AND product_name NOT LIKE '%apple%'; -- 중복 방지
        ```
        이 방법은 특히 `OR` 조건이 복잡하거나, 각 조건이 다른 인덱스를 활용할 수 있을 때 효과적입니다.

**성능 최적화 팁:**
*   가능한 한 `LIKE 'prefix%'` 형태의 쿼리를 사용하도록 설계합니다.
*   `%`로 시작하는 검색이 빈번하다면, `Full-text Index` 또는 외부 검색 솔루션을 검토합니다.
*   `WHERE` 절에 `LIKE`와 함께 다른 조건이 있다면, 인덱스를 활용할 수 있는 다른 조건을 먼저 배치하여 검색 범위를 줄이는 것을 고려합니다.

### 1.4. `NULL` 값 처리 (`IS NULL`, `IS NOT NULL`)

`NULL`은 값이 없음을 나타내는 특별한 값입니다. `NULL`은 어떤 값과도 비교할 수 없으므로 (`= NULL`은 항상 거짓), `IS NULL` 또는 `IS NOT NULL`을 사용하여 확인해야 합니다.

```sql
-- phone_number가 NULL인 직원 조회
SELECT employee_id, first_name, phone_number
FROM employees
WHERE phone_number IS NULL;

-- phone_number가 NULL이 아닌 직원 조회
SELECT employee_id, first_name, phone_number
FROM employees
WHERE phone_number IS NOT NULL;
```

## 2. 내장 함수: 데이터 가공의 기술

SQL 내장 함수는 데이터를 조회하는 과정에서 값을 계산하거나, 형식을 변경하거나, 특정 정보를 추출하는 등 다양한 데이터 가공 작업을 수행할 수 있도록 돕습니다. 이는 데이터 분석가가 원본 데이터를 분석에 적합한 형태로 변환하는 데 필수적입니다.

### 2.1. 문자열 함수 (CONCAT, SUBSTRING, LENGTH, REPLACE, TRIM 등)

문자열 데이터를 조작하는 데 사용됩니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `CONCAT(str1, str2, ...)` | 여러 문자열을 연결 | `CONCAT('Hello', ' ', 'World')` | `'Hello World'` |
| `LENGTH(str)` | 문자열의 길이 (바이트) | `LENGTH('SQL')` | `3` |
| `CHAR_LENGTH(str)` | 문자열의 길이 (문자 수) | `CHAR_LENGTH('한글')` | `2` |
| `SUBSTRING(str, pos, len)` | 문자열의 부분 문자열 추출 | `SUBSTRING('Database', 4, 3)` | `'aba'` |
| `REPLACE(str, from_str, to_str)` | 문자열 내의 특정 부분을 다른 문자열로 교체 | `REPLACE('Hello World', 'World', 'SQL')` | `'Hello SQL'` |
| `TRIM([BOTH/LEADING/TRAILING] [remstr FROM] str)` | 문자열의 양쪽 끝, 앞, 뒤에서 특정 문자(기본 공백) 제거 | `TRIM('  SQL  ')` | `'SQL'` |
| `UPPER(str)` | 문자열을 대문자로 변환 | `UPPER('sql')` | `'SQL'` |
| `LOWER(str)` | 문자열을 소문자로 변환 | `LOWER('SQL')` | `'sql'` |
| `LEFT(str, len)` | 문자열의 왼쪽에서 `len`만큼 추출 | `LEFT('Database', 4)` | `'Data'` |
| `RIGHT(str, len)` | 문자열의 오른쪽에서 `len`만큼 추출 | `RIGHT('Database', 4)` | `'base'` |

```sql
-- 직원 이름과 성을 합쳐서 전체 이름 컬럼 생성
SELECT CONCAT(first_name, ' ', last_name) AS full_name, email
FROM employees;

-- 이메일 주소에서 도메인 부분만 추출
SELECT email, SUBSTRING(email, INSTR(email, '@') + 1) AS domain
FROM employees;

-- job_id에서 '_'를 공백으로 교체하고 대문자로 변환
SELECT job_id, REPLACE(UPPER(job_id), '_', ' ') AS formatted_job_title
FROM employees;
```

**데이터 정제 및 변환 (실무적 활용):**
데이터 분석에서 원본 데이터는 종종 불완전하거나 일관되지 않은 형태로 존재합니다. 문자열 함수는 이러한 데이터를 정제하고 분석에 적합한 형태로 변환하는 데 필수적입니다.

*   **공백 제거:** 사용자 입력 오류 등으로 인해 문자열 앞뒤에 불필요한 공백이 포함된 경우가 많습니다. `TRIM()` 함수를 사용하여 이러한 공백을 제거하여 데이터 일관성을 확보합니다.
    ```sql
    -- 컬럼 값의 앞뒤 공백 제거
    UPDATE products SET product_name = TRIM(product_name);
    ```
*   **특정 문자/패턴 제거 또는 교체:** 데이터 내에 분석에 방해가 되는 특수 문자나 패턴이 있을 수 있습니다. `REPLACE()` 함수를 사용하여 이를 제거하거나 다른 문자로 교체합니다.
    ```sql
    -- 상품명에서 'Limited Edition' 문자열 제거
    UPDATE products SET product_name = REPLACE(product_name, 'Limited Edition', '');

    -- 전화번호에서 하이픈 제거 (숫자만 남기기)
    UPDATE employees SET phone_number = REPLACE(REPLACE(REPLACE(phone_number, '-', ''), '(', ''), ')', '');
    ```
*   **대소문자 통일:** 문자열 데이터의 대소문자가 일관되지 않으면 `GROUP BY`나 `JOIN` 시 문제가 발생할 수 있습니다. `UPPER()` 또는 `LOWER()` 함수를 사용하여 대소문자를 통일합니다.
    ```sql
    -- 모든 부서명을 대문자로 통일하여 조회
    SELECT UPPER(department_name) AS upper_dept_name, COUNT(*)
    FROM departments
    GROUP BY UPPER(department_name);
    ```
*   **데이터 형식 표준화:** 예를 들어, 주소 데이터에서 '서울시'와 '서울특별시'가 혼용되어 있다면 `REPLACE()`를 사용하여 '서울특별시'로 통일하는 등의 작업을 수행할 수 있습니다.

이러한 문자열 함수를 활용한 데이터 정제는 데이터 분석의 첫 단계이자 가장 중요한 과정 중 하나입니다.

#### 2.1.11. `GROUP_CONCAT(expr)` (MySQL 특화)

`GROUP_CONCAT()` 함수는 `GROUP BY` 절과 함께 사용하여 그룹 내의 문자열 값을 하나의 문자열로 연결합니다. 이는 그룹별로 특정 속성들의 목록을 요약할 때 매우 유용합니다.

```sql
-- 부서별 직원 이름 목록을 콤마로 구분하여 조회
SELECT
    d.department_name,
    GROUP_CONCAT(e.first_name ORDER BY e.first_name SEPARATOR ', ') AS employee_names
FROM
    departments d
JOIN
    employees e ON d.department_id = e.department_id
GROUP BY
    d.department_name;

-- 결과 예시:
-- department_name | employee_names
-- -----------------|----------------------------------
-- Development     | Alice, Bob, David, John, Peter
-- Human Resources | Charlie, Jane
-- Marketing       | Emily
```

### 2.2. 숫자 함수 (ROUND, CEIL, FLOOR, ABS, MOD 등)

숫자 데이터를 계산하거나 형식을 변경하는 데 사용됩니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `ROUND(X, D)` | `X`를 소수점 `D`자리까지 반올림 (D 생략 시 정수) | `ROUND(123.456, 2)` | `123.46` |
| `CEIL(X)` | `X`보다 크거나 같은 가장 작은 정수 (올림) | `CEIL(123.45)` | `124` |
| `FLOOR(X)` | `X`보다 작거나 같은 가장 큰 정수 (내림) | `FLOOR(123.45)` | `123` |
| `ABS(X)` | `X`의 절댓값 | `ABS(-10)` | `10` |
| `MOD(N, M)` | `N`을 `M`으로 나눈 나머지 | `MOD(10, 3)` | `1` |
| `POW(X, Y)` / `POWER(X, Y)` | `X`의 `Y` 제곱 | `POW(2, 3)` | `8` |
| `SQRT(X)` | `X`의 제곱근 | `SQRT(9)` | `3` |

```sql
-- 급여를 소수점 첫째 자리에서 반올림
SELECT employee_id, salary, ROUND(salary) AS rounded_salary
FROM employees;

-- 급여를 10000으로 나눈 나머지를 계산
SELECT employee_id, salary, MOD(salary, 10000) AS salary_remainder
FROM employees;
```

### 2.3. 날짜 및 시간 함수 (NOW, CURDATE, DATEDIFF, DATE_FORMAT 등)

날짜와 시간 데이터를 조작하고 형식을 변경하는 데 사용됩니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `NOW()` | 현재 날짜와 시간 (DATETIME) | `NOW()` | `2025-05-20 10:30:00` |
| `CURDATE()` | 현재 날짜 (DATE) | `CURDATE()` | `2025-05-20` |
| `CURTIME()` | 현재 시간 (TIME) | `CURTIME()` | `10:30:00` |
| `DATE_FORMAT(date, format)` | 날짜/시간을 지정된 형식의 문자열로 변환 | `DATE_FORMAT(NOW(), '%Y년 %m월 %d일')` | `'2025년 05월 20일'` |
| `DATEDIFF(date1, date2)` | 두 날짜 간의 일수 차이 | `DATEDIFF('2025-05-20', '2025-05-10')` | `10` |
| `TIMESTAMPDIFF(unit, datetime_expr1, datetime_expr2)` | 두 날짜/시간 간의 지정된 단위(YEAR, MONTH, DAY, HOUR, MINUTE, SECOND) 차이 | `TIMESTAMPDIFF(MONTH, '2023-01-01', '2025-05-20')` | `28` |
| `ADDDATE(date, INTERVAL expr unit)` | 날짜에 시간 간격을 더함 | `ADDDATE(CURDATE(), INTERVAL 7 DAY)` | `CURDATE()`로부터 7일 후 |
| `SUBDATE(date, INTERVAL expr unit)` | 날짜에서 시간 간격을 뺌 | `SUBDATE(CURDATE(), INTERVAL 1 MONTH)` | `CURDATE()`로부터 1개월 전 |
| `YEAR(date)`, `MONTH(date)`, `DAY(date)` | 날짜에서 연도, 월, 일 추출 | `YEAR('2025-05-20')` | `2025` |
| `INSTR(str, substr)` | 문자열 내에서 부분 문자열의 시작 위치 반환 | `INSTR('example@email.com', '@')` | `8` |

```sql
-- 직원의 고용 기간 (일수) 계산
SELECT employee_id, first_name, hire_date, DATEDIFF(CURDATE(), hire_date) AS days_employed
FROM employees;

-- 직원의 고용 연도 추출
SELECT employee_id, first_name, YEAR(hire_date) AS hire_year
FROM employees;

-- 현재 날짜를 'YYYY-MM-DD' 형식으로 출력
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s') AS current_datetime;
```

**날짜 및 시간 연산 (실무적 활용):**
날짜 및 시간 데이터는 시계열 분석, 기간별 집계, 이벤트 간 시간 계산 등 데이터 분석에서 매우 중요하게 다루어집니다. SQL의 날짜/시간 함수를 활용하면 이러한 연산을 효율적으로 수행할 수 있습니다.

*   **날짜/시간 더하기/빼기:** 특정 날짜나 시간에 일정 기간을 더하거나 빼서 새로운 날짜/시간을 계산합니다.
    *   `DATE_ADD(date, INTERVAL expr unit)` / `ADDDATE(date, INTERVAL expr unit)`: 날짜에 기간을 더합니다.
    *   `DATE_SUB(date, INTERVAL expr unit)` / `SUBDATE(date, INTERVAL expr unit)`: 날짜에서 기간을 뺍니다.
    *   `unit`에는 `DAY`, `MONTH`, `YEAR`, `HOUR`, `MINUTE`, `SECOND` 등이 올 수 있습니다.
    ```sql
    -- 고용일로부터 1년 후의 날짜 계산
    SELECT employee_id, hire_date, DATE_ADD(hire_date, INTERVAL 1 YEAR) AS one_year_later
    FROM employees;

    -- 현재 시간으로부터 30분 전 시간 계산
    SELECT NOW(), DATE_SUB(NOW(), INTERVAL 30 MINUTE) AS thirty_minutes_ago;
    ```
*   **기간 계산:** 두 날짜/시간 사이의 차이를 특정 단위로 계산합니다.
    *   `DATEDIFF(date1, date2)`: 두 날짜 간의 일수 차이.
    *   `TIMESTAMPDIFF(unit, datetime_expr1, datetime_expr2)`: 두 날짜/시간 간의 지정된 단위(년, 월, 일, 시, 분, 초 등) 차이.
    ```sql
    -- 직원의 근속 개월 수 계산
    SELECT employee_id, hire_date, TIMESTAMPDIFF(MONTH, hire_date, CURDATE()) AS months_of_service
    FROM employees;
    ```
*   **요일/주차/분기 추출:** 날짜에서 특정 요소를 추출하여 분석에 활용합니다.
    *   `DAYOFWEEK(date)`: 요일 (1=일요일, ..., 7=토요일)
    *   `WEEK(date)` / `WEEKOFYEAR(date)`: 연간 주차
    *   `QUARTER(date)`: 분기 (1-4)
    ```sql
    -- 각 직원이 고용된 요일 조회
    SELECT employee_id, hire_date, DAYOFWEEK(hire_date) AS day_of_week
    FROM employees;
    ```
이러한 날짜 및 시간 연산 함수들은 시계열 데이터 분석, 트렌드 파악, 주기성 분석 등 다양한 데이터 분석 시나리오에서 핵심적인 역할을 합니다.

### 2.4. 형 변환 함수 (CAST, CONVERT)

데이터 타입을 다른 타입으로 명시적으로 변환할 때 사용합니다. 데이터 타입 불일치로 인한 오류를 방지하거나, 특정 연산을 수행하기 위해 필요합니다.

```sql
-- 문자열을 숫자로 변환
SELECT CAST('123' AS SIGNED INTEGER) AS num_int;
SELECT CONVERT('123.45' USING DECIMAL(5,2)) AS num_decimal;

-- 숫자를 문자열로 변환
SELECT CONCAT('Salary: ', CAST(salary AS CHAR)) AS employee_salary_text
FROM employees;

-- 날짜를 문자열로 변환
SELECT CAST(CURDATE() AS CHAR) AS current_date_str;
```

### 2.5. 조건 함수 (`IF`, `IFNULL`, `NULLIF`)

쿼리 내에서 조건부 로직을 구현할 때 사용합니다. `CASE` 문보다 간단한 조건에 유용합니다.

| 함수 | 설명 | 예시 | 결과 |
| :--- | :--- | :--- | :--- |
| `IF(condition, value_if_true, value_if_false)` | 조건이 참이면 첫 번째 값, 거짓이면 두 번째 값 반환 | `IF(10 > 5, 'True', 'False')` | `'True'` |
| `IFNULL(expr1, expr2)` | `expr1`이 `NULL`이 아니면 `expr1` 반환, `NULL`이면 `expr2` 반환 | `IFNULL(phone_number, 'N/A')` | `phone_number`가 `NULL`이면 `'N/A'` |
| `NULLIF(expr1, expr2)` | `expr1`과 `expr2`가 같으면 `NULL` 반환, 다르면 `expr1` 반환 | `NULLIF(salary, 0)` | `salary`가 0이면 `NULL` |

```sql
-- 급여가 60000 이상이면 'High', 아니면 'Low'로 분류
SELECT first_name, salary, IF(salary >= 60000, 'High', 'Low') AS salary_level
FROM employees;

-- phone_number가 NULL인 경우 'No Phone'으로 표시
SELECT first_name, IFNULL(phone_number, 'No Phone') AS contact_phone
FROM employees;
```

#### 2.5.4. `COALESCE(expr1, expr2, ...)`

`COALESCE()` 함수는 인자로 전달된 표현식들 중에서 첫 번째로 `NULL`이 아닌 값을 반환합니다. `IFNULL`이 두 개의 인자만 받는 반면, `COALESCE`는 여러 개의 인자를 받을 수 있어 더 유연합니다. 데이터 클리닝이나 결측치 처리 시 유용하게 사용됩니다.

```sql
-- phone_number가 NULL이면 email을, email도 NULL이면 'N/A'를 반환
SELECT
    employee_id, first_name,
    COALESCE(phone_number, email, 'N/A') AS contact_info
FROM employees;

-- 결과 예시:
-- employee_id | first_name | contact_info
-- -------------|------------|--------------------------
-- 1            | John       | 123-456-7890
-- 2            | Jane       | jane.smith@example.com
-- 3            | Alice      | N/A
```

### 2.6. JSON 함수 (JSON_EXTRACT, JSON_ARRAY_APPEND 등)

MySQL 5.7 이상에서 지원하는 JSON 데이터 타입과 관련된 함수들입니다. 반정형 데이터를 쿼리하고 조작하는 데 사용됩니다.

| 함수 | 설명 | 예시 |
| :--- | :--- | :--- |
| `JSON_EXTRACT(json_doc, path)` | JSON 문서에서 특정 경로의 값 추출 | `JSON_EXTRACT('{"name": "Alice"}', '$.name')` -> `"Alice"` |
| `JSON_UNQUOTE(json_val)` | JSON 문자열에서 따옴표 제거 | `JSON_UNQUOTE('"Alice" ')` -> `'Alice'` |
| `JSON_ARRAY_APPEND(json_doc, path, val)` | JSON 배열에 값 추가 | `JSON_ARRAY_APPEND('[1, 2]', '$', 3)` -> `[1, 2, 3]` |
| `JSON_OBJECT(key, val, ...)` | 키-값 쌍으로 JSON 객체 생성 | `JSON_OBJECT('name', 'Bob', 'age', 30)` -> `{"name": "Bob", "age": 30}` |
| `JSON_ARRAY(val, ...)` | 값으로 JSON 배열 생성 | `JSON_ARRAY('apple', 'banana')` -> `["apple", "banana"]` |
| `JSON_CONTAINS(json_doc, json_val, path)` | JSON 문서에 특정 값이 포함되어 있는지 확인 | `JSON_CONTAINS('{"a": 1, "b": 2}', '1', '$.a')` -> `1` (True) |

```sql
-- 예시: products 테이블에 JSON 타입의 details 컬럼이 있다고 가정
-- CREATE TABLE products (product_id INT PRIMARY KEY, product_name VARCHAR(100), details JSON);
-- INSERT INTO products VALUES (1, 'Laptop', '{"weight": 1.5, "color": "silver", "features": ["SSD", "Backlit Keyboard"]}');
-- INSERT INTO products VALUES (2, 'Mouse', '{"weight": 0.1, "color": "black", "features": ["Wireless"]}');

-- JSON 컬럼에서 특정 속성 값 추출
SELECT product_name, JSON_UNQUOTE(JSON_EXTRACT(details, '$.color')) AS color
FROM products;

-- JSON 배열에서 특정 요소가 포함된 로우 조회
SELECT product_name
FROM products
WHERE JSON_CONTAINS(details, '"SSD"', '$.features');

-- JSON 배열에 새로운 값 추가
UPDATE products
SET details = JSON_ARRAY_APPEND(details, '$.features', 'Bluetooth')
WHERE product_id = 2;
```

## 3. 데이터 집계와 그룹 분석

데이터 집계는 여러 로우의 데이터를 요약하여 하나의 값으로 만드는 과정입니다. `GROUP BY` 절과 함께 사용하면 특정 그룹별로 데이터를 집계하여 분석할 수 있습니다. 이는 데이터 분석에서 핵심적인 기술입니다.

### 3.1. 집계 함수 (Aggregate Functions)

여러 로우의 값을 입력으로 받아 단일 값을 반환하는 함수입니다. `GROUP BY` 절 없이 사용하면 전체 테이블에 대해 집계하고, `GROUP BY` 절과 함께 사용하면 각 그룹별로 집계합니다.

| 함수 | 설명 | 예시 |
| :--- | :--- | :--- |
| `COUNT(컬럼명)` | `NULL`이 아닌 값의 개수 | `COUNT(employee_id)` |
| `COUNT(*)` | 모든 로우의 개수 (NULL 포함) | `COUNT(*)` |
| `COUNT(DISTINCT 컬럼명)` | 중복을 제외한 값의 개수 | `COUNT(DISTINCT job_id)` |
| `SUM(컬럼명)` | 컬럼 값의 합계 | `SUM(salary)` |
| `AVG(컬럼명)` | 컬럼 값의 평균 | `AVG(salary)` |
| `MIN(컬럼명)` | 컬럼 값 중 최솟값 | `MIN(salary)` |
| `MAX(컬럼명)` | 컬럼 값 중 최댓값 | `MAX(salary)` |

**집계 함수와 `NULL` 값:**
대부분의 집계 함수( `SUM`, `AVG`, `MIN`, `MAX`, `COUNT(컬럼명)` )는 `NULL` 값을 **자동으로 제외**하고 계산합니다. `COUNT(*)`만이 `NULL`을 포함한 모든 로우의 수를 셉니다. 이 특성을 이해하는 것은 정확한 분석 결과를 얻는 데 중요합니다.

*   **`NULL` 값의 의도적 처리 (실무적 관점):**
    때로는 `NULL`을 특정 값(예: 0)으로 간주하여 집계에 포함시켜야 할 때가 있습니다. 예를 들어, 시험 점수 테이블에서 결시생의 점수가 `NULL`일 때, 이들을 0점 처리하여 전체 평균을 계산해야 할 수 있습니다. 이 경우 `IFNULL`이나 `COALESCE` 함수를 사용하여 `NULL` 값을 대체한 후 집계 함수를 적용해야 합니다.
    ```sql
    -- NULL을 0으로 간주하여 평균 계산
    SELECT AVG(IFNULL(score, 0)) AS average_score_including_absentees
    FROM test_scores;
    ```

```sql
-- 예시: phone_number가 NULL인 직원이 있다고 가정
SELECT
    COUNT(*) AS total_employees,           -- 전체 로우 수 (NULL 포함)
    COUNT(phone_number) AS employees_with_phone, -- phone_number가 NULL이 아닌 직원 수
    AVG(salary) AS avg_salary_all,         -- NULL이 아닌 급여의 평균
    SUM(salary) AS total_salary_all        -- NULL이 아닌 급여의 합계
FROM employees;
```

### 3.1.1. `COUNT()`: 로우 수 세기

`COUNT()` 함수는 특정 컬럼의 `NULL`이 아닌 값의 개수를 세거나, 전체 로우의 개수를 셉니다.

```sql
-- 전체 직원의 수
SELECT COUNT(*) AS total_employees
FROM employees;

-- job_id가 NULL이 아닌 직원의 수
SELECT COUNT(job_id) AS employees_with_job_id
FROM employees;

-- 고유한 직무(job_id)의 개수
SELECT COUNT(DISTINCT job_id) AS unique_job_count
FROM employees;
```

**`COUNT(DISTINCT ...)`의 성능 함정과 대안:**
`COUNT(DISTINCT column_name)`은 고유한 값의 개수를 세는 데 매우 유용하지만, 일반 `COUNT(*)`보다 훨씬 많은 자원을 소모할 수 있습니다. 데이터베이스는 중복을 제거하기 위해 내부적으로 정렬(Sorting)이나 해싱(Hashing) 작업을 수행해야 하기 때문입니다. 대규모 데이터셋에서 `COUNT(DISTINCT ...)`를 자주 사용해야 한다면, 다음과 같은 성능 저하 문제와 대안을 고려해야 합니다.

*   **성능 저하:** 수십억 건의 데이터를 가진 테이블에서 `COUNT(DISTINCT)`를 실행하면, 쿼리가 몇 시간 동안 끝나지 않거나 데이터베이스 서버에 심각한 부하를 줄 수 있습니다.
*   **대안 1: 서브쿼리와 `COUNT`:**
    `GROUP BY`를 사용하여 고유한 값 목록을 먼저 만든 후, 그 결과의 개수를 세는 방식입니다. 때로는 옵티마이저가 더 효율적인 실행 계획을 세울 수 있습니다.
    ```sql
    SELECT COUNT(*) FROM (SELECT DISTINCT user_id FROM access_logs) AS unique_users;
    ```
*   **대안 2: 근사치 계산 (Approximate Count):**
    정확한 값이 아닌, 매우 근사한 값으로도 충분한 비즈니스 요구사항이 많습니다 (예: 웹사이트의 일일 순 방문자 수 추정). 이 경우 HyperLogLog(HLL)와 같은 확률적 데이터 구조를 사용하는 것이 매우 효율적입니다. 일부 현대적인 데이터 웨어하우스(BigQuery, Redshift, Snowflake)나 데이터베이스(PostgreSQL, Redis)는 `APPROX_COUNT_DISTINCT` 또는 유사한 이름의 함수를 내장하고 있습니다.
*   **대안 3: 요약 테이블:**
    매일 또는 매시간 배치 작업을 통해 순 방문자 수와 같은 고유 사용자 수를 미리 계산하여 요약 테이블에 저장해두는 방법입니다. 이는 가장 일반적이고 효과적인 대규모 데이터 처리 방식입니다.

### 3.1.2. `SUM()`: 합계 계산

`SUM()` 함수는 특정 컬럼의 값들의 합계를 계산합니다. 숫자 타입 컬럼에만 적용할 수 있습니다.

```sql
-- 전체 직원의 급여 합계
SELECT SUM(salary) AS total_salary
FROM employees;

-- department_id가 1인 부서의 급여 합계
SELECT SUM(salary) AS dept1_total_salary
FROM employees
WHERE department_id = 1;
```

### 3.1.3. `AVG()`: 평균 계산

`AVG()` 함수는 특정 컬럼의 값들의 평균을 계산합니다. 숫자 타입 컬럼에만 적용할 수 있습니다.

*   **부동 소수점 연산의 위험성:**
    `FLOAT`나 `DOUBLE`과 같은 부동 소수점 타입에 `AVG()`나 `SUM()` 같은 집계 함수를 사용할 경우, 미세한 계산 오류가 누적되어 예상과 다른 결과를 초래할 수 있습니다. 이는 컴퓨터가 2진수로 소수를 표현하는 방식의 한계 때문입니다. **금융 데이터와 같이 1원의 오차도 허용되지 않는 정확한 계산이 필요할 때는, 반드시 `DECIMAL` 데이터 타입을 사용해야 합니다.**

```sql
-- 전체 직원의 평균 급여
SELECT AVG(salary) AS average_salary
FROM employees;

-- job_id가 'DEV'인 직원의 평균 급여
SELECT AVG(salary) AS dev_average_salary
FROM employees
WHERE job_id = 'DEV';
```

### 3.1.4. `MIN()`, `MAX()`: 최소/최대 값 찾기

`MIN()` 함수는 특정 컬럼의 값 중 최솟값을 찾고, `MAX()` 함수는 최댓값을 찾습니다. 숫자, 문자열, 날짜/시간 타입 컬럼에 모두 적용할 수 있습니다.

```sql
-- 가장 높은 급여와 가장 낮은 급여
SELECT MAX(salary) AS max_salary, MIN(salary) AS min_salary
FROM employees;

-- 가장 최근 고용된 날짜와 가장 오래된 고용 날짜
SELECT MAX(hire_date) AS latest_hire_date, MIN(hire_date) AS earliest_hire_date
FROM employees;

-- 알파벳 순으로 가장 빠른 이름과 가장 늦은 이름
SELECT MIN(first_name) AS first_name_alpha, MAX(first_name) AS last_name_alpha
FROM employees;
```

#### 3.1.5. 조건부 집계 (Conditional Aggregation)

`CASE` 문과 집계 함수를 함께 사용하여 특정 조건에 맞는 로우에 대해서만 집계를 수행할 수 있습니다. 이는 데이터를 다양한 기준으로 분류하여 요약할 때 매우 유용합니다.

```sql
-- 부서별 남성 직원 수와 여성 직원 수 조회
SELECT
    d.department_name,
    COUNT(CASE WHEN e.gender = 'M' THEN 1 END) AS male_employees,
    COUNT(CASE WHEN e.gender = 'F' THEN 1 END) AS female_employees,
    COUNT(*) AS total_employees
FROM
    departments d
LEFT JOIN
    employees e ON d.department_id = e.department_id
GROUP BY
    d.department_name;

-- 결과 예시:
-- department_name | male_employees | female_employees | total_employees
-- -----------------|----------------|------------------|----------------
-- Development     | 3              | 2                | 5
-- Human Resources | 1              | 1                | 2
-- Marketing       | 0              | 1                | 1
```

**조건부 집계의 다른 표현 (실무적 관점):**
MySQL에서는 `CASE` 문 외에도 `IF()` 함수를 사용하여 조건부 집계를 간결하게 표현할 수 있습니다. 또한, 표준 SQL에서는 `FILTER` 절을 사용하여 더 명확하게 조건부 집계를 수행할 수 있습니다.

*   **`SUM(IF(condition, value_if_true, value_if_false))` (MySQL 특화):**
    `COUNT(CASE WHEN ... THEN 1 END)`와 유사하게, `SUM()` 함수와 `IF()` 함수를 조합하여 특정 조건에 맞는 로우의 개수를 세거나 값을 합산할 수 있습니다. `IF()` 함수는 조건이 참이면 1, 거짓이면 0을 반환하므로 `SUM()`과 함께 사용하면 `COUNT()`와 동일한 효과를 낼 수 있습니다.
    ```sql
    SELECT
        d.department_name,
        SUM(IF(e.gender = 'M', 1, 0)) AS male_employees, -- 남성 직원 수
        SUM(IF(e.gender = 'F', 1, 0)) AS female_employees, -- 여성 직원 수
        COUNT(*) AS total_employees
    FROM
        departments d
    LEFT JOIN
        employees e ON d.department_id = e.department_id
    GROUP BY
        d.department_name;
    ```

*   **`COUNT(*) FILTER (WHERE condition)` (표준 SQL, PostgreSQL 등):**
    PostgreSQL과 같은 일부 DBMS에서는 표준 SQL의 `FILTER` 절을 지원하여 조건부 집계를 더 직관적으로 표현할 수 있습니다. 이는 `CASE` 문을 사용하는 것보다 가독성이 높고, 옵티마이저가 더 효율적인 실행 계획을 세울 수 있도록 돕는 경우가 많습니다.
    ```sql
    -- PostgreSQL 예시
    SELECT
        d.department_name,
        COUNT(*) FILTER (WHERE e.gender = 'M') AS male_employees,
        COUNT(*) FILTER (WHERE e.gender = 'F') AS female_employees,
        COUNT(*) AS total_employees
    FROM
        departments d
    LEFT JOIN
        employees e ON d.department_id = e.department_id
    GROUP BY
        d.department_name;
    ```
    데이터 분석가는 다양한 DBMS 환경에 적응하기 위해 이러한 여러 표현 방식을 알아두는 것이 좋습니다.

### 3.2. `GROUP BY`: 데이터 그룹화

`GROUP BY` 절은 특정 컬럼의 값을 기준으로 로우들을 그룹으로 묶습니다. 집계 함수는 이 그룹별로 적용되어 각 그룹의 요약 값을 계산합니다.

```sql
-- 부서별 직원 수
SELECT department_id, COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;

-- 직무별 평균 급여
SELECT job_id, AVG(salary) AS average_salary
FROM employees
GROUP BY job_id;
```

#### 3.2.1. 단일 컬럼 그룹화

하나의 컬럼을 기준으로 그룹을 나눕니다.

```sql
-- 고용 연도별 직원 수
SELECT YEAR(hire_date) AS hire_year, COUNT(*) AS employee_count
FROM employees
GROUP BY hire_year;
```

#### 3.2.2. 다중 컬럼 그룹화

여러 컬럼을 조합하여 더 세분화된 그룹을 나눕니다. `GROUP BY` 절에 나열된 컬럼의 순서가 중요합니다.

```sql
-- 부서별, 직무별 평균 급여
SELECT department_id, job_id, AVG(salary) AS average_salary
FROM employees
GROUP BY department_id, job_id
ORDER BY department_id, job_id;
```

### 3.3. `HAVING`: 그룹 필터링

`HAVING` 절은 `GROUP BY` 절에 의해 생성된 그룹에 조건을 적용하여 필터링합니다. `WHERE` 절이 개별 로우를 필터링하는 반면, `HAVING` 절은 집계된 결과(그룹)를 필터링합니다.

```sql
-- 부서별 평균 급여가 60000 이상인 부서만 조회
SELECT department_id, AVG(salary) AS average_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) >= 60000;

-- 직무별 직원 수가 2명 이상인 직무의 평균 급여 조회
SELECT job_id, COUNT(*) AS employee_count, AVG(salary) AS average_salary
FROM employees
GROUP BY job_id
HAVING COUNT(*) >= 2;
```

#### 3.3.1. `WHERE`와 `HAVING`의 차이점

| 구분 | `WHERE` 절 | `HAVING` 절 |
| :--- | :--- | :--- |
| **적용 시점** | `GROUP BY` 전에 개별 로우에 적용 | `GROUP BY` 후에 그룹화된 결과에 적용 |
| **사용 가능 컬럼** | 원본 테이블의 모든 컬럼 | `GROUP BY` 컬럼 또는 집계 함수 결과 |
| **집계 함수 사용** | 직접 사용 불가 | 사용 가능 |

*   **SQL 쿼리의 논리적 실행 순서:**
    `WHERE`와 `HAVING`의 차이를 근본적으로 이해하려면 SQL의 논리적 실행 순서를 아는 것이 중요합니다. 옵티마이저에 따라 실제 실행 방식은 달라질 수 있지만, 개념적인 순서는 다음과 같습니다.

    1.  **`FROM`**: 쿼리에 필요한 테이블을 가져옵니다.
    2.  **`JOIN`**: 테이블을 연결합니다.
    3.  **`WHERE`**: 개별 로우를 필터링합니다.
    4.  **`GROUP BY`**: 로우를 그룹으로 묶습니다.
    5.  **`HAVING`**: 그룹화된 결과를 필터링합니다.
    6.  **`SELECT`**: 최종적으로 반환할 컬럼을 선택합니다.
    7.  **`DISTINCT`**: 중복된 결과를 제거합니다.
    8.  **`ORDER BY`**: 결과를 정렬합니다.
    9.  **`LIMIT` / `OFFSET`**: 반환할 로우의 수를 제한합니다.

    이 순서를 이해하면, 예를 들어 `SELECT` 절에서 정의한 별칭(Alias)을 `WHERE` 절에서 사용할 수 없는 이유(`SELECT`가 `WHERE`보다 나중에 실행됨)와 `HAVING` 절에서는 집계 함수를 사용할 수 있는 이유(`HAVING`이 `GROUP BY` 이후에 실행됨)를 명확하게 파악할 수 있습니다.

```sql
-- 예시: department_id가 1인 직원들 중에서 평균 급여가 60000 이상인 직무 조회
SELECT department_id, job_id, AVG(salary) AS average_salary
FROM employees
WHERE department_id = 1 -- 개별 로우 필터링
GROUP BY job_id
HAVING AVG(salary) >= 60000; -- 그룹 필터링
```

### 3.4. `WITH ROLLUP`: 그룹별 소계 및 총계

`WITH ROLLUP`은 `GROUP BY` 절과 함께 사용하여 그룹별 소계(Subtotal)와 전체 총계(Grand Total)를 계산하는 기능을 제공합니다. 계층적인 집계 결과를 한 번에 얻을 수 있습니다.

```sql
-- 부서별, 직무별 평균 급여와 소계, 총계
SELECT
    IFNULL(department_id, 'Total') AS department,
    IFNULL(job_id, 'Subtotal') AS job,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department_id, job_id WITH ROLLUP;

-- 결과 예시:
-- department_name | male_employees | female_employees | total_employees
-- -----------------|----------------|------------------|----------------
-- Development     | 3              | 2                | 5
-- Human Resources | 1              | 1                | 2
-- Marketing       | 0              | 1                | 1
-- -----------|------------|---------------
-- 1          | DEV        | 61000.00
-- 1          | MGR        | 70000.00
-- 1          | Subtotal   | 64333.33  -- department_id 1의 소계
-- 2          | HR         | 56500.00
-- 2          | Subtotal   | 56500.00  -- department_id 2의 소계
-- Total      | Subtotal   | 61000.00  -- 전체 총계
```

**`IFNULL` 함수 활용:** `ROLLUP`으로 생성된 총계 로우의 그룹핑 컬럼은 `NULL` 값을 가집니다. `IFNULL` 함수를 사용하여 이 `NULL` 값을 'Total'이나 'Subtotal'과 같은 의미 있는 문자열로 대체하여 가독성을 높일 수 있습니다.

**`GROUP_CONCAT`과 `WITH ROLLUP`의 표준 SQL 대체 (실무적 관점):**
`GROUP_CONCAT`과 `WITH ROLLUP`은 MySQL에서 매우 유용하게 사용되는 기능이지만, 표준 SQL은 아닙니다. 따라서 다른 DBMS에서는 직접 지원하지 않거나 다른 문법을 사용해야 합니다. 데이터 분석가는 이러한 차이를 인지하고, 필요에 따라 표준 SQL 또는 해당 DBMS의 대체 기능을 활용할 수 있어야 합니다.

*   **`GROUP_CONCAT` 대체:**
    *   **표준 SQL (`STRING_AGG`):** PostgreSQL, SQL Server 등 많은 DBMS에서 `STRING_AGG` 함수를 지원합니다. 이는 `GROUP_CONCAT`과 유사하게 그룹 내 문자열을 연결하는 기능을 제공합니다.
        ```sql
        -- PostgreSQL 예시
        SELECT
            d.department_name,
            STRING_AGG(e.first_name, ', ' ORDER BY e.first_name) AS employee_names
        FROM
            departments d
        JOIN
            employees e ON d.department_id = e.department_id
        GROUP BY
            d.department_name;
        ```

*   **`WITH ROLLUP` 대체:**
    *   **표준 SQL (`GROUPING SETS`, `CUBE`, `ROLLUP`):** 표준 SQL에서는 `GROUPING SETS`, `CUBE`, `ROLLUP` 연산자를 사용하여 다양한 수준의 그룹화를 수행하고 소계 및 총계를 계산할 수 있습니다. MySQL의 `WITH ROLLUP`은 표준 `ROLLUP` 연산자의 한 형태입니다.
        ```sql
        -- 표준 SQL 예시 (PostgreSQL, SQL Server 등)
        SELECT
            department_id,
            job_id,
            AVG(salary) AS average_salary
        FROM employees
        GROUP BY ROLLUP(department_id, job_id);

        -- GROUPING SETS 예시 (더 유연한 그룹화)
        SELECT
            IFNULL(department_id, 'Total') AS department,
            IFNULL(job_id, 'Subtotal') AS job,
            AVG(salary) AS average_salary
        FROM employees
        GROUP BY GROUPING SETS (
            (department_id, job_id), -- 부서별, 직무별
            (department_id),         -- 부서별 총계
            ()                       -- 전체 총계
        )
        ORDER BY department_id, job_id;
        ```
    이러한 표준 SQL 기능을 이해하면 다양한 DBMS 환경에서 유연하게 쿼리를 작성하고 분석을 수행할 수 있습니다.

### 3.5. 데이터 샘플링 (Sampling): 대규모 데이터 탐색 및 테스트

대규모 데이터셋을 다룰 때, 전체 데이터를 처리하는 것은 시간과 자원이 많이 소모될 수 있습니다. 이럴 때 데이터 샘플링은 전체 데이터의 특성을 대표하는 일부 데이터를 추출하여 빠르게 탐색적 분석을 수행하거나, 모델 학습을 위한 테스트 데이터를 생성하는 데 유용합니다. MySQL은 `ORDER BY RAND()`와 `LIMIT`를 조합하여 샘플링을 수행할 수 있습니다.

**주의:** `ORDER BY RAND()`는 테이블의 모든 로우를 정렬해야 하므로, 대규모 테이블에서는 성능이 매우 저하될 수 있습니다. 실무에서는 더 효율적인 샘플링 전략(예: 특정 조건에 맞는 로우만 필터링 후 샘플링, 해시 함수 활용, 또는 데이터 웨어하우스의 샘플링 기능 활용)을 고려해야 합니다.

```sql
-- employees 테이블에서 무작위로 10개의 로우 샘플링
SELECT * FROM employees
ORDER BY RAND()
LIMIT 10;

-- 특정 부서(department_id = 1)에서 무작위로 5개의 로우 샘플링
SELECT * FROM employees
WHERE department_id = 1
ORDER BY RAND()
LIMIT 5;
```

**더 효율적인 대규모 데이터 샘플링 전략 (실무적 고려사항):**
`ORDER BY RAND()`는 작은 테이블에서는 문제가 없지만, 수백만 로우 이상의 대규모 테이블에서는 심각한 성능 병목이 됩니다. 다음과 같은 대안을 고려할 수 있습니다.

1.  **기본 키(Primary Key) 기반 샘플링:**
    테이블의 기본 키가 연속적이거나 예측 가능한 패턴을 가진다면, 기본 키의 범위를 무작위로 선택하여 해당 범위 내의 로우를 가져오는 방식이 더 효율적입니다. 예를 들어, `employee_id`가 1부터 100만까지 있다면, 1부터 100만 사이의 무작위 숫자를 생성하여 `WHERE employee_id BETWEEN X AND Y`와 같이 쿼리할 수 있습니다.
    ```sql
    -- 예시: ID 범위 기반 샘플링 (최소/최대 ID를 미리 알아야 함)
    SET @min_id = (SELECT MIN(employee_id) FROM employees);
    SET @max_id = (SELECT MAX(employee_id) FROM employees);
    SET @random_offset = FLOOR(RAND() * (@max_id - @min_id + 1));

    SELECT * FROM employees
    WHERE employee_id >= @min_id + @random_offset
    LIMIT 10;
    ```

2.  **테이블 스키마에 해시 컬럼 추가:**
    테이블에 미리 해시 함수(예: `MD5`, `SHA1`)를 사용하여 생성된 해시 값을 저장하는 컬럼을 추가하고, 이 해시 값을 기준으로 샘플링하는 방법입니다. 특정 범위의 해시 값을 선택하여 데이터를 가져옵니다.
    ```sql
    -- 예시: 해시 컬럼 기반 샘플링 (미리 hash_value 컬럼이 있다고 가정)
    SELECT * FROM employees
    WHERE hash_value < '0.1' -- 전체 데이터의 약 10% 샘플링
    LIMIT 100; -- 또는 원하는 샘플 크기
    ```

3.  **데이터 웨어하우스/분석 플랫폼의 샘플링 기능 활용:**
    BigQuery, Redshift, Snowflake 등 최신 데이터 웨어하우스나 분석 플랫폼은 자체적으로 효율적인 샘플링 기능을 제공합니다. (예: `TABLESAMPLE` 절) 이러한 플랫폼을 사용한다면 내장된 샘플링 기능을 활용하는 것이 가장 좋습니다.

데이터 샘플링은 분석의 초기 단계에서 데이터의 대략적인 분포나 패턴을 파악하는 데 매우 유용하지만, 통계적 유의미성을 위해서는 샘플링 방법론에 대한 깊은 이해가 필요합니다.

### 3.6. 고급 그룹화: `CUBE`, `GROUPING SETS`

`GROUP BY` 절은 지정된 컬럼의 조합으로 데이터를 그룹화하지만, `CUBE`와 `GROUPING SETS`는 여러 그룹화 수준을 한 번의 쿼리로 생성하여 다양한 관점의 집계 결과를 얻을 수 있도록 돕습니다. 이는 특히 다차원 분석이나 보고서 생성 시 유용합니다.

*   **`CUBE`:**
    `CUBE` 연산자는 `GROUP BY` 절에 지정된 모든 컬럼의 가능한 모든 조합에 대해 집계 결과를 생성합니다. 예를 들어, `CUBE(A, B)`는 `(A, B)`, `(A)`, `(B)`, `()` (전체 총계)의 모든 조합에 대한 그룹화 결과를 반환합니다.

    ```sql
    -- 부서별, 직무별, 그리고 전체 총계까지 모든 조합에 대한 평균 급여 조회
    SELECT
        IFNULL(department_id, 'Total') AS department,
        IFNULL(job_id, 'Subtotal') AS job,
        AVG(salary) AS average_salary
    FROM employees
    GROUP BY CUBE(department_id, job_id)
    ORDER BY department_id, job_id;
    ```
    **실무적 활용:** 다차원 분석에서 모든 가능한 조합에 대한 요약이 필요할 때 유용합니다. 예를 들어, 제품, 지역, 시간에 따른 판매량 분석 시 모든 조합의 합계를 한 번에 얻을 수 있습니다.

*   **`GROUPING SETS`:**
    `GROUPING SETS`는 `GROUP BY` 절에 명시적으로 여러 그룹화 기준을 지정할 수 있도록 합니다. `CUBE`보다 더 유연하게 원하는 그룹화 조합만 선택하여 집계할 수 있습니다.

    ```sql
    -- 부서별, 직무별 평균 급여와 부서별 총계, 그리고 전체 총계 조회
    SELECT
        IFNULL(department_id, 'Total') AS department,
        IFNULL(job_id, 'Subtotal') AS job,
        AVG(salary) AS average_salary
    FROM employees
    GROUP BY GROUPING SETS (
        (department_id, job_id), -- 부서별, 직무별
        (department_id),         -- 부서별 총계
        ()                       -- 전체 총계
    )
    ORDER BY department_id, job_id;
    ```
    **실무적 활용:** 특정 보고서에서 필요한 몇 가지 그룹화 조합에 대해서만 집계 결과를 얻고 싶을 때 효율적입니다.

*   **`ROLLUP` (참고):**
    `ROLLUP` 연산자는 계층적인 그룹화를 수행합니다. `ROLLUP(A, B)`는 `(A, B)`, `(A)`, `()` (전체 총계)의 그룹화 결과를 반환합니다. MySQL의 `WITH ROLLUP`은 이 표준 `ROLLUP` 연산자의 한 형태입니다.

**`CUBE`, `GROUPING SETS`와 `WITH ROLLUP`의 차이:**
*   `WITH ROLLUP` (또는 표준 `ROLLUP`): 계층적인 그룹화 (예: 총계 -> 대분류 -> 중분류 -> 소분류)
*   `CUBE`: 모든 가능한 그룹화 조합 (비계층적)
*   `GROUPING SETS`: 원하는 그룹화 조합을 명시적으로 선택 (가장 유연)

이러한 고급 그룹화 기능은 데이터 분석가가 복잡한 비즈니스 질문에 답하고, 다양한 관점에서 데이터를 요약하는 데 강력한 도구가 됩니다.
