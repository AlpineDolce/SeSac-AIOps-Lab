## 1. 실전 프로젝트 예제

### 1.1. 프로젝트 목표 설정

웹 크롤링 프로젝트를 시작하기 전에 가장 먼저 해야 할 일은 **명확하고 구체적인 목표를 설정**하는 것입니다. 목표가 명확해야 어떤 데이터를 수집할지, 어떤 웹사이트를 크롤링할지, 어떤 기술을 사용할지 등 프로젝트의 모든 단계를 효율적으로 계획하고 실행할 수 있습니다. 목표가 모호하면 불필요한 데이터 수집이나 비효율적인 크롤링으로 이어질 수 있습니다.

*   **목표 설정의 중요성:**
    *   **방향성 제시:** 프로젝트의 목적과 범위를 명확히 하여 불필요한 작업이나 데이터 수집을 방지합니다.
    *   **효율성 증대:** 필요한 데이터에 집중하여 크롤링 시간과 자원을 최적화합니다.
    *   **성공 측정:** 프로젝트의 성공 여부를 객관적으로 평가할 수 있는 기준을 제공합니다.
    *   **의사소통:** 팀원이나 이해관계자들과 프로젝트 목표를 공유하고 합의하는 데 도움을 줍니다.

*   **SMART 원칙을 활용한 목표 설정:**
    *   **Specific (구체적):** 무엇을, 왜, 어떻게 크롤링할 것인가? (예: '특정 온라인 쇼핑몰에서 노트북 제품의 가격과 리뷰를 수집한다.')
    *   **Measurable (측정 가능):** 목표 달성 여부를 어떻게 측정할 것인가? (예: '매일 1000개 이상의 노트북 제품 데이터를 수집한다.', '수집된 데이터의 정확도는 95% 이상이어야 한다.')
    *   **Achievable (달성 가능):** 현재 기술과 자원으로 목표를 달성할 수 있는가? (예: '해당 쇼핑몰이 봇 차단이 강하지 않고, Selenium으로 접근 가능하다.')
    *   **Relevant (관련성):** 이 크롤링이 비즈니스 목표나 분석 목적에 부합하는가? (예: '수집된 데이터는 노트북 시장 가격 동향 분석에 활용된다.')
    *   **Time-bound (시간 제한):** 언제까지 목표를 달성할 것인가? (예: '2주 이내에 초기 데이터 수집을 완료한다.')

> **[실무 노트] 프로젝트 목표 설정 시 고려사항:**
> 데이터 과학 프로젝트에서 크롤링은 데이터 확보의 중요한 단계입니다. 목표 설정 시 다음 사항들을 함께 고려하면 실무적 완성도를 높일 수 있습니다.
>
> *   **데이터 사용 목적:** 수집된 데이터가 어떤 분석에 활용될지, 어떤 비즈니스 질문에 답할 것인지 명확히 합니다. (예: '경쟁사 가격 모니터링', '고객 리뷰 감성 분석', '채용 시장 동향 파악')
> *   **데이터 항목 정의:** 어떤 정보(예: 제품명, 가격, 리뷰 텍스트, 별점, 작성일)를 수집할 것인지 구체적으로 정의합니다. 각 항목의 데이터 타입(문자열, 숫자, 날짜)과 예상되는 형식도 함께 고려합니다.
> *   **수집 범위:** 크롤링할 웹 페이지의 범위(예: 특정 카테고리, 특정 기간의 게시물, 전체 페이지)를 설정합니다. 너무 넓은 범위는 크롤링 시간과 자원 소모를 증가시킬 수 있습니다.
> *   **수집 주기:** 데이터의 신선도 요구사항에 따라 수집 주기를 결정합니다. (예: 실시간, 매일, 매주, 매월)
> *   **데이터 볼륨 예측:** 수집될 데이터의 양을 대략적으로 예측하여 저장 공간, 처리 시간, 시스템 자원 등을 계획합니다.
> *   **윤리적/법적 고려사항:** 목표 설정 단계에서부터 `robots.txt` 준수, 이용 약관 확인, 개인 정보 보호, 저작권 등 윤리적/법적 측면을 고려합니다. (자세한 내용은 [13_크롤링_윤리_및_법적_고려사항.md](./13_크롤링_윤리_및_법적_고려사항.md) 참조)
>
> 명확한 목표 설정은 성공적인 웹 크롤링 프로젝트의 첫걸음입니다.

### 1.2. 대상 웹사이트 분석

프로젝트 목표가 설정되었다면, 다음 단계는 크롤링 대상 웹사이트를 면밀히 분석하는 것입니다. 웹사이트의 구조와 동작 방식을 정확히 이해해야만 효율적이고 안정적인 크롤링 스크립트를 작성할 수 있습니다. 이 단계는 크롤링 프로젝트의 성공 여부를 좌우하는 핵심적인 과정입니다.

*   **웹사이트 구조 분석 (HTML/CSS/JavaScript):**
    *   **HTML 구조:** 원하는 데이터가 어떤 태그(tag), ID, 클래스(class), 속성(attribute)에 포함되어 있는지 파악합니다. 데이터가 반복되는 패턴(예: 게시물 목록, 상품 리스트)을 찾아냅니다.
    *   **CSS:** 요소의 시각적 표현을 담당하지만, `class`나 `id`와 같은 선택자는 데이터 추출에 중요한 단서가 됩니다.
    *   **JavaScript:** 페이지의 동적인 동작(버튼 클릭 시 내용 변경, 무한 스크롤, 팝업 등)을 담당합니다. JavaScript를 통해 데이터가 동적으로 로드되는지 여부를 파악하는 것이 중요합니다.
*   **동적 vs 정적 콘텐츠 파악:**
    *   **정적 콘텐츠:** 웹 페이지의 HTML 소스에 데이터가 직접 포함되어 있는 경우입니다. `Requests`와 `BeautifulSoup` 조합으로 충분합니다.
    *   **동적 콘텐츠:** JavaScript 실행 후 AJAX 호출 등을 통해 데이터가 비동기적으로 로드되거나, 사용자 상호작용(클릭, 스크롤)에 따라 콘텐츠가 변경되는 경우입니다. `Selenium`과 같은 브라우저 자동화 도구가 필요합니다.
    *   **확인 방법:** 웹 페이지를 로드한 후, 브라우저의 '페이지 소스 보기'(`Ctrl+U` 또는 `Cmd+Option+U`)로 HTML 소스를 확인합니다. 원하는 데이터가 소스에 직접 보이지 않는다면 동적 콘텐츠일 가능성이 높습니다.
*   **봇 탐지 시스템 확인:**
    *   웹사이트가 봇에 의한 접근을 막기 위한 어떤 방어 메커니즘을 가지고 있는지 파악합니다. (예: `robots.txt`, `User-Agent` 검사, IP 차단, CAPTCHA, 로그인 요구)
    *   `robots.txt` 파일은 반드시 확인하고 준수해야 합니다. (자세한 내용은 [13_크롤링_윤리_및_법적_고려사항.md](./13_크롤링_윤리_및_법적_고려사항.md) 참조)
*   **개발자 도구(Developer Tools) 활용 (F12):**
    *   **Elements 탭:** 웹 페이지의 실시간 HTML/DOM 구조를 보여줍니다. 원하는 요소에 마우스를 올리면 해당 요소의 HTML 코드를 확인할 수 있습니다. 'Copy selector' 또는 'Copy XPath' 기능을 활용하여 요소의 선택자를 쉽게 얻을 수 있습니다.
    *   **Network 탭:** 웹 페이지가 로드될 때 발생하는 모든 HTTP 요청과 응답을 모니터링합니다. AJAX 호출로 동적으로 로드되는 데이터(주로 JSON 형태)를 파악하는 데 매우 중요합니다. `XHR` 필터를 사용하여 비동기 요청만 확인할 수 있습니다.
    *   **Console 탭:** JavaScript 오류나 경고를 확인하고, JavaScript 코드를 직접 실행하여 웹 페이지의 동작을 테스트할 수 있습니다.

> **[실무 노트] 웹사이트 분석의 깊이:**
> 웹사이트 분석은 단순히 눈으로 보는 것을 넘어, 개발자 도구를 활용하여 웹 페이지의 '내부 동작'을 이해하는 과정입니다. 이 단계에서 시간을 충분히 투자할수록 크롤링 스크립트의 안정성과 효율성이 높아집니다.
>
> *   **데이터가 어디에 있는가?**
>     *   HTML 태그의 텍스트 내용? (예: `<p>상품명</p>`) -> `.text` 또는 `.get_text()`
>     *   HTML 태그의 속성 값? (예: `<img src="image.jpg">`) -> `.get('src')`
>     *   JavaScript 변수 내부? (예: `var productData = {...};`) -> `driver.execute_script("return productData;")`
>     *   AJAX 응답 (JSON/XML)? (Network 탭의 XHR 요청 확인) -> `Requests`로 직접 API 호출 고려
> *   **데이터가 어떻게 로드되는가?**
>     *   페이지 로드 시 한 번에 로드되는가? (정적) -> `Requests` + `BeautifulSoup`
>     *   스크롤 시 추가 로드되는가? (무한 스크롤) -> `Selenium` + 스크롤링 로직
>     *   버튼 클릭 시 로드되는가? (동적 상호작용) -> `Selenium` + 클릭 로직
> *   **웹사이트는 봇을 어떻게 막는가?**
>     *   `robots.txt` 확인
>     *   `User-Agent` 검사 (User-Agent 변경 필요)
>     *   IP 차단 (프록시 필요)
>     *   CAPTCHA (우회 기술 필요)
>     *   로그인/세션 관리 (로그인 자동화 필요)
>
> 이 모든 질문에 대한 답을 찾고, 이를 바탕으로 크롤링 전략을 수립해야 합니다. 웹사이트 분석은 크롤링 스크립트 작성의 절반 이상을 차지하는 중요한 과정입니다.

### 1.3. 크롤링 전략 수립

대상 웹사이트 분석을 통해 얻은 정보를 바탕으로, 이제 구체적인 크롤링 전략을 수립해야 합니다. 이 단계에서는 어떤 라이브러리를 사용할지, 데이터 수집 흐름을 어떻게 설계할지, 그리고 발생 가능한 문제에 어떻게 대응할지 등을 결정합니다.

*   **라이브러리 선택:**
    *   **정적 페이지:** `Requests` + `BeautifulSoup` 조합을 우선적으로 고려합니다. 빠르고 자원 소모가 적습니다.
    *   **동적 페이지:** `Selenium`을 사용하여 브라우저를 자동화하고, 필요에 따라 `BeautifulSoup`으로 파싱합니다. `Selenium`은 자원 소모가 크고 느리므로, 동적 콘텐츠 처리가 필수적인 경우에만 사용합니다.
    *   **대규모/복잡한 프로젝트:** `Scrapy` 프레임워크를 사용하여 크롤링 프로세스 전체를 관리하고, 필요에 따라 다른 라이브러리를 통합합니다.
*   **데이터 수집 흐름 설계:**
    *   **시작 URL:** 크롤링을 시작할 초기 URL을 정의합니다.
    *   **탐색 경로:** 웹사이트 내에서 원하는 데이터를 찾기 위해 어떤 페이지들을 방문할지, 어떤 링크를 따라갈지, 어떤 버튼을 클릭할지 등의 경로를 설계합니다.
    *   **페이지네이션 처리:** 페이지네이션(다음 페이지 버튼, 페이지 번호, 무한 스크롤)이 있다면 이를 어떻게 처리할지 결정합니다.
    *   **데이터 추출 규칙:** 각 페이지에서 어떤 요소를 찾아 어떤 데이터를 추출할지 구체적인 규칙을 정의합니다. (예: 제품명은 `h2` 태그의 `class="product-title"`에 있음)
    *   **데이터 저장 방식:** 수집된 데이터를 어떤 형식(CSV, JSON, 데이터베이스)으로 저장할지 결정합니다.
*   **오류 처리 및 안정성 확보:**
    *   **네트워크 오류:** 연결 끊김, 타임아웃 등 네트워크 문제 발생 시 재시도 로직을 구현합니다.
    *   **웹사이트 구조 변경:** 웹사이트 구조가 변경될 경우 크롤링 스크립트가 오작동할 수 있습니다. 주기적인 모니터링과 스크립트 업데이트 계획을 세웁니다.
    *   **봇 탐지 및 차단:** `User-Agent` 변경, 프록시 로테이션, 요청 간 지연 시간 설정 등 봇 탐지 우회 기술을 적용합니다.
    *   **명시적 대기:** 동적 콘텐츠 로딩 시 `time.sleep()` 대신 `WebDriverWait`를 사용하여 요소가 로드될 때까지 기다립니다.
*   **윤리적/법적 고려사항 재확인:**
    *   `robots.txt` 파일과 웹사이트 이용 약관을 다시 한번 확인하고, 크롤링 전략이 이에 위배되지 않는지 최종 점검합니다.
    *   개인 정보 보호 및 저작권 관련 법규를 준수합니다.

> **[실무 노트] 크롤링 전략 수립: 설계는 곧 성공:**
> 크롤링 전략 수립은 단순히 코드를 작성하는 것보다 훨씬 중요합니다. 이 단계에서 얼마나 철저하게 분석하고 계획하느냐에 따라 크롤링 프로젝트의 성공 여부와 유지보수 비용이 결정됩니다.
>
> *   **단계별 접근:**
>     1.  **작은 범위부터 시작:** 전체 웹사이트를 한 번에 크롤링하려 하지 말고, 가장 핵심적인 데이터가 있는 페이지부터 시작하여 점진적으로 범위를 확장합니다.
>     2.  **프로토타이핑:** 간단한 스크립트로 원하는 데이터가 제대로 추출되는지 빠르게 테스트해봅니다. 이 과정에서 웹사이트의 숨겨진 동작이나 예상치 못한 문제점을 발견할 수 있습니다.
>     3.  **오류 시나리오 고려:** 네트워크 끊김, 요소 미발견, CAPTCHA 등장 등 발생 가능한 모든 오류 시나리오를 미리 예측하고, 이에 대한 처리 로직(재시도, 로깅, 알림)을 설계합니다.
> *   **데이터 품질 관리:**
>     *   수집된 데이터의 유효성을 검증하는 로직을 포함합니다. (예: 숫자가 와야 할 자리에 문자가 오는지, 필수 필드가 누락되었는지)
>     *   웹사이트 구조 변경에 대비하여 크롤링 스크립트의 유연성을 확보하고, 변경 감지 시 알림을 받을 수 있는 시스템을 구축합니다.
> *   **자원 관리:**
>     *   크롤링에 필요한 CPU, 메모리, 네트워크 자원을 예측하고, 서버 환경에 맞춰 최적화합니다. (예: `Headless` 모드 사용, 불필요한 리소스 로드 방지)
> *   **버전 관리:**
>     *   크롤링 스크립트도 코드이므로 Git과 같은 버전 관리 시스템을 사용하여 변경 이력을 관리하고, 팀원들과 협업합니다.
>
> 잘 수립된 크롤링 전략은 안정적이고 효율적인 데이터 수집을 가능하게 하며, 데이터 분석 프로젝트의 성공적인 기반이 됩니다.

### 1.4. 데이터 추출 및 저장

크롤링 전략에 따라 웹 페이지에 접근하고 필요한 요소를 찾았다면, 이제 실제 데이터를 추출하고 저장하는 단계입니다. 이 단계에서는 `BeautifulSoup`과 `Selenium`의 기능을 활용하여 데이터를 가져오고, 적절한 형식으로 저장하여 분석에 활용할 수 있도록 준비합니다.

```python
import requests
from bs4 import BeautifulSoup
from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.chrome.options import Options
from webdriver_manager.chrome import ChromeDriverManager
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
import time
import csv
import json
import pandas as pd
from sqlalchemy import create_engine
import sqlite3

# 예시: 가상의 쇼핑몰 제품 페이지 크롤링
# 실제 웹사이트 URL과 HTML 구조에 맞춰 코드를 수정해야 합니다.
product_list_url = "https://example.com/products" # 실제 URL로 변경

def scrape_product_page(url):
    """단일 제품 페이지에서 제품 정보를 추출하는 함수"""
    try:
        # Requests와 BeautifulSoup을 사용한 정적 페이지 크롤링 예시
        response = requests.get(url, timeout=10)
        response.raise_for_status() # HTTP 오류 발생 시 예외
        soup = BeautifulSoup(response.text, 'lxml')

        # 제품 정보 추출 (예시: 실제 HTML 구조에 맞춰 선택자 수정)
        product_name = soup.select_one('h1.product-title').text.strip() if soup.select_one('h1.product-title') else 'N/A'
        price = soup.select_one('span.price').text.strip() if soup.select_one('span.price') else 'N/A'
        description = soup.select_one('div.description').text.strip() if soup.select_one('div.description') else 'N/A'

        # 리뷰 개수 (동적으로 로드될 수 있다면 Selenium 필요)
        # reviews_count = soup.select_one('span.reviews-count').text.strip() if soup.select_one('span.reviews-count') else '0'

        return {
            'product_name': product_name,
            'price': price,
            'description': description,
            'url': url
        }
    except Exception as e:
        print(f"Error scraping {url}: {e}")
        return None

def scrape_dynamic_page_with_selenium(url):
    """Selenium을 사용하여 동적 페이지에서 정보를 추출하는 함수"""
    service = Service(ChromeDriverManager().install())
    options = Options()
    options.add_argument('--headless')
    options.add_argument('--window-size=1920,1080')
    options.add_argument("user-agent=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/100.0.4896.127 Safari/537.36")
    driver = webdriver.Chrome(service=service, options=options)

    try:
        driver.get(url)
        # 동적 콘텐츠 로딩을 위한 명시적 대기
        WebDriverWait(driver, 10).until(
            EC.presence_of_element_located((By.CSS_SELECTOR, 'div.dynamic-content-area'))
        )

        # Selenium으로 요소 찾기 및 텍스트 추출
        dynamic_data = driver.find_element(By.CSS_SELECTOR, 'div.dynamic-content-area').text.strip()
        return {'dynamic_content': dynamic_data, 'url': url}

    except Exception as e:
        print(f"Error scraping dynamic page {url}: {e}")
        return None
    finally:
        driver.quit()

# --- 데이터 추출 실행 --- #
# 이 부분은 실제 프로젝트에서 반복문 등을 통해 여러 페이지를 크롤링하는 로직으로 대체됩니다.

# 정적 페이지 예시
product_data = scrape_product_page(product_list_url)
if product_data:
    all_crawled_data = [product_data]
else:
    all_crawled_data = []

# 동적 페이지 예시 (필요시)
# dynamic_page_url = "https://example.com/dynamic-page" # 실제 URL로 변경
# dynamic_data = scrape_dynamic_page_with_selenium(dynamic_page_url)
# if dynamic_data: all_crawled_data.append(dynamic_data)

print("\n--- Data Extraction Complete ---")
print(all_crawled_data)

# --- 데이터 저장 실행 --- #

# 1. CSV 파일로 저장
csv_file_path = 'crawled_products.csv'
if all_crawled_data:
    df_products = pd.DataFrame(all_crawled_data)
    df_products.to_csv(csv_file_path, index=False, encoding='utf-8')
    print(f"\nData saved to {csv_file_path} (CSV).")

# 2. JSON 파일로 저장
json_file_path = 'crawled_products.json'
if all_crawled_data:
    with open(json_file_path, 'w', encoding='utf-8') as f:
        json.dump(all_crawled_data, f, ensure_ascii=False, indent=4)
    print(f"Data saved to {json_file_path} (JSON).")

# 3. 데이터베이스에 저장 (SQLite 예시)
db_file_path = 'crawled_products.db'
if all_crawled_data:
    engine = create_engine(f'sqlite:///{db_file_path}')
    df_products.to_sql('products', con=engine, if_exists='replace', index=False)
    print(f"Data saved to {db_file_path} (SQLite Database).")

    # 데이터베이스에서 확인
    with sqlite3.connect(db_file_path) as conn:
        cursor = conn.cursor()
        cursor.execute("SELECT * FROM products")
        print("\n--- Data from SQLite DB ---")
        for row in cursor.fetchall():
            print(row)
```

> **[실무 노트] 데이터 추출 및 저장의 품질 관리:**
> 데이터 추출과 저장은 크롤링 프로젝트의 최종 단계이자, 수집된 데이터의 품질을 결정하는 중요한 과정입니다. 단순히 데이터를 가져오는 것을 넘어, 데이터의 정확성, 일관성, 그리고 활용성을 고려해야 합니다.
> 
> *   **데이터 추출 시 오류 처리:**
>     *   `try-except` 블록을 사용하여 요소가 발견되지 않거나(예: `NoSuchElementException`), 네트워크 오류(`requests.exceptions.RequestException`)가 발생했을 때 스크립트가 중단되지 않도록 예외 처리를 해야 합니다.
>     *   요소가 없을 경우 `None`을 반환하거나 기본값(예: 'N/A', '0')을 할당하여 데이터 누락을 방지합니다.
> *   **데이터 정제 (Data Cleaning):**
>     *   추출된 텍스트 데이터는 불필요한 공백, 줄바꿈, 특수 문자 등을 포함할 수 있습니다. `strip()`, `replace()`, 정규 표현식(`re` 모듈) 등을 사용하여 데이터를 깔끔하게 정제해야 합니다.
>     *   숫자나 날짜 형식의 데이터는 적절한 타입으로 변환하고, 유효성 검사를 수행해야 합니다.
> *   **데이터 구조화:**
>     *   수집된 데이터를 딕셔너리나 리스트 오브 딕셔너리 형태로 구조화하여 관리하면 Pandas DataFrame이나 JSON, 데이터베이스에 저장하기 용이합니다.
> *   **저장 형식 선택:**
>     *   **CSV:** 간단한 테이블 형태의 데이터, 소규모 데이터셋, 다른 프로그램과의 쉬운 연동에 적합합니다.
>     *   **JSON:** 계층적 데이터, 스키마가 유연한 데이터, 웹 API와의 연동에 적합합니다.
>     *   **데이터베이스:** 대규모 데이터, 복잡한 쿼리 및 분석, 데이터 무결성 보장이 필요한 경우에 적합합니다. (SQLite, MySQL, PostgreSQL 등)
> *   **데이터 품질 관리:**
>     *   수집된 데이터의 유효성(예: 가격이 음수인지, 날짜 형식이 올바른지)을 주기적으로 검사합니다.
>     *   웹사이트 구조 변경에 대비하여 크롤링 스크립트의 유지보수 계획을 세우고, 데이터 수집 오류 발생 시 알림을 받을 수 있는 시스템을 구축합니다.
> *   **증분 크롤링 (Incremental Crawling):**
>     *   매번 전체 데이터를 다시 크롤링하는 것은 비효율적입니다. 이미 수집된 데이터와 비교하여 새로 추가되거나 변경된 데이터만 업데이트하는 증분 크롤링 전략을 고려합니다. (예: 마지막 크롤링 이후의 게시물만 가져오기, 변경된 제품 정보만 업데이트)
> 
> 데이터 추출과 저장은 크롤링 프로젝트의 최종 산출물이므로, 데이터의 품질과 활용성을 최우선으로 고려하여 신중하게 구현해야 합니다.
