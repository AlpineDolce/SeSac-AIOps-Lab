## 1. 크롤링 성능 최적화

### 1.1. 병렬 처리 (Multiprocessing/Threading)

웹 크롤링은 네트워크 I/O 작업이 많아 단일 프로세스로 실행하면 비효율적일 수 있습니다. 병렬 처리는 여러 작업을 동시에 실행하여 크롤링 속도를 향상시키는 방법입니다. 파이썬에서는 주로 `multiprocessing` (다중 프로세스)과 `threading` (다중 스레드) 모듈을 사용하여 병렬 처리를 구현합니다.

*   **`threading` (다중 스레드):**
    *   **개념:** 하나의 프로세스 내에서 여러 개의 스레드를 생성하여 작업을 동시에 실행합니다. 스레드들은 메모리 공간을 공유합니다.
    *   **장점:** 스레드 생성 및 전환 비용이 낮아 가볍습니다. 메모리 공유가 용이하여 데이터 공유가 필요한 작업에 적합합니다.
    *   **단점:** 파이썬의 GIL(Global Interpreter Lock) 때문에 CPU 바운드(CPU 연산 위주) 작업에서는 진정한 병렬 처리가 어렵습니다. I/O 바운드(네트워크 통신, 파일 입출력 위주) 작업에 더 적합합니다.
*   **`multiprocessing` (다중 프로세스):**
    *   **개념:** 여러 개의 독립적인 프로세스를 생성하여 작업을 동시에 실행합니다. 각 프로세스는 별도의 메모리 공간을 가집니다.
    *   **장점:** GIL의 영향을 받지 않아 CPU 바운드 작업에서도 진정한 병렬 처리가 가능합니다. 프로세스 중 하나가 죽어도 다른 프로세스에 영향을 주지 않아 안정적입니다.
    *   **단점:** 프로세스 생성 및 전환 비용이 스레드보다 높습니다. 메모리 공간이 분리되어 있어 프로세스 간 데이터 공유가 복잡합니다.

```python
import requests
import time
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

# 크롤링할 URL 목록 (예시)
urls = [
    "https://www.example.com",
    "https://www.naver.com",
    "https://www.google.com",
    "https://www.daum.net",
    "https://www.youtube.com"
]

def fetch_url(url):
    """단일 URL을 요청하고 상태 코드를 반환하는 함수"""
    try:
        response = requests.get(url, timeout=5) # 타임아웃 설정
        print(f"Fetched {url}: {response.status_code}")
        return url, response.status_code
    except requests.exceptions.RequestException as e:
        print(f"Error fetching {url}: {e}")
        return url, str(e)

print("\n--- Sequential Fetching ---")
start_time = time.time()
for url in urls:
    fetch_url(url)
end_time = time.time()
print(f"Sequential fetching took {end_time - start_time:.2f} seconds.")

print("\n--- ThreadPoolExecutor (Threading) ---")
start_time = time.time()
with ThreadPoolExecutor(max_workers=5) as executor:
    results = executor.map(fetch_url, urls)
    # for result in results:
    #     print(result)
end_time = time.time()
print(f"ThreadPoolExecutor took {end_time - start_time:.2f} seconds.")

print("\n--- ProcessPoolExecutor (Multiprocessing) ---")
start_time = time.time()
with ProcessPoolExecutor(max_workers=3) as executor:
    results = executor.map(fetch_url, urls)
    # for result in results:
    #     print(result)
end_time = time.time()
print(f"ProcessPoolExecutor took {end_time - start_time:.2f} seconds.")
```

> **[실무 노트] 병렬 처리 전략 선택:**
> 웹 크롤링은 대부분 네트워크 I/O 작업이므로, `threading`이 `multiprocessing`보다 더 적합한 경우가 많습니다. 하지만 `Selenium`과 같이 브라우저를 직접 제어하는 작업은 CPU 자원을 많이 소모할 수 있으므로 `multiprocessing`이 유리할 수도 있습니다.
> 
> *   **`ThreadPoolExecutor` (스레딩):**
>     *   **장점:** 구현이 간단하고, 스레드 간 데이터 공유가 용이합니다. 네트워크 요청처럼 I/O 대기가 많은 작업에서 효율적입니다.
>     *   **적합한 시나리오:** `Requests` 라이브러리를 사용하여 여러 URL에서 동시에 데이터를 가져올 때.
> *   **`ProcessPoolExecutor` (멀티프로세싱):**
>     *   **장점:** 파이썬 GIL의 영향을 받지 않아 CPU 바운드 작업에서 진정한 병렬 처리가 가능합니다. 각 프로세스가 독립적이므로 하나가 실패해도 다른 프로세스에 영향을 주지 않습니다.
>     *   **적합한 시나리오:** `Selenium`을 사용하여 여러 브라우저를 동시에 실행하거나, 크롤링 후 복잡한 데이터 처리(CPU 연산)를 병렬로 수행할 때.
> *   **`concurrent.futures` 모듈:**
>     *   `ThreadPoolExecutor`와 `ProcessPoolExecutor`를 포함하는 고수준(high-level) 인터페이스를 제공하여 병렬 처리를 쉽게 구현할 수 있습니다. 복잡한 스레드/프로세스 관리 없이 `map()`이나 `submit()` 메서드를 통해 작업을 제출하고 결과를 받을 수 있습니다.
> *   **주의사항:**
>     *   **서버 부하:** 병렬 처리를 과도하게 사용하면 크롤링 대상 서버에 큰 부하를 줄 수 있습니다. `time.sleep()`을 사용하여 요청 간 지연 시간을 두거나, `max_workers`를 적절히 제한해야 합니다.
>     *   **봇 탐지:** 너무 빠른 요청은 봇으로 탐지되어 차단될 위험이 있습니다.
>     *   **자원 관리:** `multiprocessing` 사용 시 각 프로세스가 별도의 메모리를 사용하므로, 메모리 사용량에 주의해야 합니다.
>
> 실무에서는 크롤링 대상 웹사이트의 정책과 서버 부하를 고려하여 적절한 병렬 처리 전략과 작업자 수를 선택하는 것이 중요합니다.

### 1.2. 비동기 크롤링 (Asyncio/Aiohttp)

비동기 프로그래밍은 단일 스레드에서 여러 I/O 바운드 작업을 동시에 처리하는 효율적인 방법입니다. 웹 크롤링은 네트워크 I/O 작업이 대부분이므로, 비동기 방식을 사용하면 대기 시간 동안 다른 작업을 수행하여 전체 크롤링 속도를 크게 향상시킬 수 있습니다. 파이썬에서는 `asyncio` 모듈이 비동기 프로그래밍의 기반을 제공하며, `aiohttp`와 같은 라이브러리가 비동기 HTTP 요청을 지원합니다.

```python
import asyncio
import aiohttp
import time

# 크롤링할 URL 목록 (예시)
urls = [
    "https://www.example.com",
    "https://www.naver.com",
    "https://www.google.com",
    "https://www.daum.net",
    "https://www.youtube.com"
]

async def fetch_url_async(session, url):
    """비동기적으로 URL을 요청하고 상태 코드를 반환하는 함수"""
    try:
        async with session.get(url, timeout=5) as response:
            print(f"Fetched {url}: {response.status}")
            return url, response.status
    except aiohttp.ClientError as e:
        print(f"Error fetching {url}: {e}")
        return url, str(e)
    except asyncio.TimeoutError:
        print(f"Timeout fetching {url}")
        return url, "Timeout"

async def main_async():
    """비동기 크롤링을 실행하는 메인 함수"""
    start_time = time.time()
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_url_async(session, url) for url in urls]
        await asyncio.gather(*tasks)
    end_time = time.time()
    print(f"\nAsync fetching took {end_time - start_time:.2f} seconds.")

if __name__ == "__main__":
    # Python 3.7+에서는 asyncio.run() 사용
    asyncio.run(main_async())

    # Python 3.6 이하에서는
    # loop = asyncio.get_event_loop()
    # loop.run_until_complete(main_async())
    # loop.close()
```

> **[실무 노트] 비동기 크롤링의 장점과 적용:**
> 비동기 크롤링은 특히 대량의 URL을 동시에 요청해야 하는 상황에서 `threading`이나 `multiprocessing`보다 더 효율적인 성능을 제공할 수 있습니다.
> 
> *   **동작 원리:**
>     *   `asyncio`는 파이썬의 비동기 프로그래밍을 위한 프레임워크입니다. `await` 키워드를 사용하여 I/O 작업(네트워크 요청, 파일 읽기 등)이 완료될 때까지 기다리는 동안, CPU는 다른 작업을 수행할 수 있도록 제어권을 이벤트 루프에 넘겨줍니다.
>     *   `aiohttp`는 `asyncio` 기반의 비동기 HTTP 클라이언트/서버 라이브러리입니다. `Requests`와 유사하게 HTTP 요청을 보내지만, 비동기적으로 동작하여 여러 요청을 동시에 처리할 수 있습니다.
> *   **장점:**
>     *   **높은 동시성:** 단일 스레드에서 수천, 수만 개의 동시 요청을 효율적으로 처리할 수 있습니다. 이는 스레드나 프로세스를 많이 생성하는 것보다 시스템 자원(메모리)을 훨씬 적게 사용합니다.
>     *   **I/O 바운드 작업에 최적:** 웹 크롤링처럼 네트워크 대기 시간이 긴 I/O 바운드 작업에서 CPU를 효율적으로 활용하여 전체 작업 시간을 단축시킵니다.
>     *   **GIL(Global Interpreter Lock)의 영향 없음:** `asyncio`는 GIL의 영향을 받지 않으므로, I/O 바운드 작업에서 진정한 동시성을 달성할 수 있습니다.
> *   **적합한 시나리오:**
>     *   대량의 URL에서 데이터를 수집해야 할 때.
>     *   API 호출을 통해 데이터를 가져올 때.
>     *   `Requests` 라이브러리만으로는 속도 한계에 부딪혔을 때.
> *   **주의사항:**
>     *   **학습 곡선:** 비동기 프로그래밍(`async`/`await` 문법, 이벤트 루프)은 일반적인 순차 프로그래밍보다 학습 곡선이 높습니다.
>     *   **`Selenium`과의 통합:** `Selenium`은 동기적으로 동작하는 라이브러리이므로, `asyncio`와 직접적으로 통합하기 어렵습니다. `Selenium`을 비동기적으로 사용하려면 `asyncio`의 `run_in_executor`를 사용하거나, `playwright`와 같은 비동기 브라우저 자동화 라이브러리를 고려해야 합니다.
>     *   **서버 부하:** 비동기 크롤링은 매우 빠르게 요청을 보낼 수 있으므로, 크롤링 대상 서버에 과도한 부하를 주지 않도록 요청 간 지연 시간(`asyncio.sleep()`)을 적절히 설정해야 합니다.
>
> 비동기 크롤링은 대규모 웹 크롤링 프로젝트에서 성능을 극대화하는 고급 기술이므로, 필요에 따라 학습하고 적용하는 것을 권장합니다.

### 1.3. 캐싱 (Caching)

캐싱은 이전에 가져온 데이터를 임시 저장소에 보관하여, 동일한 데이터에 대한 다음 요청 시 웹 서버에 다시 요청을 보내지 않고 캐시된 데이터를 사용하여 크롤링 속도를 향상시키고 서버 부하를 줄이는 기법입니다. 특히 자주 접근하는 페이지나 변경이 적은 데이터를 크롤링할 때 매우 효과적입니다.

```python
import requests
import os
import hashlib
import json
import time

CACHE_DIR = 'web_cache'
os.makedirs(CACHE_DIR, exist_ok=True)

def get_cache_path(url):
    """URL을 해싱하여 캐시 파일 경로 생성"""
    hash_object = hashlib.md5(url.encode())
    return os.path.join(CACHE_DIR, hash_object.hexdigest() + '.json')

def fetch_with_cache(url, cache_timeout=3600): # 기본 1시간 캐시 유지
    """캐싱을 적용하여 URL 요청"""
    cache_path = get_cache_path(url)

    # 1. 캐시 확인
    if os.path.exists(cache_path):
        # 캐시 파일이 존재하고, 유효 기간 내라면 캐시된 데이터 반환
        file_mod_time = os.path.getmtime(cache_path)
        if (time.time() - file_mod_time) < cache_timeout:
            print(f"[Cache Hit] Loading from cache: {url}")
            with open(cache_path, 'r', encoding='utf-8') as f:
                return json.load(f)

    # 2. 캐시 미스 또는 만료 시, 실제 요청
    print(f"[Cache Miss] Fetching from web: {url}")
    try:
        response = requests.get(url, timeout=10)
        response.raise_for_status() # HTTP 오류 발생 시 예외
        data = {
            'url': url,
            'status_code': response.status_code,
            'text': response.text[:500] # 예시로 일부만 저장
        }
        # 캐시 저장
        with open(cache_path, 'w', encoding='utf-8') as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
        return data
    except requests.exceptions.RequestException as e:
        print(f"Error fetching {url}: {e}")
        return None

if __name__ == "__main__":
    test_url = "https://www.example.com"

    # 첫 번째 요청 (캐시 미스)
    result1 = fetch_with_cache(test_url)
    if result1: print(f"Result 1 Status: {result1['status_code']}")

    time.sleep(2) # 잠시 대기

    # 두 번째 요청 (캐시 히트)
    result2 = fetch_with_cache(test_url)
    if result2: print(f"Result 2 Status: {result2['status_code']}")

    # 캐시 만료 후 요청 (캐시 미스)
    print("\nWaiting for cache to expire (5 seconds timeout)...")
    time.sleep(5) # 캐시 타임아웃보다 길게 대기
    result3 = fetch_with_cache(test_url, cache_timeout=3) # 짧은 캐시 타임아웃 설정
    if result3: print(f"Result 3 Status: {result3['status_code']}")
```

> **[실무 노트] 크롤링 캐싱 전략:**
> 캐싱은 크롤링 속도를 높이고 대상 서버의 부하를 줄이는 매우 효과적인 방법입니다. 하지만 캐시 무효화(Cache Invalidation) 전략을 잘 세우는 것이 중요합니다.
>
> *   **캐싱의 목적:**
>     *   **속도 향상:** 동일한 페이지를 여러 번 요청할 필요 없이 로컬 캐시에서 빠르게 데이터를 가져옵니다.
>     *   **서버 부하 감소:** 대상 웹 서버에 대한 불필요한 요청을 줄여 서버에 가해지는 부담을 완화합니다.
>     *   **네트워크 비용 절감:** 클라우드 환경에서 네트워크 트래픽 비용을 줄일 수 있습니다.
> *   **캐싱 구현 방법:**
>     *   **로컬 파일 시스템:** 가장 간단한 방법입니다. URL을 해싱하여 파일 이름으로 사용하고, 응답 내용을 파일로 저장합니다. (위 예시)
>     *   **데이터베이스:** SQLite, Redis, MongoDB 등 데이터베이스를 캐시 저장소로 활용할 수 있습니다. Redis는 인메모리(in-memory) 데이터베이스로 매우 빠른 캐싱 성능을 제공합니다.
>     *   **라이브러리 활용:** `requests-cache`와 같은 라이브러리를 사용하면 `Requests` 요청에 캐싱 기능을 쉽게 추가할 수 있습니다.
> *   **캐시 무효화 (Cache Invalidation) 전략:**
>     캐시된 데이터가 원본 웹 페이지의 내용과 달라지는 것을 방지하기 위한 전략입니다. 잘못된 캐싱은 부정확한 데이터를 초래할 수 있습니다.
>     *   **TTL (Time To Live) 기반:** 일정 시간(예: 1시간, 1일)이 지나면 캐시를 만료시켜 다시 웹 서버에 요청을 보냅니다. 데이터 변경 주기가 예측 가능한 경우에 적합합니다.
>     *   **수동 무효화:** 특정 이벤트(예: 웹사이트 구조 변경 감지) 발생 시 수동으로 캐시를 삭제합니다.
>     *   **조건부 요청:** `If-Modified-Since` 또는 `ETag` 헤더를 사용하여 서버에 데이터 변경 여부를 확인하고, 변경된 경우에만 새로운 데이터를 가져옵니다.
> *   **주의사항:**
>     *   **데이터 신선도:** 캐싱은 데이터의 신선도를 희생할 수 있습니다. 실시간성이 중요한 데이터(예: 주가, 실시간 뉴스)에는 캐싱을 신중하게 적용해야 합니다.
>     *   **저장 공간:** 캐시 데이터가 많아지면 저장 공간을 많이 차지할 수 있으므로, 주기적인 캐시 정리 정책이 필요합니다.
>
> 캐싱은 크롤링 성능을 크게 향상시키지만, 데이터의 특성과 비즈니스 요구사항을 고려하여 적절한 캐싱 전략을 수립하는 것이 중요합니다.

### 1.4. 불필요한 리소스 로드 방지

웹 페이지는 HTML 외에도 이미지, CSS, JavaScript, 폰트 등 다양한 리소스를 포함합니다. `Selenium`과 같이 브라우저를 직접 사용하는 크롤링 방식에서는 이러한 모든 리소스를 로드하므로, 불필요한 리소스 로드를 방지하면 크롤링 속도를 높이고 시스템 자원 소모를 줄일 수 있습니다.

from selenium import webdriver
from selenium.webdriver.chrome.service import Service
from selenium.webdriver.chrome.options import Options
from webdriver_manager.chrome import ChromeDriverManager
import time

# WebDriver 설정 (이전 섹션 참조)
service = Service(ChromeDriverManager().install())
options = Options()
options.add_argument('--headless')
options.add_argument('--window-size=1920,1080')
options.add_argument("user-agent=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/100.0.4896.127 Safari/537.36")

# 불필요한 리소스 로드 방지 옵션
# ChromeOptions의 experimental_options를 사용하여 성능 향상
prefs = {"profile.managed_default_content_settings.images": 2} # 이미지 로드 비활성화
options.add_experimental_option("prefs", prefs)

# JavaScript 비활성화 (필요한 경우)
# options.add_argument('--disable-javascript')

driver = webdriver.Chrome(service=service, options=options)

    end_time = time.time()

> **[실무 노트] 불필요한 리소스 로드 방지 전략:**
> `Selenium`은 실제 브라우저를 사용하므로, 웹 페이지의 모든 리소스를 로드합니다. 하지만 크롤링 목적에 따라 이미지, CSS, JavaScript 등이 필요 없는 경우가 많습니다. 이러한 리소스 로드를 방지하면 크롤링 속도를 크게 향상시키고, 네트워크 트래픽 및 시스템 자원 소모를 줄일 수 있습니다.
> 
> *   **이미지 로드 비활성화:**
>     *   `ChromeOptions`의 `prefs`를 사용하여 `profile.managed_default_content_settings.images` 값을 2로 설정하면 이미지를 로드하지 않습니다. 이는 이미지 로딩에 드는 시간과 네트워크 트래픽을 절약하여 크롤링 속도를 높이는 데 매우 효과적입니다.
> *   **JavaScript 비활성화:**
>     *   `options.add_argument('--disable-javascript')` 옵션을 사용하면 JavaScript 실행을 비활성화할 수 있습니다. 이는 JavaScript로 동적으로 로드되는 콘텐츠가 필요 없는 정적 페이지 크롤링 시 유용합니다. 하지만 JavaScript가 필수적인 페이지에서는 이 옵션을 사용하면 페이지가 제대로 렌더링되지 않거나 데이터가 로드되지 않을 수 있습니다.
> *   **CSS 로드 비활성화:**
>     *   CSS 로드를 직접적으로 비활성화하는 `Selenium` 옵션은 일반적으로 제공되지 않습니다. 하지만 `ChromeOptions`의 `prefs`를 통해 `profile.managed_default_content_settings.stylesheets` 값을 2로 설정하여 CSS 로드를 막을 수 있습니다.
> *   **네트워크 요청 차단 (고급):**
>     *   `Selenium` 자체만으로는 특정 유형의 네트워크 요청(예: 광고 스크립트, 분석 스크립트)을 선택적으로 차단하기 어렵습니다. `Selenium Wire`나 `BrowserMob Proxy`와 같은 프록시 도구를 `Selenium`과 함께 사용하면, 네트워크 요청을 가로채어 특정 URL 패턴의 리소스 로드를 차단할 수 있습니다. 이는 가장 강력한 방법이지만 설정이 복잡합니다.
> 
> **실무 가이드:**
> 1.  **크롤링 목적 명확화:** 어떤 데이터가 필요한지 명확히 하고, 해당 데이터를 얻는 데 불필요한 리소스(이미지, CSS, JS 등)가 무엇인지 파악합니다.
> 2.  **단계별 적용:** 먼저 이미지 로드 비활성화와 같이 효과가 크고 안전한 옵션부터 적용해보고, 필요에 따라 JavaScript 비활성화나 네트워크 요청 차단과 같은 고급 기술을 고려합니다.
> 3.  **테스트 필수:** 옵션을 적용한 후 웹 페이지가 제대로 로드되고 원하는 데이터가 정상적으로 추출되는지 반드시 테스트해야 합니다. 특히 JavaScript 비활성화는 페이지 렌더링에 큰 영향을 미칠 수 있습니다.
> 
> 불필요한 리소스 로드를 방지하는 것은 `Selenium` 크롤링의 효율성을 극대화하고, 대상 서버에 대한 부담을 줄이는 데 매우 중요한 최적화 기법입니다.
