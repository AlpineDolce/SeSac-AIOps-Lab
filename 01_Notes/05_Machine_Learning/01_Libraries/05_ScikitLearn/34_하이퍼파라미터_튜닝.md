## 1. 하이퍼파라미터 튜닝이란?
머신러닝 모델을 만드는 과정은 종종 요리에 비유됩니다. 데이터는 '재료', 모델 알고리즘은 '조리법'이라면, **하이퍼파라미터는 그 조리법의 세부적인 조절 값(예: 불의 세기, 조리 시간, 양념의 양)**에 해당합니다. 아무리 좋은 재료와 조리법이 있어도, 불 조절에 실패하거나 양념을 잘못 넣으면 맛있는 요리가 나올 수 없는 것처럼, 머신러닝 모델도 하이퍼파라미터 설정에 따라 성능이 크게 달라집니다.

**하이퍼파라미터 튜닝(Hyperparameter Tuning)**이란, 이처럼 모델의 성능을 최대로 끌어올릴 수 있는 최적의 '조절 값' 조합을 체계적으로 찾아내는 과정을 의미합니다.

### 1.1. 모델 파라미터 vs. 하이퍼파라미터
머신러닝 모델의 '값'은 두 종류로 나뉩니다. 이 둘을 명확히 구분하는 것이 중요합니다.

*   **모델 파라미터 (Model Parameters):** 모델이 **데이터로부터 스스로 학습하는** 변수입니다. 이 값들은 학습 데이터의 패턴을 가장 잘 표현하도록 훈련 과정에서 자동으로 최적화됩니다. 개발자가 직접 설정하지 않습니다.
    *   **예시:** 선형 회귀 모델의 가중치(계수) `w`와 편향 `b`, 인공 신경망의 각 연결 가중치들.

*   **하이퍼파라미터 (Hyperparameters):** 모델이 학습을 시작하기 전에 개발자가 **직접 설정해야 하는** 값입니다. 이 값들은 모델의 구조나 학습 방식을 결정하며, 학습 과정 자체를 제어하는 역할을 합니다.
    *   **예시:**
        *   K-최근접 이웃(K-NN)의 이웃 수 `n_neighbors`
        *   의사결정 트리의 최대 깊이 `max_depth`
        *   서포트 벡터 머신(SVM)의 비용 `C`와 커널 계수 `gamma`
        *   신경망의 학습률(learning rate), 은닉층의 수, 뉴런의 수
        *   경사 하강법의 반복 횟수(epochs)

### 1.2. 왜 하이퍼파라미터 튜닝이 필요한가?
최적의 하이퍼파라미터 조합은 데이터셋이나 해결하려는 문제에 따라 모두 다릅니다. 따라서 "만능" 하이퍼파라미터 설정은 존재하지 않습니다. 하이퍼파라미터 튜닝이 필요한 이유는 모델의 **일반화 성능(Generalization Performance)**을 극대화하기 위함이며, 이는 결국 **과적합(Overfitting)과 과소적합(Underfitting) 사이의 균형**을 찾는 것과 같습니다.

*   **과소적합 (Underfitting):** 모델이 너무 단순하여 데이터의 패턴을 제대로 학습하지 못하는 상태입니다. (예: `max_depth`를 너무 작게 설정한 의사결정 트리)
*   **과적합 (Overfitting):** 모델이 학습 데이터에만 너무 치중하여 노이즈까지 학습해버린 나머지, 새로운 데이터에 대한 예측 성능이 떨어지는 상태입니다. (예: `max_depth`를 너무 크게 설정한 의사결정 트리)

하이퍼파라미터 튜닝은 이 두 가지 극단 사이에서 최적의 지점, 즉 모델이 학습 데이터의 패턴을 충분히 잘 학습하면서도 새로운 데이터에 대해 안정적인 예측 성능을 보이는 '스위트 스팟(sweet spot)'을 찾는 과정입니다. 이를 통해 모델의 신뢰도를 높이고 실제 비즈니스 문제에 성공적으로 적용할 수 있게 됩니다.

## 2. 그리드 서치 (Grid Search)
그리드 서치는 가장 기본적이고 직관적인 하이퍼파라미터 튜닝 방법입니다. 이름 그대로, 사용자가 지정한 하이퍼파라미터 값들을 격자(Grid) 형태로 만들어, 그 격자의 모든 점(모든 가능한 조합)을 체계적으로 탐색합니다.

### 2.1. `GridSearchCV` 핵심 개념
`GridSearchCV`는 Scikit-learn에서 그리드 서치를 구현한 클래스이며, 두 가지 핵심 기능을 결합한 것입니다.
1.  **Grid Search:** 탐색할 하이퍼파라미터들의 후보 값 목록을 전달하면, 모든 가능한 조합을 생성합니다.
2.  **Cross Validation (CV):** 생성된 각 조합에 대해 교차 검증을 수행하여 모델의 성능을 안정적으로 평가합니다. 특정 데이터 분할(split)에 성능이 우연히 좋게 나오는 경우를 방지하고, 모델의 일반화 성능을 더 신뢰성 있게 측정합니다.

예를 들어, `C` 후보가 `[0.1, 1, 10]`이고 `gamma` 후보가 `[0.1, 0.01]`라면 다음과 같은 2D 격자가 만들어집니다. `GridSearchCV`는 이 6개의 모든 조합에 대해 교차 검증을 수행하여 평균 점수가 가장 높은 조합을 선택합니다.

| | `gamma=0.1` | `gamma=0.01` |
| :--- | :---: | :---: |
| **`C=0.1`** | 탐색 1 | 탐색 2 |
| **`C=1`** | 탐색 3 | 탐색 4 |
| **`C=10`** | 탐색 5 | 탐색 6 |

전체 탐색 횟수는 **(C 후보 개수) x (gamma 후보 개수) x (CV 폴드 수)** 가 됩니다.

### 2.2. 장단점
*   **장점:**
    *   **최적값 보장:** 사용자가 지정한 탐색 공간 내에서는 모든 조합을 검증하므로, 이론적으로 최적의 하이퍼파라미터 조합을 반드시 찾을 수 있습니다.
    *   **간단한 사용법:** 개념이 직관적이고 Scikit-learn을 통해 쉽게 구현할 수 있습니다.

*   **단점:**
    *   **계산 비용:** 탐색해야 할 하이퍼파라미터의 종류가 늘어나거나 각 후보 값의 개수가 많아지면, 탐색해야 할 조합의 수가 기하급수적으로 증가합니다. 이를 '차원의 저주(Curse of Dimensionality)'라고도 하며, 매우 많은 시간과 컴퓨팅 자원을 소모하게 됩니다.
        *   예시: 파라미터 4개, 각 후보 5개 -> `5 * 5 * 5 * 5 = 625`개의 조합 탐색 필요.
    *   **비효율성:** 실제 모델 성능에 거의 영향을 주지 않는 불필요한 하이퍼파라미터까지 모두 탐색에 포함시켜 비효율을 초래할 수 있습니다.

### 2.3. 실습
`Pipeline`과 함께 `GridSearchCV`를 사용하여 SVM 모델의 하이퍼파라미터를 튜닝하는 예제입니다.

#### 2.3.1. 코드 구현
```python
from sklearn.model_selection import GridSearchCV
from sklearn.svm import SVC
from sklearn.datasets import load_iris
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
import pandas as pd

# 데이터 로드
iris = load_iris()
X, y = iris.data, iris.target

# 파이프라인 정의: 데이터 스케일링 후 SVM 모델 적용
# 파이프라인을 사용하면 데이터 전처리와 모델 학습을 하나의 객체로 묶어 관리할 수 있어,
# 교차 검증 시 각 폴드마다 동일한 전처리 과정을 적용할 수 있습니다.
pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('svc', SVC(random_state=42))
])

# 탐색할 하이퍼파라미터 그리드 정의
# 파이프라인 내의 단계 이름과 이중 밑줄(__)을 사용하여 해당 단계의 파라미터를 지정
param_grid = {
    'svc__C': [0.1, 1, 10, 100],         # 규제 강도
    'svc__gamma': [0.1, 0.01, 0.001],    # 결정 경계의 곡률
    'svc__kernel': ['rbf', 'linear']     # 커널 함수
}
# 총 탐색 횟수: 4 * 3 * 2 = 24개 조합 * 5-fold CV = 120번의 모델 학습

# GridSearchCV 객체 생성
# cv=5: 5-겹 교차 검증을 의미
# n_jobs=-1: 사용 가능한 모든 CPU 코어를 사용하여 병렬로 학습
grid_search = GridSearchCV(pipe, param_grid, cv=5, scoring='accuracy', n_jobs=-1, verbose=1)

# 그리드 서치 수행 (학습 데이터에 대해)
grid_search.fit(X, y)

# 탐색 결과 확인
print(f"\n최적의 하이퍼파라미터: {grid_search.best_params_}")
print(f"최고 교차 검증 정확도: {grid_search.best_score_:.4f}")

# cv_results_ 속성을 DataFrame으로 변환하여 전체 결과 확인
cv_results_df = pd.DataFrame(grid_search.cv_results_)
print("\n--- 전체 탐색 결과 (상위 5개) ---")
print(cv_results_df.sort_values(by='rank_test_score').head(5)[['param_svc__C', 'param_svc__gamma', 'param_svc__kernel', 'mean_test_score']])
```

#### 2.3.2. 결과 해석
*   **`최적의 하이퍼파라미터` (`best_params_`):** `GridSearchCV`가 찾은 모든 조합 중 교차 검증 평균 점수가 가장 높았던 하이퍼파라미터 조합을 보여줍니다. 위 예시에서는 `{'svc__C': 10, 'svc__gamma': 0.1, 'svc__kernel': 'rbf'}` 와 같은 결과가 나올 수 있습니다.
*   **`최고 교차 검증 정확도` (`best_score_`):** 위 최적의 하이퍼파라미터 조합으로 5-겹 교차 검증을 수행했을 때의 평균 정확도를 의미합니다. 이는 모델이 새로운 데이터에 대해 보여줄 것으로 기대되는 성능 추정치입니다.
*   **`전체 탐색 결과` (`cv_results_`):** 그리드 서치가 수행한 모든 조합에 대한 상세 결과를 담고 있습니다. 각 조합의 평균 점수(`mean_test_score`), 표준 편차(`std_test_score`), 순위(`rank_test_score`) 등을 확인할 수 있어, 어떤 파라미터가 성능에 더 큰 영향을 미치는지 분석하는 데 도움이 됩니다.

`GridSearchCV`는 최적의 파라미터를 찾은 후, **전체 학습 데이터**를 사용하여 `best_params_`로 모델을 자동으로 다시 학습시킵니다. 이 최종 모델은 `grid_search.best_estimator_` 속성에 저장되어 있으며, 별도의 재학습 없이 바로 예측에 사용할 수 있습니다.

## 3. 랜덤 서치 (Random Search)
랜덤 서치는 그리드 서치의 비효율성을 개선하기 위해 제안된 방법입니다. 모든 조합을 다 탐색하는 대신, 지정된 범위 내에서 하이퍼파라미터 조합을 **무작위로 샘플링**하여 탐색합니다.

### 3.1. `RandomizedSearchCV` 핵심 개념
`RandomizedSearchCV`는 사용자가 지정한 하이퍼파라미터의 **분포(distribution)**에서 **정해진 횟수(`n_iter`)만큼** 조합을 무작위로 추출하여 교차 검증을 수행합니다.

*   **핵심 차이점:** 그리드 서치가 정해진 '점'들을 모두 검사한다면, 랜덤 서치는 정해진 '범위' 안에서 무작위로 '점'을 찍어보는 방식입니다.
*   **`n_iter`의 중요성:** 이 파라미터는 **탐색 횟수**를 의미하며, 탐색 시간과 성능 사이의 트레이드오프를 조절하는 핵심적인 역할을 합니다. `n_iter`를 늘리면 최적의 조합을 찾을 확률은 높아지지만, 탐색 시간은 길어집니다.

연구에 따르면, 대부분의 경우 중요한 하이퍼파라미터는 소수이며, 이러한 중요한 파라미터들의 최적값은 넓은 범위에 걸쳐 있을 수 있습니다. 랜덤 서치는 덜 중요한 파라미터에 시간을 낭비하지 않고, 다양한 값을 시도함으로써 중요한 파라미터의 최적값을 더 효율적으로 찾을 가능성이 있습니다.

### 3.2. 장단점
*   **장점:**
    *   **효율성 및 속도:** 그리드 서치보다 훨씬 적은 반복으로도 준수한, 혹은 더 나은 성능의 하이퍼파라미터 조합을 찾을 수 있습니다. 특히 탐색 공간이 매우 클 때 효과적입니다.
    *   **유연한 탐색:** 그리드 서치처럼 정해진 값만 시도하는 것이 아니라, 연속형 하이퍼파라미터(예: learning rate)의 경우 지정된 분포 내에서 다양한 값을 탐색할 수 있어 더 세밀한 최적화가 가능합니다.
    *   **중요한 파라미터 집중:** 운이 좋다면, 성능에 큰 영향을 미치는 소수의 중요한 파라미터에 대해 더 다양한 값들을 테스트해볼 수 있습니다.

*   **단점:**
    *   **최적값 보장 불가:** 무작위 샘플링 방식이므로, 그리드 서치처럼 지정된 공간 내의 최적 조합을 반드시 찾는다는 보장은 없습니다.
    *   **재현성:** `random_state`를 고정하지 않으면 실행할 때마다 결과가 달라질 수 있습니다.

### 3.3. 실습
`RandomizedSearchCV`를 사용하여 랜덤 포레스트 모델의 하이퍼파라미터를 튜닝하는 예제입니다. 랜덤 포레스트는 튜닝할 하이퍼파라미터가 많아 랜덤 서치가 효과적인 대표적인 모델입니다.

#### 3.3.1. 코드 구현
```python
from sklearn.model_selection import RandomizedSearchCV
from sklearn.ensemble import RandomForestClassifier
from sklearn.datasets import load_iris
from scipy.stats import randint, uniform # 하이퍼파라미터 분포 정의를 위함
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
import pandas as pd

# 데이터 로드
iris = load_iris()
X, y = iris.data, iris.target

# 파이프라인 정의: 스케일링 -> 랜덤 포레스트
pipe_rf = Pipeline([
    ('scaler', StandardScaler()),
    ('rf', RandomForestClassifier(random_state=42))
])

# 탐색할 하이퍼파라미터 분포 정의
# scipy.stats의 분포 객체를 사용하여 연속형/이산형 값의 범위를 지정
param_dist = {
    'rf__n_estimators': randint(10, 200),       # 트리의 개수 (10~199 사이 정수)
    'rf__max_depth': randint(1, 10),            # 트리의 최대 깊이 (1~9 사이 정수)
    'rf__min_samples_split': randint(2, 20),    # 노드를 분할하기 위한 최소 샘플 수
    'rf__min_samples_leaf': randint(1, 20),     # 리프 노드가 되기 위한 최소 샘플 수
    'rf__max_features': uniform(0.5, 0.5)       # 최적 분할을 위해 고려할 특성의 최대 비율 (0.5~1.0 사이 실수)
}

# RandomizedSearchCV 객체 생성
# n_iter=50: 50개의 조합을 무작위로 샘플링하여 테스트
random_search = RandomizedSearchCV(pipe_rf, param_distributions=param_dist, n_iter=50, cv=5, 
                                   scoring='accuracy', random_state=42, n_jobs=-1, verbose=1)

# 랜덤 서치 수행
random_search.fit(X, y)

# 탐색 결과 확인
print(f"
최적의 하이퍼파라미터: {random_search.best_params_}")
print(f"최고 교차 검증 정확도: {random_search.best_score_:.4f}")

# cv_results_ 속성을 DataFrame으로 변환하여 전체 결과 확인
cv_results_df_rand = pd.DataFrame(random_search.cv_results_)
print("
--- 전체 탐색 결과 (상위 5개) ---")
print(cv_results_df_rand.sort_values(by='rank_test_score').head(5)[['params', 'mean_test_score']])
```

#### 3.3.2. 결과 해석
*   **`param_dist`:** `GridSearchCV`에서는 후보 값들을 리스트(`[]`)로 전달했지만, `RandomizedSearchCV`에서는 `scipy.stats`의 분포 객체(`randint`, `uniform` 등)를 사용하여 탐색할 값의 '범위'를 지정합니다. 이를 통해 훨씬 넓고 유연한 탐색이 가능해집니다.
*   **`n_iter=50`:** 이 예제에서는 총 50개의 하이퍼파라미터 조합을 무작위로 테스트합니다. 총 학습 횟수는 `50 * 5-fold CV = 250`번으로, 그리드 서치보다 훨씬 적은 횟수로 넓은 범위를 탐색할 수 있습니다.
*   **`최적의 하이퍼파라미터` (`best_params_`):** 테스트한 50개의 조합 중 교차 검증 평균 점수가 가장 높았던 조합을 보여줍니다.
*   **`최고 교차 검증 정확도` (`best_score_`):** 최적 조합의 교차 검증 평균 점수입니다.

랜덤 서치는 제한된 시간과 자원 내에서 최대한 넓은 하이퍼파라미터 공간을 효율적으로 탐색하고자 할 때 매우 강력한 도구입니다.

### 4. Halving Search

-   `HalvingGridSearchCV`와 `HalvingRandomSearchCV`는 연속적인 제거(successive halving) 방식을 사용하여 하이퍼파라미터 튜닝을 수행한다.
-   초기에는 적은 리소스(데이터 샘플)로 많은 후보를 평가하고, 점차적으로 유망한 후보들에게 더 많은 리소스를 할당하여 탐색 효율을 높인다.

#### 4.1. 예제 코드 (HalvingGridSearchCV)

```python
from sklearn.experimental import enable_halving_search_cv
from sklearn.model_selection import HalvingGridSearchCV
from sklearn.svm import SVC
from sklearn.datasets import load_iris

# 데이터 로드
iris = load_iris()
X, y = iris.data, iris.target

# 모델 생성
svc = SVC()

# 하이퍼파라미터 그리드 설정
param_grid = {
    'C': [0.1, 1, 10, 100],
    'gamma': [1, 0.1, 0.01, 0.001],
    'kernel': ['rbf', 'linear']
}

# HalvingGridSearchCV 객체 생성
halving_search = HalvingGridSearchCV(svc, param_grid, cv=5, factor=3,
                                     refit=True, verbose=2, random_state=42)

# 모델 훈련
halving_search.fit(X, y)

# 최적의 하이퍼파라미터와 점수 출력
print("Best parameters found: ", halving_search.best_params_)
print("Best score: ", halving_search.best_score_)
```

---

#### 4.2. 주요 파라미터 설명

-   `estimator`: 튜닝할 모델 객체
-   `param_grid` / `param_distributions`: 탐색할 하이퍼파라미터의 목록이나 분포
-   `cv`: 교차 검증 폴드 수
-   `n_iter`: `RandomizedSearchCV`, `BayesSearchCV`에서 탐색할 횟수
-   `scoring`: 모델 성능 평가 지표 (e.g., 'accuracy', 'f1', 'roc_auc')
-   `refit`: 최적의 하이퍼파라미터로 전체 데이터에 대해 모델을 다시 학습시킬지 여부
-   `verbose`: 진행 상황 출력 레벨
-   `random_state`: 재현성을 위한 시드 값
-   `n_jobs`: 병렬로 실행할 작업 수 (-1은 모든 CPU 코어 사용)

## 5. 베이지안 최적화 (Bayesian Optimization)
베이지안 최적화는 그리드 서치나 랜덤 서치보다 한 단계 더 발전한 **지능적인 탐색** 방법입니다. 이전 탐색 결과를 단순히 버리는 것이 아니라, 그 정보를 적극적으로 활용하여 다음 탐색 지점을 결정합니다. 마치 '감'으로 맛을 보며 다음 양념을 조절하는 요리사처럼, 베이지안 최적화는 **과거의 데이터를 바탕으로 최적의 값을 찾아나가는** 효율적인 접근 방식입니다.

### 5.1. 핵심 개념
베이지안 최적화는 두 가지 핵심 구성 요소를 기반으로 동작합니다.

1.  **대체 모델 (Surrogate Model):**
    *   **역할:** 실제 목적 함수(하이퍼파라미터 조합을 입력받아 모델 성능을 출력하는 함수)는 평가 비용이 매우 비쌉니다. 대체 모델은 이 비싼 실제 함수를 근사하는 간단한 확률 모델입니다. 지금까지 관찰된 하이퍼파라미터 조합과 그 성능 점수를 바탕으로, 아직 시도해보지 않은 지점의 성능을 불확실성(uncertainty)과 함께 예측합니다.
    *   **대표적인 모델:** 가우시안 프로세스 (Gaussian Process, GP)가 널리 사용됩니다.

2.  **획득 함수 (Acquisition Function):**
    *   **역할:** 대체 모델이 예측한 정보를 바탕으로, '다음 번에 어떤 하이퍼파라미터 조합을 시도하는 것이 가장 이득일까?'를 결정하는 함수입니다. 획득 함수는 두 가지를 동시에 고려하여 균형을 맞춥니다.
        *   **탐색 (Exploration):** 아직 시도해보지 않아 불확실성이 높은 영역을 탐색하여 새로운 최적값을 찾으려는 시도.
        *   **활용 (Exploitation):** 지금까지의 결과 중 가장 성능이 좋았던 영역 주변을 더 깊게 탐색하여 현재 최적값을 개선하려는 시도.
    *   **대표적인 함수:** Expected Improvement (EI), Probability of Improvement (PI), Upper Confidence Bound (UCB) 등이 있습니다.

이 두 요소를 통해 베이지안 최적화는 **"최소한의 시도로 최적의 해답을 찾는다"**는 목표를 달성하려고 합니다.

### 5.2. 장단점
*   **장점:**
    *   **탐색 효율성:** 그리드/랜덤 서치보다 훨씬 적은 횟수의 평가만으로도 높은 성능의 하이퍼파라미터 조합을 찾을 가능성이 높습니다.
    *   **시간 비용 절약:** 딥러닝 모델처럼 한 번 학습하는 데 수 시간에서 수 일이 걸리는 모델의 하이퍼파라미터를 튜닝할 때 특히 강력한 성능을 발휘합니다.

*   **단점:**
    *   **구현의 복잡성:** 그리드/랜덤 서치에 비해 내부 동작 원리가 복잡하고, 별도의 라이브러리 설치가 필요합니다.
    *   **순차적 탐색:** 다음 탐색 지점을 결정하기 위해 이전 결과가 필요하므로, 기본적으로 순차적으로 동작합니다. 이로 인해 병렬 처리의 이점을 완전히 활용하기 어렵다는 단점이 있습니다. (최신 라이브러리들은 이를 일부 보완하는 기능을 제공합니다.)

### 5.3. 주요 라이브러리 및 실습
Scikit-learn은 베이지안 최적화를 직접 지원하지 않지만, 호환되는 우수한 라이브러리들이 많습니다. 여기서는 Scikit-learn과 API가 유사하여 사용하기 편리한 `scikit-optimize`를 사용한 예제를 소개합니다.

#### 5.3.1. 라이브러리 설치
```bash
pip install scikit-optimize
```

#### 5.3.2. 코드 구현 (`BayesSearchCV`)
`scikit-optimize`의 `BayesSearchCV`는 Scikit-learn의 `GridSearchCV`와 거의 동일한 인터페이스를 제공하여 매우 쉽게 사용할 수 있습니다.

```python
from skopt import BayesSearchCV
from skopt.space import Real, Categorical, Integer
from sklearn.ensemble import RandomForestClassifier
from sklearn.datasets import load_iris
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

# 데이터 로드
iris = load_iris()
X, y = iris.data, iris.target

# 파이프라인 정의
pipe_rf = Pipeline([
    ('scaler', StandardScaler()),
    ('rf', RandomForestClassifier(random_state=42))
])

# 탐색할 하이퍼파라미터 공간(Search Space) 정의
# 각 파라미터의 타입을 Real, Categorical, Integer로 명확히 지정
search_spaces = {
    'rf__n_estimators': Integer(10, 200),
    'rf__max_depth': Integer(1, 10),
    'rf__min_samples_split': Integer(2, 20),
    'rf__min_samples_leaf': Integer(1, 20),
    'rf__max_features': Real(0.5, 1.0, prior='uniform') # 'uniform' 분포에서 실수 샘플링
}

# BayesSearchCV 객체 생성
# n_iter: 총 탐색 횟수
bayes_search = BayesSearchCV(pipe_rf, search_spaces, n_iter=50, cv=5, 
                             scoring='accuracy', random_state=42, n_jobs=-1, verbose=1)

# 베이지안 최적화 수행
bayes_search.fit(X, y)

# 결과 확인
print(f"\n최적의 하이퍼파라미터: {bayes_search.best_params_}")
print(f"최고 교차 검증 정확도: {bayes_search.best_score_:.4f}")
```

#### 5.3.3. 결과 해석
*   **`search_spaces`:** `RandomizedSearchCV`와 유사하게 탐색 범위를 지정하지만, `skopt.space`의 `Real`, `Integer`, `Categorical` 객체를 사용하여 각 파라미터의 타입과 범위를 더 명시적으로 정의합니다.
*   **동작 방식:** `BayesSearchCV`는 `n_iter=50`번의 반복 동안, 처음 몇 번은 랜덤 탐색을 통해 초기 정보를 수집하고, 그 이후부터는 대체 모델과 획득 함수를 사용하여 가장 유망한 지점을 예측하여 탐색을 수행합니다.
*   **결과:** `GridSearchCV`나 `RandomizedSearchCV`와 마찬가지로 `best_params_`와 `best_score_` 속성을 통해 최적의 결과를 확인할 수 있습니다.

베이지안 최적화는 특히 **평가 비용이 비싼 문제**에서 시간과 자원을 크게 절약하며 더 나은 솔루션을 찾을 수 있는 강력한 방법입니다.

## 6. 자동화된 머신러닝 (AutoML)


### 6.1. AutoML이란?
AutoML (Automated Machine Learning)은 데이터 전처리, 특성 공학, 모델 선택, 하이퍼파라미터 튜닝, 앙상블 구성 등 머신러닝 파이프라인의 **전 과정을 자동화**하는 기술을 의미합니다. 데이터 과학자의 수동적인 개입을 최소화하여 모델 개발 시간을 단축하고, 비전문가도 고성능 모델을 쉽게 구축할 수 있도록 돕습니다.

하이퍼파라미터 튜닝이 머신러닝 파이프라인의 한 단계를 자동화하는 것이라면, AutoML은 이 개념을 파이프라인 전체로 확장한 것입니다. AutoML 도구는 내부적으로 베이지안 최적화, 유전 프로그래밍 등 다양한 최적화 기법을 사용하여 다음과 같은 과정을 자동으로 수행합니다.

1.  **데이터 준비 및 전처리:** 결측치 처리, 이상치 제거, 범주형 변수 인코딩 등 데이터에 맞는 전처리 방법을 자동으로 선택하고 적용합니다.
2.  **특성 공학 및 선택:** 기존 특성을 조합하여 새로운 특성을 만들거나, 모델 성능에 가장 중요한 영향을 미치는 특성들을 선택합니다.
3.  **모델 선택:** 주어진 문제(회귀, 분류 등)에 적합한 여러 머신러닝 알고리즘(예: 랜덤 포레스트, SVM, XGBoost 등)을 테스트하고 가장 성능이 좋은 모델을 선택합니다.
4.  **하이퍼파라미터 최적화:** 선택된 모델의 하이퍼파라미터를 자동으로 튜닝합니다.
5.  **앙상블 및 모델 평가:** 최종적으로 가장 성능이 좋은 여러 모델을 결합(앙상블)하여 예측 성능을 극대화하고, 그 결과를 제시합니다.

### 6.2. 주요 AutoML 프레임워크
*   **`Auto-Sklearn`:** Scikit-learn 기반의 AutoML 프레임워크로, 베이지안 최적화와 메타 학습(Meta-learning)을 사용하여 최적의 파이프라인을 찾습니다.
*   **`TPOT (Tree-based Pipeline Optimization Tool)`:** 유전 프로그래밍(Genetic Programming)을 사용하여 데이터에 가장 적합한 Scikit-learn 파이프라인을 '진화'시키는 방식으로 탐색합니다. 최종 결과물로 최적의 파이프라인 코드를 직접 생성해주는 것이 특징입니다.
*   **`H2O.ai AutoML`:** H2O 플랫폼에서 제공하는 AutoML 기능으로, 다양한 모델과 앙상블을 자동으로 탐색하며 사용이 간편합니다.
*   **`PyCaret`:** 로우코드(low-code) 머신러닝 라이브러리로, 몇 줄의 코드만으로 데이터 준비부터 모델 배포까지 전 과정을 자동화하고 실험 결과를 비교 분석하는 데 강점이 있습니다.
*   **클라우드 기반 AutoML 서비스:** Google Cloud AutoML, Azure Machine Learning AutoML, AWS SageMaker Autopilot 등 주요 클라우드 벤더들이 제공하는 서비스도 있습니다. 복잡한 인프라 설정 없이 대규모 데이터에 대한 AutoML을 수행할 수 있습니다.

### 6.3. 장단점
*   **장점:**
    *   **생산성 향상:** 모델 개발에 필요한 반복적인 작업을 자동화하여 데이터 과학자가 더 중요한 문제 분석에 집중할 수 있게 해줍니다.
    *   **비전문가의 접근성:** 머신러닝에 대한 깊은 지식이 없어도 고품질의 모델을 구축할 수 있도록 진입 장벽을 낮춥니다.
    *   **고성능 베이스라인 확보:** 전문가가 직접 튜닝한 모델과 대등하거나 더 나은 성능을 내는 경우가 많아, 프로젝트 초기에 강력한 성능의 기준 모델을 빠르게 확보할 수 있습니다.
    *   **개발자 편향 감소:** 특정 모델이나 기법에 대한 개발자의 선입견을 배제하고 데이터 기반으로 객관적인 최적의 파이프라인을 탐색합니다.

*   **단점:**
    *   **높은 계산 비용:** 최적의 파이프라인을 찾기 위해 수많은 모델과 파라미터를 테스트하므로 상당한 컴퓨팅 자원과 시간이 소요될 수 있습니다.
    *   **블랙박스 특성:** 최종 모델이 어떻게 그런 구조로 결정되었는지 해석하기 어려울 수 있습니다. (TPOT처럼 코드를 생성해주는 경우는 예외)
    *   **제한적인 제어:** 세부적인 로직을 직접 제어하거나 특정 도메인 지식을 반영하기 어려울 수 있습니다.

### 6.4. 실습 (TPOT 예제)
TPOT을 사용하여 분류 문제에 대한 최적의 파이프라인을 찾는 예제입니다.

#### 6.4.1. 라이브러리 설치
```bash
pip install tpot
```

#### 6.4.2. 코드 구현
```python
from tpot import TPOTClassifier
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

# 데이터 로드 및 분할
iris = load_iris()
X_train, X_test, y_train, y_test = train_test_split(
    iris.data, iris.target,
    train_size=0.75, test_size=0.25, random_state=42
)

# TPOTClassifier 객체 생성
# generations: 유전 알고리즘의 세대 수 (클수록 더 많이 탐색)
# population_size: 각 세대에서 유지할 파이프라인의 수
# verbosity=2: 진행 상황을 자세히 출력
# random_state=42: 재현성을 위한 시드 고정
tpot = TPOTClassifier(generations=5, population_size=50, verbosity=2, random_state=42, n_jobs=-1)

# AutoML 수행
tpot.fit(X_train, y_train)

# 테스트 데이터로 성능 평가
print(f"
TPOT 최종 모델 정확도: {tpot.score(X_test, y_test):.4f}")

# 찾은 최적의 파이프라인 코드를 파일로 내보내기
tpot.export('tpot_iris_pipeline.py')
```

#### 6.4.3. 결과 해석
*   TPOT은 지정된 `generations`와 `population_size`에 따라 유전 알고리즘을 실행하여 수많은 파이프라인을 생성하고 평가합니다.
*   학습이 완료되면, `tpot.score`를 통해 최종적으로 선택된 최적 파이프라인의 성능을 확인할 수 있습니다.
*   가장 중요한 결과물은 `tpot.export()`를 통해 생성된 `tpot_iris_pipeline.py` 파일입니다. 이 파일에는 TPOT이 찾은 **최고의 성능을 내는 Scikit-learn 파이프라인 코드가 그대로 담겨 있습니다.** 사용자는 이 코드를 직접 분석, 수정하거나 실제 프로덕션 환경에 적용할 수 있습니다. 이는 AutoML의 '블랙박스' 문제를 해결해주는 TPOT의 큰 장점입니다.

AutoML은 머신러닝 프로젝트의 초기 단계에서 빠르게 성능 기준을 설정하거나, 제한된 시간 안에 최적의 모델을 찾아야 할 때 매우 유용한 도구입니다.

## 7. 어떤 튜닝 방법을 선택해야 할까?

-   Grid Search, Randomized Search, Bayesian Optimization은 각각 장단점이 있으므로 상황에 맞는 적절한 방법을 선택해야 한다.

-   **Grid Search**:
    -   **장점**: 지정된 하이퍼파라미터 공간을 모두 탐색하므로, 최적의 조합을 찾을 가능성이 높다.
    -   **단점**: 탐색 공간이 커질수록 계산 비용이 기하급수적으로 증가한다. 중요하지 않은 하이퍼파라미터에 많은 시간을 낭비할 수 있다.
    -   **추천 경우**: 탐색할 하이퍼파라미터의 수가 적고, 각 파라미터의 탐색 범위가 작을 때 유용하다.

-   **Randomized Search**:
    -   **장점**: 제한된 예산 내에서 넓은 하이퍼파라미터 공간을 효율적으로 탐색할 수 있다. Grid Search보다 더 빠르게 좋은 성능을 내는 조합을 찾을 수 있다.
    -   **단점**: 무작위 탐색이므로 최적의 조합을 놓칠 수 있다. 재현성이 부족할 수 있다 (random_state를 고정하여 해결 가능).
    -   **추천 경우**: 탐색할 하이퍼파라미터의 수가 많거나, 탐색 공간이 넓을 때, 또는 계산 리소스가 제한적일 때 적합하다.

-   **Bayesian Optimization**:
    -   **장점**: 이전 탐색 결과를 바탕으로 다음 탐색 지점을 효율적으로 결정하므로, 적은 반복 횟수로도 최적의 하이퍼파라미터를 찾을 가능성이 높다. 특히, 평가 비용이 높은 모델(예: 딥러닝)에 효과적이다.
    -   **단점**: 내부적으로 복잡한 확률 모델을 사용하므로, 이해하고 구현하기가 다른 방법에 비해 어렵다. 병렬 처리가 상대적으로 비효율적일 수 있다.
    -   **추천 경우**: 개별 탐색(학습)에 시간이 매우 오래 걸리는 경우, 계산 비용을 최소화하면서 최적의 성능을 찾고 싶을 때 가장 유용하다.

**결론적으로, 다음과 같은 전략을 고려할 수 있다:**

1.  **초기 탐색**: 프로젝트 초기에는 **Randomized Search**를 사용하여 넓은 범위의 하이퍼파라미터 공간을 빠르게 탐색하고, 성능에 영향을 미치는 중요한 하이퍼파라미터와 유망한 값의 범위를 파악한다.
2.  **세부 튜닝**: Randomized Search를 통해 찾은 유망한 하이퍼파라미터 범위를 중심으로 **Grid Search**를 사용하여 더 세밀하게 최적의 조합을 찾는다.
3.  **고비용 모델**: 모델 학습에 시간이 매우 오래 걸리는 경우, 처음부터 **Bayesian Optimization**을 사용하여 최소한의 시도로 최적의 하이퍼파라미터를 찾는다.

**Halving Search (HalvingGridSearchCV, HalvingRandomSearchCV)**:
-   **장점**: Grid Search나 Randomized Search의 효율성을 개선한 방법으로, 특히 많은 수의 하이퍼파라미터 조합을 탐색해야 할 때 유용하다. 불필요한 조합에 대한 계산을 줄여 시간을 절약한다.
-   **단점**: `factor`와 같은 추가적인 파라미터 설정이 필요하며, 모든 경우에 최적의 성능을 보장하지는 않는다.
-   **추천 경우**: Grid Search나 Randomized Search를 사용하지만, 계산 리소스나 시간 제약이 더 클 때 고려할 수 있다. 특히, 탐색 공간이 크고, 각 조합의 평가 비용이 높은 경우에 효율적이다.

**최종 선택 가이드라인:**

-   **가장 간단하고 빠른 방법**: 하이퍼파라미터 공간이 작고, 각 조합의 평가 시간이 짧다면 **Grid Search**.
-   **넓은 공간을 효율적으로 탐색**: 하이퍼파라미터 공간이 넓거나, 계산 리소스가 제한적이라면 **Randomized Search**.
-   **평가 비용이 높은 모델**: 모델 학습 시간이 길고, 최적화에 많은 시간이 소요될 경우 **Bayesian Optimization**.
-   **효율적인 대규모 탐색**: Grid Search나 Randomized Search의 효율성을 높이고 싶을 때 **Halving Search**.

각 방법의 장단점과 프로젝트의 특성(데이터 크기, 모델 복잡성, 시간 및 계산 리소스 제약)을 고려하여 가장 적합한 하이퍼파라미터 튜닝 방법을 선택하는 것이 중요하다. 여러 방법을 조합하여 사용하는 것도 좋은 전략이다.

---

### 7.1. 실제 프로젝트에서의 하이퍼파라미터 튜닝 전략

실제 머신러닝 프로젝트에서는 단일 튜닝 방법만을 고수하기보다는, 여러 방법을 조합하여 사용하는 **하이브리드 전략**이 가장 효과적입니다. 다음은 일반적인 워크플로우와 고려사항입니다.

1.  **초기 탐색 (Exploration) - Randomized Search 활용:**
    *   **목표**: 넓은 하이퍼파라미터 공간에서 성능에 큰 영향을 미치는 주요 파라미터와 그 유망한 범위를 빠르게 파악하는 것입니다.
    *   **방법**: `RandomizedSearchCV`를 사용하여 각 하이퍼파라미터에 대해 넓은 분포(예: `uniform`, `randint`)를 설정하고, `n_iter`를 적절히 설정하여 제한된 시간 내에 다양한 조합을 시도합니다.
    *   **이유**: 모든 조합을 탐색하는 Grid Search는 비효율적이며, Bayesian Optimization은 초기 정보가 부족할 때 탐색 효율이 떨어질 수 있습니다. Randomized Search는 초기 단계에서 '운'에 기대어 좋은 조합을 발견할 가능성이 높습니다.

2.  **세부 탐색 (Exploitation) - Grid Search 또는 Bayesian Optimization 활용:**
    *   **목표**: 초기 탐색에서 발견한 유망한 하이퍼파라미터 범위 내에서 최적의 조합을 더 정밀하게 찾는 것입니다.
    *   **방법**: Randomized Search를 통해 얻은 `best_params_` 주변으로 하이퍼파라미터 범위를 좁혀 `GridSearchCV`를 적용하거나, 모델 평가 비용이 높다면 `Bayesian Optimization`을 사용합니다.
    *   **이유**: 유망한 영역이 좁혀졌을 때 Grid Search는 해당 영역 내의 최적값을 보장하며, Bayesian Optimization은 더욱 효율적으로 최적값을 수렴합니다.

3.  **모델 복잡도 및 계산 자원 고려:**
    *   **간단한 모델/충분한 자원**: SVM, 로지스틱 회귀 등 비교적 간단한 모델이거나 컴퓨팅 자원이 충분하다면, Grid Search를 통해 모든 조합을 탐색하는 것이 가장 확실한 방법일 수 있습니다.
    *   **복잡한 모델/제한된 자원**: 딥러닝 모델, 복잡한 앙상블 모델 등 학습 시간이 오래 걸리거나 컴퓨팅 자원이 제한적이라면, Bayesian Optimization이나 Halving Search가 필수적입니다.

4.  **하이퍼파라미터 간의 상호작용:**
    *   일부 하이퍼파라미터는 서로 독립적이지 않고 상호작용하여 모델 성능에 영향을 미칠 수 있습니다. 예를 들어, 신경망의 학습률과 배치 크기는 함께 튜닝해야 할 경우가 많습니다.
    *   이러한 상호작용을 고려하여 탐색 공간을 설계하고, 필요하다면 조건부 하이퍼파라미터(conditional hyperparameters)를 지원하는 고급 튜닝 라이브러리(예: Optuna)를 고려할 수 있습니다.

5.  **평가 지표의 선택:**
    *   모델의 성능을 평가하는 지표(`scoring` 파라미터)는 문제의 특성에 맞게 신중하게 선택해야 합니다. 단순히 정확도(accuracy)만을 보는 것이 아니라, 정밀도(precision), 재현율(recall), F1-점수, ROC-AUC 등 다양한 지표를 고려해야 합니다.
    *   특히 불균형 데이터셋에서는 정확도만으로는 모델의 실제 성능을 제대로 평가하기 어렵습니다.

6.  **재현성 확보:**
    *   하이퍼파라미터 튜닝 결과를 재현 가능하게 하려면 `random_state` 파라미터를 항상 고정해야 합니다. 이는 특히 Randomized Search나 Bayesian Optimization과 같이 무작위성을 포함하는 방법에서 중요합니다.

7.  **AutoML의 활용:**
    *   프로젝트 초기에 빠르게 강력한 베이스라인 모델을 구축하거나, 머신러닝 전문 지식이 부족한 팀원들이 모델을 개발해야 할 때 AutoML을 활용하는 것이 매우 효과적입니다.
    *   또한, 어떤 모델과 파이프라인이 데이터에 가장 적합한지 모를 때, AutoML은 넓은 탐색을 통해 유용한 통찰을 제공할 수 있습니다.

**요약:**
하이퍼파라미터 튜닝은 단순히 최적의 숫자를 찾는 것을 넘어, 모델의 특성과 데이터의 복잡성, 그리고 사용 가능한 컴퓨팅 자원을 종합적으로 고려하는 전략적인 과정입니다. 각 튜닝 방법의 장단점을 이해하고, 프로젝트의 단계와 목표에 맞춰 유연하게 조합하여 사용하는 것이 성공적인 머신러닝 모델 개발의 핵심입니다.
