## 1. 데이터 전처리 (Data Preprocessing)

데이터 전처리는 머신러닝 모델의 성능에 결정적인 영향을 미치는 중요한 단계입니다. Scikit-learn은 다양한 전처리 도구를 제공하여 원시 데이터를 모델 학습에 적합한 형태로 변환할 수 있도록 돕습니다.

### 1.1. 불균형 데이터 처리 (Handling Imbalanced Data)
분류 문제에서 각 클래스에 속한 데이터의 양이 현저하게 차이 나는 경우를 **클래스 불균형(Class Imbalance)**이라고 합니다. 이는 머신러닝에서 매우 흔하게 발생하는 문제이며, 특히 실제 비즈니스 문제(예: 신용카드 사기 탐지, 질병 진단, 불량 제품 검출)에서 소수 클래스(사기, 질병, 불량)가 훨씬 더 중요하지만 데이터 수가 적은 경우가 많습니다.

**클래스 불균형이 문제가 되는 이유:**
1.  **모델의 다수 클래스 편향:** 대부분의 머신러닝 알고리즘은 전체적인 정확도(Accuracy)를 최대화하는 방향으로 학습됩니다. 불균형 데이터셋에서는 다수 클래스를 올바르게 예측하는 것만으로도 높은 정확도를 달성할 수 있으므로, 모델은 소수 클래스를 무시하거나 제대로 학습하지 못하는 경향이 있습니다.
2.  **소수 클래스 예측 성능 저하:** 결과적으로 모델은 소수 클래스에 대한 예측 성능(예: 재현율, 정밀도, F1-점수)이 매우 낮아지게 됩니다. 이는 소수 클래스의 예측이 중요한 문제에서는 치명적인 결과를 초래할 수 있습니다.
3.  **잘못된 평가 지표:** 정확도(Accuracy)와 같은 지표는 불균형 데이터셋에서 모델의 실제 성능을 제대로 반영하지 못할 수 있습니다. 예를 들어, 99%가 정상인 데이터에서 항상 정상이라고 예측하는 모델은 99%의 정확도를 보이지만, 사기를 전혀 탐지하지 못하는 무의미한 모델이 됩니다.

이러한 문제를 해결하기 위해 다양한 전략이 사용됩니다. 주요 전략은 `class_weight` 파라미터 조정과 리샘플링(Resampling) 기법입니다.

#### 1.1.1. `class_weight` 파라미터 사용
많은 Scikit-learn 분류 모델(예: `LogisticRegression`, `SVC`, `RandomForestClassifier`, `GradientBoostingClassifier` 등)은 `class_weight`라는 파라미터를 제공합니다. 이 파라미터를 사용하면 모델 학습 시 각 클래스에 다른 가중치를 부여하여 클래스 불균형의 영향을 완화할 수 있습니다.

*   **작동 원리:**
    *   `class_weight='balanced'`: 이 옵션을 설정하면, 모델은 자동으로 각 클래스의 샘플 수에 반비례하는 가중치를 계산하여 소수 클래스의 데이터에 더 높은 가중치를 부여합니다. 이는 모델이 소수 클래스의 오류에 더 큰 페널티를 부여하도록 하여, 소수 클래스를 더 잘 학습하도록 유도합니다.
    *   **수동 설정:** `class_weight`를 딕셔너리 형태로 직접 지정할 수도 있습니다 (예: `class_weight={0: 1, 1: 10}`는 클래스 1에 10배의 가중치를 부여).

*   **장점:**
    *   **구현 용이성:** 대부분의 Scikit-learn 모델에서 파라미터 하나만 설정하면 되므로 구현이 매우 간단합니다.
    *   **데이터 복제 불필요:** 데이터를 물리적으로 복제하거나 제거하지 않으므로 데이터셋의 크기를 변경하지 않습니다.

*   **단점:**
    *   모든 모델에 `class_weight` 파라미터가 있는 것은 아닙니다.
    *   가중치 조정만으로는 복잡한 불균형 문제를 완전히 해결하기 어려울 수 있습니다.

```python
from sklearn.linear_model import LogisticRegression
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.metrics import classification_report, confusion_matrix, accuracy_score
import numpy as np

# 불균형 데이터 생성 (95%가 클래스 0, 5%가 클래스 1)
# n_samples: 총 샘플 수
# weights: 각 클래스의 비율을 지정합니다. [다수 클래스 비율, 소수 클래스 비율]
# random_state: 재현성을 위한 난수 시드
X, y = make_classification(n_samples=1000, n_features=10, n_informative=5, 
                           n_redundant=0, n_classes=2, n_clusters_per_class=1, 
                           weights=[0.95, 0.05], flip_y=0, random_state=42)

# 훈련/테스트 데이터 분리
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

print(f"훈련 데이터 클래스 분포: {np.bincount(y_train)}")
print(f"테스트 데이터 클래스 분포: {np.bincount(y_test)}")

# class_weight를 사용하지 않은 모델
print("\n--- class_weight를 사용하지 않은 모델 ---")
model_unbalanced = LogisticRegression(random_state=42, solver='liblinear') # solver 지정
model_unbalanced.fit(X_train, y_train)
y_pred_unbalanced = model_unbalanced.predict(X_test)

print("혼동 행렬:\n", confusion_matrix(y_test, y_pred_unbalanced))
print("분류 보고서:\n", classification_report(y_test, y_pred_unbalanced))
print(f"정확도: {accuracy_score(y_test, y_pred_unbalanced):.4f}")

# class_weight='balanced'를 사용한 모델
print("\n--- class_weight='balanced'를 사용한 모델 ---")
model_balanced = LogisticRegression(class_weight='balanced', random_state=42, solver='liblinear') # solver 지정
model_balanced.fit(X_train, y_train)
y_pred_balanced = model_balanced.predict(X_test)

print("혼동 행렬:\n", confusion_matrix(y_test, y_pred_balanced))
print("분류 보고서:\n", classification_report(y_test, y_pred_balanced))
print(f"정확도: {accuracy_score(y_test, y_pred_balanced):.4f}")

# 해석: class_weight='balanced'를 사용한 모델이 소수 클래스(클래스 1)에 대한 재현율(recall)이 향상되었는지 확인합니다.
# 정확도(accuracy)는 낮아질 수 있지만, 소수 클래스 예측 성능이 중요한 경우 더 나은 모델입니다.
```

**`class_weight` 파라미터 사용 시 고려사항:**
*   **평가 지표:** 불균형 데이터셋에서는 정확도(Accuracy)보다는 재현율(Recall), 정밀도(Precision), F1-점수(F1-Score), ROC-AUC(Receiver Operating Characteristic - Area Under Curve)와 같은 평가 지표를 사용하여 모델의 성능을 평가해야 합니다. 특히 소수 클래스에 대한 성능을 중점적으로 확인해야 합니다.
*   **모델 선택:** `class_weight` 파라미터를 지원하는 모델인지 확인해야 합니다.
*   **과적합 위험:** 소수 클래스에 너무 높은 가중치를 부여하면 모델이 소수 클래스에 과적합될 위험이 있습니다.


#### 1.1.2. 리샘플링 (Resampling)
리샘플링(Resampling)은 데이터의 양을 조절하여 클래스 불균형을 해소하는 기법입니다. 이는 데이터셋 자체를 변형하여 모델이 균형 잡힌 데이터로부터 학습할 수 있도록 합니다. Scikit-learn과 함께 사용되는 `imbalanced-learn` 라이브러리는 다양한 리샘플링 기법을 제공합니다.

*   **언더샘플링 (Undersampling):**
    *   **방법:** 다수 클래스의 데이터를 무작위로 제거하거나, 특정 알고리즘(예: `NearMiss`, `TomekLinks`)을 사용하여 제거하여 소수 클래스의 데이터 수와 맞춥니다.
    *   **장점:** 훈련 데이터의 크기를 줄여 학습 시간을 단축할 수 있습니다.
    *   **단점:** 다수 클래스의 중요한 정보가 손실될 수 있다는 단점이 있습니다. 이는 모델의 일반화 성능을 저하시킬 수 있습니다.
    *   **사용 시기:** 데이터셋의 크기가 매우 커서 오버샘플링이 비효율적이거나, 다수 클래스의 정보 손실이 크게 문제되지 않을 때.

*   **오버샘플링 (Oversampling):**
    *   **방법:** 소수 클래스의 데이터를 복제하거나, 기존 소수 클래스 데이터 포인트들로부터 새로운 합성(synthetic) 데이터를 생성하여 다수 클래스의 데이터 수와 맞춥니다.
    *   **장점:** 데이터 손실이 없으며, 소수 클래스의 정보를 더 많이 활용할 수 있습니다.
    *   **단점:** 단순히 복제하는 경우 과적합의 위험이 있을 수 있습니다. 새로운 데이터를 생성하는 경우에도 데이터의 분포를 잘못 학습하면 문제가 될 수 있습니다.

*   **SMOTE (Synthetic Minority Over-sampling Technique):**
    *   가장 대표적이고 널리 사용되는 오버샘플링 기법입니다. 단순히 소수 클래스 데이터를 복제하는 것이 아니라, 소수 클래스 데이터 포인트들 사이의 공간에 새로운 합성(synthetic) 데이터를 생성합니다.
    *   **작동 원리:**
        1.  소수 클래스의 각 샘플에 대해 K-최근접 이웃(KNN)을 찾습니다.
        2.  해당 샘플과 K개의 이웃 중 무작위로 선택된 이웃 사이의 선을 긋습니다.
        3.  이 선 위에서 무작위 지점을 선택하여 새로운 합성 샘플을 생성합니다.
    *   **장점:** 소수 클래스의 과적합을 줄이면서 데이터 불균형을 효과적으로 해소합니다.

**SMOTE 사용 예시 (`imbalanced-learn` 라이브러리 필요)**:
`imbalanced-learn` 라이브러리는 Scikit-learn과 호환되도록 설계되었으며, 리샘플링 기법들을 `fit_resample()` 메서드를 통해 제공합니다.

```bash
# imbalanced-learn 설치 (아직 설치되지 않았다면)
# pip install imbalanced-learn
```

```python
from sklearn.datasets import make_classification
from imblearn.over_sampling import SMOTE
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, confusion_matrix
import numpy as np

# 불균형 데이터 생성
X, y = make_classification(n_samples=1000, weights=[0.95, 0.05], random_state=42)
print(f"원본 데이터 클래스 분포: {np.bincount(y)}")

# 훈련/테스트 데이터 분리 (리샘플링은 훈련 데이터에만 적용해야 합니다!)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

# SMOTE 적용 (훈련 데이터에만 적용)
smote = SMOTE(random_state=42)
X_resampled, y_resampled = smote.fit_resample(X_train, y_train)

print(f"SMOTE 적용 후 훈련 데이터 클래스 분포: {np.bincount(y_resampled)}")

# 이제 리샘플링된 훈련 데이터 (X_resampled, y_resampled)를 사용하여 모델을 학습시킵니다.
print("\n--- SMOTE 적용 후 모델 학습 및 평가 ---")
model_smote = LogisticRegression(random_state=42, solver='liblinear')
model_smote.fit(X_resampled, y_resampled)
y_pred_smote = model_smote.predict(X_test)

print("혼동 행렬:\n", confusion_matrix(y_test, y_pred_smote))
print("분류 보고서:\n", classification_report(y_test, y_pred_smote))

# 참고: 리샘플링은 훈련 데이터에만 적용해야 합니다. 테스트 데이터에 적용하면 데이터 누수(Data Leakage)가 발생하여
# 모델의 일반화 성능을 과대평가하게 됩니다. 파이프라인(Pipeline)을 사용하면 이러한 문제를 효과적으로 관리할 수 있습니다.
```

**리샘플링 사용 시 고려사항:**
*   **데이터 누수 방지:** 리샘플링은 **반드시 훈련 데이터에만** 적용해야 합니다. 테스트 데이터에 리샘플링을 적용하면 모델이 테스트 데이터의 정보를 미리 학습하게 되어 성능이 과대평가될 수 있습니다. `Pipeline`과 `imblearn.pipeline.Pipeline`을 사용하면 이 문제를 효과적으로 관리할 수 있습니다.
*   **적절한 기법 선택:** 언더샘플링, 오버샘플링, 또는 이 둘을 조합한 기법(예: `SMOTEENN`, `SMOTETomek`) 중 어떤 것이 문제에 가장 적합한지 실험을 통해 찾아야 합니다.
*   **과적합 위험:** 오버샘플링은 소수 클래스에 대한 과적합을 유발할 수 있습니다. 특히 SMOTE는 선형 보간을 통해 새로운 샘플을 생성하므로, 소수 클래스 내의 노이즈까지 증폭시킬 수 있습니다.
*   **평가 지표:** `class_weight`와 마찬가지로, 리샘플링 후에도 정확도보다는 재현율, 정밀도, F1-점수, ROC-AUC 등 불균형 데이터셋에 적합한 평가 지표를 사용해야 합니다.
