## 1. 성능 최적화 팁

대규모 데이터를 다룰 때 Pandas의 성능을 최적화하는 것은 매우 중요합니다. 비효율적인 코드는 메모리 부족이나 긴 처리 시간으로 이어질 수 있습니다. 다음은 Pandas 성능을 향상시키는 주요 팁들입니다.

### 1.1. 벡터화된 연산 활용

Pandas에서 성능 최적화의 **가장 기본이자 핵심**은 **벡터화된 연산(Vectorized Operations)**을 최대한 활용하는 것입니다. 이는 파이썬의 일반적인 `for` 루프를 사용하는 것보다 훨씬 빠르고 효율적입니다.

**왜 벡터화된 연산이 빠른가?**

Pandas와 NumPy의 핵심 연산들은 파이썬이 아닌, 저수준의 컴파일된 언어(주로 C나 Cython)로 구현되어 있습니다. 벡터화된 연산은 이 최적화된 코드를 활용하여 전체 배열(Series)이나 행렬(DataFrame)에 대해 한 번에 연산을 수행합니다. 반면 파이썬 `for` 루프는 각 요소를 개별적으로 처리하며 파이썬 인터프리터의 오버헤드를 반복적으로 발생시키기 때문에 대규모 데이터에서는 매우 비효율적입니다.

--- 
**다양한 벡터화된 연산 예시**

```python
import pandas as pd
import numpy as np
import time

size = 10**6 # 100만 개의 데이터
df_perf = pd.DataFrame({
    'A': np.random.rand(size),
    'B': np.random.rand(size),
    'C': np.random.rand(size)
})

print(f"데이터 크기: {size} 행")
```

**1. 기본 산술 연산**

```python
# 비효율적인 for 루프 (절대 사용하지 마세요!)
start_time = time.time()
result_list = []
for i in range(len(df_perf)):
    result_list.append(df_perf['A'][i] + df_perf['B'][i])
end_time = time.time()
print(f"For 루프 시간: {end_time - start_time:.4f} 초")

# 벡터화된 Pandas 연산
start_time = time.time()
result_pandas = df_perf['A'] + df_perf['B']
end_time = time.time()
print(f"Pandas 벡터화 시간: {end_time - start_time:.4f} 초")

# 여러 컬럼을 포함한 복합 연산
start_time = time.time()
result_complex = (df_perf['A'] * df_perf['B']) / df_perf['C']
end_time = time.time()
print(f"복합 벡터화 연산 시간: {end_time - start_time:.4f} 초")
```

**2. 조건부 연산 (`np.where`)**

파이썬의 `if/else` 문을 `for` 루프 없이 벡터화하여 적용할 수 있습니다.

```python
# A가 0.5보다 크면 A*2, 아니면 B*3
start_time = time.time()
df_perf['D'] = np.where(df_perf['A'] > 0.5, df_perf['A'] * 2, df_perf['B'] * 3)
end_time = time.time()
print(f"np.where 벡터화 시간: {end_time - start_time:.4f} 초")
```

**3. 수학 함수 적용**

NumPy의 수학 함수들은 Series나 DataFrame에 직접 적용하면 자동으로 벡터화됩니다.

```python
start_time = time.time()
df_perf['log_A'] = np.log(df_perf['A'])
df_perf['sqrt_B'] = np.sqrt(df_perf['B'])
end_time = time.time()
print(f"수학 함수 벡터화 시간: {end_time - start_time:.4f} 초")
```

**4. 문자열 연산 (`.str` 접근자)**

문자열 컬럼에 대한 연산도 `.str` 접근자를 통해 벡터화할 수 있습니다. 이는 `for` 루프를 사용하는 것보다 훨씬 빠릅니다.

```python
df_text = pd.DataFrame({'text': ['apple', 'banana', 'cherry', 'date'] * (size // 4)})

start_time = time.time()
lower_text = df_text['text'].str.lower()
contains_a = df_text['text'].str.contains('a')
end_time = time.time()
print(f"문자열 연산 벡터화 시간: {end_time - start_time:.4f} 초")
```

**결과 분석**: 모든 벡터화된 연산은 파이썬 `for` 루프에 비해 압도적으로 빠릅니다. 대규모 데이터 처리 시 `for` 루프를 사용하는 것은 피하고, 항상 벡터화된 대안을 먼저 고려해야 합니다.

### 1.2. `apply()` 대신 벡터화된 함수 사용

`apply()` 메서드는 `DataFrame`의 행 또는 열에 파이썬 함수를 적용할 수 있어 매우 유연합니다. 하지만 이 유연성은 **성능 저하**라는 대가를 치르게 합니다.

**`apply()`가 느린 이유**: `apply()`는 내부적으로 파이썬 `for` 루프와 유사하게 동작하기 때문에, 대규모 데이터에서는 벡터화된 연산에 비해 현저히 느립니다. 각 행/열에 대해 파이썬 함수를 호출하는 과정에서 파이썬 인터프리터의 오버헤드가 반복적으로 발생하며, 이는 C/Cython으로 최적화된 Pandas/NumPy의 벡터화된 연산보다 훨씬 느립니다.

---
**`apply()` 사용을 피해야 하는 경우 (벡터화된 대안이 있는 경우)**

대부분의 경우, `apply()`를 사용하는 대신 더 빠른 벡터화된 대안이 존재합니다.

1.  **단순 산술 연산**: 
    ```python
    # apply()를 사용한 비효율적인 연산
    start_time = time.time()
    df_perf['D_apply'] = df_perf.apply(lambda row: row['A'] * 2 + row['B'] * 3, axis=1)
    end_time = time.time()
    print(f"Apply() 연산 시간: {end_time - start_time:.4f} 초")

    # 벡터화된 연산으로 대체
    start_time = time.time()
    df_perf['D_vectorized'] = df_perf['A'] * 2 + df_perf['B'] * 3
    end_time = time.time()
    print(f"벡터화된 연산 시간: {end_time - start_time:.4f} 초")
    ```

2.  **조건부 로직**: `np.where()`나 불리언 마스킹(Boolean Masking)을 사용합니다.
    ```python
    # apply 예시: A가 0.5보다 크면 A*2, 아니면 B*3
    start_time = time.time()
    df_perf['E_apply'] = df_perf.apply(lambda row: row['A'] * 2 if row['A'] > 0.5 else row['B'] * 3, axis=1)
    end_time = time.time()
    print(f"Apply() 조건부 연산 시간: {end_time - start_time:.4f} 초")

    # np.where를 사용한 벡터화된 구현
    start_time = time.time()
    df_perf['E_vectorized'] = np.where(df_perf['A'] > 0.5, df_perf['A'] * 2, df_perf['B'] * 3)
    end_time = time.time()
    print(f"np.where 조건부 연산 시간: {end_time - start_time:.4f} 초")
    ```

3.  **문자열 연산**: `.str` 접근자를 사용합니다.
    ```python
    df_text_apply = pd.DataFrame({'text': ['apple', 'banana', 'cherry'] * (size // 3)})
    start_time = time.time()
    df_text_apply['upper_apply'] = df_text_apply['text'].apply(lambda x: x.upper())
    end_time = time.time()
    print(f"Apply() 문자열 연산 시간: {end_time - start_time:.4f} 초")

    start_time = time.time()
    df_text_apply['upper_vectorized'] = df_text_apply['text'].str.upper()
    end_time = time.time()
    print(f"벡터화된 문자열 연산 시간: {end_time - start_time:.4f} 초")
    ```

4.  **타입 변환**: `.astype()`나 `pd.to_numeric()` 등을 사용합니다.
    ```python
    # df_perf['A'].apply(int) 대신 df_perf['A'].astype(int) 사용
    ```

---
**`apply()` 사용이 불가피한 경우**

`apply()`는 모든 로직을 벡터화할 수 없는 것은 아닙니다. 다음과 같은 경우에는 `apply()`가 유일하거나 가장 합리적인 선택일 수 있습니다.

-   **진정으로 복잡한 행/열 단위 로직**: Pandas나 NumPy의 내장 함수로 표현하기 어려운, 매우 복잡한 파이썬 함수를 각 행/열에 적용해야 할 때. (예: 복잡한 정규 표현식 파싱, 외부 API 호출 등)
-   **그룹별 연산 중 `agg`나 `transform`으로 해결 불가능한 경우**: `groupby().apply()`는 각 그룹에 `DataFrame`을 전달하므로, 그룹별로 복잡한 연산을 수행하고 다양한 형태의 결과를 반환할 때 유용합니다. (이전 문서에서 다룸)
-   **데이터 크기가 작아 성능이 중요하지 않은 경우**: 소규모 데이터에서는 `apply()`의 성능 저하가 미미하므로, 코드의 가독성이나 개발 편의성을 위해 사용할 수 있습니다.

**`apply()` 성능 개선을 위한 대안**:

`apply()` 사용이 불가피하고 성능이 중요하다면, 다음과 같은 라이브러리를 고려할 수 있습니다.

-   **Numba**: 파이썬 함수를 JIT(Just-In-Time) 컴파일하여 NumPy 배열에 대한 연산을 C 속도로 가속화합니다.
-   **Cython**: 파이썬 코드에 C 정적 타입 선언을 추가하여 컴파일 속도를 높입니다.

**결론**: `apply()`는 Pandas의 유연성을 제공하지만, 성능 최적화를 위해서는 항상 벡터화된 대안을 먼저 고려하고, 불가피한 경우에만 신중하게 사용해야 합니다.

### 1.3. 적절한 데이터 타입 (`dtype`) 사용

데이터 타입을 적절하게 사용하는 것은 Pandas 성능 최적화에서 **메모리 사용량과 연산 속도** 모두에 큰 영향을 미칩니다. Pandas는 기본적으로 `int64`나 `float64`와 같이 넓은 범위를 커버하는 데이터 타입을 사용하지만, 실제 데이터의 범위가 작다면 더 작은 메모리를 사용하는 타입을 지정하여 효율을 높일 수 있습니다.

**왜 `dtype`가 중요한가?**

-   **메모리 효율성**: 작은 `dtype`는 더 적은 RAM을 사용합니다. 대규모 데이터셋의 경우, 이는 메모리 부족 오류를 방지하고, CPU 캐시에 더 많은 데이터를 담을 수 있게 하여 연산 속도를 향상시킵니다.
-   **연산 속도**: 특정 연산은 더 작은 `dtype`에서 더 빠르게 수행될 수 있습니다.

---
**주요 `dtype` 종류 및 메모리 효율적인 사용법**

| `dtype` | 메모리 (바이트) | 정수 범위 | 부동 소수점 범위 |
| :--- | :--- | :--- | :--- |
| `int8` | 1 | -128 ~ 127 | - |
| `int16` | 2 | -32,768 ~ 32,767 | - |
| `int32` | 4 | 약 -20억 ~ 20억 | - |
| `int64` | 8 | 약 -900경 ~ 900경 | - |
| `float16` | 2 | - | 약 6.55e+04 |
| `float32` | 4 | - | 약 3.4e+38 |
| `float64` | 8 | - | 약 1.8e+308 |

```python
# 예시 데이터프레임 생성
df_dtype = pd.DataFrame({
    'ID': np.arange(1000000), # 0부터 999,999까지
    'Value': np.random.randint(0, 255, 1000000), # 0부터 254까지
    'Price': np.random.rand(1000000) * 1000 # 0부터 1000 미만
})

print("--- 원본 DataFrame 메모리 사용량 ---")
print(df_dtype.info(memory_usage='deep'))

# 데이터 타입 변경 (astype)
# ID: 100만까지이므로 int32로 충분 (int64의 절반)
df_dtype['ID'] = df_dtype['ID'].astype('int32')
# Value: 0-254이므로 int8로 충분 (int64의 1/8)
df_dtype['Value'] = df_dtype['Value'].astype('int8')
# Price: float32로 충분 (float64의 절반)
df_dtype['Price'] = df_dtype['Price'].astype('float32')

print("\n--- 타입 변경 후 DataFrame 메모리 사용량 ---")
print(df_dtype.info(memory_usage='deep'))
```
**결과 분석**: `int64`와 `float64`를 더 작은 범위의 타입으로 변경함으로써 메모리 사용량이 크게 줄어든 것을 확인할 수 있습니다.

---
**`object` 타입의 문제점과 해결책**

`object` `dtype`은 문자열, 혼합된 타입 등 Pandas가 특정 타입을 추론하기 어려울 때 사용됩니다. `object` 타입 컬럼은 메모리 사용량이 많고 연산 속도가 느려지는 주범이 될 수 있습니다.

-   **`pd.to_numeric(errors='coerce', downcast='...')`**: 숫자형으로 변환 가능한 `object` 컬럼을 효율적으로 숫자형으로 변환합니다. 변환 불가능한 값은 `NaN`으로 처리(`errors='coerce'`)하고, `downcast` 옵션으로 가장 작은 숫자형으로 자동 변환할 수 있습니다.
    ```python
    df_obj = pd.DataFrame({'num_str': ['1', '2', '3', '4', 'invalid', '5']})
    print("\n원본 object 타입 Series:\n", df_obj['num_str'])
    print("메모리 사용량 (object):", df_obj['num_str'].memory_usage(deep=True))

    # 숫자형으로 변환, 변환 불가 시 NaN, 가장 작은 정수형으로 다운캐스팅
    df_obj['num_str_converted'] = pd.to_numeric(df_obj['num_str'], errors='coerce', downcast='integer')
    print("\n변환 후 숫자형 Series:\n", df_obj['num_str_converted'])
    print("메모리 사용량 (변환 후):", df_obj['num_str_converted'].memory_usage(deep=True))
    ```

-   **`pd.to_datetime()`**: 날짜/시간 문자열을 `datetime` 타입으로 변환합니다. `datetime`은 Pandas에서 최적화된 시계열 `dtype`입니다.

**결론**: 데이터 로딩 시 또는 전처리 초기 단계에서 `df.info(memory_usage='deep')`를 통해 메모리 사용량을 확인하고, 데이터의 실제 범위에 맞춰 `dtype`를 명시적으로 지정하거나 `pd.to_numeric`의 `downcast` 옵션을 활용하는 습관을 들이는 것이 좋습니다.


### 1.4. `inplace=True` 사용 주의

`inplace=True` 옵션은 Pandas 메서드가 원본 `DataFrame`을 직접 수정하고 `None`을 반환하도록 지시합니다. 과거에는 메모리 복사를 피하고 성능을 향상시키는 방법으로 권장되기도 했으나, **최근 Pandas 버전에서는 `inplace=True` 사용을 권장하지 않습니다.**

**`inplace=True` 사용을 피해야 하는 이유**

1.  **메서드 체이닝 방해**: `inplace=True`를 사용하면 메서드가 `None`을 반환하므로, 다음 메서드를 연쇄적으로 호출하는 메서드 체이닝이 불가능해집니다. 이는 코드의 가독성과 흐름을 해칩니다.
    ```python
    # 비권장: 체이닝이 끊어짐
    # df.fillna(0, inplace=True)
    # df.dropna(inplace=True) # 오류 발생: 'NoneType' object has no attribute 'dropna'
    ```

2.  **예상치 못한 부작용 및 버그**: 원본 `DataFrame`이 직접 수정되므로, 다른 변수가 동일한 `DataFrame`을 참조하고 있다면 예상치 못한 방식으로 데이터가 변경될 수 있습니다. 이는 특히 함수 내에서 `DataFrame`을 처리할 때 디버깅을 매우 어렵게 만듭니다.

3.  **`SettingWithCopyWarning` 발생 가능성 증가**: `DataFrame`의 '뷰(view)'에 대해 `inplace=True` 연산을 수행할 때 `SettingWithCopyWarning`이 발생할 가능성이 높아집니다. 이 경고는 원본이 아닌 복사본을 수정하고 있을 수 있음을 알려주며, 잘못된 결과를 초래할 수 있습니다.

4.  **성능 이점 미미 또는 없음**: 최신 Pandas 버전에서는 `inplace=True`를 사용하지 않아도 내부적으로 메모리 최적화가 잘 되어 있어, 성능이나 메모리 사용량 측면에서 큰 이점이 없습니다. 오히려 특정 상황에서는 `inplace=True`가 더 느릴 수도 있습니다.

**권장되는 방식: 새로운 `DataFrame` 반환받기**

대부분의 경우, 메서드가 새로운 `DataFrame`을 반환하도록 하고, 그 결과를 새로운 변수에 할당하거나 기존 변수에 재할당하는 것이 더 안전하고 가독성이 좋습니다.

```python
# 권장: 새로운 DataFrame을 반환받아 재할당
df_processed = df_perf.drop(columns=['A']) # df_perf는 그대로 유지
df_perf = df_perf.fillna(0) # df_perf가 새로운 DataFrame으로 업데이트됨

# 메서드 체이닝 가능
df_chained = (
    df_perf
    .fillna(0)
    .dropna()
    .reset_index()
)
```
`inplace=True`를 사용하지 않는 것은 더 안전하고 예측 가능한 코드를 작성하는 현대 Pandas의 모범 사례입니다.

### 1.6. `Categorical` 타입 활용

고유한 값의 개수가 적은(low cardinality) 문자열 컬럼의 경우 `Categorical` 타입으로 변환하면 **메모리 사용량을 크게 줄이고 연산 속도를 향상**시킬 수 있습니다. Pandas는 문자열 자체를 저장하는 대신, 각 고유 문자열에 정수형 코드를 할당하고 이 코드를 저장하는 방식으로 작동합니다.

**`Categorical` 타입이 효율적인 이유**

-   **메모리 절약**: 반복되는 긴 문자열을 여러 번 저장하는 대신, 고유한 문자열만 한 번 저장하고 나머지는 작은 정수형 코드로 참조합니다.
-   **연산 속도 향상**: 정수형 코드를 기반으로 연산하므로, `groupby()`, `value_counts()`, 정렬 등 특정 연산이 `object` 타입보다 훨씬 빠릅니다.

--- 
**언제 `Categorical` 타입을 사용해야 할까?**

-   **낮은 카디널리티 (Low Cardinality)**: 고유한 값의 개수가 전체 데이터 개수에 비해 매우 적을 때 (예: 성별, 지역, 제품 카테고리).
-   **문자열 데이터**: 특히 긴 문자열이 반복될 때 효과적입니다.
-   **정해진 범주**: 데이터에 나타나지 않는 범주도 미리 정의해두고 싶을 때 (예: '월', '화', '수'만 있지만 '목', '금'도 범주에 포함하고 싶을 때).

--- 
**`Categorical` 타입 활용 예시**

```python
# 예시 데이터프레임 (문자열 컬럼 포함)
df_category = pd.DataFrame({
    'Product_ID': np.arange(100000),
    'Category': np.random.choice(['Electronics', 'Clothing', 'Books', 'Home'], size=100000),
    'Region': np.random.choice(['East', 'West', 'North', 'South'], size=100000),
    'Status': np.random.choice(['Active', 'Inactive', 'Pending'], size=100000)
})

print("--- 원본 문자열 컬럼 메모리 사용량 ---")
print(df_category.info(memory_usage='deep'))

# Category와 Region 컬럼을 Categorical 타입으로 변환
df_category['Category'] = df_category['Category'].astype('category')
df_category['Region'] = df_category['Region'].astype('category')

print("\n--- Categorical 타입 변환 후 메모리 사용량 ---")
print(df_category.info(memory_usage='deep'))
```
**결과 분석**: `object` 타입이었던 문자열 컬럼이 `category` 타입으로 변환되면서 메모리 사용량이 크게 줄어든 것을 확인할 수 있습니다.

--- 
**`Categorical` 타입의 추가 기능**

`Categorical` 타입은 `.cat` 접근자를 통해 다양한 추가 기능을 제공합니다.

-   **카테고리 확인**: `.cat.categories`로 고유한 범주 목록을 확인합니다.
-   **코드 확인**: `.cat.codes`로 각 값이 매핑된 정수형 코드를 확인합니다.
-   **순서 지정**: `ordered=True`로 순서를 지정하고 `.cat.set_categories()`로 범주 순서를 변경할 수 있습니다.
-   **범주 추가/제거**: `.cat.add_categories()`, `.cat.remove_categories()`로 범주를 동적으로 관리할 수 있습니다.

```python
# Status 컬럼을 Categorical로 변환하고 순서 지정
df_category['Status'] = pd.Categorical(df_category['Status'], categories=['Pending', 'Inactive', 'Active'], ordered=True)
print("\nStatus 컬럼의 카테고리 및 순서:", df_category['Status'].cat.categories)
print("Status 컬럼의 순서 지정 여부:", df_category['Status'].cat.ordered)

# 특정 카테고리만 필터링 (Categorical 타입에서도 일반 필터링 가능)
print("\nStatus가 'Active'인 데이터 (일부):\n", df_category[df_category['Status'] == 'Active'].head())
```
`Categorical` 타입은 메모리 및 성능 최적화뿐만 아니라, 범주형 데이터의 의미론적 관리에도 유용한 기능을 제공합니다.


### 1.7. 대용량 데이터 처리를 위한 `query()`와 `eval()`

`query()`와 `eval()` 메서드는 대용량 `DataFrame`에서
**필터링 및 연산을 더 빠르고 메모리 효율적으로** 수행하기 위해 설계되었습니다. 이들은 내부적으로 Numexpr 라이브러리(또는 유사한 최적화된 백엔드)를 활용하여, 파이썬 연산이 중간에 임시 객체를 생성하여 발생하는 메모리 오버헤드를 최소화합니다.

**왜 `query()`와 `eval()`이 빠른가?**

일반적인 Pandas 연산은 파이썬 객체를 생성하고 조작하는 과정에서 추가적인 메모리를 사용합니다. 예를 들어 `df[df['A'] > 0.5]`는 `df['A'] > 0.5`라는 불리언 Series를 먼저 생성한 후 이를 필터링에 사용합니다. `query()`와 `eval()`은 이러한 중간 객체 생성을 피하고, C/Cython 수준에서 직접 연산을 수행하여 속도와 메모리 효율을 높입니다.

---
**1. `query()`: 문자열 기반의 효율적인 필터링**

-   **활용**: 문자열 형태로 조건을 전달하여 행을 필터링합니다. 복잡한 조건문을 작성할 때 가독성이 좋습니다.
-   **성능**: 대용량 데이터에서 일반 불리언 인덱싱보다 빠르고 메모리 효율적입니다.

```python
size_eval = 5  10*6 # 500만 개의 데이터
df_eval = pd.DataFrame({
    'A': np.random.rand(size_eval),
    'B': np.random.rand(size_eval),
    'C': np.random.rand(size_eval),
    'D': np.random.rand(size_eval)
})
print(f"\n데이터 크기 (query/eval): {size_eval} 행")
query() vs 일반 불리언 인덱싱
start_time = time.time()
result_boolean = df_eval[df_eval['A'] > 0.5]
end_time = time.time()
print(f"불리언 인덱싱 시간: {end_time - start_time:.4f} 초")
start_time = time.time()
result_query = df_eval.query('A > 0.5')
end_time = time.time()
print(f"query() 시간: {end_time - start_time:.4f} 초")
```
  
**`query()` 사용 팁**:
-   컬럼명에 공백이나 특수 문자가 포함된 경우 백틱(`` ` ``)으로 감쌉니다.  예: `` `column name` > 10 ``
-   파이썬 변수를 조건에 포함하려면 `@` 기호를 사용합니다. 예: `threshold = 0.5; df.query('A > @threshold')`
  
---
**2. `eval()`: 문자열 기반의 효율적인 연산**

-   **활용**: 문자열 형태로 수식을 전달하여 새로운 컬럼을 생성하거나 기존 컬럼을 수정합니다. 복잡한 산술 연산에 특히 유용합니다.
-   **성능**: 대용량 데이터에서 일반적인 파이썬 연산보다 빠르고 메모리 효율적입니다.
```python
# eval() vs 일반 연산
start_time = time.time()
df_eval['E_normal'] = df_eval['A'] * df_eval['B'] + df_eval['C'] /
df_eval['D']
end_time = time.time()
print(f"일반 연산 시간: {end_time - start_time:.4f} 초")
start_time = time.time()
# inplace=True를 사용하면 원본 DataFrame을 직접 수정하고 None을 반환합니다.
# (inplace=True 사용 주의는 이전 섹션 참조)
df_eval.eval('E_eval = A * B + C / D', inplace=True)
end_time = time.time()
print(f"eval() 시간: {end_time - start_time:.4f} 초")
```
  
**`eval()` 사용 팁**:
-   `query()`와 마찬가지로 `@` 기호를 사용하여 파이썬 변수를 수식에 포함할 수 있습니다.
-   `inplace=True`를 사용하여 원본 `DataFrame`을 직접 수정할 수 있습니다.

---
**`query()`와 `eval()`의 한계**

-   **데이터 크기**: 소규모 데이터에서는 일반 연산과 성능 차이가 미미하거나 오히려 느릴 수 있습니다. 대용량 데이터에서만 진정한 이점을 발휘합니다.
-   **표현식 제한**: 모든 파이썬 연산을 문자열 표현식으로 나타낼 수 있는 것은 아닙니다. 복잡한 함수 호출이나 외부 라이브러리 함수는 직접 사용할 수 없습니다.

**결론**: 대용량 `DataFrame`을 다루면서 필터링이나 복합 연산이 빈번하게 발생한다면, `query()`와 `eval()`을 사용하여 코드의 효율성과 가독성을 동시에 높일 수 있습니다.

### 1.8. 병렬 및 분산 처리 (Parallel & Distributed Computing)

Pandas는 기본적으로 **단일 코어(single-core)**에서 동작하며, 모든 데이터를 **메모리(RAM)**에 로드해야 합니다. 따라서 데이터 규모가 커지면(예: 수 GB ~ 수십 GB 이상) 메모리 부족 오류가 발생하거나, 처리 시간이 너무 길어져 성능 한계에 부딪히게 됩니다.

이러한 문제를 해결하기 위해, Pandas와 유사한 API를 제공하면서 내부적으로 병렬/분산 처리를 수행하는 라이브러리들이 등장했습니다. 대표적으로 **Dask**와 **Modin**이 있습니다. 이들은 기존 Pandas 코드를 최소한으로 수정하여 대용량 데이터를 효율적으로 처리할 수 있게 해줍니다.

---
**1. Dask: 대규모 데이터셋을 위한 병렬 컴퓨팅**

Dask는 NumPy 배열, Pandas DataFrame, 파이썬 리스트와 유사한 API를 제공하는 병렬 컴퓨팅 라이브러리입니다. `dask.dataframe`은 Pandas DataFrame과 거의 동일한 API를 가지며, 내부적으로 데이터를 여러 파티션으로 나누어 병렬로 처리합니다.

-   **작동 방식**: Dask DataFrame은 실제 데이터를 메모리에 로드하지 않고, 연산 그래프(task graph)를 구축합니다. `compute()` 메서드가 호출될 때 비로소 실제 계산이 시작되며, 이 계산은 여러 CPU 코어나 분산 클러스터에서 병렬로 수행됩니다.
-   **장점**: Pandas API에 익숙한 사용자가 대용량 데이터를 다룰 수 있게 해줍니다.

```python
import dask.dataframe as dd
import dask.array as da

# 예시: 1억 행의 Dask DataFrame 생성 (실제 메모리에 로드되지 않음)
ddf = dd.from_dask_array(da.random.random((10**8, 5)), columns=[f'col_{i}' for i in range(5)])
print("Dask DataFrame (1억 행) 생성:", ddf)

# Dask DataFrame에 대한 연산 (실제 계산은 .compute() 호출 시 발생)
# Pandas와 동일한 API 사용
ddf_result = ddf.groupby('col_0').col_1.mean()
print("Dask DataFrame 연산 결과 (compute() 호출 전):", ddf_result)

# 실제 계산 수행
final_dask_result = ddf_result.compute()
print("Dask DataFrame 연산 결과 (compute() 호출 후):", final_dask_result.head())
```

---
**2. Modin: Pandas API를 통한 병렬 처리**

Modin은 Pandas API를 그대로 사용하면서, 내부적으로 Dask나 Ray와 같은 병렬 처리 엔진을 활용하여 연산을 가속화하는 라이브러리입니다.

-   **가장 큰 장점**: 기존 Pandas 코드를 거의 수정할 필요 없이, `import pandas as pd` 대신 `import modin.pandas as pd`로 변경하는 것만으로 병렬 처리를 활성화할 수 있습니다.
-   **백엔드**: Ray (기본값) 또는 Dask를 백엔드로 사용할 수 있습니다.

```python
# Modin을 사용하려면 import 문만 변경하면 됩니다.
import modin.pandas as mpd

# 기존 Pandas 코드와 동일하게 사용
df_modin = mpd.DataFrame(np.random.rand(10**6, 2))
print("Modin DataFrame 생성 및 연산:", df_modin.head())

# Modin으로 연산 수행 (내부적으로 병렬 처리)
modin_result = df_modin.groupby(0).mean()
print("Modin 연산 결과:", modin_result.head())
```

---
**실무적 중요성 및 고려사항**

-   **언제 사용할까?**: 로컬 머신의 RAM을 초과하거나, 단일 CPU 코어로 처리하기에 너무 오래 걸리는 대용량 데이터셋(수 GB ~ 수십 GB)을 다룰 때 Dask나 Modin은 매우 유용한 대안이 됩니다.
-   **빅데이터 시스템과의 관계**: Spark와 같은 분산 컴퓨팅 프레임워크는 훨씬 더 큰 규모(TB 이상)의 데이터를 다루는 데 적합하지만, 학습 곡선이 가파릅니다. Dask나 Modin은 기존 Pandas 지식을 활용하여 빅데이터 시스템으로 넘어가기 전 단계에서 성능을 크게 향상시킬 수 있는 '중간 다리' 역할을 합니다.
-   **제한 사항**: 모든 Pandas API가 100% 구현되어 있지는 않으며, 특정 연산에서는 성능 이점이 미미하거나 오히려 느릴 수도 있습니다. 또한, 디버깅이 일반 Pandas보다 복잡할 수 있습니다.

**결론**: 데이터 규모가 커질수록 Pandas의 성능 최적화는 필수적입니다. 벡터화된 연산, 적절한 `dtype` 사용, `read_csv` 옵션, `Categorical` 타입, `query`/`eval` 활용은 기본이며, 더 큰 규모에서는 Dask나 Modin과 같은 병렬/분산 처리 라이브러리를 고려해야 합니다.
