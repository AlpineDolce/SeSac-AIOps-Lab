### 1. CSV/Excel의 한계

CSV(Comma Separated Values)와 Excel 파일은 범용성과 가독성이 뛰어나지만, 대규모 데이터 처리에는 다음과 같은 한계가 있습니다.

-   **텍스트 기반**: 데이터를 텍스트로 저장하므로 파싱(parsing) 과정이 필요하여 읽기/쓰기 속도가 느립니다.
-   **비효율적인 저장**: 숫자형 데이터도 텍스트로 저장되어 파일 크기가 커지고, 압축 효율이 낮습니다.
-   **스키마 부재**: 데이터 타입 정보가 없어 파일을 읽을 때마다 데이터 타입을 추론해야 합니다.
-   **컬럼 기반 연산 비효율**: 행(row) 단위로 저장되어 특정 컬럼만 읽거나 연산할 때 비효율적입니다.

### 2. Parquet 포맷

Parquet은 Apache Hadoop 생태계에서 주로 사용되는 컬럼 기반(columnar) 이진 파일 포맷입니다. 대규모 분석 워크로드에 최적화되어 있습니다.

-   **컬럼 기반 저장**: 데이터를 컬럼별로 저장하여 특정 컬럼만 읽을 때 매우 효율적입니다. (Predicate Pushdown, Column Pruning)
-   **높은 압축률**: 컬럼별로 데이터 타입이 동일하여 효율적인 압축 알고리즘을 적용할 수 있습니다.
-   **스키마 포함**: 파일 내에 스키마(데이터 타입, 컬럼명 등) 정보가 포함되어 있어 데이터 읽기 시 타입 추론 과정이 필요 없습니다.
-   **빅데이터 생태계 통합**: Spark, Hive, Impala, Dask 등 다양한 빅데이터 처리 프레임워크와 잘 연동됩니다.

**Pandas를 이용한 Parquet 입출력:**
`pyarrow` 또는 `fastparquet` 라이브러리가 필요합니다. (`pip install pyarrow` 또는 `pip install fastparquet`)

```python
import pandas as pd
import numpy as np

# 예시 DataFrame 생성
df = pd.DataFrame({
    'id': np.arange(1_000_000),
    'value': np.random.rand(1_000_000),
    'category': np.random.choice(['A', 'B', 'C'], 1_000_000)
})

# Parquet 파일로 저장
parquet_file = 'large_data.parquet'
df.to_parquet(parquet_file, index=False) # index=False는 인덱스를 저장하지 않음

# Parquet 파일 읽기
df_from_parquet = pd.read_parquet(parquet_file)
print("Read from Parquet - Head:\n", df_from_parquet.head())
print("Read from Parquet - Info:\n")
df_from_parquet.info()
```

### 3. Feather 포맷

Feather는 Python(Pandas)과 R 간의 데이터 교환을 위해 설계된 경량의 컬럼 기반 이진 파일 포맷입니다.

-   **매우 빠른 읽기/쓰기**: 인메모리(in-memory) 데이터 전송에 최적화되어 있어 Parquet보다도 빠른 읽기/쓰기 속도를 제공합니다.
-   **컬럼 기반**: Parquet과 유사하게 컬럼 기반으로 저장됩니다.
-   **간단한 스키마**: Parquet보다 스키마 기능이 단순하며, 주로 Pandas DataFrame의 스키마를 그대로 반영합니다.
-   **언어 간 호환성**: Python과 R 사용자 간에 대규모 DataFrame을 쉽게 공유할 수 있습니다.

**Pandas를 이용한 Feather 입출력:**
`pyarrow` 라이브러리가 필요합니다. (`pip install pyarrow`)

```python
# Feather 파일로 저장
feather_file = 'large_data.feather'
df.to_feather(feather_file) # Feather는 기본적으로 인덱스를 저장하지 않음

# Feather 파일 읽기
df_from_feather = pd.read_feather(feather_file)
print("\nRead from Feather - Head:\n", df_from_feather.head())
print("Read from Feather - Info:\n")
df_from_feather.info()
```

### 4. 기타 고성능 포맷 (간략히)

-   **HDF5 (Hierarchical Data Format 5)**: 복잡하고 계층적인 데이터 구조를 저장하는 데 적합합니다. 대규모 과학 데이터 저장에 많이 사용됩니다. Pandas는 `read_hdf()`, `to_hdf()`를 제공합니다.
-   **Pickle**: Python 객체를 직렬화(serialize)하여 파일로 저장하는 Python 고유의 포맷입니다. Pandas DataFrame도 Pickle로 저장할 수 있지만, Python 환경에 종속적이며 보안에 취약할 수 있습니다.

### 5. 실무 적용 및 선택 가이드

| 파일 포맷 | 장점                                     | 단점                                     | 주요 사용 사례                                   |
| :-------- | :--------------------------------------- | :--------------------------------------- | :----------------------------------------------- |
| **CSV**   | 범용성, 가독성, 언어 독립적              | 느린 속도, 큰 파일 크기, 스키마 부재     | 소규모 데이터, 인간 가독성, 간단한 데이터 교환   |
| **Excel** | 스프레드시트 기능, 서식 지원             | 느린 속도, 큰 파일 크기, 복잡한 파싱     | 소규모 보고서, 수동 데이터 입력                |
| **Parquet** | 컬럼 기반, 고압축률, 스키마 포함, 분산 처리 | 텍스트 편집 불가, 이진 포맷              | 대규모 분석 데이터, 빅데이터 파이프라인, 장기 저장 |
| **Feather** | 매우 빠른 읽기/쓰기, 컬럼 기반, 언어 간 호환 | 스키마 단순, 분산 처리 기능 부족         | Python/R 간 빠른 데이터 교환, 중간 결과 저장     |
| **HDF5**  | 계층적 구조, 대용량 데이터, 유연한 스키마 | 복잡한 API, 특정 사용 사례에 최적화      | 복잡한 과학 데이터, 시계열 데이터 저장           |

-   **대규모 분석 데이터 저장**: **Parquet**을 최우선으로 고려하세요.
-   **Python/R 간 빠른 데이터 교환**: **Feather**가 가장 효율적입니다.
-   **중간 결과 저장**: **Feather** 또는 **Parquet**을 사용하여 다음 단계의 처리 속도를 높이세요.
-   **인간 가독성 및 소규모 데이터**: 여전히 **CSV**나 **Excel**이 편리할 수 있습니다.

### 6. 요약 및 모범 사례

-   데이터의 규모와 사용 목적에 따라 **적절한 파일 포맷을 선택**하는 것이 데이터 처리 파이프라인의 성능을 결정합니다.
-   대규모 데이터셋에서는 **이진 컬럼 기반 포맷(Parquet, Feather)**을 적극적으로 활용하여 읽기/쓰기 속도와 메모리 효율성을 극대화하세요.
-   `to_parquet()`나 `to_feather()` 사용 시 `index=False` 옵션을 사용하여 불필요한 인덱스 저장을 피하는 것이 일반적입니다.
